# कंटेंट एंडपॉइंट

<div class="article-intro">

कंटेंट मॉड्यूल वेबसाइट के पेज, सेक्शन, एलिमेंट, ब्लॉक, ब्लॉग पोस्ट, रीडायरेक्ट, सरमन, प्लेलिस्ट, स्ट्रीमिंग सेवाएँ, इवेंट, क्यूरेटेड कैलेंडर, फ़ाइलें, गैलरी, बाइबल अनुवाद और वचन खोज, गीत, अरेंजमेंट, ग्लोबल स्टाइल, स्टॉक फ़ोटो और सेटिंग्स को प्रबंधित करता है। यह API का सबसे बड़ा मॉड्यूल है और सभी ChurchApps एप्लिकेशन में CMS, मीडिया/स्ट्रीमिंग, वर्शिप प्लानिंग और बाइबल सुविधाओं को सशक्त बनाता है।

</div>

**बेस पाथ:** `/content`

## पेज

बेस पाथ: `/content/pages`

| विधि | पाथ | प्रमाणीकरण | अनुमति | विवरण |
|--------|------|------|------|------|
| GET | `/:churchId/tree?url=&id=` | सार्वजनिक | — | URL या ID द्वारा पूरा पेज ट्री (सेक्शन, एलिमेंट, ब्लॉक) लोड करें। URL से लाने पर आंतरिक ID हटा दी जाती हैं। URL-आधारित फ़ेच `pages.visibility` लागू करते हैं — सीमित पेज `{ restricted: true, visibility }` लौटाता है, जब तक (वैकल्पिक) JWT शर्त पूरी न करे |
| GET | `/public/:churchId` | सार्वजनिक | — | सार्वजनिक पेज सूचीबद्ध करें (`url`, `title`, `metaDescription`); केवल `visibility = everyone` वाले |
| GET | `/:id` | JWT | — | ID द्वारा पेज प्राप्त करें |
| GET | `/` | JWT | — | चर्च के सभी पेज सूचीबद्ध करें |
| POST | `/duplicate/:id` | JWT | Content.Edit | सभी सेक्शन और एलिमेंट के साथ पेज की प्रतिलिपि बनाएँ |
| POST | `/temp/ai` | JWT | Content.Edit | AI द्वारा बनाया गया पेज सहेजें (एक कॉल में पेज, सेक्शन और एलिमेंट) |
| POST | `/importTree` | JWT | Content.Edit | नेस्टेड ट्री से पेज बनाएँ (`title`, `url`, `sections[].elements[]…`)। हमेशा कॉलर के चर्च के अंदर डालता है; बॉडी के ID अनदेखे किए जाते हैं। पंक्तियों में उनके `column` चाइल्ड होने चाहिए। अधिकतम 30 सेक्शन / 500 एलिमेंट |
| POST | `/` | JWT | Content.Edit | पेज बनाएँ या अपडेट करें (बैच में) |
| DELETE | `/:id` | JWT | Content.Edit | पेज हटाएँ |

### उदाहरण: पेज ट्री लोड करना

```
GET /content/pages/abc-church-id/tree?url=/about
```

```json
{
  "name": "About",
  "url": "/about",
  "sections": [
    {
      "background": "#FFFFFF",
      "textColor": "dark",
      "elements": [
        { "elementType": "textWithPhoto", "answers": { "text": "Welcome" } }
      ]
    }
  ]
}
```

## पोस्ट (ब्लॉग)

बेस पाथ: `/content/posts`

ब्लॉग पोस्ट स्वतंत्र पंक्तियाँ हैं: `title`, `slug` (हर चर्च में अद्वितीय), `excerpt`, `content` (markdown बॉडी), `authorId`, `photoUrl`, `publishDate`, `category`, और `tags`। `publishDate` सेट होने और अतीत में होने पर ही पोस्ट प्रकाशित मानी जाती है। पढ़ने वाले एंडपॉइंट हर पोस्ट में `authorId` से हल किया गया `authorName` जोड़ते हैं। देखें [वेबसाइट बिल्डर आर्किटेक्चर](../../architecture/website-builder.md#blog)।

| विधि | पाथ | प्रमाणीकरण | अनुमति | विवरण |
|--------|------|------|------|------|
| GET | `/public/:churchId?category=&tag=&page=&pageSize=` | सार्वजनिक | — | प्रकाशित पोस्ट सूचीबद्ध करें, पेजिनेटेड (प्रति पेज अधिकतम 50) |
| GET | `/public/:churchId/categories` | सार्वजनिक | — | प्रकाशित पोस्ट की अलग-अलग श्रेणियाँ |
| GET | `/public/:churchId/slug/:slug` | सार्वजनिक | — | slug द्वारा प्रकाशित पोस्ट प्राप्त करें |
| GET | `/rss/:churchId?siteUrl=` | सार्वजनिक | — | प्रकाशित पोस्ट का RSS 2.0 फ़ीड (लिंक `{siteUrl}/blog/{slug}` के रूप में बनते हैं) |
| GET | `/:id` | JWT | — | ID द्वारा पोस्ट प्राप्त करें |
| GET | `/` | JWT | — | चर्च की सभी पोस्ट सूचीबद्ध करें |
| POST | `/` | JWT | Content.Edit | पोस्ट बनाएँ या अपडेट करें (बैच में) |
| DELETE | `/:id` | JWT | Content.Edit | पोस्ट हटाएँ |

## रीडायरेक्ट

बेस पाथ: `/content/redirects`

हर चर्च के लिए URL रीडायरेक्ट (`fromPath` → `toPath`), प्रति चर्च अधिकतम 200। पाथ सामान्यीकृत होते हैं (छोटे अक्षर, आरंभ में स्लैश, अंत में स्लैश नहीं) और प्रति चर्च `fromPath` अद्वितीय होता है। B1App संभावित 404 पर इन्हें हल करता है और HTTP 308 जारी करता है।

| विधि | पाथ | प्रमाणीकरण | अनुमति | विवरण |
|--------|------|------|------|------|
| GET | `/public/:churchId?path=` | सार्वजनिक | — | पाथ हल करें (`path` न होने पर सभी रीडायरेक्ट सूचीबद्ध करें) |
| GET | `/:id` | JWT | — | ID द्वारा रीडायरेक्ट प्राप्त करें |
| GET | `/` | JWT | — | चर्च के सभी रीडायरेक्ट सूचीबद्ध करें |
| POST | `/` | JWT | Content.Edit | रीडायरेक्ट बनाएँ या अपडेट करें। `fromPath = toPath` अस्वीकार करता है और 200-पंक्ति सीमा लागू करता है |
| DELETE | `/:id` | JWT | Content.Edit | रीडायरेक्ट हटाएँ |

| विधि | पाथ | प्रमाणीकरण | अनुमति | विवरण |

| GET | `/hasAccount` | JWT | — | जाँचें कि उपयोगकर्ता का PraiseCharts खाता लिंक है या नहीं |
| GET | `/search?q=` | JWT | — | PraiseCharts कैटलॉग खोजें |
| GET | `/products/:id?keys=` | JWT | — | किसी गीत के उत्पाद प्राप्त करें (प्रमाणित होने पर लाइब्रेरी से, अन्यथा कैटलॉग से) |
| GET | `/arrangement/raw/:id?keys=` | JWT | — | लाइब्रेरी से मूल अरेंजमेंट डेटा प्राप्त करें |
