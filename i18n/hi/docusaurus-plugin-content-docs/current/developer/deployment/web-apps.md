# वेब ऐप परिनियोजन

<div class="article-intro">

ChurchApps वेब एप्लिकेशन को **Amazon S3** पर स्टैटिक साइट्स के रूप में परिनियोजित किया जाता है, जिसमें **CloudFront** CDN के रूप में काम करता है। परिनियोजन GitHub Actions के माध्यम से स्वचालित होते हैं, लेकिन आवश्यकता होने पर इन्हें मैन्युअल रूप से भी चलाया जा सकता है।

</div>

<div class="prereqs">
<h4>शुरू करने से पहले</h4>

- वेब ऐप को स्थानीय रूप से सेट अप करें और सत्यापित करें कि यह बिल्ड होता है -- देखें [वेब ऐप्स](../web-apps/index.md)
- S3 और CloudFront एक्सेस के साथ AWS क्रेडेंशियल कॉन्फ़िगर करें
- लक्ष्य S3 बकेट का नाम और CloudFront distribution ID जानें

</div>

## परिनियोजन के चरण

1. **ऐप बिल्ड करें** -- स्टैटिक आउटपुट तैयार करें:

   ```bash
   npm run build
   ```

2. **S3 पर सिंक करें** -- बिल्ड आउटपुट को S3 बकेट पर अपलोड करें:

   ```bash
   aws s3 sync build/ s3://bucket-name
   ```

3. **CloudFront इनवैलिडेट करें** -- CDN कैश साफ़ करें ताकि उपयोगकर्ताओं को नवीनतम संस्करण मिले:

   ```bash
   aws cloudfront create-invalidation --distribution-id YOUR_DIST_ID --paths "/*"
   ```

## स्वचालित परिनियोजन

GitHub Actions workflows `main` ब्रांच पर push होने पर परिनियोजन स्वचालित रूप से संभालते हैं। यह workflow ऊपर के तीनों चरण -- बिल्ड, S3 सिंक और CloudFront इनवैलिडेशन -- बिना मैन्युअल हस्तक्षेप के करता है।

:::info
आमतौर पर आपको ये कमांड मैन्युअल रूप से चलाने की आवश्यकता नहीं होती। किसी pull request को `main` में merge करने से स्वचालित परिनियोजन pipeline शुरू हो जाती है।
:::

:::tip
परिनियोजन से पहले यदि आप बिल्ड को स्थानीय रूप से सत्यापित करना चाहते हैं, तो `npm run build` चलाएँ और `build/` डायरेक्टरी में आउटपुट देखें। यह पुष्टि करने के लिए कि सब कुछ सही काम कर रहा है, आप इसे किसी भी स्टैटिक फ़ाइल सर्वर से स्थानीय रूप से चला सकते हैं।
:::
