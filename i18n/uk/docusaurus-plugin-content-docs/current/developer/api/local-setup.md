# Налаштування локального API

<div class="article-intro">

Цей посібник проведе вас через налаштування API ChurchApps для локальної розробки. Ви клонуєте репозиторій, налаштуєте підключення до баз даних, ініціалізуєте схему та запустите сервер розробки з гарячим перезавантаженням.

</div>

<div class="prereqs">
<h4>Перш ніж почати</h4>

- Встановіть **Node.js 24+**, **Git** та **MySQL 8.0+** -- див. [Передумови](../setup/prerequisites)
- Створіть користувача MySQL з правами на створення баз даних
- Ознайомтеся з довідником [Змінні середовища](../setup/environment-variables) щодо конфігурації API

</div>

## Покроткове налаштування

### 1. Клонуйте репозиторій

```bash
git clone https://github.com/ChurchApps/Api.git
```

### 2. Встановіть залежності

Проєкт використовує Yarn (захист блокує `npm install`):

```bash
cd Api
yarn install
```

### 3. Налаштуйте змінні середовища

```bash
cp .env.sample .env
```

Відкрийте `.env` і налаштуйте рядки підключення до MySQL. Кожен модуль потребує власного підключення до бази даних у такому форматі:

```
mysql://root:password@localhost:3306/dbname
```

Вам знадобляться рядки підключення для всіх шести баз даних модулів (membership, attendance, content, giving, messaging, doing).

### 4. Ініціалізуйте бази даних

```bash
npm run initdb
```

Ця команда автоматично створює всі шість баз даних та їхні таблиці.

:::tip
Ви можете ініціалізувати базу даних окремого модуля командою `npm run initdb -- --module=membership` (або `attendance`, `content`, `giving`, `messaging`, `doing`).
:::

### 5. Запустіть сервер розробки

```bash
npm run dev
```

API запускається з гарячим перезавантаженням за адресою [http://localhost:8084](http://localhost:8084).

## Основні команди

| Команда | Опис |
|---------|------|
| `npm run dev` | Запуск сервера розробки з гарячим перезавантаженням (tsx watch) |
| `npm run build` | Очищення, компіляція TypeScript та копіювання ресурсів |
| `npm run test` | Запуск тестів з Jest (включно з покриттям коду) |
| `npm run test:watch` | Запуск тестів у режимі спостереження |
| `npm run lint` | Запуск ESLint з автовиправленням (ESLint є єдиним форматувальником) |

## Розгортання

Тестове середовище (staging) більше не використовується. API розгортається в демо-середовищі при кожному push до `main`, а в продуктивне середовище -- через вручну запускаємий робочий процес **Deploy Prod**, який також застосовує очікувані міграції бази даних. Детальніше див. [Розгортання API](../deployment/apis).

## Локальна розробка бібліотек

Якщо вам потрібно розробляти спільну бібліотеку (`@churchapps/helpers` або `@churchapps/apihelper`) разом з API, зберіть її в робочому просторі [Packages](https://github.com/ChurchApps/Packages) і додайте тимчасовий Yarn portal в API:

```bash
# У робочому просторі Packages
yarn build

# У каталозі API
yarn link ../Packages/helpers
# ... тестування ...
yarn unlink ../Packages/helpers && yarn install
```

Це дозволяє тестувати зміни бібліотеки з API без публікації в npm. Детальніше див. [Спільні бібліотеки](../shared-libraries/#local-development-against-a-consuming-app) -- і ніколи не комітьте до `package.json` портал, який записує команда link.
