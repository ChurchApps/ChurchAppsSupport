# Ендпоїнти Doing

<div class="article-intro">

Модуль Doing керує плануванням служінь, розкладом волонтерів, управлінням завданнями та автоматизаціями. Він надає інструменти для створення планів служінь з часом і позиціями, призначення волонтерів, керування датами блокування, побудови елементів порядку служіння, підключення до зовнішніх постачальників контенту та налаштування автоматизованих процесів з умовами і діями.

</div>

**Базовий шлях:** `/doing`

## Плани

Базовий шлях: `/doing/plans`

| Метод | Шлях | Авторизація | Дозвіл | Опис |
|--------|------|------|------------|-------------|
| GET | `/` | JWT | — | Отримати всі плани церкви |
| GET | `/:id` | JWT | — | Отримати план за ID |
| GET | `/ids?ids=` | JWT | — | Отримати кілька планів за ID, розділеними комами |
| GET | `/types/:planTypeId` | JWT | — | Отримати плани за типом плану |
| GET | `/textRange?startDate=&endDate=&ministryId=&planTypeId=` | JWT | `texting.send` + редагування служіння | Переглянути огляд служіння, який **Text Volunteers** надсилає перед відправкою: `{ totalMembers, eligibleCount, optedOutCount, noPhoneCount, capped }` для волонтерів, призначених у діапазоні (один запис на особу; пропускаються ті, хто відмовився від повідомлень, і ті, без номера; спільні номери дедуплікуються; обмеження 200) |
| GET | `/presenter` | JWT | — | Отримати плани на наступні 7 днів (вигляд презентера) |
| GET | `/confirmationWorkflows?ministryId=` | JWT | Редагування служіння | Активні процеси підтвердження призначень на служіння (`workflowType = "assignmentConfirmation"`), які може вибрати план: `[{ id, name }]` |
| GET | `/public/current/:planTypeId` | Публічний | — | Отримати поточний план для типу плану |
| GET | `/public/signup/:churchId` | Публічний | — | Плани, відкриті для самостійної реєстрації, найближчі спочатку; кожен із позиціями самостійної реєстрації (відсортовані за `categoryName`, потім за `name`, плюс `filledCount` для призначень Accepted/Unconfirmed) та часом. Імена волонтерів не повертаються. Якщо налаштування церкви `volunteerSignupNextOnly` має значення `"true"`, повертається лише перший план кожного типу. Кожен `plan` містить обчислений `signupDeadline` (ISO-мітка часу або `null`): за `signupDeadlineHours` годин до найранішого часу типу `service` плану (будь-який запис із часом, якщо часу служіння немає; 9:00 за часовим поясом церкви у `serviceDate`, якщо у плану немає часів) |
| GET | `/signup/:planId/volunteers` | JWT | — | `[{ positionId, names }]` для позицій самостійної реєстрації плану (відображувані імена виконавців із призначеннями Accepted/Unconfirmed). Повертає `[]`, якщо у плану не увімкнено `showVolunteerNames` |
| POST | `/` | JWT | — | Створити або оновити плани (приймає один об'єкт або масив). Встановіть `confirmationWorkflowId`, щоб підключити план до процесу підтвердження служіння, або `null`, щоб відключити для майбутніх запитів. Надішліть `signupDeadlineHours: null`, щоб очистити термін; якщо поле пропущено, збережене значення зберігається |
| POST | `/copy/:id` | JWT | Редагування служіння | Копіювати план разом із позиціями, часами, призначеннями та елементами порядку служіння. Тіло містить `ministryId`, `serviceDate`, `copyMode` ("none", "positions", "all") та `copyServiceOrder` (логічне значення). Без `targetPlanId` створюється новий план, а `notes`, `signupDeadlineHours`, `showVolunteerNames` і `autoReplaceOnDecline` переносяться з вихідного плану, якщо тіло запиту не задає їх інакше. З `targetPlanId` копія заповнює цей наявний план (викликач має мати право його редагувати). Опція **Repeat weekly** у B1Admin викликає цей метод щотижня, щоразу копіюючи з плану, створеного тижнем раніше |
| POST | `/textRange` | JWT | `texting.send` + редагування служіння | Надіслати текст кожному волонтеру, призначеному в діапазоні дат, через постачальника SMS церкви. Тіло: `{ startDate, endDate, ministryId, planTypeId?, message }` (повідомлення до 1600 символів; поля злиття підставляються для кожного одержувача). Повертає попередні підрахунки, а також `recipientCount`, `successCount`, `failCount` і `error` (`no_provider` або `insufficient_credits`), якщо надсилання зупинилося раніше |
| POST | `/:id/issueRequests` | JWT | Редагування плану | Надіслати нові призначення плану зі статусом Unconfirmed, які ще не сповіщені, через його процес підтвердження: позначає кожне як сповіщене і запускає одну картку процесу для кожного призначення. Порожнє тіло; повертає `{ issued }`. Завершується помилкою, якщо план не опублікований (не `prepared`), не має активного `confirmationWorkflowId` з принаймні одним кроком, або якщо термін відповіді вже минув |
| POST | `/autofill/:id` | JWT | — | Автоматично заповнити призначення волонтерів для плану. Тіло: `{ teams: [{ positionId, personIds }] }` |
| DELETE | `/:id` | JWT | — | Видалити план і всі пов'язані часи, призначення, позиції та елементи плану |

## Автентифікації постачальників контенту

Базовий шлях: `/doing/contentProviderAuths`

Розширює базовий клас CRUD (GET `/`, GET `/:id`, POST `/`, DELETE `/:id` — без перевірок дозволів).

Керує записами OAuth-автентифікації для зовнішніх постачальників контенту (наприклад, інтеграцій із програмами для презентацій).

Значення `accessToken` і `refreshToken` шифруються у сховищі за допомогою `EncryptionHelper` і розшифровуються під час читання, тому API все одно повертає звичайні токени. Записи, збережені до впровадження шифрування, містять відкритий текст (який ніколи не містить `|`); вони повертаються як є і шифруються під час наступного збереження.

| Метод | Шлях | Авторизація | Дозвіл | Опис |
|--------|------|------|------------|-------------|
| GET | `/` | JWT | — | Отримати всі автентифікації постачальників контенту |
| GET | `/:id` | JWT | — | Отримати автентифікацію постачальника контенту за ID |
| GET | `/ids?ids=` | JWT | — | Отримати кілька автентифікацій постачальників контенту за ID, розділеними комами |
| GET | `/ministry/:ministryId` | JWT | — | Отримати всі автентифікації постачальників контенту для служіння |

## Проксі постачальника

Базовий шлях: `/doing/providerProxy`

Перенаправляє запити до зовнішніх постачальників контенту (наприклад, ProPresenter, EasyWorship). Автоматично оновлює токени, коли вони спливають.

| Метод | Шлях | Авторизація | Дозвіл | Опис |
|--------|------|------|------------|-------------|
| POST | `/browse` | JWT | — | Переглянути файли постачальника контенту. Тіло: `{ ministryId, providerId, path }` |
| POST | `/getPresentations` | JWT | — | Отримати презентації від постачальника контенту. Тіло: `{ ministryId, providerId, path }` |
| POST | `/getPlaylist` | JWT | — | Отримати плейлист від постачальника контенту. Тіло: `{ ministryId, providerId, path, resolution }` |
| POST | `/getInstructions` | JWT | — | Отримати інструкції для елемента контенту. Тіло: `{ ministryId, providerId, path }` |
| POST | `/getExpandedInstructions` | JWT | — | Отримати розширені інструкції для елемента контенту. Тіло: `{ ministryId, providerId, path }` |
