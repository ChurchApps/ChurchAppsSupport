# Кінцеві точки повідомлень

<div class="article-intro">

Модуль повідомлень керує розмовами в реальному часі, чат-повідомленнями, push-сповіщеннями, доставкою SMS і електронних листів, підключеннями WebSocket, приватними повідомленнями, реєстрацією пристроїв і провайдерами SMS. Це комунікаційний рівень, який використовують усі застосунки ChurchApps як для чату під час прямих трансляцій, так і для асинхронних сповіщень.

</div>

**Базовий шлях:** `/messaging`

## Розмови

Базовий шлях: `/messaging/conversations`

| Метод | Шлях | Авторизація | Дозвіл | Опис |
|--------|------|------------|-----------|-------------|
| GET | `/timeline/ids?ids=` | JWT | — | Завантажити розмови за ідентифікаторами, розділеними комами, з першим і останнім повідомленнями |
| GET | `/messages/:contentType/:contentId` | JWT | — | Завантажити розмови для вмісту з постраничними повідомленнями (`?page=&limit=`) |
| GET | `/posts` | JWT | — | Отримати розмови типу «допис» для груп поточного користувача |
| GET | `/posts/group/:groupId` | JWT | — | Отримати розмови типу «допис» для конкретної групи |
| GET | `/notes/feed?section=&limit=&before=` | JWT | — | Найновіші нотатки з усіх записів для сторінки нотаток B1 Admin. `section` може бути `people`, `groups`, `events` або `workflows` (інакше 400); `limit` за замовчуванням 25 (максимум 100); `before` — курсор з попередньої сторінки. Кожна нотатка все одно має відповідати правилу свого типу (дозвіл People Edit або перегляд конфіденційних нотаток, лідери групи, глядачі події, глядачі картки робочого процесу), тож викликачі бачать лише ті нотатки, які могли б відкрити. Текст нотатки обрізається до 300 символів |
| GET | `/current/:churchId/:contentType/:contentId` | Публічний | — | Отримати або створити поточну розмову для вмісту (автоматично розшифровує contentId) |
| GET | `/:churchId/:contentType/:contentId` | Публічний | — | Завантажити розмови за типом вмісту та ідентифікатором |
| GET | `/:churchId/:id` | Публічний | — | Завантажити одну розмову за ідентифікатором |
| POST | `/` | JWT | — | Створити або оновити розмови (пакетно) |
| POST | `/start` | JWT | — | Почати нову розмову з початковим коментарем |
| DELETE | `/:churchId/:id` | JWT | — | Видалити розмову |

### Контроль доступу до нотаток про людей

Розмови з `contentType: "person"` (вкладка «Нотатки» в картці людини) або `contentType: "personConfidential"` (розділ «Конфіденційні нотатки») перевіряються на кожному шляху читання та запису, зокрема й на публічних маршрутах вище, які повертають `401` для цих типів вмісту. Для `person` потрібен дозвіл MembershipApi **People / Edit**; для `personConfidential` — **People / View Confidential Notes**. Для API-ключів з обмеженим доступом `people:write` охоплює обидві дії (користувач, якому належить ключ, також має мати відповідний дозвіл ролі).

### Контроль доступу до нотаток групи та події {#group-and-event-notes-access-control}

Ще два типи нотаток перевіряються так само, на кожному шляху читання та запису (включно з публічними маршрутами вище), і ніколи не відкриті для анонімних публікацій:

- **`groupNote`** (`contentId` = ідентифікатор групи) — стрічка **Leader notes** у групі. Читати чи публікувати можуть лише лідери цієї групи (`leaderGroupIds` у JWT). Жоден дозвіл персоналу не надає доступу, включно з `content.edit` та дозволами, пов'язаними з членством у групі.
- **`eventNote`** (`contentId` = ідентифікатор події) — нотатки до події в календарі. Персонал із `content.edit` або **Calendars / Admin** завжди може читати й публікувати. В інших випадках доступ визначається полями події `notesViewRole` (читання) та `notesPostRole` (публікація): `staff` (за замовчуванням, коли поле `null`) не дає доступу нікому іншому, `leaders` дає доступ лідерам групи події, а `members` — членам і лідерам групи події. Подія без `groupId` доступна лише персоналу.

### Контроль доступу до нотаток картки робочого процесу

Розмови з `contentType: "workflowCard"` (нотатки на картці робочого процесу, де `contentId` — ідентифікатор завдання картки) можна читати й записувати лише тим, хто може відкрити цю картку: користувачу з дозволом DoingApi **Tasks / View** або особі чи групі, яким призначено картку, які створили її або яких вона стосується. Усі інші отримують `401` на кожному шляху читання, включно з публічними маршрутами вище. Розмова прикріплюється до картки через `POST /doing/tasks/:id/conversation` (тіло `{ "conversationId": "..." }`; перемагає перша прикріплена розмова), і це можуть викликати редактори картки та її виконавець.

### Приклад: почати розмову

```
POST /messaging/conversations/start
Authorization: Bearer <token>

{
  "groupId": "group-123",
  "contentType": "group",
  "contentId": "group-123",
  "title": "Weekly Discussion",
  "comment": "Welcome to this week's discussion thread!"
}
```

```json
{
  "id": "conv-456",
  "churchId": "church-789",
  "contentType": "group",
  "contentId": "group-123",
  "title": "Weekly Discussion",
  "dateCreated": "2026-02-17T10:00:00.000Z",
  "visibility": "public",
  "allowAnonymousPosts": false,
  "groupId": "group-123"
}
```

## Повідомлення

Базовий шлях: `/messaging/messages`

| Метод | Шлях | Авторизація | Дозвіл | Опис |
|--------|------|------------|-----------|-------------|
| GET | `/conversation/:conversationId` | JWT | — | Завантажити всі повідомлення розмови |
| GET | `/catchup/:churchId/:conversationId` | Публічний | — | Завантажити всі повідомлення розмови (публічне наздоганяння для чату в прямому ефірі) |
| GET | `/:churchId/:id` | Публічний | — | Завантажити одне повідомлення за ідентифікатором |
| POST | `/` | JWT | — | Зберегти повідомлення (пакетно). Надсилає оновлення в реальному часі та запускає сповіщення. Щоб оновити наявне повідомлення, потрібно бути його автором або мати `content.edit`; збережений автор ніколи не може бути змінений |
| POST | `/send` | Публічний | — | Надіслати повідомлення (пакетно, публічно). Надсилає оновлення в реальному часі через WebSocket і запускає сповіщення |
| POST | `/setCallout` | JWT | — | (застарілий) Розіслати повідомлення-виділення в реальному часі. Активного клієнта немає; чат прямих трансляцій більше не відображає виділення |
| DELETE | `/:churchId/:id` | JWT | — | Видалити повідомлення та розіслати видалення в реальному часі. Див. [Модерація повідомлень](#message-moderation) |

### Модерація повідомлень

Видаляти повідомлення може:

- автор повідомлення;
- персонал із `content.edit` (у будь-якій частині церкви);
- **лідери груп** — для розмов із `contentType` `group` або `groupAnnouncement`, де `contentId` — група, якою вони керують (`leaderGroupIds` у JWT).

Розмови з нотатками про людей (`person` / `personConfidential`) ніколи не модеруються лідерами — для них діють дозволи на нотатки (`people.edit`, `people.viewConfidentialNotes`).

Лідери можуть лише видаляти, але не редагувати: переписувати повідомлення іншого учасника й далі можуть тільки автор і персонал із `content.edit`.

### Приклад: надіслати повідомлення

```
POST /messaging/messages/send

[
  {
    "churchId": "church-789",
    "conversationId": "conv-456",
    "personId": "person-123",
    "displayName": "John Smith",
    "content": "Hello everyone!",
    "messageType": "comment"
  }
]
```

```json
[
  {
    "id": "msg-001",
    "churchId": "church-789",
    "conversationId": "conv-456",
    "personId": "person-123",
    "displayName": "John Smith",
    "timeSent": "2026-02-17T10:05:00.000Z",
    "content": "Hello everyone!",
    "messageType": "comment"
  }
]
```

## Підключення

Базовий шлях: `/messaging/connections`

Керує підключеннями WebSocket/у реальному часі для чату, групових розмов, приватних повідомлень і прямих трансляцій. Наскрізний протокол описано в [Архітектура реального часу](../../realtime.md).

| Метод | Шлях | Авторизація | Дозвіл | Опис |
|--------|------|------------|-----------|-------------|
| GET | `/:churchId/:conversationId` | Публічний | — | Завантажити всі підключення до розмови |
| POST | `/` | Публічний | — | Зареєструвати підключення (пакетно). Запускає розсилку відвідуваності для розмови. Елементи тіла: `{ churchId, conversationId, socketId, displayName?, personId? }` |
| POST | `/setName` | Публічний | — | Оновити відображуване ім'я підключення за ідентифікатором сокета. Тіло: `{ socketId, name }` |
| DELETE | `/:churchId/:conversationId/:socketId` | Публічний | — | Видалити підключення з розмови. Запускає розсилку відвідуваності |
| POST | `/tmpSendAlert` | Публічний | — | Надіслати сповіщення на підключення особи. Тіло: `{ churchId, personId }` |

## SMS

Базовий шлях: `/messaging/texting`

Керує провайдерами SMS, груповими текстовими повідомленнями та відстеженням доставки.

| Метод | Шлях | Авторизація | Дозвіл | Опис |
|--------|------|------------|-----------|-------------|
| GET | `/providers` | JWT | — | Завантажити провайдерів SMS для церкви (облікові дані приховані) |
| GET | `/status` | JWT | — | `{ enabled }` — чи має церква увімкненого провайдера SMS. Доступно будь-якому авторизованому користувачу церкви; використовується, щоб показувати опції **Text** лише тоді, коли можна надсилати тексти |
| GET | `/inboundUrl` | JWT | `texting.send` або `settings.edit` | `{ url }` — URL вхідного вебхука церкви (STOP), який потрібно вставити в налаштування провайдера |
| POST | `/inbound/:churchId/:token` | Публічний | — | Вебхук вхідних повідомлень провайдера. `token` — HMAC від ідентифікатора церкви. Відповідь, що точно збігається з ключовим словом відмови (`STOP`, `STOPALL`, `UNSUBSCRIBE`, `CANCEL`, `END`, `QUIT`, `OPTOUT`, `REVOKE`), позначає кожну відповідну особу як `optedOut` і вимикає її `allowSms`. Повертає `{ optedOut: <count> }`; інші відповіді повертають `{ optedOut: 0 }` |
| GET | `/preview/:groupId` | JWT | — | Попередній перегляд одержувачів групового тексту (кількість тих, кому можна надіслати, тих, що відмовилися, і тих, без телефону) |
| GET | `/sent` | JWT | — | Завантажити всі записи надісланих текстових повідомлень церкви |
| GET | `/sent/:id/details` | JWT | — | Завантажити надісланий текст із журналами доставки для кожного одержувача |
| POST | `/providers` | JWT | — | Зберегти провайдерів SMS (пакетно). Шифрує API-облікові дані |
| POST | `/send` | JWT | — | Надіслати SMS усім придатним учасникам групи. Тіло: `{ groupId, message }`. Поля злиття (`{{firstName}}`, `{{lastName}}`, `{{displayName}}`, `{{churchName}}`) замінюються для кожного одержувача |
| POST | `/sendPerson` | JWT | — | Надіслати SMS одній особі. Тіло: `{ personId, phoneNumber, message }`. Поля злиття замінюються, і в журнал записується вже заміщений текст |
| DELETE | `/providers/:id` | JWT | — | Видалити провайдера SMS |

## Шаблони електронних листів

Базовий шлях: `/messaging/emailTemplates`

Керує багаторазовими шаблонами електронних листів і надсиланням листів за шаблонами до груп.

| Метод | Шлях | Авторизація | Дозвіл | Опис |
|--------|------|------------|-----------|-------------|
| GET | `/` | JWT | — | Завантажити всі шаблони електронних листів церкви |
| GET | `/:id` | JWT | — | Завантажити один шаблон електронного листа за ідентифікатором |
| GET | `/sendStatus` | JWT | `groupMembers.edit` або `tasks.admin` | Статус електронної пошти групи церкви: `{ approved, paused, remaining, requested }`. Діалог Send Email у B1Admin і дія робочого процесу **Send email** використовують його, щоб попередити, коли лист не буде надіслано |
| POST | `/requestApproval` | JWT | `groupMembers.edit` | Попросити підтримку схвалити церкву для листів групам (не частіше одного разу на тиждень для кожної церкви) |
| GET | `/preview/:groupId` | JWT | — | Попередній перегляд доставки листів для групи (кількість придатних одержувачів, учасники без електронної адреси) |
| POST | `/` | JWT | — | Створити або оновити шаблони електронних листів (пакетно) |
| POST | `/send` | JWT | — | Надіслати лист за шаблоном усім учасникам групи. Тіло: `{ groupId, subject, htmlContent }` |
| DELETE | `/:id` | JWT | — | Видалити шаблон електронного листа |

### Приклад: надіслати лист групі

```
POST /messaging/emailTemplates/send
Authorization: Bearer <token>

{
  "groupId": "group-123",
  "subject": "This Week's Update - {{churchName}}",
  "htmlContent": "<p>Hello {{firstName}},</p><p>Here's what's happening this week...</p>"
}
```

```json
{
  "totalMembers": 50,
  "recipientCount": 45,
  "successCount": 44,
  "failCount": 1,
  "noEmailCount": 5
}
```

**Підтримувані поля злиття:** `{{firstName}}`, `{{lastName}}`, `{{displayName}}`, `{{email}}`, `{{churchName}}`

## Заблоковані IP-адреси

Базовий шлях: `/messaging/blockedips`

(застарілий) Блокування IP для чату прямих трансляцій. Клієнт B1App більше не викликає `POST /` — блокування IP було вилучено під час міграції до уніфікованої доставки. Маршрут `/clear` досі викликається між серверами з `StreamingServiceController` під час збереження потокових служб.

| Метод | Шлях | Авторизація | Дозвіл | Опис |
|--------|------|------------|-----------|-------------|
| POST | `/` | JWT | — | (застарілий) Зберегти заблоковані IP (пакетно). Активного клієнта немає |
| POST | `/clear` | JWT | — | Очистити всі заблоковані IP для конкретних служб. Тіло: `[{ serviceId, churchId }]` |

## Журнали доставки

Базовий шлях: `/messaging/deliverylogs`

Відстежує статус доставки надісланих повідомлень (SMS, push-сповіщень, електронних листів).

| Метод | Шлях | Авторизація | Дозвіл | Опис |
|--------|------|------------|-----------|-------------|
| GET | `/content/:contentType/:contentId` | JWT | — | Завантажити журнали доставки за типом і ідентифікатором вмісту |
| GET | `/person/:personId` | JWT | — | Завантажити журнали доставки для особи. Необов'язкові фільтри `?startDate=&endDate=` |
| GET | `/recent` | JWT | — | Завантажити останні журнали доставки для церкви. Необов'язковий `?limit=` (за замовчуванням 100) |
| GET | `/:id` | JWT | — | Завантажити журнал доставки за ідентифікатором |
