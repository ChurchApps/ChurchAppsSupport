# Кінцеві точки модуля повідомлень

<div class="article-intro">

Модуль повідомлень керує розмовами в реальному часі, чатами, push-сповіщеннями, доставкою SMS та електронної пошти, підключеннями WebSocket, приватними повідомленнями, реєстрацією пристроїв і провайдерами текстових повідомлень. Він забезпечує комунікаційний рівень, який використовують усі застосунки ChurchApps як для чату під час трансляцій, так і для асинхронних сповіщень.

</div>

**Базовий шлях:** `/messaging`

## Розмови

Базовий шлях: `/messaging/conversations`

| Метод | Шлях | Автентифікація | Дозвіл | Опис |
|--------|------|------|------|------|
| GET | `/timeline/ids?ids=` | JWT | — | Завантажити розмови за ідентифікаторами, розділеними комами, з першим і останнім повідомленнями |
| GET | `/messages/:contentType/:contentId` | JWT | — | Завантажити розмови для вмісту з посторінковими повідомленнями (`?page=&limit=`) |
| GET | `/posts` | JWT | — | Отримати розмови типу «допис» для груп поточного користувача |
| GET | `/posts/group/:groupId` | JWT | — | Отримати розмови типу «допис» для конкретної групи |
| GET | `/notes/feed?section=&limit=&before=` | JWT | — | Найновіші нотатки з усіх записів для сторінки нотаток B1 Admin. `section` має значення `people`, `groups`, `events` або `workflows` (інакше 400); `limit` за замовчуванням дорівнює 25 (максимум 100); `before` є курсором із попередньої сторінки. Кожна нотатка все одно проходить перевірку правила свого типу (дозвіл People Edit / конфіденційні нотатки, лідери групи, глядачі події, глядачі картки робочого процесу), тож викликачі бачать лише ті нотатки, які могли б відкрити. Текст нотатки обрізається до 300 символів |
| GET | `/current/:churchId/:contentType/:contentId` | Публічний | — | Отримати або створити поточну розмову для вмісту (автоматично розшифровує contentId) |
| GET | `/:churchId/:contentType/:contentId` | Публічний | — | Завантажити розмови за типом вмісту та ідентифікатором |
| GET | `/:churchId/:id` | Публічний | — | Завантажити одну розмову за ідентифікатором |
| POST | `/` | JWT | — | Створити або оновити розмови (пакетно) |
| POST | `/start` | JWT | — | Почати нову розмову з початковим коментарем |
| DELETE | `/:churchId/:id` | JWT | — | Видалити розмову |

### Контроль доступу до нотаток про людей

Розмови з `contentType: "person"` (вкладка «Нотатки» в записі людини) або `contentType: "personConfidential"` (розділ «Конфіденційні нотатки») перевіряються на кожному шляху читання та запису, зокрема й на публічних маршрутах вище, які для цих типів вмісту повертають `401`. Для `person` потрібен дозвіл MembershipApi **People / Edit**; для `personConfidential` — **People / View Confidential Notes**. Для ключів API з обмеженим доступом `people:write` охоплює обидві дії (користувач, якому належить ключ, також мусить мати відповідний дозвіл своєї ролі).

### Контроль доступу до нотаток групи та події {#group-and-event-notes-access-control}

Два інші типи нотаток перевіряються так само, на кожному шляху читання та запису (включно з публічними маршрутами вище), і ніколи не відкриті для анонімних публікацій:

- **`groupNote`** (`contentId` = ідентифікатор групи) — стрічка **нотаток лідерів** у групі. Читати чи публікувати може лише лідер цієї групи (`leaderGroupIds` у JWT). Жоден дозвіл персоналу не надає доступу, зокрема `content.edit` і дозволи на членство в групі.
- **`eventNote`** (`contentId` = ідентифікатор події) — нотатки до події в календарі. Персонал із `content.edit` або **Calendars / Admin** завжди може читати й публікувати. В іншому разі доступ визначається полями події `notesViewRole` (читання) та `notesPostRole` (публікація): `staff` (за замовчуванням, коли поле має значення `null`) не дає доступу нікому іншому, `leaders` дає доступ лідерам групи події, а `members` — членам і лідерам групи події. Подія без `groupId` доступна лише персоналу.

### Контроль доступу до нотаток картки робочого процесу

Розмови з `contentType: "workflowCard"` (нотатки на картці робочого процесу, де `contentId` є ідентифікатором завдання картки) може читати та змінювати лише той, хто має доступ до цієї картки: користувач із дозволом DoingApi **Tasks / View** або людина чи група, яким призначено картку, які її створили або яких вона стосується. Усі інші отримують `401` на кожному шляху читання, зокрема на публічних маршрутах вище. Розмова картки прикріплюється через саму картку командою `POST /doing/tasks/:id/conversation` (тіло `{ "conversationId": "..." }`; перемагає перша прикріплена розмова), яку можуть викликати редактори картки та її виконавець.

### Приклад: почати розмову

```
POST /messaging/conversations/start
Authorization: Bearer <token>

{
  "groupId": "group-123",
  "contentType": "group",
  "contentId": "group-123",
  "title": "Weekly Discussion",
  "comment": "Welcome to this week's discussion thread!"
}
```

```json
{
  "id": "conv-456",
  "churchId": "church-789",
  "contentType": "group",
  "contentId": "group-123",
  "title": "Weekly Discussion",
  "dateCreated": "2026-02-17T10:00:00.000Z",
  "visibility": "public",
  "allowAnonymousPosts": false,
  "groupId": "group-123"
}
```

## Повідомлення

Базовий шлях: `/messaging/messages`

| Метод | Шлях | Автентифікація | Дозвіл | Опис |
|--------|------|------|------|------|
| GET | `/conversation/:conversationId` | JWT | — | Завантажити всі повідомлення розмови |
| GET | `/catchup/:churchId/:conversationId` | Публічний | — | Завантажити всі повідомлення розмови (публічне наздоганяння для живого чату) |
| GET | `/:churchId/:id` | Публічний | — | Завантажити одне повідомлення за ідентифікатором |
| POST | `/` | JWT | — | Зберегти повідомлення (пакетно). Надсилає оновлення в реальному часі та запускає сповіщення. Щоб оновити наявне повідомлення, потрібно бути його автором або мати `content.edit`; збережений автор ніколи не може бути змінений |
| POST | `/send` | Публічний | — | Надіслати повідомлення (пакетно, публічно). Надсилає оновлення в реальному часі через WebSocket та запускає сповіщення |
| POST | `/setCallout` | JWT | — | (застарілий) Транслювати виноску в реальному часі. Активного клієнта немає; чат живих трансляцій більше не відображає виноски |
| DELETE | `/:churchId/:id` | JWT | — | Видалити повідомлення та транслювати видалення в реальному часі. Див. [Модерація повідомлень](#message-moderation) |

### Модерація повідомлень

Видалити повідомлення можуть:

- автор повідомлення;
- персонал із `content.edit` (у будь-якій частині церкви);
- **лідери групи** — для розмов із `contentType` `group` або `groupAnnouncement`, де `contentId` є групою, яку вони очолюють (`leaderGroupIds` у JWT).

Розмови про людей (`person` / `personConfidential`) ніколи не модеруються лідерами — для них діють дозволи на нотатки (`people.edit`, `people.viewConfidentialNotes`).

Лідери мають право лише видаляти, але не редагувати: переписувати чуже повідомлення може лише автор і персонал із `content.edit`.

### Приклад: надіслати повідомлення

```
POST /messaging/messages/send

[
  {
    "churchId": "church-789",
    "conversationId": "conv-456",
    "personId": "person-123",
    "displayName": "John Smith",
    "content": "Hello everyone!",
    "messageType": "comment"
  }
]
```

```json
[
  {
    "id": "msg-001",
    "churchId": "church-789",
    "conversationId": "conv-456",
    "personId": "person-123",
    "displayName": "John Smith",
    "timeSent": "2026-02-17T10:05:00.000Z",
    "content": "Hello everyone!",
    "messageType": "comment"
  }
]
```

## Налаштування сповіщень

Базовий шлях: `/messaging/notificationpreferences`

| Метод | Шлях | Автентифікація | Дозвіл | Опис |
|--------|------|------|------|------|

## Підключення

Базовий шлях: `/messaging/connections`

Керує підключеннями WebSocket/у реальному часі для чату, групових розмов, приватних повідомлень і живих трансляцій. Наскрізний протокол див. у [Архітектура реального часу](../../realtime.md).

| Метод | Шлях | Автентифікація | Дозвіл | Опис |
|--------|------|------|------|------|
| GET | `/:churchId/:conversationId` | Публічний | — | Завантажити всі підключення до розмови |
| POST | `/` | Публічний | — | Зареєструвати підключення (пакетно). Запускає трансляцію відвідуваності для розмови. Елементи тіла: `{ churchId, conversationId, socketId, displayName?, personId? }` |
| POST | `/setName` | Публічний | — | Оновити відображуване ім'я підключення за ідентифікатором сокета. Тіло: `{ socketId, name }` |
| DELETE | `/:churchId/:conversationId/:socketId` | Публічний | — | Видалити підключення з розмови. Запускає трансляцію відвідуваності |
| POST | `/tmpSendAlert` | Публічний | — | Надіслати сповіщення-попередження на підключення людини. Тіло: `{ churchId, personId }` |

## Текстові повідомлення

Базовий шлях: `/messaging/texting`

Керує провайдерами SMS, груповим надсиланням текстових повідомлень і відстеженням доставки.

| Метод | Шлях | Автентифікація | Дозвіл | Опис |
|--------|------|------|------|------|
| GET | `/providers` | JWT | — | Завантажити провайдерів текстових повідомлень для церкви (облікові дані приховано) |
| GET | `/status` | JWT | — | `{ enabled }` — чи має церква увімкненого провайдера текстових повідомлень. Доступно будь-якому авторизованому користувачеві церкви; використовується, щоб показувати опції **Text** лише тоді, коли тексти можна надіслати |
| GET | `/inboundUrl` | JWT | `texting.send` або `settings.edit` | `{ url }` — URL вхідного вебхука (STOP) церкви, який потрібно вставити в провайдера |
| POST | `/inbound/:churchId/:token` | Публічний | — | Вебхук вхідних повідомлень провайдера. `token` є HMAC від ідентифікатора церкви. Відповідь, що точно збігається зі стоп-словом (`STOP`, `STOPALL`, `UNSUBSCRIBE`, `CANCEL`, `END`, `QUIT`, `OPTOUT`, `REVOKE`), позначає кожну відповідну людину як `optedOut` і вимикає її `allowSms`. Повертає `{ optedOut: <count> }`; інші відповіді повертають `{ optedOut: 0 }` |
| GET | `/preview/:groupId` | JWT | — | Переглянути одержувачів групового текстового повідомлення (кількість відповідних, відмовилися, без телефону) |
| GET | `/sent` | JWT | — | Завантажити всі записи надісланих текстових повідомлень для церкви |
| GET | `/sent/:id/details` | JWT | — | Завантажити надіслане текстове повідомлення з журналами доставки для кожного одержувача |
| POST | `/providers` | JWT | — | Зберегти провайдерів текстових повідомлень (пакетно). Шифрує API-облікові дані |
| POST | `/send` | JWT | — | Надіслати SMS усім відповідним учасникам групи. Тіло: `{ groupId, message }`. Поля злиття (`{{firstName}}`, `{{lastName}}`, `{{displayName}}`, `{{churchName}}`) розв'язуються для кожного одержувача окремо |
| POST | `/sendPerson` | JWT | — | Надіслати SMS одній людині. Тіло: `{ personId, phoneNumber, message }`. Поля злиття розв'язуються, і в журнал записується вже розв'язаний текст |

## Заблоковані IP-адреси

Базовий шлях: `/messaging/blockedips`

(застарілий) Блокування IP-адрес для чату живих трансляцій. Клієнт B1App більше не викликає `POST /` — блокування IP було видалено під час міграції до уніфікованої доставки. Маршрут `/clear` досі викликається між серверами з `StreamingServiceController`, коли служби трансляції зберігаються.

| Метод | Шлях | Автентифікація | Дозвіл | Опис |
|--------|------|------|------|------|
| POST | `/` | JWT | — | (застарілий) Зберегти заблоковані IP-адреси (пакетно). Активного клієнта немає |
| POST | `/clear` | JWT | — | Очистити всі заблоковані IP-адреси для конкретних служб. Тіло: `[{ serviceId, churchId }]` |

## Журнали доставки

Базовий шлях: `/messaging/deliverylogs`

Відстежує статус доставки надісланих повідомлень (SMS, push-сповіщень, електронної пошти).

| Метод | Шлях | Автентифікація | Дозвіл | Опис |
|--------|------|------|------|------|
| GET | `/content/:contentType/:contentId` | JWT | — | Завантажити журнали доставки за типом вмісту та ідентифікатором |
| GET | `/person/:personId` | JWT | — | Завантажити журнали доставки для людини. Необов'язкові фільтри `?startDate=&endDate=` |
| GET | `/recent` | JWT | — | Завантажити останні журнали доставки для церкви. Необов'язковий `?limit=` (за замовчуванням 100) |
| GET | `/:id` | JWT | — | Завантажити журнал доставки за ідентифікатором |
