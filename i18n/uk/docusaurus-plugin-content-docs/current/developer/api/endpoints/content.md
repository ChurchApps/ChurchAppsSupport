# Ендпоінти Content

<div class="article-intro">

Модуль Content керує сторінками веб-сайту, секціями, елементами, блоками, дописами блогу, перенаправленнями, проповідями, плейлистами, потоковими службами, подіями, куративними календарями, файлами, галереями, перекладами Біблії та пошуком віршів, піснями, аранжуваннями, глобальними стилями, стоковими фотографіями та налаштуваннями. Це найбільший модуль в API. Він забезпечує роботу CMS, медіа та трансляцій, планування богослужінь і функцій Біблії у всіх застосунках ChurchApps.

</div>

**Базовий шлях:** `/content`

## Сторінки

Базовий шлях: `/content/pages`

| Метод | Шлях | Автентифікація | Дозвіл | Опис |
|--------|------|------|------|-------------|
| GET | `/:churchId/tree?url=&id=` | Публічний | — | Завантажити повне дерево сторінки (секції, елементи, блоки) за URL або ID. Внутрішні ID видаляються, якщо сторінку запитано за URL. Запити за URL враховують `pages.visibility`: сторінка з обмеженим доступом повертає `{ restricted: true, visibility }`, якщо (необов'язковий) JWT не відповідає умовам доступу |
| GET | `/public/:churchId` | Публічний | — | Список публічних сторінок (`url`, `title`, `metaDescription`); лише з `visibility = everyone` |
| GET | `/:id` | JWT | — | Отримати сторінку за ID |
| GET | `/` | JWT | — | Список усіх сторінок церкви |
| POST | `/duplicate/:id` | JWT | Content.Edit | Дублювати сторінку разом з усіма секціями та елементами |
| POST | `/temp/ai` | JWT | Content.Edit | Зберегти сторінку, згенеровану ШІ (сторінка, секції та елементи одним викликом) |
| POST | `/importTree` | JWT | Content.Edit | Створити сторінку із вкладеного дерева (`title`, `url`, `sections[].elements[]…`). Завжди вставляє сторінку в церкву викликача; ID у тілі запиту ігноруються. Рядки повинні містити свої дочірні `column`. Максимум 30 секцій / 500 елементів |
| POST | `/` | JWT | Content.Edit | Створити або оновити сторінки (пакетно) |
| DELETE | `/:id` | JWT | Content.Edit | Видалити сторінку |

### Приклад: завантаження дерева сторінки

```
GET /content/pages/abc-church-id/tree?url=/about
```

```json
{
  "name": "About",
  "url": "/about",
  "sections": [
    {
      "background": "#FFFFFF",
      "textColor": "dark",
      "elements": [
        { "elementType": "textWithPhoto", "answers": { "text": "Welcome" } }
      ]
    }
  ]
}
```

## Дописи (блог)

Базовий шлях: `/content/posts`

Дописи блогу є самостійними рядками: `title`, `slug` (унікальний для церкви), `excerpt`, `content` (тіло у форматі markdown), `authorId`, `photoUrl`, `publishDate`, `category` і `tags`. Допис вважається опублікованим, щойно задано `publishDate` і ця дата вже минула. Ендпоінти читання доповнюють кожен допис полем `authorName`, яке визначається за `authorId`. Див. [Архітектура конструктора веб-сайтів](../../architecture/website-builder#blog).

| Метод | Шлях | Автентифікація | Дозвіл | Опис |

## Перенаправлення

Базовий шлях: `/content/redirects`

URL-перенаправлення для кожної церкви (`fromPath` → `toPath`), максимум 200 на церкву. Шляхи нормалізуються (переводяться в нижній регістр, додається початковий слеш, прибирається завершальний слеш), а `fromPath` є унікальним для кожної церкви. B1App обробляє їх у разі помилок 404 і видає HTTP 308.

| Метод | Шлях | Автентифікація | Дозвіл | Опис |
|--------|------|------|------|-------------|
| GET | `/public/:churchId?path=` | Публічний | — | Визначити перенаправлення для шляху (або перелічити всі перенаправлення, якщо `path` не вказано) |
| GET | `/:id` | JWT | — | Отримати перенаправлення за ID |
| GET | `/` | JWT | — | Список усіх перенаправлень церкви |
| POST | `/` | JWT | Content.Edit | Створити або оновити перенаправлення. Відхиляє `fromPath = toPath` і дотримується обмеження в 200 рядків |
| DELETE | `/:id` | JWT | Content.Edit | Видалити перенаправлення |

| POST | `/` | JWT | — | Створити або оновити події (пакетно) |

Записи подій містять `photoUrl` (фото події у співвідношенні 16:9, яке показується на публічній сторінці події та в плитках майбутніх подій), `tags` (через кому, використовуються фільтром тегів елемента Calendar на веб-сайті) і `notesViewRole` / `notesPostRole` (`staff`, якщо `null`, `leaders` або `members`), які визначають доступ до розмови `eventNote` події. Див. [Керування доступом до нотаток групи та події](./messaging.md#group-and-event-notes-access-control). Відповіді публічних куративних подій також містять `photoUrl` і `tags` кожної події.
