# Довідник з ендпоінтів

<div class="article-intro">

У цьому розділі описано всі REST-ендпоінти, що надаються API ChurchApps. На кожній сторінці модуля перелічено всі маршрути з їхніми HTTP-методами, шляхами, вимогами до автентифікації та необхідними дозволами.

</div>

## Базова URL-адреса

| Середовище | URL |
|------------|-----|
| Локальна розробка | `http://localhost:8084` |
| Продакшн | `https://api.churchapps.org` |

## Загальні правила запитів

- **Content-Type:** Усі тіла запитів і відповідей використовують `application/json`
- **Багатоорендність:** Кожен автентифікований запит прив'язаний до `churchId`, який витягується з JWT-токена, — `churchId` не передається в URL
- **Пакетне збереження:** Більшість `POST`-ендпоінтів приймають **масив об'єктів**. API вставляє нові записи (без поля `id`) і оновлює існуючі (з полем `id`) одним викликом
- **ID:** Усі ID сутностей є UUID

### Приклад: пакетне збереження

```json
POST /membership/people
Authorization: Bearer <token>

[
  { "firstName": "Jane", "lastName": "Doe" },
  { "id": "abc-123", "firstName": "John", "lastName": "Smith" }
]
```

Перший об'єкт створюється (новий); другий оновлюється (має `id`).

## Формат відповіді

Успішні відповіді повертають JSON — або один об'єкт, або масив. Помилкові відповіді використовують стандартні коди статусу HTTP:

| Код | Значення |
|-----|----------|
| `200` | Успіх |
| `400` | Некоректний запит (помилки валідації) |
| `401` | Неавторизовано (відсутній або недійсний токен чи недостатньо дозволів) |
| `404` | Не знайдено |
| `500` | Помилка сервера |

Помилки валідації повертаються у такому вигляді:

```json
{
  "errors": [
    { "msg": "enter a valid email address", "param": "email", "location": "body" }
  ]
}
```

## Як читати таблиці ендпоінтів

На кожній сторінці модуля ендпоінти згруповано за контролерами. У таблицях використовуються такі стовпці:

| Стовпець | Опис |
|----------|------|
| **Method** | HTTP-метод (`GET`, `POST`, `DELETE`) |
| **Path** | Шлях маршруту відносно базового шляху контролера |
| **Auth** | **JWT** = потрібен Bearer-токен, **Public** = автентифікація не потрібна |
| **Permission** | Необхідний дозвіл (наприклад, `People.Edit`). `—` означає, що доступ має будь-який автентифікований користувач |
| **Description** | Що робить ендпоінт |

Контролери, що успадковують стандартний базовий клас CRUD, автоматично надають чотири ендпоінти: `GET /` (отримати список усіх), `GET /:id` (отримати за ID), `POST /` (створити/оновити) та `DELETE /:id` (видалити).

## Модуль звітності

Модуль звітності працює інакше, ніж інші модулі. Замість CRUD-операцій із базою даних він завантажує визначення звітів із JSON-файлів на диску та виконує параметризовані SQL-запити.

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| GET | `/reporting/reports/:keyName` | JWT | Завантажити визначення звіту за ключовою назвою |
| GET | `/reporting/reports/:keyName/run` | JWT | Виконати звіт і повернути результати |

Параметри звіту передаються як значення рядка запиту (наприклад, `?startDate=2024-01-01&endDate=2024-12-31`). Параметр `churchId` додається автоматично з JWT-токена. Кожне визначення звіту може задавати власні вимоги до дозволів.
