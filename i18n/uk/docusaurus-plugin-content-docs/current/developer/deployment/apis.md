# Розгортання API

<div class="article-intro">

API ChurchApps розгортаються як функції AWS Lambda за допомогою Serverless Framework. Ця сторінка описує робочий процес збірки, розгортання та налаштування для демонстраційного і продуктивного середовищ.

</div>

<div class="prereqs">
<h4>Перш ніж почати</h4>

- Налаштуйте API локально -- див. [Локальне налаштування API](../api/local-setup)
- Налаштуйте облікові дані AWS на своєму комп'ютері
- Переконайтеся, що маєте доступ до цільового облікового запису AWS

## Збірка

API збираються для продуктивного середовища за допомогою окремої конфігурації TypeScript:

```bash
npm run build:prod
```

Це використовує `tsconfig.prod.json` для компіляції проєкту для середовища виконання Lambda.

## Розгортання

Розгортання в демонстраційне середовище:

```bash
npm run deploy-demo
```

Розгортання в продуктивне середовище:

```bash
npm run deploy-prod
```

На практиці API розгортається через GitHub Actions: **Deploy Demo** запускається при кожному push до `main`, а **Deploy Prod** запускається вручну (workflow dispatch). Проміжне середовище (staging) більше не використовується.

## Міграції бази даних

**Deploy Prod** застосовує очікувані міграції бази даних як частину розгортання. Продуктивні бази даних приймають підключення лише зсередини VPC, тому одразу після `serverless deploy` робочий процес викликає Lambda `migrate` (`api-Prod-migrate`), яка виконує очікувані міграції кожного модуля та повертає `{ ok, environment, modules }`. Якщо будь-який модуль завершується з помилкою або відмовляє (наприклад, база даних без історії міграцій), завдання завершується з помилкою, щоб схема ніколи не відставала від коду. **Rollback Prod** відкочує лише код Lambda; міграції залишаються застосованими, тому їх потрібно писати як додаткові (additive). Перегляд статусу або ручне виконання міграцій описано в [Server Admin -- Database Migrations](../server-admin#database-migrations).

## Що створюється

Кожне розгортання API створює або оновлює наведені нижче функції AWS Lambda:

| Функція | Призначення |
|----------|---------|
| `web` | Обробник HTTP-запитів через API Gateway |
| `socket` | Обробник WebSocket-з'єднань |
| `timer15Min` | Заплановане завдання, що виконується кожні 30 хвилин (назва історична) |
| `timerMidnight` | Заплановане завдання, що виконується щодня опівночі |
| `migrate` | Застосовує очікувані міграції бази даних; викликається робочим процесом Deploy Prod |

## Конфігурація середовища

У розгорнутих середовищах конфігурація зчитується з **AWS SSM Parameter Store**, а не з файлів `.env`. Це дозволяє не включати секрети до пакета розгортання та змінювати конфігурацію без повторного розгортання.

:::warning
Ніколи не додавайте облікові дані продуктивного середовища до репозиторію. Уся конфіденційна конфігурація має зберігатися в AWS SSM Parameter Store і зчитуватися під час виконання.
:::

:::tip
Кожне злиття до `main` спочатку розгортається в демонстраційне середовище. Перевірте свої зміни там (наприклад, на [demo.b1.church](https://demo.b1.church)), перш ніж запускати Deploy Prod.
:::
