# Розгортання мобільного застосунку

<div class="article-intro">

Мобільні застосунки ChurchApps збираються та розгортаються за допомогою **Expo EAS Build** і поширюються через магазини застосунків. Ця сторінка охоплює збірку, надсилання та відправлення оновлень «по повітрю» (OTA) як для Android, так і для iOS.

</div>

<div class="prereqs">
<h4>Перш ніж почати</h4>

- Налаштуйте мобільний застосунок локально — див. [B1 Mobile](../mobile/b1-mobile)
- Встановіть і налаштуйте [EAS CLI](https://docs.expo.dev/eas/)
- Переконайтеся, що маєте доступ до Google Play Console (Android) та/або Apple App Store Connect (iOS)

</div>

## Збірка

### Android

```bash
npm run build:android
```

### iOS

```bash
eas build --platform ios --profile production
```

## Надсилання до магазинів застосунків

### Android -- Google Play Store

Після успішної збірки EAS файл Android (AAB) надсилається до Google Play Store через Play Console.

### iOS -- Apple App Store

Надішліть збірку для iOS безпосередньо через EAS:

```bash
eas submit --platform ios
```

## Оновлення OTA

Для змін лише в JavaScript, які не потребують перевірки в магазині застосунків, використовуйте оновлення «по повітрю» (OTA):

```bash
npm run update:production
```

Це використовує EAS Update, щоб надіслати зміни безпосередньо користувачам без повного надсилання до магазину.

:::tip
Оновлення OTA значно швидші за збірки для магазинів — зміни можуть дійти до користувачів за хвилини, а не за дні. Використовуйте їх для виправлень помилок, змін тексту та незначних змін інтерфейсу, що не стосуються нативного коду.
:::

## Номери версій

Перед створенням збірки для магазину номери версій мають бути оновлені в кількох файлах:

- `package.json`
- `app.config.js`
- `android/app/build.gradle`
- `ios/*/Info.plist`
- `ios/*/project.pbxproj`

:::warning
Якщо не оновити номери версій в усіх файлах, це призведе до помилок збірки або відхилення застосунку магазином. Перевірте кожен файл зі списку вище перед початком збірки для продакшну.
:::
