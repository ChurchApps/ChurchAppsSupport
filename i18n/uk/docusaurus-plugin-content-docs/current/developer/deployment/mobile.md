# Розгортання мобільних застосунків

<div class="article-intro">

Мобільні застосунки ChurchApps на Expo, зокрема B1 Checkin, створюються за допомогою **Expo EAS Build** або локальної збірки Gradle та розповсюджуються через магазини застосунків. На цій сторінці описано створення збірок, публікацію та надсилання оновлень «по повітрю» (OTA) для Android і iOS на прикладі B1 Checkin.

</div>

<div class="prereqs">
<h4>Перш ніж почати</h4>

- Налаштуйте застосунок локально. Див. [Мобільні застосунки](../mobile/index.md#local-setup)
- Встановіть і налаштуйте [EAS CLI](https://docs.expo.dev/eas/)
- Маєте мати доступ до Консолі Google Play (Android) та/або App Store Connect (iOS)

</div>

## Створення збірок

### Android

Релізні збірки для Android виконуються локально та підписуються релізним ключем із EAS. Завантажте його один раз командою `npx eas-cli credentials -p android` (виберіть **credentials.json: Download credentials from EAS**, тобто «Завантажити облікові дані з EAS»), а потім виконайте:

```bash
yarn build:android
```

Пакет для Google Play буде записано до `android/app/build/outputs/bundle/release/app-release.aab`. Щоб натомість створити збірку в EAS, виконайте `yarn build:android:eas`.

### iOS

Збірки для iOS завжди виконуються в EAS:

```bash
yarn build:ios
```

## Надсилання до магазинів застосунків

### Android — Google Play Store

Завантажте AAB через Консоль Play або надішліть його за допомогою EAS:

```bash
npx eas-cli submit -p android --path android/app/build/outputs/bundle/release/app-release.aab
```

### iOS — Apple App Store

Надішліть збірку для iOS безпосередньо через EAS:

```bash
eas submit --platform ios
```

## Оновлення OTA

Для змін лише в JavaScript, які не потребують перевірки в магазині застосунків, використовуйте оновлення «по повітрю» (OTA):

```bash
yarn update
```

Це працює через EAS Update: зміни надсилаються користувачам напряму, без повторної публікації в магазині.

:::tip
Оновлення OTA значно швидші за збірки для магазинів: зміни можуть дійти до користувачів за кілька хвилин, а не за кілька днів. Використовуйте їх для виправлень помилок, змін тексту та незначних змін інтерфейсу, які не стосуються нативного коду.
:::

## Номери версій

Перед створенням збірки для магазину номери версій потрібно оновити в кількох файлах:

- `package.json`
- `app.json`
- `android/app/build.gradle` (`versionName` і `versionCode`)

Номер збірки для iOS EAS збільшує автоматично.

:::warning
Якщо не оновити номери версій в усіх файлах, збірка може не вдатися або застосунок може бути відхилено в магазині. Перед створенням production-збірки двічі перевірте кожен файл зі списку вище.
:::
