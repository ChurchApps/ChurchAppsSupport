# Архітектура

<div class="article-intro">

Ці сторінки є наскрізними системними картами: вони описують, як працює кожна основна система ChurchApps від початку до кінця, через застосунки, модулі API та спільні бібліотеки, а не те, як налаштовується окремий проєкт. Читайте їх перед тим, як змінювати поведінку системи. Щоб запустити проєкт, скористайтеся розділом [Налаштування](../setup/index.md), а для довідки з кінцевих точок ендпоінтів дивіться [розділ API](../api/index.md).

</div>

## Екосистема в одному погляді

ChurchApps — це близько 20 незалежних репозиторіїв (а не монорепозиторій). Клієнтські застосунки взаємодіють з невеликим набором бекенд-API через HTTPS і WebSocket та спільно використовують код через npm-пакети, опубліковані в області `@churchapps`.

```
┌────────────────────────────────┐            ┌──────────────────────────────────────────────┐
│  Clients                       │            │  Api — core modular monolith (AWS Lambda)    │
│                                │            │                                              │
│  B1Admin    staff dashboard    │   HTTPS    │   membership    attendance    content        │
│  B1App      member portal +    │ ─────────▶ │   giving        messaging     doing          │
│             church websites    │            │                                              │
│  B1Checkin  check-in kiosk     │ ◀───WS───▶ │   one MySQL database per module (6 total)    │
│  B1Mobile   (maintenance-only) │            └──────────────────────────────────────────────┘
│  FreePlay   TV content player  │            ┌──────────────────────────────────────────────┐
└───────────────┬────────────────┘            │  LessonsApi — Lessons.church backend         │
                │                             └──────────────────────────────────────────────┘
                │  shared code via npm (@churchapps/*)
                ▼
   helpers (cross-app interfaces) · apphelper (React components) · apihelper (Express/server utilities)
```

Дві структурні засади визначають усе, що описано в цьому розділі:

1. **Модулі ізольовані.** Кожен модуль Api володіє своєю базою даних і своїми таблицями; інші модулі та застосунки отримують доступ до його даних лише через його REST-ендпоінти. Див. [Структура модуля](../api/module-structure.md).
2. **Спільний код поширюється як npm-пакети.** Застосунки не імпортують вихідний код одне одного; будь-що, що використовується повторно, переходить межі репозиторіїв через `@churchapps/helpers`, `@churchapps/apphelper` або `@churchapps/apihelper`. Див. [Спільні бібліотеки](../shared-libraries/index.md).

## Системні карти

| Сторінка | Що охоплює | Охоплює |
|------|----------------|-------------|
| [Сповіщення та нагадування](./notifications.md) | Як що-небудь повідомляє людині щось: два канали відправлення, ланцюжок ескалації каналів і механізм нагадувань | Api (messaging), B1Admin, B1App |
| [Архітектура реального часу](../realtime.md) | Фреймворк доставки через WebSocket, що лежить в основі чату, присутності та доставки всередині застосунку | Api (messaging), усі веб-застосунки |
| [Веб-push-сповіщення](../web-push.md) | Канал браузерних push-сповіщень: ключі VAPID, зберігання підписок, доставка | Api (messaging), усі веб-застосунки |
| [Пожертви](./giving.md) | Платіжні провайдери та шлюзи, потоки пожертв, фонди/пакети, вебхуки шлюзів | Api (giving), apphelper, B1App, B1Admin |
| [Реєстрації на події](./registrations.md) | Модель комерції реєстрацій: типи учасників, вибори, коди знижок, платежі через шлюз пожертв і список очікування | Api (content + giving), B1App, B1Admin |
| [Реєстрація відвідувачів](./check-ins.md) | Реєстрація на кіоску та самостійна реєстрація, модель даних відвідуваності, маршрутизація кімнат, рівень безпеки дітей, друк етикеток | B1Checkin, B1App, B1Admin, Api (attendance + membership) |
| [Конструктор веб-сайтів](./website-builder.md) | Дерево сторінок/секцій/елементів, контракт типів елементів і рендерери, блог, сторінки з обмеженим доступом, SEO та генерація за допомогою ШІ | Api (content), AskApi, helpers/apphelper, B1Admin, B1App |
| [Маршрутизація сайтів та кілька сайтів](./websites.md) | Як запит визначає церкву та конкретний сайт, модель даних із кількома сайтами `siteId` і периферійний рівень власних доменів Caddy | B1App, Api (membership + content), B1Admin |
| [Інтеграції](./integrations.md) | Поверхня розширень: OAuth, ключі API, вебхуки, провайдери контенту, MCP | Api, спільні бібліотеки, зовнішні застосунки |
| [Журнал аудиту та відмінні пакети](./audit-log.md) | Увімкнений за замовчуванням аудит кожної зміни на рівні контролера та шар пакетів, що робить імпорт і масові дії відмінними | Api (усі модулі), B1Admin, B1Transfer |
| [MinistryStuff](./ministrystuff.md) | Платний сервіс сховища та кредитів на SMS-повідомлення: ідентичність через спільний JWT, S2S через сервісний ключ, точки інтеграції провайдерів текстових повідомлень і сховища, оплата через Stripe | MinistryStuffApi, MinistryStuffWeb, Api (content + messaging), пакети texting/apihelper, B1Admin |
| [Власне сховище](./byos-storage.md) | Церкви підключають Google Drive, Dropbox, OneDrive або S3-сумісний бакет для завантажень понад безкоштовні 100 МБ: підключення через OAuth, форми завантаження для кожного провайдера, публічне перенаправлення для завантаження | Api (content + membership), пакети helpers/apphelper, B1Admin, B1App |
| [Спільний контент](./commons.md) | Спільна основа активів і подань, що лежить в основі користувацького контенту між продуктами, та єдина черга модерації лише для персоналу в B1Admin Server Admin | Api (модуль commons), B1Admin, WorshipCommons, Lessons.church, FreeShow |

:::tip
Коли зміна стосується того, як працює одна з цих систем, а не лише сторінки всередині одного застосунку, відповідну системну карту тут слід оновити в межах тієї самої роботи. Це зберігає довіру до цього розділу як до першого джерела для нових учасників.
:::
