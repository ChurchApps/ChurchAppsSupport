# Допоміжні функції

<div class="article-intro">

Пакет `@churchapps/helpers` містить базові утиліти, які використовують усі проєкти ChurchApps, як фронтенд, так і бекенд. Він не прив'язаний до конкретного фреймворку і включає поширені допоміжні функції, зокрема `DateHelper`, `ApiHelper`, `CurrencyHelper`, а також спільні інтерфейси TypeScript, які визначають структуру даних між застосунками та API.

</div>

## Хто це використовує

Кожен API ChurchApps (основний Api, AskApi і LessonsApi) та кожен веб-фронтенд (B1Admin, B1App, B1Transfer, LessonsApp) безпосередньо залежить від цього пакета. Фронтенди також отримують багато його експортів (`ApiHelper`, `DateHelper`, `UserHelper` та інші інтерфейси), які повторно експортуються через [`@churchapps/apphelper`](./app-helper). Інші спільні пакети оголошують його як peer-залежність, щоб кожен застосунок використовував рівно одну копію.

## Налаштування для локальної розробки

Цей пакет розташований у робочому просторі [Packages](https://github.com/ChurchApps/Packages) разом з іншими спільними бібліотеками:

1. Клонуйте робочий простір:

   ```bash
   git clone https://github.com/ChurchApps/Packages.git
   ```

2. Встановіть залежності в корені робочого простору:

   ```bash
   cd Packages && yarn install
   ```

3. Зберіть пакет (компілює TypeScript у `dist/`):

   ```bash
   yarn workspace @churchapps/helpers build
   ```

   Або виконайте `yarn build` у корені, щоб зібрати всі пакети в порядку залежностей.

Щоб протестувати зміни в проєкті, що їх використовує, скористайтеся тимчасовим Yarn portal -- див. [Локальна розробка з застосунком-споживачем](./index.md#local-development-against-a-consuming-app).

## Публікація

Випуски виконуються через changesets, а не через ручне підвищення версій:

1. Виконайте `yarn changeset` у корені робочого простору, оберіть `@churchapps/helpers` із відповідним типом підвищення версії та додайте згенерований файл changeset до коміту зі своєю зміною.
2. Коли будете готові до випуску, виконайте `yarn publish-all` у корені -- він підвищує версії, записує CHANGELOG, збирає пакети в порядку залежностей і публікує їх у npm.

Нові спільні інтерфейси розміщуйте в `helpers/src/interfaces/` і повторно експортуйте через головний файл пакета. Каталог типів елементів конструктора сайтів (`ElementTypes.ts` -- 35 типів зі схемами відповідей) також розташований тут; це контракт, спільний для рендерерів apphelper, форм редактора B1Admin і промптів для генерації ШІ (див. [Архітектура конструктора сайтів](../architecture/website-builder)).

:::warning
Оскільки цей пакет використовує кожен проєкт ChurchApps, зміни тут мають широкий вплив. Випуск `helpers` автоматично підвищує версії `apihelper` і `apphelper`, щоб їхні діапазони залежностей залишалися актуальними. Перед публікацією протестуйте з Yarn portal принаймні в одному API-споживачі та одному веб-застосунку-споживачі.
:::
