# Оцінка ризиків передачі даних

<div class="article-intro">

Цей документ фіксує оцінку ChurchApps щодо ризиків, пов'язаних з міжнародною передачею персональних даних з Великої Британії та ЄЕЗ до Сполучених Штатів, відповідно до вимог GDPR Великої Британії та GDPR ЄС. Це внутрішній документ відповідності, який веде ChurchApps як обробник даних.

</div>

**Останній перегляд:** квітень 2026

## 1. Деталі передачі

| Показник | Деталі |
|---|---|
| **Експортер даних** | Церкви, які використовують ChurchApps (контролери даних), розташовані у Великій Британії або ЄЕЗ |
| **Імпортер даних** | ChurchApps (обробник даних), що працює із Сполучених Штатів |
| **Категорії суб'єктів даних** | Члени церкви, відвідувачі, гості, донори, волонтери, діти (керовані батьками або адміністраторами) |
| **Категорії персональних даних** | Імена, адреси електронної пошти, номери телефонів, поштові адреси, дати народження, стать, сімейний стан, фотографії профілю, записи про пожертви, записи про відвідуваність, членство в групах, призначення волонтерів, історія повідомлень |
| **Чутливі дані** | Навмисно не збираються. Дані про здоров'я, біометричні дані або судимість не зберігаються. Дані фінансових рахунків (кредитні картки, банківські рахунки) ніколи не зберігаються ChurchApps — їх обробляє безпосередньо Stripe. |
| **Мета передачі** | Надання програмного забезпечення для управління церквою (управління членством, пожертви, облік відвідуваності, комунікації, планування волонтерів, реєстрація на заходи) |
| **Країна призначення** | Сполучені Штати |
| **Механізм передачі** | Стандартні договірні положення ЄС (SCC) та Додаток про міжнародну передачу даних Великої Британії (IDTA), включені через Додаткову угоду про обробку даних AWS |

## 2. Субобробники

| Субобробник | Роль | Розташування | Механізм передачі |
|---|---|---|---|
| **Amazon Web Services (AWS)** | Хостинг інфраструктури, зберігання даних, доставка контенту (регіон us-east-2) | Сполучені Штати | DPA AWS із SCC (автоматично включено до Умов обслуговування AWS) |
| **Stripe** | Обробка платежів за пожертви | Сполучені Штати | DPA Stripe із SCC |

Дані кредитних карток та банківських рахунків передаються безпосередньо з браузера користувача до Stripe і ніколи не зберігаються на серверах ChurchApps та не проходять через них.

## 3. Оцінка ризиків

### 3.1 Шифрування

- **Під час передачі:** Усі дані шифруються за допомогою TLS/HTTPS для всіх комунікацій між користувачами та серверами ChurchApps.
- **У стані спокою:** Дані, що зберігаються на AWS, шифруються в стані спокою за допомогою шифрування, керованого AWS.

### 3.2 Контроль доступу

- Доступ до продуктивних серверів обмежений двома особами, які є членами ради директорів ChurchApps.
- Розробники, волонтери та інші члени ради не мають доступу до продуктивних серверів або баз даних.
- Серверні бази даних розташовані за брандмауером і не доступні безпосередньо з інтернету.
- Дані церков логічно розділені — кожна церква може отримати доступ лише до власних даних через засоби контролю доступу на рівні застосунку.

### 3.3 Розділення даних

Дані розподілені між шістьма незалежними базами даних (Membership, Giving, Attendance, Messaging, Doing, Content). Компрометація однієї бази даних не розкриває дані з інших. Наприклад, база Giving містить суми та дати пожертв, але не імена чи контактні дані донорів (вони зберігаються у Membership).

### 3.4 Мінімізація даних

- Інформація про кредитні картки або банківські рахунки не зберігається (обробляє Stripe).
- Паролі зберігаються з використанням одностороннього хешування і не можуть бути відновлені.
- Церкви самостійно контролюють, які дані збирати від своїх членів.

### 3.5 Права суб'єктів даних

ChurchApps надає технічні інструменти, що дозволяють церквам виконувати запити суб'єктів даних:

- **Доступ і переносимість:** Повний експорт даних у машиночитному форматі JSON.
- **Видалення:** Анонімізація у всіх шести базах даних із заміною персональних даних на загальні значення із збереженням сукупних записів, необхідних для фінансової звітності.
- **Обмеження:** Статус неактивного членства виключає особу з пошуку, каталогу, звітів і повідомлень, зберігаючи її запис.
- **Виправлення:** Члени та адміністратори можуть редагувати персональну інформацію через застосунок.

### 3.6 Повідомлення про порушення

ChurchApps зобов'язується повідомити уражені церкви протягом 72 годин після того, як дізнається про порушення безпеки персональних даних, як зазначено в [Умовах надання послуг](https://churchapps.org/terms) (розділ 11.6).

### 3.7 Ризик доступу урядів США

Основний ризик, пов'язаний із даними, що розміщуються в США, полягає в можливому доступі державних органів США відповідно до розділу 702 FISA або Виконавчого наказу 12333. Цей ризик оцінюється як **низький** з таких причин:

- ChurchApps обробляє дані про членство та відвідуваність церков, а не дані, що мають розвідувальну цінність.
- Суб'єктами даних є члени церкви та відвідувачі — не категорії, які зазвичай є об'єктами програм спостереження.
- Не зберігаються чутливі персональні дані (про здоров'я, фінансові рахунки, політичні погляди).
- Додаткова угода про обробку даних AWS містить зобов'язання щодо запитів урядів на доступ і звітності про прозорість.
- Рамкова угода про конфіденційність даних ЄС-США (встановлена у 2023 році) забезпечує додаткові гарантії для передачі даних сертифікованим організаціям США.

## 4. Загальний висновок щодо ризиків

Ризик для суб'єктів даних від цієї міжнародної передачі оцінюється як **низький**. Поєднання:

- Стандартних договірних положень як правового механізму передачі
- Шифрування під час передачі та в стані спокою
- Суворого контролю доступу, де лише дві уповноважені особи
- Розділення даних між незалежними базами даних
- Відсутності зберігання даних фінансових рахунків
- Низької чутливості та низької розвідувальної цінності оброблюваних даних
- Технічних інструментів для реалізації всіх прав суб'єктів даних

забезпечує належні додаткові заходи, щоб переданим даним надавався рівень захисту, по суті еквівалентний тому, що гарантується в межах Великої Британії та ЄЕЗ.

## 5. Графік перегляду

Ця оцінка переглядатиметься щорічно або у разі суттєвих змін в обробці даних, субобробниках чи правовій базі, що регулює міжнародну передачу даних.
