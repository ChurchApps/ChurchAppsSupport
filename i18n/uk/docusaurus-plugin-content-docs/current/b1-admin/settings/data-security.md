# Безпека даних

<div class="article-intro">

</div>

## Обмеження зберігання конфіденційних даних

Наш перший підхід полягає в тому, щоб не зберігати жодних конфіденційних даних понад необхідне. Це означає, що ми ніколи не зберігаємо дані кредитних карток або банківських рахунків, які використовуються для здійснення пожертв. Коли користувач робить пожертву через B1.church Admin або B1, дані кредитної картки ніколи не передаються на жоден з наших серверів, а лише до вашого платіжного шлюзу (Stripe). Це означає, що у разі витоку даних жодна інформація про кредитні картки чи банківські рахунки не буде скомпрометована.

Ми також ніколи не зберігаємо паролі в нашій системі. Усі паролі обробляються за допомогою односпрямованого алгоритму хешування, під час якого частину даних знищується, що унеможливлює отримання паролів із бази даних будь-ким, навіть нами. Щоб перевірити пароль, введене значення має пройти те саме односпрямоване хешування і дати такий самий результат.

Після видалення цих двох джерел єдиними конфіденційними даними, що залишаються, є список імен та контактна інформація.

:::tip
Оскільки ChurchApps ніколи не зберігає дані кредитних карток чи банківських рахунків, навіть у найгіршому разі витоку даних фінансові реквізити не будуть розкриті. Під загрозою опиняться лише імена та контактна інформація.
:::

## Дотримання загальних найкращих практик

Ми дотримуємося галузевих найкращих практик безпеки, зокрема шифруємо всі дані, що передаються до наших серверів і від них, за допомогою HTTPS. Усі сервери розміщені в захищеному фізичному дата-центрі Amazon Web Services. Усі серверні бази даних розташовані за брандмауером і недоступні з Інтернету.

## Сегментація даних

Дані розділено на різні бази даних залежно від сфери застосування. Кожен з наших API (Membership, Giving, Attendance, Messaging, Doing та Lessons) є незалежним сховищем даних з власними базами даних. Якщо один із них буде скомпрометовано, корисність даних обмежується, якщо інші не скомпрометовано так само. Наприклад, якщо API/база даних Giving буде скомпрометовано, зловмисник потенційно може отримати доступ до списку пожертв і дат (але ніколи до даних карток чи банківських рахунків). Проте він не матиме доступу до того, які користувачі робили пожертви або для яких церков, оскільки ці дані зберігаються в окремій базі даних Membership.

:::info
Сегментація даних означає, що компрометація однієї системи не надає доступу до всіх даних церкви. Кожен API працює незалежно, зі своєю базою даних, що обмежує наслідки можливого витоку.
:::

## Обмежений доступ

Доступ до продуктивних серверів суворо обмежено адміністраторами серверів, які його потребують. Наразі це двоє осіб, які також є членами ради директорів. Розробникам, волонтерам та іншим членам ради доступ до продуктивних серверів не надається.

## Політика конфіденційності

Ваші дані належать вам і ніколи не будуть продані третім сторонам. Ознайомитися з повною політикою конфіденційності можна [тут](https://churchapps.org/privacy).

## Відповідність GDPR

ChurchApps підтримує відповідність GDPR для церков із членами у Сполученому Королівстві або Європейському Союзі. Ось як ми виконуємо ключові вимоги:

### Права суб'єктів даних

ChurchApps надає інструменти, які допомагають церквам відповідати на запити суб'єктів даних:

- **Право доступу (стаття 15)** — Члени можуть запросити копію своїх персональних даних, звернувшись до своєї церкви. Адміністратори можуть експортувати дані будь-якої особи з розділу **Управління даними** на сторінці деталей особи в B1.church Admin.
- **Право на видалення (стаття 17)** — Члени можуть самостійно запросити видалення облікового запису зі сторінки свого профілю (див. [Розгляд запитів на видалення облікового запису](../profile/account-deletion.md)) або звернувшись безпосередньо до своєї церкви. Адміністратори також можуть анонімізувати дані особи у всіх модулях із розділу **Управління даними** на сторінці деталей особи. Анонімізація замінює персональну інформацію загальними значеннями, зберігаючи сукупні записи (суми пожертв, кількість відвідувань), необхідні для фінансової звітності церкви.
- **Право на обмеження обробки (стаття 18)** — Члени можуть запросити обмеження обробки, звернувшись до своєї церкви, зокрема відмовившись від отримання повідомлень.
- **Право на переносимість даних (стаття 20)** — Адміністратори можуть експортувати персональні дані у структурованому, придатному для машинної обробки форматі JSON від імені членів, які цього запросили.

### Використання інструментів управління даними

Щоб отримати доступ до інструментів роботи з даними GDPR для окремої особи:

1. Перейдіть до розділу **People** у B1 Admin і відкрийте картку особи.
2. Натисніть **Edit**, щоб увійти в режим редагування.
3. Прокрутіть униз до розділу **Управління даними** (за замовчуванням згорнутий) і натисніть, щоб розгорнути його.
4. Скористайтеся **Export Data**, щоб завантажити файл JSON з усіма даними, збереженими про цю особу.
5. Скористайтеся **Anonymize**, щоб замінити персональну інформацію загальними значеннями. Вас попросять ввести `ANONYMIZE` для підтвердження — цю дію неможливо скасувати.

:::warning
Анонімізація є незворотною. Суми пожертв і кількість відвідувань зберігаються для цілей фінансової звітності, але всі персональні ідентифікатори (ім'я, електронна пошта, адреса тощо) видаляються і не можуть бути відновлені.
:::

### Обробка даних

ChurchApps виступає **обробником даних** від імені вашої церкви (**контролера даних**). Наша [Угода про обробку даних](https://churchapps.org/terms) визначає обов'язки кожної зі сторін, зокрема використання субобробників, процедури повідомлення про порушення безпеки та поводження з даними після припинення співпраці.

### Міжнародна передача даних

Дані ChurchApps розміщені в Amazon Web Services (AWS) у Сполучених Штатах. Міжнародна передача даних із Великої Британії та ЄС охоплюється Стандартними договірними положеннями (SCC) AWS відповідно до [Додатка про обробку даних AWS](https://aws.amazon.com/compliance/data-processing-addendum/). Додаток про обробку даних AWS автоматично включено до Умов обслуговування AWS для всіх клієнтів. Розміщення даних у ЄС не є обов'язковим, якщо застосовано відповідні механізми передачі, такі як SCC.

Докладніше про те, як оцінювалися ризики передачі, див. [Оцінку ризиків передачі](./transfer-risk-assessment.md).

### Субобробники

- **Amazon Web Services (AWS)** — Хмарне розміщення інфраструктури, зберігання даних і доставка контенту
- **Stripe** — Обробка платежів за пожертви (ChurchApps не зберігає дані карток)

:::info
Повну інформацію про те, як ми обробляємо персональні дані, див. у нашій [Політиці конфіденційності](https://churchapps.org/privacy) та [Умовах обслуговування](https://churchapps.org/terms). Якщо у вас є запитання щодо відповідності GDPR, звертайтеся до нас за адресою support@churchapps.org.
:::
