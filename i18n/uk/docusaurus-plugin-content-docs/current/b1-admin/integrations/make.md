# Make

<div class="article-intro">

[Make](https://www.make.com) (раніше Integromat) — це візуальна платформа для автоматизації робочих процесів, схожа на Zapier, але з гнучкішою логікою та нижчою вартістю при великих обсягах. Офіційний застосунок B1.church для Make дає змогу створювати «сценарії», які миттєво реагують на події B1 і записують дані назад у B1.

</div>

<div class="prereqs">
<h4>Перш ніж почати</h4>

- Обліковий запис у [Make](https://www.make.com) (безкоштовного тарифу достатньо для невеликих робочих процесів)
- Адміністратор церкви з дозволом **Edit Settings** (Редагування налаштувань) у B1Admin
- Загальне уявлення про сценарій, який ви хочете створити

</div>

## Модулі

| Тип | Що робить | Подія B1 / кінцева точка |
|---|---|---|
| **Instant Trigger** | Watch Events (Стеження за подіями) | будь-яка передплачена подія B1 (`person.created`, `donation.created`, …) |
| **Action** (Дія) | Create Person (Створити особу) | додає нову особу |
| **Action** (Дія) | Add Donation (Додати пожертву) | записує пожертву |
| **Action** (Дія) | Add Group Member (Додати учасника групи) | додає особу до групи |
| **Search** (Пошук) | Search People (Пошук людей) | знаходить людей за іменем або електронною адресою |

Миттєвий тригер дає змогу вибрати, яку подію відстежувати: один модуль-тригер на сценарій, який налаштовується для кожної події.

## Налаштування

### 1. Створіть ключ API B1

1. У B1Admin перейдіть до **Settings → Developer → API Keys** (Налаштування → Розробник → Ключі API).
2. Натисніть **New API Key** (Новий ключ API), назвіть його «Make» і надайте потрібні дозволи (scopes).
3. **Додайте `settings:write`**, якщо будь-який із ваших сценаріїв використовує миттєвий тригер: Make реєструє вебхук від вашого імені, коли сценарій вмикається.
4. Також надайте дозволи, які потрібні модулям дій (наприклад, `donations:write` для модуля Add Donation).
5. Збережіть і скопіюйте ключ `cak_…`.

### 2. Встановіть підключення

1. У Make створіть новий сценарій і перетягніть модуль-тригер **B1.church** на полотно.
2. Коли з'явиться запит, виберіть **Create a connection** (Створити підключення). Вставте ключ API в поле *API Key* і залиште *API Base URL* як `https://api.churchapps.org` (якщо ви не тестуєте на сервері staging).
3. Натисніть **Save** (Зберегти): Make перевіряє ключ, читаючи профіль вашої церкви.

Підключення зберігається у вашому обліковому записі Make і використовується повторно в різних сценаріях.

### 3. Налаштуйте тригер

1. Відкрийте налаштування модуля **Watch Events** (Стеження за подіями).
2. Виберіть потрібну подію, наприклад `donation.created`.
3. Збережіть. Make створює унікальну URL-адресу вебхука і зберігає її внутрішньо.

### 4. Додайте наступні модулі

Перетягніть на полотно будь-які з сотень модулів застосунків Make: Mailchimp, Google Sheets, Slack, HubSpot, власну HTTP-кінцеву точку тощо. Зіставте вихідні дані тригера (`event`, `churchId`, `data.id`, `data.amount`, …) з полями введення цих модулів. Модулі flatten, iterator, router та aggregator у Make дають змогу будувати розгалужені та паралельні потоки, які було б важко реалізувати в Zapier.

### 5. Увімкніть сценарій

Перемкніть **Active** (Активний) у заголовку сценарію. Make викликає `POST /membership/webhooks` у B1, щоб зареєструвати URL-адресу. Відтоді кожна відповідна подія B1 у режимі реального часу проходить через сценарій.

Вимкнення сценарію викликає `DELETE /membership/webhooks/{id}`, тож не залишається «сиротливих» підписок.

## Поширені рецепти

### Синхронізація пожертв із Google Sheet для фінансового огляду

- **Тригер** — B1: Watch Events (`donation.created`)
- **Дія** — Google Sheets: Add a Row (Додати рядок). Зіставте `data.donationDate`, `data.amount`, `data.personId`, `data.method`, `data.batchId` зі стовпцями таблиці.

### Умовне сповіщення в Slack залежно від суми пожертви

- **Тригер** — B1: Watch Events (`donation.created`)
- **Router** (Маршрутизатор):
  - Гілка A — Filter (Фільтр): `data.amount >= 1000` → Slack: публікація в `#major-gifts`
  - Гілка B — інші випадки → Slack: публікація в `#donations`

### Нова особа → CRM + вітальний лист + Slack

- **Тригер** — B1: Watch Events (`person.created`)
- **Дія** — HubSpot: Create Contact (Створити контакт)
- **Дія** — Mailgun: Send Welcome Email (Надіслати вітальний лист)
- **Дія** — Slack: сповіщення в `#new-people` (паралельно, за допомогою маршрутизатора Make)

## Як працює миттєвий тригер

Миттєвий тригер працює на основі вебхуків, а не опитування. Після активації Make викликає `POST /membership/webhooks` із згенерованою URL-адресою та обраною вами подією. Коли подія відбувається в B1, B1 надсилає POST-запит з даними на URL-адресу Make, і ваш сценарій запускається за кілька секунд. Вимкнення сценарію видаляє вебхук.

Тригер спрацьовує лише для подій, які відбуваються **поки сценарій активний**. Подій, що сталися раніше, він не обробляє.

## Обмеження та примітки

- **Одна подія на модуль Watch Events.** Щоб відстежувати кілька подій в одному сценарії, додайте кілька модулів-тригерів в окремі сценарії (або використовуйте один модуль з об'єднаним списком подій — див. нижче).
- **Перевірка підпису не надається** — Make не передає `X-B1-Signature` до сценарію; межею довіри є невгадувана URL-адреса вебхука для кожного сценарію. Це звичайна практика Make. Якщо вам потрібна явна перевірка підпису, створіть власну інтеграцію за допомогою [SDK](/docs/developer/api/webhooks#sdk-support).
- **Кількість операцій** — кожен виклик API з модуля дії зараховується до вашої квоти операцій Make і ні на що з боку B1 не впливає.

## Усунення несправностей

- **Тест підключення не проходить** — найчастіше через помилку в ключі API. Скопіюйте його ще раз із B1Admin (повний ключ показується лише один раз; якщо ви його втратили, створіть новий ключ).
- **Модуль-тригер не активується** — перевірте **Settings → Developer → Webhooks** (Налаштування → Розробник → Вебхуки) у B1Admin. Якщо після активації сценарію ви не бачите рядка «Make — &lt;event&gt;», у ключі немає `settings:write`. Оновіть ключ і знову активуйте сценарій.
- **Дія повертає `403 Forbidden`** — ключ API не має дозволу для цієї кінцевої точки. Наприклад, Add Donation потребує `donations:write`. Оновіть ключ у B1Admin і повторіть тест.

## Налаштування застосунку

Застосунок B1.church для Make має відкритий вихідний код — JSON-визначення знаходяться в репозиторії `B1Integrations/Make/`. Якщо вам потрібен модуль, якого ще немає (наприклад, нова дія для кінцевої точки, яку ми ще не охопили), відкрийте issue або pull request у цьому репозиторії.
