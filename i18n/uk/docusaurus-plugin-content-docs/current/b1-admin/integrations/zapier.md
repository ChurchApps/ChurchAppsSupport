# Zapier

<div class="article-intro">

Офіційний застосунок B1.church у Zapier дає змогу запускати Zap у відповідь на події у вашій церкві (нова людина, нове пожертвування, новий учасник групи, …) і записувати дані назад у B1. Без програмування та без власної інфраструктури: ви налаштовуєте все в редакторі Zapier із перетягуванням, вставляєте ключ API і вмикаєте Zap.

</div>

:::caution Очікування схвалення Zapier
Застосунок B1.church створено і він працює, але він ще очікує на перевірку Zapier, перш ніж з'явитися у загальнодоступному каталозі застосунків редактора Zap. До схвалення користуватися ним можуть лише запрошені облікові записи. Нижче описано, як це працюватиме після схвалення.
:::

<div class="prereqs">
<h4>Перш ніж почати</h4>

- Обліковий запис [Zapier](https://zapier.com) (безкоштовного тарифу вистачить для кількох Zap)
- Адміністратор церкви з дозволом **Edit Settings** у B1Admin (ви створите ключ API)
- Розуміння того, чого ви хочете досягти, наприклад: «коли в B1 додається людина, додати її до мого списку Mailchimp»

</div>

## Тригери та дії

| Тип | Що це | Подія B1 / кінцева точка |
|---|---|---|
| **Тригер** | Нова людина | `person.created` |
| **Тригер** | Оновлена людина | `person.updated` |
| **Тригер** | Нове пожертвування | `donation.created` |
| **Тригер** | Новий учасник групи | `group.member.added` |
| **Тригер** | Нове надсилання форми | `form.submission.created` |
| **Дія** | Створити людину | додає нову людину |
| **Дія** | Додати пожертвування | записує пожертвування |
| **Дія** | Додати учасника групи | додає людину до групи |
| **Дія** | Знайти людину | шукає людину за ідентифікатором, електронною адресою або іменем; завершує завдання з помилкою, якщо нікого не знайдено |

Їх можна вільно поєднувати з будь-яким із понад 7 000 застосунків, які підтримує Zapier.

## Налаштування

### 1. Створіть ключ API для B1

1. У B1Admin перейдіть до **Settings → Developer → API Keys**.
2. Натисніть **New API Key**, дайте ключу назву на кшталт «Zapier» і виберіть області доступу (scopes), потрібні для Zap.
3. **Важливо:** тригери Zapier від вашого імені реєструють вебхук у момент увімкнення Zap, для чого потрібна область доступу **`settings:write`**. Завжди включайте `settings:write`, якщо будь-який із ваших Zap використовує тригер B1.
4. Також надайте області доступу, потрібні для дій, наприклад дії «Add Donation» потрібна `donations:write`, а «Create Person» потребує `people:write`.
5. Збережіть. Повний ключ `cak_…` показується **лише один раз**, скопіюйте його.

### 2. Підключіть Zapier до B1

1. У Zapier створіть новий Zap.
2. Коли ви вперше вибираєте тригер або дію B1, Zapier попросить вас **Sign in to B1.church**.
3. Вставте ключ API з кроку 1 і натисніть **Yes, Continue**. Zapier перевірить його для вашої церкви.

Підключення зберігається в Zapier і використовується кожним Zap у вашому обліковому записі.

### 3. Побудуйте Zap

Виберіть тригер, а потім додайте один або кілька кроків-дій. Приклади наведено нижче.

## Типові сценарії

### Додавати нових людей із B1 до Mailchimp

- **Тригер** — B1: New Person
- **Дія** — Mailchimp: Add/Update Subscriber. Зіставте `name__first`, `name__last` і `contactInfo__email` з B1 з полями First Name, Last Name і Email у Mailchimp.

### Публікувати пожертвування в каналі Slack картką з більшими можливостями, ніж вбудований конектор

- **Тригер** — B1: New Donation
- **Дія** — Slack: Send Channel Message. Створіть будь-який макет, зокрема кнопки, вкладення тощо, які не може створити вбудований [конектор Slack](./slack-discord).

### Додавати нових учасників груп до Google Group

- **Тригер** — B1: New Group Member (фільтрований за конкретним `groupId`)
- **Дія** — Filter by Zapier: продовжувати лише тоді, коли група B1 є тією, яка вас цікавить
- **Дія** — B1: Find Person (використайте `personId` з тригера, щоб отримати електронну адресу)
- **Дія** — Google Groups: Add Member

### Надсилати надіслані форми до трекера проєктів

- **Тригер** — B1: New Form Submission
- **Дія** — Notion / Linear / Asana / Trello: Create page / issue / task

## Як працюють тригери

Тригери є **REST hooks**, а не опитуванням. Zapier не звертається до B1 кожні 15 хвилин. Коли ви вмикаєте Zap, Zapier просить B1 зареєструвати вебхук, що вказує на приватну адресу Zapier. Коли подія відбувається, B1 надсилає дані Zapier, і ваш Zap запускається **протягом кількох секунд**. Коли ви вимикаєте Zap, Zapier просить B1 видалити вебхук, тож підписки не залишаються без власника.

Це означає, що тригер спрацьовує лише для подій, які відбуваються **після** увімкнення Zap. Бекфілу немає: увімкнення Zap не відтворює вчорашні пожертвування.

## Обмеження та примітки

- **Кілька Zap з одним тригером** кожен реєструє власний вебхук B1. Конфлікту немає, але варто знати про це, якщо ви переглядаєте **Settings → Developer → Webhooks** і дивуєтеся, чому там є три однакові рядки `Zapier — donation.created`.
- **Тестові дані в налаштуванні Zap**: під час побудови Zap Zapier просить зразкові дані для зіставлення полів. Він візьме найновішу відповідну подію з B1, якщо така є; інакше використає синтетичний зразок із визначення застосунку.
- **Помилки дій відображаються як помилки Zap** в історії завдань Zapier. Типова причина: ключ API без потрібної області доступу (наприклад, дія «Add Donation» потребує `donations:write`). Створіть ключ заново з правильними областями доступу та повторно підключіть його в Zapier.
- **Квоти вихідних викликів API**: кожен виклик API B1 з дії зараховується до квоти завдань Zapier і ні до чого на боці B1.

## Усунення несправностей

- **«Authentication failed»** під час підключення: ключ API невірний, відкликаний або не має областей доступу, потрібних для Zap. Створіть його заново в B1Admin щонайменше з `settings:write` та областями доступу до ресурсів, яких торкається Zap, а потім оновіть підключення.
- **Тригер ніколи не спрацьовує**: переконайтеся, що вебхук справді зареєстровано. У B1Admin **Settings → Developer → Webhooks** має містити рядок з назвою «Zapier — &lt;event&gt;». Якщо його немає, ймовірно, у ключі API не було `settings:write` під час увімкнення Zap. Виправте ключ, вимкніть Zap і знову увімкніть.
- **Тригер спрацьовує двічі**: Zapier інколи повторно надсилає подію, якщо підтвердження було втрачено. Якщо потрібна строга деduplікація, використайте крок «Filter by Zapier» за унікальним ідентифікатором (наприклад, `id` людини).
