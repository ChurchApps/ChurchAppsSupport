# Google Таблиці

<div class="article-intro">

**B1 Export** — офіційна надбудова Google Таблиць для B1.church. Вона додає бічну панель до будь-якої таблиці, яка експортує дані про людей, пожертви, групи або відвідуваність з вашої церкви B1 до іменованих аркушів — за запитом, одним клацанням. Надбудова працює повністю в обліковому записі Google користувача; окрім викликів API лише для читання, які виконує кожен експорт, вона ніяк не взаємодіє з серверами ChurchApps.

</div>

<div class="prereqs">
<h4>Перш ніж почати</h4>

- Обліковий запис Google з правом редагування таблиці, до якої ви хочете експортувати дані
- Адміністратор церкви (або особа з правом читання даних, які ви хочете експортувати), яка може створити ключ API B1
- Надбудова B1 Export, встановлена з Google Workspace Marketplace

</div>

## Що експортується

| Пункт меню | Аркуш | Дані |
|---|---|---|
| Export People | `B1 People` | ID, відображуване ім'я, ім'я, прізвище, електронна пошта, статус членства |
| Export Donations | `B1 Donations` | ID, ID особи, дата, сума, спосіб, ID пакета |
| Export Groups | `B1 Groups` | ID, назва, категорія, кількість учасників |
| Export Attendance | `B1 Attendance` | ID, ID особи, дата відвідування, ID служіння, ID групи |

Кожен експорт **замінює** вміст свого іменованого аркуша: повторний запуск експорту створює актуальний знімок, а не додає рядки. Інші аркуші таблиці не змінюються.

## Налаштування

### 1. Створіть ключ API B1 з відповідними дозволами

1. У B1Admin перейдіть до **Settings → Developer → API Keys**.
2. Натисніть **New API Key**, назвіть ключ "Sheets Export" і надайте дозволи **read** для того, що плануєте експортувати:
   - `people:read` для експорту людей
   - `donations:read` для пожертв
   - `groups:read` для груп
   - `attendance:read` для відвідуваності
3. Ключ, призначений лише для експорту, **не** потребує `settings:write` — цей дозвіл потрібен лише для інтеграцій, які реєструють вебхуки (Zapier / Make). Тримайте цей ключ вузьким, з мінімальними правами.
4. Збережіть і скопіюйте ключ `cak_…`.

### 2. Встановіть надбудову

1. Відкрийте таблицю, до якої хочете експортувати дані.
2. **Розширення → Додатки → Отримати додатки**.
3. Знайдіть **B1 Export** і встановіть її. Google попросить надати доступ до ваших таблиць і до зовнішніх HTTP-запитів (щоб надбудова могла викликати API B1).

Після встановлення пункт **B1 Export** з'являється в меню **Розширення** кожної таблиці, яку ви відкриваєте з цим обліковим записом Google.

### 3. Підключіть ключ

1. **Розширення → B1 Export → Connect…** (або **B1 Export → Connect…** з панелі меню після першого відкриття).
2. Вставте ключ API на бічній панелі, залиште Base URL як `https://api.churchapps.org` (якщо ви не тестуєте на тестовому сервері) і натисніть **Save**.
3. Натисніть **Test Connection** — зелений напис "Connection OK" підтверджує, що ключ працює.

Ключ зберігається у **властивостях користувача** (`PropertiesService.getUserProperties()`): він прив'язаний до вашого облікового запису Google, ніколи не записується в таблицю і ніколи не видно іншим редакторам таблиці.

## Запуск експорту

Можна одним із двох способів:

- **З меню** — **Розширення → B1 Export → Export People** (або Donations / Groups / Attendance)
- **З бічної панелі** — відкрийте бічну панель (Connect…) і натисніть відповідну кнопку набору даних

Спливаюче повідомлення з'являється після завершення, наприклад: "_N_ row(s) written to 'B1 People'."

## Побудова звітів поверх даних

Експортовані аркуші — це звичайні дані Google Таблиць. Створюйте власну аналітику, посилаючись на ці аркуші:

- Підсумковий **аркуш** з формулою `=SUMIF('B1 Donations'!E:E, "card", 'B1 Donations'!D:D)` для підсумовування пожертв карткою
- **Відфільтрований вигляд** лише членів із формулою `=FILTER('B1 People'!A:F, 'B1 People'!F:F = "Member")`
- **Діаграма** трендів відвідуваності на основі аркуша `B1 Attendance`

Повторний запуск експорту оновлює базовий аркуш, і ваші формули оновлюються автоматично.

## Планування регулярних експортів

За замовчуванням надбудова працює за запитом. Для щотижневих або щомісячних експортів використовуйте вбудовані в Apps Script тригери за часом:

1. **Розширення → Apps Script** у таблиці (відкриває прив'язаний скрипт надбудови).
2. Натисніть значок **⏰ Triggers** на лівій бічній панелі.
3. **Add Trigger** для `exportPeople` (або будь-якої іншої функції експорту) — оберіть *Time-driven*, *Week timer*, наприклад, *Every Monday 6am*.

Експорт виконується у фоновому режимі від імені вашого облікового запису Google. Якщо ключ API буде замінено або відкликано, тригер надішле вам електронний лист під час наступної помилки.

## Дозволи та конфіденційність

- Надбудова запитує лише `spreadsheets.currentonly` (вона може працювати лише з таблицею, яку відкрито) та `script.external_request` (щоб `UrlFetchApp` міг викликати API B1). Вона **не** має доступу до вашого Диска, Gmail чи інших даних Google.
- Ключ API B1 зберігається окремо для кожного користувача: інші редактори тієї самої таблиці не можуть його побачити.
- Усі виклики API B1 виконуються через HTTPS з заголовком `Authorization: Bearer cak_…`.

## Усунення несправностей

- **"No API key set"** — відкрийте **Розширення → B1 Export → Connect…** і вставте ключ.
- **"B1 rejected the API key (401)"** — ключ відкликано або він невірний. Створіть новий ключ і вставте його знову.
- **"This API key lacks permission for /giving/donations (403)"** — ключ не має дозволу `donations:read`. Оновіть дозволи ключа в B1Admin.
- **Аркуш не оновлюється** після запуску — переконайтеся, що дивитеся на *правильну* назву аркуша (`B1 People` тощо). Експорт створює аркуш, якщо його не було.
- **"Quota exceeded"** — Apps Script встановлює для кожного користувача щоденні квоти на `UrlFetchApp` (зазвичай кілька тисяч викликів на день). Великій церкві з багатьма записами може знадобитися розподілити експорти на кілька днів або використати [Make](./make) чи власну інтеграцію для синхронізації великих обсягів даних.

## Налаштування надбудови

Надбудова має відкритий код — проєкт Apps Script розташовано в репозиторії `B1Integrations/GoogleSheetsAddon/`. Якщо вам потрібен стовпець, якого ми не експортуємо, додатковий набір даних або інший формат виводу, створіть issue або pull request у цьому репозиторії.
