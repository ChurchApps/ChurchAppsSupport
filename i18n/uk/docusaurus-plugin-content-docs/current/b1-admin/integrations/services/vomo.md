# VOMO

<div class="article-intro">

VOMO — це платформа для залучення волонтерів: люди записуються на проєкти, реєструються на кіоску та накопичують години. Якщо ви використовуєте VOMO для планування волонтерів, а B1 для облікових записів людей, Zapier може синхронізувати членство та реєстрації між ними, щоб дані в обох системах не розходилися.

</div>

<div class="prereqs">
<h4>Перед початком роботи</h4>

- Обліковий запис [VOMO](https://vomo.org) на тарифі, який відкриває доступ до Zapier (якщо не впевнені, уточніть у служби підтримки VOMO)
- Обліковий запис [Zapier](https://zapier.com)
- Користувач B1Admin з дозволом **Edit Settings**

</div>

## Що можна налаштувати

Застосунок VOMO для Zapier надає чотири миттєві тригери та чотири дії. Найпоширеніші сценарії для церков:

| Напрямок | Тригер | Дія |
|---|---|---|
| VOMO → B1 | VOMO Membership (created) | B1: Find Person → Create Person (якщо особа нова) |
| VOMO → B1 | VOMO Kiosk check-in | B1: Add Group Member до групи "Currently Serving" або запис як відвідування |
| B1 → VOMO | B1 `person.created` | VOMO: Find Organizer (за електронною поштою); інакше власний крок |
| Будь-який | VOMO Participation (signups) | B1: Add Group Member до групи конкретного проєкту |

Дії VOMO обмежені **створенням чернеток проєктів** та **пошуком** наявних організаторів і проєктів. Наразі немає дії «додати цю особу до проєкту VOMO». Найцікавіше налаштування здебільшого стосується напрямку VOMO → B1.

## Налаштування

### 1. Створіть ключ API B1

**Settings → Developer → API Keys → New API Key**. Області доступу (scopes):

- `people:read`, `people:write` — для пошуку та створення волонтерів як людей у B1
- `groups:write` — для додавання їх до груп служіння
- (Необов'язково) `attendance:write`, якщо ви обліковуєте реєстрації на кіоску як відвідування

### 2. Побудуйте Zap для синхронізації членства

1. **Тригер** — VOMO: Membership (event = `created`).
2. **Дія** — B1.church: Find Person, пошук за електронною поштою.
3. **Фільтр / Гілка** — розгалуження залежно від того, знайдено особу чи ні:
   - Не знайдено → B1.church: Create Person, потім Add Group Member до відповідної групи волонтерів.
   - Знайдено → B1.church: Add Group Member напряму.
4. Увімкніть. Нові волонтери VOMO тепер з'являтимуться в B1 з потрібним членством у групах.

### 3. (Необов'язково) Побудуйте Zap для реєстрації на кіоску

1. **Тригер** — VOMO: Kiosk
2. **Дія** — B1.church: Find Person (за електронною поштою)
3. **Дія** — на ваш вибір:
   - *Якщо облік як відвідування* — Webhooks by Zapier надсилає POST на кінцеву точку `/attendance/visits` в B1 (застосунок B1 для Zapier поки що не має окремої дії *Record Attendance*). [Ключ API B1](/docs/developer/api/api-keys) передається в заголовку `Authorization: Bearer cak_…`.
   - *Якщо як членство в групі* — B1.church: Add Group Member з групою "Currently Serving (Today)", а другий Zap пізніше протягом дня видаляє їх через запланований процес очищення.

## Типові сценарії

### Синхронізація груп за проєктами

- **Тригер** — VOMO: Participation (created)
- **Дія** — Filter by Zapier за ідентифікатором проєкту, потім
- **Дія** — B1.church: Add Group Member до групи B1, назва якої відповідає проєкту VOMO.

Коли проєкт VOMO завершується, вручну очистіть групу B1 (або поєднайте це з тригером *Participation deleted*, який видаляє учасників).

### Надсилання SMS-повідомлення «Дякуємо за реєстрацію»

Додайте в той самий Zap ланцюжок VOMO Participation → Clearstream Send Text або Text In Church Send Message. Обидві мають вбудовані дії Zapier. Див. [Clearstream](./clearstream) та [Text In Church](./text-in-church).

### Виявлення відтоку

Запускайте щоденний тригер *Schedule* у Zapier, який викликає Find Organizer у VOMO для списку людей із B1, що приєдналися до команди служіння цього місяця. Якщо VOMO повертає «not found», ця особа не активувала VOMO і їй потрібне нагадування.

## Обмеження та примітки

- **Електронна пошта — ключ з'єднання.** Дані VOMO містять електронну пошту користувача, але не ідентифікатор особи в B1. Донори, які використовують різні адреси в кожній системі, створюватимуть дублікати.
- **Немає дії «Add to Project» у застосунку VOMO для Zapier.** Якщо потрібно зараховувати людей з B1 до проєкту VOMO, слід надсилати POST до REST API VOMO з кроку *Webhooks by Zapier*. Це власна інтеграція.
- **Безкоштовні або нижчі тарифи VOMO можуть не включати Zapier.** Уточніть у служби підтримки VOMO, перш ніж обіцяти дату запуску.

## Усунення несправностей

- **Тригер ніколи не спрацьовує** — миттєвим тригерам VOMO потрібно, щоб токен API залишався дійсним. Повторно протестуйте Zap; якщо токен було оновлено, підключіть VOMO знову.
- **B1 *Add Group Member* завершується з помилкою 422** — ідентифікатора групи, вказаного в дії, не існує. Відкрийте **B1Admin → Groups**, натисніть на групу та скопіюйте сегмент ідентифікатора з URL у крок Zap.
- **Дублікати людей у B1 від одного волонтера VOMO** — ймовірно, він зареєструвався з іншою адресою, ніж та, що вже була в B1. Або стандартизуйте адреси, або додайте до Zapier *Path* пошук за номером телефону перед створенням.
