# Donorbox

<div class="article-intro">

Якщо ваша церква приймає пожертви через Donorbox, але веде облік людей і виписок у B1, ви можете налаштувати миттєві тригери Donorbox у Zapier, які створюватимуть відповідні записи пожертв у B1, а також створюватимуть донора як особу в B1, якщо його там ще немає. Без ручного звіряння і без щомісячного експорту.

</div>

<div class="prereqs">
<h4>Перш ніж почати</h4>

- Обліковий запис [Donorbox](https://donorbox.org) з принаймні однією кампанією
- Обліковий запис [Zapier](https://zapier.com)
- Користувач B1Admin з дозволом **Edit Settings**

</div>

## Що можна налаштувати

| Напрямок | Тригер Donorbox | Дія в B1 |
|---|---|---|
| Donorbox → B1 | New or Updated Donation (миттєво) | Find Person → Add Donation |
| Donorbox → B1 | New or Updated Donor | Create Person |
| Donorbox → B1 | New or Updated Plan (повторювані платежі) | Find Person → Add Donation (використовуйте id плану як примітку) |

Donorbox публікує свої тригери як **миттєві**. Вони спрацьовують протягом кількох секунд після справжньої пожертви, без затримки на опитування.

## Налаштування

### 1. Створіть ключ API у B1

У B1Admin перейдіть до **Settings → Developer → API Keys → New API Key**. Області доступу:

- `people:read` — щоб знайти донора за електронною адресою
- `people:write` — щоб створити його, якщо він новий
- `donations:write` — щоб записати пожертву

Тригери в цьому напрямку належать Donorbox, а не B1, тому тут `settings:write` не потрібен.

### 2. Створіть Zap «запис пожертви»

1. **Тригер** — Donorbox: New Donation. Підключіть його за допомогою ключа API Donorbox (у Donorbox: *Account → Profile → API Settings*).
2. **Дія** — B1.church: Find Person. Зіставте електронну адресу донора з тригера з полем пошуку *Email*.
3. **Дія** — Filter by Zapier (необов'язково): продовжувати, лише якщо донора не знайдено, а потім…
4. **Дія** — B1.church: Create Person. Зіставте ім'я, прізвище та електронну адресу, щоб донор став учасником, а не лише записом про пожертву.
5. **Дія** — B1.church: Add Donation. Зіставте:
   - Amount → `data.amount`
   - Donation Date → дату пожертви з тригера
   - Fund → оберіть фонд B1, що відповідає кампанії Donorbox (Zapier дозволяє змінювати фонд залежно від фільтра або кроку форматування)
   - Method → «Online»
   - Notes → ідентифікатор транзакції Donorbox (зручно для звіряння)

Увімкніть Zap. Наступна жива пожертва через Donorbox автоматично з'явиться в **B1Admin → Donations**.

## Типові рецепти

### Один Zap на фонд

Якщо ви проводите кілька кампаній Donorbox, які відповідають окремим фондам B1, найзручніше створити один Zap на кампанію з фільтром *campaign* від Donorbox на початку. Тоді зіставлення фонду жорстко задано, і крок пошуку можна пропустити.

### Оновлені пожертви як виправлення

*New or Updated Donation* від Donorbox спрацьовує й під час редагування. Використовуйте крок Zapier *Path* за полем `event_type`, щоб розгалузити процес: «new» → Add Donation, «updated» → Find Donation + Update. Зауважте: у застосунку B1 для Zapier поки немає дії Update Donation, тож наразі журналюйте події «updated» у канал Slack для ручного перегляду.

### Надсилання змін повторюваних планів у канал Slack

- **Тригер** — Donorbox: New or Updated Plan
- **Дія** — Slack: Send Message до `#donations` (наприклад, «План змінено — щомісячна пожертва Сари тепер становить $200»)

## Обмеження та примітки

- **Зіставляйте донорів за електронною адресою.** Donorbox не передає ідентифікатор особи B1; єдиний надійний ключ для зв'язування — електронна адреса. Донори, які жертвують з іншою адресою, створять нову особу в B1, тому під час щомісячного звіряння шукайте такі випадки.
- **Повернення коштів окремо не відображаються.** Donorbox надсилає оновлення статусу для тієї самої пожертви. У застосунку B1 для Zapier поки немає дії *Update Donation*; безпечний підхід на сьогодні — журналювати події повернення поза системою та вручну коригувати пожертву.
- **Спочатку протестуйте в пісочниці Donorbox**, щоб не створювати фіктивні пожертви уробочій B1. Donorbox надає тестові облікові дані, окремі від бойових.

## Усунення несправностей

- **Попередження «Person not found» під час кожного запуску** — це нормально, якщо ви розташували кроки так, щоб *Create Person* виконувався у гілці «не знайдено». Якщо крок Create Person теж ніколи не виконується, перевірте, чи має ключ API дозвіл `people:write`.
- **Сума пожертви у 100 разів більша або менша за очікувану** — Donorbox в одних варіантах даних надсилає суми в центах, в інших — у доларах. За потреби використайте крок *Formatter by Zapier — Numbers*, щоб поділити на 100.
- **Дублікати пожертв від одного внеску** — Donorbox спрацьовує і на *New Donation*, і на *Updated Donation*. Або відфільтруйте за `event_type = "donation.succeeded"`, або створіть два Zap з неперетинними фільтрами.
