# Checkr

<div class="article-intro">

[Checkr](https://checkr.com) виконує фонові перевірки персоналу та волонтерів, і ця потреба є майже в кожної церкви, яка веде дитячу чи молодіжну програму. B1 **не має вбудованої функції перевірки в фоновому режимі**. Замовлення перевірок, відстеження результатів і контроль відповідності всі відбуваються в Checkr. Наведений нижче рецепт лише пов'язує події B1 із Checkr. Checkr не має застосунку для Zapier, але [інтеграція Checkr у Make.com](https://www.make.com/en/integrations/checkr) перевірена і надає дії, потрібні для запуску перевірки з події B1.

</div>

<div class="prereqs">
<h4>Перш ніж почати</h4>

- Обліковий запис [Checkr](https://checkr.com) з доступом до API та принаймні одним налаштованим пакетом перевірок
- Обліковий запис [Make](https://www.make.com)
- Користувач B1Admin із дозволом **Редагування налаштувань**

</div>

## Що можна налаштувати

Застосунок Checkr у Make має 1 тригер і 6 дій:

| Напрямок | Тригер B1 / Make | Дія |
|---|---|---|
| B1 → Checkr | B1 `group.member.added` (відфільтровано за групою волонтерів) | Checkr: Create Candidate → Create Background Check Invitation |
| Checkr → B1 | Вебхук Checkr (подія запрошення або звіту) | B1: оновлення запису особи (наприклад, додавання мітки «Checkr cleared») |

Дії Checkr у Make: Create Candidate, Create Background Check Invitation, Get Candidate, Get Report, Get Report's ETA та Get an Invitation. Крім того, є 4 модулі пошуку.

## Налаштування

### 1. Створіть ключ API для B1

**Settings → Developer → API Keys → New API Key**:

- `settings:write` для вебхука тригера
- `people:read`, щоб знаходити ім'я та електронну пошту особи під час запуску перевірки
- (Необов'язково) `people:write`, якщо хочете записувати статус звіту назад як користувацьке поле або мітку

### 2. Створіть у Make сценарій «запуск перевірки під час реєстрації волонтера»

1. **Тригер**: B1.church: Watch Events (`group.member.added`).
2. **Фільтр**: продовжувати лише тоді, коли `data.groupId` відповідає вашій групі «Children's Volunteers» (або подібній).
3. **Дія**: B1.church: Find Person (за `data.personId`), щоб отримати електронну адресу та ім'я й прізвище.
4. **Дія**: Checkr: Create Candidate. Зіставте ім'я, прізвище та електронну адресу з кроку 3.
5. **Дія**: Checkr: Create Background Check Invitation. Зіставте ідентифікатор нового кандидата з кроку 4 з полем *candidate_id*. Виберіть пакет перевірок (наприклад, `tasker_standard` або той, який доступний у вашому обліковому записі).
6. (Необов'язково) **Дія**: Slack: повідомте координатора з безпечного служіння, що перевірку розпочато.

Увімкніть сценарій. Нові волонтери цільової групи автоматично отримають запрошення Checkr електронною поштою. Вони заповнюють його на телефоні або ноутбуці, а Checkr проводить перевірку.

### 3. (Необов'язково) Отримання звіту назад

1. **Тригер**: Checkr: Watch Events (вебхук). Після активації Make реєструє вебхук у Checkr.
2. **Фільтр**: продовжувати лише тоді, коли `event_type = report.completed`.
3. **Дія**: Checkr: Get Report (використовуйте ідентифікатор звіту з вебхука).
4. **Дія**: B1.church: Find Person (за електронною адресою кандидата).
5. **Умовна дія**: Slack або електронна пошта: повідомте координатора зі статусом `clear`, `consider` або `suspended`.

Примітка: наразі в B1 немає вбудованого поля «статус фонової перевірки». Практичні варіанти такі: (а) публікувати результат у приватному каналі Slack для перегляду, (б) записувати його в Google Sheets для аудиту або (в) додавати особу до групи B1 «Cleared volunteers» у разі статусу `clear`.

## Типові рецепти

### Повторна перевірка волонтерів раз на 2 роки

Поєднайте наведене вище з тригером розкладу в Make:

- **Тригер**: Make: Schedule (щомісяця)
- **Дія**: B1.church: List Group Members для групи «Cleared volunteers»
- **Дія**: фільтр Make: дата проходження перевірки старша за 22 місяці
- **Дія**: Checkr: Create Background Check Invitation (так само, як у початковому процесі)

### Блокування доступу етапу 1, доки перевірка не завершиться

Якщо ваша церква використовує членство в групах B1 для обмеження доступу (наприклад, у графіках служіння відображаються лише члени групи «Cleared»), тримайте нових волонтерів у проміжній групі, доки подія Checkr `report.completed` не змінить їхній статус.

## Обмеження та примітки

- **Checkr працює лише в США** для більшості пакетів перевірок. Церквам в Австралії, Великій Британії та Канаді потрібна альтернатива.
- **Ціна** визначається за перевірку. Кожне створення запрошення в Make спричиняє реальну перевірку, тож спочатку протестуйте в пісочниці або тестовому обліковому записі Checkr. Застосунок Checkr у Make використовує облікові дані, які ви передаєте в підключенні, тому заміна даних перемикає між пісочницею та робочим режимом.
- **Доступ до API Checkr залежить від тарифного плану.** Менші облікові записи Checkr можуть мати лише інтерфейс без API. Щоб увімкнути API, зверніться до Checkr.

## Усунення несправностей

- **Create Candidate завершується з помилкою `403`**: токен API Checkr доступний лише для читання або не має потрібних дозволів облікового запису. Випустіть його знову в панелі Checkr з правом запису.
- **Запрошення не надходить**: перевірте електронну адресу кандидата на кроці 3. У B1 для цієї особи може бути порожнє поле електронної пошти. Додайте фільтр обов'язкової електронної пошти перед кроком Checkr.
- **Тригер вебхука не спрацьовує**: реєстрація вебхука в Checkr іноді мовчки не вдається, якщо ваш обліковий запис Make не має платного тарифу, що підтримує вихідні вебхуки. Перевірте на сторінці *Webhooks* панелі Checkr, чи вказано URL Make.
