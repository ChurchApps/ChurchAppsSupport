# Slack та Discord

<div class="article-intro">

Надсилайте зручні для читання сповіщення з B1 безпосередньо в канал Slack або Discord: про нових людей, пожертви, реєстрації в групи, надіслані форми, події календаря тощо. Не потрібен сторонній обліковий запис і не потрібно підтримувати Zap. B1 перетворює події на повідомлення для чату й сам надсилає їх на URL-адресу вебхука каналу.

</div>

<div class="prereqs">
<h4>Перш ніж почати</h4>

- Вам потрібен дозвіл **Edit Settings** у B1Admin
- Адміністратор вашого робочого простору Slack або сервера Discord, який створить Incoming Webhook для каналу
- Визначте, в який канал надсилати сповіщення (можна використовувати один канал для кількох типів подій або розподілити їх між кількома каналами)

</div>

## Як це працює

У B1 є вбудований **тип з'єднання** (Connector Type) для платформ чату. Коли ви створюєте вебхук із типом **Slack** або **Discord**, механізм вебхуків виконує звичайні дії: доставку, повторні спроби та підписані заголовки. Проте тіло запиту змінюється: замість стандартного конверта B1 `{event,churchId,data}` надсилається коротке повідомлення у форматі `{text}` (Slack) або `{content}` (Discord), яке очікують ці сервіси.

B1 не звертається до Slack окремо для кожної церкви, а використовує наявний потік вихідних вебхуків. Нічого нового розгортати не потрібно, і нічого додатково сплачувати не треба.

## Slack: покроково

### 1. Отримайте Incoming Webhook URL для Slack

1. Відкрийте [api.slack.com/apps](https://api.slack.com/apps) у робочому просторі Slack, для якого хочете отримувати сповіщення.
2. Натисніть **Create New App → From scratch**, назвіть застосунок, наприклад «B1 Notifications», і виберіть робочий простір.
3. У лівій навігації виберіть **Incoming Webhooks** і перемкніть **Activate Incoming Webhooks** у положення *On*.
4. Натисніть **Add New Webhook to Workspace**, виберіть канал (наприклад, `#donations`), а потім **Allow**.
5. Slack поверне вас на сторінку з новою **Webhook URL**, яка має вигляд `https://hooks.slack.com/services/T0XXXXXXX/B0YYYYYYY/zzz…`. Скопіюйте її. Це єдиний параметр, який потрібен B1.

:::caution
Ставтеся до URL-адреси вебхука Slack як до секретного ключа. Будь-хто, хто її має, може публікувати в каналі довільні повідомлення. Якщо ви випадково її оприлюднили, перегенеруйте її на сторінці застосунку Slack. Перегенерація лише змінює URL-адресу, тому потім оновіть її в B1.
:::

### 2. Підключіть вебхук у B1Admin

1. У B1Admin перейдіть до **Settings → Developer → Webhooks**.
2. Натисніть **New Webhook**.
3. Заповніть поля:
   - **Name**: зрозуміла назва, наприклад «Пожертви → #donations». Її бачить лише ваша команда.
   - **Connector Type**: виберіть **Slack**.
   - **Payload URL**: вставте URL-адресу Slack з кроку 1.
   - **Events**: позначте події, які мають надходити як повідомлення. Для каналу пожертв достатньо `donation.created`. Для каналу #people спробуйте `person.created` і `group.member.added`.
4. Натисніть **Save**. З'явиться діалогове вікно «Signing Secret». Для Slack його можна ігнорувати, оскільки Slack не перевіряє підписи B1. Закрийте його.

### 3. Перевірте роботу

Знову відкрийте вебхук зі списку та натисніть **Send Test Event**. За секунду-дві у каналі Slack з'явиться повідомлення на кшталт

> 💝 New donation: $50.00

а в таблиці **Recent Deliveries** на цьому самому екрані з'явиться новий рядок зі статусом `succeeded`. Готово.

## Discord: покроково

### 1. Отримайте URL-адресу вебхука Discord

1. На сервері Discord наведіть вказівник на канал, для якого хочете отримувати сповіщення, і натисніть **⚙** (шестерня, Edit Channel).
2. Відкрийте **Integrations → Webhooks → New Webhook**.
3. Дайте вебхуку назву, за бажання додайте аватар, а потім натисніть **Copy Webhook URL**. URL-адреса має вигляд `https://discord.com/api/webhooks/123…/abc…`.

### 2. Підключіть вебхук у B1Admin

Порядок такий самий, як для Slack, за винятком того, що **Connector Type** потрібно встановити в **Discord**. Вставте URL-адресу Discord у **Payload URL** і збережіть.

:::tip
До URL-адреси Discord **не** потрібно додавати `/slack` в кінці. B1 надсилає дані у форматі `{content}`, рідному для Discord, а не сумісному з Slack. Просто вставте URL-адресу, яку видав Discord.
:::

### 3. Перевірте роботу

Скористайтеся тією самою кнопкою **Send Test Event**. Discord покаже повідомлення у вибраному каналі, а журнал доставки зміниться на `succeeded`.

## Як виглядають повідомлення

| Подія | Приклад повідомлення |
|---|---|
| `person.created` | 👤 New person added: Jordan Rivera |
| `person.updated` | 👤 Person updated: Jordan Rivera |
| `group.created` | 👥 New group created: Tuesday Bible Study |
| `group.member.added` | ➕ Someone was added to a group |
| `donation.created` | 💝 New donation: $50.00 |
| `donation.updated` | 💝 Donation updated: $75.00 |
| `attendance.recorded` | ✅ Attendance recorded |
| `form.submission.created` | 📝 New form submission received |
| `event.created` | 📅 New event: Easter Service |

Повний список міститься в [каталозі подій вебхуків](/docs/developer/api/webhooks#event-catalog). Будь-яку подію з цього каталогу можна спрямувати до Slack або Discord.

## Окремий канал для кожної теми

Не обов'язково збирати всі події в одному місці. Більшість церков налаштовують кілька вебхуків:

- Канал **#donations**, який отримує лише `donation.created`
- Канал **#new-people** для `person.created` і `group.member.added`
- Канал **#admin-alerts** для подій із низькою частотою, наприклад `form.submission.created`

Кількість вебхуків для однієї церкви не обмежена. Кожен із них працює незалежно: видалення або вимкнення одного не впливає на інші.

## Перегляд доставок

У таблиці **Recent Deliveries** редактора вебхука відображаються останні 50 спроб. Натисніть на рядок, щоб побачити точні дані, які було надіслано, і відповідь, яка повернулася. Для з'єднувача Slack тіло запиту має вигляд `{"text":"💝 New donation: $50.00"}`, а не необроблений конверт `{event,churchId,...}`, бо B1 перетворює його перед доставкою.

Якщо доставка не вдалася (червона позначка `failed` або `exhausted`), у діалоговому вікні відображаються HTTP-статус і текст відповіді. Так можна побачити, що саме не сподобалося Slack або Discord. Зазвичай причиною є помилка копіювання URL-адреси.

## Усунення несправностей

- **Повідомлення не з'являється, а статус доставки `400`**: зазвичай тип з'єднання встановлено як **Standard**, але URL-адреса належить Slack або Discord. Ці сервіси відхиляють необроблений конверт. Змініть значення в списку на **Slack** або **Discord** і повторно надішліть тестову подію.
- **Вебхук вимкнувся автоматично**: після 3 поспіль невдалих доставок B1 вимикає вебхук. Виправте URL-адресу (або перегенеруйте її в Slack чи Discord) і знову увімкніть **Active**.
- **Повідомлення прийшло, але без деталей**: кожна платформа чату обмежує розмір повідомлення. Повідомлення B1 навмисно стислі, в один рядок. Для детальніших сповіщень використовуйте [Zapier](./zapier) або [Make](./make), щоб сформувати повніше повідомлення в Slack через їхні дії для Slack.

## Зміна типу з'єднання пізніше

Ви можете змінити тип з'єднання для наявного вебхука, і зміна набуде чинності під час наступної доставки. Якщо перейти від Slack до Standard, вкажіть URL-адресу вашої власної кінцевої точки HTTPS. Той самий секрет підпису (він був створений разом із вебхуком) знову можна буде використовувати для перевірки необробленого конверта.
