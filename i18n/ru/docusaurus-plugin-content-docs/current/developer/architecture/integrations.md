# Поверхность интеграции и расширения

<div class="article-intro">

Все, что может подключить третья сторона, работает через один API и одну модель авторизации. Эта страница - это карта: она называет каждую поверхность интеграции, показывает, как они подключены, и связывает подробную справку для каждого. Если вы создаете для B1, начните здесь, чтобы выбрать правильную дверь, затем следуйте ссылке на страницу, которая документирует это детально.

## Поверхности с первого взгляда

Есть шесть способов входа или выхода, и они все используют один и тот же слой авторизации:

- **[REST API](../api/api-keys)** -- вся поверхность продукта, вызываемая с маркером носителя с любого языка.
- **[API keys](../api/api-keys)** -- самые простые учетные данные: маркер `cak_…`, привязанный к одному человеку в одной церкви.
- **[OAuth 2.0 & Connected Apps](../api/connected-apps)** -- согласие per-church для многотенантных приложений; выдает тот же JWT, который получает пользователь.
- **[Webhooks](../api/webhooks)** -- подписанные, надежно доставляемые исходящие события.
