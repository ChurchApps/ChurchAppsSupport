# Архитектура

<div class="article-intro">

Эти страницы представляют собой межрепозиторные карты систем. Они описывают, как работает основная система ChurchApps от начала до конца: через приложения, модули API и общие библиотеки. Они не объясняют настройку отдельного проекта. Прочитайте их перед изменением поведения системы. Чтобы запустить проект, используйте [Установку](../setup/index.md), а для справочника по конечным точкам API обращайтесь к [разделу API](../api/index.md).

</div>

## Экосистема в общих чертах

ChurchApps состоит примерно из 20 независимых репозиториев (это не монорепозиторий). Клиентские приложения обмениваются данными с небольшим набором серверных API по HTTPS и WebSocket. Общий код передаётся через npm-пакеты в области `@churchapps`.

```
┌────────────────────────────────┐            ┌──────────────────────────────────────────────┐
│  Clients                       │            │  Api — core modular monolith (AWS Lambda)    │
│                                │            │                                              │
│  B1Admin    staff dashboard    │   HTTPS    │   membership    attendance    content        │
│  B1App      member portal +    │ ─────────▶ │   giving        messaging     doing          │
│             church websites    │            │                                              │
│  B1Checkin  check-in kiosk     │ ◀───WS───▶ │   one MySQL database per module (6 total)    │
│                                │            └──────────────────────────────────────────────┘
│  FreePlay   TV content player  │            ┌──────────────────────────────────────────────┐
└───────────────┬────────────────┘            │  LessonsApi — Lessons.church backend         │
                │                             └──────────────────────────────────────────────┘
                │  shared code via npm (@churchapps/*)
                ▼
   helpers (cross-app interfaces) · apphelper (React components) · apihelper (Express/server utilities)
```

Два структурных правила определяют всё, что описано в этом разделе:

1. **Модули изолированы.** Каждый модуль Api владеет своей базой данных и своими таблицами. Другие модули и приложения получают доступ к его данным только через его REST-эндпоинты. См. [Структура модуля](../api/module-structure.md).
2. **Общий код поставляется как npm-пакеты.** Приложения не импортируют исходный код друг друга. Всё, что используется повторно, передаётся между репозиториями через `@churchapps/helpers`, `@churchapps/apphelper` или `@churchapps/apihelper`. См. [Общие библиотеки](../shared-libraries/index.md).

|------|----------------|-------|
| [Уведомления и напоминания](./notifications.md) | Как система сообщает человеку что-либо: два канала отправки, цепочка эскалации по каналам и механизм напоминаний | Api (messaging), B1Admin, B1App |

| [Пожертвования](./giving.md) | Платёжные провайдеры и шлюзы, потоки пожертвований, фонды и пакеты платежей, вебхуки шлюзов | Api (giving), apphelper, B1App, B1Admin |
| [Регистрации на события](./registrations.md) | Модель коммерции для регистраций: типы участников, выборы, промокоды, платежи через шлюз пожертвований и лист ожидания | Api (content + giving), B1App, B1Admin |
| [Check-in](./check-ins.md) | Регистрация на киоске и самостоятельный check-in, модель данных посещаемости, маршрутизация по комнатам, защита детей, печать этикеток | B1Checkin, B1App, B1Admin, Api (attendance + membership) |
| [Конструктор сайтов](./website-builder.md) | Дерево страниц, секций и элементов, контракт типов элементов и их рендереры, блог, страницы с ограниченным доступом, SEO и генерация с помощью ИИ | Api (content), AskApi, helpers/apphelper, B1Admin, B1App |
| [Маршрутизация сайтов и несколько сайтов](./websites.md) | Как запрос определяет церковь и конкретный сайт, модель данных с несколькими сайтами через `siteId` и пограничный уровень Caddy для собственных доменов | B1App, Api (membership + content), B1Admin |
| [Интеграции](./integrations.md) | Точки расширения: OAuth, ключи API, вебхуки, провайдеры контента, MCP | Api, общие библиотеки, внешние приложения |
| [Журнал аудита и отменяемые пакетные операции](./audit-log.md) | Аудит каждого изменения по умолчанию на уровне контроллера и слой пакетных операций, благодаря которому импорт и массовые действия можно отменить | Api (все модули), B1Admin, B1Transfer |
| [MinistryStuff](./ministrystuff.md) | Платный сервис хранилища и кредитов на SMS: идентификация через общий JWT, сервисный ключ для обмена между серверами, точки подключения провайдеров SMS и хранилища, биллинг Stripe | MinistryStuffApi, MinistryStuffWeb, Api (content + messaging), пакеты texting/apihelper, B1Admin |
| [Собственное хранилище (BYOS)](./byos-storage.md) | Церкви подключают Google Drive, Dropbox, OneDrive или S3-совместимый бакет для загрузок сверх бесплатных 100 МБ: подключение через OAuth, схемы загрузки для каждого провайдера, публичное перенаправление на скачивание | Api (content + membership), пакеты helpers/apphelper, B1Admin, B1App |
| [Общий контент](./commons.md) | Общая основа ресурсов и заявок для пользовательского контента, который используется в нескольких продуктах, и единая очередь модерации только для сотрудников в серверной администрации B1Admin | Api (модуль commons), B1Admin, WorshipCommons, Lessons.church, FreeShow |

:::tip
Если изменение меняет работу одной из этих систем, а не только отдельной страницы в одном приложении, соответствующую карту системы здесь нужно обновить в той же работе. Так этот раздел остаётся надёжной отправной точкой для новых участников.
:::
