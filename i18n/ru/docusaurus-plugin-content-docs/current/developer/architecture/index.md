# Архитектура

<div class="article-intro">

Эти страницы — межрепозиторные карты систем: они описывают, как работает основная система ChurchApps от начала до конца — через приложения, модули API и общие библиотеки, — а не то, как настроен отдельный проект. Читайте их перед изменением поведения системы; чтобы запустить проект, перейдите к разделу [Настройка](../setup/), а для справки по эндпоинтам API — к [разделу API](../api/).

</div>

## Экосистема в двух словах

ChurchApps — это около 20 независимых репозиториев (а не монорепозиторий). Клиентские приложения обращаются к небольшому набору бэкенд-API по HTTPS и WebSocket и делят код через npm-пакеты в области `@churchapps`.

```
┌────────────────────────────────┐            ┌──────────────────────────────────────────────┐
│  Clients                       │            │  Api — core modular monolith (AWS Lambda)    │
│                                │            │                                              │
│  B1Admin    staff dashboard    │   HTTPS    │   membership    attendance    content        │
│  B1App      member portal +    │ ─────────▶ │   giving        messaging     doing          │
│             church websites    │            │                                              │
│  B1Checkin  check-in kiosk     │ ◀───WS───▶ │   one MySQL database per module (6 total)    │
│  B1Mobile   (maintenance-only) │            └──────────────────────────────────────────────┘
│  FreePlay   TV content player  │            ┌──────────────────────────────────────────────┐
└───────────────┬────────────────┘            │  LessonsApi — Lessons.church backend         │
                │                             └──────────────────────────────────────────────┘
                │  shared code via npm (@churchapps/*)
                ▼
   helpers (cross-app interfaces) · apphelper (React components) · apihelper (Express/server utilities)
```

Два структурных правила определяют всё, что описано в этом разделе:

1. **Модули изолированы.** Каждый модуль Api владеет своей базой данных и своими таблицами; другие модули и приложения получают доступ к его данным только через его REST-эндпоинты. См. [Структура модуля](../api/module-structure).
2. **Общий код поставляется как npm-пакеты.** Приложения никогда не импортируют исходный код друг друга; всё, что используется повторно, пересекает границы репозиториев через `@churchapps/helpers`, `@churchapps/apphelper` или `@churchapps/apihelper`. См. [Общие библиотеки](../shared-libraries/).

## Карты систем

| Страница | Что описывает | Охватывает |
|------|----------------|-------|
| [Уведомления и напоминания](./notifications) | Как что-либо сообщает человеку информацию: два канала отправки, цепочка эскалации каналов и движок напоминаний | Api (messaging), B1Admin, B1App |
| [Архитектура реального времени](../realtime) | Фреймворк доставки через WebSocket, который лежит в основе чата, присутствия и доставки в приложении | Api (messaging), все веб-приложения |
| [Web Push-уведомления](../web-push) | Канал push-уведомлений в браузере: ключи VAPID, хранение подписок, доставка | Api (messaging), все веб-приложения |
| [Пожертвования](./giving) | Платёжные провайдеры и шлюзы, потоки пожертвований, фонды/пакеты, webhook-и шлюзов | Api (giving), apphelper, B1App, B1Admin |
| [Регистрации на мероприятия](./registrations) | Модель коммерции регистраций: типы участников, выборы, промокоды, платежи через шлюз пожертвований и лист ожидания | Api (content + giving), B1App, B1Admin |
| [Регистрация посещений](./check-ins) | Регистрация на киоске и самостоятельная, модель данных посещаемости, маршрутизация по классам, слой защиты детей, печать этикеток | B1Checkin, B1App, B1Admin, Api (attendance + membership) |
| [Конструктор сайтов](./website-builder) | Дерево страниц/секций/элементов, контракт типов элементов и рендереры, блог, страницы с ограниченным доступом, SEO и генерация с ИИ | Api (content), AskApi, helpers/apphelper, B1Admin, B1App |
| [Маршрутизация сайтов и мультисайтовость](./websites) | Как запрос определяет церковь и конкретный сайт, модель данных мультисайтовости с `siteId` и граничный узел Caddy для собственных доменов | B1App, Api (membership + content), B1Admin |
| [Интеграции](./integrations) | Поверхность расширения: OAuth, API-ключи, webhook-и, провайдеры контента, MCP | Api, общие библиотеки, внешние приложения |
| [Журнал аудита и отменяемые пакеты](./audit-log) | Аудит каждого изменения по умолчанию на контроллере и слой пакетов, который делает импорты и массовые действия отменяемыми | Api (все модули), B1Admin, B1Transfer |
| [MinistryStuff](./ministrystuff) | Платный сервис хранения и кредитов на рассылку текстовых сообщений: идентификация по общему JWT, S2S с сервисным ключом, границы провайдеров текста и хранения, биллинг Stripe | MinistryStuffApi, MinistryStuffWeb, Api (content + messaging), пакеты texting/apihelper, B1Admin |
| [Собственное хранилище (BYOS)](./byos-storage) | Церкви подключают Google Drive, Dropbox, OneDrive или S3-совместимый бакет для загрузок сверх бесплатных 100 МБ: подключение OAuth, формат загрузки для каждого провайдера, публичное перенаправление на скачивание | Api (content + membership), пакеты helpers/apphelper, B1Admin, B1App |
| [Общие материалы контента](./commons) | Общий слой ресурсов и заявок, лежащий в основе пользовательского контента, который используется сразу в нескольких продуктах, и единая очередь модерации только для сотрудников в Server Admin B1Admin | Api (модуль commons), B1Admin, WorshipCommons, Lessons.church, FreeShow |

:::tip
Когда изменение меняет работу одной из этих систем — а не только страницы внутри одного приложения — соответствующую карту системы здесь нужно обновить в рамках той же работы. Так этот раздел остаётся надёжной первой отправной точкой для новых участников.
:::
