# Эндпоинты модуля Membership

<div class="article-intro">

Модуль Membership управляет людьми, церквями, группами, домохозяйствами, ролями, разрешениями, формами и настройками. Это самый большой модуль, и он предоставляет основной слой идентификации и авторизации для всех остальных модулей.

</div>

**Базовый путь:** `/membership`

## Люди

Базовый путь: `/membership/people`

| Метод | Путь | Авторизация | Разрешение | Описание |
|--------|------|------|------------|-------------|
| GET | `/` | JWT | People.View или Member | Список всех людей церкви |
| GET | `/:id` | JWT | People.View или собственная запись | Получить человека по ID (включает отправленные формы) |
| GET | `/ids?ids=` | JWT | People.View, Member или People.ViewNames | Получить несколько людей по ID, перечисленным через запятую. Вызывающие с People.ViewNames без People.View получают базовую модель; люди, отказавшиеся от показа, исключаются (кроме самого вызывающего) |
| GET | `/basic?ids=` | JWT | — | Получить базовую информацию (только имя) для нескольких людей |
| GET | `/names?ids=` | JWT | Любое разрешение церкви | `[{ id, name: { display, first, last }, photo }]`, отсортировано по фамилии, затем по имени, для ID через запятую, которые вызывающий уже имеет, чтобы роли без People.View (пожертвования, посещаемость) могли подписывать людей. Без поиска и без фильтра каталога |
| POST | `/names` | JWT | Любое разрешение церкви | То же, что `GET /names`. Тело: `{ peopleIds }` (или `{ ids }`) |
| GET | `/recent` | JWT | People.View, Member или People.ViewNames | Недавно добавленные люди. Вызывающие с People.ViewNames без People.View (даже участники с доступом к каталогу) получают базовую модель (`id`, `name.display`, `photo`, `membershipStatus`); люди, отказавшиеся от показа, исключаются |
| GET | `/guest-register/options?churchId=` | Публично | — | Чек-лист гостевой регистрации по QR-коду: возвращает `{ email, phone, address, birthDate, gender, maritalStatus, grade, comments }`, каждое значение — `"off"`, `"optional"` или `"required"` (разбирается из публичной настройки `guestRegistrationFields`; отсутствующие или некорректные значения переходят к значениям по умолчанию: email/телефон необязательны, остальное выключено). Требует `enableQRGuestRegistration`, если только запрос не содержит совпадающий токен сайта/церкви; есть ограничение частоты запросов (429) |
| GET | `/search?term=&email=` | JWT | People.View, Member или People.ViewNames | Поиск людей по имени или email (до 100, отсортировано по фамилии, затем по имени). Вызывающие с People.ViewNames без People.View (даже участники с доступом к каталогу) получают поиск по имени с базовой моделью; поиск по `email` возвращает `[]` |
| GET | `/search/phone?number=` | JWT | People.View или Member | Поиск по номеру телефона |
| GET | `/search/group?groupId=` | JWT | People.View или Member | Получить людей в конкретной группе |
| GET | `/household/:householdId` | JWT | — | Получить всех людей в домохозяйстве |
| GET | `/attendance` | JWT | People.Edit | Загрузить посетителей с фильтрами (campusId, serviceId, serviceTimeId, groupId, categoryName, startDate, endDate) |
| GET | `/timeline?personIds=&groupIds=` | JWT | — | Загрузить данные хронологии для людей и групп |
| GET | `/directory/:id` | JWT | — | Получить человека для просмотра в каталоге (учитывает настройки видимости) |
| GET | `/claim/:churchId` | JWT | — | Привязать запись человека к текущему пользователю в церкви |
| POST | `/` | JWT | People.Edit или EditSelf | Создать или обновить людей (пакетно) |
| POST | `/search` | JWT | People.View, Member или People.ViewNames | Поиск людей (вариант POST). Тело: `{ term }` или `{ email }`; те же правила ограничения только именами, что и у `GET /search` |
| POST | `/advancedSearch` | JWT | People.View или Member | Поиск по нескольким условиям (возраст, birthMonth, membershipStatus и т. д.). Тело — массив условий; пустое тело означает отсутствие условий, а любое другое тело, не являющееся массивом, возвращает 400 |
| POST | `/loadOrCreate` | Публично | — | Найти или создать человека по email. Тело: `{ churchId, email, firstName, lastName }` |
| POST | `/guest-register` | Публично | — | Гостевая регистрация по QR-коду. Тело: `{ churchId, members: [{ firstName, lastName, email?, phone?, birthDate?, gender?, grade? }], address?, maritalStatus?, comments? }` (от 1 до 10 участников; email/phone/maritalStatus применяются только к первому участнику). Поля, которые церковь отключила, отбрасываются; отсутствующие обязательные или некорректные значения возвращают 400. Создает новое домохозяйство (названное по фамилии первого участника) со всеми участниками со статусом `membershipStatus: "Visitor"`, распространяет `address` на всех участников, сохраняет `comments` как заметку у главы, добавляет всех в приватную группу `guestRegistrationGroupId`, если она задана, и — когда `guestRegistrationRecordAttendance` равен `"true"` — записывает посещаемость на запланированные службы этой группы, для которых окно регистрации открыто прямо сейчас. Возвращает `{ householdId, people: [{ id, name }] }`. Те же правила включения/токена и ограничения частоты, что и для вызова options |
| POST | `/household/:householdId` | JWT | People.Edit | Обновить назначения участников домохозяйства |
| POST | `/public/email` | Публично | — | Отправить email человеку. Тело: `{ churchId, personId, subject, body, appName }` |
| POST | `/apiEmails` | Внутренний | — | Загрузить email людей по ID (от сервера к серверу, требуется jwtSecret) |
| DELETE | `/:id` | JWT | People.Edit | Удалить человека |

### Пример: поиск людей

```
GET /membership/people/search?term=John
Authorization: Bearer <token>
```

```json
[
  {
    "id": "abc-123",
    "name": { "first": "John", "last": "Smith" },
    "contactInfo": { "email": "john@example.com" },
    "membershipStatus": "Member"
  }
]
```

### Пример: создание человека

```
POST /membership/people
Authorization: Bearer <token>

[{ "firstName": "Jane", "lastName": "Doe", "contactInfo": { "email": "jane@example.com" } }]
```

## Отправки форм

Базовый путь: `/membership/formsubmissions`

| Метод | Путь | Авторизация | Разрешение | Описание |
|--------|------|------|------------|-------------|
| GET | `/` | JWT | Forms.Admin или Forms.Edit | Список отправок. Фильтры: `?personId=` или `?formId=` |
| GET | `/my?include=questions,answers` | JWT | — | Только для себя: до 50 отдельно стоящих форм (не форм людей), которые отправил вошедший участник или которые связаны с его записью человека (`contentType` `person`, `contentId` = ID его записи — например, после изменения записи администратором), от новых к старым, каждая с `form.name`. `include` добавляет вопросы каждой формы и ответы отправки. Возвращает `401`, если пользователь не связан с человеком. Используется для раздела **My Forms** на странице B1 Me |
| GET | `/group/:groupId` | JWT | Руководитель группы | Ответы для руководителей группы: одна запись на каждую связанную форму и на каждое событие группы с формой регистрации, каждая с `form`, `event` (`id`, `title`, `start`; только для записей событий), `questions` и `submissions` (с `answers` и `personName`, `null` для анонимных) |
| GET | `/:id` | JWT | Forms.Admin, Forms.Edit или доступ на просмотр | Получить отправку по ID. Добавьте `?include=form,questions,answers`. Руководители связанной группы формы и руководители группы, к которой относится регистрация на событие, также могут ее читать |
| GET | `/formId/:formId` | JWT | Доступ к форме (просмотр) | Получить все отправки формы (включает form, questions, answers). Руководители связанной группы формы имеют доступ на просмотр |
| POST | `/` | JWT | — | Отправить ответы формы (обрабатывает ограниченные и неограниченные формы, отправляет уведомления по email). Если у формы включено `autoCreatePerson`, находит или создает гостевого человека по email и связывает с ним отправку; если у формы также есть `groupId`, добавляет этого человека в группу; если заданы `followUpSubject`/`followUpBody`, отправляет отправителю письмо-продолжение по шаблону. Если вызывающий не может управлять формой, `submittedBy` всегда задается как человек вошедшего участника (или остается пустым для анонимных отправок) |
| DELETE | `/:id` | JWT | Forms.Admin или Forms.Edit | Удалить отправку и её ответы |
