# Эндпоинты Membership

<div class="article-intro">

Модуль Membership управляет людьми, церквями, группами, домохозяйствами, ролями, правами доступа, формами и настройками. Это самый крупный модуль; он обеспечивает основной слой идентификации и авторизации для всех остальных модулей.

</div>

**Базовый путь:** `/membership`

## Люди

Базовый путь: `/membership/people`

| Метод | Путь | Auth | Права | Описание |
|--------|------|------|------------|-------------|
| GET | `/` | JWT | People.View или Member | Список всех людей церкви |
| GET | `/:id` | JWT | People.View или собственная запись | Получить человека по ID (включает отправки форм) |
| GET | `/ids?ids=` | JWT | People.View, Member или People.ViewNames | Получить нескольких людей по ID, перечисленным через запятую. Вызывающие с People.ViewNames без People.View получают базовую модель, при этом люди, отказавшиеся от показа, не возвращаются (кроме самого вызывающего) |
| GET | `/basic?ids=` | JWT | — | Получить базовые сведения (только имя) для нескольких людей |
| GET | `/names?ids=` | JWT | Любое право церкви | `[{ id, name: { display, first, last }, photo }]`, отсортировано по фамилии, затем по имени, для перечисленных через запятую ID, которые вызывающий уже видит, чтобы роли без People.View (пожертвования, посещаемость) могли подписывать людей. Поиска и фильтра каталога нет |
| POST | `/names` | JWT | Любое право церкви | То же, что `GET /names`. Тело: `{ peopleIds }` (или `{ ids }`) |
| GET | `/recent` | JWT | People.View, Member или People.ViewNames | Недавно добавленные люди. Вызывающие с People.ViewNames без People.View (даже участники с доступом к каталогу) получают базовую модель (`id`, `name.display`, `photo`, `membershipStatus`), при этом люди, отказавшиеся от показа, не возвращаются |
| GET | `/guest-register/options?churchId=` | Public | — | Чек-лист регистрации гостей по QR-коду: возвращает `{ email, phone, address, birthDate, gender, maritalStatus, grade, comments }`, где каждое значение — `"off"`, `"optional"` или `"required"` (разбирается из публичной настройки `guestRegistrationFields`; при отсутствии или неверном значении используются значения по умолчанию: email/телефон — необязательные, остальное — выключено). Требует `enableQRGuestRegistration`, если только запрос не содержит подходящий токен сайта или церкви; ограничено по частоте (429) |
| GET | `/search?term=&email=` | JWT | People.View, Member или People.ViewNames | Поиск людей по имени или email (до 100, сортировка по фамилии, затем по имени). Вызывающие с People.ViewNames без People.View (даже участники с доступом к каталогу) получают при поиске по имени базовую модель; поиск по `email` возвращает `[]` |
| GET | `/search/phone?number=` | JWT | People.View или Member | Поиск по номеру телефона |
| GET | `/search/group?groupId=` | JWT | People.View или Member | Получить людей в конкретной группе |
| GET | `/household/:householdId` | JWT | — | Получить всех людей домохозяйства |
| GET | `/attendance` | JWT | People.Edit | Загрузить посетителей с фильтрами (campusId, serviceId, serviceTimeId, groupId, categoryName, startDate, endDate) |
| GET | `/timeline?personIds=&groupIds=` | JWT | — | Загрузить данные временной шкалы для людей и групп |
| GET | `/directory/:id` | JWT | — | Получить человека для просмотра в каталоге (учитываются настройки видимости) |
| GET | `/claim/:churchId` | JWT | — | Привязать запись человека к текущему пользователю в церкви |
| POST | `/` | JWT | People.Edit или EditSelf | Создать или обновить людей (пакетно) |
| POST | `/search` | JWT | People.View, Member или People.ViewNames | Поиск людей (вариант POST). Тело: `{ term }` или `{ email }`; те же правила для режима только имён, что и у `GET /search` |
| POST | `/advancedSearch` | JWT | People.View или Member | Поиск по нескольким условиям (возраст, birthMonth, membershipStatus и др.). Тело — массив условий; пустое тело означает отсутствие условий, а любое другое тело, не являющееся массивом, возвращает 400 |
| POST | `/loadOrCreate` | Public | — | Найти или создать человека по email. Тело: `{ churchId, email, firstName, lastName }` |
| POST | `/guest-register` | Public | — | Регистрация гостя по QR-коду. Тело: `{ churchId, members: [{ firstName, lastName, email?, phone?, birthDate?, gender?, grade? }], address?, maritalStatus?, comments? }` (от 1 до 10 участников; email/phone/maritalStatus относятся только к первому участнику). Поля, отключённые церковью, отбрасываются; отсутствующие обязательные или неверные значения возвращают 400. Сначала используются существующие люди: участник совпадает, если ровно один не удалённый человек имеет то же имя (без учёта регистра) и тот же email или цифры телефона (домашний, рабочий или мобильный); участник без email или телефона совпадает по имени внутри совпавшего домохозяйства. Совпавших людей никогда не редактируют. Несовпавшие участники присоединяются к совпавшему домохозяйству или создают новое (названное по фамилии первого участника) со статусом `membershipStatus: "Visitor"` и общим `address`. Сохраняет `comments` как заметку у первого участника, добавляет всех в приватную группу `guestRegistrationGroupId`, если она задана, и — когда `guestRegistrationRecordAttendance` равно `"true"` — записывает посещаемость на те запланированные времена служений этой группы, окно регистрации которых открыто сейчас. Возвращает `{ householdId, people: [{ id, name }] }`, повторяя переданные имена, а не сохранённые. Те же правила согласия/токена и ограничения по частоте, что и для запроса options |
| POST | `/household/:householdId` | JWT | People.Edit | Обновить назначения участников домохозяйства |
| POST | `/public/email` | Public | — | Отправить письмо человеку. Тело: `{ churchId, personId, subject, body, appName }` |
| POST | `/apiEmails` | Internal | — | Загрузить email людей по ID (межсерверный вызов, требуется jwtSecret) |
| DELETE | `/:id` | JWT | People.Edit | Удалить человека |

### Пример: поиск людей

```
GET /membership/people/search?term=John
Authorization: Bearer <token>
```

```json
[
  {
    "id": "abc-123",
    "name": { "first": "John", "last": "Smith" },
    "contactInfo": { "email": "john@example.com" },
    "membershipStatus": "Member"
  }
]
```

### Пример: создание человека

```
POST /membership/people
Authorization: Bearer <token>

[{ "firstName": "Jane", "lastName": "Doe", "contactInfo": { "email": "jane@example.com" } }]
```

Если у формы включён `autoCreatePerson`, находит или создаёт Guest-человека по email и привязывает к нему отправку; если у формы также есть `groupId`, добавляет этого человека в группу; если заданы `followUpSubject`/`followUpBody`, отправляет отправителю письмо по шаблону. ## Вопросы

Базовый путь: `/membership/questions`

| Метод | Путь | Auth | Права | Описание |
|--------|------|------|------------|-------------|
| GET | `/` | JWT | Доступ к форме | Список вопросов формы. Требуется `?formId=` |
| GET | `/:id` | JWT | Доступ к форме | Получить вопрос по ID |
| GET | `/unrestricted?formId=` | JWT | — | Получить вопросы неограниченной формы |
| GET | `/sort/:id/up` | JWT | — | Переместить вопрос вверх в порядке сортировки |
| GET | `/sort/:id/down` | JWT | — | Переместить вопрос вниз в порядке сортировки |
| POST | `/` | JWT | Доступ к форме | Создать или обновить вопросы (порядок сортировки назначается автоматически) |
| DELETE | `/:id?formId=` | JWT | Доступ к форме | Удалить вопрос |

## Ответы

Базовый путь: `/membership/answers`

| Метод | Путь | Auth | Права | Описание |
|--------|------|------|------------|-------------|
| GET | `/` | JWT | Forms.Admin или Forms.Edit | Список ответов. Фильтр: `?formSubmissionId=` |
| POST | `/` | JWT | Forms.Admin или Forms.Edit | Создать или обновить ответы |

## Права участников на формы

Базовый путь: `/membership/memberpermissions`

Управляет доступом отдельных участников к конкретным формам.

| Метод | Путь | Auth | Права | Описание |
|--------|------|------|------------|-------------|
| GET | `/:id` | JWT | Доступ к форме | Получить право участника на форму по ID |
| GET | `/member/:id` | JWT | Доступ к форме | Получить все права участника на формы |
| GET | `/form/:id` | JWT | Доступ к форме | Получить все права участников на форму |
| GET | `/form/:id/my` | JWT | Доступ к форме | Получить право текущего пользователя на форму |
| POST | `/` | JWT | Доступ к форме | Создать или обновить права участника на форму |
| DELETE | `/:id?formId=` | JWT | Доступ к форме | Удалить право участника на форму |
| DELETE | `/member/:id?formId=` | JWT | Доступ к форме | Удалить все права участника на форме |

## Настройки

Базовый путь: `/membership/settings`

| Метод | Путь | Auth | Права | Описание |
|--------|------|------|------------|-------------|
| GET | `/` | JWT | Settings.Edit | Получить все настройки церкви |

| POST | `/` | JWT | Settings.Edit | Сохранить настройки (поддерживает загрузку изображений в base64) |

## Домены

Базовый путь: `/membership/domains`

Наследует стандартный CRUD (GET `/:id`, GET `/`, DELETE `/:id` из базового класса).

| Метод | Путь | Auth | Права | Описание |
|--------|------|------|------------|-------------|
| GET | `/` | JWT | — | Список всех доменов |
| GET | `/:id` | JWT | — | Получить домен по ID |
| GET | `/lookup/:domainName` | JWT | — | Найти домен по имени |
| GET | `/public/lookup/:domainName` | Public | — | Публичный поиск домена по имени |
| GET | `/health/check` | Public | — | Запустить проверку работоспособности непроверенных доменов |
| POST | `/` | JWT | Settings.Edit | Создать или обновить домены (обновляет Caddy) |
| DELETE | `/:id` | JWT | Settings.Edit | Удалить домен |

## Связь пользователя с церковью

Базовый путь: `/membership/userchurch`

Управляет связью между пользователями и церквями.

| Метод | Путь | Auth | Права | Описание |
|--------|------|------|------------|-------------|
| GET | `/userid/:userId` | JWT | — | Получить запись «пользователь — церковь» по ID пользователя |
| GET | `/personid/:personId` | JWT | — | Получить email связанного пользователя для человека |
| GET | `/user/:userId` | JWT | Server.Admin | Загрузить все церкви пользователя |
| POST | `/` | JWT | — | Создать связь пользователя с церковью |
| PATCH | `/:userId` | JWT | — | Обновить время последнего доступа и записать доступ в журнал |
| DELETE | `/record/:userId/:churchId/:personId` | JWT | — | Удалить запись «пользователь — церковь» |
