# Эндпоинты сообщений

<div class="article-intro">

Модуль сообщений управляет беседами в реальном времени, сообщениями чата, push-уведомлениями, доставкой SMS и email, WebSocket-соединениями, личными сообщениями, регистрацией устройств и провайдерами SMS. Он обеспечивает слой коммуникации, который используется во всех приложениях ChurchApps как для чата прямых трансляций, так и для асинхронных уведомлений.

</div>

**Базовый путь:** `/messaging`

## Беседы

Базовый путь: `/messaging/conversations`

| Метод | Путь | Аутентификация | Право | Описание |
|--------|------|------------|-------------|-------------|
| GET | `/timeline/ids?ids=` | JWT | — | Загрузить беседы по списку ID через запятую с первым и последним сообщениями |
| GET | `/messages/:contentType/:contentId` | JWT | — | Загрузить беседы для контента с постраничными сообщениями (`?page=&limit=`) |
| GET | `/posts` | JWT | — | Получить беседы типа «публикация» для групп текущего пользователя |
| GET | `/posts/group/:groupId` | JWT | — | Получить беседы типа «публикация» для конкретной группы |
| GET | `/notes/feed?section=&limit=&before=` | JWT | — | Самые новые заметки по всем записям для страницы «Заметки» в B1 Admin. `section` -- `people`, `groups`, `events` или `workflows` (иначе 400); `limit` по умолчанию 25 (максимум 100); `before` -- курсор с предыдущей страницы. Каждая заметка по-прежнему проходит правило своего типа (право People Edit / конфиденциальные заметки, руководители группы, просматривающие мероприятия, просматривающие карточки процессов), поэтому вызывающая сторона видит только заметки, которые может открыть. Текст заметки обрезается до 300 символов |
| GET | `/current/:churchId/:contentType/:contentId` | Публичный | — | Получить или создать текущую беседу для контента (автоматически расшифровывает contentId) |
| GET | `/:churchId/:contentType/:contentId` | Публичный | — | Загрузить беседы по типу контента и ID |
| GET | `/:churchId/:id` | Публичный | — | Загрузить одну беседу по ID |
| POST | `/` | JWT | — | Создать или обновить беседы (пакетно) |
| POST | `/start` | JWT | — | Начать новую беседу с первым комментарием |
| DELETE | `/:churchId/:id` | JWT | — | Удалить беседу |

### Контроль доступа к заметкам о людях

Беседы с `contentType: "person"` (вкладка «Заметки» в карточке человека) или `contentType: "personConfidential"` (раздел «Конфиденциальные заметки») ограничены на каждом пути чтения и записи, включая общедоступные маршруты выше, которые возвращают `401` для этих типов контента. Для `person` требуется право MembershipApi **People / Edit**; для `personConfidential` -- право **People / View Confidential Notes**. Для ключей API с ограниченной областью `people:write` покрывает оба действия (у пользователя ключа по-прежнему должно быть соответствующее право роли).

### Контроль доступа к заметкам групп и мероприятий {#group-and-event-notes-access-control}

Ещё два типа заметок ограничены так же, на каждом пути чтения и записи (включая общедоступные маршруты выше), и никогда не открыты для анонимной публикации:

- **`groupNote`** (`contentId` = ID группы) -- лента **Заметки руководителя** группы. Читать или писать может только руководитель этой группы (`leaderGroupIds` в JWT). Никакое право сотрудника не даёт доступа, включая `content.edit` и права на участие в группах.
- **`eventNote`** (`contentId` = ID мероприятия) -- заметки к мероприятию календаря. Сотрудники с `content.edit` или **Calendars / Admin** всегда могут читать и писать. В остальных случаях доступ определяется полями мероприятия `notesViewRole` (чтение) и `notesPostRole` (публикация): `staff` (по умолчанию, используется, когда поле `null`) не даёт доступа никому другому, `leaders` даёт доступ руководителям группы мероприятия, `members` -- участникам и руководителям группы мероприятия. Мероприятие без `groupId` доступно только сотрудникам.

### Контроль доступа к заметкам карточки процесса

Беседы с `contentType: "workflowCard"` (заметки к карточке процесса, где `contentId` -- ID задачи карточки) могут читать и писать только те, кто может открыть эту карточку: пользователь с правом DoingApi **Tasks / View**, либо человек или группа, которым назначена карточка, которые её создали или которых она касается. Все остальные получают `401` на каждом пути чтения, включая общедоступные маршруты выше. Беседа карточки прикрепляется через саму карточку с помощью `POST /doing/tasks/:id/conversation` (тело `{ "conversationId": "..." }`; побеждает первая прикреплённая беседа), что могут вызывать редакторы карточки и её исполнитель.

### Пример: начать беседу

```
POST /messaging/conversations/start
Authorization: Bearer <token>

{
  "groupId": "group-123",
  "contentType": "group",
  "contentId": "group-123",
  "title": "Weekly Discussion",
  "comment": "Welcome to this week's discussion thread!"
}
```

```json
{
  "id": "conv-456",
  "churchId": "church-789",
  "contentType": "group",
  "contentId": "group-123",
  "title": "Weekly Discussion",
  "dateCreated": "2026-02-17T10:00:00.000Z",
  "visibility": "public",
  "allowAnonymousPosts": false,
  "groupId": "group-123"
}
```

## Сообщения

Базовый путь: `/messaging/messages`

| Метод | Путь | Аутентификация | Право | Описание |
|--------|------|------------|-------------|-------------|
| GET | `/conversation/:conversationId` | JWT | — | Загрузить все сообщения беседы |
| GET | `/catchup/:churchId/:conversationId` | Публичный | — | Загрузить все сообщения беседы (публичная догрузка для живого чата) |
| GET | `/:churchId/:id` | Публичный | — | Загрузить одно сообщение по ID |
| POST | `/` | JWT | — | Сохранить сообщения (пакетно). Отправляет обновления в реальном времени и запускает уведомления. Для обновления существующего сообщения нужно быть его автором или иметь `content.edit`; сохранённый автор никогда не может быть переназначен |
| POST | `/send` | Публичный | — | Отправить сообщения (пакетно, публично). Отправляет обновления в реальном времени через WebSocket и запускает уведомления |
| POST | `/setCallout` | JWT | — | (устаревший) Передать выделенное сообщение в реальном времени. Нет активного клиента; чат прямой трансляции больше не отображает выделенные сообщения |
| DELETE | `/:churchId/:id` | JWT | — | Удалить сообщение и передать удаление в реальном времени. См. [Модерация сообщений](#message-moderation) |

### Модерация сообщений {#message-moderation}

Удалять сообщение могут:

- автор сообщения;
- сотрудники с `content.edit` (в любом месте церкви);
- **руководители групп** -- для бесед с `contentType` `group` или `groupAnnouncement`, у которых `contentId` -- группа, которой они руководят (`leaderGroupIds` в JWT).

Беседы с заметками о людях (`person` / `personConfidential`) никогда не модерируются руководителями -- для них действуют права на заметки (`people.edit`, `people.viewConfidentialNotes`).

Руководители могут только удалять, но не редактировать: переписывать сообщение другого участника по-прежнему могут только автор и сотрудники с `content.edit`.

### Пример: отправить сообщение

```
POST /messaging/messages/send

[
  {
    "churchId": "church-789",
    "conversationId": "conv-456",
    "personId": "person-123",
    "displayName": "John Smith",
    "content": "Hello everyone!",
    "messageType": "comment"
  }
]
```

```json
[
  {
    "id": "msg-001",
    "churchId": "church-789",
    "conversationId": "conv-456",
    "personId": "person-123",
    "displayName": "John Smith",
    "timeSent": "2026-02-17T10:05:00.000Z",
    "content": "Hello everyone!",
    "messageType": "comment"
  }
]
```

## Запланированные уведомления

Базовый путь: `/messaging/scheduledNotifications`

Push-уведомления, запланированные заранее. `audience` -- это `church` (все, у кого есть приложение; нужно `content.edit`) или `group` (нужны `groupMembers.edit` и `groupId`). Заголовок ограничен 80 символами, сообщение -- 240. Уведомление, срок которого наступил, отправляется таймером раз в минуту.

| Метод | Путь | Аутентификация | Право | Описание |
|--------|------|------------|-------------|-------------|
| GET | `/` | JWT | `groupMembers.edit` или `content.edit` | Список запланированных и недавних уведомлений церкви |
| POST | `/` | JWT | в зависимости от аудитории | Создать запланированное уведомление или обновить его, если задан `id`. Тело: `{ id?, audience, groupId?, title, message, link?, imageUrl?, sendAt }`. Обновление уведомления, которое больше не ожидает отправки, возвращает 409 |
| POST | `/:id/sendNow` | JWT | в зависимости от аудитории | Отправить ожидающее уведомление сейчас. Возвращает 409, если оно уже отправлено, отменено или отправляется |
| DELETE | `/:id` | JWT | в зависимости от аудитории | Отменить ожидающее уведомление или удалить отправленное, неудавшееся или отменённое из списка. Возвращает 409, пока оно отправляется |
| DELETE | `/` | JWT | `groupMembers.edit` или `content.edit` | Удалить все отправленные, неудавшиеся и отменённые уведомления для аудиторий, которым может отправлять пользователь. Возвращает `{ deleted }` |

## SMS

Базовый путь: `/messaging/texting`

Управляет провайдерами SMS, групповыми текстовыми сообщениями и отслеживанием доставки.

| Метод | Путь | Аутентификация | Право | Описание |
|--------|------|------------|-------------|-------------|
| GET | `/providers` | JWT | — | Загрузить провайдеров SMS церкви (учётные данные скрыты) |
| GET | `/status` | JWT | — | `{ enabled }` -- есть ли у церкви включённый провайдер SMS. Любой авторизованный пользователь церкви; используется, чтобы показывать варианты **SMS** только тогда, когда можно отправлять SMS |
| GET | `/inboundUrl` | JWT | `texting.send` или `settings.edit` | `{ url }` -- входящий (STOP) webhook-адрес церкви, который нужно вставить в провайдера |
| POST | `/inbound/:churchId/:token` | Публичный | — | Webhook входящих сообщений провайдера. `token` -- HMAC от ID церкви. Ответ, точно совпадающий со стоп-словом (`STOP`, `STOPALL`, `UNSUBSCRIBE`, `CANCEL`, `END`, `QUIT`, `OPTOUT`, `REVOKE`), помечает каждого подходящего человека как `optedOut` и выключает его `allowSms`. Возвращает `{ optedOut: <count> }`; другие ответы возвращают `{ optedOut: 0 }` |
| GET | `/preview/:groupId` | JWT | — | Предпросмотр получателей группового SMS (счётчики: подходящие, отказавшиеся, без телефона) |
| GET | `/sent` | JWT | — | Загрузить все записи отправленных SMS церкви |
| GET | `/sent/:id/details` | JWT | — | Загрузить отправленное SMS с журналами доставки по каждому получателю |
| POST | `/providers` | JWT | — | Сохранить провайдеров SMS (пакетно). Шифрует API-учётные данные |
| POST | `/send` | JWT | — | Отправить SMS всем подходящим участникам группы. Тело: `{ groupId, message }`. Поля подстановки (`{{firstName}}`, `{{lastName}}`, `{{displayName}}`, `{{churchName}}`) разрешаются для каждого получателя |
| POST | `/sendPerson` | JWT | — | Отправить SMS одному человеку. Тело: `{ personId, phoneNumber, message }`. Поля подстановки разрешаются, и в журнал записывается уже разрешённый текст |
| DELETE | `/providers/:id` | JWT | — | Удалить провайдера SMS |

### Пример: отправить групповое SMS

```
POST /messaging/texting/send
Authorization: Bearer <token>

{
  "groupId": "group-123",
  "message": "Reminder: Service starts at 10 AM this Sunday!"
}
```

```json
{
  "totalMembers": 50,
  "recipientCount": 42,
  "successCount": 40,
  "failCount": 2,
  "optedOutCount": 5,
  "noPhoneCount": 3
}
```

## Шаблоны писем

Базовый путь: `/messaging/emailTemplates`

Управляет многоразовыми шаблонами писем и отправкой шаблонных писем группам.

| Метод | Путь | Аутентификация | Право | Описание |
|--------|------|------------|-------------|-------------|
| GET | `/` | JWT | — | Загрузить все шаблоны писем церкви |
| GET | `/:id` | JWT | — | Загрузить один шаблон письма по ID |
| GET | `/sendStatus` | JWT | `groupMembers.edit` или `tasks.admin` | Статус email групп церкви: `{ approved, paused, remaining, requested }`. Диалоговое окно «Отправить письмо» в B1Admin и действие процесса **Отправить письмо** используют его, чтобы предупредить, когда письмо не будет отправлено |
| POST | `/requestApproval` | JWT | `groupMembers.edit` | Попросить поддержку одобрить церковь для групповых писем (не чаще одного раза в неделю на церковь) |
| GET | `/preview/:groupId` | JWT | — | Предпросмотр доставки писем группе (количество подходящих получателей, участники без email) |
| POST | `/` | JWT | — | Создать или обновить шаблоны писем (пакетно) |
| POST | `/send` | JWT | — | Отправить шаблонное письмо всем участникам группы. Тело: `{ groupId, subject, htmlContent }` |
| DELETE | `/:id` | JWT | — | Удалить шаблон письма |

### Пример: отправить письмо группе

```
POST /messaging/emailTemplates/send
Authorization: Bearer <token>

{
  "groupId": "group-123",
  "subject": "This Week's Update - {{churchName}}",
  "htmlContent": "<p>Hello {{firstName}},</p><p>Here's what's happening this week...</p>"
}
```

```json
{
  "totalMembers": 50,
  "recipientCount": 45,
  "successCount": 44,
  "failCount": 1,
  "noEmailCount": 5
}
```

**Поддерживаемые поля подстановки:** `{{firstName}}`, `{{lastName}}`, `{{displayName}}`, `{{email}}`, `{{churchName}}`

## Заблокированные IP-адреса

Базовый путь: `/messaging/blockedips`

(устаревший) Блокировка IP-адресов для чата прямых трансляций. Клиент B1App больше не вызывает `POST /` -- блокировка IP была удалена при миграции на единую доставку. Маршрут `/clear` по-прежнему вызывается между серверами из `StreamingServiceController` при сохранении трансляций.

| Метод | Путь | Аутентификация | Право | Описание |
|--------|------|------------|-------------|-------------|
| POST | `/` | JWT | — | (устаревший) Сохранить заблокированные IP (пакетно). Нет активного клиента |
| POST | `/clear` | JWT | — | Очистить все заблокированные IP для конкретных служб. Тело: `[{ serviceId, churchId }]` |

## Журналы доставки

Базовый путь: `/messaging/deliverylogs`

Отслеживает статус доставки отправленных сообщений (SMS, push-уведомления, email).

| Метод | Путь | Аутентификация | Право | Описание |
|--------|------|------------|-------------|-------------|
| GET | `/content/:contentType/:contentId` | JWT | — | Загрузить журналы доставки по типу и ID контента |
| GET | `/person/:personId` | JWT | — | Загрузить журналы доставки для человека. Необязательные `?startDate=&endDate=` для фильтрации |
| GET | `/recent` | JWT | — | Загрузить недавние журналы доставки церкви. Необязательный `?limit=` (по умолчанию 100) |
| GET | `/:id` | JWT | — | Загрузить журнал доставки по ID |
