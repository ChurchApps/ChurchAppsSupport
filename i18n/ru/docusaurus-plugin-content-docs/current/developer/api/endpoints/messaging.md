# Эндпоинты Messaging

<div class="article-intro">

Модуль Messaging управляет беседами в реальном времени, сообщениями чата, push-уведомлениями, доставкой SMS и электронной почты, WebSocket-соединениями, личными сообщениями, регистрацией устройств и провайдерами текстовых сообщений. Он обеспечивает коммуникационный уровень, используемый во всех приложениях ChurchApps, как для чата живых трансляций, так и для асинхронных уведомлений.

</div>

**Базовый путь:** `/messaging`

## Беседы

| Метод | Путь | Авторизация | Разрешение | Описание |
|--------|------|------|------------|-------------|
| GET | `/timeline/ids?ids=` | JWT | — | Загрузить беседы по идентификаторам, перечисленным через запятую, с первым и последним сообщениями |
| GET | `/messages/:contentType/:contentId` | JWT | — | Загрузить беседы для контента с постраничными сообщениями (`?page=&limit=`) |
| GET | `/posts` | JWT | — | Получить беседы типа «публикация» для групп текущего пользователя |
| GET | `/posts/group/:groupId` | JWT | — | Получить беседы типа «публикация» для конкретной группы |
| GET | `/current/:churchId/:contentType/:contentId` | Public | — | Получить или создать текущую беседу для контента (contentId расшифровывается автоматически) |
| GET | `/:churchId/:contentType/:contentId` | Public | — | Загрузить беседы по типу контента и идентификатору |
| GET | `/:churchId/:id` | Public | — | Загрузить одну беседу по идентификатору |
| POST | `/` | JWT | — | Создать или обновить беседы (пакетно) |
| POST | `/start` | JWT | — | Начать новую беседу с первым комментарием |
| DELETE | `/:churchId/:id` | JWT | — | Удалить беседу |

### Контроль доступа к заметкам о людях

Беседы с `contentType: "person"` (вкладка **Заметки** в карточке человека) или `contentType: "personConfidential"` (раздел **Конфиденциальные заметки**) защищены на каждом пути чтения и записи, включая перечисленные выше публичные маршруты, которые для этих типов контента возвращают `401`. Для `person` требуется разрешение MembershipApi **People / Edit**; для `personConfidential` — разрешение **People / View Confidential Notes**. Для ключей API с ограниченной областью действия `people:write` включает оба действия (пользователь, которому принадлежит ключ, по-прежнему должен иметь соответствующее разрешение роли).

### Контроль доступа к заметкам групп и событий {#group-and-event-notes-access-control}

Еще два типа заметок защищены так же, на каждом пути чтения и записи (включая публичные маршруты выше), и никогда не открыты для анонимной публикации:

- **`groupNote`** (`contentId` = идентификатор группы) — лента **Заметки руководителей** в группе. Читать и публиковать могут только руководители этой группы (`leaderGroupIds` в JWT). Никакое разрешение сотрудника не дает доступа, включая `content.edit` и разрешения на членство в группах.
- **`eventNote`** (`contentId` = идентификатор события) — заметки к событию календаря. Сотрудники с `content.edit` или **Calendars / Admin** всегда могут читать и публиковать. В остальных случаях доступ определяется полями события `notesViewRole` (чтение) и `notesPostRole` (публикация): `staff` (по умолчанию, используется, когда поле равно `null`) не дает доступа никому другому, `leaders` дает доступ руководителям группы события, а `members` — участникам и руководителям группы события. Событие без `groupId` доступно только сотрудникам.

### Контроль доступа к заметкам карточек рабочего процесса

Беседы с `contentType: "workflowCard"` (заметки к карточке рабочего процесса, где `contentId` — идентификатор задачи карточки) может читать и изменять только тот, кто может открыть эту карточку: пользователь с разрешением DoingApi **Tasks / View**, либо человек или группа, которым назначена карточка, которые ее создали или которых она касается. Все остальные получают `401` на каждом пути чтения, включая публичные маршруты выше. Беседа прикрепляется к карточке через саму карточку командой `POST /doing/tasks/:id/conversation` (тело `{ "conversationId": "..." }`; побеждает первая прикрепленная беседа), которую могут вызывать редакторы карточки и ее исполнитель.

### Пример: начало беседы

```
POST /messaging/conversations/start
Authorization: Bearer <token>

{
  "groupId": "group-123",
  "contentType": "group",
  "contentId": "group-123",
  "title": "Weekly Discussion",
  "comment": "Welcome to this week's discussion thread!"
}
```

```json
{
  "id": "conv-456",
  "churchId": "church-789",
  "contentType": "group",
  "contentId": "group-123",
  "title": "Weekly Discussion",
  "dateCreated": "2026-02-17T10:00:00.000Z",
  "visibility": "public",
  "allowAnonymousPosts": false,
  "groupId": "group-123"
}
```

## Сообщения

Базовый путь: `/messaging/messages`

| Метод | Путь | Авторизация | Разрешение | Описание |
|--------|------|------|------------|-------------|
| GET | `/conversation/:conversationId` | JWT | — | Загрузить все сообщения беседы |
| GET | `/catchup/:churchId/:conversationId` | Public | — | Загрузить все сообщения беседы (публичная догрузка для живого чата) |
| GET | `/:churchId/:id` | Public | — | Загрузить одно сообщение по идентификатору |
| POST | `/` | JWT | — | Сохранить сообщения (пакетно). Отправляет обновления в реальном времени и запускает уведомления. Для изменения существующего сообщения нужно быть его автором или иметь `content.edit`; сохраненный автор никогда не может быть переназначен |
| POST | `/send` | Public | — | Отправить сообщения (пакетно, публично). Отправляет обновления в реальном времени через WebSocket и запускает уведомления |
| POST | `/setCallout` | JWT | — | (устаревший) Транслировать выделенное сообщение в реальном времени. Активных клиентов нет; чат живых трансляций больше не отображает выделенные сообщения |
| DELETE | `/:churchId/:id` | JWT | — | Удалить сообщение и транслировать удаление в реальном времени. См. [Модерация сообщений](#message-moderation) |

### Модерация сообщений {#message-moderation}

Удалить сообщение могут:

- автор сообщения;
- сотрудники с `content.edit` (в любом месте церкви);
- **руководители групп** — для бесед с `contentType` равным `group` или `groupAnnouncement`, у которых `contentId` — это группа, которой они руководят (`leaderGroupIds` в JWT).

Беседы с заметками о людях (`person` / `personConfidential`) никогда не модерируются руководителями — для них действуют разрешения на заметки (`people.edit`, `people.viewConfidentialNotes`).

Руководители могут только удалять сообщения, но не редактировать их: переписывать сообщение другого участника по-прежнему могут только автор и сотрудники с `content.edit`.

### Пример: отправка сообщения

```
POST /messaging/messages/send

[
  {
    "churchId": "church-789",
    "conversationId": "conv-456",
    "personId": "person-123",
    "displayName": "John Smith",
    "content": "Hello everyone!",
    "messageType": "comment"
  }
]
```

```json
[
  {
    "id": "msg-001",
    "churchId": "church-789",
    "conversationId": "conv-456",
    "personId": "person-123",
    "displayName": "John Smith",
    "timeSent": "2026-02-17T10:05:00.000Z",
    "content": "Hello everyone!",
    "messageType": "comment"
  }
]
```

## SMS-рассылка

Базовый путь: `/messaging/texting`

Управляет провайдерами SMS, групповой рассылкой текстовых сообщений и отслеживанием доставки.

| Метод | Путь | Авторизация | Разрешение | Описание |
|--------|------|------|------------|-------------|
| GET | `/providers` | JWT | — | Загрузить провайдеров текстовых сообщений церкви (учетные данные скрыты) |
| GET | `/status` | JWT | — | `{ enabled }` — включен ли у церкви провайдер текстовых сообщений. Доступно любому авторизованному пользователю церкви; используется, чтобы показывать опции **Текст** только тогда, когда можно отправлять SMS |
| GET | `/inboundUrl` | JWT | `texting.send` или `settings.edit` | `{ url }` — URL входящего вебхука (STOP) церкви, который нужно вставить в настройки провайдера |
| POST | `/inbound/:churchId/:token` | Public | — | Вебхук входящих сообщений провайдера. `token` — это HMAC от идентификатора церкви. Ответ, который точно совпадает с стоп-словом (`STOP`, `STOPALL`, `UNSUBSCRIBE`, `CANCEL`, `END`, `QUIT`, `OPTOUT`, `REVOKE`), помечает всех подходящих людей как `optedOut` и отключает их `allowSms`. Возвращает `{ optedOut: <count> }`; другие ответы возвращают `{ optedOut: 0 }` |
| GET | `/preview/:groupId` | JWT | — | Предпросмотр получателей групповой SMS (количество подходящих, отказавшихся и без номера телефона) |
| GET | `/sent` | JWT | — | Загрузить все записи отправленных текстовых сообщений церкви |
| GET | `/sent/:id/details` | JWT | — | Загрузить отправленное текстовое сообщение с журналами доставки по каждому получателю |
| POST | `/providers` | JWT | — | Сохранить провайдеров текстовых сообщений (пакетно). Шифрует учетные данные API |
| POST | `/send` | JWT | — | Отправить SMS всем подходящим участникам группы. Тело: `{ groupId, message }`. Поля подстановки (`{{firstName}}`, `{{lastName}}`, `{{displayName}}`, `{{churchName}}`) подставляются для каждого получателя |
| POST | `/sendPerson` | JWT | — | Отправить SMS одному человеку. Тело: `{ personId, phoneNumber, message }`. Поля подстановки заменяются, и в журнал записывается уже подставленный текст |
| DELETE | `/providers/:id` | JWT | — | Удалить провайдера текстовых сообщений |

### Пример: групповая SMS-рассылка

```

{
  "groupId": "group-123",
  "message": "Reminder: Service starts at 10 AM this Sunday!"
}
```

```json

  "totalMembers": 50,
  "recipientCount": 42,
```

## Заблокированные IP-адреса

Базовый путь: `/messaging/blockedips`

(устаревший) Блокировка IP-адресов для чата живых трансляций. Клиент B1App больше не вызывает `POST /` — блокировка IP была удалена в ходе миграции к унифицированной доставке. Маршрут `/clear` по-прежнему вызывается между серверами из `StreamingServiceController` при сохранении служб трансляции.

| Метод | Путь | Авторизация | Разрешение | Описание |
|--------|------|------|------------|-------------|
| POST | `/` | JWT | — | (устаревший) Сохранить заблокированные IP-адреса (пакетно). Активных клиентов нет |
| POST | `/clear` | JWT | — | Очистить все заблокированные IP-адреса для конкретных служб. Тело: `[{ serviceId, churchId }]` |

## Журналы доставки

Базовый путь: `/messaging/deliverylogs`

Отслеживает статус доставки отправленных сообщений (SMS, push-уведомления, электронная почта).

| Метод | Путь | Авторизация | Разрешение | Описание |
|--------|------|------|------------|-------------|
| GET | `/content/:contentType/:contentId` | JWT | — | Загрузить журналы доставки по типу и идентификатору контента |
| GET | `/person/:personId` | JWT | — | Загрузить журналы доставки для человека. Необязательные фильтры `?startDate=&endDate=` |
| GET | `/recent` | JWT | — | Загрузить недавние журналы доставки для церкви. Необязательный `?limit=` (по умолчанию 100) |
| GET | `/:id` | JWT | — | Загрузить журнал доставки по идентификатору |
