# Эндпоинты модуля Messaging

<div class="article-intro">

Модуль Messaging управляет диалогами в реальном времени, сообщениями чата, push-уведомлениями, доставкой SMS/email, WebSocket-соединениями, личными сообщениями, регистрацией устройств и провайдерами текстовых сообщений. Он обеспечивает коммуникационный уровень, который используется во всех приложениях ChurchApps как для чата прямых трансляций, так и для асинхронных уведомлений.

</div>

**Базовый путь:** `/messaging`

|--------|------|------|------------|-------------|
| GET | `/timeline/ids?ids=` | JWT | — | Загрузить диалоги по ID, перечисленным через запятую, с первым и последним сообщениями |
| GET | `/messages/:contentType/:contentId` | JWT | — | Загрузить диалоги для контента с постраничными сообщениями (`?page=&limit=`) |
| GET | `/posts` | JWT | — | Получить диалоги типа «публикация» для групп текущего пользователя |
| GET | `/posts/group/:groupId` | JWT | — | Получить диалоги типа «публикация» для конкретной группы |

Каждая заметка по-прежнему проходит правило своего типа (разрешение People Edit / конфиденциальные заметки, руководители группы, просматривающие события, просматривающие карточки процессов), поэтому вызывающие видят только те заметки, которые могли бы открыть. | GET | `/:churchId/:contentType/:contentId` | Публично | — | Загрузить диалоги по типу контента и ID |
| GET | `/:churchId/:id` | Публично | — | Загрузить один диалог по ID |
| POST | `/` | JWT | — | Создать или обновить диалоги (пакетно) |
| POST | `/start` | JWT | — | Начать новый диалог с первым комментарием |
| DELETE | `/:churchId/:id` | JWT | — | Удалить диалог |

### Контроль доступа к заметкам о людях

Диалоги с `contentType: "person"` (вкладка Notes в записи человека) или `contentType: "personConfidential"` (раздел Confidential Notes) ограничены на каждом пути чтения и записи, включая перечисленные выше публичные маршруты, которые возвращают `401` для этих типов контента. Для `person` требуется разрешение MembershipApi **People / Edit**; для `personConfidential` — **People / View Confidential Notes**. Для ключей API с ограниченными областями `people:write` включает оба действия (пользователь, которому принадлежит ключ, по-прежнему должен иметь базовое разрешение роли).

### Контроль доступа к заметкам группы и события {#group-and-event-notes-access-control}

Еще два типа заметок ограничены так же, на каждом пути чтения и записи (включая публичные маршруты выше), и никогда не открыты для анонимной публикации:

- **`groupNote`** (`contentId` = ID группы) — лента **Leader notes** в группе. Читать или публиковать могут только руководители этой группы (`leaderGroupIds` в JWT). Никакое разрешение персонала не дает доступа, включая `content.edit` и разрешения членства в группе.
- **`eventNote`** (`contentId` = ID события) — заметки к событию календаря. Персонал с `content.edit` или **Calendars / Admin** всегда может читать и публиковать. В остальных случаях доступ определяется полями события `notesViewRole` (чтение) и `notesPostRole` (публикация): `staff` (по умолчанию, используется, когда поле равно `null`) не разрешает никому другому, `leaders` разрешает руководителям группы события, а `members` разрешает участникам и руководителям группы события. Событие без `groupId` доступно только персоналу.

### Контроль доступа к заметкам карточки процесса

Диалоги с `contentType: "workflowCard"` (заметки на карточке процесса, где `contentId` — это ID задачи карточки) могут читать и изменять только те, кто может открыть эту карточку: пользователь с разрешением DoingApi **Tasks / View**, либо человек или группа, которым назначена карточка, которые ее создали или к которым она относится. Все остальные получают `401` на каждом пути чтения, включая публичные маршруты выше. Диалог карточки привязывается через саму карточку с помощью `POST /doing/tasks/:id/conversation` (тело `{ "conversationId": "..." }`; побеждает первый привязанный диалог), что могут вызывать редакторы карточки и ее исполнитель.

### Пример: начать диалог

```
POST /messaging/conversations/start
Authorization: Bearer <token>

{
  "groupId": "group-123",
  "contentType": "group",
  "contentId": "group-123",
  "title": "Weekly Discussion",
  "comment": "Welcome to this week's discussion thread!"
}
```

```json
{
  "id": "conv-456",
  "churchId": "church-789",
  "contentType": "group",
  "contentId": "group-123",
  "title": "Weekly Discussion",
  "dateCreated": "2026-02-17T10:00:00.000Z",
  "visibility": "public",
  "allowAnonymousPosts": false,
  "groupId": "group-123"
}
```

| Метод | Путь | Авторизация | Разрешение | Описание |
|--------|------|------|------------|-------------|
| GET | `/conversation/:conversationId` | JWT | — | Загрузить все сообщения диалога |
| GET | `/catchup/:churchId/:conversationId` | Публично | — | Загрузить все сообщения диалога (публичная догрузка для живого чата) |
| GET | `/:churchId/:id` | Публично | — | Загрузить одно сообщение по ID |
| POST | `/` | JWT | — | Сохранить сообщения (пакетно). Отправляет обновления в реальном времени и запускает уведомления. Для изменения существующего сообщения нужно быть его автором или иметь `content.edit`; сохраненный автор никогда не может быть переназначен |
| POST | `/send` | Публично | — | Отправить сообщения (пакетно, публично). Отправляет обновления в реальном времени через WebSocket и запускает уведомления |
| POST | `/setCallout` | JWT | — | (устаревший) Разослать сообщение-выноску в реальном времени. Активного клиента нет; чат прямых трансляций больше не отображает выноски |
| DELETE | `/:churchId/:id` | JWT | — | Удалить сообщение и разослать удаление в реальном времени. См. [Модерация сообщений](#message-moderation) |

### Модерация сообщений {#message-moderation}

Удалить сообщение могут:

- автор сообщения;
- персонал с `content.edit` (в любой точке церкви);
- **руководители групп** — для диалогов с `contentType` `group` или `groupAnnouncement`, у которых `contentId` — группа, которую они возглавляют (`leaderGroupIds` в JWT).

Диалоги с заметками о людях (`person` / `personConfidential`) никогда не модерируются руководителями — для них действуют разрешения на заметки (`people.edit`, `people.viewConfidentialNotes`).

Руководители могут только удалять, но не редактировать: переписывать чужое сообщение по-прежнему могут только автор и персонал с `content.edit`.

### Пример: отправить сообщение

```
POST /messaging/messages/send

[
  {
    "churchId": "church-789",
    "conversationId": "conv-456",
    "personId": "person-123",
    "displayName": "John Smith",
    "content": "Hello everyone!",
    "messageType": "comment"
  }
]
```

```json
[
  {
    "id": "msg-001",
    "churchId": "church-789",
    "conversationId": "conv-456",
    "personId": "person-123",
    "displayName": "John Smith",
    "timeSent": "2026-02-17T10:05:00.000Z",
    "content": "Hello everyone!",
    "messageType": "comment"
  }
]
```

## Текстовые сообщения

Базовый путь: `/messaging/texting`

Управляет провайдерами SMS, групповой текстовой рассылкой и отслеживанием доставки.

| Метод | Путь | Авторизация | Разрешение | Описание |
|--------|------|------|------------|-------------|
| GET | `/providers` | JWT | — | Загрузить провайдеров текстовых сообщений церкви (учетные данные скрыты) |
| GET | `/status` | JWT | — | `{ enabled }` — включен ли у церкви провайдер текстовых сообщений. Любой вошедший пользователь церкви; используется, чтобы показывать опции **Text** только тогда, когда сообщения можно отправлять |
| GET | `/inboundUrl` | JWT | `texting.send` или `settings.edit` | `{ url }` — URL входящего вебхука церкви (STOP), который нужно вставить в провайдера |
| POST | `/inbound/:churchId/:token` | Публично | — | Вебхук входящих сообщений провайдера. `token` — это HMAC от ID церкви. Ответ, который точно совпадает с стоп-словом (`STOP`, `STOPALL`, `UNSUBSCRIBE`, `CANCEL`, `END`, `QUIT`, `OPTOUT`, `REVOKE`), помечает всех подходящих людей как `optedOut` и выключает их `allowSms`. Возвращает `{ optedOut: <count> }`; другие ответы возвращают `{ optedOut: 0 }` |
| GET | `/preview/:groupId` | JWT | — | Предпросмотр получателей группового текстового сообщения (количество подходящих, отказавшихся и без телефона) |
| GET | `/sent` | JWT | — | Загрузить все записи отправленных текстовых сообщений церкви |
| GET | `/sent/:id/details` | JWT | — | Загрузить отправленное текстовое сообщение с журналами доставки по каждому получателю |
| POST | `/providers` | JWT | — | Сохранить провайдеров текстовых сообщений (пакетно). Шифрует API-учетные данные |
| POST | `/send` | JWT | — | Отправить SMS всем подходящим участникам группы. Тело: `{ groupId, message }`. Поля подстановки (`{{firstName}}`, `{{lastName}}`, `{{displayName}}`, `{{churchName}}`) заменяются для каждого получателя |
| POST | `/sendPerson` | JWT | — | Отправить SMS одному человеку. Тело: `{ personId, phoneNumber, message }`. Поля подстановки заменяются, и в журнал записывается уже заменённый текст |
| DELETE | `/providers/:id` | JWT | — | Удалить провайдера текстовых сообщений |

### Пример: отправить email группе


## Заблокированные IP-адреса

Базовый путь: `/messaging/blockedips`

(устаревший) Блокировка IP для чата прямых трансляций. Клиент B1App больше не вызывает `POST /` — блокировка IP была удалена в ходе миграции к единой доставке. Маршрут `/clear` по-прежнему вызывается между серверами из `StreamingServiceController` при сохранении служб трансляции.

| Метод | Путь | Авторизация | Разрешение | Описание |
|--------|------|------|------------|-------------|
| POST | `/` | JWT | — | (устаревший) Сохранить заблокированные IP (пакетно). Активного клиента нет |
| POST | `/clear` | JWT | — | Очистить все заблокированные IP для конкретных служб. Тело: `[{ serviceId, churchId }]` |

## Журналы доставки

Базовый путь: `/messaging/deliverylogs`

Отслеживает статус доставки отправленных сообщений (SMS, push-уведомления, email).

| Метод | Путь | Авторизация | Разрешение | Описание |
|--------|------|------|------------|-------------|
| GET | `/content/:contentType/:contentId` | JWT | — | Загрузить журналы доставки по типу контента и ID |
| GET | `/person/:personId` | JWT | — | Загрузить журналы доставки для человека. Необязательные фильтры `?startDate=&endDate=` |
| GET | `/recent` | JWT | — | Загрузить недавние журналы доставки церкви. Необязательный `?limit=` (по умолчанию 100) |
| GET | `/:id` | JWT | — | Загрузить журнал доставки по ID |
