# Конечные точки сообщений

<div class="article-intro">

Модуль сообщений управляет беседами в реальном времени, чат-сообщениями, push-уведомлениями, доставкой SMS и электронной почты, WebSocket-соединениями, личными сообщениями, регистрацией устройств и провайдерами SMS-рассылки. Он обеспечивает слой коммуникации, который используется во всех приложениях ChurchApps как для чата в прямых трансляциях, так и для асинхронных уведомлений.

</div>

**Базовый путь:** `/messaging`

## Беседы

Базовый путь: `/messaging/conversations`

| Метод | Путь | Авторизация | Разрешение | Описание |
|--------|------|------------|------------|----------|
| GET | `/timeline/ids?ids=` | JWT | — | Загрузить беседы по ID, перечисленным через запятую, с первым и последним сообщениями |
| GET | `/messages/:contentType/:contentId` | JWT | — | Загрузить беседы для контента с постраничными сообщениями (`?page=&limit=`) |
| GET | `/posts` | JWT | — | Получить беседы типа «публикация» для групп текущего пользователя |
| GET | `/posts/group/:groupId` | JWT | — | Получить беседы типа «публикация» для указанной группы |
| GET | `/notes/feed?section=&limit=&before=` | JWT | — | Самые новые заметки по всем записям для страницы заметок B1 Admin. `section` может быть `people`, `groups`, `events` или `workflows` (иначе ошибка 400); `limit` по умолчанию 25 (максимум 100); `before` — курсор из предыдущей страницы. Каждая заметка по-прежнему проверяется по правилу своего типа (право редактирования людей / конфиденциальные заметки, руководители группы, просматривающие события, просматривающие карточки процессов), поэтому вызывающая сторона видит только те заметки, которые ей доступны. Текст заметки обрезается до 300 символов |
| GET | `/current/:churchId/:contentType/:contentId` | Публичный | — | Получить или создать текущую беседу для контента (автоматически расшифровывает contentId) |
| GET | `/:churchId/:contentType/:contentId` | Публичный | — | Загрузить беседы по типу контента и ID |
| GET | `/:churchId/:id` | Публичный | — | Загрузить одну беседу по ID |
| POST | `/` | JWT | — | Создать или обновить беседы (пакетно) |
| POST | `/start` | JWT | — | Начать новую беседу с первым комментарием |
| DELETE | `/:churchId/:id` | JWT | — | Удалить беседу |

### Контроль доступа к заметкам о людях

Беседы с `contentType: "person"` (вкладка «Заметки» в карточке человека) или `contentType: "personConfidential"` (раздел «Конфиденциальные заметки») защищены на каждом пути чтения и записи, включая перечисленные выше публичные маршруты, которые для этих типов контента возвращают `401`. Для `person` требуется разрешение MembershipApi **Люди / Редактирование**; для `personConfidential` требуется **Люди / Просмотр конфиденциальных заметок**. Для ключей API с ограниченной областью действия `people:write` включает оба действия (пользователь, которому принадлежит ключ, по-прежнему должен иметь соответствующее разрешение роли).

### Контроль доступа к заметкам групп и событий {#group-and-event-notes-access-control}

Два других типа заметок защищены аналогично, на каждом пути чтения и записи (включая публичные маршруты выше), и никогда не открыты для анонимной публикации:

- **`groupNote`** (`contentId` = ID группы) -- лента **заметок руководителей** в группе. Читать или писать могут только руководители этой группы (`leaderGroupIds` в JWT). Никакое разрешение персонала не открывает доступ, включая `content.edit` и разрешения, связанные с членством в группе.
- **`eventNote`** (`contentId` = ID события) -- заметки к событию в календаре. Сотрудники с `content.edit` или **Календари / Администрирование** всегда могут читать и писать. В остальных случаях доступ определяется полями события `notesViewRole` (чтение) и `notesPostRole` (публикация): `staff` (значение по умолчанию, используется, когда поле равно `null`) не открывает доступ никому, кроме персонала; `leaders` открывает доступ руководителям группы события; `members` открывает доступ участникам и руководителям группы события. Событие без `groupId` доступно только персоналу.

### Контроль доступа к заметкам карточек процессов

Беседы с `contentType: "workflowCard"` (заметки к карточке процесса, где `contentId` -- это ID задачи карточки) может читать и изменять только тот, кто может открыть эту карточку: пользователь с разрешением DoingApi **Задачи / Просмотр**, либо человек или группа, которым назначена карточка, которые создали карточку или к которым она относится. Все остальные получают `401` на каждом пути чтения, включая публичные маршруты выше. Беседа карточки прикрепляется через саму карточку с помощью `POST /doing/tasks/:id/conversation` (тело `{ "conversationId": "..." }`; побеждает первая прикреплённая беседа), вызывать который могут редакторы карточки и её исполнитель.

### Пример: начало беседы

```
POST /messaging/conversations/start
Authorization: Bearer <token>

{
  "groupId": "group-123",
  "contentType": "group",
  "contentId": "group-123",
  "title": "Weekly Discussion",
  "comment": "Welcome to this week's discussion thread!"
}
```

```json
{
  "id": "conv-456",
  "churchId": "church-789",
  "contentType": "group",
  "contentId": "group-123",
  "title": "Weekly Discussion",
  "dateCreated": "2026-02-17T10:00:00.000Z",
  "visibility": "public",
  "allowAnonymousPosts": false,
  "groupId": "group-123"
}
```

## Сообщения

Базовый путь: `/messaging/messages`

| Метод | Путь | Авторизация | Разрешение | Описание |
|--------|------|------------|------------|----------|
| GET | `/conversation/:conversationId` | JWT | — | Загрузить все сообщения беседы |
| GET | `/catchup/:churchId/:conversationId` | Публичный | — | Загрузить все сообщения беседы (публичная синхронизация для чата в прямом эфире) |
| GET | `/:churchId/:id` | Публичный | — | Загрузить одно сообщение по ID |
| POST | `/` | JWT | — | Сохранить сообщения (пакетно). Отправляет обновления в реальном времени и запускает уведомления. Для изменения существующего сообщения нужно быть его автором или иметь `content.edit`; сохранённый автор никогда не может быть переназначен |
| POST | `/send` | Публичный | — | Отправить сообщения (пакетно, публично). Отправляет обновления в реальном времени через WebSocket и запускает уведомления |
| POST | `/setCallout` | JWT | — | (устаревший) Передать выделенное сообщение в реальном времени. Активных клиентов нет; чат прямых трансляций больше не отображает выделенные сообщения |
| DELETE | `/:churchId/:id` | JWT | — | Удалить сообщение и передать информацию об удалении в реальном времени. См. [Модерация сообщений](#message-moderation) |

### Модерация сообщений

Удалять сообщение могут:

- автор сообщения;
- сотрудники с `content.edit` (в любом месте церкви);
- **руководители групп** -- для бесед с `contentType` равным `group` или `groupAnnouncement`, у которых `contentId` -- это группа, которой они руководят (`leaderGroupIds` в JWT).

Беседы о заметках к людям (`person` / `personConfidential`) никогда не модерируются руководителями -- для них действуют разрешения на заметки (`people.edit`, `people.viewConfidentialNotes`).

Руководители могут только удалять, но не редактировать: переписывание чужого сообщения остаётся доступным только автору и сотрудникам с `content.edit`.

### Пример: отправка сообщения

```
POST /messaging/messages/send

[
  {
    "churchId": "church-789",
    "conversationId": "conv-456",
    "personId": "person-123",
    "displayName": "John Smith",
    "content": "Hello everyone!",
    "messageType": "comment"
  }
]
```

```json
[
  {
    "id": "msg-001",
    "churchId": "church-789",
    "conversationId": "conv-456",
    "personId": "person-123",
    "displayName": "John Smith",
    "timeSent": "2026-02-17T10:05:00.000Z",
    "content": "Hello everyone!",
    "messageType": "comment"
  }
]
```

## SMS-рассылка

Базовый путь: `/messaging/texting`

Управляет провайдерами SMS, групповой рассылкой текстовых сообщений и отслеживанием доставки.

| Метод | Путь | Авторизация | Разрешение | Описание |
|--------|------|------------|------------|----------|
| GET | `/providers` | JWT | — | Загрузить провайдеров SMS для церкви (учётные данные скрыты) |
| GET | `/status` | JWT | — | `{ enabled }` -- включён ли у церкви провайдер SMS. Доступно любому авторизованному пользователю церкви; используется для показа вариантов **Текст** только тогда, когда сообщения можно отправить |
| GET | `/inboundUrl` | JWT | `texting.send` или `settings.edit` | `{ url }` -- входящий (STOP) webhook-адрес церкви, который нужно вставить в настройки провайдера |
| POST | `/inbound/:churchId/:token` | Публичный | — | Webhook входящих сообщений от провайдера. `token` -- это HMAC от ID церкви. Ответ, состоящий ровно из стоп-слова (`STOP`, `STOPALL`, `UNSUBSCRIBE`, `CANCEL`, `END`, `QUIT`, `OPTOUT`, `REVOKE`), помечает всех подходящих людей как `optedOut` и отключает их `allowSms`. Возвращает `{ optedOut: <count> }`; другие ответы возвращают `{ optedOut: 0 }` |
| GET | `/preview/:groupId` | JWT | — | Предпросмотр получателей групповой рассылки (количество подходящих, отказавшихся и без телефона) |
| GET | `/sent` | JWT | — | Загрузить все записи отправленных текстовых сообщений церкви |
| GET | `/sent/:id/details` | JWT | — | Загрузить отправленное текстовое сообщение с журналами доставки по каждому получателю |
| POST | `/providers` | JWT | — | Сохранить провайдеров SMS (пакетно). Шифрует API-учётные данные |
| POST | `/send` | JWT | — | Отправить SMS всем подходящим участникам группы. Тело: `{ groupId, message }`. Поля подстановки (`{{firstName}}`, `{{lastName}}`, `{{displayName}}`, `{{churchName}}`) заменяются для каждого получателя отдельно |
| POST | `/sendPerson` | JWT | — | Отправить SMS одному человеку. Тело: `{ personId, phoneNumber, message }`. Поля подстановки заменяются, и в журнал записывается уже заменённый текст |
| DELETE | `/providers/:id` | JWT | — | Удалить провайдера SMS |

### Пример: групповая SMS-рассылка

  "message": "Reminder: Service starts at 10 AM this Sunday!"

## Шаблоны электронной почты

| Метод | Путь | Авторизация | Разрешение | Описание |
|--------|------|------------|------------|----------|

| GET | `/sendStatus` | JWT | `groupMembers.edit` или `tasks.admin` | Статус электронной почты групп церкви: `{ approved, paused, remaining, requested }`. Диалог «Отправить письмо» в B1Admin и действие процесса **Отправить письмо** используют его, чтобы предупредить, когда письмо не будет отправлено |
| POST | `/requestApproval` | JWT | `groupMembers.edit` | Попросить службу поддержки одобрить церковь для почты групп (не более одного раза в неделю для каждой церкви) |
| GET | `/preview/:groupId` | JWT | — | Предпросмотр доставки писем группе (количество подходящих получателей, участники без адреса) |
| POST | `/` | JWT | — | Создать или обновить шаблоны электронной почты (пакетно) |
| POST | `/send` | JWT | — | Отправить шаблонное письмо всем участникам группы. Тело: `{ groupId, subject, htmlContent }` |
| DELETE | `/:id` | JWT | — | Удалить шаблон электронной почты |

### Пример: отправка письма группе

```
POST /messaging/emailTemplates/send
Authorization: Bearer <token>

{
  "groupId": "group-123",
  "subject": "This Week's Update - {{churchName}}",
  "htmlContent": "<p>Hello {{firstName}},</p><p>Here's what's happening this week...</p>"
}
```

```json
{
  "totalMembers": 50,
  "recipientCount": 45,
  "successCount": 44,
  "failCount": 1,
  "noEmailCount": 5
}
```

**Поддерживаемые поля подстановки:** `{{firstName}}`, `{{lastName}}`, `{{displayName}}`, `{{email}}`, `{{churchName}}`

## Заблокированные IP-адреса

Базовый путь: `/messaging/blockedips`

(устаревший) Блокировка IP-адресов для чата прямых трансляций. Клиент B1App больше не вызывает `POST /` -- блокировка IP была удалена в ходе миграции на единую доставку. Маршрут `/clear` по-прежнему вызывается сервер-к-серверу из `StreamingServiceController` при сохранении служб трансляции.

| Метод | Путь | Авторизация | Разрешение | Описание |
|--------|------|------------|------------|----------|
| POST | `/` | JWT | — | (устаревший) Сохранить заблокированные IP-адреса (пакетно). Активных клиентов нет |
| POST | `/clear` | JWT | — | Очистить все заблокированные IP-адреса для указанных служб. Тело: `[{ serviceId, churchId }]` |

## Журналы доставки

Базовый путь: `/messaging/deliverylogs`

Отслеживает статус доставки отправленных сообщений (SMS, push-уведомлений, электронной почты).

| Метод | Путь | Авторизация | Разрешение | Описание |
|--------|------|------------|------------|----------|
| GET | `/content/:contentType/:contentId` | JWT | — | Загрузить журналы доставки по типу и ID контента |
| GET | `/person/:personId` | JWT | — | Загрузить журналы доставки для человека. Необязательные `?startDate=&endDate=` для фильтрации |
| GET | `/recent` | JWT | — | Загрузить последние журналы доставки церкви. Необязательный `?limit=` (по умолчанию 100) |
| GET | `/:id` | JWT | — | Загрузить журнал доставки по ID |
