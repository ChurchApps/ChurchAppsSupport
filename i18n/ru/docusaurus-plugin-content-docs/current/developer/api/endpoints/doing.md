# Эндпоинты Doing

<div class="article-intro">

Модуль Doing управляет планированием служений, расписанием волонтёров, управлением задачами и автоматизацией. Он предоставляет инструменты для создания планов служений с временем и позициями, назначения волонтёров, управления датами недоступности, формирования элементов порядка служения, подключения к внешним поставщикам контента и настройки автоматизированных процессов с условиями и действиями.

</div>

**Базовый путь:** `/doing`

## Планы

Базовый путь: `/doing/plans`

| Метод | Путь | Авторизация | Разрешение | Описание |
|--------|------|------|------------|-------------|
| GET | `/` | JWT | — | Список всех планов церкви |
| GET | `/:id` | JWT | — | Получить план по ID |
| GET | `/ids?ids=` | JWT | — | Получить несколько планов по ID через запятую |
| GET | `/types/:planTypeId` | JWT | — | Получить планы по типу плана |
| GET | `/textRange?startDate=&endDate=&ministryId=&planTypeId=` | JWT | `texting.send` + право редактирования служения | Предпросмотр сводки, которую **Text Volunteers** отправит для служения: `{ totalMembers, eligibleCount, optedOutCount, noPhoneCount, capped }` для волонтёров, назначенных в диапазоне (один раз на человека; отказавшиеся и без номера пропускаются; общие номера дедуплицируются; ограничение 200) |
| GET | `/presenter` | JWT | — | Получить планы на следующие 7 дней (вид для презентации) |
| GET | `/confirmationWorkflows?ministryId=` | JWT | Право редактирования служения | Активные рабочие процессы подтверждения назначений на служение (`workflowType = "assignmentConfirmation"`), которые можно выбрать для плана: `[{ id, name }]` |
| GET | `/public/current/:planTypeId` | Публичный | — | Получить текущий план для типа плана |
| GET | `/public/signup/:churchId` | Публичный | — | Планы, открытые для самостоятельной записи, сначала ближайшие; у каждого есть позиции самозаписи (сортировка по `categoryName`, затем по `name`, плюс `filledCount` назначений со статусом Accepted/Unconfirmed) и времена. Имена волонтёров не возвращаются. Когда настройка церкви `volunteerSignupNextOnly` равна `"true"`, возвращается только первый план каждого типа. Каждый `plan` содержит вычисляемое поле `signupDeadline` (ISO-момент или `null`): `signupDeadlineHours` до самого раннего времени плана типа `service` (если времени служения нет, то любое время с указанным временем; если у плана нет времён, то 9:00 во временной зоне церкви в дату `serviceDate`) |
| GET | `/signup/:planId/volunteers` | JWT | — | `[{ positionId, names }]` для позиций самозаписи плана (отображаемые имена назначенных со статусом Accepted/Unconfirmed). Возвращает `[]`, если у плана не включён `showVolunteerNames` |
| POST | `/` | JWT | — | Создать или обновить планы (принимает один объект или массив). Задайте `confirmationWorkflowId`, чтобы подключить план к рабочему процессу подтверждения служения, или `null`, чтобы отключить его для будущих запросов. Передайте `signupDeadlineHours: null`, чтобы снять срок; если поле не передано, сохранённое значение остаётся |
| POST | `/copy/:id` | JWT | Право редактирования служения | Скопировать план вместе с позициями, временами, назначениями и элементами порядка служения. Тело включает `ministryId`, `serviceDate`, `copyMode` ("none", "positions", "all") и `copyServiceOrder` (логическое значение). Без `targetPlanId` создаётся новый план, а `notes`, `signupDeadlineHours`, `showVolunteerNames` и `autoReplaceOnDecline` переносятся из исходного плана, если тело их не задаёт. С `targetPlanId` копия заполняет существующий план (вызывающий должен иметь право его редактировать). Опция **Repeat weekly** в B1Admin вызывает этот эндпоинт раз в неделю, каждый раз копируя из плана, созданного неделей раньше |
| POST | `/textRange` | JWT | `texting.send` + право редактирования служения | Отправить SMS каждому волонтёру, назначенному в диапазоне дат, через провайдера рассылки церкви. Тело: `{ startDate, endDate, ministryId, planTypeId?, message }` (сообщение до 1600 символов; поля подстановки разрешаются для каждого получателя). Возвращает счётчики предпросмотра, а также `recipientCount`, `successCount`, `failCount` и `error` (`no_provider` или `insufficient_credits`), если отправка остановилась раньше времени |
| POST | `/:id/issueRequests` | JWT | Право редактирования плана | Выпустить новые назначения плана со статусом Unconfirmed, по которым ещё не отправлено уведомление, через его рабочий процесс подтверждения: каждое назначение помечается как уведомлённое, и для каждого запускается одна карточка рабочего процесса. Пустое тело; возвращает `{ issued }`. Завершается ошибкой, если план не опубликован (не `prepared`), у него нет активного `confirmationWorkflowId` с хотя бы одним шагом или истёк срок ответа |
| POST | `/autofill/:id` | JWT | — | Автоматически заполнить назначения волонтёров для плана. Тело: `{ teams: [{ positionId, personIds }] }` |
| DELETE | `/:id` | JWT | — | Удалить план и все связанные времена, назначения, позиции и элементы плана |

### Пример: копирование плана

```
POST /doing/plans/copy/abc-123
Authorization: Bearer <token>

{
  "serviceDate": "2026-03-01T10:00:00.000Z",
  "copyMode": "all",
  "copyServiceOrder": true
}
```

```json
{
  "id": "def-456",
  "churchId": "church-1",
  "serviceDate": "2026-03-01T10:00:00.000Z"
}
```

| Метод | Путь | Авторизация | Разрешение | Описание |
|--------|------|------|------------|-------------|
| GET | `/:id` | JWT | — | Получить элемент плана по ID |
| GET | `/ids?ids=` | JWT | — | Получить несколько элементов плана по ID через запятую |
| GET | `/plan/:planId` | JWT | — | Получить все элементы плана (возвращается древовидная структура) |
| GET | `/presenter/:churchId/:planId` | Публичный | — | Получить элементы плана для вида презентации (возвращается древовидная структура) |
| POST | `/` | JWT | — | Создать или обновить элементы плана |

| POST | `/accept/:id` | JWT | — | Принять назначение (только назначенный человек) |
| POST | `/decline/:id` | JWT | — | Отклонить назначение (только назначенный человек) |
| POST | `/signup` | JWT | — | Самозапись на позицию. Тело: `{ positionId }`. Позиция должна допускать самозапись и иметь свободные места; создаётся назначение со статусом Accepted. Отклоняется с сообщением "Signup deadline has passed", если прошёл срок самозаписи плана (отсчитывается назад от первого времени служения, как описано выше) |
| DELETE | `/signup/:id` | JWT | — | Удалить собственную самозапись. После срока самозаписи плана отклоняется с сообщением "Removal deadline has passed" |
| DELETE | `/:id` | JWT | — | Удалить назначение |
