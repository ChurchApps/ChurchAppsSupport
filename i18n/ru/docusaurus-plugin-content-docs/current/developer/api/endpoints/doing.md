# Эндпоинты Doing

<div class="article-intro">

Модуль Doing управляет планированием служений, расписанием волонтеров, задачами и автоматизациями. Он предоставляет инструменты для создания планов служения с временем и должностями, назначения волонтеров, управления периодами недоступности, формирования элементов порядка служения, подключения к внешним поставщикам контента и настройки автоматизированных рабочих процессов с условиями и действиями.

</div>

**Базовый путь:** `/doing`

## Планы

Базовый путь: `/doing/plans`

| Метод | Путь | Авторизация | Разрешение | Описание |
|--------|------|------------|-------------|-------------|
| GET | `/` | JWT | — | Список всех планов церкви |
| GET | `/:id` | JWT | — | Получить план по ID |
| GET | `/ids?ids=` | JWT | — | Получить несколько планов по ID через запятую |
| GET | `/types/:planTypeId` | JWT | — | Получить планы по типу плана |
| GET | `/textRange?startDate=&endDate=&ministryId=&planTypeId=` | JWT | `texting.send` + редактирование служения | Предпросмотр рассылки **Text Volunteers** из обзора служения: `{ totalMembers, eligibleCount, optedOutCount, noPhoneCount, capped }` для волонтеров, назначенных в диапазоне (один на человека, пропускаются отказавшиеся от рассылки и без номера, общие номера дедуплицируются, ограничение 200) |
| GET | `/presenter` | JWT | — | Получить планы на ближайшие 7 дней (вид презентера) |
| GET | `/public/current/:planTypeId` | Public | — | Получить текущий план для типа плана |
| GET | `/public/signup/:churchId` | Public | — | Планы, открытые для самостоятельной записи, ближайшие первыми, каждый со своими должностями (сортировка по `categoryName`, затем по `name`, плюс `filledCount` назначений Accepted/Unconfirmed) и временами. Имена волонтеров не возвращаются. Когда настройка церкви `volunteerSignupNextOnly` равна `"true"`, возвращается только первый план каждого типа |
| GET | `/signup/:planId/volunteers` | JWT | — | `[{ positionId, names }]` для должностей плана с самостоятельной записью (отображаемые имена исполнителей со статусом Accepted/Unconfirmed). Возвращает `[]`, если у плана не включен `showVolunteerNames` |
| POST | `/` | JWT | — | Создать или обновить планы (принимает один объект или массив) |
| POST | `/copy/:id` | JWT | Редактирование служения | Копировать план вместе с должностями, временами, назначениями и элементами порядка служения. Тело включает `ministryId`, `serviceDate`, `copyMode` (`"none"`, `"positions"`, `"all"`) и `copyServiceOrder` (boolean). Без `targetPlanId` создается новый план, а `notes`, `signupDeadlineHours`, `showVolunteerNames` и `autoReplaceOnDecline` переносятся из исходного плана, если тело их не задает. С `targetPlanId` копия заполняет существующий план (вызывающий должен иметь право его редактировать). Опция **Repeat weekly** в B1Admin вызывает этот метод по одному разу на неделю, каждый раз копируя из плана, созданного неделей раньше |
| POST | `/textRange` | JWT | `texting.send` + редактирование служения | Отправить SMS каждому волонтеру, назначенному в диапазоне дат, через провайдера SMS церкви. Тело: `{ startDate, endDate, ministryId, planTypeId?, message }` (сообщение до 1600 символов; поля подстановки разрешаются для каждого получателя). Возвращает счетчики предпросмотра, а также `recipientCount`, `successCount`, `failCount` и `error` (`no_provider` или `insufficient_credits`), если отправка остановлена досрочно |
| POST | `/autofill/:id` | JWT | — | Автоматически заполнить назначения волонтеров для плана. Тело: `{ teams: [{ positionId, personIds }] }` |
| DELETE | `/:id` | JWT | — | Удалить план и все связанные времена, назначения, должности и элементы плана |

### Пример: копирование плана

```
POST /doing/plans/copy/abc-123
Authorization: Bearer <token>

{
  "serviceDate": "2026-03-01T10:00:00.000Z",
  "copyMode": "all",
  "copyServiceOrder": true
}
```

```json
{
  "id": "def-456",
  "churchId": "church-1",
  "serviceDate": "2026-03-01T10:00:00.000Z"
}
```

| Метод | Путь | Авторизация | Разрешение | Описание |
|--------|------|------------|-------------|-------------|
| GET | `/:id` | JWT | — | Получить элемент плана по ID |
| GET | `/ids?ids=` | JWT | — | Получить несколько элементов плана по ID через запятую |
| GET | `/plan/:planId` | JWT | — | Получить все элементы плана (возвращается древовидная структура) |
| GET | `/presenter/:churchId/:planId` | Public | — | Получить элементы плана для вида презентера (возвращается древовидная структура) |
| POST | `/` | JWT | — | Создать или обновить элементы плана |

## Лента плана

Базовый путь: `/doing/planFeed`

Предоставляет ленты элементов плана для презентера. Если элементов плана нет, автоматически заполняет их из ленты площадки Lessons.church по `contentId` плана.

| Метод | Путь | Авторизация | Разрешение | Описание |
|--------|------|------------|-------------|-------------|
| GET | `/presenter/:churchId/:planId` | Public | — | Получить ленту плана для презентера (автоматически заполняется из ленты площадки, если пуста) |

## Прокси поставщика

Базовый путь: `/doing/providerProxy`

Проксирует запросы к внешним поставщикам контента (например, ProPresenter, EasyWorship). Автоматически обрабатывает обновление токенов при их истечении.

| Метод | Путь | Авторизация | Разрешение | Описание |
|--------|------|------------|-------------|-------------|
| POST | `/browse` | JWT | — | Просмотр файлов поставщика контента. Тело: `{ ministryId, providerId, path }` |
| POST | `/getPresentations` | JWT | — | Получить презентации от поставщика контента. Тело: `{ ministryId, providerId, path }` |
| POST | `/getPlaylist` | JWT | — | Получить плейлист от поставщика контента. Тело: `{ ministryId, providerId, path, resolution }` |
| POST | `/getInstructions` | JWT | — | Получить инструкции для элемента контента. Тело: `{ ministryId, providerId, path }` |
| POST | `/getExpandedInstructions` | JWT | — | Получить расширенные инструкции для элемента контента. Тело: `{ ministryId, providerId, path }` |
