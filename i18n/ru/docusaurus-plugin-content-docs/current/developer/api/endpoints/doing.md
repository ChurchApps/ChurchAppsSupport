# Эндпоинты Doing

<div class="article-intro">

Модуль Doing управляет планированием служений, расписанием волонтёров, задачами и автоматизациями. Он предоставляет инструменты для создания планов служения с временами и позициями, назначения волонтёров, управления датами недоступности, составления элементов порядка служения, подключения к внешним поставщикам контента и настройки автоматизированных рабочих процессов с условиями и действиями.

</div>

**Базовый путь:** `/doing`

## Планы

Базовый путь: `/doing/plans`

| Метод | Путь | Auth | Права | Описание |
|--------|------|------|------------|-------------|
| GET | `/` | JWT | — | Список всех планов церкви |
| GET | `/:id` | JWT | — | Получить план по ID |
| GET | `/ids?ids=` | JWT | — | Получить несколько планов по ID, перечисленным через запятую |
| GET | `/types/:planTypeId` | JWT | — | Получить планы по типу плана |
| GET | `/textRange?startDate=&endDate=&ministryId=&planTypeId=` | JWT | `texting.send` + право на редактирование служения | Предпросмотр того, кому отправит **Text Volunteers** обзор служений: `{ totalMembers, eligibleCount, optedOutCount, noPhoneCount, capped }` для волонтёров, назначенных в диапазоне (по одному на человека, отказавшиеся и без номера пропускаются, общие номера дедуплицируются, не более 200) |
| GET | `/presenter` | JWT | — | Планы на ближайшие 7 дней (вид презентатора) |
| GET | `/confirmationWorkflows?ministryId=` | JWT | Право на редактирование служения | Активные рабочие процессы подтверждения назначений служения (`workflowType = "assignmentConfirmation"`), которые может выбрать план: `[{ id, name }]` |
| GET | `/public/current/:planTypeId` | Public | — | Получить текущий план для типа плана |
| GET | `/public/signup/:churchId` | Public | — | Планы, открытые для самостоятельной записи, ближайшие первыми; у каждого — его позиции для самозаписи (отсортированы по `categoryName`, затем по `name`, плюс `filledCount` назначений со статусом Accepted/Unconfirmed) и времена. Имена волонтёров не возвращаются. Если настройка церкви `volunteerSignupNextOnly` равна `"true"`, возвращается только первый план каждого типа. Каждый `plan` включает вычисляемое поле `signupDeadline` (ISO-момент или `null`): `signupDeadlineHours` до самого раннего времени типа `service` плана (если времени служения нет — любое время с отметкой; если времён нет вообще — 9:00 по часовому поясу церкви в день `serviceDate`) |
| GET | `/signup/:planId/volunteers` | JWT | — | `[{ positionId, names }]` для позиций самозаписи плана (отображаемые имена назначенных со статусом Accepted/Unconfirmed). Возвращает `[]`, если у плана не включён `showVolunteerNames` |
| POST | `/` | JWT | — | Создать или обновить планы (принимает один объект или массив). Задайте `confirmationWorkflowId`, чтобы подключить план к рабочему процессу подтверждения служения, или `null`, чтобы отключить его для будущих запросов. Передайте `signupDeadlineHours: null`, чтобы убрать срок; если поле не передано, сохранённое значение остаётся |
| POST | `/copy/:id` | JWT | Право на редактирование служения | Скопировать план вместе с позициями, временами, назначениями и элементами порядка служения. Тело содержит `ministryId`, `serviceDate`, `copyMode` (`"none"`, `"positions"`, `"all"`) и `copyServiceOrder` (boolean). Без `targetPlanId` создаётся новый план, а `notes`, `signupDeadlineHours`, `showVolunteerNames` и `autoReplaceOnDecline` переносятся из исходного плана, если тело их не задаёт. С `targetPlanId` копия заполняет уже существующий план (вызывающий должен иметь право его редактировать). Опция **Repeat weekly** в B1Admin вызывает этот эндпоинт по разу на каждую неделю, каждый раз копируя из плана, созданного неделей раньше |
| POST | `/textRange` | JWT | `texting.send` + право на редактирование служения | Отправить SMS каждому волонтёру, назначенному в диапазоне дат, через провайдера SMS церкви. Тело: `{ startDate, endDate, ministryId, planTypeId?, message }` (сообщение до 1600 символов; поля подстановки подставляются для каждого получателя). Возвращает счётчики предпросмотра, а также `recipientCount`, `successCount`, `failCount` и `error` (`no_provider` или `insufficient_credits`), если отправка прервалась досрочно |
| POST | `/:id/issueRequests` | JWT | Право на редактирование плана | Выдать новые назначения плана со статусом Unconfirmed, которые ещё не получили уведомление, через его рабочий процесс подтверждения: отмечает каждое назначение как уведомлённое и создаёт по одной карточке рабочего процесса на назначение. Пустое тело; возвращает `{ issued }`. Выполняется только если план опубликован (не `prepared`), имеет активный `confirmationWorkflowId` с хотя бы одним шагом и срок ответа ещё не истёк |
| POST | `/autofill/:id` | JWT | — | Автоматически заполнить назначения волонтёров для плана. Тело: `{ teams: [{ positionId, personIds }] }` |
| DELETE | `/:id` | JWT | — | Удалить план и все связанные времена, назначения, позиции и элементы плана |

### Пример: копирование плана

```
POST /doing/plans/copy/abc-123
Authorization: Bearer <token>

{
  "serviceDate": "2026-03-01T10:00:00.000Z",
  "copyMode": "all",
  "copyServiceOrder": true
}
```

```json
{
  "id": "def-456",
  "churchId": "church-1",
  "serviceDate": "2026-03-01T10:00:00.000Z"
}
```

## Аутентификации поставщиков контента

Базовый путь: `/doing/contentProviderAuths`

Наследует базовый класс CRUD (GET `/`, GET `/:id`, POST `/`, DELETE `/:id` — без проверок прав).

Управляет записями OAuth-аутентификации для внешних поставщиков контента (например, интеграций с программами для презентаций).

Поля `accessToken` и `refreshToken` шифруются при хранении с помощью `EncryptionHelper` и расшифровываются при чтении, поэтому API по-прежнему возвращает токены в открытом виде. Записи, сохранённые до введения шифрования, содержат токены в открытом виде (которые никогда не содержат `|`); они возвращаются как есть и шифруются при следующем сохранении.

| Метод | Путь | Auth | Права | Описание |
|--------|------|------|------------|-------------|
| GET | `/` | JWT | — | Список всех аутентификаций поставщиков контента |
| GET | `/:id` | JWT | — | Получить аутентификацию поставщика контента по ID |
| GET | `/ids?ids=` | JWT | — | Получить несколько аутентификаций по ID, перечисленным через запятую |
| GET | `/ministry/:ministryId` | JWT | — | Получить все аутентификации поставщиков контента для служения |
| GET | `/ministry/:ministryId/:providerId` | JWT | — | Получить запись аутентификации для конкретных служения и поставщика |
| POST | `/` | JWT | — | Создать или обновить аутентификации поставщиков контента |
| DELETE | `/:id` | JWT | — | Удалить аутентификацию поставщика контента |
