# Развёртывание мобильных приложений

<div class="article-intro">

Мобильные приложения ChurchApps на базе Expo, например B1 Checkin, собираются с помощью **Expo EAS Build** или локальной сборки Gradle и распространяются через магазины приложений. На этой странице описано, как собирать, отправлять и публиковать обновления по воздуху (OTA) для Android и iOS на примере B1 Checkin.

</div>

<div class="prereqs">
<h4>Перед началом работы</h4>

- Настройте приложение локально -- см. [Мобильные приложения](../mobile/index.md#local-setup)
- Установите и настройте [EAS CLI](https://docs.expo.dev/eas/)
- Убедитесь, что у вас есть доступ к Google Play Console (Android) и/или Apple App Store Connect (iOS)

</div>

## Сборка

### Android

Релизные сборки для Android выполняются локально и подписываются релизным ключом из EAS. Загрузите его один раз командой `npx eas-cli credentials -p android` (выберите **credentials.json: Download credentials from EAS**), затем выполните:

```bash
yarn build:android
```

Пакет для Google Play будет записан в `android/app/build/outputs/bundle/release/app-release.aab`. Чтобы собрать его на EAS, выполните `yarn build:android:eas`.

### iOS

Сборки iOS всегда выполняются на EAS:

```bash
yarn build:ios
```

## Отправка в магазины приложений

### Android -- Google Play Store

Загрузите AAB через Play Console или отправьте его через EAS:

```bash
npx eas-cli submit -p android --path android/app/build/outputs/bundle/release/app-release.aab
```

### iOS -- Apple App Store

Отправьте сборку iOS напрямую через EAS:

```bash
eas submit --platform ios
```

## OTA-обновления

Для изменений только в JavaScript, которые не требуют проверки в магазине приложений, используйте обновления по воздуху (over-the-air, OTA):

```bash
yarn update
```

Это использует EAS Update, чтобы передать изменения пользователям напрямую, без полной отправки в магазин.

:::tip
OTA-обновления значительно быстрее сборок для магазинов -- изменения могут дойти до пользователей за минуты, а не за дни. Используйте их для исправлений ошибок, правок текстов и небольших изменений интерфейса, не затрагивающих нативный код.
:::

## Номера версий

Перед созданием сборки для магазина номера версий нужно обновить в нескольких файлах:

- `package.json`
- `app.json`
- `android/app/build.gradle` (`versionName` и `versionCode`)

Номер сборки iOS EAS увеличивает автоматически.

:::warning
Если забыть обновить номера версий во всех файлах, сборка завершится ошибкой или приложение будет отклонено магазином. Перед началом производственной сборки перепроверьте каждый файл из списка выше.
:::
