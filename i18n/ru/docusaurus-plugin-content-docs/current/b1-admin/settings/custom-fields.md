# Пользовательские поля

<div class="article-intro">

**Пользовательские поля** позволяют вести собственную информацию в каждой записи человека — то, для чего в B1 нет встроенного поля, например дата истечения проверки на судимость, размер футболки или статус прохождения курса крещения. Вы определяете поле один раз в Settings, а затем заполняете значение в профиле каждого человека и ищете или формируете списки по этому полю. Это заменяет прежний обходной путь, когда для хранения одного пользовательского значения приходилось создавать форму People.

</div>

## Открытие пользовательских полей

В B1 Admin откройте [меню Jump](../introduction.md#getting-around-with-the-jump-menu) (строку поиска в верхнем левом углу), выберите **Settings > Settings** и нажмите **Custom Fields** в левом списке, чтобы перейти к разделу **Custom Fields**. Можно также сразу открыть **/settings/custom-fields**. Вы увидите список всех определенных полей с их **Name** и **Field Type**. Если полей еще нет, панель сообщит: *«No custom fields have been added yet.»*

## Добавление поля

1. Нажмите **Add Field**.
2. В редакторе, который откроется справа, введите **Name** — это подпись, которую сотрудники будут видеть в профилях людей и в поиске (например, *Background check expires*).
3. Выберите **Field Type**:
   - **Textbox** — свободный короткий текст.
   - **Whole Number** — целые числа без дробной части (например, количество).
   - **Decimal** — числа, которые могут содержать дробную часть.
   - **Date** — календарная дата.
   - **Yes/No** — простой ответ «да» или «нет».
   - **Multiple Choice** — список выбора. Когда вы выбираете этот тип, появляется **редактор вариантов**, в котором можно добавить каждый вариант, доступный для выбора.
4. Нажмите **Save**.

Поле становится доступным в профиле каждого человека.

:::info
Типы полей такие же, как и для [вопросов формы](../forms/creating-forms.md), поэтому значения ведут себя одинаково во всем B1.
:::

## Редактирование поля

Нажмите на любую строку поля в списке, чтобы открыть его в редакторе. Измените название, тип или варианты и нажмите **Save**.

:::warning
Изменение **Field Type** для поля, в котором уже есть значения (например, с Textbox на Date), может оставить ранее введенные значения в формате, который больше не соответствует новому типу. Меняйте типы осторожно, если сотрудники уже начали заполнять поле.
:::

## Удаление поля

Откройте поле для редактирования и нажмите **Delete**. Система попросит подтвердить действие: *«Are you sure you wish to delete this custom field? Its stored values will also be removed.»* Удаление поля навсегда убирает его **и все значения, сохраненные для него**, у всех людей. Это действие нельзя отменить.

## Заполнение значений для человека

Как только существует хотя бы одно пользовательское поле, его значения появляются прямо рядом со встроенными данными в записи каждого человека: вы видите их вместе с контактными данными человека в левой части профиля и редактируете в той же форме, которой пользуетесь для остальной информации о человеке. Ничего дополнительного не появляется, пока вы не определите первое поле.

1. Откройте запись человека в **People**.
2. Нажмите кнопку **Edit** слева в профиле, под контактными данными человека.
3. Прокрутите к области **Custom Fields** в нижней части формы редактирования и заполните значение для каждого поля. Каждое поле показывает ввод, соответствующий его типу: календарь для полей Date, выпадающий список да/нет для полей Yes/No, список выбора для Multiple Choice и так далее.
4. Нажмите **Save**. Значения пользовательских полей сохраняются вместе с остальными данными человека.

Вернувшись к профилю, вы увидите, что любое поле с значением отображается под контактными данными человека в виде *Название поля: значение* (ответы Yes/No выводятся как *Yes* или *No*, а для Multiple Choice показывается подпись варианта). Пустые поля просто скрываются. Чтобы удалить значение, отредактируйте человека, очистите поле и сохраните — пустое значение удаляется из записи, а не сохраняется как пустое.

:::tip
Классический пример использования — безопасность волонтеров: создайте поле **Date** под названием *Background check expires*, внесите дату для каждого волонтера, а затем создайте [сохраненный список](../people/lists.md), который отмечает тех, чья дата уже прошла.
:::

## Поиск и формирование списков по пользовательским полям

По пользовательским полям можно выполнять полноценный поиск:

1. На странице **People** откройте [Advanced Search](../people/searching-people.md).
2. Разверните категорию **Custom Fields**.
3. Отметьте поле, по которому хотите фильтровать, выберите оператор и введите значение. Доступные операторы соответствуют типу поля:
   - **Textbox** — содержит, равно, начинается с, заканчивается на.
   - **Whole Number / Decimal** — равно, больше, больше или равно, меньше, меньше или равно.
   - **Date** — равно, после (больше), до (меньше).
   - **Yes/No** — равно Yes или No.
   - **Multiple Choice** — равно одному из вариантов или содержит его.

Любой поиск по пользовательскому полю можно сохранить как [список](../people/lists.md). Списки являются динамическими запросами, поэтому список, построенный на условии *Background check expires is before today*, при каждом открытии заново проверяет всех людей и не требует ручного обновления.

## Показ пользовательского поля как столбца

Чтобы сразу увидеть значения поля для всех, добавьте его как столбец на странице **People**. Переключите **View as** на **Table**, нажмите значок **Select columns** в заголовке страницы, перейдите на вкладку **Custom** и отметьте поле. Значение каждого человека появится в отдельном столбце рядом со встроенными. См. [Отображение пользовательских полей как столбцов](../people/searching-people.md#showing-custom-fields-as-columns).

## Что происходит при объединении

Когда вы [объединяете две записи людей](../people/adding-people.md), значения пользовательских полей переносятся автоматически. Человек, которого вы оставляете, сохраняет свои значения; для любого поля, где значение было только у удаляемого человека, это значение копируется, чтобы ничего не потерялось.
