# Пользовательские поля

<div class="article-intro">

**Custom Fields** (пользовательские поля) позволяют отслеживать собственную информацию в каждой карточке человека — то, для чего в B1 нет встроенного поля, например дату истечения проверки биографии, размер футболки или статус прохождения курса подготовки к крещению. Вы один раз задаёте поле в разделе Settings, затем заполняете значение в профиле каждого человека и можете искать по нему или строить списки. Это заменяет прежний обходной путь — создание формы People только ради хранения одного значения.

</div>

<div class="prereqs">
<h4>Прежде чем начать</h4>

- Вам нужны права на редактирование раздела **People**, чтобы определять поля и заполнять значения, а также доступ к разделу **Settings**. Любой, у кого есть право просмотра People, может видеть значения. См. [Роли и права доступа](./roles-permissions.md).
- Прежде чем начать, определите, что вы хотите отслеживать и какой тип подходит лучше всего (текст, число, дата, ответ «да/нет» или список выбора).

</div>

## Открытие пользовательских полей

В B1 Admin перейдите в **Settings** на левой боковой панели и выберите карточку **Custom Fields**. Можно также перейти напрямую по адресу **/settings/custom-fields**. Вы увидите список всех определённых вами полей с их **Name** и **Field Type**. Если вы ещё ничего не создали, панель покажет сообщение: *«No custom fields have been added yet.»*

## Добавление поля

1. Нажмите **Add Field**.
2. В редакторе, который откроется справа, введите **Name** — это подпись, которую сотрудники увидят в профилях людей и при поиске (например, *Background check expires*).
3. Выберите **Field Type**:
   - **Textbox** — произвольный короткий текст.
   - **Whole Number** — числа без десятичных знаков (например, количество).
   - **Decimal** — числа, которые могут содержать десятичные знаки.
   - **Date** — календарная дата.
   - **Yes/No** — простой ответ «да» или «нет».
   - **Multiple Choice** — список выбора. При выборе этого типа появляется **редактор вариантов**, где можно добавить каждый вариант, доступный для выбора.
4. Нажмите **Save**.

Теперь поле доступно в профиле каждого человека.

:::info
Типы полей совпадают с теми, что используются для [вопросов форм](../forms/creating-forms.md), поэтому значения ведут себя одинаково во всём B1.
:::

## Редактирование поля

Нажмите на любую строку поля в списке, чтобы снова открыть его в редакторе. Измените имя, тип или варианты и нажмите **Save**.

:::warning
Изменение **Field Type** у поля, в котором уже есть значения (например, с Textbox на Date), может привести к тому, что ранее введённые значения окажутся в формате, не соответствующем новому типу. Меняйте типы осторожно, если сотрудники уже начали заполнять поле.
:::

## Удаление поля

Откройте поле для редактирования и нажмите **Delete**. Вам будет предложено подтвердить действие: *«Are you sure you wish to delete this custom field? Its stored values will also be removed.»* Удаление поля безвозвратно удаляет само поле **и все хранящиеся в нём значения** у всех людей — это действие нельзя отменить.

## Заполнение значений в карточке человека

Как только существует хотя бы одно пользовательское поле, его значения располагаются прямо рядом со встроенными данными в карточке каждого человека — вы просматриваете их в разделе **Personal Details** и редактируете на той же форме, что и остальную информацию о человеке. Пока вы не создали первое поле, ничего дополнительного не отображается.

1. Откройте карточку человека в разделе **People**.
2. В разделе **Personal Details** нажмите кнопку **Edit** (значок карандаша).
3. Прокрутите до области **Custom Fields** в нижней части формы редактирования и заполните значение для каждого поля. Каждое поле показывает элемент ввода, соответствующий его типу — выбор даты для полей Date, выпадающий список для полей Yes/No, список выбора для Multiple Choice и так далее.
4. Нажмите **Save**. Значения пользовательских полей сохраняются вместе с остальными данными человека.

Вернувшись в профиль, вы увидите, что любое заполненное поле теперь отображается в разделе **Personal Details** (ответы Yes/No показываются как *Yes* или *No*, а для Multiple Choice отображается подпись выбранного варианта). Незаполненные поля просто скрыты. Чтобы удалить значение, отредактируйте человека, очистите поле и сохраните — пустое значение удаляется из записи, а не сохраняется как пустое.

:::tip
Классический пример использования — безопасность волонтёров: создайте поле типа **Date** с названием *Background check expires*, внесите дату для каждого волонтёра, а затем постройте [сохранённый список](../people/lists.md), который отмечает всех, у кого дата уже прошла.
:::

## Поиск и построение списков по пользовательским полям

Пользовательские поля полностью доступны для поиска:

1. На странице **People** откройте [Расширенный поиск](../people/searching-people.md).
2. Разверните категорию **Custom Fields**.
3. Отметьте нужное поле, выберите оператор и введите значение. Доступные операторы зависят от типа поля:
   - **Textbox** — содержит, равно, начинается с, заканчивается на.
   - **Whole Number / Decimal** — равно, больше, больше или равно, меньше, меньше или равно.
   - **Date** — равно, после (больше), до (меньше).
   - **Yes/No** — равно Yes или No.
   - **Multiple Choice** — равно одному из вариантов или содержит один из вариантов.

Любой поиск по пользовательскому полю можно сохранить как [список](../people/lists.md). Списки — это живые запросы, поэтому список, построенный на условии *Background check expires is before today*, заново проверяет каждого человека при каждом открытии — никакого ручного обслуживания не требуется.

## Что происходит при слиянии

Когда вы [объединяете две карточки человека](../people/adding-people.md), значения пользовательских полей переносятся автоматически. У человека, которого вы оставляете, сохраняются его собственные значения; для любого поля, значение которого было только у удаляемого человека, это значение копируется, чтобы ничего не потерялось.
