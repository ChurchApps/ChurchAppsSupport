# Роли и права

<div class="article-intro">

Роли позволяют контролировать, что разные пользователи могут делать в вашей учётной записи ChurchApps. Вы можете создавать собственные роли для сотрудников, волонтёров и других членов команды, и у каждой будет свой уровень доступа, чтобы ваши данные оставались защищёнными.

</div>

## Доступ к ролям

1. В B1 Admin откройте [меню перехода](../introduction.md#getting-around-with-the-jump-menu) (строку поиска в левом верхнем углу) и разверните **Settings**.
2. Нажмите **Roles**.
3. На странице Roles отображаются все роли, определённые для вашей церкви. В колонке **Members** показано, сколько пользователей в каждой роли, а строка **(Everyone)** показывает **All users**.

## Структура страницы ролей

Страница Roles разделена на две панели:

- **Левая сторона** — список участников, назначенных выбранной роли.
- **Правая сторона** — настройки прав, которые можно задать для этой роли.

Нажмите на название любой роли, чтобы просмотреть и настроить её участников и права.

## Добавление пользователей в роль

1. Выберите роль, в которую хотите добавить участников.
2. Используйте **поле поиска** слева, чтобы найти нужного человека.
3. Выберите человека в результатах поиска.
4. Он сразу будет добавлен в роль.

## Удаление пользователей из роли

1. Выберите роль, в которой находится нужный пользователь.
2. Найдите человека в списке участников слева.
3. Нажмите **кнопку удаления** рядом с его именем.

## Настройка прав

Каждой роли можно предоставить доступ к определённым разделам B1 Admin. В панели **Edit Permissions** права сгруппированы в разделы, которые можно развернуть, например **Attendance**, **Content**, **Donations**, **Forms and Plans**, **Lessons**, **Messaging**, **People and Groups** и **Tasks**. Введите текст в поле **Filter permissions**, чтобы показать только подходящие права.

Отметьте или снимите отметку с права, чтобы предоставить или отозвать его у роли. В заголовке каждого раздела показано, сколько его прав есть у роли, например **2 of 5**, и этот счётчик обновляется по мере установки и снятия флажков.

### Права на пожертвования

В разделе **Donations** есть следующие права:

- **View Donation Summaries** — доступ к разделу Donations, включая страницы Summary, Batches, Funds, Campaigns и Giving Statements.
- **View Donations** — просмотр отдельных пожертвований, например подношений внутри пакета.
- **Edit Donations** — полный контроль: добавление, редактирование и удаление пожертвований и пакетов, а также [закрытие и повторное открытие пакетов](../donations/batches.md#closing-and-reopening-a-batch).
- **Enter Donations** — добавление пакетов и ввод, редактирование или удаление пожертвований, но только в пакетах, которые ещё открыты. Люди только с этим правом не могут удалять пакеты, закрывать или открывать их, а также менять подношения, поступившие через онлайн-пожертвования.
- **Edit Settings** — управление настройками пожертвований.

Тот, у кого есть **Enter Donations**, но нет **View Donation Summaries**, видит в разделе **Donations** только страницу **Batches**. Дайте счётной команде роль с правами **Enter Donations** и **View Donations**, чтобы они могли открывать пакет и видеть подношения, которые внесли. Подробнее см. в [Кто может изменять пакет](../donations/batches.md#who-can-change-a-batch).

### Только имена людей {#people-names-only}

В разделе **People and Groups** есть право **View People Names Only**. Используйте его для волонтёров, которым нужно находить людей по имени — например, чтобы выбрать кого-то в поле поиска, — без доступа ко всему каталогу. Только с этим правом человек:

- может искать людей по имени и видеть список недавно добавленных, но видит только имя, фото и статус членства каждого;
- не может искать по email, видеть контактные данные или открывать каталог **People**.

Сочетайте **View People Names Only** с **View Attendance** или **Edit Attendance** для волонтёров, которые ведут посещаемость классов. Тогда пункт **People** в их меню открывает **Groups**, где они могут открыть список **All groups** и увидеть имена участников и занятия каждого класса. С правом **Edit Attendance** они также могут [записывать посещаемость](../attendance/recording-attendance.md) и добавлять гостей, находя их по имени. Имена не являются ссылками на записи людей, а конфиденциальные группы остаются скрытыми, если волонтёр не является участником.

B1 Admin скрывает ссылки и кнопки, для которых у роли нет нужных прав. Например, список **All groups** доступен только тем, кто может редактировать группы, просматривать участников групп или просматривать людей, либо тем, у кого есть **View People Names Only** вместе с **View Attendance** или **Edit Attendance** (остальных возвращает на Dashboard). Настройка посещаемости появляется только при **Edit Services**, кнопка **Email** группы — только при **Edit Group Members** (праве, необходимом для отправки групповой почты), печать списка группы требует **View Group Members** или руководства этой группой, а удаление события календаря требует **Edit Content** (или отзыва собственного ожидающего запроса).

### Учётные записи киоска регистрации {#check-in-kiosk-accounts}

Учётная запись, которая входит в киоск [B1 Checkin](../../b1-checkin/getting-started/logging-in.md), нуждается в праве **Checkin** в разделе **Attendance** (или **Edit Attendance**). Только с правом **Checkin** киоск может искать семьи по имени или телефону, регистрировать их на службу и с неё, а также показывать, кто может забрать ребёнка, без доступа к каталогу People.

Право Checkin больше не выдаётся через строку **(Everyone)**. Нахождение в роли с другими правами не даёт права запускать киоск; добавьте **Checkin** в роль, например «Check-In Volunteers», и поместите туда учётные записи киоска.

:::warning
**Domain Admin** имеют полный доступ ко всем разделам вашей учётной записи ChurchApps. Их права нельзя изменить или ограничить. Используйте эту роль только для самых доверенных администраторов.
:::

:::tip
Создавайте узкие роли, например «Treasurer» только с доступом к **Donations**, «Counting Team» с **Enter Donations** и **View Donations** или «Check-In Volunteer» только с доступом к **Attendance**. Так соблюдается принцип минимальных привилегий и защищаются ваши данные. Подробнее о том, как ChurchApps защищает вашу информацию, см. в [Безопасность данных](./data-security.md).
:::
