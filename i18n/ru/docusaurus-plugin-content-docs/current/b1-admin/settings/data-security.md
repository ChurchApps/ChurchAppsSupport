## Ограничение хранения конфиденциальных данных {#limiting-sensitive-data-stored}

Наш первый подход — не хранить конфиденциальных данных больше, чем необходимо. Это значит, что мы никогда не храним данные банковских карт или банковских счетов, используемые для пожертвований. Когда пользователь делает пожертвование через B1.church Admin или B1, данные карты никогда не передаются на наши серверы — только на ваш платёжный шлюз (Stripe). Поэтому в случае утечки данных никакие данные карт или банковские реквизиты не будут скомпрометированы.

Мы также никогда не храним пароли в нашей системе. Все пароли обрабатываются односторонним алгоритмом хеширования, при котором часть данных уничтожается, так что получить пароли из базы данных невозможно никому, в том числе нам. Для проверки пароля введённое значение должно пройти через тот же односторонний хеш и дать тот же результат.

После удаления этих двух источников единственными конфиденциальными данными остаются список имён и контактная информация.

:::tip
Поскольку ChurchApps никогда не хранит данные банковских карт или банковских счетов, даже в худшем случае утечки данных не раскрылись бы реквизиты финансовых счетов. Под угрозой оказались бы только имена и контактная информация.
:::

## Использование стандартных лучших практик {#using-standard-best-practices}

Мы используем отраслевые лучшие практики безопасности, включая шифрование всех данных, передаваемых к нашим серверам и от них, по HTTPS. Все серверы размещены в защищённом физическом дата-центре Amazon Web Services. Все серверы баз данных находятся за межсетевым экраном и недоступны из интернета.

## Разделение данных {#data-segregation}

Данные разделены по разным базам данных в зависимости от области. Каждый наш модуль (Membership, Giving, Attendance, Messaging, Doing и Content) — это независимый контур данных со своими базами. Если один из них будет скомпрометирован, ценность данных ограничена, пока не скомпрометированы и остальные. Например, если бы API/база данных Giving была взломана, злоумышленник мог бы получить список пожертвований и дат (но никогда данные карт или счетов). Однако у него не было бы доступа к тому, какие пользователи делали пожертвования и в какие церкви, так как эти данные хранятся в отдельной базе Membership.

:::info
Разделение данных означает, что компрометация одной системы не даёт доступа ко всем данным церкви. Каждый API работает независимо, со своей базой данных, что ограничивает последствия возможной утечки.
:::

## Ограниченный доступ {#limited-access}

Доступ к производственным серверам строго ограничен администраторами серверов, которым он необходим. Сейчас это два человека, которые также входят в состав правления. Разработчикам, волонтёрам и другим членам правления доступ к производственным серверам не предоставляется.

## Политика конфиденциальности {#privacy-policy}

Ваши данные принадлежат вам и никогда не будут проданы третьим лицам. Полный текст нашей политики конфиденциальности вы можете прочитать [здесь](https://churchapps.org/privacy).

## Соответствие GDPR {#gdpr-compliance}

ChurchApps поддерживает соответствие GDPR для церквей, в которых есть участники в Великобритании или Европейском союзе. Вот как мы выполняем ключевые требования:

### Права субъектов данных {#data-subject-rights}

ChurchApps предоставляет инструменты, которые помогают церквям отвечать на запросы субъектов данных:

- **Право на доступ (статья 15)** — участники могут запросить копию своих персональных данных, обратившись в свою церковь. Администраторы могут выгрузить данные любого человека с помощью **Export Data** в его записи или в разделе **Data Management** формы редактирования записи в B1.church Admin.
- **Право на удаление (статья 17)** — участники могут сами запросить удаление аккаунта на странице Profile (см. [Рассмотрение запросов на удаление аккаунта](../profile/account-deletion.md)) или обратившись напрямую в свою церковь. Администраторы также могут анонимизировать данные человека во всех модулях в разделе **Data Management** на странице записи человека. Анонимизация заменяет персональные данные общими значениями, но сохраняет агрегированные записи (итоги пожертвований, количество посещений), необходимые для финансовой отчётности церкви.
- **Право на ограничение обработки (статья 18)** — участники могут запросить ограничение обработки, обратившись в свою церковь, в том числе отказавшись от рассылок.
- **Право на переносимость данных (статья 20)** — администраторы могут выгрузить персональные данные в структурированном машиночитаемом формате JSON по запросу участников.

### Использование инструментов управления данными {#using-the-data-management-tools}

Чтобы получить доступ к инструментам GDPR для конкретного человека:

1. Перейдите в **People** в B1 Admin и откройте запись человека.
2. Нажмите **Edit**, чтобы перейти в режим редактирования.
3. Прокрутите вниз до раздела **Data Management** (по умолчанию свёрнут) и раскройте его.
4. Используйте **Export Data**, чтобы скачать файл JSON со всеми данными, хранящимися о человеке. (Та же ссылка **Export Data** есть среди действий под именем человека — без открытия формы редактирования.)
5. Используйте **Anonymize**, чтобы заменить персональные данные общими значениями. Система попросит ввести `ANONYMIZE` для подтверждения — это действие нельзя отменить.

:::warning
Анонимизация необратима. Итоги пожертвований и количество посещений сохраняются для финансовой отчётности, но все персональные идентификаторы (имя, электронная почта, адрес и т. д.) удаляются и не могут быть восстановлены.
:::

### Обработка данных {#data-processing}

ChurchApps выступает в роли **обработчика данных** от имени вашей церкви (**контролёра данных**). Наше [Соглашение об обработке данных](https://churchapps.org/terms) описывает обязанности каждой стороны, включая использование субподрядчиков, порядок уведомления о нарушениях и обращение с данными при расторжении.

### Международная передача данных {#international-data-transfers}

Данные ChurchApps размещены в Amazon Web Services (AWS) в Соединённых Штатах. Международные передачи данных из Великобритании/ЕС покрываются Стандартными договорными оговорками (SCC) AWS в рамках [Дополнения об обработке данных AWS](https://aws.amazon.com/compliance/data-processing-addendum/). Дополнение AWS по обработке данных автоматически включено в Условия обслуживания AWS для всех клиентов. Размещение в ЕС не требуется, когда установлены подходящие механизмы передачи, такие как SCC.

Подробности о том, как оценивались риски передачи, см. в [Оценке рисков передачи](./transfer-risk-assessment.md).

### Субподрядчики {#sub-processors}

- **Amazon Web Services (AWS)** — хостинг инфраструктуры, хранение данных и доставка контента
- **Stripe** — обработка платежей за пожертвования (ChurchApps не хранит данные карт)

:::info
Полные сведения о том, как мы обрабатываем персональные данные, см. в нашей [Политике конфиденциальности](https://churchapps.org/privacy) и [Условиях обслуживания](https://churchapps.org/terms). Если у вас есть вопросы о соответствии GDPR, напишите нам на support@churchapps.org.
:::
