# Запросы на вступление в группу

<div class="article-intro">

Когда группа настроена с порядком вступления по одобрению, люди могут отправлять запросы на вступление. Руководители групп и администраторы рассматривают эти запросы и одобряют или отклоняют их. Это дает вашей общине контроль над членством в группах и при этом облегчает людям возможность заявить о желании присоединиться.

</div>

## Порядки вступления {#understanding-join-policies}

У групп может быть три разных порядка вступления:

- **Open** — любой может вступить сразу, без одобрения
- **Request** — люди отправляют запрос на вступление, который требует одобрения
- **Closed** — никто не может запросить вступление (участников добавляют вручную)

Когда группа использует порядок **Request**, все попытки вступления проходят через процесс одобрения, описанный на этой странице.

## Просмотр ожидающих запросов {#viewing-pending-requests}

### Для руководителей групп {#for-group-leaders}

1. В B1 Admin откройте [меню Jump](../introduction.md#getting-around-with-the-jump-menu) и выберите **People > Groups**
2. Нажмите на название группы
3. В разделе **Members** показано, сколько запросов ожидают решения (например, «1 pending»). Нажмите **All members** — ожидающие запросы этой группы появятся под **Pending Requests** вверху списка участников

### Для администраторов {#for-administrators}

Администраторы с правами управления группами могут просматривать ожидающие запросы по всем группам:

1. В меню Jump выберите **People > Groups**
2. Нажмите кнопку **pending requests** в заголовке страницы (например, «3 pending requests»). Она появляется только тогда, когда есть ожидающие запросы.
3. Страница **Pending Join Requests** перечисляет все ожидающие запросы по всей общине, с группой, в которую человек хочет вступить, рядом с его именем. Нажмите **Groups** вверху страницы, чтобы вернуться. Когда ожидающих запросов нет, страница показывает **No pending requests.**

## Рассмотрение запроса на вступление {#reviewing-a-join-request}

Каждый запрос на вступление показывает:

- **Имя и фото человека** — человек, который запрашивает вступление (а на общей странице — и группу)
- **Необязательное сообщение** — личное сообщение с объяснением, почему он хочет вступить (если оно указано)
- **Дату запроса** — когда запрос был отправлен

Чтобы рассмотреть запрос:

1. Прочитайте сообщение человека, если он его указал
2. При необходимости нажмите на имя человека, чтобы открыть его профиль
3. Решите, одобрить запрос или отклонить его

## Одобрение запроса {#approving-a-request}

1. Нажмите **Approve** у запроса на вступление
2. Человек сразу добавляется в группу как участник, а запрос исчезает из списка
3. Отправитель запроса получает уведомление, что его запрос одобрен
4. Запрос помечается в системе как одобренный

:::tip
Когда вы одобряете запрос, человек становится обычным участником группы. Позже при необходимости вы можете назначить его руководителем группы на странице [Участники группы](./group-members.md).
:::

## Отклонение запроса {#declining-a-request}

1. Нажмите **Decline** у запроса на вступление
2. В диалоге **Decline Request** при желании введите **Reason (optional)** (до 500 символов)
3. Нажмите **Decline**
4. Отправитель запроса получает уведомление с причиной отказа (если она указана)
5. Запрос помечается как отклоненный

:::info
Указание причины отказа помогает человеку понять, почему его запрос не одобрен, и может побудить его попробовать снова позже или изучить другие группы.
:::

## Одобрение со страницы задач {#approving-from-the-tasks-page}

Каждый запрос на вступление также создает задачу в разделе **Serving &rarr; My Work** с названием «*Person* requested to join *Group*». Она назначается руководителям группы. Если у группы пока нет руководителя, задача идет любому сотруднику с правом **Group Members &gt; Edit**, а если такого права ни у кого нет — администраторам домена вашей общины. Сотрудники и администраторы, которые получили задачу таким образом, также получают уведомление, ведущее прямо к ней.

Открытие задачи показывает имя отправителя, группу и его необязательное сообщение, а на карточке задачи есть кнопки **Approve** и **Decline** (Decline открывает то же необязательное поле причины, описанное выше). Так у руководителей появляется второй способ действовать по запросу, управляемый уведомлениями, без открытия списка участников группы.

Решение по запросу из любого места — из списка участников группы или из карточки задач — закрывает его везде, поэтому руководители никогда не видят устаревшую задачу для запроса, который кто-то уже обработал.

## Уведомления {#notifications}

Система запросов на вступление автоматически отправляет уведомления:

- **Когда запрос отправлен** — все руководители группы получают уведомление. Если у группы нет руководителя, вместо них уведомляются сотрудники или администраторы, которым назначена задача (см. выше).
- **Когда запрос одобрен** — отправитель получает подтверждение
- **Когда запрос отклонен** — отправитель получает уведомление с причиной отказа, если она есть

Уведомления появляются в центре уведомлений пользователя на B1.church и в мобильном приложении. В колокольчике уведомлений B1 Admin нажатие на уведомление о запросе на вступление (или на **View Details**) открывает группу на сайте B1.church вашей общины в новой вкладке.

## Управление запросами со стороны участника {#managing-requests-from-the-member-side}

Люди могут управлять своими запросами на вступление на B1.church:

- Просматривать статус своих ожидающих запросов на странице сведений о группе
- Отменять ожидающий запрос, если передумали
- Видеть, одобрен или отклонен их запрос

## Рекомендации {#best-practices}

- **Отвечайте быстро** — старайтесь рассматривать запросы в течение 24–48 часов, чтобы люди не ждали слишком долго
- **Будьте ясны в причинах отказа** — помогайте людям понять дальнейшие шаги или альтернативы
- **Проверяйте профили** — посмотрите профиль человека, чтобы понять, подходит ли он группе
- **Обозначайте ожидания** — убедитесь, что описание группы ясно говорит, для кого она
