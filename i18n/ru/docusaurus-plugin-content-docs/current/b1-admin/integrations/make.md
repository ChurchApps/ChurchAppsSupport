# Make

<div class="article-intro">

[Make](https://www.make.com) (ранее Integromat) — платформа визуальной автоматизации процессов, похожая по духу на Zapier, но с более гибкой логикой и меньшими затратами при большом объёме. Официальное приложение B1.church для Make позволяет создавать «сценарии», которые мгновенно реагируют на события B1 и записывают данные обратно в B1.

</div>

:::caution Пока недоступно
Приложение B1.church для Make ещё не опубликовано в каталоге приложений Make, поэтому добавить модули **B1.church**, описанные ниже, в сценарий сейчас нельзя. До его публикации используйте [Zapier](./zapier.md) или вызывайте [REST API](/docs/developer/api) B1 из модуля Make **HTTP — Make a request** с [API-ключом](/docs/developer/api/api-keys). Всё, что описано ниже, показывает, как приложение будет работать после выпуска.
:::

- Учётная запись [Make](https://www.make.com) (бесплатного тарифа хватает для небольших процессов)
- Администратор церкви с правом **Edit Settings** в B1Admin
- Примерное представление о сценарии, который вы хотите построить

## Модули {#modules}

| Тип | Что делает | Событие / конечная точка B1 |
|---|---|---|
| **Instant Trigger** | Watch Events | любое подписанное событие B1 (`person.created`, `donation.created`, …) |
| **Action** | Create Person | добавляет нового человека |
| **Action** | Add Donation | записывает пожертвование |
| **Action** | Add Group Member | добавляет человека в группу |
| **Search** | Search People | находит людей по имени или адресу электронной почты |

Мгновенный триггер позволяет выбрать, какое событие отслеживать: один модуль триггера на сценарий, настраивается для каждого события.

## Настройка {#setup}

### 1. Создайте API-ключ B1 {#1-create-a-b1-api-key}

1. В B1Admin перейдите в **Settings → Developer → API Keys**.
2. Нажмите **New API Key**, назовите его «Make» и выдайте нужные области доступа.
3. **Добавьте `settings:write`**, если какой-либо из ваших сценариев использует мгновенный триггер: Make регистрирует веб-хук от вашего имени при включении сценария.
4. Также выдайте области, которые нужны модулям действий (например, `donations:write` для модуля Add Donation).
5. Сохраните и скопируйте ключ `cak_…`.

### 2. Установите подключение {#2-install-the-connection}

1. В Make создайте новый сценарий и перетащите модуль триггера **B1.church** на холст.
2. Когда появится запрос, выберите **Create a connection**. Вставьте API-ключ в поле *API Key* и оставьте *API Base URL* как `https://api.churchapps.org` (если только вы не тестируете на staging).
3. Нажмите **Save** — Make проверит ключ, прочитав профиль вашей церкви.

Подключение сохраняется в вашей учётной записи Make и используется во всех сценариях.

### 3. Настройте триггер {#3-configure-the-trigger}

1. Откройте настройки модуля **Watch Events**.
2. Выберите нужное событие, например `donation.created`.
3. Сохраните. Make создаст уникальный URL веб-хука и сохранит его внутри.

### 4. Добавьте последующие модули {#4-add-downstream-modules}

Перетащите на холст любой из сотен модулей приложений Make — Mailchimp, Google Sheets, Slack, HubSpot, собственную конечную точку HTTP и т. д. Сопоставьте выходные данные триггера (`event`, `churchId`, `data.id`, `data.amount`, …) с полями ввода. Модули flatten / iterator / router / aggregator в Make позволяют строить ветвящиеся и параллельные потоки, которые в Zapier было бы трудно реализовать.

### 5. Включите сценарий {#5-turn-the-scenario-on}

Переключите **Active** в заголовке сценария. Make вызывает `POST /membership/webhooks` в B1, чтобы зарегистрировать URL. С этого момента каждое подходящее событие B1 в реальном времени проходит через сценарий.

Выключение сценария вызывает `DELETE /membership/webhooks/{id}`, чтобы не оставлять осиротевших подписок.

## Типичные рецепты {#common-recipes}

### Синхронизация пожертвований с таблицей Google для проверки финансов {#sync-donations-to-a-google-sheet-for-finance-review}

- **Триггер** — B1: Watch Events (`donation.created`)
- **Действие** — Google Sheets: Add a Row. Сопоставьте `data.donationDate`, `data.amount`, `data.personId`, `data.method` и `data.batchId` со столбцами таблицы.

### Условное уведомление в Slack по сумме пожертвования {#conditional-slack-notification-by-donation-amount}

- **Триггер** — B1: Watch Events (`donation.created`)
- **Router**:
  - Ветка A — Filter: `data.amount >= 1000` → Slack: публикация в `#major-gifts`
  - Ветка B — по умолчанию → Slack: публикация в `#donations`

### Новый человек → CRM + приветственное письмо + Slack {#new-person--crm--welcome-email--slack}

- **Триггер** — B1: Watch Events (`person.created`)
- **Действие** — HubSpot: Create Contact
- **Действие** — Mailgun: Send Welcome Email
- **Действие** — Slack: уведомление в `#new-people` (параллельно — через router Make)

## Как работает мгновенный триггер {#how-the-instant-trigger-works}

Мгновенный триггер основан на веб-хуке, а не на опросе: при активации Make вызывает `POST /membership/webhooks` с созданным им URL и выбранным событием. Когда событие происходит в B1, B1 отправляет пакет на URL Make, и ваш сценарий запускается в течение нескольких секунд. Деактивация сценария удаляет веб-хук.

Триггер срабатывает только на события, которые происходят **пока сценарий активен**. Прошлые события не подгружаются.

## Ограничения и примечания {#limits--notes}

- **Одно событие на модуль Watch Events.** Чтобы отслеживать несколько событий, создайте по одному сценарию на каждое событие.
- **Проверка подписи не предоставляется** — Make не передаёт `X-B1-Signature` в сценарий; границей доверия служит невычисляемый URL веб-хука каждого сценария. Это обычная практика Make. Если нужна явная проверка подписи, создайте собственную интеграцию с помощью [SDK](/docs/developer/api/webhooks#sdk-support).
- **Количество операций** — каждый вызов API из модуля действия расходует квоту операций Make, а не что-либо на стороне B1.

## Устранение неполадок {#troubleshooting}

- **Проверка подключения не проходит** — чаще всего опечатка в API-ключе. Скопируйте его заново из B1Admin (полный ключ показывается только один раз; если вы его потеряли, создайте новый).
- **Модуль триггера не активируется** — проверьте **Settings → Developer → Webhooks** в B1Admin. Если после активации сценария вы не видите строку «Make — &lt;event&gt;», в ключе не хватает `settings:write`. Обновите ключ и включите сценарий снова.
- **Действие возвращает `403 Forbidden`** — у API-ключа нет области для этой конечной точки. Например, Add Donation требует `donations:write`. Обновите ключ в B1Admin и проверьте снова.

## Не хватает модуля? {#missing-a-module}

Если вам нужен модуль, которого нет (например, новое действие для конечной точки, которую мы ещё не охватили), напишите на [support@churchapps.org](mailto:support@churchapps.org). А пока модуль Make **HTTP — Make a request** может вызывать любую конечную точку B1 с заголовком `Authorization: Bearer cak_…`.
