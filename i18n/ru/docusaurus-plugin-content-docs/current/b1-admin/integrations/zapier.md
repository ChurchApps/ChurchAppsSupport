# Zapier

<div class="article-intro">

Официальное приложение B1.church в Zapier позволяет Zap реагировать на события в вашей церкви (новый человек, новое пожертвование, новый участник группы, …) и записывать данные обратно в B1. Без программирования и без собственной инфраструктуры: вы настраиваете всё в визуальном редакторе Zapier, вставляете API-ключ и включаете Zap.

</div>

:::caution Ожидает одобрения Zapier
Приложение B1.church готово и работает, но оно ещё ожидает проверки Zapier, прежде чем появится в публичном каталоге приложений редактора Zap. Пока оно не одобрено, им могут пользоваться только приглашённые учётные записи. Всё, что описано ниже, показывает, как это будет работать после одобрения.
:::

<div class="prereqs">
<h4>Прежде чем начать</h4>

- Учётная запись [Zapier](https://zapier.com) (бесплатного тарифа хватает для нескольких Zap)
- Администратор церкви с правом **Edit Settings** в B1Admin (там вы создадите API-ключ)
- Представление о том, что вы хотите сделать, например: «когда человек добавляется в B1, добавлять его в мой список Mailchimp»

</div>

## Триггеры и действия {#triggers-and-actions}

| Тип | Что делает | Событие / конечная точка B1 |
|---|---|---|
| **Trigger** | New Person | `person.created` |
| **Trigger** | Updated Person | `person.updated` |
| **Trigger** | New Donation | `donation.created` |
| **Trigger** | New Group Member | `group.member.added` |
| **Trigger** | New Form Submission | `form.submission.created` |
| **Action** | Create Person | добавляет нового человека |
| **Action** | Add Donation | записывает пожертвование |
| **Action** | Add Group Member | добавляет человека в группу |
| **Action** | Find Person | ищет человека по id, адресу электронной почты или имени; если никто не подходит, задача завершается с ошибкой |

Эти действия можно свободно сочетать с любым из более чем 7 000 поддерживаемых Zapier приложений.

## Настройка {#setup}

### 1. Создайте API-ключ B1 {#1-create-a-b1-api-key}

1. В B1Admin перейдите в **Settings → Developer → API Keys**.
2. Нажмите **New API Key**, назовите его, например, «Zapier», и выберите области доступа, которые нужны Zap.
3. **Важно:** всегда включайте область **`settings:write`**. Zapier проверяет ключ по списку веб-хуков B1 при подключении, а триггеры B1 регистрируют веб-хук от вашего имени при включении Zap — обоим нужен `settings:write`. Ключ без неё не пройдёт проверку подключения, даже если ваши Zap используют только действия B1.
4. Также выдайте области, которые нужны действиям: например, действию «Add Donation» нужен `donations:write`, а «Create Person» — `people:write`.
5. Сохраните. Полный ключ `cak_…` показывается **один раз** — скопируйте его.

### 2. Подключите Zapier к B1 {#2-connect-zapier-to-b1}

1. В Zapier создайте новый Zap.
2. Когда вы впервые выбираете триггер или действие B1, Zapier попросит **Sign in to B1.church**.
3. Вставьте API-ключ из шага 1 в поле **API Key** (поле **API URL** оставьте пустым) и нажмите **Yes, Continue**. Zapier проверит ключ для вашей церкви.

Подключение сохраняется в Zapier и используется каждым Zap вашей учётной записи.

### 3. Создайте Zap {#3-build-the-zap}

Выберите триггер, затем добавьте один или несколько шагов-действий. Примеры ниже.

## Типичные рецепты {#common-recipes}

### Добавлять новых людей из B1 в Mailchimp {#add-new-b1-people-to-mailchimp}

- **Trigger** — B1: New Person
- **Action** — Mailchimp: Add/Update Subscriber. Сопоставьте `name__first`, `name__last`, `contactInfo__email` из B1 с полями First Name / Last Name / Email в Mailchimp.

### Публиковать пожертвования в канал Slack карточкой, богаче встроенного коннектора {#post-donations-to-a-slack-channel-with-a-richer-card-than-the-built-in-connector}

- **Trigger** — B1: New Donation
- **Action** — Slack: Send Channel Message. Составьте любой макет — кнопки, вложения и т. п., — которого не умеет [встроенный коннектор Slack](./slack-discord.md).

### Добавлять новых участников групп в Google Group {#add-new-group-members-to-a-google-group}

- **Trigger** — B1: New Group Member
- **Action** — Filter by Zapier: продолжать, только если `groupId` триггера совпадает с нужной вам группой B1
- **Action** — B1: Find Person (используйте `personId` из триггера, чтобы получить адрес электронной почты)
- **Action** — Google Groups: Add Member

### Передавать отправки форм в трекер задач {#forward-form-submissions-to-a-project-tracker}

- **Trigger** — B1: New Form Submission
- **Action** — Notion / Linear / Asana / Trello: Create page / issue / task

## Как работают триггеры {#how-triggers-work-under-the-hood}

Триггеры основаны на **REST-хуках**, а не на опросе: Zapier не обращается к B1 каждые 15 минут. Когда вы включаете Zap, Zapier просит B1 зарегистрировать веб-хук на закрытый URL Zapier; когда событие происходит, B1 отправляет конверт в Zapier, и ваш Zap запускается **в течение нескольких секунд**. Когда вы выключаете Zap, Zapier просит B1 удалить веб-хук — осиротевших подписок не остаётся.

Это значит, что триггер срабатывает только на события, которые происходят **после** включения Zap. Прошлые события не подгружаются: включение Zap не повторяет вчерашние пожертвования.

## Ограничения и примечания {#limits--notes}

- **Несколько Zap с одним и тем же триггером** регистрируют каждый свой веб-хук B1 — конфликта нет, но полезно знать, если вы смотрите **Settings → Developer → Webhooks** и удивляетесь, почему там три одинаковые строки `Zapier — donation.created`.
- **Тестовые данные при настройке Zap** — при создании Zap Zapier запрашивает образцы данных для сопоставления полей. Он возьмёт последнее подходящее событие из B1, если оно есть; иначе использует синтетический образец из определения приложения.
- **Ошибки действий отображаются как ошибки Zap** в истории задач Zapier. Частая причина — API-ключ без нужной области (например, действию «Add Donation» нужен `donations:write`). Создайте ключ заново с правильными областями и подключите его в Zapier снова.
- **Квоты исходящих API-вызовов** — каждый вызов API B1 из действия расходует квоту задач Zapier, а не что-либо на стороне B1.

## Устранение неполадок {#troubleshooting}

- **«Authentication failed»** при подключении — API-ключ неверен, удалён или не содержит `settings:write`. Создайте новый ключ в B1Admin с `settings:write` и теми областями ресурсов, которые затрагивает Zap (области у существующего ключа изменить нельзя), затем обновите подключение.
- **Триггер никогда не срабатывает** — убедитесь, что веб-хук действительно зарегистрирован: в **Settings → Developer → Webhooks** в B1Admin должна появиться строка «Zapier — &lt;event&gt;». Если её нет, скорее всего, при включении Zap в ключе не было `settings:write`. Исправьте ключ, выключите Zap и включите его снова.
- **Триггер срабатывает дважды** — Zapier иногда повторно доставляет событие, если его подтверждение потерялось. Если нужна строгая дедупликация, используйте шаг «Filter by Zapier» по уникальному идентификатору (например, `id` человека).
