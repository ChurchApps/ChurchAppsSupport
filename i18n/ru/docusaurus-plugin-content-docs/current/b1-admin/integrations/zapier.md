# Zapier

<div class="article-intro">

Официальное приложение B1.church в Zapier позволяет Zap реагировать на события в вашей церкви (новый человек, новое пожертвование, новый участник группы, …) и записывать данные обратно в B1. Никакого программирования, никакой инфраструктуры — вы настраиваете все в редакторе Zapier перетаскиванием, вставляете API-ключ и включаете Zap.

</div>

<div class="prereqs">
<h4>Прежде чем начать</h4>

- Учетная запись [Zapier](https://zapier.com) (бесплатного тарифа достаточно для нескольких Zap)
- Администратор церкви с правом **Редактировать настройки** в B1Admin (вы создадите API-ключ)
- Идея того, что вы хотите сделать — например, «когда в B1 добавляют человека, добавить его в мой список Mailchimp»

</div>

## Триггеры и действия

| Тип | Что | Событие / endpoint B1 |
|---|---|---|
| **Триггер** | Новый человек | `person.created` |
| **Триггер** | Обновленный человек | `person.updated` |
| **Триггер** | Новое пожертвование | `donation.created` |
| **Триггер** | Новый участник группы | `group.member.added` |
| **Триггер** | Новая отправка формы | `form.submission.created` |
| **Действие** | Создать человека | добавляет нового человека |
| **Действие** | Добавить пожертвование | записывает пожертвование |
| **Действие** | Добавить участника группы | добавляет человека в группу |
| **Действие** | Найти человека | ищет человека по id, email или имени; завершает задачу с ошибкой, если совпадений не найдено |

Свободно комбинируйте их с любым из более чем 7000 поддерживаемых приложений Zapier.

## Настройка

### 1. Создайте API-ключ B1

1. В B1Admin перейдите в **Настройки → Для разработчиков → API-ключи**.
2. Нажмите **Новый API-ключ**, присвойте ему имя, например «Zapier», и выберите области доступа, необходимые Zap.
3. **Важно:** триггеры Zapier регистрируют веб-хук от вашего имени при включении Zap, что требует области доступа **`settings:write`**. Всегда включайте `settings:write`, если хотя бы один из ваших Zap использует триггер B1.
4. Также предоставьте области доступа, необходимые действиям — например, действию «Добавить пожертвование» нужен `donations:write`, «Создать человека» нужен `people:write`.
5. Сохраните. Полный ключ `cak_…` показывается **один раз** — скопируйте его.

### 2. Подключите Zapier к B1

1. В Zapier создайте новый Zap.
2. При первом выборе триггера или действия B1 Zapier попросит вас **войти в B1.church**.
3. Вставьте API-ключ из шага 1 и нажмите **Да, продолжить**. Zapier проверит его в вашей церкви.

Подключение сохраняется в Zapier и используется повторно каждым Zap в вашем аккаунте.

### 3. Постройте Zap

Выберите триггер, затем добавьте одно или несколько действий. Примеры ниже.

## Общие рецепты

### Добавление новых людей из B1 в Mailchimp

- **Триггер** — B1: Новый человек
- **Действие** — Mailchimp: Добавить/обновить подписчика. Сопоставьте `name__first`, `name__last`, `contactInfo__email` из B1 с полями Имя / Фамилия / Email в Mailchimp.

### Публикация пожертвований в канал Slack с более насыщенной карточкой, чем встроенный коннектор

- **Триггер** — B1: Новое пожертвование
- **Действие** — Slack: Отправить сообщение в канал. Составьте любой макет — кнопки, вложения и т. д. — который не поддерживает встроенный [коннектор Slack](./slack-discord).

### Добавление новых участников группы в Google Group

- **Триггер** — B1: Новый участник группы (отфильтровано по конкретному `groupId`)
- **Действие** — Фильтр Zapier: продолжать только если группа B1 — та, что вам нужна
- **Действие** — B1: Найти человека (использовать `personId` из триггера для получения email)
- **Действие** — Google Groups: Добавить участника

### Пересылка отправленных форм в трекер проектов

- **Триггер** — B1: Новая отправка формы
- **Действие** — Notion / Linear / Asana / Trello: Создать страницу / задачу / карточку

## Как триггеры работают внутри

Триггеры — это **REST-хуки**, а не опрос — Zapier не пингует B1 каждые 15 минут. Когда вы включаете Zap, Zapier просит B1 зарегистрировать веб-хук, указывающий на приватный URL Zapier; когда происходит событие, B1 отправляет конверт методом POST в Zapier, и ваш Zap запускается **в течение нескольких секунд**. Отключите Zap — и Zapier попросит B1 удалить веб-хук — никаких «осиротевших» подписок.

Это означает, что триггер срабатывает только для событий, происходящих **после** включения Zap. Обратного заполнения нет — включение Zap не воспроизводит вчерашние пожертвования.

## Ограничения и заметки

- **Несколько Zap с одним и тем же триггером** каждый регистрирует собственный веб-хук B1 — конфликтов нет, но стоит об этом знать, если вы просматриваете **Настройки → Для разработчиков → Веб-хуки** и удивляетесь, почему там три одинаковые строки `Zapier — donation.created`.
- **Тестовые данные при настройке Zap** — при создании Zap Zapier запрашивает образец данных для сопоставления полей. Он подтянет самое последнее подходящее событие из B1, если оно есть; в противном случае используется синтетический образец из описания приложения.
- **Сбои действий отображаются как ошибки Zap** в истории задач Zapier. Частая причина: API-ключ без нужной области доступа (например, действию «Добавить пожертвование» нужен `donations:write`). Переоформите ключ с правильными областями доступа и переподключите его в Zapier.
- **Квоты исходящих вызовов API** — каждый вызов API B1 из действия засчитывается в вашу квоту задач Zapier, а не в что-либо на стороне B1.

## Устранение неполадок

- **«Authentication failed»** при подключении — API-ключ неверен, отозван или не имеет нужных областей доступа для Zap. Переоформите его в B1Admin как минимум с `settings:write` плюс любыми областями доступа к ресурсам, которые затрагивает Zap, затем обновите подключение.
- **Триггер никогда не срабатывает** — убедитесь, что веб-хук действительно зарегистрирован: в B1Admin в разделе **Настройки → Для разработчиков → Веб-хуки** теперь должна отображаться строка с названием «Zapier — &lt;событие&gt;». Если ее нет, вероятно, у API-ключа не было `settings:write`, когда вы включали Zap. Исправьте ключ, отключите и снова включите Zap.
- **Триггер срабатывает дважды** — Zapier иногда повторно доставляет событие, если подтверждение было потеряно. Используйте шаг «Фильтр Zapier» по уникальному идентификатору (например, `id` человека), если вам нужна строгая дедупликация.
