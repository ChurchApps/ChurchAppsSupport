# Slack и Discord

<div class="article-intro">

Публикуйте понятные уведомления из B1 прямо в канал Slack или Discord: новые люди, пожертвования, регистрации в группы, отправки форм, события календаря и многое другое. Не нужна сторонняя учётная запись и не нужно поддерживать Zap: B1 сама преобразует события в сообщения чата и отправляет их на URL веб-хука канала.

</div>

<div class="prereqs">
<h4>Прежде чем начать</h4>

- Нужно право **Edit Settings** в B1Admin
- Администратор вашего рабочего пространства Slack или сервера Discord, который может создать входящий веб-хук канала
- Решите, в какой канал отправлять уведомления (можно использовать один канал для нескольких типов событий или разнести их по разным каналам)

</div>

## Как это работает {#how-it-works}

В B1 есть встроенный **Connector Type** для платформ чата. Когда вы создаёте веб-хук с типом **Slack** или **Discord**, механизм веб-хуков по-прежнему выполняет обычную доставку, повторные попытки и подпись заголовков, но тело сообщения преобразуется из стандартного конверта B1 `{event,churchId,data}` в простое сообщение `{text}` (Slack) или `{content}` (Discord), которое ожидают эти сервисы.

B1 не обращается к Slack для каждой церкви отдельно, кроме существующего потока исходящих веб-хуков, — ничего нового размещать и ничем дополнительно платить не нужно.

## Slack — пошагово {#slack--step-by-step}

### 1. Получите URL входящего веб-хука Slack {#1-get-a-slack-incoming-webhook-url}

1. Откройте [api.slack.com/apps](https://api.slack.com/apps) в рабочем пространстве Slack, куда хотите получать уведомления.
2. Нажмите **Create New App → From scratch**, назовите приложение, например, «B1 Notifications», и выберите рабочее пространство.
3. В левом меню выберите **Incoming Webhooks** и переключите **Activate Incoming Webhooks** в положение *On*.
4. Нажмите **Add New Webhook to Workspace**, выберите канал (например, `#donations`), затем **Allow**.
5. Slack вернёт вас на страницу с новым **Webhook URL**, который выглядит так: `https://hooks.slack.com/services/T0XXXXXXX/B0YYYYYYY/zzz…`. Скопируйте его — это единственное, что нужно B1.

:::caution
Относитесь к URL веб-хука Slack как к секрету. Любой, у кого он есть, может публиковать произвольные сообщения в канал. Если он случайно раскрыт, перегенерируйте его на странице приложения Slack (перегенерация лишь меняет URL; обновите B1 в соответствии с ним).
:::

### 2. Подключите его в B1Admin {#2-connect-it-in-b1admin}

1. В B1Admin перейдите в **Settings → Developer → Webhooks**.
2. Нажмите **New Webhook**.
3. Заполните:
   - **Name** — понятное название, например «Donations → #donations». Видно только вашей команде.
   - **Connector Type** — выберите **Slack**.
   - **Payload URL** — вставьте URL Slack из шага 1.
   - **Events** — отметьте события, которые хотите получать как сообщения. Для канала пожертвований достаточно `donation.created`. Для канала #people попробуйте `person.created` и `group.member.added`.
4. Нажмите **Save**. Появится диалог «Signing Secret» — для Slack его можно игнорировать (Slack не проверяет подписи B1) и закрыть.

### 3. Проверьте {#3-test-it}

Откройте веб-хук из списка снова и нажмите **Send Test Event**. B1 отправит пример первого отмеченного события, и примерно через секунду-две в канале Slack появится сообщение вида

> 💝 New donation: $50.00

а в таблице **Recent Deliveries** на том же экране появится новая строка со статусом `succeeded`. Готово.

## Discord — пошагово {#discord--step-by-step}

### 1. Получите URL веб-хука Discord {#1-get-a-discord-webhook-url}

1. На сервере Discord наведите курсор на канал, в который хотите получать уведомления, и нажмите **⚙ шестерёнку** (Edit Channel).
2. Откройте **Integrations → Webhooks → New Webhook**.
3. Задайте имя и (при желании) аватар, затем нажмите **Copy Webhook URL** — он выглядит так: `https://discord.com/api/webhooks/123…/abc…`.

### 2. Подключите его в B1Admin {#2-connect-it-in-b1admin-1}

Точно так же, как и для Slack выше, только **Connector Type** укажите **Discord**. Вставьте URL Discord в **Payload URL** и сохраните.

:::tip
Добавлять `/slack` в конец URL Discord **не нужно** — B1 отправляет нативные для Discord пакеты `{content}`, а не совместимые со Slack. Просто вставьте URL, который дал Discord.
:::

### 3. Проверьте {#3-test-it-1}

Та же кнопка **Send Test Event** — Discord покажет сообщение в выбранном канале, а журнал доставки переключится на `succeeded`.

## Как выглядят сообщения {#what-the-messages-look-like}

| Событие | Пример сообщения |
|---|---|
| `person.created` | 👤 New person added: Jordan Rivera |
| `person.updated` | 👤 Person updated: Jordan Rivera |
| `group.created` | 👥 New group created: Tuesday Bible Study |
| `group.member.added` | ➕ Someone was added to a group |
| `donation.created` | 💝 New donation: $50.00 |
| `donation.updated` | 💝 Donation updated: $75.00 |
| `attendance.recorded` | ✅ Attendance recorded |
| `form.submission.created` | 📝 New form submission received |
| `event.created` | 📅 New event: Easter Service |

Полный список находится в [каталоге событий веб-хуков](/docs/developer/api/webhooks#event-catalog) — любое событие оттуда можно направить в Slack/Discord.

## Один канал на тему {#one-channel-per-topic}

Не обязательно складывать все события в одно место. Большинство церквей настраивают несколько веб-хуков:

- Канал **#donations**, который слушает только `donation.created`
- Канал **#new-people** для `person.created` и `group.member.added`
- Канал **#admin-alerts** для редких событий, например `form.submission.created`

Количество веб-хуков для церкви не ограничено. Каждый из них независим: удаление или отключение одного не влияет на остальные.

## Просмотр доставок {#inspecting-deliveries}

В таблице **Recent Deliveries** в редакторе веб-хука показаны последние 50 попыток. Нажмите на строку, чтобы увидеть точный пакет, который был отправлен, и ответ, который пришёл в ответ. Для коннектора Slack пакет выглядит как `{"text":"💝 New donation: $50.00"}`, а не как исходный конверт `{event,churchId,...}`, потому что B1 преобразует его перед отправкой.

Если что-то не сработало (жёлтый значок `failed`, пока B1 ещё повторяет попытки, или красный значок `exhausted`, когда B1 перестала пытаться), в столбце **Response** показан HTTP-статус, а в диалоге строки — тело ответа, так что вы видите, что именно не понравилось Slack или Discord, обычно это ошибка копирования URL. Нажмите **Redeliver**, чтобы отправить доставку повторно.

## Устранение неполадок {#troubleshooting}

- **Сообщение не появляется, статус доставки `400`** — обычно тип коннектора установлен **Standard**, но URL принадлежит Slack/Discord. Slack/Discord отклоняют исходный конверт. Переключите список на **Slack** или **Discord** и отправьте тестовое событие снова.
- **Веб-хук отключился автоматически** — B1 повторяет каждую неудачную доставку примерно пять дней. Если три доставки подряд исчерпали повторы, B1 выключает веб-хук (его статус становится **Disabled**). Исправьте URL (или перегенерируйте его в Slack/Discord), снова включите **Active** и сохраните.
- **Сообщение пришло, но без подробностей** — все платформы чата ограничивают размер сообщения. Сообщения B1 намеренно короткие; для более насыщенных уведомлений используйте [Zapier](./zapier.md) или [Make](./make.md), чтобы составить полное сообщение Slack через их действия Slack.

## Смена типа коннектора {#switching-connector-types-later}

Тип коннектора у существующего веб-хука можно поменять — изменение вступает в силу при следующей доставке. Если вы переключаетесь с Slack на Standard, укажите URL на свою конечную точку HTTPS; тот же секрет подписи (он был выдан при создании веб-хука) теперь можно проверять по исходному конверту.
