# Mailchimp

<div class="article-intro">

Синхронизируйте аудиторию Mailchimp с B1 Admin автоматически: люди поступают с их именем, адресом электронной почты и телефоном; членство в группах и списках становится тегами Mailchimp; удаленные люди архивируются. Синхронизация встроена в B1 — нет третьей стороны, нет поэтапного учета, а изменения прибывают в реальном времени, а не по расписанию.

</div>

<div class="prereqs">
<h4>Перед началом</h4>

- Учетная запись [Mailchimp](https://mailchimp.com) с аудиторией, которой должна управлять B1
- **API ключ** Mailchimp (Mailchimp: значок профиля → **Account & billing → Extras → API keys**)
- Ваш **Audience ID** (Mailchimp: **Audience → Settings → Audience name and defaults**)
- Пользователь B1Admin с разрешением **Edit Settings**

</div>

## Что синхронизируется

| Изменение в B1 | Эффект в Mailchimp |
|---|---|
| Добавлен или обновлен человек | Подписчик добавлен/обновлен (имя, фамилия, телефон; новые подписчики приходят как `подписанные`) |
| Человек удален (или стерт по GDPR) | Подписчик архивирован |
| Человек присоединится к группе | Добавлен тег с названием группы |
| Человек покидает группу | Этот тег удален |
| Человек входит в сохраненный список | Добавлен тег с названием списка |
| Человек покидает сохраненный список | Этот тег удален |

**Сохраненные списки - обычно лучший источник тегов.** Сохраненный список B1 - это аудитория на основе правил, которая переоценивает себя - "все на кампусе North", "члены, которые согласились на пастырские письма". Укажите ваши сегменты Mailchimp на теги списков, и синхронизация поддерживает их; используйте теги группы для рассылок команд служения.

Синхронизация **односторонняя** (B1 → Mailchimp) и касается только стандартных полей Mailchimp, поэтому не может конфликтовать с полями слияния или сегментами, которыми вы управляете в Mailchimp.

## Настройка

1. В B1Admin перейдите на **Settings → Developer → Webhooks → Add Webhook**.
2. Установите **Connector Type** на **Mailchimp**.
3. Вставьте ваш **Mailchimp API Key** и **Audience ID**. Ключ хранится в зашифрованном виде и больше никогда не отображается.
4. Соответствующие события предварительно выбраны; снимите флажки для любых нежелательных (например, оставьте события людей, но пропустите теги группы).
5. Сохраните. B1 проверяет ключ и аудиторию в Mailchimp перед принятием — опечатка сразу же выдаст причину отказа.

Используйте **Send Test** в любое время для повторной проверки соединения. Каждая попытка синхронизации регистрируется в истории доставки вебхука с фактическим ответом Mailchimp, и неудачные доставки автоматически повторяются с отступлением на протяжении примерно пяти дней.

## Первоначальный импорт

Соединитель синхронизирует *изменения* с момента его включения; он не заполняет вашу существующую директорию. В день настройки:

1. В B1Admin перейдите в **People**, найдите людей, которых вы хотите (или запустите сохраненный список), и нажмите **Export** для загрузки CSV.
2. В Mailchimp используйте **Audience → Import contacts** для загрузки CSV, применяя любые теги при импорте.

Первоначальная загрузка через импортер Mailchimp сохраняет за вами контроль над вопросом согласия - импортируйте только людей, которые действительно согласились получать ваши письма. Массовый импорт всей директории как подписанных контактов может нарушить условия Mailchimp и законодательство о спаме (CAN-SPAM/GDPR).

## Ограничения и примечания

- **Односторонняя синхронизация.** Отписки, отскоки и правки, сделанные в Mailchimp, не возвращаются в B1. Человек, который отпишется в Mailchimp, может по-прежнему получать письма, отправленные непосредственно из B1 — рассматривайте Mailchimp как источник истины для согласия на массовую почту.
- **Люди без адреса электронной почты пропускаются** (зарегистрированы как таковые в истории доставки) — подписчики Mailchimp идентифицируются по электронной почте.
- **Изменения адреса электронной почты создают нового подписчика.** Mailchimp идентифицирует людей по электронной почте, поэтому изменение чьей-то электронной почты в B1 добавляет их под новый адрес; старый подписчик остается до архивации в Mailchimp.
- **Синхронизируются только стандартные поля** — имя, фамилия, телефон. Статус членства, кампус и пользовательские поля B1 не отображаются в полях слияния Mailchimp в этой версии; вместо этого используйте теги списка для сегментации.
- **Имена тегов - это названия групп/списков.** Переименование группы или списка начинает маркировку под новым именем; старый тег остается на существующих подписчиках до удаления в Mailchimp.
- **Ограничения контактов Mailchimp по-прежнему применяются** — синхронизация, которая отправляет аудиторию бесплатного уровня сверх лимита, будет регистрировать ошибки `Member limit reached` в истории доставки.

## Прочие рецепты (Zapier / Make)

Что-либо кроме синхронизации аудитории — маркировка дарителей на `donation.created`, обратная синхронизация Mailchimp → B1 или синхронизация с совершенно другой платформой электронной почты (Constant Contact, Brevo и т.д.) — по-прежнему доступно через [Zapier](../zapier) или [Make](../make), которые срабатывают по одним и тем же событиям веб-хука:

- **Пометить дарителей:** B1 *New Donation* → B1 *Find Person* → Mailchimp *Add Subscriber to Tag* (`Gave-2026`)
- **Двусторонняя:** Mailchimp *New Subscriber* → B1 *Create Person*

Если вы ранее подключили синхронизацию людей/групп через Zapier, отключите эти Zaps после включения нативного соединителя — запуск обоих двойных процессов каждого события и расходует задачи Zapier напрасно.

## Устранение неполадок

- **Сохранение не удается с "Mailchimp rejected the API key"** — ключ был отозван или неправильно введен. Ключи должны заканчиваться на суффикс центра данных типа `-us21`.
- **Сохранение не удается с "audience not found"** — Audience ID не существует в этой учетной записи. Скопируйте его из **Audience → Settings → Audience name and defaults** (это не название аудитории).
- **Человек никогда не появился в Mailchimp** — проверьте историю доставки веб-хука. "Skipped: person has no email address" означает ровно это; `4xx` от Mailchimp показывает причину в теле ответа.
- **Доставки полностью остановлены** — после повторных исчерпанных доставок веб-хук автоматически отключается. Исправьте причину (обычно отозванный ключ), повторно включите и используйте **Send Test** для подтверждения.
