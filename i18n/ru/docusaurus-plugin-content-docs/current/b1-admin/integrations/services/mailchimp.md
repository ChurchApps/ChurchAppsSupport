# Mailchimp

<div class="article-intro">

Держите аудиторию Mailchimp в синхронизации с B1 автоматически: люди поступают со своим именем, электронной почтой и телефоном; членство в группе и списке становится тегами Mailchimp; удаленные люди архивируются. Синхронизация встроена в B1 -- никакой третьей стороны сервис, нет метров за задачу, и изменения поступают в режиме реального времени, а не по ночному расписанию.

</div>

<div class="prereqs">
<h4>Перед началом работы</h4>

- Учетная запись [Mailchimp](https://mailchimp.com) с аудиторией, которой вы хотите управлять B1
- Mailchimp **API key** (Mailchimp: значок профиля → **Account & billing → Extras → API keys**)
- Ваш **Audience ID** (Mailchimp: **Audience → Settings → Audience name and defaults**)
- Пользователь B1Admin с разрешением **Edit Settings**

</div>

## Что синхронизируется

| Изменение B1 | Эффект Mailchimp |
|---|---|
| Человек добавлен или обновлен | Подписчик добавлен/обновлен (имя, фамилия, телефон; новые подписчики поступают как `subscribed`) |
| Человек удален (или стерт GDPR) | Подписчик архивирован |
| Человек присоединяется к группе | Добавлен тег с названием группы |
| Человек покидает группу | Этот тег удален |
| Человек входит в сохраненный список | Добавлен тег с названием списка |
| Человек покидает сохраненный список | Этот тег удален |

**Сохраненные списки обычно лучший источник тегов.** B1 [сохраненный список](/docs/b1-admin/people/lists) - это аудитория на основе правил, которая переоценивает себя -- "все на кампусе North", "члены, которые согласились на пастырские письма". Укажите ваши сегменты Mailchimp на теги списков и синхронизация поддерживает их; используйте теги групп для рассылок команд служения.

Синхронизация **один-путевая** (B1 → Mailchimp) и касается только стандартных полей Mailchimp, поэтому она не может конфликтовать с полями слияния или сегментами, которыми вы управляете внутри Mailchimp.

## Установка

1. В B1Admin перейдите к **Settings → Developer → Webhooks → Add Webhook**.
2. Установите **Connector Type** на **Mailchimp**.
3. Вставьте ваш **Mailchimp API Key** и **Audience ID**. Ключ хранится зашифрованным и больше никогда не показывается.
4. Соответствующие события предварительно выбраны; отмените выбор тех, которые вы не хотите (например, оставьте события людей, но пропустите теги групп).
5. Сохраните. B1 проверяет ключ и аудиторию для Mailchimp перед принятием -- опечатка немедленно не получается с причиной.

Используйте **Send Test** в любое время для повторной проверки соединения. Каждая попытка синхронизации регистрируется в истории доставки веб-хука с фактическим ответом Mailchimp, и неудачные доставки автоматически повторяются с резервными копиями примерно пять дней.

## Первоначальный импорт

Соединитель синхронизирует *изменения* с момента включения; он не заполняет вашу существующую директорию. Для дня установки:

1. В B1Admin перейдите к **People**, поищите людей, которых вы хотите (или запустите сохраненный список), и нажмите **Export**, чтобы загрузить CSV.
2. В Mailchimp используйте **Audience → Import contacts**, чтобы загрузить CSV, применив любые теги при импорте.

Выполнение начальной загрузки через импортер Mailchimp сохраняет вас в контроле над вопросом согласия -- импортируйте только людей, которые фактически согласились получать ваши письма. Массовый импорт целой директории как подписанных контактов может нарушить условия Mailchimp и антиспам-закон (CAN-SPAM/GDPR).

## Ограничения и примечания

- **Один-путевая синхронизация.** Отписки, отскоки и правки, сделанные в Mailchimp, не поступают обратно в B1. Кто-то, кто отписался в Mailchimp, все еще может получать письма, отправленные прямо из B1 -- рассматривайте Mailchimp как источник правды для согласия на массовую рассылку.
- **Люди без адреса электронной почты пропускаются** (зарегистрированы как таковые в истории доставки) -- подписчики Mailchimp идентифицируются по электронной почте.
- **Изменения адреса электронной почты создают нового подписчика.** Mailchimp идентифицирует людей по электронной почте, поэтому изменение чьей-то электронной почты в B1 добавляет их под новым адресом; старый подписчик остается до архивации в Mailchimp.
- **Синхронизируются только стандартные поля** -- имя, фамилия, телефон. Статус членства, кампус и пользовательские поля B1 не отображаются в полях слияния Mailchimp в этой версии; используйте теги списков для сегментации вместо этого.
- **Имена тегов - это имена групп/списков.** Переименование группы или списка начинает маркировать под новым именем; старый тег остается на существующих подписчиках до удаления в Mailchimp.
- **Ограничения контактов Mailchimp все еще применяются** -- синхронизация, которая подталкивает аудиторию бесплатного уровня к его пределу, будет регистрировать ошибки `Member limit reached` в истории доставки.

## Другие рецепты (Zapier / Make)

Все, что выходит за пределы синхронизации аудитории -- маркировка жертвователей на `donation.created`, обратное направление Mailchimp → B1, или синхронизация с другой платформой электронной почты полностью (Constant Contact, Brevo и т.д.) -- все еще доступно через [Zapier](../zapier) или [Make](../make), которые срабатывают на тех же событиях веб-хука:

- **Tag givers:** B1 *New Donation* → B1 *Find Person* → Mailchimp *Add Subscriber to Tag* (`Gave-2026`)
- **Two-way:** Mailchimp *New Subscriber* → B1 *Create Person*

Если вы ранее провели синхронизацию человека/группы через Zapier, отключите эти Zaps после включения встроенного соединителя -- запуск обоих двойных процессов каждого события и сжигает задачи Zapier впустую.

## Устранение неполадок

- **Save fails with "Mailchimp rejected the API key"** -- ключ был отозван или неправильно введен. Ключи должны заканчиваться суффиксом центра данных, как `-us21`.
- **Save fails with "audience not found"** -- ID аудитории не существует в этой учетной записи. Скопируйте его из **Audience → Settings → Audience name and defaults** (это не имя аудитории).
- **A person never appeared in Mailchimp** -- проверьте историю доставки веб-хука. "Skipped: person has no email address" означает именно это; `4xx` из Mailchimp показывает причину в теле ответа.
- **Deliveries stopped entirely** -- после повторных исчерпанных доставок веб-хук автоматически отключается. Исправьте причину (обычно отозванный ключ), повторно включите его и используйте **Send Test** для подтверждения.
