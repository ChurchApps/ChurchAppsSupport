# Mailchimp

<div class="article-intro">

Поддерживайте аудиторию Mailchimp в автоматической синхронизации с B1: люди попадают в неё с именем, адресом электронной почты и телефоном; членство в группах и списках становится метками Mailchimp; удалённые люди архивируются. Синхронизация встроена в B1 — без стороннего сервиса и без оплаты за каждую задачу, а изменения приходят почти в реальном времени, а не по ночному расписанию.

</div>

<div class="prereqs">
<h4>Прежде чем начать</h4>

- Учётная запись [Mailchimp](https://mailchimp.com) с аудиторией, которой B1 должна управлять
- **API-ключ** Mailchimp (Mailchimp: значок профиля → **Account & billing → Extras → API keys**)
- Ваш **Audience ID** (Mailchimp: **Audience → Settings → Audience name and defaults**)
- Пользователь B1Admin с правом **Edit Settings**

</div>

## Что синхронизируется {#what-syncs}

| Изменение в B1 | Эффект в Mailchimp |
|---|---|
| Человек добавлен или обновлён | Подписчик добавлен или обновлён (имя, фамилия, телефон; новые подписчики получают статус `subscribed`) |
| Человек удалён (или стёрт по GDPR) | Подписчик архивируется |
| Человек вступает в группу | Добавляется метка с названием группы |
| Человек выходит из группы | Эта метка удаляется |
| Человек попадает в сохранённый список | Добавляется метка с названием списка |
| Человек выходит из сохранённого списка | Эта метка удаляется |

**Сохранённые списки обычно лучший источник меток.** [Сохранённый список](/docs/b1-admin/people/lists) в B1 — это аудитория на основе правил, которая сама себя пересчитывает: «все в северном кампусе», «участники, согласившиеся на пасторские письма». Направьте сегменты Mailchimp на метки списков, и синхронизация будет поддерживать их; метки групп используйте для рассылок служебным командам.

Синхронизация **односторонняя** (B1 → Mailchimp) и затрагивает только стандартные поля Mailchimp, поэтому она не может конфликтовать с полями слияния или сегментами, которые вы ведёте внутри Mailchimp.

## Настройка {#setup}

1. В B1Admin перейдите в **Settings → Developer → Webhooks → New Webhook**.
2. Установите **Connector Type** в значение **Mailchimp**.
3. Вставьте **Mailchimp API Key** и **Audience ID**. Ключ хранится в зашифрованном виде и больше не показывается.
4. Нужные события уже выбраны; снимите отметку с ненужных (например, оставьте события людей, но пропустите метки групп).
5. Сохраните. B1 проверит ключ и аудиторию в Mailchimp до принятия — опечатка сразу выдаст ошибку с причиной.

Откройте веб-хук снова и нажмите **Send Test Event**, чтобы в любой момент повторно проверить подключение (для Mailchimp это проверка ключа и аудитории, а не отправка образца подписчика). Каждая попытка синхронизации записывается в журнал доставок веб-хука с настоящим ответом Mailchimp, а неудачные доставки автоматически повторяются с нарастающими паузами примерно пять дней.

## Первичный импорт {#initial-import}

Коннектор синхронизирует *изменения* с момента включения; он не загружает задним числом ваш существующий каталог. Для дня настройки:

1. В B1Admin перейдите в **People**, найдите нужных людей (или загрузите сохранённый список) и нажмите **Export**, чтобы скачать CSV.
2. В Mailchimp используйте **Audience → Import contacts**, чтобы загрузить CSV, применяя метки при импорте.

Первоначальную загрузку через импортёр Mailchimp вы контролируете сами — в вопросе согласия. Импортируйте только тех, кто действительно согласился получать ваши письма. Массовый импорт всего каталога как подписчиков может нарушать условия Mailchimp и законы против спама (CAN-SPAM/GDPR).

## Ограничения и примечания {#limits--notes}

- **Односторонняя синхронизация.** Отписки, отскоки и правки, сделанные в Mailchimp, в B1 не возвращаются. Человек, отписавшийся в Mailchimp, всё равно может получать письма, отправленные напрямую из B1, — считайте Mailchimp источником истины для согласия на массовые рассылки.
- **Люди без адреса электронной почты пропускаются** (это отмечается в журнале доставок), потому что подписчики Mailchimp идентифицируются по адресу электронной почты.
- **Изменение адреса электронной почты создаёт нового подписчика.** Mailchimp различает людей по адресу электронной почты, поэтому, если изменить адрес человека в B1, он появится под новым адресом; старый подписчик останется, пока вы не архивируете его в Mailchimp.
- **Синхронизируются только стандартные поля** — имя, фамилия, телефон. Статус членства, кампус и пользовательские поля B1 в этой версии не сопоставляются с полями слияния Mailchimp; для сегментации используйте метки списков.
- **Названия меток совпадают с названиями групп и списков.** При переименовании группы или списка новые метки будут создаваться под новым названием; старая метка останется у существующих подписчиков, пока вы её не удалите в Mailchimp.
- **Действуют ограничения контактов Mailchimp** — если синхронизация переводит бесплатную аудиторию за её лимит, в журнале доставок появятся ошибки `Member limit reached`.

## Другие рецепты (Zapier / Make) {#other-recipes-zapier--make}

Всё, что выходит за рамки синхронизации аудитории — метки для жертвователей по событию `donation.created`, обратное направление Mailchimp → B1 или синхронизация с совершенно другой платформой email (Constant Contact, Brevo и т. д.), — по-прежнему доступно через [Zapier](../zapier.md) или [Make](../make.md), которые срабатывают на те же события веб-хуков:

- **Метка для жертвователей:** B1 *New Donation* → B1 *Find Person* → Mailchimp *Add Subscriber to Tag* (`Gave-2026`)
- **В обе стороны:** Mailchimp *New Subscriber* → B1 *Create Person*

Если вы раньше настраивали синхронизацию людей и групп через Zapier, отключите эти Zap после включения встроенного коннектора: одновременная работа обоих обрабатывает каждое событие дважды и впустую расходует задачи Zapier.

## Устранение неполадок {#troubleshooting}

- **Сохранение не проходит с ошибкой «Mailchimp rejected the API key»** — ключ отозван или введён с опечаткой. Ключи должны заканчиваться суффиксом дата-центра, например `-us21`.
- **Сохранение не проходит с ошибкой «audience not found»** — Audience ID не существует в этой учётной записи. Скопируйте его из **Audience → Settings → Audience name and defaults** (это не название аудитории).
- **Человек так и не появился в Mailchimp** — проверьте журнал доставок веб-хука. «Skipped: person has no email address» означает именно это; ответ `4xx` от Mailchimp показывает причину в теле ответа.
- **Доставки полностью остановились** — после многократных исчерпанных доставок веб-хук автоматически отключается. Устраните причину (обычно отозванный ключ), включите его снова и проверьте через **Send Test Event**.
