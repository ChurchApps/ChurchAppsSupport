# Checkr

<div class="article-intro">

[Checkr](https://checkr.com) выполняет проверку биографических данных для сотрудников и волонтеров — практически универсальная потребность для любой церкви, ведущей детскую или молодежную программу. В B1 **нет встроенной функции проверки биографических данных** — заказ проверок, отслеживание результатов и соответствие требованиям проверки полностью находятся в Checkr; приведенный ниже рецепт лишь связывает события B1 с ним. У Checkr нет приложения Zapier, но [интеграция Checkr в Make.com](https://www.make.com/en/integrations/checkr) проверена и предоставляет действия, необходимые для запуска проверки из события B1.

</div>

## Что можно связать

Приложение Checkr в Make предоставляет 1 триггер и 6 действий:

| Направление | Триггер B1 / Make | Действие |
|---|---|---|
| B1 → Checkr | B1 `group.member.added` (отфильтровано по группе волонтеров) | Checkr: Создать кандидата → Создать приглашение на проверку биографии |
| Checkr → B1 | Веб-хук Checkr (событие приглашения / отчета) | B1: Обновить запись человека (например, метка «Проверка Checkr пройдена») |

Действия Checkr в Make: Создать кандидата, Создать приглашение на проверку биографии, Получить кандидата, Получить отчет, Получить ожидаемое время отчета, Получить приглашение. Плюс 4 модуля поиска.

## Настройка

### 1. Создайте API-ключ B1

**Настройки → Для разработчиков → API-ключи → Новый API-ключ**:

- `settings:write` — для веб-хука триггера
- `people:read` — для получения имени/почты человека при запуске проверки
- (Необязательно) `people:write`, если вы хотите записывать статус отчета обратно в виде пользовательского поля или метки

### 2. Создайте сценарий «запустить проверку при регистрации волонтера» в Make

1. **Триггер** — B1.church: Отслеживать события (`group.member.added`).
2. **Фильтр** — продолжать только если `data.groupId` соответствует вашей группе «Волонтеры детского служения» (или аналогичной).
3. **Действие** — B1.church: Найти человека (по `data.personId`), чтобы получить email и имя/фамилию.
4. **Действие** — Checkr: Создать кандидата. Сопоставьте имя/фамилию/email из шага 3.
5. **Действие** — Checkr: Создать приглашение на проверку биографии. Сопоставьте id нового кандидата из шага 4 с полем *candidate_id*. Выберите пакет проверки (например, `tasker_standard` или другой, доступный в вашей учетной записи).
6. (Необязательно) **Действие** — Slack: уведомите координатора безопасного служения о том, что проверка инициирована.

Включите сценарий. Новые волонтеры в целевой группе автоматически получат приглашение Checkr по email; они заполняют его на телефоне или ноутбуке; Checkr выполняет проверку.

### 3. (Необязательно) Получение отчета обратно

1. **Триггер** — Checkr: Отслеживать события (веб-хук). Make регистрирует веб-хук Checkr при активации.
2. **Фильтр** — продолжать только если `event_type = report.completed`.
3. **Действие** — Checkr: Получить отчет (используйте id отчета из веб-хука).
4. **Действие** — B1.church: Найти человека (по email кандидата).
5. **Действие** — Условный Slack / Email: уведомите координатора со статусом `clear` / `consider` / `suspended`.

Примечание: в B1 сегодня нет встроенного поля «статус проверки биографии». Практичные варианты: (а) публиковать результат в приватном канале Slack для проверки, (б) записывать его в Google Sheet для аудита или (в) добавлять человека в группу B1 «Проверенные волонтеры» при статусе `clear`.

## Общие рецепты

### Повторная проверка волонтеров каждые 2 года

Совместите приведенный выше сценарий с триггером расписания Make:

- **Триггер** — Make: Расписание (ежемесячно)
- **Действие** — B1.church: Список участников группы «Проверенные волонтеры»
- **Действие** — Фильтр в Make: дата проверки старше 22 месяцев
- **Действие** — Checkr: Создать приглашение на проверку биографии (как в исходном сценарии)

### Блокировка доступа к первому этапу до завершения проверки

Если ваша церковь использует членство в группе B1 для ограничения доступа (например, только участники группы «Проверенные» появляются в расписаниях служения), удерживайте новых волонтеров в удерживающей группе, пока событие Checkr `report.completed` не переместит их.

## Ограничения и заметки

- **Checkr работает только в США** для большинства пакетов проверки. Церквям из Австралии, Великобритании и Канады понадобится альтернатива.
- **Оплата взимается за каждую проверку** — каждое действие «Создать приглашение» в Make тратит реальную проверку. Сначала протестируйте в песочнице / staging-аккаунте Checkr (приложение Checkr в Make использует те же учетные данные, что вы передаете при подключении, так что смена учетных данных переключает песочницу/боевую среду).
- **Доступ к API Checkr зависит от тарифа.** Небольшие аккаунты Checkr могут быть на тарифе только с UI; свяжитесь с Checkr, чтобы включить API.

## Устранение неполадок

- **Создание кандидата завершается ошибкой `403`** — токен API Checkr доступен только для чтения или не имеет нужных прав аккаунта. Переоформите его в панели Checkr с правами на запись.
- **Приглашение не приходит** — проверьте email кандидата в шаге 3; у B1 может быть пустое поле email для этого человека. Добавьте фильтр, требующий наличия email, перед шагом Checkr.
- **Триггер веб-хука не срабатывает** — регистрация веб-хука Checkr иногда молча не срабатывает, если ваш аккаунт Make не на платном тарифе, поддерживающем исходящие веб-хуки. Проверьте на странице *Webhooks* панели Checkr, что URL Make указан в списке.
