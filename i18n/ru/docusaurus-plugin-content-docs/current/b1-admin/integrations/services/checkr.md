# Checkr

<div class="article-intro">

[Checkr](https://checkr.com) проводит проверку биографии сотрудников и волонтёров — это почти обязательная потребность для любой церкви с детскими или молодёжными программами. В B1 **нет встроенной функции проверки биографии**: заказ проверок, отслеживание результатов и соответствие требованиям проверки ведутся в Checkr, а рецепт ниже лишь связывает события B1 с Checkr. У Checkr нет приложения Zapier, но [интеграция Checkr в Make.com](https://www.make.com/en/integrations/checkr) проверена и предоставляет действия, которые нужны, чтобы запустить проверку по событию B1.

</div>

:::caution
Этот рецепт использует приложение B1.church для Make, которое ещё не выпущено (см. [Make](../make.md)). До его выпуска сторона B1 в этих сценариях строится с помощью модуля **HTTP** в Make, который вызывает [REST API](/docs/developer/api) B1.
:::

- Учётная запись [Checkr](https://checkr.com) с доступом к API и хотя бы одним настроенным пакетом проверки

- Пользователь B1Admin с правом **Edit Settings**

## Что можно связать {#what-you-can-wire-up}

Приложение Checkr в Make предоставляет 1 триггер и 6 действий:

| Направление | Триггер B1 / Make | Действие |
|---|---|---|
| B1 → Checkr | B1 `group.member.added` (отфильтровано по группе волонтёров) | Checkr: Create Candidate → Create Background Check Invitation |
| Checkr → B1 | Веб-хук Checkr (событие приглашения / отчёта) | B1: Обновить запись человека (например, метка «Checkr cleared») |

Действия Checkr в Make: Create Candidate, Create Background Check Invitation, Get Candidate, Get Report, Get Report's ETA, Get an Invitation. Плюс 4 модуля поиска.

## Настройка {#setup}

### 1. Создайте API-ключ B1 {#1-mint-a-b1-api-key}

**Settings → Developer → API Keys → New API Key**:

- `settings:write` — для веб-хука триггера
- `people:read` — чтобы найти имя и адрес электронной почты человека при запуске проверки
- (необязательно) `people:write`, если вы хотите записывать статус отчёта обратно как пользовательское поле или метку

### 2. Постройте сценарий «запустить проверку при регистрации волонтёра» в Make {#2-build-the-kick-off-a-check-on-volunteer-signup-scenario-in-make}

1. **Триггер** — B1.church: Watch Events (`group.member.added`).
2. **Фильтр** — продолжать, только если `data.groupId` совпадает с вашей группой «Children's Volunteers» (или аналогичной).
3. **Действие** — B1.church: Find Person (по `data.personId`), чтобы получить адрес электронной почты, имя и фамилию.
4. **Действие** — Checkr: Create Candidate. Сопоставьте имя, фамилию и адрес из шага 3.
5. **Действие** — Checkr: Create Background Check Invitation. Сопоставьте id нового кандидата из шага 4 с полем *candidate_id*. Выберите пакет проверки (например, `tasker_standard` или любой, доступный в вашей учётной записи).
6. (необязательно) **Действие** — Slack: уведомить координатора безопасного служения, что проверка начата.

Включите сценарий. Новые волонтёры в нужной группе автоматически получают приглашение Checkr по электронной почте; они заполняют его на телефоне или ноутбуке, а Checkr проводит проверку.

### 3. (необязательно) Получите отчёт обратно {#3-optional-receive-the-report-back}

1. **Триггер** — Checkr: Watch Events (веб-хук). Make регистрирует веб-хук Checkr при активации.
2. **Фильтр** — продолжать, только если `event_type = report.completed`.
3. **Действие** — Checkr: Get Report (используйте id отчёта из веб-хука).
4. **Действие** — B1.church: Find Person (по адресу электронной почты кандидата).
5. **Действие** — условное уведомление в Slack / Email: сообщить координатору статус `clear` / `consider` / `suspended`.

Примечание: в B1 сегодня нет встроенного поля «статус проверки биографии». Практичные варианты: (а) публиковать результат в закрытом канале Slack для проверки, (б) записывать его в таблицу Google для аудита или (в) добавлять человека в группу B1 «Cleared volunteers» при статусе `clear`.

## Типичные рецепты {#common-recipes}

### Повторная проверка волонтёров раз в 2 года {#re-screen-volunteers-every-2-years}

Сочетайте описанное выше с триггером расписания Make:

- **Триггер** — Make: Schedule (ежемесячно)
- **Действие** — HTTP — Make a request: GET к `/membership/groupmembers?groupId=…` в B1 для вашей группы «Cleared volunteers» (в приложении B1.church нет действия списка)
- **Действие** — Filter by Make: дата проверки старше 22 месяцев
- **Действие** — Checkr: Create Background Check Invitation (как в первоначальном процессе)

### Блокировать доступ этапа 1 до завершения проверки {#block-stage-1-access-until-check-completes}

Если ваша церковь использует членство в группах B1 для ограничения доступа (например, в расписаниях служения появляются только участники группы «Cleared»), держите новых волонтёров в промежуточной группе, пока событие Checkr `report.completed` не переведёт их в нужную группу.

## Ограничения и примечания {#limits--notes}

- **Checkr работает только в США** для большинства пакетов проверки. Церквям в Австралии, Великобритании и Канаде понадобится альтернатива.
- **Оплата взимается за каждую проверку** — каждое действие «Create Invitation» в Make тратит реальную проверку. Сначала протестируйте в песочнице / staging-аккаунте Checkr (приложение Checkr в Make использует учётные данные из подключения, поэтому смена учётных данных переключает песочницу и боевой режим).
- **Доступ к API Checkr зависит от тарифа.** Небольшие учётные записи Checkr могут работать только через веб-интерфейс; чтобы включить API, свяжитесь с Checkr.

## Устранение неполадок {#troubleshooting}

- **Create Candidate завершается с `403`** — токен API Checkr только для чтения или не имеет нужных прав учётной записи. Выпустите его заново в панели Checkr с правом записи.
- **Приглашение не приходит** — проверьте адрес электронной почты кандидата на шаге 3: в B1 у этого человека может быть пустое поле электронной почты. Добавьте фильтр «требуется адрес электронной почты» перед шагом Checkr.
- **Триггер веб-хука не срабатывает** — регистрация веб-хука Checkr иногда молча не проходит, если ваша учётная запись Make не на платном тарифе, поддерживающем исходящие веб-хуки. Проверьте на странице *Webhooks* в панели Checkr, что URL Make там указан.
