# Donorbox

<div class="article-intro">

Если ваша церковь принимает пожертвования через Donorbox, а людей и справки ведёт в B1, триггеры Donorbox для Zapier могут мгновенно создавать соответствующие записи пожертвований в B1 — и создавать жертвователя как человека в B1, если его там ещё нет. Никакой ручной сверки и ежемесячных выгрузок.

</div>

<div class="prereqs">
<h4>Прежде чем начать</h4>

- Учётная запись [Donorbox](https://donorbox.org) хотя бы с одной кампанией
- Учётная запись [Zapier](https://zapier.com)
- Пользователь B1Admin с правом **Edit Settings**

</div>

## Что можно связать {#what-you-can-wire-up}

| Направление | Триггер Donorbox | Действие B1 |
|---|---|---|
| Donorbox → B1 | New or Updated Donation (мгновенно) | Find Person → Add Donation |
| Donorbox → B1 | New or Updated Donor | Create Person |
| Donorbox → B1 | New or Updated Plan (регулярные) | Find Person → Add Donation (id плана как примечание) |

Donorbox публикует свои триггеры как **мгновенные** — они срабатывают в течение нескольких секунд после реального пожертвования. Задержки опроса нет.

## Настройка {#setup}

### 1. Создайте API-ключ B1 {#1-mint-a-b1-api-key}

В B1Admin: **Settings → Developer → API Keys → New API Key**. Области:

- `people:read` — чтобы найти жертвователя по адресу электронной почты
- `people:write` — чтобы создать его, если он новый
- `donations:write` — чтобы записать пожертвование

- `settings:write` — Zapier проверяет каждый ключ B1 по списку веб-хуков B1 при подключении, поэтому без неё подключение не пройдёт (хотя триггер здесь принадлежит Donorbox, а не B1)

### 2. Создайте Zap «записать пожертвование» {#2-build-the-record-a-donation-zap}

1. **Триггер** — Donorbox: New Donation. Подключитесь с помощью API-ключа Donorbox (в Donorbox: *Account → Profile → API Settings*).
2. **Действие** — B1.church: Find Person. Сопоставьте адрес электронной почты жертвователя из триггера с полем *Email*.
3. **Действие** — B1.church: Add Donation. Сопоставьте:
   - Person → id из шага 2
   - Amount → сумма пожертвования из триггера
   - Donation Date → дата пожертвования из триггера
   - Fund → выберите фонд B1, который соответствует кампании Donorbox (Zapier позволяет менять фонд по фильтру или шагу Formatter)
   - Method → «Online»
   - Notes → id транзакции Donorbox (удобно при сверке)

Включите Zap. Следующее живое пожертвование через Donorbox автоматически появится в **B1Admin → Donations**.

Find Person в B1 останавливает Zap с ошибкой «No person found», если никто с таким адресом электронной почты не найден, поэтому шаг Filter не может ветвиться по этому условию. Чтобы обработать пожертвования от новых жертвователей, включите в Zapier обработку ошибок для шага Find Person и в её пути ошибки выполните B1.church: Create Person (сопоставьте имя, фамилию и адрес электронной почты), а затем Add Donation с id нового человека. Или запустите Zap *New Donor* → *Create Person* из таблицы выше, чтобы жертвователи уже существовали в B1 до поступления их пожертвования.

## Типичные рецепты {#common-recipes}

### Один Zap на фонд {#one-zap-per-fund}

Если у вас несколько кампаний Donorbox, которые соответствуют отдельным фондам B1, самая чистая схема — один Zap на кампанию с фильтром по *campaign* Donorbox в начале: тогда сопоставление фонда задано жёстко, и шаг поиска не нужен.

### Обновлённые пожертвования считать исправлениями {#treat-updated-donations-as-corrections}

Триггер Donorbox *New or Updated Donation* срабатывает и при изменениях. Используйте шаг Zapier *Path* по `event_type`, чтобы разделить потоки: «new» → Add Donation, «updated» → Find Donation + Update (учтите, что в приложении Zapier для B1 сейчас нет действия Update Donation — пока события «updated» записывайте в канал Slack для ручной проверки).

### Отправлять изменения регулярных планов в канал Slack {#sync-recurring-plan-changes-to-a-slack-channel}

- **Триггер** — Donorbox: New or Updated Plan
- **Действие** — Slack: Send Message в `#donations` (например, «План изменён — ежемесячное пожертвование Сары теперь $200»)

## Ограничения и примечания {#limits--notes}

- **Сопоставляйте жертвователей по адресу электронной почты.** Donorbox не передаёт id человека из B1; единственный надёжный ключ связи — адрес электронной почты. Жертвователи, которые дают под другим адресом, создадут нового человека в B1, — ваша ежемесячная сверка должна искать такие случаи.
- **Возвраты отдельно не передаются** — Donorbox отправляет обновление статуса для того же пожертвования. В приложении Zapier для B1 сейчас нет действия *Update Donation*; безопасный способ на сегодня — фиксировать события возврата вне системы и вручную корректировать пожертвование.
- **Сначала проверьте в песочнице Donorbox**, чтобы не создать поддельные пожертвования в рабочей B1. Donorbox предоставляет учётные данные тестового режима отдельно от боевых.

## Устранение неполадок {#troubleshooting}

- **Ошибки «No person found»** — жертвователя ещё нет в B1 (или он дал пожертвование под другим адресом электронной почты). Добавьте путь ошибки, описанный выше, и проверьте, что в API-ключе есть `people:write`, чтобы *Create Person* мог выполниться.
- **Сумма пожертвования в 100 раз больше или меньше** — Donorbox в одних вариантах полезной нагрузки передаёт центы, в других — доллары. При необходимости используйте шаг *Formatter by Zapier — Numbers*, чтобы разделить на 100.
- **Дублирование пожертвований от одного подарка** — Donorbox срабатывает и на *New Donation*, и на *Updated Donation*. Либо отфильтруйте по `event_type = "donation.succeeded"`, либо создайте два Zap с непересекающимися фильтрами.
