# VOMO

<div class="article-intro">

VOMO — платформа для вовлечения волонтёров: люди записываются на проекты, регистрируются на киоске и накапливают часы. Если вы используете VOMO для расписания волонтёров, а B1 — для учёта людей, Zapier может синхронизировать членство и регистрации между ними, чтобы данные в двух системах не расходились.

</div>

<div class="prereqs">
<h4>Прежде чем начать</h4>

- Учётная запись [VOMO](https://vomo.org) на тарифе, который поддерживает Zapier (если не уверены, уточните в поддержке VOMO)
- Учётная запись [Zapier](https://zapier.com)
- Пользователь B1Admin с правом **Edit Settings**

</div>

## Что можно связать {#what-you-can-wire-up}

Приложение VOMO для Zapier предоставляет четыре мгновенных триггера и четыре действия. Чаще всего церкви нужны такие рецепты:

| Направление | Триггер | Действие |
|---|---|---|
| VOMO → B1 | VOMO Membership (создан) | B1: Find Person → Create Person (если человек новый) |
| VOMO → B1 | VOMO Kiosk check-in | B1: Add Group Member в группу «Currently Serving» или запись посещаемости |
| B1 → VOMO | B1 `person.created` | VOMO: Find Organizer (по адресу электронной почты); иначе собственный шаг |
| Любое | VOMO Participation (записи) | B1: Add Group Member в группу конкретного проекта |

Действия VOMO сегодня ограничены **созданием черновиков проектов** и **поиском** существующих организаторов и проектов — действия «добавить этого человека в проект VOMO» пока нет. Самые полезные связки в основном идут от VOMO к B1.

## Настройка {#setup}

### 1. Создайте API-ключ B1 {#1-mint-a-b1-api-key}

**Settings → Developer → API Keys → New API Key**. Области:

- `settings:write` — Zapier проверяет каждый ключ B1 по списку веб-хуков B1 при подключении, поэтому без неё подключение не пройдёт
- `people:read`, `people:write` — чтобы искать и создавать волонтёров как людей B1
- `groups:write` — чтобы добавлять их в группы служебных команд
- (необязательно) `attendance:write`, если вы учитываете регистрации на киоске как посещаемость

### 2. Создайте Zap синхронизации членства {#2-build-the-membership-sync-zap}

1. **Триггер** — VOMO: Membership (событие = `created`).
2. **Действие** — B1.church: Find Person по адресу электронной почты.
3. **Действие** — B1.church: Add Group Member, добавляя человека из шага 2 в подходящую группу волонтёров.

   Find Person в B1 останавливает Zap с ошибкой «No person found», если совпадений нет. Для волонтёров, которых ещё нет в B1, включите в Zapier обработку ошибок для шага Find Person и в её пути ошибки выполните B1.church: Create Person, затем Add Group Member.
4. Включите Zap. Новые волонтёры VOMO теперь появляются в B1 с нужным членством в группе.

### 3. (необязательно) Создайте Zap регистрации на киоске {#3-optional-build-the-kiosk-check-in-zap}

1. **Триггер** — VOMO: Kiosk
2. **Действие** — B1.church: Find Person (по адресу электронной почты)
3. **Действие** — на ваш выбор:
   - *Если это учитывается как посещаемость* — Webhooks by Zapier POST на конечную точку B1 `/attendance/visits` (в приложении B1 для Zapier пока нет полноценного действия *Record Attendance*). [API-ключ](/docs/developer/api/api-keys) B1 передаётся в заголовке `Authorization: Bearer cak_…`.
   - *Если это учитывается как членство в группе* — B1.church: Add Group Member в группу «Currently Serving (Today)», а второй Zap позже в тот же день удаляет их через плановую очистку.

## Типичные рецепты {#common-recipes}

### Синхронизация групп по проектам {#per-project-group-sync}

- **Триггер** — VOMO: Participation (created)
- **Действие** — Filter by Zapier по id проекта, затем
- **Действие** — B1.church: Add Group Member в группу B1, название которой повторяет проект VOMO.

Когда проект VOMO заканчивается, очистите группу B1 вручную (или дополните это триггером *Participation deleted*, который удаляет их).

### Отправить SMS «спасибо, что записались» {#send-a-thanks-for-signing-up-text-via-sms}

Добавьте в тот же Zap цепочку VOMO Participation → Clearstream Send Text или Text In Church Send Message. У обоих есть нативные действия Zapier — см. [Clearstream](./clearstream.md) и [Text In Church](./text-in-church.md).

### Выявить отток {#detect-drop-off}

Запускайте ежедневный триггер *Schedule* в Zapier, который вызывает Find Organizer в VOMO для списка людей из B1, которые вступили в служебную команду в этом месяце. Если VOMO отвечает «not found», значит, они не активировали VOMO и им нужно напомнить.

## Ограничения и примечания {#limits--notes}

- **Ключом связи служит адрес электронной почты.** Данные VOMO содержат адрес электронной почты пользователя, но не id человека в B1. Жертвователи, которые используют разные адреса в каждой системе, создадут дубликаты.
- **Сегодня в приложении VOMO для Zapier нет действия «Add to Project».** Если нужно записывать людей из B1 в проекты VOMO, придётся отправлять POST в REST API VOMO из шага *Webhooks by Zapier*, а это собственная интеграция.
- **На бесплатных и младших тарифах VOMO Zapier может быть недоступен.** Уточните у поддержки VOMO, прежде чем обещать дату подключения.

## Устранение неполадок {#troubleshooting}

- **Триггер никогда не срабатывает** — мгновенным триггерам VOMO нужен действующий API-токен. Повторно протестируйте Zap; если токен был перевыпущен, переподключите VOMO.
- **B1 *Add Group Member* завершается с ошибкой** — группа в действии больше не существует. Выберите группу заново в выпадающем списке **Group** шага или откройте группу в B1Admin (**People > Groups**) и скопируйте id из конца её веб-адреса.
- **Дубликаты людей в B1 от одного волонтёра VOMO** — скорее всего, он записался под адресом электронной почты, отличным от того, что уже был в B1. Либо приведите адреса к единому виду, либо добавьте Zapier *Path*, который перед созданием также ищет по телефону.
