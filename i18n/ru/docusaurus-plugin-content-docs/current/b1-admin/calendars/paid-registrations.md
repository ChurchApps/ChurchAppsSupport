# Платные регистрации

<div class="article-intro">

Регистрация на событие может быть не просто подсчётом участников. Вы можете задать типы участников с разными ценами (например, «Взрослый» и «Ребёнок»), предложить дополнительные платные опции с собственными ценами и количеством, создать промокоды на скидку и принимать оплату при регистрации через уже подключённого в вашей церкви провайдера пожертвований. Когда событие заполняется, необязательный лист ожидания удерживает заинтересованных участников в очереди и автоматически продвигает их по мере освобождения мест.

</div>

<div class="prereqs">
<h4>Прежде чем начать</h4>

- Сначала включите регистрацию для события — см. [Создание календарей](creating-calendars#enabling-event-registration)
- Для приёма платежей в вашей церкви должен быть [настроен приём онлайн-пожертвований](../donations/online-giving-setup.md) (Stripe, PayPal или Kingdom Funding). Для бесплатных событий настройка платежей не требуется.

</div>

## Открытие настроек регистрации

1. В B1 Admin перейдите на страницу **Registrations** и откройте своё событие (или откройте его из календаря).
2. Карточка **Registration Settings** показывает основные параметры — **Enable Registration**, **Capacity**, **Registration Opens/Closes**, **Tags** и **Registration Questions**.
3. Под основными параметрами расположены три раскрывающихся блока: **Attendee Types**, **Selections** и **Discount Codes**.

## Типы участников

Типы участников позволяют устанавливать разные цены для разных категорий гостей — и отдельно ограничивать вместимость для каждой.

1. Разверните блок **Attendee Types** и нажмите **Add Type**.
2. Введите **Name** (например, «Adult», «Child», «Student»).
3. Задайте **Price**. Укажите 0 для бесплатного типа.
4. При необходимости задайте **Capacity** только для этого типа (например, всего 20 мест для типа «Child»). Оставьте поле пустым, если ограничения по этому типу не нужны.
5. Нажмите **Save**.

Во время регистрации каждый участник выбирает тип; типы, на которые закончились места, отображаются как **Sold out** и недоступны для выбора. В списке регистраций показывается тип каждого участника и текущее количество по каждому типу.

## Дополнительные опции (Selections)

Selections — это необязательные платные дополнения: футболки, варианты питания, улучшения программы.

1. Разверните блок **Selections** и нажмите **Add Selection**.
2. Введите **Name**, при желании **Description** и **Price** (0 отображается как «Free»).
3. При необходимости задайте **Capacity** (общее количество доступных мест по всем регистрациям) и **Max Qty** (максимальное количество, которое можно заказать в одной регистрации).
4. Нажмите **Save**.

Участники выбирают количество при регистрации, и итоги учитываются в общей вместимости, так что перепродажа мест исключена.

## Промокоды на скидку

1. Разверните блок **Discount Codes** и нажмите **Add Discount Code**.
2. Введите **Code**, который будут вводить участники.
3. Выберите **Type** — **Percent** (процент) или **Amount** (фиксированная сумма) — и укажите **Value**.
4. При необходимости ограничьте действие кода датами **Start Date** / **End Date**, минимальным количеством участников **Min Members** и **Max Uses**.
5. Нажмите **Save**.

Для каждого кода отображается счётчик **Uses**, чтобы видеть, как часто он был использован. Участники сразу получают обратную связь при применении кода — включая понятные сообщения о том, что срок действия кода истёк, ещё не начался или требуется больше участников.

## Лист ожидания

Включите **Enable Waitlist** на карточке Registration Settings. Когда событие заполняется:

- Новым регистрантам вместо отказа предлагается место в листе ожидания. Они проходят ту же регистрацию (оплата пропускается, пока они в листе ожидания).
- Когда кто-то отменяет регистрацию, самая старая запись в листе ожидания **автоматически продвигается** и получает письмо о том, что освободилось место. Если за ней остаётся задолженность, письмо содержит ссылку для завершения оплаты.
- Вы можете продвинуть кого-то вручную в любой момент действием **Promote** в строке листа ожидания — это полезно после увеличения вместимости события.

:::info
Продвинутые регистрации остаются в статусе *pending*, пока не будет оплачена задолженность; оплата (или её отсутствие) подтверждает регистрацию.
:::

## Список регистраций

Откройте событие со страницы Registrations, чтобы увидеть все регистрации. В таблице показаны **Name**, **Members**, **Type** (тип каждого участника), **Paid / Total** (с предупреждением о задолженности, если деньги ещё не внесены), **Status** и **Date**, а также чипы с количеством по каждому типу над таблицей.

- Нажмите значок сведений в строке, чтобы открыть диалог **Registration Details** — участники, выбранные опции, оплачено/задолженность и таблица **Payments** со всеми платежами (сумма, способ, дата).
- **Export CSV** загружает полный список со столбцами для участников, типов участников, дополнительных опций, оплачено/итого/задолженность, статуса и по одному столбцу на каждый вопрос регистрации.
- **Add Attendee** по-прежнему позволяет вручную зафиксировать оффлайн-регистрации.

:::info
Возвраты средств не обрабатываются внутри B1. Если нужно вернуть деньги за отменённую платную регистрацию, оформите возврат в панели вашего провайдера платежей (например, Stripe).
:::

## Как работает оплата

Платежи проходят через тот же платёжный шлюз, который ваша церковь уже использует для пожертвований — данные карты передаются напрямую провайдеру и никогда не попадают на серверы B1. Цены всегда рассчитываются на сервере на основе настроенных вами типов участников, дополнительных опций и промокодов, поэтому участник не может изменить итоговую сумму. Авторизованные участники могут оплатить сохранённой картой; гости вводят данные карты при оформлении.
