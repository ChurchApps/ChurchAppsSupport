# Платные регистрации

<div class="article-intro">

Регистрация на события может быть больше, чем простой подсчёт участников. Вы можете задать типы участников с ценами (например, взрослый и ребёнок), предложить необязательные дополнения со своими ценами и количеством, создавать промокоды и принимать оплату при регистрации через существующего платёжного провайдера вашей церкви. Когда мест не остаётся, необязательный лист ожидания сохраняет очерёдность для заинтересованных участников и автоматически переводит их на освободившиеся места.

## Открытие настроек регистрации

1. В B1 Admin откройте [меню Jump](../introduction.md#getting-around-with-the-jump-menu) (строка поиска в верхнем левом углу), выберите **Calendars > Registrations** и откройте своё событие (или откройте его из календаря).
2. Карточка **Registration Settings** показывает основные параметры -- **Enable Registration**, **Capacity**, **Registration Opens/Closes**, **Tags** и **Registration Questions**.
3. Ниже основных параметров расположены три раскрывающихся блока: **Attendee Types**, **Selections** и **Discount Codes**.

## Типы участников

Типы участников позволяют назначать разные цены для разных категорий участников и ограничивать количество мест в каждой категории отдельно.

1. Раскройте блок **Attendee Types** и нажмите **Add Type**.
2. Введите **Name** (например, «Adult», «Child», «Student»).
3. Укажите **Price**. Используйте 0 для бесплатного типа.
4. При желании задайте **Capacity** только для этого типа (например, всего 20 мест для детей). Оставьте поле пустым, если ограничения для типа нет.
5. Нажмите **Save**.

Во время регистрации каждый участник выбирает тип; распроданные типы отображаются как **Sold out** и не могут быть выбраны. В списке участников показаны тип каждого участника и текущие счётчики по типам.

## Дополнения

Selections -- это необязательные платные дополнения: футболки, пакеты питания, улучшения программы.

1. Раскройте блок **Selections** и нажмите **Add Selection**.
2. Введите **Name**, необязательное **Description** и **Price** (0 отображается как «Free»).
3. При желании задайте **Capacity** (общее количество доступных единиц по всем регистрациям) и **Max Qty** (максимальное количество, которое может заказать одна регистрация).
4. Нажмите **Save**.

Участники выбирают количество при записи, а итоговые суммы учитываются в пределах вместимости, так что продажа сверх лимита невозможна.

## Промокоды

1. Раскройте блок **Discount Codes** и нажмите **Add Discount Code**.
2. Введите **Code**, который будут вводить участники.
3. Выберите **Type** -- **Percent** (процент) или **Amount** (сумма) -- и укажите **Value**.
4. При желании ограничьте действие кода полями **Start Date** / **End Date**, **Min Members** (минимальное количество участников в регистрации) и **Max Uses**.
5. Нажмите **Save**.

Для каждого кода отображается счётчик **Uses**, чтобы вы видели, как часто им воспользовались. Участники сразу получают отклик при применении кода, включая понятные сообщения, если срок кода истёк, он ещё не начался или требуется больше участников.

## Лист ожидания {#waitlist}

Включите **Enable Waitlist** в карточке Registration Settings. Когда событие достигает вместимости:

- Новым участникам предлагается место в листе ожидания вместо отказа. Они проходят ту же процедуру записи (оплата в листе ожидания пропускается).
- Когда кто-то отменяет регистрацию, самая ранняя регистрация из листа ожидания **переводится автоматически**, и участник получает письмо о том, что освободилось место. Если у него есть непогашенный баланс, в письме есть ссылка на [My Registrations](../../b1-church/events/my-registrations) на сайте B1 вашей церкви, где он может произвести оплату.
- Вы можете перевести участника вручную в любое время, используя действие **Promote** в строке со статусом ожидания -- это полезно, например, после увеличения вместимости события.

:::info
Переведённые регистрации остаются *pending* (в ожидании), пока не оплачен баланс; после оплаты (или если платить нечего) они подтверждаются.
:::

## Список участников {#the-registration-roster}

Откройте событие на странице Registrations, чтобы увидеть все регистрации. В заголовке карточки указано, сколько регистраций занимают место относительно вместимости (например, *Registrations (18 / 20)*). Учитываются только регистрации со статусом pending и confirmed; если есть участники в листе ожидания, к заголовку добавляется их количество (например, *· 3 waitlisted*), и то же число отображается под индикатором вместимости. В таблице показаны **Name**, **Members**, **Type** (тип каждого участника), **Paid / Total** (с предупреждением о балансе, если деньги ещё не внесены), **Status** и **Date**, а над таблицей -- счётчики по типам участников.

- Нажмите значок сведений в строке, чтобы открыть диалог **Registration Details** -- участники, дополнения, оплачено/баланс и таблица **Payments** со всеми списаниями (сумма, способ оплаты, дата).
- **Export CSV** скачивает полный список с колонками для участников, типов, дополнений, оплачено/всего/баланс, статуса и отдельной колонкой для каждого вопроса регистрации.
- **Add Attendee** записывает офлайн или телефонную регистрацию для любого человека в вашей церкви. Выберите человека и, для платного события, его тип участника. С его карты ничего не списывается: платная регистрация сохраняется как **pending** с полной суммой к оплате. Если в вашей церкви есть онлайн-пожертвования, человек может оплатить через [My Registrations](../../b1-church/events/my-registrations); в противном случае деньги принимаются лично. Для добавления участников нужно право Registrations Edit.

:::info
Возвраты в B1 не обрабатываются. Если нужно вернуть деньги за отменённую платную регистрацию, оформите возврат в панели вашего платёжного провайдера (например, Stripe).
:::

## Как проходит оплата

Платежи проходят через тот же платёжный шлюз, который ваша церковь уже использует для пожертвований. Данные банковской карты передаются напрямую провайдеру и никогда не попадают на серверы B1. Цены всегда рассчитываются на сервере по настроенным типам, дополнениям и промокодам, поэтому участник не может изменить итоговую сумму. Авторизованные участники могут платить сохранённой картой. Гости вводят данные карты на этапе оплаты и должны отметить **I'm not a robot**, прежде чем платить.

### Церкви без онлайн-пожертвований {#churches-without-online-giving}

Если у вашей церкви не настроен платёжный провайдер для пожертвований, платные события всё равно могут принимать регистрации. На шаге оплаты участникам сообщается, что онлайн-оплата недоступна и что они могут заплатить церкви напрямую, а кнопка **Register and Pay Later** сохраняет регистрацию. Она сохраняется как **pending** с полной суммой к оплате и отображается в списке участников с предупреждением о балансе. Собирайте деньги так, как ваша церковь обычно это делает.

:::info
B1 не может отметить офлайн-платёж как полученный. Задолженность остаётся в списке участников и на карточке [My Registrations](../../b1-church/events/my-registrations) участника даже после того, как вы получили деньги, поэтому ведите собственный учёт того, кто уже заплатил.
:::
