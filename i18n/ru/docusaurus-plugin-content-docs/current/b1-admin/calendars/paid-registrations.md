# Платные регистрации

<div class="article-intro">

Регистрация на событие может выходить за пределы простого подсчета участников. Вы можете определить типы участников с ценами (например, Взрослый и Ребенок), предложить дополнительные надстройки со своими ценами и количественными, создать коды скидок и собирать платежи при регистрации через существующего провайдера благотворительности вашей церкви. Когда событие заполняется, дополнительный список ожидания держит заинтересованных членов в очереди и автоматически продвигает их, когда открываются места.

</div>

<div class="prereqs">
<h4>Перед началом работы</h4>

- Включите регистрацию на событие первым -- см. [Creating Calendars](creating-calendars#enabling-event-registration)
- Для сбора платежей вашей церкви нужна [online giving configured](../donations/online-giving-setup.md) (Stripe, PayPal, или Kingdom Funding). Бесплатные события не нуждаются в настройке благотворительности.

</div>

## Открытие параметров регистрации

1. В B1 Admin перейдите на страницу **Registrations** и откройте ваше событие (или откройте событие из его календаря).
2. Карточка **Registration Settings** показывает основы -- **Enable Registration**, **Capacity**, **Registration Opens/Closes**, **Tags**, и **Registration Questions**.
3. Ниже основ находятся три аккордеона: **Attendee Types**, **Selections**, и **Discount Codes**.

## Типы участников

Типы участников позволяют вам взимать разные цены для разных видов участников -- и ограничивать каждый отдельно.

1. Разверните аккордеон **Attendee Types** и нажмите **Add Type**.
2. Введите **Name** (например, "Взрослый", "Ребенок", "Студент").
3. Установите **Price**. Используйте 0 для бесплатного типа.
4. При необходимости установите **Capacity** только для этого типа (например, только 20 мест Ребенок). Оставьте пусто для отсутствия лимита для каждого типа.
5. Нажмите **Save**.

Во время регистрации каждый участник выбирает тип; распроданные типы показываются как **Sold out** и не могут быть выбраны. Реестр показывает тип каждого участника и текущие подсчеты для каждого типа.

## Выборки

Selections являются дополнительными платными надстройками -- футболки, планы питания, обновления деятельности.

1. Разверните аккордеон **Selections** и нажмите **Add Selection**.
2. Введите **Name**, дополнительное **Description**, и **Price** (0 показывается как "Free").
3. При необходимости установите **Capacity** (всего доступно для всех регистраций) и **Max Qty** (максимум одна регистрация может заказать).
4. Нажмите **Save**.

Регистранты выбирают количество во время регистрации, и итоги считаются против мощности, поэтому вы никогда не переселяете.

## Коды скидок

1. Разверните аккордеон **Discount Codes** и нажмите **Add Discount Code**.
2. Введите **Code** который будут вводить регистранты.
3. Выберите **Type** -- **Percent** или **Amount** -- и его **Value**.
4. При необходимости ограничьте код **Start Date** / **End Date**, **Min Members** (минимальное количество участников при регистрации), и **Max Uses**.
5. Нажмите **Save**.

Каждый код показывает подсчет **Uses** чтобы вы видели, как часто он был использован. Регистранты получают мгновенную обратную связь, когда они применяют код -- включая четкие сообщения, когда код истек, еще не начался, или требует больше участников.

## Список ожидания

Включите **Enable Waitlist** в карточке Registration Settings. Когда событие достигает мощности:

- Новые регистранты получают предложение место в списке ожидания вместо того, чтобы быть отклоненными. Они завершают ту же регистрацию (платежи пропускаются при попадании в список ожидания).
- Когда кто-то отменяет регистрацию, самая старая регистрация в списке ожидания **promoted automatically** и получает письмо, что место открылось. Если они задолжены баланс, письмо ссылает их на завершение платежа.
- Вы можете вручную продвинуть кого-нибудь в любое время с действием **Promote** на строке в списке ожидания -- полезно после повышения мощности события.

:::info
Продвинутые регистрации остаются *pending* пока не будет оплачен любой баланс; оплата (или отсутствие необходимости платить) подтверждает их.
:::

## Реестр регистраций

Откройте событие со страницы Registrations, чтобы увидеть каждую регистрацию. Таблица показывает **Name**, **Members**, **Type** (тип каждого участника), **Paid / Total** (с предупреждением баланса, когда деньги еще должны быть оплачены), **Status**, и **Date**, плюс фишки подсчета по типам выше таблицы.

- Нажмите значок деталей строки, чтобы открыть диалоговое окно **Registration Details** -- члены, selections, paid/balance, и таблица **Payments** со списком каждого платежа (сумма, метод, дата).
- **Export CSV** загружает полный реестр со столбцами для членов, типов участников, selections, paid/total/balance, status, и один столбец на каждый вопрос регистрации.
- **Add Attendee** все еще позволяет вам записать автономные регистрации вручную.

:::info
Возвраты не обрабатываются внутри B1. Если вам нужно вернуть отмененную платежную регистрацию, выдайте возврат из панели вашего провайдера благотворительности (например, Stripe).
:::

## Как работает платеж

Платежи проходят через тот же шлюз благотворительности, который ваша церковь уже использует для пожертвований -- детали карты идут прямо к провайдеру и никогда не касаются серверов B1. Цены всегда вычисляются на сервере из ваших настроенных типов, selections, и кодов скидок, поэтому регистрант не может подделать итоговую сумму. Залогированные члены могут платить сохраненной картой; гости вводят карту при оформлении.
