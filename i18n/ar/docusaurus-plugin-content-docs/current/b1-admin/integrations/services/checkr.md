# Checkr

<div class="article-intro">

[Checkr](https://checkr.com) تُجري عمليات الفحص الخلفي للموظفين والمتطوعين، وهي حاجة شبه عامة لأي كنيسة تدير برنامجًا للأطفال أو الشباب. لا يحتوي B1 على **ميزة فحص خلفي مدمجة**؛ فطلب الفحوصات وتتبع النتائج والامتثال لإجراءات الفحص كلها تتم داخل Checkr، والوصفة أدناه تقتصر على ربط أحداث B1 بالخدمة. لا يوفر Checkr تطبيقًا على Zapier، لكن [تكامل Checkr في Make.com](https://www.make.com/en/integrations/checkr) موثّق ويوفر الإجراءات اللازمة لبدء فحص من حدث في B1.

</div>

<div class="prereqs">
<h4>قبل أن تبدأ</h4>

- حساب في [Checkr](https://checkr.com) مع إمكانية الوصول إلى واجهة برمجة التطبيقات (API) وباقة فحص واحدة على الأقل مُعدّة
- حساب في [Make](https://www.make.com)
- مستخدم B1Admin يملك صلاحية **تعديل الإعدادات** (Edit Settings)

</div>

## ما يمكنك ربطه

يوفر تطبيق Checkr في Make مُشغِّلًا واحدًا و6 إجراءات:

| الاتجاه | المُشغِّل في B1 / Make | الإجراء |
|---|---|---|
| B1 → Checkr | B1 `group.member.added` (مُصفّى إلى مجموعة متطوعين) | Checkr: Create Candidate → Create Background Check Invitation |
| Checkr → B1 | Checkr webhook (حدث الدعوة / التقرير) | B1: تحديث سجل الشخص (مثلًا وسم "Checkr cleared") |

إجراءات Checkr في Make: Create Candidate، وCreate Background Check Invitation، وGet Candidate، وGet Report، وGet Report's ETA، وGet an Invitation. إضافةً إلى 4 وحدات بحث.

## الإعداد

### 1. إنشاء مفتاح API في B1

**الإعدادات ← المطوّر ← مفاتيح API ← مفتاح API جديد**:

- `settings:write` — لمُشغِّل الـ webhook
- `people:read` — للبحث عن اسم الشخص وبريده الإلكتروني عند بدء الفحص
- (اختياري) `people:write` إذا أردت كتابة حالة التقرير مرة أخرى إلى حقل مخصص أو وسم

### 2. بناء سيناريو "بدء فحص عند تسجيل متطوع" في Make

1. **المُشغِّل** — B1.church: Watch Events (`group.member.added`).
2. **المرشِّح** — استمر فقط إذا تطابق `data.groupId` مع مجموعة "متطوعي الأطفال" (أو ما يعادلها).
3. **الإجراء** — B1.church: Find Person (باستخدام `data.personId`) للحصول على البريد الإلكتروني والاسم الأول واسم العائلة.
4. **الإجراء** — Checkr: Create Candidate. طابق الاسم الأول واسم العائلة والبريد من الخطوة 3.
5. **الإجراء** — Checkr: Create Background Check Invitation. اربط معرّف المرشح الجديد من الخطوة 4 بالحقل *candidate_id*. اختر باقة الفحص (مثل `tasker_standard` أو أي باقة يعرضها حسابك).
6. (اختياري) **الإجراء** — Slack: أبلغ منسّق الخدمة الآمنة لديك ببدء الفحص.

فعّل السيناريو. يتلقى المتطوعون الجدد في المجموعة المستهدفة دعوة Checkr تلقائية عبر البريد الإلكتروني، فيكملونها على هواتفهم أو حواسيبهم المحمولة، ثم يُجري Checkr الفحص.

### 3. (اختياري) استقبال التقرير

1. **المُشغِّل** — Checkr: Watch Events (webhook). يسجّل Make عنوان الـ webhook في Checkr عند التفعيل.
2. **المرشِّح** — استمر فقط إذا كان `event_type = report.completed`.
3. **الإجراء** — Checkr: Get Report (باستخدام معرّف التقرير من الـ webhook).
4. **الإجراء** — B1.church: Find Person (باستخدام بريد المرشح الإلكتروني).
5. **إجراء شرطي** — Slack / Email: أبلغ المنسّق بالحالة `clear` / `consider` / `suspended`.

ملاحظة: لا يحتوي B1 حاليًا على حقل مدمج لـ"حالة الفحص الخلفي". الخيارات العملية هي (أ) نشر النتيجة في قناة Slack خاصة للمراجعة، أو (ب) كتابتها في Google Sheet للتدقيق، أو (ج) إضافة الشخص إلى مجموعة "المتطوعون المعتمدون" في B1 عند الحالة `clear`.

## وصفات شائعة

### إعادة فحص المتطوعين كل عامين

أضف إلى ما سبق مُشغِّل جدولة في Make:

- **المُشغِّل** — Make: Schedule (شهريًا)
- **الإجراء** — B1.church: List Group Members لمجموعة "المتطوعون المعتمدون"
- **الإجراء** — تصفية في Make: تاريخ الاعتماد أقدم من 22 شهرًا
- **الإجراء** — Checkr: Create Background Check Invitation (نفس التدفق الأولي)

### حجب الوصول في المرحلة الأولى حتى يكتمل الفحص

إذا كانت كنيستك تستخدم عضوية مجموعات B1 لتقييد الوصول (مثلًا لا يظهر في جداول الخدمة إلا أعضاء مجموعة "المعتمدين")، فأبقِ المتطوعين الجدد في مجموعة انتظار حتى يُحدّث حدث `report.completed` من Checkr حالتهم.

## القيود والملاحظات

- **Checkr متاح في الولايات المتحدة فقط** لمعظم باقات الفحص. ستحتاج الكنائس في أستراليا والمملكة المتحدة وكندا إلى بديل آخر.
- **التسعير** يكون لكل فحص، فكل Create Invitation في Make يستهلك فحصًا حقيقيًا. اختبر أولًا في بيئة الاختبار (sandbox) لدى Checkr. يستخدم تطبيق Checkr في Make بيانات الاعتماد التي تمررها في الاتصال، لذا تبديل بيانات الاعتماد ينقلك بين البيئة التجريبية والإنتاج.
- **الوصول إلى واجهة API مرتبط بالباقة** لدى Checkr. قد تكون الحسابات الصغيرة على مستوى واجهة مستخدم فقط؛ تواصل مع Checkr لتفعيل API.

## استكشاف الأخطاء وإصلاحها

- **يفشل Create Candidate بالخطأ `403`**: رمز Checkr API للقراءة فقط أو لا يملك صلاحيات الحساب المناسبة. أعد إصداره من لوحة Checkr بصلاحية الكتابة.
- **لا تصل الدعوة أبدًا**: تحقق من بريد المرشح في الخطوة 3؛ قد يكون حقل البريد الإلكتروني لدى B1 فارغًا لذلك الشخص. أضف مرشّحًا يشترط وجود بريد إلكتروني قبل خطوة Checkr.
- **مُشغِّل الـ webhook لا يعمل**: قد يفشل تسجيل الـ webhook في Checkr بصمت إذا لم يكن حساب Make لديك على باقة مدفوعة تدعم الـ webhooks الصادرة. تحقق في صفحة *Webhooks* في لوحة Checkr من إدراج عنوان Make.
