# Make

<div class="article-intro">

[Make](https://www.make.com) (المعروفة سابقًا باسم Integromat) منصة لأتمتة سير العمل بواجهة مرئية. تشبه Zapier في الفكرة، لكنها توفر منطقًا أكثر مرونة وتكلفة أقل على نطاق واسع. يتيح تطبيق Make الرسمي من B1.church إنشاء "سيناريوهات" تستجيب فورًا لأحداث B1 وتكتب السجلات مرة أخرى إلى B1.

</div>

<div class="prereqs">
<h4>قبل أن تبدأ</h4>

- حساب على [Make](https://www.make.com) (الخطة المجانية تكفي لسير العمل الصغيرة)
- مسؤول كنيسة لديه صلاحية **Edit Settings** في B1Admin
- فكرة تقريبية عن السيناريو الذي تريد إنشاءه

## الوحدات

| النوع | الوظيفة | حدث B1 / نقطة النهاية |
|---|---|---|
| **Instant Trigger** | Watch Events | أي حدث B1 مشترك فيه (`person.created`, `donation.created`, …) |
| **Action** | Create Person | يضيف شخصًا جديدًا |
| **Action** | Add Donation | يسجّل تبرعًا |
| **Action** | Add Group Member | يضيف شخصًا إلى مجموعة |
| **Search** | Search People | يبحث عن أشخاص بالاسم أو البريد الإلكتروني |

يتيح المشغّل الفوري اختيار الحدث الذي تريد الاستماع إليه. وحدة مشغّل واحدة لكل سيناريو، تُهيَّأ لكل حدث على حدة.

## الإعداد

### 1. إنشاء مفتاح API في B1

1. في B1Admin، انتقل إلى **Settings → Developer → API Keys**.
2. انقر على **New API Key**، وسمّه "Make"، ثم امنح النطاقات (scopes) التي تحتاجها.
3. **أدرِج `settings:write`** إذا كان أي من سيناريوهاتك يستخدم المشغّل الفوري، لأن Make يسجّل خطاف ويب (webhook) نيابةً عنك عند تفعيل السيناريو.
4. امنح أيضًا النطاقات التي تحتاجها وحدات الإجراءات، مثل `donations:write` لوحدة Add Donation.
5. احفظ المفتاح وانسخ المفتاح `cak_…`.

### 2. تثبيت الاتصال

1. في Make، أنشئ سيناريو جديدًا وأفلِت وحدة المشغّل **B1.church** على اللوحة.
2. عند الظهور، اختر **Create a connection**. الصق مفتاح API في حقل *API Key*، واترك *API Base URL* كما هو `https://api.churchapps.org` (إلا إذا كنت تختبر على بيئة staging).
3. انقر **Save**. يختبر Make المفتاح بقراءة ملف كنيستك الشخصي.

يُحفظ الاتصال في حساب Make الخاص بك ويُعاد استخدامه عبر السيناريوهات.

### 3. تهيئة المشغّل

1. افتح إعدادات وحدة **Watch Events**.
2. اختر الحدث المطلوب، مثل `donation.created`.
3. احفظ. يولّد Make عنوان URL فريدًا لخطاف الويب ويخزّنه داخليًا.

### 4. إضافة الوحدات اللاحقة

أفلِت أيًا من مئات وحدات التطبيقات في Make على اللوحة، مثل Mailchimp أو Google Sheets أو Slack أو HubSpot أو نقطة نهاية HTTP خاصة بك. اربط مخرجات المشغّل (`event`, `churchId`, `data.id`, `data.amount`, …) بحقول الإدخال لديها. تتيح وحدات flatten وiterator وrouter وaggregator في Make بناء تدفقات متفرعة ومتوازية يصعب تنفيذها في Zapier.

### 5. تشغيل السيناريو

فعّل **Active** في رأس السيناريو. عندها يرسل Make طلب `POST /membership/webhooks` إلى B1 لتسجيل العنوان. ومن تلك اللحظة، تمر كل أحداث B1 المطابقة عبر السيناريو في الوقت الفعلي.

يؤدي إيقاف السيناريو إلى إرسال طلب `DELETE /membership/webhooks/{id}`، حتى لا تبقى اشتراكات يتيمة.

## وصفات شائعة

### مزامنة التبرعات إلى جدول Google لمراجعة المالية

- **المشغّل** — B1: Watch Events (`donation.created`)
- **الإجراء** — Google Sheets: Add a Row. اربط `data.donationDate` و`data.amount` و`data.personId` و`data.method` و`data.batchId` بأعمدة الجدول.

### إشعار Slack شرطي حسب مبلغ التبرع

- **المشغّل** — B1: Watch Events (`donation.created`)
- **Router**:
  - الفرع A — Filter: `data.amount >= 1000` → Slack: نشر في `#major-gifts`
  - الفرع B — الافتراضي → Slack: نشر في `#donations`

### شخص جديد → CRM + بريد ترحيب + Slack

- **المشغّل** — B1: Watch Events (`person.created`)
- **الإجراء** — HubSpot: Create Contact
- **الإجراء** — Mailgun: Send Welcome Email
- **الإجراء** — Slack: إشعار `#new-people` (بالتوازي، باستخدام router في Make)

## كيف يعمل المشغّل الفوري

المشغّل الفوري مدعوم بخطاف ويب وليس بالاستطلاع (polling). عند تفعيله، يرسل Make طلب `POST /membership/webhooks` مع عنوان URL الذي ولّده والحدث الذي اخترته. عندما يقع الحدث في B1، يرسل B1 البيانات إلى عنوان Make، وينفّذ سيناريوك خلال ثوانٍ. إلغاء تفعيل السيناريو يزيل خطاف الويب.

يعمل المشغّل فقط للأحداث التي تقع **أثناء تفعيل السيناريو**. لا توجد عملية استرداد للأحداث السابقة.

## حدود وملاحظات

- **حدث واحد لكل وحدة Watch Events.** للاستماع إلى عدة أحداث في سيناريو واحد، أفلِت وحدات مشغّل متعددة في سيناريوهات منفصلة (أو استخدم وحدة واحدة مع قائمة الأحداث الموحّدة، انظر أدناه).
- **التحقق من التوقيع غير متاح.** لا يمرر Make الترويسة `X-B1-Signature` إلى السيناريو، وحدود الثقة هي عنوان خطاف الويب الخاص بكل سيناريو، وهو عنوان لا يمكن تخمينه. هذه ممارسة معتادة في Make. إذا احتجت إلى فحوصات توقيع صريحة، فابنِ تكاملًا مخصصًا باستخدام [SDK](/docs/developer/api/webhooks#sdk-support) بدلًا من ذلك.
- **عدد العمليات.** يُحتسب كل استدعاء API من وحدة إجراء ضمن حصة عمليات Make لديك، ولا يؤثر على أي شيء في جانب B1.

## استكشاف الأخطاء وإصلاحها

- **فشل اختبار الاتصال:** غالبًا ما يكون السبب خطأً مطبعيًا في مفتاح API. أعد نسخه من B1Admin (المفتاح الكامل يُعرض مرة واحدة فقط، وإذا فقدته فأنشئ مفتاحًا جديدًا).
- **لا تُفعَّل وحدة المشغّل:** تحقق من **Settings → Developer → Webhooks** في B1Admin. إذا لم تجد صفًا باسم "Make — &lt;event&gt;" بعد تفعيل السيناريو، فالمفتاح يفتقر إلى `settings:write`. حدّث المفتاح وأعد التفعيل.
- **يرجع الإجراء `403 Forbidden`:** مفتاح API لا يملك النطاق المطلوب لتلك نقطة النهاية. مثلًا، تحتاج Add Donation إلى `donations:write`. حدّث المفتاح في B1Admin وأعد الاختبار.

## تخصيص التطبيق

تطبيق Make من B1.church مفتوح المصدر، وتعيش تعريفات JSON في مستودع `B1Integrations/Make/`. إذا احتجت إلى وحدة غير موجودة (مثلًا إجراء جديد لنقطة نهاية لم نغطّها بعد)، فافتح issue أو PR هناك.
