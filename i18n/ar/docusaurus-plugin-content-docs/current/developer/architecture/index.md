# البنية المعمارية

<div class="article-intro">

تُعدّ هذه الصفحات خرائط شاملة للأنظمة عبر المستودعات، إذ توثّق كيفية عمل نظام أساسي من أنظمة ChurchApps من البداية إلى النهاية، عبر التطبيقات ووحدات واجهات Api والمكتبات المشتركة، بدلاً من توثيق كيفية إعداد مشروع منفرد. اقرأها قبل تغيير سلوك أي نظام. واقرأ [الإعداد](../setup/index.md) لتشغيل مشروع، و[قسم واجهة Api](../api/index.md) للرجوع إلى مرجع نقاط النهاية.

</div>

## المنظومة في لمحة

تضم ChurchApps نحو 20 مستودعاً مستقلاً (وليس مستودعاً أحادياً واحداً). تتصل تطبيقات العميل بمجموعة صغيرة من واجهات الخلفية عبر HTTPS وWebSocket، وتتشارك الشيفرة عبر حزم npm المنشورة ضمن النطاق `@churchapps`.

```
┌────────────────────────────────┐            ┌──────────────────────────────────────────────┐
│  Clients                       │            │  Api — core modular monolith (AWS Lambda)    │
│                                │            │                                              │
│  B1Admin    staff dashboard    │   HTTPS    │   membership    attendance    content        │
│  B1App      member portal +    │ ─────────▶ │   giving        messaging     doing          │
│             church websites    │            │                                              │
│  B1Checkin  check-in kiosk     │ ◀───WS───▶ │   one MySQL database per module (6 total)    │
│  B1Mobile   (maintenance-only) │            └──────────────────────────────────────────────┘
│  FreePlay   TV content player  │            ┌──────────────────────────────────────────────┐
└───────────────┬────────────────┘            │  LessonsApi — Lessons.church backend         │
                │                             └──────────────────────────────────────────────┘
                │  shared code via npm (@churchapps/*)
                ▼
   helpers (cross-app interfaces) · apphelper (React components) · apihelper (Express/server utilities)
```

تحكم قاعدتان بنيويتان كل ما يُوثَّق في هذا القسم:

1. **عزل الوحدات.** تملك كل وحدة من وحدات Api قاعدة بياناتها وجداولها، ولا تصل الوحدات الأخرى والتطبيقات إلى بياناتها إلا عبر نقاط نهاية REST الخاصة بها. انظر [بنية الوحدة](../api/module-structure.md).
2. **الشيفرة المشتركة تُنشر حزمَ npm.** لا تستورد التطبيقات شيفرة مصدر بعضها بعضاً أبداً، وأي شيء يُعاد استخدامه يعبر حدود المستودعات عبر `@churchapps/helpers` أو `@churchapps/apphelper` أو `@churchapps/apihelper`. انظر [المكتبات المشتركة](../shared-libraries/index.md).

## خرائط الأنظمة

| الصفحة | ما تغطيه | النطاق |
|------|----------------|-------|
| [الإشعارات والتذكيرات](./notifications.md) | كيف يُبلغ أي شيء شخصاً بشيء ما: بوابتا الإرسال، وسلسلة تصعيد القنوات، ومحرك التذكيرات | Api (messaging)، وB1Admin، وB1App |
| [البنية الفورية](../realtime.md) | إطار تسليم WebSocket الذي تقوم عليه المحادثات والحضور والتسليم داخل التطبيق | Api (messaging)، وجميع تطبيقات الويب |
| [إشعارات الويب Push](../web-push.md) | قناة Push في المتصفح: مفاتيح VAPID، وتخزين الاشتراكات، والتسليم | Api (messaging)، وجميع تطبيقات الويب |
| [العطاء](./giving.md) | مزودو الدفع وبواباته، وتدفقات التبرع، والصناديق والدفعات، وwebhooks البوابات | Api (giving)، وapphelper، وB1App، وB1Admin |
| [تسجيلات الفعاليات](./registrations.md) | نموذج التجارة في التسجيل: أنواع المشاركين، والاختيارات، ورموز الخصم، والمدفوعات عبر بوابة العطاء، وقائمة الانتظار | Api (content + giving)، وB1App، وB1Admin |
| [تسجيل الوصول](./check-ins.md) | تسجيل الوصول عبر الكشك والذاتي، ونموذج بيانات الحضور، وتوجيه الغرف، وطبقة سلامة الأطفال، وطباعة الملصقات | B1Checkin، وB1App، وB1Admin، وApi (attendance + membership) |
| [منشئ المواقع](./website-builder.md) | شجرة الصفحات والأقسام والعناصر، وعقد أنواع العناصر ومحولات عرضها، والمدونة، والصفحات المقيّدة بالوصول، وتحسين محركات البحث، وتوليد الذكاء الاصطناعي | Api (content)، وAskApi، وhelpers/apphelper، وB1Admin، وB1App |
| [التوجيه بين المواقع وتعدد المواقع](./websites.md) | كيف يُحلّ الطلب إلى كنيسة وموقع محدد، ونموذج البيانات متعدد المواقع `siteId`، وطبقة الحواف Caddy للنطاقات المخصصة | B1App، وApi (membership + content)، وB1Admin |
| [التكاملات](./integrations.md) | سطح التوسعة: OAuth، ومفاتيح API، وwebhooks، ومزودو المحتوى، وMCP | Api، والمكتبات المشتركة، والتطبيقات الخارجية |
| [سجل التدقيق والدفعات القابلة للتراجع](./audit-log.md) | تدقيق مفعّل افتراضياً لكل عملية تعديل عند نقطة التحكم في المتحكّم، وطبقة الدفعات التي تجعل الاستيراد والإجراءات الجماعية قابلة للتراجع | Api (جميع الوحدات)، وB1Admin، وB1Transfer |
| [MinistryStuff](./ministrystuff.md) | خدمة التخزين المدفوعة وأرصدة الرسائل النصية: هوية JWT المشتركة، ومصادقة الخادم إلى الخادم بمفتاح الخدمة، ونقاط ربط مزودي الرسائل النصية والتخزين، وفوترة Stripe | MinistryStuffApi، وMinistryStuffWeb، وApi (content + messaging)، وحزم texting/apihelper، وB1Admin |
| [التخزين بمزودك الخاص](./byos-storage.md) | تربط الكنائس Google Drive أو Dropbox أو OneDrive أو حاوية متوافقة مع S3 للرفع بعد حد 100 ميغابايت المجاني: ربط OAuth، وأشكال الرفع لكل مزود، وإعادة التوجيه العامة للتنزيل | Api (content + membership)، وحزم helpers/apphelper، وB1Admin، وB1App |
| [مشاعات المحتوى](./commons.md) | طبقة الأصول والتقديمات المشتركة التي تقوم عليها المحتويات التي ينشئها المستخدمون عبر المنتجات، وقائمة الإشراف الواحدة المخصصة للموظفين في Server Admin بتطبيق B1Admin | Api (وحدة commons)، وB1Admin، وWorshipCommons، وLessons.church، وFreeShow |

:::tip
عندما يغيّر تعديلٌ طريقةَ عمل أحد هذه الأنظمة، لا صفحةً داخل تطبيق واحد فحسب، ينبغي تحديث خريطة النظام المقابلة هنا في العمل نفسه. فذلك يحافظ على موثوقية هذا القسم بوصفه المرجع الأول للمساهمين الجدد.
:::
