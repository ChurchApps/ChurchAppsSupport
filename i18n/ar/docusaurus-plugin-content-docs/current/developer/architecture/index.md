# البنية المعمارية

<div class="article-intro">

هذه الصفحات هي خرائط أنظمة عابرة للمستودعات: فهي توثّق كيفية عمل نظام أساسي من أنظمة ChurchApps من الطرف إلى الطرف، عبر التطبيقات ووحدات API والمكتبات المشتركة، بدلاً من توضيح كيفية إعداد مشروع واحد بعينه. اقرأها قبل تغيير سلوك أي نظام، واقرأ [الإعداد](../setup/index.md) لتشغيل أحد المشاريع، و[قسم API](../api/index.md) للاطلاع على المرجع الخاص بنقاط النهاية.

</div>

## نظرة عامة على المنظومة

يتألف ChurchApps من نحو 20 مستودعاً مستقلاً (وليس مستودعاً أحادياً). تتواصل تطبيقات العميل مع مجموعة صغيرة من واجهات API الخلفية عبر HTTPS وWebSocket، وتتشارك الشيفرة البرمجية عبر حزم npm المنشورة ضمن النطاق `@churchapps`.

```
┌────────────────────────────────┐            ┌──────────────────────────────────────────────┐
│  Clients                       │            │  Api — core modular monolith (AWS Lambda)    │
│                                │            │                                              │
│  B1Admin    staff dashboard    │   HTTPS    │   membership    attendance    content        │
│  B1App      member portal +    │ ─────────▶ │   giving        messaging     doing          │
│             church websites    │            │                                              │
│  B1Checkin  check-in kiosk     │ ◀───WS───▶ │   one MySQL database per module (6 total)    │
│                                │            └──────────────────────────────────────────────┘
│  FreePlay   TV content player  │            ┌──────────────────────────────────────────────┐
└───────────────┬────────────────┘            │  LessonsApi — Lessons.church backend         │
                │                             └──────────────────────────────────────────────┘
                │  shared code via npm (@churchapps/*)
                ▼
   helpers (cross-app interfaces) · apphelper (React components) · apihelper (Express/server utilities)
```

هناك قاعدتان بنيويتان تشكّلان كل ما يُوثَّق في هذا القسم:

1. **الوحدات معزولة.** تمتلك كل وحدة من وحدات Api قاعدة بياناتها وجداولها، ولا تصل الوحدات الأخرى والتطبيقات إلى بياناتها إلا من خلال نقاط نهاية REST الخاصة بها. انظر [بنية الوحدة](../api/module-structure.md).
2. **الشيفرة المشتركة تُنشر كحزم npm.** لا تستورد التطبيقات شيفرة مصدرية بعضها من بعض، وأي شيفرة يُعاد استخدامها تعبر حدود المستودعات عبر `@churchapps/helpers` أو `@churchapps/apphelper` أو `@churchapps/apihelper`. انظر [المكتبات المشتركة](../shared-libraries/index.md).

## خرائط الأنظمة

| الصفحة | ما تغطيه | النطاق |
|------|----------------|-------|
| [الإشعارات والتذكيرات](./notifications.md) | كيف يُبلغ النظام الشخصَ بأي شيء: بوابتا الإرسال، وسلسلة تصعيد القنوات، ومحرك التذكيرات | Api (messaging)، B1Admin، B1App |
| [البنية الفورية](../realtime.md) | إطار تسليم WebSocket الذي تقوم عليه الدردشة والحضور والتسليم داخل التطبيق | Api (messaging)، جميع تطبيقات الويب |
| [إشعارات الويب (Web Push)](../web-push.md) | قناة الإشعارات الفورية في المتصفح: مفاتيح VAPID، وتخزين الاشتراكات، والتسليم | Api (messaging)، جميع تطبيقات الويب |
| [التبرعات](./giving.md) | مزودو الدفع والبوابات، وتدفقات التبرع، والصناديق والدفعات، وwebhooks البوابات | Api (giving)، apphelper، B1App، B1Admin |
| [تسجيلات الفعاليات](./registrations.md) | نموذج التجارة الخاص بالتسجيل: أنواع المشاركين، والاختيارات، ورموز الخصم، والمدفوعات عبر بوابة التبرعات، وقائمة الانتظار | Api (content + giving)، B1App، B1Admin |
| [تسجيل الحضور](./check-ins.md) | تسجيل الحضور عبر الكشك والخدمة الذاتية، ونموذج بيانات الحضور، وتوجيه الغرف، وطبقة حماية الأطفال، وطباعة الملصقات | B1Checkin، B1App، B1Admin، Api (attendance + membership) |
| [منشئ المواقع](./website-builder.md) | شجرة الصفحات والأقسام والعناصر، وعقد أنواع العناصر ومعالجاتها، والمدونة، والصفحات المقيّدة بالوصول، وتحسين محركات البحث، وتوليد الذكاء الاصطناعي | Api (content)، AskApi، helpers/apphelper، B1Admin، B1App |
| [توجيه المواقع وتعدد المواقع](./websites.md) | كيفية ربط الطلب بكنيسة وموقع محدد، ونموذج البيانات متعدد المواقع بالمعرّف `siteId`، وطبقة الحافة Caddy للنطاقات المخصصة | B1App، Api (membership + content)، B1Admin |
| [التكاملات](./integrations.md) | سطح التوسعة: OAuth، ومفاتيح API، وwebhooks، ومزودو المحتوى، وMCP | Api، المكتبات المشتركة، تطبيقات خارجية |
| [سجل التدقيق والدفعات القابلة للتراجع](./audit-log.md) | تدقيق مفعّل افتراضياً لكل عملية تعديل عند نقطة التحكم في المتحكِّمات، وطبقة الدفعات التي تجعل الاستيراد والإجراءات الجماعية قابلة للتراجع | Api (جميع الوحدات)، B1Admin، B1Transfer |
| [MinistryStuff](./ministrystuff.md) | خدمة التخزين المدفوعة وأرصدة الرسائل النصية: هوية JWT المشتركة، وS2S بمفتاح الخدمة، ونقاط الربط لمزودي الرسائل النصية والتخزين، وفوترة Stripe | MinistryStuffApi، MinistryStuffWeb، Api (content + messaging)، حزم texting/apihelper، B1Admin |
| [التخزين بمزودك الخاص (BYOS)](./byos-storage.md) | تربط الكنائس Google Drive أو Dropbox أو OneDrive أو حاوية S3 متوافقة للرفع يتجاوز حد 100 ميغابايت المجاني: ربط OAuth، وأشكال الرفع لكل مزود، وإعادة التوجيه العامة للتنزيل | Api (content + membership)، حزم helpers/apphelper، B1Admin، B1App |
| [محتوى المجتمع (Content Commons)](./commons.md) | طبقة الأصول والتقديمات المشتركة التي تقوم عليها المحتويات التي ينشئها المستخدمون عبر المنتجات، وقائمة المراجعة الموحدة الخاصة بالموظفين فقط في إدارة الخادم بتطبيق B1Admin | Api (وحدة commons)، B1Admin، WorshipCommons، Lessons.church، FreeShow |

:::tip
عندما يغيّر أي تعديل طريقةَ عمل أحد هذه الأنظمة، لا مجرد صفحة داخل تطبيق واحد، ينبغي تحديث خريطة النظام المطابقة هنا ضمن العمل نفسه. فهذا يحافظ على موثوقية هذا القسم بوصفه المرجع الأول للمساهمين الجدد.
:::
