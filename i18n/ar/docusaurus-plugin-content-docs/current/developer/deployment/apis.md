# نشر واجهة برمجة التطبيقات

<div class="article-intro">

تُنشر واجهات برمجة تطبيقات ChurchApps كدوال AWS Lambda باستخدام Serverless Framework. تغطي هذه الصفحة سير عمل البناء والنشر والإعداد لبيئتي العرض التجريبي والإنتاج.

</div>

<div class="prereqs">

- إعداد بيانات اعتماد AWS على جهازك
- التأكد من امتلاك صلاحية الوصول إلى حساب AWS المستهدف

## البناء

تُبنى واجهات برمجة التطبيقات للإنتاج باستخدام ملف إعداد TypeScript مخصص:

```bash
npm run build:prod
```

يستخدم هذا الأمر `tsconfig.prod.json` لتجميع المشروع لبيئة تشغيل Lambda.

## النشر

للنشر إلى بيئة العرض التجريبي:

```bash
npm run deploy-demo
```

للنشر إلى الإنتاج:

```bash
npm run deploy-prod
```

عمليًا، تُنشر واجهة برمجة التطبيقات عبر GitHub Actions: يعمل **Deploy Demo** عند كل دفع إلى `main`، ويُبدأ **Deploy Prod** يدويًا (workflow dispatch). لم تعد هناك بيئة تجهيز (staging).

## ترحيلات قاعدة البيانات

يطبّق **Deploy Prod** ترحيلات قاعدة البيانات المعلقة كجزء من عملية النشر. قواعد بيانات الإنتاج تقبل الاتصالات من داخل VPC فقط، لذلك يستدعي سير العمل، مباشرةً بعد `serverless deploy`، دالة `migrate` Lambda (`api-Prod-migrate`). تشغّل هذه الدالة ترحيلات كل وحدة المعلقة وتُرجع `{ ok, environment, modules }`. إذا فشلت وحدة أو رُفضت (على سبيل المثال، قاعدة بيانات بلا سجل ترحيلات)، يفشل العمل حتى لا يتأخر المخطط عن الكود أبدًا. يتراجع **Rollback Prod** عن كود Lambda فقط، وتبقى الترحيلات مطبّقة، لذا اجعلها إضافية دائمًا. انظر [إدارة الخادم -- ترحيلات قاعدة البيانات](../server-admin#database-migrations) للتحقق من الحالة أو لتشغيل الترحيلات يدويًا.

## ما الذي يُنشأ

ينشئ كل نشر لواجهة برمجة التطبيقات دوال AWS Lambda التالية أو يحدّثها:

| الدالة | الغرض |
|----------|---------|
| `web` | معالج طلبات HTTP عبر API Gateway |
| `socket` | معالج اتصالات WebSocket |
| `timer15Min` | مهمة مجدولة تعمل كل 30 دقيقة (الاسم تاريخي) |
| `timerMidnight` | مهمة مجدولة تعمل يوميًا عند منتصف الليل |
| `migrate` | تطبّق ترحيلات قاعدة البيانات المعلقة؛ يستدعيها سير عمل Deploy Prod |

## إعداد البيئة

في البيئات المنشورة، تُقرأ الإعدادات من **AWS SSM Parameter Store** بدلًا من ملفات `.env`. هذا يُبقي الأسرار خارج حزمة النشر، ويتيح تغيير الإعدادات دون إعادة النشر.

:::warning
لا تُرفع بيانات اعتماد الإنتاج إلى المستودع أبدًا. يجب تخزين جميع الإعدادات الحساسة في AWS SSM Parameter Store والوصول إليها أثناء التشغيل.
:::

:::tip
كل دمج إلى `main` يُنشر أولًا إلى بيئة العرض التجريبي. تحقّق من تغييرك هناك (على سبيل المثال على [demo.b1.church](https://demo.b1.church)) قبل تشغيل Deploy Prod.
:::
