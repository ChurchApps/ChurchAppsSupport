# نقاط نهاية Doing

<div class="article-intro">

تُدير وحدة Doing تخطيط الخدمات وجدولة المتطوعين وإدارة المهام والأتمتة. وتوفر أدوات لإنشاء خطط الخدمة مع الأوقات والمناصب، وتعيين المتطوعين، وإدارة تواريخ الحجب، وبناء عناصر ترتيب الخدمة، والاتصال بمزودي المحتوى الخارجيين، وإعداد سير العمل الآلي مع الشروط والإجراءات.

</div>

**المسار الأساسي:** `/doing`

## الخطط

المسار الأساسي: `/doing/plans`

| الطريقة | المسار | المصادقة | الصلاحية | الوصف |
|--------|------|------|------------|-------------|
| GET | `/` | JWT | — | عرض جميع الخطط الخاصة بالكنيسة |
| GET | `/:id` | JWT | — | الحصول على خطة حسب المعرف |
| GET | `/ids?ids=` | JWT | — | الحصول على عدة خطط حسب المعرفات مفصولة بفواصل |
| GET | `/types/:planTypeId` | JWT | — | الحصول على الخطط حسب نوع الخطة |
| GET | `/textRange?startDate=&endDate=&ministryId=&planTypeId=` | JWT | `texting.send` + تعديل الخدمة | معاينة نظرة عامة على الخدمة التي ستُرسل إليها **رسائل المتطوعين النصية**: `{ totalMembers, eligibleCount, optedOutCount, noPhoneCount, capped }` للمتطوعين المعينين في النطاق (شخص واحد لكل فرد، مع تخطي من أوقفوا الاشتراك والأرقام المفقودة، وإلغاء تكرار الأرقام المشتركة، والحد الأقصى 200) |
| GET | `/presenter` | JWT | — | الحصول على الخطط للأيام السبعة القادمة (عرض المقدّم) |
| GET | `/confirmationWorkflows?ministryId=` | JWT | تعديل الخدمة | سير عمل تأكيد تعيين الخدمة النشط (`workflowType = "assignmentConfirmation"`) الذي يمكن للخطة اختياره: `[{ id, name }]` |
| GET | `/public/current/:planTypeId` | عامة | — | الحصول على الخطة الحالية لنوع خطة معين |
| GET | `/public/signup/:churchId` | عامة | — | الخطط المفتوحة للتسجيل الذاتي، الأقرب أولاً، مع مناصب التسجيل الذاتي الخاصة بكل منها (مرتبة حسب `categoryName` ثم `name`، مع `filledCount` للتعيينات Accepted/Unconfirmed) وأوقاتها. دون أسماء المتطوعين. عندما يكون إعداد الكنيسة `volunteerSignupNextOnly` هو `"true"`، تُعاد أول خطة فقط لكل نوع خطة. يتضمن كل `plan` حقل `signupDeadline` محسوباً (وقت ISO، أو `null`)، وهو `signupDeadlineHours` قبل أقرب وقت من نوع `service` للخطة (أي وقت محدد إن لم يوجد وقت خدمة؛ والساعة 9:00 بتوقيت الكنيسة في `serviceDate` إن لم تكن للخطة أوقات) |
| GET | `/signup/:planId/volunteers` | JWT | — | `[{ positionId, names }]` لمناصب التسجيل الذاتي في الخطة (أسماء العرض للمكلفين بـ Accepted/Unconfirmed). تُعيد `[]` ما لم يكن `showVolunteerNames` مفعّلاً للخطة |
| POST | `/` | JWT | — | إنشاء الخطط أو تحديثها (يقبل كائناً واحداً أو مصفوفة). اضبط `confirmationWorkflowId` لاختيار الخطة لسير عمل تأكيد الخدمة، أو `null` لإلغاء الاختيار للطلبات المستقبلية. أرسل `signupDeadlineHours: null` لمسح موعد نهائي؛ وإغفال الحقل يُبقي القيمة المحفوظة |
| POST | `/copy/:id` | JWT | تعديل الخدمة | نسخ خطة مع مناصبها وأوقاتها وتعييناتها وعناصر ترتيب الخدمة. يتضمن الطلب `ministryId` و`serviceDate` و`copyMode` (القيم "none" أو "positions" أو "all") و`copyServiceOrder` (قيمة منطقية). بدون `targetPlanId` تُنشأ خطة جديدة، وتنتقل `notes` و`signupDeadlineHours` و`showVolunteerNames` و`autoReplaceOnDecline` من الخطة المصدر ما لم يوفرها الطلب. مع `targetPlanId`، تملأ النسخة تلك الخطة الموجودة بدلاً من ذلك (يجب أن يكون المستدعي قادراً على تعديلها). يستدعي خيار **Repeat weekly** في B1Admin هذه الواجهة مرة كل أسبوع، ويُنسخ في كل مرة من الخطة التي أُنشئت الأسبوع السابق |
| POST | `/textRange` | JWT | `texting.send` + تعديل الخدمة | إرسال رسالة نصية إلى كل متطوع معيّن في نطاق تاريخ عبر مزود الرسائل النصية الخاص بالكنيسة. الطلب: `{ startDate, endDate, ministryId, planTypeId?, message }` (الرسالة حتى 1600 حرف؛ تُحل حقول الدمج لكل مستلم). تُعيد أعداد المعاينة مع `recipientCount` و`successCount` و`failCount` و`error` (القيمة `no_provider` أو `insufficient_credits`) عند توقف الإرسال مبكراً |
| POST | `/:id/issueRequests` | JWT | تعديل الخطة | إصدار التعيينات الجديدة غير المؤكدة وغير المُبلَّغ عنها للخطة عبر سير عمل التأكيد الخاص بها: يُعلّم كل تعيين بأنه مُبلَّغ عنه ويبدأ بطاقة سير عمل واحدة لكل تعيين. طلب فارغ؛ يُعيد `{ issued }`. يفشل ما لم تكن الخطة منشورة (وليست `prepared`)، ولديها `confirmationWorkflowId` نشط بخطوة واحة على الأقل، ولم يتجاوز موعد الرد النهائي |
| POST | `/autofill/:id` | JWT | — | ملء تعيينات المتطوعين تلقائياً لخطة. الطلب: `{ teams: [{ positionId, personIds }] }` |
| DELETE | `/:id` | JWT | — | حذف خطة وجميع الأوقات والتعيينات والمناصب وعناصر الخطة المرتبطة بها |

### مثال: نسخ خطة

```
POST /doing/plans/copy/abc-123
Authorization: Bearer <token>

{
  "serviceDate": "2026-03-01T10:00:00.000Z",
  "copyMode": "all",
  "copyServiceOrder": true
}
```

```json
{
  "id": "def-456",
  "churchId": "church-1",
  "serviceDate": "2026-03-01T10:00:00.000Z"
}
```

## مصادقات مزودي المحتوى

المسار الأساسي: `/doing/contentProviderAuths`

يرث من الفئة الأساسية CRUD (GET `/`، GET `/:id`، POST `/`، DELETE `/:id` — دون فحوصات صلاحيات).

يدير سجلات المصادقة عبر OAuth لمزودي المحتوى الخارجيين (مثل تكاملات برامج العرض التقديمي).

يتم تشفير `accessToken` و`refreshToken` عند التخزين باستخدام `EncryptionHelper` وفك تشفيرهما عند القراءة، لذا تُعيد الواجهة الرموز كنص عادي. أما الصفوف المحفوظة قبل التشفير فتحتوي على نص عادي (وهو لا يحتوي أبداً على `|`)؛ وتُعاد كما هي، ويتم تشفيرها عند حفظها في المرة التالية.

| الطريقة | المسار | المصادقة | الصلاحية | الوصف |
|--------|------|------|------------|-------------|
| GET | `/` | JWT | — | عرض جميع مصادقات مزودي المحتوى |
| GET | `/:id` | JWT | — | الحصول على مصادقة مزود محتوى حسب المعرف |
| GET | `/ids?ids=` | JWT | — | الحصول على عدة مصادقات مزودي محتوى حسب المعرفات مفصولة بفواصل |
| GET | `/ministry/:ministryId` | JWT | — | الحصول على جميع مصادقات مزودي المحتوى لخدمة |
| GET | `/ministry/:ministryId/:providerId` | JWT | — | الحصول على سجل المصادقة لخدمة ومزود محددين |
| POST | `/` | JWT | — | إنشاء مصادقات مزودي المحتوى أو تحديثها |
| DELETE | `/:id` | JWT | — | حذف مصادقة مزود محتوى |

## وكيل المزود

المسار الأساسي: `/doing/providerProxy`

يمرر الطلبات إلى مزودي المحتوى الخارجيين (مثل ProPresenter وEasyWorship). ويتولى تجديد الرموز تلقائياً عند انتهاء صلاحيتها.

| الطريقة | المسار | المصادقة | الصلاحية | الوصف |
|--------|------|------|------------|-------------|
| POST | `/browse` | JWT | — | تصفح ملفات مزود المحتوى. الطلب: `{ ministryId, providerId, path }` |
| POST | `/getPresentations` | JWT | — | الحصول على العروض التقديمية من مزود المحتوى. الطلب: `{ ministryId, providerId, path }` |
| POST | `/getPlaylist` | JWT | — | الحصول على قائمة تشغيل من مزود المحتوى. الطلب: `{ ministryId, providerId, path, resolution }` |
| POST | `/getInstructions` | JWT | — | الحصول على تعليمات لعنصر محتوى. الطلب: `{ ministryId, providerId, path }` |
| POST | `/getExpandedInstructions` | JWT | — | الحصول على تعليمات موسعة لعنصر محتوى. الطلب: `{ ministryId, providerId, path }` |
