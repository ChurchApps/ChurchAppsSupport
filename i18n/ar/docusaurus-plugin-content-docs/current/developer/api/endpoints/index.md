# مرجع نقاط النهاية

<div class="article-intro">

يوثّق هذا القسم جميع نقاط نهاية REST التي تعرضها واجهة ChurchApps البرمجية (API). تسرد كل صفحة وحدة جميع المسارات مع طريقة HTTP الخاصة بها، ومسارها، ومتطلبات المصادقة، والصلاحيات المطلوبة.

</div>

## عنوان القاعدة (Base URL)

| البيئة | العنوان |
|-------------|-----|
| التطوير المحلي | `http://localhost:8084` |
| الإنتاج | `https://api.churchapps.org` |

## أعراف الطلبات

- **Content-Type:** تستخدم جميع أجسام الطلبات والاستجابات الصيغة `application/json`
- **تعدد المستأجرين (Multi-tenant):** يُحدَّد نطاق كل طلب موثّق بمعرّف `churchId` المستخرج من رمز JWT، لذا لا تُمرِّر `churchId` في عنوان URL
- **الحفظ الدفعي (Batch saves):** تقبل معظم نقاط نهاية `POST` **مصفوفة من الكائنات**. تُنشئ واجهة API السجلات الجديدة (التي لا تحتوي على حقل `id`) وتُحدّث السجلات الموجودة (التي تحتوي على حقل `id`) في استدعاء واحد
- **المعرّفات (IDs):** جميع معرّفات الكيانات من نوع UUID

### مثال: الحفظ الدفعي

```json
POST /membership/people
Authorization: Bearer <token>

[
  { "firstName": "Jane", "lastName": "Doe" },
  { "id": "abc-123", "firstName": "John", "lastName": "Smith" }
]
```

يُنشأ الكائن الأول (جديد)، ويُحدَّث الكائن الثاني (لأنه يحتوي على `id`).

## صيغة الاستجابة

تُعيد الاستجابات الناجحة بيانات JSON، إما كائنًا واحدًا أو مصفوفة. تستخدم استجابات الخطأ رموز حالة HTTP القياسية:

| الرمز | المعنى |
|------|---------|
| `200` | نجاح |
| `400` | طلب غير صالح (أخطاء التحقق) |
| `401` | غير مصرّح (رمز مفقود أو غير صالح، أو صلاحيات غير كافية) |
| `404` | غير موجود |
| `500` | خطأ في الخادم |

تُعيد أخطاء التحقق البيانات التالية:

```json
{
  "errors": [
    { "msg": "enter a valid email address", "param": "email", "location": "body" }
  ]
}
```

## كيفية قراءة جداول نقاط النهاية

تُنظّم كل صفحة وحدة نقاط النهاية حسب المتحكم (Controller). تستخدم الجداول الأعمدة التالية:

| العمود | الوصف |
|--------|-------------|
| **Method** | طريقة HTTP (`GET`، `POST`، `DELETE`) |
| **Path** | مسار الطريق نسبةً إلى المسار الأساسي للمتحكم |
| **Auth** | **JWT** = يتطلب رمز Bearer، **Public** = لا يتطلب مصادقة |
| **Permission** | الصلاحية المطلوبة (مثل `People.Edit`). تعني `—` أن أي مستخدم موثّق مسموح له |
| **Description** | وصف ما تفعله نقطة النهاية |

تُوفّر المتحكمات التي ترث من فئة CRUD الأساسية أربع نقاط نهاية تلقائيًا: `GET /` (عرض الكل)، و`GET /:id` (الحصول حسب المعرّف)، و`POST /` (الإنشاء/التحديث)، و`DELETE /:id` (الحذف).

## وحدة التقارير

تعمل وحدة التقارير بطريقة مختلفة عن بقية الوحدات. فبدلًا من عمليات CRUD المدعومة بقاعدة البيانات، تحمّل تعريفات التقارير من ملفات JSON على القرص، وتنفّذ استعلامات SQL معاملية.

| الطريقة | المسار | المصادقة | الوصف |
|--------|------|------|-------------|
| GET | `/reporting/reports/:keyName` | JWT | تحميل تعريف تقرير حسب اسم المفتاح |
| GET | `/reporting/reports/:keyName/run` | JWT | تنفيذ تقرير وإرجاع النتائج |

تُمرَّر معاملات التقرير كقيم في سلسلة الاستعلام (مثل `?startDate=2024-01-01&endDate=2024-12-31`). يُحقن معامل `churchId` تلقائيًا من رمز JWT. يمكن لكل تعريف تقرير أن يحدد متطلبات الصلاحيات الخاصة به.
