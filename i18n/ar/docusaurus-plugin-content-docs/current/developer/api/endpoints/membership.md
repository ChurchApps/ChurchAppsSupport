# نقاط نهاية العضوية

<div class="article-intro">

تدير وحدة العضوية الأشخاص والكنائس والمجموعات والأسر والأدوار والصلاحيات والنماذج والإعدادات. وهي أكبر الوحدات، وتوفر طبقة الهوية والتفويض الأساسية لجميع الوحدات الأخرى.

</div>

**المسار الأساسي:** `/membership`

## الأشخاص

|--------|------|------|------------|-------------|

| POST | `/advancedSearch` | JWT | People.View أو Member | بحث متعدد الشروط (العمر، شهر الميلاد، حالة العضوية، إلخ). الجسم مصفوفة من الشروط؛ الجسم الفارغ يعني عدم وجود شروط، وأي جسم آخر غير مصفوفة يُرجع 400 |
| POST | `/loadOrCreate` | عام | — | البحث عن شخص بالبريد الإلكتروني أو إنشاؤه. الجسم: `{ churchId, email, firstName, lastName }` |
| POST | `/guest-register` | عام | — | تسجيل الضيوف عبر QR. الجسم: `{ churchId, members: [{ firstName, lastName, email?, phone?, birthDate?, gender?, grade? }], address?, maritalStatus?, comments? }` (من 1 إلى 10 أعضاء؛ البريد والهاتف والحالة الاجتماعية تنطبق على العضو الأول فقط). تُستبعد الحقول التي أوقفتها الكنيسة؛ القيم المطلوبة المفقودة أو غير الصالحة تُرجع 400. أولاً يعيد الاستخدام للأشخاص الموجودين: يتطابق العضو عندما يوجد شخص واحد بالضبط غير محذوف بنفس الاسم الأول (دون حساسية لحالة الأحرف) ونفس البريد أو أرقام الهاتف (المنزل أو العمل أو الجوال)؛ والعضو الذي لا يملك بريداً أو هاتفاً يتطابق بالاسم الأول داخل الأسرة المطابقة. لا يتم تعديل الأشخاص المطابقين أبداً. يُضاف الأعضاء غير المطابقين إلى الأسرة المطابقة، أو إلى أسرة جديدة (تُسمى باسم العائلة للعضو الأول إن لم توجد)، بالحالة `membershipStatus: "Visitor"` والعنوان المشترك `address`. يحفظ `comments` كملاحظة على العضو الأول، ويضيف الجميع إلى المجموعة الخاصة `guestRegistrationGroupId` إن كانت محددة، وعندما تكون قيمة `guestRegistrationRecordAttendance` هي `"true"` يسجل الحضور لأوقات الخدمة المجدولة لتلك المجموعة التي تكون نافذة تسجيل الحضور مفتوحة لها الآن. يُرجع `{ householdId, people: [{ id, name }] }`، مع إعادة الأسماء المرسلة بدلاً من المخزنة. نفس قواعد الاشتراك/الرمز وتحديد المعدل كما في استدعاء الخيارات |
| POST | `/household/:householdId` | JWT | People.Edit | تحديث تعيينات أعضاء الأسرة |
| POST | `/public/email` | عام | — | إرسال بريد إلكتروني إلى شخص. الجسم: `{ churchId, personId, subject, body, appName }` |
| POST | `/apiEmails` | داخلي | — | تحميل رسائل البريد الإلكتروني للأشخاص بواسطة المعرفات (من خادم إلى خادم، يتطلب jwtSecret) |
| DELETE | `/:id` | JWT | People.Edit | حذف شخص |

### مثال: البحث عن الأشخاص

```
GET /membership/people/search?term=John
Authorization: Bearer <token>
```

```json
[
  {
    "id": "abc-123",
    "name": { "first": "John", "last": "Smith" },
    "contactInfo": { "email": "john@example.com" },
    "membershipStatus": "Member"
  }
]
```

### مثال: إنشاء شخص

```
POST /membership/people
Authorization: Bearer <token>

[{ "firstName": "Jane", "lastName": "Doe", "contactInfo": { "email": "jane@example.com" } }]
```

| DELETE | `/:id` | JWT | صلاحية الوصول إلى النموذج | حذف نموذج |

## إرسالات النماذج

المسار الأساسي: `/membership/formsubmissions`

| الطريقة | المسار | المصادقة | الصلاحية | الوصف |
|--------|------|------|------------|-------------|
| GET | `/` | JWT | Forms.Admin أو Forms.Edit | عرض الإرسالات. فلترة بـ `?personId=` أو `?formId=` |
| GET | `/my?include=questions,answers` | JWT | ذاتي النطاق: حتى 50 إرسالاً لنموذج مستقل (وليس نماذج الأشخاص) قدمه العضو المسجل دخوله أو المرتبط بشخصه (`contentType` هو `person`، و`contentId` = معرف شخصه، على سبيل المثال بعد تغيير قام به مسؤول)، من الأحدث إلى الأقدم، مع `form.name` لكل منها. يُضمّن `include` أسئلة كل نموذج وإجابات الإرسال. يُرجع `401` إذا لم يكن المستخدم مرتبطاً بشخص. يدعم قسم **نماذجي** في صفحة B1 Me |
| GET | `/group/:groupId` | JWT | قائد المجموعة | إجابات قادة المجموعة: إدخال واحد لكل نموذج مرتبط ولكل حدث للمجموعة لديه نموذج تسجيل، وكل منها يحتوي على `form` و`event` (`id` و`title` و`start`؛ لإدخالات الأحداث فقط) و`questions` و`submissions` (مع `answers` و`personName`، و`null` عند الإرسال المجهول) |
| GET | `/:id` | JWT | Forms.Admin أو Forms.Edit أو صلاحية العرض | الحصول على إرسال بواسطة المعرف. أضف `?include=form,questions,answers`. يمكن لقادة المجموعة المرتبطة بالنموذج، وقادة المجموعة التي ينتمي إليها تسجيل حدث، قراءته أيضاً |
| GET | `/formId/:formId` | JWT | صلاحية الوصول إلى النموذج (العرض) | الحصول على جميع الإرسالات لنموذج (يتضمن النموذج والأسئلة والإجابات). لقادة المجموعة المرتبطة بالنموذج صلاحية العرض |
| POST | `/` | JWT | — | إرسال إجابات النموذج (يتعامل مع النماذج المقيدة وغير المقيدة، ويرسل إشعارات البريد الإلكتروني). عندما يملك النموذج `autoCreatePerson`، يبحث عن شخص ضيف بالبريد الإلكتروني أو ينشئه ويربط الإرسال به؛ وعندما يملك النموذج أيضاً `groupId`، يضيف ذلك الشخص إلى المجموعة؛ وعندما يتم تعيين `followUpSubject`/`followUpBody`، يرسل بريداً إلكترونياً متابعة بقالب إلى المُرسِل. ما لم يكن المستدعي قادراً على إدارة النموذج، يُعيَّن `submittedBy` دائماً إلى شخص العضو المسجل دخوله (أو يُترك فارغاً للإرسالات المجهولة) |
| DELETE | `/:id` | JWT | Forms.Admin أو Forms.Edit | حذف إرسال وإجاباته |
