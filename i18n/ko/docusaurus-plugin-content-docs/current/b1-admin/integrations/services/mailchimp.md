# Mailchimp

<div class="article-intro">

Mailchimp 대상자를 B1과 자동으로 동기화 유지하세요: 사람은 이름, 이메일, 전화번호로 유입됩니다. 그룹 및 목록 구성원이 Mailchimp 태그가 됩니다. 삭제된 사람은 보관됩니다. 동기화는 B1에 내장되어 있습니다 — 제3자 서비스 없음, 작업별 계량 없음, 야간 일정이 아닌 거의 실시간으로 변경사항이 도착합니다.

</div>

<div class="prereqs">
<h4>시작하기 전에</h4>

- B1이 관리하려는 대상자가 있는 [Mailchimp](https://mailchimp.com) 계정
- Mailchimp **API 키**(Mailchimp: 프로필 아이콘 → **계정 및 청구 → 추가 기능 → API 키**)
- 당신의 **대상자 ID**(Mailchimp: **대상자 → 설정 → 대상자 이름 및 기본값**)
- **설정 편집** 권한이 있는 B1Admin 사용자

</div>

## 동기화되는 항목

| B1 변경 | Mailchimp 효과 |
|---|---|
| 사람 추가 또는 업데이트 | 구독자 추가/업데이트(이름, 성, 전화; 새 구독자는 `구독됨`으로 표시됨) |
| 사람 삭제(또는 GDPR 삭제) | 구독자 보관 |
| 사람이 그룹에 가입 | 그룹 이름 따라 명명된 태그 추가 |
| 사람이 그룹을 떠남 | 해당 태그 제거 |
| 사람이 저장된 목록에 들어감 | 목록 이름 따라 명명된 태그 추가 |
| 사람이 저장된 목록을 떠남 | 해당 태그 제거 |

**저장된 목록은 일반적으로 더 나은 태그 소스입니다.** B1 [저장된 목록](/docs/b1-admin/people/lists)은 자신을 재평가하는 규칙 기반 대상자입니다 — "북쪽 캠퍼스에 있는 모든 사람", "목사 이메일에 옵트인한 구성원입니다." Mailchimp 세그먼트를 목록 태그로 지정하면 동기화가 유지됩니다. 사역팀 우편발송에는 그룹 태그를 사용하세요.

동기화는 **일방향**(B1 → Mailchimp)이고 Mailchimp의 표준 필드만 건드리므로 Mailchimp 내에서 관리하는 병합 필드나 세그먼트와 충돌할 수 없습니다.

## 설정

1. B1Admin에서 **설정 → 개발자 → Webhooks → Webhook 추가**로 이동합니다.
2. **커넥터 유형**을 **Mailchimp**로 설정합니다.
3. **Mailchimp API 키** 및 **대상자 ID**를 붙여 넣습니다. 키는 암호화되어 저장되고 다시 표시되지 않습니다.
4. 관련 이벤트가 미리 선택됩니다. 원하지 않는 항목을 선택 해제합니다(예: 사람 이벤트를 켜두지만 그룹 태그를 건너뜁니다).
5. 저장합니다. B1은 수락하기 전에 키와 대상자를 Mailchimp에 대해 검증합니다 — 오타는 즉시 이유와 함께 실패합니다.

언제든지 **테스트 보내기**를 사용하여 연결을 다시 확인합니다. 모든 동기화 시도가 Mailchimp의 실제 응답이 있는 webhook의 배송 기록에 기록되고, 실패한 배송은 약 5일 동안 백오프로 자동으로 재시도됩니다.

## 초기 가져오기

커넥터는 켜져 있는 순간부터 *변경사항*을 동기화합니다. 기존 디렉토리를 역채우지 않습니다. 설정 날짜의 경우:

1. B1Admin에서 **사람**으로 이동한 후 원하는 사람을 검색(또는 저장된 목록 실행)한 후 **내보내기**를 클릭하여 CSV를 다운로드합니다.
2. Mailchimp에서 **대상자 → 연락처 가져오기**를 사용하여 CSV를 로드하고 가져오기 중에 태그를 적용합니다.

초기 로드를 Mailchimp의 가져오기 도구를 통해 수행하면 동의 질문을 제어할 수 있습니다 — 실제로 이메일을 받기로 동의한 사람만 가져옵니다. 전체 디렉토리를 구독한 연락처로 대량 가져오기하면 Mailchimp의 약관 및 스팸 방지 법률(CAN-SPAM/GDPR)을 위반할 수 있습니다.

## 제한 및 참고 사항

- **일방향 동기화.** Mailchimp의 구독 취소, 반송 및 편집은 B1로 다시 흐르지 않습니다. Mailchimp에서 구독을 취소한 사람은 B1에서 직접 보낸 이메일을 여전히 받을 수 있습니다 — Mailchimp를 대량 메일 동의의 진실 소스로 취급합니다.
- **이메일 주소가 없는 사람은 건너뜁니다**(배송 기록에 기록됨) — Mailchimp 구독자는 이메일로 키화됩니다.
- **이메일 주소 변경은 새 구독자를 만듭니다.** Mailchimp는 사람을 이메일로 식별하므로 B1에서 누군가의 이메일을 변경하면 새 주소로 추가됩니다. 이전 구독자는 Mailchimp에서 보관할 때까지 유지됩니다.
- **표준 필드만 동기화됩니다** — 이름, 성, 전화번호. 구성원 상태, 캠퍼스 및 사용자 지정 B1 필드는 이 버전에서 Mailchimp 병합 필드로 매핑되지 않습니다. 대신 목록 태그를 사용하여 세그먼트합니다.
- **태그 이름은 그룹/목록 이름입니다.** 그룹 또는 목록의 이름을 바꾸면 새 이름으로 태깅을 시작합니다. 이전 태그는 Mailchimp에서 제거될 때까지 기존 구독자에게 유지됩니다.
- **Mailchimp의 연락처 제한이 여전히 적용됩니다** — 무료 계층 대상자를 한계를 초과하는 동기화는 배송 기록에 `구성원 제한 도달` 오류를 기록합니다.

## 기타 레시피(Zapier / Make)

대상자 동기화를 넘어 — `donation.created`에 기부자 태깅, Mailchimp → B1 역방향 또는 완전히 다른 이메일 플랫폼(Constant Contact, Brevo 등)으로의 동기화 — 은 [Zapier](../zapier) 또는 [Make](../make)를 통해 여전히 사용 가능합니다. 동일한 webhook 이벤트를 트리거합니다:

- **태그 기부자:** B1 *새 기부* → B1 *사람 찾기* → Mailchimp *구독자를 태그에 추가*(`기부-2026`)
- **양방향:** Mailchimp *새 구독자* → B1 *사람 만들기*

이전에 Zapier를 통해 사람/그룹 동기화를 설정한 경우 기본 커넥터를 활성화한 후 이러한 Zaps를 끕니다 — 둘 다 실행하면 모든 이벤트를 이중 처리하고 Zapier 작업을 낭비합니다.

## 문제 해결

- **"Mailchimp이 API 키를 거부했습니다"로 저장 실패** — 키가 해지되었거나 오류가 있습니다. 키는 `-us21`과 같은 데이터 센터 접미사로 끝나야 합니다.
- **"대상자를 찾을 수 없습니다"로 저장 실패** — 대상자 ID가 해당 계정에 없습니다. **대상자 → 설정 → 대상자 이름 및 기본값**에서 복사합니다(대상자 이름이 아닙니다).
- **사람이 Mailchimp에 나타나지 않음** — webhook의 배송 기록을 확인하세요. "건너뜀: 사람에게 이메일 주소가 없습니다"는 정확히 그것을 의미합니다. Mailchimp의 `4xx`는 응답 본문에 이유를 표시합니다.
- **배송이 완전히 중단됨** — 반복적인 소진된 배송 후 webhook이 자동으로 비활성화됩니다. 원인을 수정(일반적으로 해지된 키)하고 다시 활성화한 후 **테스트 보내기**를 사용하여 확인합니다.
