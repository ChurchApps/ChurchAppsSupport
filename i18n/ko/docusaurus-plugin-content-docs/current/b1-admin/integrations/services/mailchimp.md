# Mailchimp

<div class="article-intro">

Mailchimp 청중을 B1과 자동으로 동기화합니다: 사람이 이름, 이메일, 전화번호와 함께 유입되고, 그룹 및 리스트 구성원 자격은 Mailchimp 태그가 되며, 삭제된 사람은 보관됩니다. 동기화는 B1에 기본 제공됩니다. 타사 서비스, 작업별 측정, 야간 일정이 아닌 거의 실시간으로 변경사항이 전달됩니다.

</div>

<div class="prereqs">
<h4>시작하기 전에</h4>

- B1이 관리할 청중이 있는 [Mailchimp](https://mailchimp.com) 계정
- Mailchimp **API 키** (Mailchimp: 프로필 아이콘 → **계정 및 청구 → 추가 → API 키**)
- **청중 ID** (Mailchimp: **청중 → 설정 → 청중 이름 및 기본값**)
- **설정 편집** 권한이 있는 B1Admin 사용자

</div>

## 동기화되는 항목

| B1 변경 | Mailchimp 효과 |
|---|---|
| 사람 추가 또는 업데이트 | 구독자 추가/업데이트 (성, 이름, 전화; 신규 구독자는 `구독함`으로 도착) |
| 사람 삭제 (또는 GDPR 삭제) | 구독자 보관 |
| 사람이 그룹에 참여 | 그룹 이름을 딴 태그 추가 |
| 사람이 그룹을 떠남 | 해당 태그 제거 |
| 사람이 저장된 리스트에 진입 | 리스트 이름을 딴 태그 추가 |
| 사람이 저장된 리스트를 떠남 | 해당 태그 제거 |

**저장된 리스트는 보통 더 나은 태그 소스입니다.** B1 [저장된 리스트](/docs/b1-admin/people/lists)는 규칙 기반 청중으로 자체 재평가됩니다. "북쪽 캠퍼스의 모든 사람", "목회 이메일에 동의한 회원". Mailchimp 세그먼트를 리스트 태그로 지정하고 동기화가 유지합니다. 그룹 태그는 사역팀 메일링에 사용합니다.

동기화는 **단방향** (B1 → Mailchimp)이고 Mailchimp의 표준 필드만 건드리므로 Mailchimp 내에서 관리하는 병합 필드 또는 세그먼트와 충돌할 수 없습니다.

## 설정

1. B1Admin에서 **설정 → 개발자 → Webhooks → Webhook 추가**로 이동합니다.
2. **커넥터 유형**을 **Mailchimp**로 설정합니다.
3. **Mailchimp API 키**와 **청중 ID**를 붙여넣습니다. 키는 암호화되어 저장되고 다시 표시되지 않습니다.
4. 관련 이벤트가 미리 선택되어 있습니다. 원하지 않는 것은 선택 해제합니다 (예: 사람 이벤트 유지하되 그룹 태그 건너뛰기).
5. 저장합니다. B1은 수락하기 전에 키와 청중을 Mailchimp에 대해 확인합니다. 오타는 즉시 실패하고 이유를 표시합니다.

언제든지 **테스트 전송**을 사용하여 연결을 다시 확인합니다. 모든 동기화 시도는 Mailchimp의 실제 응답과 함께 webhook의 전달 이력에 로깅되며, 실패한 전달은 자동으로 약 5일 동안 백오프와 함께 재시도됩니다.

## 초기 가져오기

커넥터는 켜진 순간부터 변경 사항을 동기화합니다. 기존 디렉토리를 채우지는 않습니다. 설정 날에:

1. B1Admin에서 **사람**으로 이동하여 원하는 사람을 검색하거나 (또는 저장된 리스트 실행) **내보내기**를 클릭하여 CSV를 다운로드합니다.
2. Mailchimp에서 **청중 → 연락처 가져오기**를 사용하여 CSV를 로드하고 가져오기 중에 태그를 적용합니다.

Mailchimp의 가져오기 도구를 통해 초기 로드를 수행하면 동의 질문에 대한 제어권을 유지합니다. 실제로 이메일 수신에 동의한 사람만 가져옵니다. 전체 디렉토리를 구독된 연락처로 대량 가져오기하면 Mailchimp 약관 및 스팸 방지법 (CAN-SPAM/GDPR)을 위반할 수 있습니다.

## 제한 사항 및 참고 사항

- **단방향 동기화.** 구독 해제, 반송, Mailchimp에서 수행한 편집은 B1으로 흐르지 않습니다. Mailchimp에서 구독을 취소한 사람도 B1에서 직접 보낸 이메일을 받을 수 있습니다. Mailchimp를 대량 메일 동의의 정보 소스로 간주합니다.
- **이메일 주소가 없는 사람은 건너뜁니다** (전달 이력에 로깅됨). Mailchimp 구독자는 이메일로 키 설정됩니다.
- **이메일 주소 변경은 새 구독자를 만듭니다.** Mailchimp는 사람을 이메일로 식별하므로 B1에서 누군가의 이메일을 변경하면 새 주소 아래 추가합니다. 이전 구독자는 Mailchimp에서 보관할 때까지 남아 있습니다.
- **표준 필드만 동기화됩니다** - 성, 이름, 전화. 이 버전에서는 회원 상태, 캠퍼스, 사용자 지정 B1 필드가 Mailchimp 병합 필드에 매핑되지 않습니다. 대신 리스트 태그를 사용하여 세그먼트합니다.
- **태그 이름은 그룹/리스트 이름입니다.** 그룹 또는 리스트 이름을 바꾸면 새 이름으로 태그 지정을 시작합니다. 이전 태그는 Mailchimp에서 제거될 때까지 기존 구독자에 남아 있습니다.
- **Mailchimp의 연락처 제한이 계속 적용됩니다** - 무료 계층 청중을 그 한계를 초과하는 동기화는 전달 이력에 `회원 제한 도달` 오류를 로깅합니다.

## 기타 레시피 (Zapier / Make)

청중 동기화 이상 - `donation.created` 시 기부자에 태그 지정, Mailchimp → B1 역방향, 또는 완전히 다른 이메일 플랫폼 동기화 (Constant Contact, Brevo 등) - 여전히 [Zapier](../zapier) 또는 [Make](../make)를 통해 동일한 webhook 이벤트를 트리거합니다:

- **기부자 태그 지정:** B1 *새로운 기부* → B1 *사람 찾기* → Mailchimp *태그에 구독자 추가* (`Gave-2026`)
- **양방향:** Mailchimp *새로운 구독자* → B1 *사람 만들기*

이전에 Zapier를 통해 사람/그룹 동기화를 연결했다면 네이티브 커넥터를 활성화한 후 해당 Zaps를 끕니다. 둘 다 실행하면 모든 이벤트가 이중 처리되고 아무것도 위해 Zapier 작업을 소모합니다.

## 문제 해결

- **"Mailchimp에서 API 키 거부" 오류와 함께 저장 실패** - 키가 취소되었거나 잘못 입력되었습니다. 키는 `-us21`과 같은 데이터 센터 접미사로 끝나야 합니다.
- **"청중을 찾을 수 없음" 오류와 함께 저장 실패** - 청중 ID가 해당 계정에 없습니다. **청중 → 설정 → 청중 이름 및 기본값**에서 복사합니다 (청중의 이름이 아님).
- **Mailchimp에 나타나지 않는 사람** - webhook의 전달 이력을 확인합니다. "건너뜀: 사람이 이메일 주소를 가지지 않음"은 정확히 그 의미입니다. Mailchimp의 `4xx`는 응답 본문에 이유를 표시합니다.
- **전달이 완전히 중지됨** - 반복된 소진 전달 후 webhook이 자동 비활성화됩니다. 원인을 수정하고 (보통 취소된 키), 다시 활성화한 후 **테스트 전송**을 사용하여 확인합니다.
