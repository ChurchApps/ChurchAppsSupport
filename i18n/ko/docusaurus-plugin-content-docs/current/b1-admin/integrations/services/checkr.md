# Checkr

<div class="article-intro">

[Checkr](https://checkr.com)는 직원과 자원봉사자를 위한 신원조회(background screening)를 수행합니다. 어린이나 청소년 프로그램을 운영하는 거의 모든 교회에 필요한 기능입니다. B1에는 **신원조회 기능이 내장되어 있지 않습니다** — 조회 요청, 결과 추적, 심사 준수는 모두 Checkr에서 이루어지며, 아래 방법은 단지 B1 이벤트를 Checkr에 연결할 뿐입니다. Checkr는 Zapier 앱을 제공하지 않지만, [Make.com의 Checkr 연동](https://www.make.com/en/integrations/checkr)이 검증되어 있으며 B1 이벤트에서 조회를 시작하는 데 필요한 작업을 제공합니다.

</div>

<div class="prereqs">
<h4>시작하기 전에</h4>

- API 접근 권한과 최소 하나의 심사 패키지가 구성된 [Checkr](https://checkr.com) 계정
- [Make](https://www.make.com) 계정
- **설정 편집** 권한을 가진 B1Admin 사용자

</div>

## 연결할 수 있는 것

Make의 Checkr 앱은 1개의 트리거와 6개의 작업을 제공합니다.

| 방향 | B1 / Make 트리거 | 작업 |
|---|---|---|
| B1 → Checkr | B1 `group.member.added` (자원봉사자 그룹으로 필터링) | Checkr: 후보자 생성 → 신원조회 초대장 생성 |
| Checkr → B1 | Checkr 웹훅(초대 / 보고서 이벤트) | B1: 해당 인물의 기록 업데이트(예: "Checkr 심사 완료" 태그 지정) |

Make의 Checkr 작업: 후보자 생성, 신원조회 초대장 생성, 후보자 조회, 보고서 조회, 보고서 예상 완료일 조회, 초대 조회. 그리고 4개의 검색 모듈.

## 설정

### 1. B1 API 키 발급

**설정 → 개발자 → API 키 → 새 API 키**에서:

- `settings:write` — 트리거 웹훅용
- `people:read` — 조회를 시작할 때 인물의 이름/이메일을 조회하기 위해
- (선택 사항) 보고서 상태를 사용자 지정 필드나 태그로 다시 기록하려면 `people:write`

### 2. Make에서 "자원봉사자 등록 시 조회 시작" 시나리오 만들기

1. **트리거** — B1.church: 이벤트 감시(`group.member.added`).
2. **필터** — `data.groupId`가 "어린이 자원봉사자"(또는 이에 상응하는) 그룹과 일치할 때만 계속 진행.
3. **작업** — B1.church: 인물 찾기(`data.personId` 기준)로 이메일과 이름을 가져옵니다.
4. **작업** — Checkr: 후보자 생성. 3단계의 이름/이메일을 매핑합니다.
5. **작업** — Checkr: 신원조회 초대장 생성. 4단계에서 생성된 후보자 ID를 *candidate_id* 필드에 매핑합니다. 심사 패키지를 선택합니다(예: `tasker_standard` 또는 계정이 제공하는 패키지).
6. (선택 사항) **작업** — Slack: 조회가 시작되었음을 안전 사역 담당자에게 알립니다.

시나리오를 켭니다. 대상 그룹에 새 자원봉사자가 등록되면 자동으로 이메일로 Checkr 초대장을 받고, 휴대폰이나 노트북에서 이를 완료하면 Checkr가 심사를 진행합니다.

### 3. (선택 사항) 보고서 결과 받기

1. **트리거** — Checkr: 이벤트 감시(웹훅). Make는 활성화 시 Checkr 웹훅을 등록합니다.
2. **필터** — `event_type = report.completed`일 때만 계속 진행.
3. **작업** — Checkr: 보고서 조회(웹훅에서 받은 보고서 ID 사용).
4. **작업** — B1.church: 인물 찾기(후보자 이메일 기준).
5. **작업** — 조건부 Slack / 이메일: `clear` / `consider` / `suspended` 상태를 담당자에게 알림.

참고: B1은 아직 "신원조회 상태"를 나타내는 내장 필드가 없습니다. 현실적인 방법은 (a) 검토를 위해 비공개 Slack 채널에 결과를 게시하거나, (b) 감사 목적으로 Google 시트에 기록하거나, (c) `clear` 판정 시 해당 인물을 "심사 완료 자원봉사자" B1 그룹에 추가하는 것입니다.

## 자주 쓰는 레시피

### 2년마다 자원봉사자 재심사

위 흐름을 Make 예약 트리거와 결합하세요.

- **트리거** — Make: 예약(매월)
- **작업** — B1.church: "심사 완료 자원봉사자" 그룹 회원 목록 조회
- **작업** — Make로 필터링: 심사 완료일이 22개월 이상 지난 경우
- **작업** — Checkr: 신원조회 초대장 생성(최초 흐름과 동일)

### 조회가 완료될 때까지 1단계 접근 차단

교회가 B1 그룹 소속을 접근 제어에 사용한다면(예: "심사 완료" 그룹 회원만 섬김 일정에 표시), Checkr의 `report.completed` 이벤트가 상태를 전환할 때까지 새 자원봉사자를 대기 그룹에 두세요.

## 제한 사항 및 참고 사항

- **Checkr는 대부분의 심사 패키지에 대해 미국 전용입니다.** 호주, 영국, 캐나다 교회는 대체 수단이 필요합니다.
- **가격은 조회당 부과됩니다** — Make에서 실행하는 모든 초대장 생성은 실제 조회 비용이 발생합니다. 먼저 Checkr의 샌드박스/스테이징 계정에서 테스트하세요(Make의 Checkr 앱은 연결에 전달된 자격 증명을 그대로 사용하므로, 자격 증명을 교체하면 샌드박스/실서비스가 전환됩니다).
- **Checkr API 접근은 요금제에 따라 제한됩니다.** 소규모 Checkr 계정은 UI 전용 등급일 수 있습니다. API를 활성화하려면 Checkr에 문의하세요.

## 문제 해결

- **후보자 생성이 `403` 오류로 실패함** — Checkr API 토큰이 읽기 전용이거나 필요한 계정 권한이 없는 경우입니다. Checkr 대시보드에서 쓰기 권한으로 다시 발급하세요.
- **초대장이 도착하지 않음** — 3단계에서 후보자의 이메일을 확인하세요. B1에 해당 인물의 이메일 필드가 비어 있을 수 있습니다. Checkr 단계 이전에 이메일 필수 필터를 추가하세요.
- **웹훅 트리거가 실행되지 않음** — Make 계정이 아웃바운드 웹훅을 지원하는 유료 등급이 아니면 Checkr의 웹훅 등록이 조용히 실패하는 경우가 있습니다. Checkr 대시보드의 *Webhooks* 페이지에서 Make의 URL이 등록되어 있는지 확인하세요.
