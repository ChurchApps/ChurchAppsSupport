# Zapier

<div class="article-intro">

공식 B1.church Zapier 앱을 사용하면 Zap이 교회 내 이벤트(신규 인물, 신규 헌금, 신규 그룹 회원 등)에 반응하고, 그 결과를 다시 B1에 기록하도록 만들 수 있습니다. 코딩도, 인프라 구축도 필요 없습니다 — Zapier의 드래그 앤 드롭 편집기에서 연결을 구성하고, API 키를 붙여넣은 다음, Zap을 켜기만 하면 됩니다.

</div>

<div class="prereqs">
<h4>시작하기 전에</h4>

- [Zapier](https://zapier.com) 계정(무료 요금제로도 Zap 몇 개 정도는 충분합니다)
- B1Admin에서 **설정 편집** 권한을 가진 교회 관리자(API 키를 생성하게 됩니다)
- 무엇을 하고 싶은지에 대한 아이디어 — 예: "B1에 인물이 추가되면 내 Mailchimp 목록에도 추가한다"

</div>

## 트리거와 작업

| 유형 | 내용 | B1 이벤트 / 엔드포인트 |
|---|---|---|
| **트리거** | 신규 인물 | `person.created` |
| **트리거** | 인물 업데이트됨 | `person.updated` |
| **트리거** | 신규 헌금 | `donation.created` |
| **트리거** | 신규 그룹 회원 | `group.member.added` |
| **트리거** | 신규 양식 제출 | `form.submission.created` |
| **작업** | 인물 생성 | 새 인물 추가 |
| **작업** | 헌금 추가 | 헌금 기록 |
| **작업** | 그룹 회원 추가 | 그룹에 인물 추가 |
| **작업** | 인물 찾기 | ID, 이메일 또는 이름으로 인물 조회; 일치하는 사람이 없으면 작업 실패 |

이 기능들을 Zapier가 지원하는 7,000개 이상의 앱과 자유롭게 조합할 수 있습니다.

## 설정

### 1. B1 API 키 생성

1. B1Admin에서 **설정 → 개발자 → API 키**로 이동합니다.
2. **새 API 키**를 클릭하고, "Zapier"처럼 이름을 지정한 다음 Zap에 필요한 범위를 선택합니다.
3. **중요:** Zapier 트리거는 Zap이 켜질 때 사용자를 대신해 웹훅을 등록하므로 **`settings:write`** 범위가 필요합니다. B1 트리거를 사용하는 모든 Zap에는 항상 `settings:write`를 포함하세요.
4. 작업에 필요한 범위도 함께 부여합니다 — 예를 들어 "헌금 추가" 작업에는 `donations:write`가, "인물 생성"에는 `people:write`가 필요합니다.
5. 저장합니다. 전체 `cak_…` 키는 **한 번만** 표시되므로 복사해 두세요.

### 2. Zapier를 B1에 연결하기

1. Zapier에서 새 Zap을 만듭니다.
2. B1 트리거나 작업을 처음 선택하면 Zapier가 **B1.church에 로그인**하라고 안내합니다.
3. 1단계에서 생성한 API 키를 붙여넣고 **예, 계속**을 클릭합니다. Zapier가 교회 정보에 대해 키를 검증합니다.

이 연결은 Zapier에 저장되며, 계정 내 모든 Zap에서 재사용됩니다.

### 3. Zap 만들기

트리거를 선택한 다음 하나 이상의 작업 단계를 추가합니다. 아래 예시를 참고하세요.

## 자주 쓰는 레시피

### 새로운 B1 인물을 Mailchimp에 추가하기

- **트리거** — B1: 신규 인물
- **작업** — Mailchimp: 구독자 추가/업데이트. B1의 `name__first`, `name__last`, `contactInfo__email`을 Mailchimp의 이름 / 성 / 이메일 필드에 매핑합니다.

### 기본 커넥터보다 풍부한 카드로 헌금 내역을 Slack 채널에 게시하기

- **트리거** — B1: 신규 헌금
- **작업** — Slack: 채널 메시지 보내기. 기본 제공 [Slack 커넥터](./slack-discord)로는 만들 수 없는 버튼, 첨부 파일 등 다양한 레이아웃을 자유롭게 구성합니다.

### 새로운 그룹 회원을 Google 그룹스에 추가하기

- **트리거** — B1: 신규 그룹 회원(특정 `groupId`로 필터링)
- **작업** — Zapier로 필터링: 관심 있는 B1 그룹인 경우에만 계속 진행
- **작업** — B1: 인물 찾기(트리거의 `personId`를 사용해 이메일 조회)
- **작업** — Google 그룹스: 회원 추가

### 양식 제출 내용을 프로젝트 관리 도구로 전달하기

- **트리거** — B1: 신규 양식 제출
- **작업** — Notion / Linear / Asana / Trello: 페이지 / 이슈 / 작업 생성

## 트리거가 내부적으로 동작하는 방식

트리거는 폴링 방식이 아니라 **REST 훅** 방식입니다 — Zapier가 15분마다 B1을 확인하는 방식이 아닙니다. Zap을 켜면 Zapier가 B1에 요청해 비공개 Zapier URL을 가리키는 웹훅을 등록합니다. 이벤트가 발생하면 B1이 해당 이벤트 데이터를 Zapier로 POST하고, Zap은 **몇 초 이내에** 실행됩니다. Zap을 끄면 Zapier가 B1에 요청해 웹훅을 삭제합니다 — 남는 구독은 없습니다.

즉, 트리거는 Zap을 켠 **이후에** 발생한 이벤트에 대해서만 실행됩니다. 소급 반영은 없습니다 — Zap을 켠다고 해서 어제의 헌금 내역이 다시 재생되지는 않습니다.

## 제한 사항 및 참고 사항

- **동일한 트리거를 사용하는 여러 Zap**은 각각 자체 B1 웹훅을 등록합니다 — 충돌은 없지만, **설정 → 개발자 → 웹훅**을 확인하다가 동일한 `Zapier — donation.created` 행이 세 개나 있는 이유가 궁금하다면 이 점을 알아두면 도움이 됩니다.
- **Zap 설정 시 테스트 데이터** — Zap을 만들 때 Zapier는 필드를 매핑할 수 있도록 샘플 데이터를 요청합니다. B1에 일치하는 최근 이벤트가 있으면 그것을 가져오고, 없으면 앱 정의에 포함된 가상의 샘플 데이터를 사용합니다.
- **작업 실패는 Zapier의 작업 기록에 Zap 오류로 표시됩니다.** 흔한 원인은 필요한 범위가 없는 API 키입니다(예: "헌금 추가" 작업에는 `donations:write`가 필요). 올바른 범위로 키를 다시 발급하고 Zapier에서 다시 연결하세요.
- **아웃바운드 API 호출 할당량** — 작업에서 발생하는 모든 B1 API 호출은 B1 측이 아니라 Zapier의 작업 할당량에 반영됩니다.

## 문제 해결

- **연결 시 "인증 실패"** — API 키가 잘못되었거나, 폐기되었거나, Zap에 필요한 범위가 빠져 있는 경우입니다. B1Admin에서 최소 `settings:write`와 Zap이 다루는 리소스에 필요한 범위를 포함해 키를 다시 발급하고 연결을 업데이트하세요.
- **트리거가 실행되지 않음** — 웹훅이 실제로 등록되었는지 확인하세요. B1Admin의 **설정 → 개발자 → 웹훅**에 "Zapier — &lt;이벤트&gt;"라는 행이 표시되어야 합니다. 표시되지 않는다면 Zap을 켰을 때 API 키에 `settings:write`가 없었을 가능성이 큽니다. 키를 수정한 다음 Zap을 껐다 다시 켜세요.
- **트리거가 두 번 실행됨** — Zapier의 확인 응답이 유실되면 이벤트를 다시 전송하는 경우가 간혹 있습니다. 엄격한 중복 방지가 필요하다면 고유 ID(예: 인물의 `id`)를 기준으로 "Zapier로 필터링" 단계를 추가하세요.
