# 계정 삭제 요청 검토

<div class="article-intro">

교회에 디렉터리 승인 그룹이 구성된 경우, 계정 삭제가 더 이상 즉시 일어나지 않습니다. 회원의 요청이 무언가가 제거되기 전에 승인 그룹이 검토할 작업이 됩니다. 이 페이지는 요청이 어떻게 이루어지는지, 승인하거나 거절하는 방법, 각 경우에 어떤 일이 발생하는지 설명합니다.

</div>

<div class="prereqs">
<h4>시작하기 전에</h4>

- **디렉터리 승인 그룹**이 **Mobile → Member portal** 아래에 구성되어 있어야 합니다. 구성되지 않은 경우, 프로필 페이지에서 **내 계정 삭제**를 클릭하면 검토 단계 없이 계정이 즉시 삭제됩니다. [모바일 앱 설정](../settings/mobile-app.md)을 참조하세요.
- 요청을 승인하거나 거절하려면 **사람들 &gt; 편집** 권한이 필요합니다.

</div>

## 회원이 삭제를 요청하는 방법

계정 삭제는 [프로필 관리](./managing-profile.md)에서 다루는 동일한 공유 계정 페이지인 **내 프로필** 페이지의 **계정 삭제** 섹션에서 요청됩니다. 승인 그룹이 구성된 경우, 요청을 확인해도 즉시 아무것도 삭제되지 않습니다. 대신 다음을 수행합니다:

1. **Serving → Tasks**에서 디렉터리 승인 그룹에 할당된 **"계정 삭제 요청"** 제목의 열린 작업을 만듭니다.
2. 해당 사람의 **내 계정 삭제** 버튼을 비활성화하고 요청이 검토 대기 중임을 나타내는 알림을 표시합니다.

요청이 이미 열려 있는 동안 두 번째 요청을 제출하면 동일한 작업만 다시 열게 됩니다. 한 사람은 한 번에 하나의 보류 중인 삭제 요청만 가질 수 있습니다.

## 요청 검토

1. **Serving → Tasks**(또는 대시보드의 **내 그룹에 할당됨**, [프로필 변경 요청](./approving-profile-changes.md)이 나타나는 동일한 위치)로 이동합니다.
2. **"*이름*의 계정 삭제 요청"** 제목의 작업을 엽니다.
3. **삭제 승인** 및 **거절** 두 가지 작업이 표시됩니다.

### 승인

**"이 사람의 기록을 영구적으로 익명 처리하고 로그인을 제거하시겠습니까? 이는 취소할 수 없습니다."**를 확인합니다. 이는 사람의 개인 정보를 일반 값으로 바꾸고(사람의 기록에서 **데이터 관리 &gt; 익명 처리** 작업으로 사용되는 것과 동일한 익명 처리) 로그인을 제거합니다. 작업이 자동으로 닫히고 회원에게 요청이 승인되었음을 알립니다.

### 거절

거절에는 GDPR이 삭제 요청을 거절하는 것을 법적 예외에만 허용하기 때문에 이유가 필요합니다:

- **법적 보유** (기부금, 세금 또는 고용 기록)
- **법적 청구에 필요**
- **기타** -- 텍스트 상자에 설명하세요 (최소 10자)

회원에게 결정과 제공한 이유가 통지되며, 동의하지 않는 경우 요청을 다시 제출하거나 감독 당국에 상담할 수 있습니다.

:::info
교회는 삭제 요청에 응답할 30일의 시간이 있습니다. 작업은 28일 내에 마감되고, 21일과 27일이 지난 후에도 여전히 열려 있으면 승인 그룹은 자동 알림을 받습니다.
:::

:::tip
삭제 및 프로필 변경 요청은 동일한 디렉터리 승인 그룹 및 동일한 작업 기반 검토 흐름을 사용합니다. 디렉터리 업데이트 요청도 검토해야 하는 경우 [프로필 변경 승인](./approving-profile-changes.md)을 참조하세요.
:::
