# 계정 삭제 요청 검토

<div class="article-intro">

교회에 디렉토리 승인 그룹이 설정되어 있으면 계정 삭제가 더 이상 즉시 수행되지 않습니다. 회원의 요청이 승인 그룹이 검토한 후에야 삭제되는 작업이 됩니다. 이 페이지는 요청이 어떻게 이루어지는지, 승인 또는 거부하는 방법, 그리고 각 경우에 무슨 일이 발생하는지 설명합니다.

</div>

<div class="prereqs">
<h4>시작하기 전에</h4>

- **디렉토리 승인 그룹**이 **모바일 → 회원 포털** 아래에 설정되어야 합니다. 설정되지 않으면 프로필 페이지에서 **내 계정 삭제**를 클릭하면 검토 단계 없이 계정이 즉시 삭제됩니다. [모바일 앱 설정](../settings/mobile-app.md)을 참조하세요.
- 요청을 승인 또는 거부하려면 **사람 > 편집** 권한이 필요합니다.

</div>

## 회원이 삭제를 요청하는 방법

계정 삭제는 [프로필 관리](./managing-profile.md)에서 다루는 동일한 공유 계정 페이지인 **내 프로필** 페이지에서 요청되며, **계정 삭제** 섹션 아래에 있습니다. 승인 그룹이 설정되어 있으면 요청을 확인해도 아무것도 즉시 삭제되지 않습니다. 대신 다음과 같이 합니다:

1. **봉사 → 내 작업** 아래 **"계정 삭제 요청"**이라는 제목의 공개 작업을 생성하여 디렉토리 승인 그룹에 할당합니다.
2. 해당 사람의 **내 계정 삭제** 버튼을 비활성화하고 요청이 검토 대기 중임을 알리는 공지를 표시합니다.

이미 열려 있는 요청이 있는 동안 두 번째 요청을 제출하면 같은 작업을 다시 엽니다. 한 사람은 한 번에 하나의 보류 중인 삭제 요청만 가질 수 있습니다.

## 요청 검토

1. **봉사 → 내 작업**으로 이동합니다 (또는 대시보드의 **내 그룹에 할당됨** - [프로필 변경 요청](./approving-profile-changes.md)이 나타나는 같은 위치).
2. **"*이름*의 계정 삭제 요청"**이라는 제목의 작업을 엽니다.
3. 두 가지 작업이 표시됩니다: **삭제 승인** 및 **거부**.

### 승인

**"이 사람의 기록을 영구적으로 익명화하고 로그인을 제거하시겠습니까? 이 작업은 실행 취소할 수 없습니다."**를 확인합니다. 이렇게 하면 해당 사람의 개인정보가 일반적인 값으로 바뀌고 (사람의 기록에 있는 **데이터 관리 > 익명화** 작업에서 사용하는 동일한 익명화 - [데이터 보안](../settings/data-security.md) 참조) 로그인이 제거됩니다. 작업이 자동으로 종료되고 회원에게 요청이 승인되었음을 알립니다.

### 거부

거부하려면 이유가 필요합니다. GDPR은 법적 예외의 경우에만 삭제 요청을 거부할 수 있기 때문입니다:

- **법적 보관** (기부금, 세금, 또는 고용 기록)
- **법적 청구에 필요**
- **기타** — 텍스트 상자에서 설명 (최소 10자)

회원에게 결정과 제공한 이유가 통지되며, 동의하지 않으면 요청을 다시 제출하거나 감독 기관에 진정할 수 있습니다.

:::info
교회는 삭제 요청에 응답하기 위해 30일이 있습니다. 작업은 28일 후에 기한이 지나며, 21일 및 27일 후에도 여전히 열려 있으면 승인 그룹이 자동 알림을 받습니다.
:::

:::tip
삭제 및 프로필 변경 요청은 동일한 디렉토리 승인 그룹과 동일한 작업 기반 검토 흐름을 사용합니다. 디렉토리 업데이트 요청도 검토해야 하면 [프로필 변경 승인](./approving-profile-changes.md)을 참조하세요.
:::
