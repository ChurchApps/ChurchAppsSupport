# 그룹 가입 요청

<div class="article-intro">

그룹이 승인 기반의 가입 정책으로 설정되어 있으면, 사람들이 가입을 요청할 수 있습니다. 그룹 리더와 관리자는 이 요청을 검토하고 승인하거나 거절합니다. 이렇게 하면 교회가 그룹 구성원을 관리하면서도 사람들이 가입에 관심을 표현하기 쉬워집니다.

</div>

- 그룹의 가입 정책이 **Request**(승인 필요)로 설정되어 있어야 합니다. 가입 정책을 설정하는 방법은 [그룹 만들기](./creating-groups.md)를 참조하세요.

## 가입 정책 이해하기 {#understanding-join-policies}

그룹에는 세 가지 가입 정책이 있을 수 있습니다.

- **Open** -- 승인 없이 누구나 바로 가입할 수 있습니다.
- **Request** -- 사람들이 승인이 필요한 가입 요청을 제출합니다.
- **Closed** -- 아무도 가입을 요청할 수 없습니다(구성원은 직접 추가해야 합니다).

그룹이 **Request** 정책을 사용하면, 모든 가입 시도는 이 페이지에서 설명하는 승인 절차를 거칩니다.

## 대기 중인 요청 보기 {#viewing-pending-requests}

### 그룹 리더용 {#for-group-leaders}

1. B1 Admin에서 [점프 메뉴](../introduction.md#getting-around-with-the-jump-menu)를 열고 **People > Groups**를 선택합니다.
2. 그룹 이름을 클릭합니다.
3. **Members** 섹션에는 대기 중인 요청 수가 표시됩니다(예: "1 pending"). **All members**를 클릭하면 이 그룹의 대기 중인 요청이 구성원 목록 맨 위의 **Pending Requests** 아래에 나타납니다.

### 관리자용 {#for-administrators}

그룹 관리 권한이 있는 관리자는 모든 그룹의 대기 중인 요청을 볼 수 있습니다.

1. 점프 메뉴에서 **People > Groups**를 선택합니다.
2. 페이지 머리글의 **pending requests** 버튼을 클릭합니다(예: "3 pending requests"). 대기 중인 요청이 있을 때만 나타납니다.
3. **Pending Join Requests** 페이지에는 교회 전체의 모든 대기 중인 요청이 나열되며, 각 사람의 이름 옆에 가입을 요청한 그룹이 표시됩니다. 페이지 상단의 **Groups**를 클릭하면 돌아갑니다. 대기 중인 요청이 없으면 페이지에 **No pending requests**.가 표시됩니다.

## 가입 요청 검토하기 {#reviewing-a-join-request}

각 가입 요청에는 다음이 표시됩니다.

- **사람의 이름과 사진** -- 가입을 요청한 사람입니다(교회 전체 페이지에서는 그룹도 표시됩니다).
- **선택 사항인 메시지** -- 가입하고 싶은 이유를 설명하는 개인 메시지입니다(제공된 경우).
- **요청 날짜** -- 요청이 제출된 날짜입니다.

요청을 검토하려면 다음과 같이 합니다.

1. 메시지가 있다면 읽어 봅니다.
2. 필요하면 사람의 이름을 클릭해 프로필을 엽니다.
3. 승인할지 거절할지 결정합니다.

## 요청 승인하기 {#approving-a-request}

1. 가입 요청에서 **Approve**를 클릭합니다.
2. 그 사람은 즉시 그룹의 구성원으로 추가되고, 요청은 목록에서 사라집니다.
3. 요청자에게 승인되었다는 알림이 전달됩니다.
4. 시스템에서 요청이 승인됨으로 표시됩니다.

:::tip
요청을 승인하면 그 사람은 일반 그룹 구성원이 됩니다. 나중에 필요하면 [그룹 구성원](./group-members.md) 페이지에서 그 사람을 그룹 리더로 승격할 수 있습니다.
:::

## 요청 거절하기 {#declining-a-request}

1. 가입 요청에서 **Decline**을 클릭합니다.
2. **Decline Request** 대화상자에서 선택 사항인 **Reason (optional)**(사유, 선택 사항)을 입력합니다(최대 500자).
3. **Decline**을 클릭합니다.
4. 요청자에게 거절 사유(제공된 경우)가 담긴 알림이 전달됩니다.
5. 시스템에서 요청이 거절됨으로 표시됩니다.

:::info
거절 사유를 알려 주면 그 사람이 요청이 승인되지 않은 이유를 이해하는 데 도움이 되며, 나중에 다시 시도하거나 다른 그룹을 알아보도록 격려할 수 있습니다.
:::

## 작업 페이지에서 승인하기 {#approving-from-the-tasks-page}

모든 가입 요청은 **Serving &rarr; My Work** 아래에 "*사람* requested to join *그룹*"이라는 제목의 작업도 만듭니다. 이 작업은 그룹의 리더에게 배정됩니다. 그룹에 리더가 아직 없다면 **Group Members &gt; Edit** 권한이 있는 직원에게 가고, 아무도 그 권한이 없다면 교회의 도메인 관리자에게 갑니다. 이 방식으로 작업을 받은 직원과 관리자는 작업으로 바로 연결되는 알림도 받습니다.

작업을 열면 요청자의 이름, 그룹, 선택 사항인 메시지가 표시되며, 작업 카드에 **Approve**와 **Decline** 버튼이 바로 있습니다(Decline을 누르면 위에서 설명한 선택 사항인 사유 입력란이 열립니다). 리더는 그룹의 구성원 목록을 열지 않고도 알림을 통해 요청에 대응할 수 있습니다.

그룹의 구성원 목록이나 작업 카드 중 어느 쪽에서든 요청을 처리하면, 요청은 모든 곳에서 닫힙니다. 그래서 리더가 이미 처리된 요청의 오래된 작업을 보는 일이 없습니다.

## 알림 {#notifications}

가입 요청 시스템은 자동으로 알림을 보냅니다.

- **요청이 제출되었을 때** -- 모든 그룹 리더에게 알림이 갑니다. 그룹에 리더가 없다면 대신 작업이 배정된 직원이나 관리자에게 알림이 갑니다(위 참조).
- **요청이 승인되었을 때** -- 요청자에게 확인 알림이 갑니다.
- **요청이 거절되었을 때** -- 요청자에게 거절 사유(있는 경우)가 담긴 알림이 갑니다.

알림은 B1.church의 알림 센터와 모바일 앱에 나타납니다. B1 Admin의 알림 종 아이콘에서 가입 요청 알림(또는 **View Details**)을 클릭하면, 교회의 B1.church 사이트에서 그룹이 새 탭으로 열립니다.

## 구성원 쪽에서 요청 관리하기 {#managing-requests-from-the-member-side}

사람들은 B1.church에서 자신의 가입 요청을 관리할 수 있습니다.

- 그룹 세부 정보 페이지에서 자신의 대기 중인 요청 상태를 봅니다.
- 마음이 바뀌면 대기 중인 요청을 취소합니다.
- 요청이 승인되었는지 거절되었는지 확인합니다.

## 권장 사항 {#best-practices}

- **신속하게 응답하세요** -- 사람들이 오래 기다리지 않도록 24~48시간 안에 요청을 검토하려고 노력하세요.
- **거절 사유는 분명하게 쓰세요** -- 다음 단계나 대안을 이해할 수 있도록 도와주세요.
- **프로필을 확인하세요** -- 그 사람이 그룹에 잘 맞는지 프로필을 검토하세요.
- **기대치를 전달하세요** -- 그룹 설명에 그룹이 누구를 위한 것인지 분명히 적으세요.
