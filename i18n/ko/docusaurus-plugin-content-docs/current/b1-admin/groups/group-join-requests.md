# 그룹 참가 요청

<div class="article-intro">

그룹이 승인 기반 참가 정책으로 구성되어 있으면 사람들이 참가 요청을 제출할 수 있습니다. 그룹 리더와 관리자는 이러한 요청을 검토하고 승인하거나 거부합니다. 이는 교회가 그룹 멤버십을 제어하면서 사람들이 참가에 관심을 표현하기 쉽게 만듭니다.

</div>

<div class="prereqs">
<h4>시작하기 전에</h4>

- 그룹을 관리할 수 있는 권한이 필요하거나 특정 그룹의 리더여야 합니다. 세부 정보는 [Roles & Permissions](../people/roles-permissions.md)를 참조합니다.
- 그룹은 참가 정책이 **Request**로 설정되어야 합니다(승인 필요). 참가 정책을 구성하는 방법은 [Creating Groups](./creating-groups.md)를 참조합니다.

</div>

## 참가 정책 이해

그룹은 3가지 다른 참가 정책을 가질 수 있습니다:

- **Open** -- 누구나 승인 없이 즉시 참가할 수 있습니다
- **Request** -- 사람들이 승인이 필요한 참가 요청을 제출합니다
- **Closed** -- 참가를 요청할 수 없습니다(멤버는 수동으로 추가되어야 함)

그룹이 **Request** 정책을 사용하면 모든 참가 시도가 이 페이지에 설명된 승인 워크플로우를 거칩니다.

## 보류 중인 요청 보기

### 그룹 리더의 경우

1. B1 Admin에서 [Jump 메뉴](../introduction.md#getting-around-with-the-jump-menu)를 열고 **People > Groups**를 선택합니다
2. 그룹 이름을 클릭합니다
3. 이 그룹의 보류 중인 요청이 **Members** 탭의 상단에 나타납니다

### 관리자의 경우

그룹 관리 권한이 있는 관리자는 모든 그룹의 보류 중인 요청을 볼 수 있습니다:

1. Jump 메뉴에서 **People > Groups**를 선택합니다
2. 페이지 헤더의 **pending requests** 버튼을 클릭합니다(예: "3 pending requests"). 대기 중인 요청이 있을 때만 나타납니다.
3. 모든 보류 중인 요청을 교회 전체에서 검토합니다

## 참가 요청 검토

각 참가 요청은 다음을 표시합니다:

- **Person's name and photo** -- 참가를 요청하는 사람
- **Optional message** -- 참가하려는 이유를 설명하는 개인 메시지(제공된 경우)
- **Request date** -- 요청이 제출된 시점

요청을 검토하려면:

1. 제공된 경우 개인의 메시지를 읽습니다
2. 필요하면 개인의 이름을 클릭하여 프로필을 봅니다
3. 승인할지 거부할지 결정합니다

## 요청 승인

1. 참가 요청에서 **Approve**를 클릭합니다
2. 해당 사람이 즉시 그룹의 멤버로 추가됩니다
3. 요청자는 요청이 승인되었다는 알림을 받습니다
4. 요청이 시스템에서 승인으로 표시됩니다

:::tip
요청을 승인하면 해당 사람은 일반 그룹 멤버가 됩니다. 나중에 [Group Members](./group-members.md) 페이지에서 그룹 리더로 승격할 수 있습니다.
:::

## 요청 거부

1. 참가 요청에서 **Decline**을 클릭합니다
2. 선택적으로 거부 이유를 제공합니다(최대 500자)
3. **Confirm**을 클릭합니다
4. 요청자는 거부 이유(제공된 경우)와 함께 알림을 받습니다
5. 요청이 거부로 표시됩니다

:::info
거부 이유를 제공하면 사람이 요청이 승인되지 않은 이유를 이해할 수 있고 나중에 다시 시도하거나 다른 그룹을 탐색하도록 격려할 수 있습니다.
:::

## 작업 페이지에서 승인

모든 참가 요청은 **Serving → My Work** 아래의 작업을 만들기도 합니다. 제목은 "*Person* requested to join *Group*"입니다. 그룹의 리더에게 할당됩니다. 그룹에 리더가 없으면 **Group Members > Edit** 권한이 있는 직원 또는 그 권한이 없으면 교회의 도메인 관리자에게 이동합니다. 이런 식으로 작업을 받는 직원 및 관리자도 직접 이동할 수 있는 알림을 받습니다.

작업을 열면 요청자의 이름, 그룹 및 선택적 메시지가 표시되며 작업 카드(Decline은 위에 설명된 선택적 이유 필드를 엽니다)에서 **Approve** 및 **Decline** 버튼이 있습니다. 이는 리더에게 그룹의 참가 요청 탭으로 이동하지 않고 요청에 대해 조치할 수 있는 두 번째 알림 중심의 방법을 제공합니다.

두 위치(그룹의 참가 요청 탭 또는 작업 카드)에서 요청을 결정하면 모든 위치에서 닫히므로 리더는 누군가가 이미 처리한 요청에 대해 오래된 작업을 보지 않습니다.

## 알림

참가 요청 시스템은 자동으로 알림을 보냅니다:

- **요청이 제출될 때** -- 모든 그룹 리더가 알림을 받습니다. 그룹에 리더가 없으면 작업이 할당된 직원 또는 관리자가 대신 알림을 받습니다(위 참조).
- **요청이 승인될 때** -- 요청자는 확인을 받습니다
- **요청이 거부될 때** -- 요청자는 거부 이유와 함께 알림을 받습니다

알림은 B1.church 및 모바일 앱의 알림 센터에 나타납니다.

## 멤버 측에서 요청 관리

사람들은 B1.church에서 자신의 참가 요청을 관리할 수 있습니다:

- 그룹 세부 정보 페이지에서 보류 중인 요청의 상태 보기
- 생각을 바꾸면 보류 중인 요청 취소
- 요청이 승인되었는지 거부되었는지 확인

## 모범 사례

- **신속하게 응답** -- 사람들이 기다리지 않도록 48시간 내에 요청을 검토해보십시오
- **거부 이유를 명확하게** -- 사람들이 다음 단계나 대체 옵션을 이해할 수 있도록 도와줍니다
- **프로필 확인** -- 사람의 프로필을 검토하여 그룹에 적합한지 확인합니다
- **기대 사항 전달** -- 그룹 설명이 그룹이 누구를 위한 것인지 명확하게 명시하는지 확인합니다
