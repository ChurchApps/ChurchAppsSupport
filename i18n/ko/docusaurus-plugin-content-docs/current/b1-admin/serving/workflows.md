# 워크플로

<div class="article-intro">

워크플로는 시각적인 보드에서 사람들을 여러 단계를 거쳐 이동시킵니다. 각 사람은 하나의 카드가 되어 한 단계에서 다음 단계로 이동합니다. 처음 방문한 손님을 위한 후속 연락, 교인 등록 과정, 처음 헌금한 사람에게 보내는 감사 인사 등 같은 단계를 거치는 많은 사람을 추적해야 할 때 무엇이든 사용할 수 있습니다. 단계에서 봉사자가 무언가를 하도록(전화하기, 대화 나누기) **그리고** 스스로 자동 작업(이메일이나 문자 보내기, 며칠 기다리기, 그룹에 사람 추가하기)을 실행할 수 있으므로, 워크플로는 사람이 하는 후속 연락과 그 주변의 번거로운 일을 모두 처리합니다. 워크플로는 [작업](./tasks.md)을 드래그 앤 드롭 방식의 칸반 보드로 확장하여 누구도 놓치지 않도록 해 줍니다.

</div>

<div class="prereqs">
<h4>시작하기 전에</h4>

- 추적할 사람이 B1 Admin에 등록되어 있는지 확인하세요
- 보드의 각 카드가 작업이므로 [작업](./tasks.md)의 작동 방식을 익혀 두세요
- **Send email** 작업을 사용하려면 먼저 보낼 이메일 템플릿을 만드세요(**Settings → Email Templates**에서 관리합니다)
- **Send text** 작업을 사용하려면 먼저 [문자 서비스 제공업체](../settings/church-settings.md#texting)를 연결하세요
- 적절한 Tasks 권한이 필요합니다. 보기, 카드 편집, 워크플로 관리는 각각 별도의 권한 수준입니다([역할 및 권한](../settings/roles-permissions.md) 참고)

</div>

## 워크플로 보기

[Jump 메뉴](../introduction.md#getting-around-with-the-jump-menu)(B1 Admin 왼쪽 상단의 검색창)를 열고 **Serving**을 펼친 다음 **Workflows**를 클릭합니다. 워크플로가 각각의 **Category**와 **Status**(**Active** 또는 **Inactive**)를 보여 주는 표에 나열됩니다. 카테고리를 사용하는 경우 목록 위의 탭으로 카테고리별로 필터링할 수 있습니다. 워크플로를 클릭하면 해당 보드가 열립니다.

## 워크플로 만들기

1. 워크플로 페이지에서 **Add Workflow**를 클릭합니다.
2. 시작 방법을 선택합니다.
   - **Blank workflow** -- 처음부터 시작하여 직접 단계를 만듭니다.
   - **From a template** -- 편집할 수 있는 기성 단계 세트로 시작합니다. 기본 제공 템플릿은 다음과 같습니다.
     - **New Visitor Follow-up** -- 환영 이메일 발송 → 개인 전화 → 다음 단계 초대 → Connected
     - **Membership Class** -- 관심 표현 → 수업 등록 → 수업 참석 → 교인 등록 완료
     - **First-time Giver Thank-you** -- 감사 편지 발송 → 헌금의 영향 나누기 → Stewarded
     - **Serving Assignment Confirmation** -- 요청을 보내고 응답 기다리기 → 응답 없는 요청에 대해 봉사자에게 전화하기([봉사 배정 확인](#serving-assignment-confirmations) 참고)

   템플릿의 단계를 만드는 데 잠시 걸릴 수 있습니다. 작업 중에는 **Add Workflow** 버튼에 **Creating...**이 표시되며 다시 클릭할 수 없으므로 워크플로가 중복으로 생성되지 않습니다. 문제가 생기면 *"The workflow could not be created. Please try again."*이 표시됩니다.
3. 워크플로의 **Name**을 입력합니다.
4. 선택 사항으로 **Category**를 지정하여 관련 워크플로를 함께 묶을 수 있습니다. 드롭다운에서 바로 새 카테고리를 만들 수도 있습니다.
   빈 워크플로의 경우 **Workflow purpose**도 선택합니다. **People follow-up**(일반적인 용도) 또는 **Serving assignment confirmation** 중에서 고릅니다. 목적은 워크플로를 만든 후에는 바꿀 수 없습니다.
5. 사람들을 워크플로에 추가할 수 있도록 **Active** 상태로 두거나, 워크플로 추가 목록에서 숨기려면 **Inactive**로 설정합니다.
6. **Save**를 클릭합니다.

:::tip
워크플로 목록의 **Duplicate** 버튼을 사용하면 단계, 자동 작업, 경로 설정을 포함한 기존 워크플로를 복사하여 새 워크플로의 출발점으로 쓸 수 있습니다.
:::

## 단계로 보드 구성하기

각 워크플로 보드는 왼쪽에서 오른쪽으로 열(column)로 표시되는 **단계**로 구성됩니다. 워크플로를 열고 **Add Step**을 사용하여 과정의 각 단계를 만듭니다.

단계를 추가하거나 편집할 때 다음 항목을 설정할 수 있습니다.

- **Step Name** -- 열의 제목입니다(예: "Welcome Call" 또는 "Awaiting Registration").
- **Due in (days)** -- 카드가 이 단계에 들어올 때 마감일을 자동으로 설정합니다. 마감일이 지난 카드에는 **Overdue** 표시가 붙습니다.
- **Default assignee** -- 이 단계의 새 카드가 자동으로 배정될 사람 또는 그룹입니다. 기본 담당자가 사람이면 카드가 배정되었다는 알림을 받습니다.
- **Automated actions** -- 카드가 도착할 때 시스템이 스스로 실행하는 작업입니다(아래 참고).
- **Routing** -- 카드가 단계를 떠날 때 이동할 위치입니다([경로 설정](#routing-cards-with-outcomes-and-conditions) 참고).

단계 열을 드래그하여 과정에 맞는 순서로 배치하세요. 이 순서는 다른 경로가 적용되지 않을 때 카드가 따르는 기본 경로이기도 합니다.

:::info
새 단계는 먼저 저장하세요. 자동 작업과 경로 설정은 단계에 연결되므로, 단계가 있어야 편집기에서 해당 섹션이 활성화됩니다.
:::

## 자동 작업

모든 단계에는 카드가 단계에 **들어오는** 순간 스스로 실행되는 **자동 작업** 목록을 설정할 수 있습니다. 누군가 카드를 건드리기 전에 실행됩니다. 이를 통해 단계는 봉사자에게 알리는 동시에 후속 연락 주변의 일상적인 작업도 처리합니다.

단계 편집기에서 **Automated actions**를 열고 **Add Action**을 클릭한 다음 유형을 선택하고 설정을 입력합니다. 필요한 만큼 추가할 수 있으며, 작업은 **위에서 아래 순서대로** 실행됩니다. 단계의 **Save**를 클릭하면 단계와 모든 작업이 함께 저장됩니다. 휴지통 아이콘으로 작업을 제거하면 즉시 적용됩니다.

| 작업 | 설명 |
|---|---|
| **Send email** | 선택한 이메일 템플릿을 사람에게 보냅니다. 제목 줄을 바꿀 수 있습니다. |
| **Send text** | 교회의 [문자 서비스 제공업체](../settings/church-settings.md#texting)를 통해 작성한 메시지를 사람에게 보냅니다. |
| **Wait** | 다음 작업을 진행하기 전에 카드를 며칠 동안 멈춥니다(아래 참고). |
| **Add to group** | 선택한 [그룹](../groups/index.md)에 사람을 추가합니다. |
| **Remove from group** | 선택한 그룹에서 사람을 제거합니다. |
| **Record Attendance** | 진행 중인 그룹 예배 시간에 사람을 출석으로 표시합니다(아래 참고). |
| **Add to workflow** | 사람을 다른 워크플로에 시작시킵니다. 프로세스 간에 넘겨줄 때 유용합니다. |
| **Add note** | 카드의 기록에 메모를 남깁니다. |
| **Set field** | 사람의 기록 중 필드를 업데이트합니다. 교인 상태, 혼인 상태, 성별, 도시, 주, 우편번호가 해당됩니다. |
| **Webhook** | 카드의 세부 정보를 직접 입력한 외부 웹 주소(URL)로 보내 다른 시스템과 연결합니다. |
| **Create task** | 입력한 제목과 설명으로 [작업](./tasks.md)을 만들고 선택한 사람에게 배정합니다. |
| **Notify Person** | 카드에 관해 선택한 교직원이나 봉사자에게 이메일과 B1 알림을 보냅니다(아래 참고). |

단계의 모든 작업이 끝나면 카드는 사람이 처리할 수 있도록 **그 단계에 머무릅니다**. 단, 단계에 카드를 다음 단계로 자동으로 옮기는 경로가 있으면 예외입니다([완전 자동 단계](#fully-automated-steps) 참고).

:::info
자동 작업은 카드가 정상적인 흐름으로 들어올 때만 실행됩니다. 즉, 처음 추가되었을 때, 결과(outcome)나 자동 경로가 카드를 들여보냈을 때, 또는 Wait가 끝난 후입니다. 직원이 카드를 단계로 직접 끌어 놓거나 되돌릴 때는 다시 실행되지 **않으므로** 같은 사람이 같은 이메일을 두 번 받지 않습니다.
:::

### 이메일 보내기

**Send email**을 선택하고 이메일 템플릿 중 하나를 고른 다음, 필요하면 제목을 직접 입력합니다. 카드가 단계에 들어오면 해당 사람은 이메일을 자동으로 받습니다. (사람의 이메일 주소가 등록되어 있지 않으면 단계가 이 작업을 그냥 건너뜁니다.) 템플릿의 [병합 필드](../settings/email-templates.md#merge-fields)(예: `{{firstName}}`)는 해당 사람의 정보로 채워집니다.

이메일이 발송되면 카드의 기록에 **Email sent**가 남습니다. 이메일을 보낼 수 없으면(예: 교회 이메일이 아직 승인되지 않았거나 일일 한도에 도달한 경우) "Email sent" 항목은 추가되지 않습니다.

:::info
워크플로 이메일은 교회가 그룹 이메일 발송을 승인받은 후에만 발송되며, 교회의 일일 이메일 한도에 포함됩니다. [교회의 그룹 이메일 켜기](../groups/group-members.md#turning-on-group-email-for-your-church)를 참고하세요. 이 이메일이 발송되지 않을 때 **Send email** 작업은 단계 편집기에 경고를 표시합니다. 승인이 대기 중이면 *"Your church's email hasn't been approved yet..."*, 최근 메시지가 반송되었거나 스팸으로 신고되었다면 *"Your church's email is paused..."*가 표시됩니다.
:::

### 출석 기록하기

**Record Attendance**를 선택하고 **Pick group**을 클릭하여 출석을 기록할 그룹을 고릅니다. 작업이 실행되면 사람은 진행 중인 그룹 예배 시간에 출석한 것으로 표시됩니다. 체크인을 한 것과 같습니다. 사람이 도착할 때마다 워크플로에 추가하는 트리거와 함께 사용하면 별도의 체크인 없이 출석이 집계되므로 유용합니다.

- 출석은 카드가 **생성된** 순간을 기준으로 측정되므로 워크플로 앞부분의 **Wait**가 예배 시간을 넘어가게 만들지 않습니다.
- 요일과 시작 시간이 있는 예배 시간만 집계됩니다. 그 순간 그룹의 예배 시간 중 진행 중인 시간이 없으면 아무것도 기록되지 않으며, 카드의 기록에는 **No scheduled service in progress — attendance not recorded**가 남습니다.
- 출석이 기록되면 카드의 기록에 **Attendance recorded**와 그룹 이름이 표시됩니다. 같은 예배에 대해 작업을 다시 실행해도 같은 사람을 두 번 집계하지 않습니다.

### 사람에게 알리기

**Notify Person**을 선택하고 **Pick person**을 클릭한 다음 필요하면 **Message**를 입력합니다. 카드가 단계에 들어오면 해당 사람은 카드에 있는 사람의 이름, 워크플로와 단계 이름, 입력한 메시지, 카드를 여는 링크가 포함된 이메일과 B1 알림을 받습니다. 교직원이나 사역 리더에게 미리 알리고 싶을 때 사용합니다. 예를 들어 *"Notify the pastor when someone reaches the Membership Interview step."*처럼 설정할 수 있습니다. 카드의 기록에는 **Notified**와 해당 사람의 이름이 남습니다.

### 문자 보내기

**Send Text**를 선택하고 **Text message**(최대 1,600자)를 입력합니다. 카드가 단계에 들어오면 해당 사람은 휴대폰으로 문자를 받습니다. 메시지에 `{{firstName}}`, `{{lastName}}`, `{{displayName}}`, `{{churchName}}`을 넣어 개인화할 수 있으며, 문자가 발송될 때 해당 사람의 정보로 채워집니다.

- 사람의 휴대폰 번호가 등록되어 있지 않으면 문자가 발송되지 않으며, 카드의 기록에 **Text skipped: no mobile phone**이 남습니다.
- 사람이 수신을 거부한 상태라면 문자가 발송되지 않으며, 카드의 기록에 **Text skipped: opted out**이 남습니다.
- 문자가 발송되면 카드의 기록에 **Text sent**가 남습니다. 연결된 문자 서비스 제공업체가 없거나 교회의 문자 크레딧이 모두 소진되는 등의 이유로 발송에 실패하면 실패 내용이 카드의 기록에 남고, 단계의 나머지 작업은 계속 실행됩니다.

:::warning
문자는 교회의 [문자 서비스 제공업체](../settings/church-settings.md#texting)를 통해 발송됩니다. 제공업체가 연결되어 있지 않으면 작업 편집기에 *"No texting provider is set up"*이 표시되며 문자는 발송되지 않습니다.
:::

### 며칠 기다리기(드립 시퀀스)

**Wait** 작업은 설정한 일수 동안 카드를 보류합니다. 기다리는 동안 카드는 **Snoozed**로 표시됩니다. B1은 30분마다 대기가 끝난 카드를 확인하므로, 카드는 대기가 끝난 후 약 30분 안에 다시 진행됩니다. 대기가 끝나면 다음과 같이 진행됩니다.

1. **같은 단계의 남은 작업**이 모두 실행됩니다. 따라서 **이메일 발송 → 3일 대기 → 리마인더 이메일 발송**과 같은 드립을 만들 수 있습니다.
2. 그다음 단계에 자동 경로가 있으면 카드가 이동하고, 없으면 사람이 가져갈 수 있도록 단계에 머무릅니다.

:::tip
단계 맨 앞의 **Wait**는 봉사자에게 보이기 전에 카드를 "보류"하는 간단한 방법입니다. 예를 들어 *7일 대기 후 코치가 연락함*과 같이 설정할 수 있습니다.
:::

## 사람을 카드로 추가하기

보드에 사람을 추가하는 방법은 여러 가지가 있습니다.

- **보드에서** -- 단계 열 아래의 **Add Card**를 클릭하고 사람을 선택합니다. 그룹을 선택할 수도 있으며, 그러면 그룹의 모든 구성원이 카드로 추가됩니다.
- **사람의 기록에서** -- 사람 페이지의 **Add to Workflow**를 사용하여 워크플로에 등록합니다.
- **People 검색에서** -- 여러 사람을 선택한 다음 일괄 **Add to Workflow** 작업을 사용하여 한 번에 추가합니다.
- **트리거로 자동 추가** -- 양식 제출이나 첫 헌금 같은 일이 일어날 때 사람을 추가합니다(아래 [트리거](#triggers) 참고).

## 보드 사용하기

워크플로를 열면 보드가 표시됩니다. 각 카드에는 사람의 이름, 배정된 담당자, 마감일 또는 상태 표시(**Overdue** 또는 **Snoozed**)가 나타납니다. 단계 열에는 해당 단계가 실행하는 자동 작업을 나타내는 작은 배지와 경로에 대한 주석도 표시되므로, 카드가 어떻게 이동하는지 한눈에 파악할 수 있습니다.

- **카드 이동** -- 사람이 진행함에 따라 카드를 한 열에서 다음 열로 끌어다 놓습니다.
- **카드 열기** -- 카드를 두 번 클릭하거나 클릭하여 세부 정보 서랍을 엽니다. 여기에서 단계를 바꾸고, 담당자를 다시 배정하고, 메모를 추가하고, 이미 진행된 내용을 검토할 수 있습니다.

카드 서랍에서 다음을 할 수 있습니다.

- 카드를 다른 사람이나 그룹에 **Assign**합니다.
- 카드를 1일, 3일 또는 1주일 동안 **Snooze**하여 마감일을 잠시 숨깁니다.
- 이전 단계로 **Send Back**하거나 다음 단계로 **Skip**합니다.
- **Pin assignment** -- 카드가 단계 사이를 이동하더라도 같은 담당자를 유지합니다. 기본적으로 카드를 새 단계로 옮기면 그 단계의 기본 담당자에게 다시 배정되며, 고정하면 현재 담당자가 끝까지 책임을 집니다.
- 카드를 **Complete**하여 끝내거나, 단계에 결과(outcome)가 설정되어 있으면 **Outcome** 버튼을 선택합니다([경로 설정](#routing-cards-with-outcomes-and-conditions) 참고).
- 메모를 **Add notes**하고 카드의 **Activity**(실행된 자동 작업 기록, 예: 발송된 이메일, 대기 등)를 날짜와 시간과 함께 확인합니다.

사람에 관한 카드의 경우 서랍에는 그 사람의 휴대폰 번호와 이메일도 링크로 표시되어 탭하여 전화하거나 이메일을 보낼 수 있습니다. 사람을 볼 권한이 있다면 **View profile** 링크도 표시됩니다. 카드가 배정된 사람은 People 권한이 없어도 휴대폰 번호와 이메일을 볼 수 있습니다.

메모는 카드와 함께 저장됩니다. 카드를 열 수 있는 사람(배정된 사람이나 그룹 포함)은 메모를 읽고 자신의 메모를 추가할 수 있습니다. 카드를 열 수 없는 사람은 메모를 볼 수 없습니다.

### 일괄 작업

여러 카드의 체크박스를 선택하여 함께 처리할 수 있습니다. 단계의 모든 카드를 한 번에 선택하려면 해당 단계 열 머리글의 **Select all** 상자를 체크합니다. 다시 체크하면 선택이 해제됩니다. 도구 모음이 나타나며 선택한 모든 카드를 한꺼번에 **Complete**, **Snooze**, **Assign**(다시 배정), 또는 다른 단계로 **Move to…**할 수 있습니다.

## 결과와 조건으로 카드 경로 설정하기

경로 설정은 카드가 단계를 떠날 때 이동할 위치를 결정합니다. 단계 편집기를 열면 두 가지 종류의 경로를 설정할 수 있습니다.

### 결과 버튼

결과(outcome)는 해당 단계의 카드를 완료할 때 카드 서랍에 표시되는 버튼입니다. 단일 **Complete** 버튼 대신 "Joined a Group"이나 "Not Interested"와 같은 선택지를 제공할 수 있습니다. 각 결과는 다음을 할 수 있습니다.

- 카드를 이 워크플로의 **다른 단계**로 보냅니다.
- 카드를 완전히 다른 워크플로로 **넘깁니다(hand off)**.
- 카드를 **닫습니다(close)**.

이를 통해 하나의 결정으로 사람을 여러 경로로 나눌 수 있습니다.

### 자동 경로(조건부)

자동 경로는 사람이 설정한 조건에 맞으면 아무도 클릭하지 않아도 카드가 단계에 **들어오는 순간**(그리고 자동 작업이 끝난 후) 다음 단계로 옮깁니다. 경로를 추가하고 대상 단계를 고른 다음 하나 이상의 **조건**(예: 사람의 캠퍼스, 나이, 교인 상태)을 정의합니다. 텍스트 필드는 정확히 일치하거나 **contains**, **starts with**, **ends with**로 비교할 수 있습니다. 조건이 없는 경로는 모든 사람과 일치합니다.

날짜 조건(Today's Date, Birth Date, Anniversary)은 전체 날짜를 비교하거나 일부만 비교할 수 있습니다. 요일, **Day of Month**, **Month**, 또는 경과한 연도 수를 기준으로 비교할 수 있습니다. 사람의 Birth Date나 Anniversary에서 **Day of Month**에는 상대적인 **Today** 옵션이 있으므로, *Birth Date · Day of Month = Today*와 같은 조건은 오늘과 같은 날짜에 생일이 있는 사람과 일치합니다. **Month**에는 **Previous Month**, **Current Month**, **Next Month** 옵션이 있습니다. 이러한 상대 값은 교회의 시간대를 기준으로 계산되므로 서버 시간이 아니라 교회 달력의 날짜와 맞습니다.

어떤 이유로든 경로의 조건을 확인할 수 없으면 해당 경로는 일치하지 않는 것으로 처리됩니다. 카드는 단계에 머물거나(또는 일치하는 다른 경로를 따릅니다) 멈추지 않습니다.

:::info
보드에서 각 단계 열에는 경로를 설명하는 작은 주석이 표시됩니다. 예를 들어 결과 라벨이나 "if matches"와 화살표 뒤에 이어지는 대상 단계 또는 워크플로가 표시됩니다.
:::

## 완전 자동 단계

단계를 아무도 처리하지 않고 스스로 실행되도록 만들 수 있습니다. 단계에 **자동 작업**을 설정하고, 다음 단계를 가리키는 **자동 경로**(조건 없음)를 추가합니다. 카드가 들어오면 작업이 실행된 다음 경로가 즉시 카드를 진행시킵니다. 카드가 그대로 통과합니다.

:::tip
**Wait**와 함께 사용하세요. *환영 이메일 발송 → 3일 대기 → "Personal call" 단계로 자동 진행*과 같이 설정하면 이메일과 시점은 자동으로 처리되고, 봉사자는 직접 연락할 때가 되어서야 카드를 보게 됩니다.
:::

## 트리거

트리거는 무언가 일어날 때 사람을 워크플로에 자동으로 추가하므로 카드를 직접 추가할 필요가 없습니다. 워크플로 보드에서 **Triggers** 탭을 클릭한 다음 **Add Trigger**를 클릭합니다. 트리거에는 두 종류가 있습니다.

### 이벤트 트리거

B1에서 기록이 변경되면 바로 실행됩니다. 이벤트를 선택하고, 필요하면 **조건**을 추가하여 일치하는 사람만 추가되도록 합니다.

- **Person · Created / Updated** -- 예: 상태가 *Visitor* 또는 *Guest*(스스로 등록한 사람에게 주어지는 상태)가 되는 모든 사람을 추가합니다.
- **Donation · Created** -- 예: 처음 헌금했거나 큰 금액을 헌금한 사람을 감사 워크플로에 추가합니다(금액, 기금, 방법으로 일치시킬 수 있습니다).
- **Group · Member Joined** / **Group · Created**.
- **Form · Submitted** -- 선택한 양식을 제출한 모든 사람을 추가합니다("I'm New" 또는 "Connect" 카드에 좋습니다).

### 일정 트리거

일별, 주별, 월별, 연별로 반복 실행되며 설정한 조건에 따라 작동합니다. *오늘이 생일인 모든 사람*(Birth Date · Day of Month = **Today**, 월은 **Current Month**로 일치)이나 *월간* 점검과 같이 시간에 따른 연락에 사용합니다. **Only once per person**을 켜지 않더라도 일정 트리거는 한 반복 주기(트리거가 실행되는 빈도에 맞춘 하루, 한 주, 한 달, 또는 한 해) 안에서 같은 사람을 다시 추가하지 않습니다.

모든 트리거에서 다음을 설정할 수 있습니다.

- 새 카드가 놓일 **Starting step**(기본값은 첫 번째 단계입니다).
- **Only once per person** -- 트리거가 같은 사람을 워크플로에 두 번 추가하지 않도록 합니다. 이 옵션을 켜면 이 워크플로에 이미 카드가 있는 사람은 건너뜁니다.
  - **Add again after their card is closed** -- **Only once per person**을 켰을 때 나타납니다. 체크하면 이 워크플로의 이전 카드가 닫힌 후 트리거가 같은 사람을 다시 추가할 수 있습니다. 사람이 워크플로에 동시에 열린 카드를 두 개 가지는 일은 여전히 없습니다. 재방문 손님이나 매년 반복되는 과정처럼 여러 번 일어날 수 있는 경우에 사용합니다.
- **Active** -- 삭제하지 않고 트리거를 켜거나 끕니다.

:::tip
**Form · Submitted** 트리거를 **New Visitor Follow-up** 템플릿과 함께 사용하면 "Connect Card" 또는 "I'm New" 양식을 자동 후속 연락 파이프라인으로 바꿀 수 있습니다.
:::

## 봉사 배정 확인

특별한 종류의 워크플로는 각 봉사자가 수락하거나 거절할 때까지 [봉사 요청](./plans.md#assigning-team-members)을 따라가며 후속 연락할 수 있습니다. 이 보드의 각 카드는 사람이 아니라 **하나의 배정**을 추적합니다. 즉, 한 계획에서 한 자리에 배정된 한 사람입니다. 같은 사람에게 두 개의 역할이나 두 개의 예배가 배정되면 각각 별도의 카드가 생깁니다. 이 기능은 선택 사항입니다. 계획 설정에서 확인 워크플로를 선택하기 전까지는 아무것도 바뀌지 않습니다.

### 설정하기

1. 워크플로 페이지에서 **Add Workflow**를 클릭하고 **Serving Assignment Confirmation** 템플릿을 선택합니다. (또는 **Blank workflow**로 시작하여 **Workflow purpose**를 **Serving assignment confirmation**으로 설정합니다.) 템플릿으로 만들려면 문자 발송 권한이 필요합니다. 문자 단계가 포함되어 있기 때문입니다.
2. 단계를 검토합니다. 템플릿은 다음으로 시작합니다.
   - **Request and wait for response** -- 봉사 요청을 이메일과 문자로 보내고, 2일을 기다린 후 리마인더 이메일을 보내고, 하루를 더 기다린 다음 카드를 자동으로 다음 단계로 옮깁니다.
   - **Call volunteer about unanswered request** -- 봉사자에게 전화하는 사람을 위한 단계이며 1일 후가 마감입니다. 이 단계에 **Default assignee**를 설정합니다. 설정하지 않으면 카드는 사역 리더에게 가고, 리더가 없으면 사역 팀에 갑니다.
3. 대기 시간, 메시지, 단계를 교회에 맞게 편집합니다.
4. [계획 설정](./plans.md#plan-settings)을 열고 **Confirmation workflow**에서 이 워크플로를 선택합니다.

이 워크플로는 **Send email**과 **Send text** 대신 **Send serving request** 작업을 사용합니다. **Email** 또는 **Text message**를 선택하고 필요하면 **Request message**를 작성합니다. 요청에는 항상 역할, 계획, 예배 날짜, 응답 링크가 포함됩니다. 메시지에는 `{{planName}}`, `{{positionName}}`, `{{serviceDate}}`를 사용할 수 있습니다. 메시지를 비워 두면 기본 요청이 사용됩니다. 봉사자의 알림 설정, 문자 수신 동의, 문자 서비스 제공업체, 교회의 이메일 승인이 모두 적용되며, 건너뛰었거나 차단된 발송 시도는 카드에 기록됩니다. 이 보드에서는 **Send email**, **Send text**, **Add to workflow**를 사용할 수 없습니다.

확인 워크플로의 **Triggers** 탭은 트리거를 제공하는 대신 카드가 어떻게 시작되는지 설명하며, 이 워크플로는 사람들의 **Add to Workflow** 목록에 나타나지 않습니다.

### 카드가 시작되고 닫히는 방식

- 카드는 게시된 계획에서 봉사자에게 **Notify**를 클릭할 때 시작됩니다([봉사자에게 알리기](./plan-validation.md#notifying-volunteers) 참고). 아직 응답하지 않은 새 배정마다 카드가 하나씩 생깁니다. 계획을 저장하거나, 게시하거나, 복사하거나, 자동으로 채운다고 해서 누군가에게 자동으로 연락하지는 않으며, 임시 저장 상태의 계획은 아무것도 보내지 않습니다.
- 봉사자는 여전히 일반적인 앱 내 알림을 받습니다. 이메일과 문자 후속 연락은 워크플로에서 발송됩니다.
- 봉사자가 **수락하거나 거절하면** 카드는 연결된 후속 작업과 함께 자동으로 닫힙니다.
- 카드 서랍에는 자리, 예배 날짜, 계획 링크가 표시됩니다. **Complete** 대신 버튼에는 **Record follow-up done**이 표시됩니다. 이를 클릭하면 누군가 후속 연락을 했다고 기록되지만, 카드는 봉사자가 응답하거나 응답 마감일이 지날 때까지 열린 상태로 남고 배정 상태도 유지됩니다(**Awaiting response**로 표시됩니다).
- 응답 마감일은 해당 자리의 팀이 봉사하는 마지막 예배 시간이 끝나는 시점입니다. 계획에 맞는 시간이 없으면 예배 날짜가 끝나는 시점입니다. 그때까지 아무도 응답하지 않으면 카드는 **Response deadline passed**와 함께 닫히고, **Review unanswered serving request** 작업이 카드의 현재 담당자나 사역 리더에게 전달되어 누군가 자리를 어떻게 채울지 결정할 수 있습니다. 배정은 **Unconfirmed** 상태로 남습니다.
- 배정을 제거하거나, 사람, 자리, 계획 날짜를 바꾸거나, 계획을 임시 저장 상태로 되돌리거나, 계획을 다른 확인 워크플로로 바꾸면 카드가 닫힙니다. 닫힌 카드는 다른 **Notify**로 다시 열리지 않습니다. 새 요청을 보내려면 새 배정을 추가하세요.

:::info
확인 워크플로를 통해 보낸 요청의 경우 [봉사자 알림](./plans.md#volunteer-reminders)은 **수락한** 봉사자에게만 전송됩니다. 따라서 응답을 기다리는 사람은 워크플로의 후속 연락에 더해 알림을 받지 않습니다.
:::

## 내 카드

봉사자와 교직원이 모든 보드를 뒤질 필요는 없습니다. **내 업무(My Work)** 페이지의 **My Cards** 목록에는 모든 워크플로에서 현재 사용자에게 배정된 모든 카드가 표시됩니다. 워크플로 페이지 상단의 **My Cards**를 클릭하거나, Jump 메뉴에서 **Serving > My Work**를 엽니다. 카드를 클릭하면 해당 카드가 속한 보드가 열립니다.

## 보고서

워크플로를 열고 **Reports**를 클릭하면 해당 워크플로의 분석을 볼 수 있습니다.

- **Overdue** -- 마감일이 지난 카드의 수입니다.
- **Cards per Step** -- 각 단계에 현재 놓여 있는 카드의 수로, 막대 차트로 표시됩니다.
- **Completed (30 days)** -- 지난 30일 동안의 처리량으로, 선 차트로 표시됩니다.

이 자료를 사용하여 병목 현상을 찾으세요. 예를 들어 카드가 쌓여서 전혀 진행되지 않는 단계를 찾을 수 있습니다.
