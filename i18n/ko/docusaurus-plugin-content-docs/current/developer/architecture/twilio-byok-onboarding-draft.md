# 교회 소유 Twilio 온보딩 초안

:::caution 제안된 통합에 대한 초안
이것은 제안된 워크플로입니다. B1에는 현재 **설정 > 문자**(Account SID, Auth Token, From Number, 수신 STOP 웹훅)에 기본 **Twilio** 선택지가 있습니다. [교회 설정: 문자](../../b1-admin/settings/church-settings.md#texting)를 참고하세요. 아래의 추가 B1 설정 항목, 동의 매핑, 검증 단계는 향후 릴리스의 요구 사항이며, 기존 설정을 찾으라는 안내가 아닙니다. 범위와 의존 관계는 [기술 제안서](./twilio-byok-proposal)를 읽어 주세요. Twilio 자료는 2026년 10월 22일에 확인했습니다. 캠페인을 제출하기 전에 현재 요구 사항을 다시 확인하세요.
:::

## 권장 구성

교회가 유료 Twilio 계정, 전화번호, Messaging Service, 요금, 캠페인 등록을 소유합니다. B1은 교회 설정에 비공개로 입력된 자격 증명을 사용해 이 자원으로 발송하게 됩니다. 최소 두 명의 적절한 교회 관리자가 Twilio 계정에 접근할 수 있어야 하고, 계정 보안을 켜야 하며, 동의, 수신 응답, 발송 거부 통지를 담당할 사람을 지정해야 합니다.

여기서 제안하는 첫 번째 릴리스는 미국 지역 번호 하나와 명확하게 설명된 교회 메시지 프로그램 하나를 대상으로 합니다. 아래 예시는 가상의 **Grace Community Church**와 프로그램 **Grace Church Updates**를 사용하며, 예배 일정 변경, 행사 알림, 봉사 일정 안내에 쓰입니다. 모든 이름, 도메인, 빈도, 연락처, 목적은 교회의 실제 방식으로 바꾸세요. 이 예시들은 Twilio 규칙을 설명하기 위한 교회별 예시이며, 미리 승인된 캠페인이나 승인을 보장하는 내용이 아닙니다.

## 1. 공개 B1 가입 경험 준비하기

교회의 B1 웹사이트에 `https://www.example.org/text-updates` 같은 페이지를 게시하세요. 이 페이지에는 공개 B1 양식을 넣거나, 독립된 공개 양식으로 가는 분명한 링크를 두세요. 또한 `https://www.example.org/privacy`와 `https://www.example.org/sms-terms`도 게시하세요. 이 주소들은 자리표시자이므로, 실제로 접근 가능한 URL을 제출하세요.

제안하는 SMS 가입 양식의 설정은 다음과 같습니다.

| 설정 | 권장 구성 |
|---|---|
| 접근 | 공개/제한 없음. 검토 기간과 계속되는 가입 기간 동안 활성 상태이며, 로그인 없이 이용 가능 |
| 양식 모드 | 처음에는 표준 모드. 대화형 모드는 기술 제안서에 설명된 명시적 동의 지원이 필요합니다 |
| 휴대전화 | 국가 번호와 함께 명확히 표시. 일반적인 연결/행사 양식 안에서 쓰는 경우에는 SMS 가입을 선택했을 때만 필수 |
| SMS 선택 | 별도의 선택 체크박스로, 기본값은 선택 해제. 특정 프로그램과 휴대전화 필드에 매핑 |
| 고지 | SMS 선택 옆에 표시. 교회/프로그램, 메시지 목적과 빈도, 가능한 요금, STOP, HELP, 지원 연락처, 실제로 클릭할 수 있는 개인정보 처리방침/SMS 약관 링크 |
| 다른 행동 | 방문자는 SMS에 동의하지 않고도 연결 카드를 제출하거나, 행사에 등록하거나, 정보를 요청할 수 있어야 합니다 |
| 증거 | 프로그램, 정확한 전화번호, 선택한 동의 내용, 제출 원본, 서버 시각, 고지/정책 버전을 저장합니다. 일반 양식 답변만으로는 오늘날 아무도 등록되지 않습니다 |
| 사람/그룹 자동화 | 교회의 기존 매칭 규칙을 검토하지 않았다면, 초기 가입 시범 운영에서는 사람 자동 생성과 그룹 자동 배정을 꺼 두세요. 그룹 배정은 SMS 승인이 될 수 없습니다 |
| 기존 자동화 | 모든 양식 제출자나 그룹 구성원을 문자 워크플로에 등록하지 마세요. 제안된 검증 동의 매핑만이 해당 프로그램을 승인할 수 있습니다 |
| 감사 문자 | 양식이 접수되었음을 확인하되, 체크박스를 거절했거나 확인/검토가 대기 중일 때는 SMS 등록이 완료된 것처럼 말하지 마세요 |

기존 체크박스 질문으로 양식을 예시할 수는 있지만, B1에는 여전히 동의 원장과 발송 게이트가 필요합니다. 현재 공유 렌더러는 설명을 일반 텍스트로 표시합니다. 설명 칸에 Markdown이나 URL을 입력한다고 해서 정책 링크가 클릭 가능해진다고 보장할 수 없습니다. 구현에서는 실제 링크가 포함된 접근 가능한 동의 컨트롤을 제공해야 합니다. [B1 양식 만들기](../../b1-admin/forms/creating-forms)와 [기술 제안서](./twilio-byok-proposal#consent-and-suppression-are-required-release-work)를 참고하세요.

Twilio는 자발적이고 검증 가능한 옵트인을 요구합니다. SMS를 필수 회원 약관, 이메일/전화 허용 여부, 기부 동의, 행사 등록과 묶지 마세요. 방문자 카드에 적힌 휴대전화 번호는 그 자체로 SMS 동의가 아닙니다. Twilio의 [자발적 동의 요구 사항](https://www.twilio.com/docs/api/errors/30923)과 [캠페인 권장 사항](https://help.twilio.com/hc/en-us/articles/26149060902555-A2P-10DLC-Campaign-Registration-Recommendations)을 참고하세요.

### 가입 안내 문구 예시

교회가 실제 목적, 발신자, 빈도를 정한 뒤에만 이 문구를 사용하세요. 체크박스는 선택 사항이며 기본적으로 선택되지 않은 상태로 시작합니다. 정책 이름은 렌더링된 양식에서 링크여야 합니다.

> 네, Grace Community Church가 [등록된 교회 번호]에서 Grace Church Updates를 통해 예배 일정 변경, 교회 행사, 봉사 일정에 대한 문자를 보내는 것에 동의합니다. 매달 최대 4건의 메시지가 발송될 수 있습니다. 메시지 및 데이터 요금이 부과될 수 있습니다. 구독을 취소하려면 STOP, 도움이 필요하면 HELP라고 답장하세요. SMS 가입은 선택 사항이며 출석, 행사 등록, 헌금의 조건이 아닙니다. 개인정보 처리방침과 SMS 약관을 참고하세요. 문의: [교회 지원 이메일 또는 전화번호].

"매달 최대 4건"은 예시 약속일 뿐이며, Twilio가 정한 한도가 아닙니다. 교회가 실제로 지킬 수 있는 빈도로 바꾸세요. 빈도가 달라진다면 사실대로 고지하고 예상되는 주기를 설명하세요. 홍보 메시지나 추가 사역 프로그램은 목적과 동의를 별도로 검토하지 않았다면 이 체크박스 밖에 두세요.

일반 방문자/행사 양식에서는 이 체크박스를 선택하지 않고 제출해도 반드시 성공해야 합니다. SMS 전용 양식에서는 체크하면 가입이 요청된다고 설명할 수 있지만, 무관한 교회 서비스가 가입 여부에 따라 달라지게 해서는 안 됩니다. 휴대폰과 데스크톱 모두에서 실제 동작을 확인하세요.

### 준비할 정책 내용

교회의 개인정보 처리방침 페이지에는 문자 발송을 위해 어떤 정보를 수집하는지, 그것을 어떻게 사용하고 보호하는지, 보관과 연락 방식은 어떤지를 설명해야 합니다. 휴대전화 번호와 메시지 동의는 제3자나 계열사에 마케팅이나 홍보 목적으로 판매되거나 공유되지 않는다고 명확히 밝혀야 합니다. 교회가 B1과 Twilio를 사용하면서도 처리업체를 쓰지 않는 것처럼 말하지 마세요. 필요한 서비스 제공업체의 처리는 정확하게 설명하세요. 이 차이에 대한 기준은 Twilio의 [개인정보 처리방침 안내](https://www.twilio.com/docs/api/errors/30908)와 [캠페인 권장 사항](https://help.twilio.com/hc/en-us/articles/26149060902555-A2P-10DLC-Campaign-Registration-Recommendations)입니다.

SMS 약관에는 교회와 프로그램, 목적, 실제 빈도, 가능한 메시지 요금, STOP/HELP 안내, 지원 연락처, 개인정보 링크를 명시하세요. Twilio의 현재 검토에서 요청하는 추가 고지도 포함하세요. 가입 페이지의 정책 링크는 캠페인에 제출한 URL과 정확히 일치해야 합니다. 2026년 6월 30일부터 Twilio는 새 API 캠페인 등록에 공개 개인정보 처리방침과 약관 URL을 요구합니다. Console 절차에서도 이를 수집합니다. [Twilio 요구 사항](https://www.twilio.com/en-us/changelog/a2p-10dlc-campaign-registration-will-require-privacy-policy-and-)

이것들은 교회의 실제 정책에 적용해야 할 내용 요구 사항입니다. 기존 개인정보 관행을 대신하거나, 확인하지 않고 붙여 넣을 수 있는 일반 정책이 되어서는 안 됩니다.

## 2. Twilio에 교회와 메시지 프로그램 등록하기

1. 교회가 소유한 **유료 계정**과 SMS를 지원하는 미국 지역 번호를 만들거나 사용하세요. 교회의 법적 명칭, EIN/사업자 등록 정보, 주소, 웹사이트, 권한 있는 대표자를 일관되게 사용하세요. ChurchApps의 정보나 다른 교회의 정보로 대체하지 마세요.
2. 교회의 실제 법인 유형에 맞춰 Twilio의 직접 고객용 Brand 등록 절차를 따르세요. 자격이 있는 비영리 단체라면 [비영리 단체 등록 안내](https://www.twilio.com/docs/messaging/compliance/a2p-10dlc/onboarding-for-government-and-non-profit-agencies)를 사용하세요. 자선단체/501(c)(3) 용도는 자격 요건에 따라 달라집니다. 교회의 이름만으로 Twilio 승인이나 면제가 확보되지 않습니다.
3. 전용 Messaging Service를 만들고, 관련 A2P 10DLC 캠페인을 제출하세요. 실제 메시지와 승인된 Brand가 사용할 수 있는 옵션에 사실대로 맞는 사용 사례를 고르세요. 여기 예시들은 모든 교회에 적용되는 사용 사례 코드를 지정하지 않습니다.
4. 공개 가입 URL, 정책 URL, 전체 옵트인/메시지 흐름 설명, 요청된 샘플 메시지를 제공하세요. 실제로 존재하는 모든 가입 방식을 포함하고, 내장 링크/전화번호 선언이 실제 내용과 일치하도록 설정하세요. 키워드 가입이나 이중 옵트인은 그 흐름이 실제로 존재하고 테스트되었을 때만 나열하세요.
5. 발신 번호를 서비스와 승인된 캠페인에 연결하세요. 발송하기 전에 **캠페인 검증과 번호 등록 완료**를 모두 기다리세요.

이 단계들은 교회 자체 Twilio Console에서 진행하세요. 제안된 B1 통합은 교회를 대신해 등록을 제출하지 않습니다. Twilio의 [등록 빠른 시작](https://www.twilio.com/docs/messaging/compliance/a2p-10dlc/quickstart)과 [캠페인 리소스](https://www.twilio.com/docs/messaging/api/usapptoperson-resource)에서 등록 항목과 상태를 확인할 수 있습니다. 캠페인이 승인된 뒤에도 대기 중인 번호는 발송을 막을 수 있습니다. [번호 등록](https://www.twilio.com/docs/api/errors/30035)

### 캠페인 설명 예시

> Grace Community Church는 Grace Church Updates를 사용해, 교회 웹사이트에서 이 프로그램을 선택한 사람들에게 예배 일정 변경, 교회 행사 알림, 봉사 일정 안내를 보냅니다. 이 프로그램으로는 한 달에 최대 4건의 메시지만 보냅니다. 수신자는 언제든지 메시지를 중단할 수 있습니다. 이 프로그램은 구매한 연락처, 제3자 홍보, 모금 호소를 포함하지 않습니다.

이 예시는 실제로 해당 한도와 제외 사항을 지키는 교회에만 맞습니다. 봉사 알림만으로도 약속한 빈도를 넘는다면, 제출 전에 프로그램 설계와 고지를 바꾸세요.

### 메시지 흐름 설명 예시

> 방문자는 [실제 교회 가입 URL]을 열고, 휴대전화 번호를 입력한 뒤, 선택 사항인 Grace Church Updates 체크박스를 독립적으로 선택합니다. 이 체크박스는 양식이 열릴 때 선택되지 않은 상태입니다. 고지에는 Grace Community Church라는 이름, 예배 일정 변경, 행사 알림, 봉사 일정 안내라는 설명, 매달 한도와 가능한 요금, STOP과 HELP에 대한 안내가 들어 있습니다. 표시되는 개인정보 처리방침과 SMS 약관은 [실제 개인정보 처리방침 URL]과 [실제 SMS 약관 URL]로 연결됩니다. SMS를 거절해도 출석, 행사 등록, 헌금, 일반 연결 양식 사용에는 영향이 없습니다. B1은 적극적인 선택, 휴대전화 번호, 제출 시각, 고지 버전을 기록합니다. 기록된 구독자에게만 이 프로그램을 보내며, 수신 거부가 접수되면 추가 발송 전에 억제합니다.

이 문단은 실제로 구현된 흐름에 맞게 고치세요. 전화 확인이나 직원 검토를 쓴다면 대기 상태와 정확한 활성화 단계를 설명하세요. 다른 방식을 쓴다면 각 방식과 그 증거를 포함하세요. 가입이 로그인 뒤에서 이루어지거나 종이로 이루어진다면, Twilio는 실제 옵트인 경험에 대한 공개되고 개인정보가 가려진 증거를 요구합니다. 완성된 양식이나 교인 데이터는 절대 노출하지 마세요. [검증 가능한 옵트인 안내](https://www.twilio.com/docs/api/errors/30923)

### 발신 메시지 예시

이것들은 고쳐서 사용할 가상의 샘플입니다. 제출하기 전에 실제 교회 URL을 쓰고 대괄호 안의 값을 바꾸세요. Twilio 캠페인 API는 샘플을 2개에서 5개까지 받습니다. 샘플에는 교회를 밝히고, 선언한 목적을 반영하고, 수신 거부 안내를 포함해야 합니다. [캠페인 샘플 필드](https://www.twilio.com/docs/messaging/api/usapptoperson-resource)

```text
Grace Community Church: Sunday's service will start at [time] due to [reason]. Details: [church website URL]. Reply STOP to end texts.
```

```text
Grace Community Church: A reminder that [church event] is on [date] at [time]. Information: [church event URL]. Reply STOP to end texts.
```

```text
Grace Community Church: You are scheduled to serve on [team] this [day]. Please review your plan: [B1 church portal URL]. Reply STOP to end texts.
```

대괄호 안의 URL은 샘플 변수를 뜻합니다. 제출하는 예시에는 실제 교회 도메인과 실제 링크 형식이 보여야 합니다. 계획 링크는 로그인이 필요할 수 있지만, 가입 페이지와 검토에 쓰이는 정책은 공개적으로 확인할 수 있어야 합니다. 승인 샘플에 비공개 메모, 어린이 정보, 식별 가능한 교인 정보를 넣지 마세요. 샘플 내용은 B1 템플릿이 실제로 보내는 내용과 일치시키세요. 사용할 수 없는 답장 수신함이나 특정 알림 동작을 약속하지 마세요.

### STOP, START, HELP 응답

이 확인 메시지에는 Twilio Messaging Service의 Advanced Opt-Out을 사용하고, 교회와 프로그램의 정체성 및 지원 정보에 맞게 맞춤 설정하세요. 응답의 예시 의도는 다음과 같습니다.

- **STOP:** Grace Church Updates가 중단되었음을 확인하고, 다시 구독하는 지원 방법을 설명합니다.
- **START:** 같은 프로그램의 재개를 확인합니다. 설정된 흐름이 요구하는 대로 프로그램 정체성, 빈도/요금, 도움말 및 중단 안내를 포함합니다.
- **HELP:** Grace Community Church를 밝히고, 실제 지원 연락처와 수신 거부 방법을 안내합니다.

Twilio가 이미 응답했다면 B1에서 두 번째 확인 메시지를 보내지 마세요. HELP 답장은 가입이 아닙니다. START는 사람을 추가 교회 프로그램에 가입시키거나 교인 명부에 노출해서는 안 됩니다. [Twilio Advanced Opt-Out](https://www.twilio.com/docs/messaging/tutorials/advanced-opt-out)

## 3. 제출 전에 승인 자료 확인하기

- [ ] 교회의 실제 법적 정보/Brand 정보, 웹사이트 정체성, 캠페인 목적이 서로 일치합니다.
- [ ] 개인 브라우저에서, 모바일 기기를 포함해 가입 페이지와 활성 양식이 로그인 없이 열립니다.
- [ ] SMS 체크박스는 선택되지 않은 상태로 시작하며, 주요 방문자/행사 행동을 완료하면서도 거절할 수 있습니다.
- [ ] 프로그램 목적, 발신자, 실제 빈도, 가능한 요금, STOP, HELP, 지원 연락처, 클릭 가능한 정책 링크가 SMS 선택 옆에 표시됩니다.
- [ ] Twilio에 제공한 정확한 개인정보/약관 URL은 공개되어 있고, 자격 증명 없이 작동하며, 같은 교회와 프로그램을 가리킵니다. 정책 내용은 실제 처리 방식과 일치합니다.
- [ ] 각 샘플 메시지는 프로그램, 실제 발신자 정체성, 예상되는 링크/전화 동작과 일치합니다. 캠페인은 실제로 존재하는 모든 옵트인 방식을 설명합니다.
- [ ] 가려진 스크린샷에는 빈 양식, 체크박스와 고지, 정책 링크가 심사자에게 보이는 그대로 나타납니다. 증거에는 교인 기록이나 키가 포함되지 않습니다.
- [ ] 교회는 동의 증거를 보관하고, 발송 전에 수신 거부를 처리할 수 있는 운영 방법을 갖추고 있습니다. 전화나 이메일로 들어온 요청도 포함합니다.

이 점검 항목은 피할 수 있는 불일치를 줄이기 위한 것입니다. 승인 결정은 Twilio와 그 검토 파트너가 내립니다. 승인 후에도 실제 가입 페이지와 정책 URL을 검토 기간뿐 아니라 계속 사용 가능한 상태로 유지하세요.

## 4. 향후 B1 통합 연결 및 검증하기

통합이 출시된 뒤, 제안된 문자 설정에서는 교회의 Account SID, 전용 API Key SID/비밀 값, 별도의 웹훅 Auth Token, Messaging Service SID, 선택한 발신 번호를 수집해야 합니다. 키는 교회의 Console에서만 만들고, 비밀 값은 비공개 B1 설정에만 입력하세요. [Twilio API 키 안내](https://www.twilio.com/docs/iam/api-keys)

B1이 제공하는 교회별 수신 웹훅과 전송 상태 웹훅 URL을 Twilio 서비스 설정의 해당 항목에 복사하세요. Advanced Opt-Out을 켜고, 수신 메시지가 설정된 웹훅에 도달하는지 확인하세요. B1은 자격 증명, 서비스/발신자 소유권, 검증된 캠페인, 완료된 번호 등록, 수신 검증, 테스트 전달에 대해 각각 별도의 확인 항목을 보여 줘야 합니다. 저장된 자격 증명이나 수락된 API 요청은 최종 전달을 의미하지 않습니다.

B1이 등록 신호를 프로그램으로 확인할 수 없다면, Console에서 직접 확인하세요. UI에는 날짜가 찍힌 결과가 관리자가 확인한 것임을 표시해야 합니다. 프로덕션 문자를 켜기 전에 대기 중이거나 실패한 상태를 해결하세요. 동의한 실제 성인 테스트 수신자에게 보내는 별도의 테스트는 명시적으로 요청한 경우에만 진행하세요. 그다음 다음을 확인하세요.

1. 일치하는 문서화된 가입이 올바른 전화/프로그램 동의 기록을 만드는지 확인합니다. 거절하거나 전화번호를 바꾼 경우 수신자가 조용히 가입되어서는 안 됩니다.
2. 테스트 메시지 하나를 보내고 수신을 확인한 뒤, B1 상태를 Twilio Message SID 및 전달 결과와 비교합니다.
3. STOP으로 답장하고, 수동 문자, 그룹 문자, 워크플로, 리마인더가 해당 전화번호를 건너뛰는지 확인합니다. 명부 노출 상태는 바뀌지 않아야 합니다.
4. 문서화된 같은 프로그램 재구독 흐름과 HELP 응답을 실행하고, 중복 확인 메시지가 없고 관련 없는 환경설정이 바뀌지 않았는지 확인합니다.

## 5. 프로그램 유지하기

교회 담당자를 지정해 Twilio에서 캠페인과 계정 상태, 잔액과 청구 알림, 메시지 실패, 수신 답장을 모니터링하게 하세요. 제안된 첫 B1 릴리스에는 대화형 SMS 수신함이 없습니다. 따라서 실제 도움 연락처를 공개하고 모니터링하며, 직원이 B1에서 답장을 본다고 가정하지 마세요.

동의 및 수신 거부 기록, 현재의 고지/정책 버전, 캠페인 식별자, 가려진 승인 증거는 교회가 관리하는 기록에 보관하세요. 키나 수신자 목록을 공개 지원 티켓에 붙여 넣지 마세요. 번호, 서비스, 자격 증명, 가입 흐름, 빈도, 목적이 바뀌면 다시 재개하기 전에 통합을 다시 확인하고, 필요하면 등록과 동의를 업데이트하세요. 가족이 함께 쓰는 번호와 바뀐 번호는 주의 깊게 검토하세요. 자격은 모든 가족 구성원의 기록이 아니라 동의한 전화번호와 프로그램을 따릅니다.

거절된 경우에는 실제 Twilio 오류를 읽고, 웹사이트와 제출 내용의 특정 불일치를 바로잡은 뒤 교회의 Console에서 다시 제출하세요. 등록되지 않았거나 대기 중인 발신자라면, 등록이 끝날 때까지 기다리세요. 이를 피하려고 번호를 바꾸지 마세요. [Twilio 등록 문제 해결](https://www.twilio.com/docs/messaging/compliance/a2p-10dlc/troubleshooting-a2p-brands)과 제공된 오류 코드 자료를 사용하세요. 정해진 처리 기간을 약속하지 마세요.
