# 서버 관리

<div class="article-intro">

ChurchApps의 서버 관리 기능은 **Server.Admin** 권한이 있는 사용자만 사용할 수 있습니다. 이러한 도구는 시스템의 모든 교회에 대해 플랫폼 운영, 지원 및 문제 해결에 사용됩니다.

</div>

:::warning 액세스 제한됨
이 페이지에서 설명하는 기능은 **Server.Admin** 권한이 필요하며 일반 교회 관리자가 사용할 수 없습니다. 플랫폼 운영자 및 지원 직원만 사용할 수 있습니다.
:::

## 서버 관리자 액세스

Server.Admin 권한이 있는 사용자는 B1 Admin에서 서버 관리자 패널에 액세스할 수 있습니다:

1. [admin.b1.church](https://admin.b1.church)에 로그인
2. **설정**을 연 다음 설정 메뉴에서 **서버 관리자**를 클릭합니다. (또는 `admin.b1.church/admin`으로 바로 이동할 수 있습니다.)
3. 서버 관리자 패널에는 교회, 사용자, 사용자 가장, 배경 작업, 커먼즈, 사용 추세, 번역 조회, 서버 상태 및 데이터베이스 마이그레이션에 대한 섹션이 있습니다

## 사용자 가장

가장 기능을 사용하면 서버 관리자가 지원 및 문제 해결 목적으로 다른 사용자로 로그인할 수 있습니다. 이는 사용자가 보고한 문제를 조사하거나 교회가 시스템을 구성하도록 도울 때 유용합니다.

### 사용자를 가장하는 방법

1. 서버 관리자 패널의 **사용자 가장** 섹션을 열기
2. 검색 필드에 사용자의 이름 또는 이메일 주소 입력
3. **검색**을 클릭하거나 Enter 키 누르기
4. 검색 결과에서 가장하려는 사용자를 클릭
5. 나타나는 대화 상자에서 가장 확인
6. 해당 사용자로 로그인되고 해당 계정으로 리디렉션됩니다

### 중요 참고사항

- 가장은 대상 사용자의 권한 및 교회 액세스 권한으로 새 세션을 만듭니다
- 다른 사용자를 가장할 때 원본 관리자 세션이 종료됩니다
- 가장 중에 수행된 모든 작업은 감사 추적에 기록됩니다
- 관리자 계정으로 돌아가려면 로그아웃한 후 자격증으로 다시 로그인합니다
- 지원 목적으로만 필요할 때만 가장을 사용하고 지원을 위해 계정에 액세스할 때는 항상 사용자에게 알립니다

### API 엔드포인트

가장 기능은 멤버십 API의 `/users/:userId/impersonate` 엔드포인트로 지원됩니다. 기술 세부 사항은 [멤버십 엔드포인트](/docs/developer/api/endpoints/membership#users)를 참고하세요.

### 보안 고려사항

- 가장은 Server.Admin 권한이 필요하며, 이 권한은 신뢰할 수 있는 플랫폼 운영자에게만 드물게 부여해야 합니다
- 모든 가장 이벤트는 관리자 사용자 ID 및 대상 사용자 ID로 기록됩니다
- 가장이 발생할 때 교회에 알림이 전송되지 않으므로, 이 기능을 사용할 때와 방법에 대한 명확한 정책을 수립합니다
- 책임성을 위해 지원 티켓 시스템에서 가장 이벤트를 문서화하는 것을 고려합니다

## 커먼즈 중재

커먼즈는 사용자가 제출한 콘텐츠 전체에 대한 공유 중재 큐입니다. WorshipCommons 곡, Lessons.church 레슨, FreeShow 템플릿 및 B1 웹사이트 빌더 템플릿은 모두 별도의 제품별 검토 도구 대신 동일한 큐를 통해 흐릅니다.

### 커먼즈 액세스

1. 서버 관리자 패널의 **커먼즈** 탭으로 이동합니다.
2. **큐**, **보고서** 및 **자산**이라는 세 개의 하위 탭이 표시됩니다.

제한된 **음악 편집기** 역할도 큐 탭을 볼 수 있지만, 곡의 권리 또는 라이선스를 변경하는 제출을 승인하는 것은 차단됩니다.

### 큐

큐는 제품 및 자산 유형별로 필터링할 수 있는 모든 제품의 모든 보류 중인 제출을 나열합니다. 각 행은 제출이 새 자산, 원본 작성자의 편집 또는 제3자 편집인지 여부, 제출자의 승인 기록 및 제출이 대기 중인 기간을 보여줍니다(72시간을 초과하면 플래그됨).

**검토**를 클릭하면 필드 수준 차이, 파일 미리보기 및 항목의 포함된 읽기 전용 미리보기가 있는 드로우어가 열립니다. **a**/**r** 키보드 바로 가기를 사용하여 승인 또는 거부하고, **j**/**k**를 사용하여 드로우어를 벗어나지 않고 다음 또는 이전 제출로 이동합니다. 거부하려면 이유(예: 품질, 중복, 라이선스, ccli, ai 또는 주제 벗어남)와 메모를 선택해야 합니다.

### 보고서

보고서 탭은 이미 게시된 자산에 대해 제출된 저작권 및 정책/품질 보고서를 처리하며, 별도의 저작권 및 정책 및 기타 큐와 해결된 기록으로 분할됩니다. 보고서를 요청하여 작업을 시작한 다음 해결책(승인, 기각 또는 중복)과 작업(없음, 게시 취소 또는 제거)으로 해결합니다.

### 자산

자산 탭은 게시된 콘텐츠의 검색 가능한 브라우저로, 자산을 **기능**(제품의 홈 페이지에 강조 표시), **게시 취소**/**재게시** 또는 **제거**(저작권 또는 정책 이유 포함)하는 작업이 있습니다.

특히 곡의 경우, 이것은 곡이 **일요일 준비**가 되어 교회의 B1 Admin 곡 검색에 나타날 수 있게 되는 곳입니다: 검토자가 자산을 열고 각 게시된 키를 **청취됨**으로 표시한 후 악보, 코드 및 슬라이드가 모두 있는지 확인합니다. 곡은 모든 키가 체크된 후에만 일요일 준비가 됩니다.

:::info
커먼즈 중재는 직원 전용입니다. 개별 교회는 이 큐를 절대 보지 못합니다. 개별 교회의 B1 Admin이 커먼즈 데이터에 접하는 유일한 곳은 [곡 검색](/docs/b1-admin/serving/songs#free-songs-from-worshipcommons)의 "WorshipCommons — 무료" 섹션입니다. 여기서는 이미 이 검토 프로세스를 거친 곡만 표시됩니다.
:::

근본적인 데이터 모델 및 제출 생명 주기에 대해서는 [콘텐츠 커먼즈 아키텍처](/docs/developer/architecture/commons) 페이지를 참고하세요.

## 그룹 이메일 승인

교회는 서버 관리자가 그룹 이메일(그룹 이메일, 양식 후속, 워크플로 이메일 및 계정 초대)을 승인할 때까지 교회 작성 이메일을 보낼 수 없습니다. 이는 봇 등록 교회가 공유 ChurchApps 발신 주소를 스팸에 사용하지 못하도록 합니다.

1. 서버 관리자 패널에서 **교회** 탭을 열기
2. 각 교회는 **그룹 이메일** 칩을 표시합니다: **승인됨**(녹색) 또는 **승인 안 됨**(윤곽선).
3. 칩을 클릭하고 교회를 승인하거나 승인을 취소하는 것을 확인합니다.

교회 직원은 B1 Admin의 이메일 전송 대화 상자에서 **검토 요청** 버튼을 사용하여 승인을 요청합니다. 요청은 지원 주소로 이메일을 통해 전송되며 교회의 이름, ID, 등록 날짜, 위치 및 요청자를 나열합니다. 교회는 주당 하나의 요청을 보낼 수 있습니다. [교회 작성 이메일 한도](/docs/developer/architecture/notifications#church-authored-email-limits)를 참고하여 일일 허용량과 반송 및 불만에 대한 자동 일시 중지를 확인하세요.

## 데이터베이스 마이그레이션

배포는 데이터베이스를 변경하지 않습니다. 호스팅된 데이터베이스는 Api의 네트워크 내부에서의 연결만 수락하므로, 마이그레이션을 추가하는 릴리스 후 서버 관리자는 **데이터베이스 마이그레이션** 탭에서 적용합니다. (자체 호스팅 Docker 설치는 Api 컨테이너가 시작될 때 여전히 마이그레이션을 자동으로 실행합니다.)

탭은 현재 환경 및 모듈(멤버십, 참석, 기부 등)당 하나의 행을 상태, 적용된 및 보류 중인 마이그레이션의 수, 마지막으로 적용된 것을 표시합니다.

- **보류 중인 마이그레이션 실행**은 모든 보류 중인 마이그레이션을 한 번에 하나씩, 순서대로 적용합니다. 첫 번째 실패에서 중지되고 각 모듈에 적용된 항목을 보여줍니다.
- **마이그레이션 기록 없음**으로 표시된 모듈은 마이그레이션 추적보다 먼저 데이터베이스를 가집니다. 이전 데이터 마이그레이션을 라이브 테이블 위에 재생하기 때문에 자동으로 실행되지 않습니다. 대신 해당 모듈에서 **스키마 확인**을 클릭합니다. Api는 각 마이그레이션이 생성하는 테이블, 열 및 인덱스를 라이브 데이터베이스와 비교하고 각 마이그레이션을 **이미 적용됨**, **누락**, **부분 적용됨** 또는 **데이터만**으로 표시합니다. 확인으로 인해 아무것도 변경되지 않습니다.
- 확인 결과에서 **이미 적용됨으로 기록**은 감지된 마이그레이션을 마이그레이션 기록에 작성하고 실행하지 않습니다. 누락된 것들은 보류 중 상태로 유지되고 정상적으로 실행할 수 있습니다.
- **부분 적용됨** 마이그레이션이 기록을 차단합니다. 마이그레이션을 다시 실행하기에 안전한 경우(먼저 읽기), **다시 실행** 확인란을 선택하여 보류 중 상태로 유지하고 맨 위에서 다시 실행합니다.

서버 관리자 패널 및 CLI(`yarn migrate:up`)는 동일한 Kysely 마이그레이터와 `kysely_migration` 테이블을 사용하므로 항상 적용된 내용에 동의합니다. 지원 엔드포인트는 `GET /membership/serverHealth/migrations`, `POST /membership/serverHealth/migrations/:module/run`, `GET .../:module/detect` 및 `POST .../:module/baseline`이며, 모두 Server.Admin 전용입니다.
