# Make

<div class="article-intro">

[Make](https://www.make.com)（旧 Integromat）は、ビジュアルなワークフロー自動化プラットフォームです。考え方は Zapier に近いものの、より柔軟なロジックを組むことができ、利用規模が大きくなってもコストを抑えやすいのが特長です。公式の B1.church Make アプリを使うと、B1 のイベントに即座に反応して、結果を B1 に書き戻す「シナリオ」を作成できます。

</div>

<div class="prereqs">
<h4>始める前に</h4>

- [Make](https://www.make.com) のアカウント（無料プランで小規模なワークフローは実行できます）
- B1Admin で **設定の編集** 権限を持つ教会の管理者
- 作成したいシナリオの大まかなイメージ

</div>

## モジュール

| 種類 | 内容 | B1 のイベント / エンドポイント |
|---|---|---|
| **即時トリガー** | イベントを監視 | 購読可能な任意の B1 イベント（`person.created`、`donation.created`、…） |
| **アクション** | 人物を作成 | 新しい人物を追加します |
| **アクション** | 寄付を追加 | 寄付を記録します |
| **アクション** | グループメンバーを追加 | 人物をグループに追加します |
| **検索** | 人物を検索 | 名前またはメールアドレスで人物を探します |

即時トリガーでは、待ち受けるイベントを選択できます。トリガーモジュールはシナリオごとに 1 つで、イベントごとに設定します。

## セットアップ

### 1. B1 の API キーを作成する

1. B1Admin で **設定 → 開発者 → API キー** を開きます。
2. **新しい API キー** をクリックし、名前を「Make」に設定して、必要なスコープを付与します。
3. シナリオで即時トリガーを使う場合は、**`settings:write` を必ず含めてください**。シナリオを有効にすると、Make が代理で Webhook を登録するためです。
4. アクションモジュールに必要なスコープも付与します（例：寄付を追加モジュールには `donations:write`）。
5. 保存し、`cak_…` で始まるキーをコピーします。

### 2. 接続を設定する

1. Make で新しいシナリオを作成し、**B1.church** トリガーモジュールをキャンバスに配置します。
2. 表示されたら **接続を作成** を選びます。*API Key* の欄に API キーを貼り付け、*API Base URL* は `https://api.churchapps.org` のままにします（ステージング環境でテストする場合を除きます）。
3. **保存** をクリックします。Make が教会のプロフィールを読み取ってキーをテストします。

接続は Make アカウントに保存され、他のシナリオでも再利用できます。

### 3. トリガーを設定する

1. **イベントを監視** モジュールの設定を開きます。
2. 対象のイベントを選択します（例：`donation.created`）。
3. 保存します。Make が一意の Webhook URL を生成し、内部に保存します。

### 4. 後続のモジュールを追加する

Make の数百種類にのぼるアプリモジュールから、必要なものをキャンバスに配置します。Mailchimp、Google スプレッドシート、Slack、HubSpot、独自の HTTP エンドポイントなどが利用できます。トリガーの出力（`event`、`churchId`、`data.id`、`data.amount`、…）を、各モジュールの入力欄にマッピングします。Make のフラット化、イテレーター、ルーター、アグリゲーターのモジュールを使うと、Zapier では実装が難しい分岐や並列処理のフローも構築できます。

### 5. シナリオを有効にする

シナリオのヘッダーにある **有効** を切り替えます。Make が B1 の `POST /membership/webhooks` を呼び出し、URL を登録します。これ以降、条件に一致する B1 のイベントがすべてリアルタイムでシナリオに流れます。

シナリオを無効にすると `DELETE /membership/webhooks/{id}` が呼び出され、使われなくなった購読が残らないようになります。

## よくあるレシピ

### 寄付を Google スプレッドシートに同期して経理で確認する

- **トリガー** — B1：イベントを監視（`donation.created`）
- **アクション** — Google スプレッドシート：行を追加。`data.donationDate`、`data.amount`、`data.personId`、`data.method`、`data.batchId` をシートの列にマッピングします。

### 寄付額に応じて Slack に通知する

- **トリガー** — B1：イベントを監視（`donation.created`）
- **ルーター**：
  - 分岐 A — フィルター：`data.amount >= 1000` → Slack：`#major-gifts` に投稿
  - 分岐 B — それ以外 → Slack：`#donations` に投稿

### 新しい人物を CRM、ウェルカムメール、Slack に連携する

- **トリガー** — B1：イベントを監視（`person.created`）
- **アクション** — HubSpot：コンタクトを作成
- **アクション** — Mailgun：ウェルカムメールを送信
- **アクション** — Slack：`#new-people` に通知（並列実行。Make のルーターを使います）

## 即時トリガーの仕組み

即時トリガーはポーリングではなく Webhook で動作します。有効化されると、Make は生成された URL と選択したイベントを指定して `POST /membership/webhooks` を呼び出します。B1 でイベントが発生すると、B1 はそのデータを Make の URL に POST し、シナリオが数秒以内に実行されます。シナリオを無効にすると、Webhook も削除されます。

トリガーが反応するのは、シナリオが**有効な状態で**発生したイベントのみです。過去のイベントが遡って処理されることはありません。

## 制限事項と注意点

- **Webhook の「イベントを監視」モジュールごとに 1 イベント。** 1 つのシナリオで複数のイベントを監視したい場合は、トリガーモジュールを別々のシナリオに分けて配置するか、後述のように結合したイベント一覧を使った 1 つのモジュールを利用してください。
- **署名検証は提供されていません。** Make は `X-B1-Signature` をシナリオに渡しません。信頼の境界は、推測困難なシナリオごとの Webhook URL にあります。これは Make では一般的な運用です。明示的な署名検証が必要な場合は、[SDK](/docs/developer/api/webhooks#sdk-support) を使ってカスタム連携を構築してください。
- **オペレーション数。** アクションモジュールによる API 呼び出しはすべて、Make のオペレーション数の上限にカウントされます。B1 側の上限には影響しません。

## トラブルシューティング

- **接続テストに失敗する。** 多くの場合、API キーの入力ミスが原因です。B1Admin から正確にコピーし直してください（キー全体は一度しか表示されません。紛失した場合は新しいキーを作成してください）。
- **トリガーモジュールが有効化されない。** B1Admin の **設定 → 開発者 → Webhook** を確認してください。シナリオを有効化した後に「Make — &lt;event&gt;」の行が表示されない場合、キーに `settings:write` が不足しています。キーを更新してから、シナリオを再度有効にしてください。
- **アクションが `403 Forbidden` を返す。** API キーに、そのエンドポイントに必要なスコープがありません。例えば、寄付を追加には `donations:write` が必要です。B1Admin でキーを更新し、再度テストしてください。

## アプリのカスタマイズ

B1.church Make アプリはオープンソースで、JSON の定義は `B1Integrations/Make/` リポジトリにあります。必要なモジュールがない場合（まだ対応していないエンドポイントの新しいアクションなど）は、そのリポジトリに Issue または PR を作成してください。
