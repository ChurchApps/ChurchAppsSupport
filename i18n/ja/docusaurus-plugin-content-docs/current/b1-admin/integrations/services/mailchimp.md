# Mailchimp

<div class="article-intro">

B1 の人物情報と Mailchimp のオーディエンスを自動で同期します。名前、メールアドレス、電話番号を持つ人が Mailchimp に追加され、グループやリストへの所属は Mailchimp のタグになり、削除された人はアーカイブされます。この同期は B1 に組み込まれており、サードパーティのサービスは不要です。タスクごとの従量課金もなく、変更は夜間のバッチではなくほぼリアルタイムで反映されます。

</div>

<div class="prereqs">
<h4>始める前に</h4>

- B1 で管理したいオーディエンスを持つ [Mailchimp](https://mailchimp.com) アカウント
- Mailchimp の **API キー**（Mailchimp: プロフィールアイコン → **Account & billing → Extras → API keys**）
- **オーディエンス ID**（Mailchimp: **Audience → Settings → Audience name and defaults**）
- **Edit Settings** 権限を持つ B1Admin のユーザー

</div>

## 同期される内容

| B1 での変更 | Mailchimp での反映 |
|---|---|
| 人物の追加または更新 | サブスクライバーを追加または更新（名、姓、電話番号。新規のサブスクライバーは `subscribed` の状態で追加されます） |
| 人物の削除（または GDPR による消去） | サブスクライバーをアーカイブ |
| 人物がグループに参加 | グループ名と同じ名前のタグを追加 |
| 人物がグループから離脱 | そのタグを削除 |
| 人物が保存済みリストに追加 | リスト名と同じ名前のタグを追加 |
| 人物が保存済みリストから削除 | そのタグを削除 |

**タグの元にするには、通常は保存済みリストの方が適しています。** B1 の [保存済みリスト](/docs/b1-admin/people/lists) は、ルールに基づいて自動的に再評価されるオーディエンスです。例えば「北キャンパスのすべての人」や「牧会的なメールの受信に同意したメンバー」などです。Mailchimp のセグメントをリストのタグに結び付けておけば、同期によって自動的に維持されます。グループのタグは、ミニストリーチームへの配信に使うとよいでしょう。

同期は**一方向**（B1 → Mailchimp）で、Mailchimp の標準フィールドにのみ反映されます。そのため、Mailchimp 内で管理しているマージフィールドやセグメントと競合することはありません。

## セットアップ

1. B1Admin で **Settings → Developer → Webhooks → New Webhook** に進みます。
2. **Connector Type** を **Mailchimp** に設定します。
3. **Mailchimp API Key** と **Audience ID** を貼り付けます。キーは暗号化されて保存され、以後は再表示されません。
4. 関連するイベントはあらかじめ選択されています。不要なものはチェックを外してください（例：人物のイベントはオンのままにして、グループのタグは除外するなど）。
5. 保存します。B1 は受け付ける前に、キーとオーディエンスを Mailchimp に対して検証します。入力ミスがあれば、理由とともにすぐに失敗します。

接続を再確認したいときは、いつでも **Send Test** を使用してください。すべての同期の試行は、Mailchimp からの実際の応答とともにウェブフックの配信履歴に記録されます。配信に失敗した場合は、約 5 日間、間隔を徐々に広げながら自動的に再試行されます。

## 初回インポート

このコネクターは、有効になった時点以降の*変更*を同期します。既存のディレクトリを遡って取り込むことはありません。セットアップの日には、次の手順を行ってください。

1. B1Admin で **People** に進み、対象の人を検索します（または保存済みリストを実行します）。**Export** をクリックして CSV をダウンロードします。
2. Mailchimp で **Audience → Import contacts** を使って CSV を読み込みます。インポート時に必要なタグを適用してください。

初回の読み込みを Mailchimp のインポーターから行うと、同意の確認を自分で管理できます。メールの受信に実際に同意している人だけをインポートしてください。ディレクトリ全体をサブスクライブ済みの連絡先として一括インポートすると、Mailchimp の利用規約や迷惑メール防止法（CAN-SPAM/GDPR）に違反するおそれがあります。

## 制限と注意点

- **一方向の同期です。** Mailchimp での購読解除、バウンス、編集は B1 に反映されません。Mailchimp で購読を解除した人も、B1 から直接送信されたメールを受け取ることがあります。一括メールの同意については、Mailchimp を正として扱ってください。
- **メールアドレスのない人はスキップされます**（配信履歴にその旨が記録されます）。Mailchimp のサブスクライバーはメールアドレスで識別されるためです。
- **メールアドレスを変更すると、新しいサブスクライバーが作成されます。** Mailchimp は人をメールアドレスで識別するため、B1 で人のメールアドレスを変更すると、新しいアドレスで追加されます。古いサブスクライバーは、Mailchimp でアーカイブするまで残ります。
- **同期されるのは標準フィールドのみです**（名、姓、電話番号）。このバージョンでは、所属ステータス、キャンパス、B1 のカスタムフィールドは Mailchimp のマージフィールドにマッピングされません。セグメントを作成するには、リストのタグを使用してください。
- **タグ名はグループ名またはリスト名になります。** グループまたはリストの名前を変更すると、新しい名前でタグ付けが始まります。古いタグは、既存のサブスクライバーから Mailchimp で削除するまで残ります。
- **Mailchimp の連絡先数の上限は引き続き適用されます。** 同期によって無料プランのオーディエンスが上限を超えると、配信履歴に `Member limit reached` のエラーが記録されます。

## その他のレシピ（Zapier / Make）

オーディエンスの同期以外の処理、例えば `donation.created` をきっかけに寄付者にタグを付ける処理、Mailchimp → B1 の逆方向の同期、あるいは Constant Contact や Brevo などの別のメールプラットフォームへの同期は、[Zapier](../zapier.md) または [Make](../make.md) を通じて引き続き行えます。どちらも同じウェブフックのイベントをトリガーにできます。

- **寄付者へのタグ付け:** B1 の *New Donation* → B1 の *Find Person* → Mailchimp の *Add Subscriber to Tag*（`Gave-2026`）
- **双方向:** Mailchimp の *New Subscriber* → B1 の *Create Person*

以前に人物とグループの同期を Zapier で設定していた場合は、ネイティブコネクターを有効にした後にそれらの Zap をオフにしてください。両方を動かすと、すべてのイベントが二重に処理され、Zapier のタスクが無駄に消費されます。

## トラブルシューティング

- **保存時に「Mailchimp rejected the API key」と表示される** — キーが無効化されたか、入力を誤っています。キーは `-us21` のようなデータセンターのサフィックスで終わる必要があります。
- **保存時に「audience not found」と表示される** — そのアカウントの下にオーディエンス ID が存在しません。**Audience → Settings → Audience name and defaults** からコピーしてください（オーディエンスの名前ではありません）。
- **人物が Mailchimp に表示されない** — ウェブフックの配信履歴を確認してください。「Skipped: person has no email address」は、その人にメールアドレスがないことを意味します。Mailchimp からの `4xx` は、応答本文に理由が表示されます。
- **配信が完全に停止している** — 配信の失敗が繰り返されると、ウェブフックは自動的に無効になります。原因（多くは無効化されたキー）を解決してから再度有効にし、**Send Test** で確認してください。
