# グループ参加リクエスト

<div class="article-intro">

グループが承認制の参加ポリシーで設定されている場合、人々は参加リクエストを送信できます。グループリーダーと管理者がこれらのリクエストを確認し、承認または辞退します。これにより、教会はグループメンバーシップを管理しつつ、参加への関心を示しやすくなります。

</div>

<h4>始める前に</h4>

- グループを管理する権限、または特定のグループのリーダーである必要があります。詳細は[役割と権限](../people/roles-permissions.md)をご覧ください。
- グループの参加ポリシーを **Request**（承認が必要）に設定しておく必要があります。参加ポリシーの設定方法は[グループの作成](./creating-groups.md)をご覧ください。

## 参加ポリシーについて

グループには3種類の参加ポリシーを設定できます。

- **Open** -- 承認なしで誰でもすぐに参加できます
- **Request** -- 参加リクエストの送信が必要で、承認が求められます
- **Closed** -- 誰も参加をリクエストできません（メンバーは手動で追加する必要があります）

グループが **Request** ポリシーを使用している場合、すべての参加の試みは、このページで説明する承認のワークフローを経由します。

## 保留中のリクエストを表示する

### グループリーダーの場合

1. B1 Adminで[ジャンプメニュー](../introduction.md#getting-around-with-the-jump-menu)を開き、**People > Groups** を選択します
2. グループ名をクリックします
3. **Members** セクションに、保留中のリクエストの件数が表示されます。**All members** をクリックすると、このグループの保留中のリクエストがメンバー一覧の上部に表示されます

### 管理者の場合

グループ管理の権限を持つ管理者は、すべてのグループの保留中のリクエストを確認できます。

1. ジャンプメニューで **People > Groups** を選択します
2. ページヘッダーの **pending requests** ボタンをクリックします（例：「3 pending requests」）。このボタンは、承認待ちのリクエストがある場合にのみ表示されます
3. 教会全体の保留中のリクエストをすべて確認します

## 参加リクエストを確認する

各参加リクエストには、以下の情報が表示されます。

- **申請者の名前と写真** -- 参加を希望している人
- **任意のメッセージ** -- 参加を希望する理由を説明した個人的なメッセージ（入力されている場合）
- **申請日** -- リクエストが送信された日時

リクエストを確認するには：

1. 申請者がメッセージを入力している場合は、その内容を読みます
2. 必要に応じて申請者の名前をクリックし、プロフィールを表示します
3. 承認するか辞退するかを決めます

## リクエストを承認する

1. 参加リクエストの **Approve** をクリックします
2. 申請者はすぐにグループのメンバーとして追加されます
3. 申請者には、リクエストが承認されたことを知らせる通知が届きます
4. リクエストはシステム上で承認済みとしてマークされます

:::tip
リクエストを承認すると、その人は通常のグループメンバーになります。必要に応じて、後から[グループメンバー](./group-members.md)ページでグループリーダーに昇格させることができます。
:::

## リクエストを辞退する

1. 参加リクエストの **Decline** をクリックします
2. 必要に応じて、辞退の理由を入力します（500文字まで）
3. **Confirm** をクリックします
4. 申請者には、辞退の理由（入力されている場合）を含む通知が届きます
5. リクエストは辞退済みとしてマークされます

:::info
辞退の理由を伝えると、申請者が承認されなかった理由を理解しやすくなり、後で再度申し込んだり、他のグループを検討したりするきっかけになる場合があります。
:::

## タスクページから承認する

すべての参加リクエストは、**Serving &rarr; My Work** の下に「*Person*が*Group*への参加をリクエストしました」というタイトルのタスクも作成します。タスクはグループのリーダーに割り当てられます。グループにまだリーダーがいない場合は、**Group Members &gt; Edit** の権限を持つスタッフに割り当てられ、その権限を持つ人がいない場合は教会のドメイン管理者に割り当てられます。この方法でタスクを受け取ったスタッフと管理者には、タスクに直接移動できる通知も届きます。

タスクを開くと、申請者の名前、グループ、任意のメッセージが表示され、タスクカード上に **Approve** と **Decline** のボタンがあります（辞退を選択すると、上で説明した任意の理由入力欄が開きます）。これにより、リーダーはグループのメンバー一覧を開かなくても、通知をきっかけに参加リクエストに対応できます。

いずれの場所（グループのメンバー一覧またはタスクカード）からリクエストを決定しても、リクエストはすべての場所で完了になります。そのため、リーダーが既に対応済みのリクエストについて古いタスクを目にすることはありません。

## 通知

参加リクエストの仕組みでは、次の通知が自動的に送信されます。

- **リクエストが送信されたとき** -- すべてのグループリーダーに通知が届きます。グループにリーダーがいない場合は、代わりにそのタスクに割り当てられたスタッフまたは管理者に通知が届きます（上記を参照）。
- **リクエストが承認されたとき** -- 申請者に確認の通知が届きます
- **リクエストが辞退されたとき** -- 申請者に、辞退の理由（ある場合）を含む通知が届きます

通知は、B1.church のユーザー通知センターとモバイルアプリに表示されます。B1 Adminの通知ベルで参加リクエストの通知（または **View Details**）をクリックすると、教会のB1.churchサイトでグループが新しいタブに開きます。

## メンバー側から参加リクエストを管理する

メンバーは B1.church から自分の参加リクエストを管理できます。

- グループの詳細ページで、保留中のリクエストの状況を確認する
- 気が変わった場合は、保留中のリクエストをキャンセルする
- リクエストが承認されたか辞退されたかを確認する

## ベストプラクティス

- **迅速に対応する** -- 人々を待たせないよう、24〜48時間以内にリクエストを確認するようにしましょう
- **辞退の理由は明確に** -- 次のステップや代替案を理解してもらえるようにしましょう
- **プロフィールを確認する** -- 申請者のプロフィールを見て、グループに合っているかを確認しましょう
- **期待される内容を伝える** -- グループの説明に、どのような人を対象としたグループかを明確に記載しましょう
