# ワークフロー

<div class="article-intro">

ワークフローは、一連のステップに沿って人々をビジュアルなボード上で進めるための機能です。参加者一人ひとりがカードとなり、最初の来訪者へのフォローアップから、メンバーシップの手続き、初めての献金者へのお礼まで、同じ段階を経て管理したい多くの人を追跡する場面で、ステップからステップへと移動していきます。各ステップでは、ボランティアに電話をかけたり面談をしたりといった作業を依頼できると同時に、メールやテキストの送信、数日間の待機、グループへの追加といった自動処理を実行できます。そのため、ワークフローは人の手によるフォローアップと、その周辺の作業の両方を担えます。ワークフローは、[タスク](./tasks.md)をドラッグ&ドロップ式のカンバンボードに拡張したもので、対応漏れが起きないようにします。

</div>

<div class="prereqs">
<h4>始める前に</h4>

- 追跡したい人が B1 Admin に登録されていることを確認してください
- 各カードはタスクになるため、[タスク](./tasks.md)の仕組みに慣れておいてください
- **メールを送信**アクションを使うには、先にメールテンプレートを作成してください(**設定 → メールテンプレート**で管理します)
- **テキストを送信**アクションを使うには、先に[テキスト送信サービス](../settings/church-settings.md#texting)を接続してください
- 適切なタスクの権限が必要です。閲覧、カードの編集、ワークフローの管理はそれぞれ別の権限レベルです([役割と権限](../settings/roles-permissions.md)を参照してください)

</div>

## ワークフローを表示する

[ジャンプメニュー](../introduction.md#getting-around-with-the-jump-menu)(B1 Admin の左上にある検索バー)を開き、**奉仕**を展開して、**ワークフロー**をクリックします。ワークフローは、それぞれの**カテゴリ**と**ステータス**(**有効**または**無効**)を示す表に一覧表示されます。カテゴリを使っている場合は、一覧の上にあるタブでカテゴリごとに絞り込めます。任意のワークフローをクリックすると、そのボードが開きます。

## ワークフローを作成する

1. ワークフローのページで、**ワークフローを追加**をクリックします。
2. 開始方法を選びます。
   - **空のワークフロー** -- ゼロから始めて、独自のステップを組み立てます。
   - **テンプレートから** -- 編集可能な既製のステップ一式から始めます。組み込みのテンプレートは次のとおりです。
     - **新しい来訪者のフォローアップ** -- 歓迎メールを送信 → 個別の電話 → 次のステップに招待 → つながり
     - **メンバーシップクラス** -- 関心を表明 → クラスに登録 → クラスに出席 → メンバーシップを完了
     - **初めての献金者へのお礼** -- お礼状を送信 → 献金の影響を共有 → 献身
     - **奉仕の割り当て確認** -- 依頼を送り返答を待つ → 返答のない依頼についてボランティアに電話 (詳しくは[奉仕の割り当ての確認](#serving-assignment-confirmations)を参照してください)

   テンプレートのステップを作成するには少し時間がかかります。処理中は**ワークフローを追加**ボタンに**作成中...**と表示され、再度クリックできません。そのため、同じワークフローが重複して作成されることはありません。問題が起きた場合は、*「ワークフローを作成できませんでした。もう一度お試しください。」*と表示されます。
3. ワークフローに**名前**を付けます。
4. 必要に応じて**カテゴリ**を割り当て、関連するワークフローをまとめられます。ドロップダウンからその場で新しいカテゴリを作成することもできます。
   空のワークフローの場合は、**ワークフローの目的**も選びます。**人のフォローアップ**(通常の用途)か**奉仕の割り当て確認**のいずれかです。目的は、ワークフローを作成した後は変更できません。
5. 人をワークフローに追加できるように**有効**のままにするか、追加先のリストから非表示にするために**無効**に設定します。
6. **保存**をクリックします。

:::tip
ワークフローの一覧にある**複製**ボタンを使うと、既存のワークフローを、ステップ、自動アクション、振り分けの設定ごとコピーして、新しいワークフローの出発点にできます。
:::

## ステップでボードを構成する

各ワークフローのボードは**ステップ**で構成され、左から右へと列で表示されます。ワークフローを開き、**ステップを追加**を使って、プロセスの各段階を作成します。

ステップを追加または編集するときは、次の項目を設定できます。

- **ステップ名** -- 列の見出し(例: 「歓迎の電話」「登録待ち」)。
- **期限(日数)** -- カードがこのステップに入ったときに、期限日を自動的に設定します。期限を過ぎたカードには**期限超過**のマークが付きます。
- **既定の担当者** -- このステップに新しく入ったカードが自動的に割り当てられる人またはグループ。既定の担当者が個人の場合、その人にはカードが割り当てられたという通知が届きます。
- **自動アクション** -- カードが到着したときに、システムが自動的に実行する処理(下記を参照)。
- **振り分け** -- カードがこのステップを離れるときの行き先(詳しくは[振り分け](#routing-cards-with-outcomes-and-conditions)を参照してください)。

ステップの列を、プロセスに合う順番にドラッグして並べ替えます。この順番は、他の振り分けが適用されないときにカードが通る既定の経路にもなります。

:::info
新しいステップは先に保存してください。自動アクションと振り分けはステップに紐づくため、ステップが存在するまで、エディターではこれらの項目を設定できません。
:::

## 自動アクション

どのステップにも、カードが**入った**瞬間に、人が何もしなくても実行される**自動アクション**の一覧を設定できます。誰かがカードに触れる前に処理が実行されます。これにより、ステップはボランティアへの指示と、フォローアップ周辺の定型作業の両方を担えます。

ステップエディターで**自動アクション**を開き、**アクションを追加**をクリックして種類を選び、設定を入力します。必要な数だけ追加でき、**上から順番に**実行されます。ステップの**保存**をクリックすると、ステップとそのすべてのアクションをまとめて保存します。ゴミ箱アイコンでアクションを削除すると、すぐに反映されます。

| アクション | 内容 |
|---|---|
| **メールを送信** | 選んだメールテンプレートを本人に送信します。件名は上書きできます。 |
| **テキストを送信** | 作成したメッセージを、教会の[テキスト送信サービス](../settings/church-settings.md#texting)を通じて本人に送信します。 |
| **待機** | 次の処理に進むまで、カードを数日間保留します(下記を参照)。 |
| **グループに追加** | 選んだ[グループ](../groups/index.md)に本人を追加します。 |
| **グループから削除** | 選んだグループから本人を削除します。 |
| **出席を記録** | 進行中のグループの礼拝時間に、本人を出席として記録します(下記を参照)。 |
| **ワークフローに追加** | 本人を別のワークフローに開始させます。プロセス間の引き継ぎに便利です。 |
| **メモを追加** | カードの履歴にメモを記録します。 |
| **フィールドを設定** | 本人の記録のフィールドを更新します。対象は、メンバーシップステータス、配偶者の有無、性別、市区町村、都道府県、郵便番号です。 |
| **Webhook** | カードの詳細を、他のシステムと連携するために指定した外部のWebアドレス(URL)に送信します。 |
| **タスクを作成** | 入力したタイトルと説明で[タスク](./tasks.md)を作成し、選んだ担当者に割り当てます。 |
| **本人に通知** | 選んだスタッフまたはボランティアに、カードについてのメールとB1の通知を送信します(下記を参照)。 |

ステップのすべてのアクションが完了すると、カードはそのステップに**留まり**、誰かが対応できるようになります。ただし、そのステップに自動的な振り分けがあり、カードを次に進める場合は別です(詳しくは[完全自動のステップ](#fully-automated-steps)を参照してください)。

:::info
自動アクションは、カードが通常の流れで到着したときにのみ実行されます。具体的には、カードが最初に追加されたとき、振り分け(結果または自動的な振り分け)によってカードが入ってきたとき、または待機が終わったときです。スタッフがカードを手動でステップにドラッグした場合や、差し戻した場合には**再実行されません**。そのため、同じ人に同じメールが二度届くことはありません。
:::

### メールを送信する

**メールを送信**を選び、メールテンプレートを1つ選択して、必要であれば任意の件名を入力します。カードがステップに入ると、本人に自動的にそのメールが届きます。(本人の登録済みメールアドレスがない場合は、このアクションをスキップします。)テンプレート内の、`{{firstName}}`などの[差し込みフィールド](../settings/email-templates.md#merge-fields)は、本人の情報で置き換えられます。

メールが送信されると、カードの履歴に**メール送信済み**と記録されます。たとえば教会のメールがまだ承認されていない場合や、1日の上限に達している場合など、送信できなかったときには「メール送信済み」の項目は追加されません。

:::info
ワークフローのメールは、教会がグループメールの送信を承認された後にのみ送信され、教会の1日のメール上限にカウントされます。詳しくは[教会のグループメールを有効にする](../groups/group-members.md#turning-on-group-email-for-your-church)を参照してください。**メールを送信**アクションは、これらのメールが送信されない場合にステップエディターで警告を表示します。承認がまだ保留中であれば*「教会のメールはまだ承認されていません...」*と、最近のメッセージが不達になったか、迷惑メールとして報告された場合は*「教会のメールは一時停止中です...」*と表示されます。
:::

### 出席を記録する

**出席を記録**を選び、**グループを選択**をクリックして、出席を記録するグループを選びます。アクションが実行されると、そのグループの進行中の礼拝時間に、本人が出席として記録されます。これは、本人がチェックインした場合と同じ扱いです。人が到着するたびにワークフローに追加するトリガーと組み合わせると便利です。別途チェックインしなくても出席としてカウントされます。

- 出席は、カードが**作成された**時点で判定されるため、ワークフロー内の前の**待機**によって礼拝の時間を過ぎることはありません。
- 曜日と開始時刻が設定された礼拝時間だけがカウントされます。その時点でグループの礼拝時間がどれも進行中でない場合は、何も記録されず、カードの履歴に**進行中の礼拝がありません — 出席は記録されませんでした**と表示されます。
- 出席が記録されると、カードの履歴に**出席を記録しました**とグループ名が表示されます。同じ礼拝に対してアクションをもう一度実行しても、本人が二重にカウントされることはありません。

### 本人に通知する

**本人に通知**を選び、**人を選択**をクリックして、必要であれば**メッセージ**を入力します。カードがステップに入ると、その人に、カードに載っている人の名前、ワークフローとステップの名前、あなたのメッセージ、カードを開くリンクを含むメールとB1の通知が届きます。スタッフや奉仕のリーダーに事前に知らせたいときに使います。例: *「someone が会員面談ステップに到達したら牧師に通知する。」* カードの履歴には、**通知しました**に続けて本人の名前が記録されます。

### テキストを送信する

**テキストを送信**を選び、**テキストメッセージ**を入力します(1,600文字まで)。カードがステップに入ると、本人の携帯電話にそのテキストが届きます。メッセージを個別化するには、メッセージ欄の下にあるチップ(**名**、**姓**、**表示名**、または**教会名**)をクリックすると、カーソル位置に`{{firstName}}`、`{{lastName}}`、`{{displayName}}`、`{{churchName}}`が挿入されます。テキストが送信されるときに、それぞれ本人の情報で置き換えられます。

- 本人の携帯電話番号が登録されていない場合は、テキストは送信されず、カードの履歴に**テキストをスキップ: 携帯電話番号なし**と記録されます。
- 本人が配信停止を選んでいる場合は、テキストは送信されず、カードの履歴に**テキストをスキップ: 配信停止**と記録されます。
- テキストが送信されると、カードの履歴に**テキストを送信しました**と記録されます。送信に失敗した場合(たとえばテキスト送信サービスが接続されていない、または教会のテキストクレジットがなくなった場合など)、失敗はカードの履歴に記録され、そのステップの残りのアクションは引き続き実行されます。

:::warning
テキストは、教会独自の[テキスト送信サービス](../settings/church-settings.md#texting)を通じて送信されます。サービスが接続されていない場合、アクションエディターに*「テキスト送信サービスが設定されていません」*と警告が表示され、テキストは送信されません。
:::

### 数日間待機する(ドリップ配信)

**待機**アクションは、設定した日数の間カードを保留します。待機中、カードには**スヌーズ中**と表示されます。B1は30分ごとに終了した待機がないかを確認するため、待機が終わってから約30分以内にカードは再び処理されます。待機が終わると、次のとおりに進みます。

1. **同じステップ内の残りのアクション**がすべて実行されます。そのため、**メールを送信 → 3日間待機 → リマインダーメールを送信**というドリップ配信を組むことができます。
2. その後、ステップに自動的な振り分けがあればカードは次に進みます。なければ、カードは誰かが対応できるようにステップに留まります。

:::tip
ステップの最初に**待機**を置くのは、ボランティアに表示される前にカードを「保留」する簡単な方法です。例: *7日間待機し、その後コーチが連絡する。*
:::

## 人をカードとして追加する

ボードに人を追加する方法は、いくつかあります。

- **ボードから** -- ステップ列の下部にある**カードを追加**をクリックし、人を選びます。グループを選ぶこともでき、そのグループの全メンバーがそれぞれカードとして追加されます。
- **人の記録から** -- 人のページで**ワークフローに追加**を使い、その人をワークフローに追加します。
- **人の検索から** -- 複数の人を選び、一括の**ワークフローに追加**アクションを使って、まとめて追加します。
- **トリガーで自動的に** -- フォームの送信や初めての献金など、何かが起きたときに人を追加します(下記の[トリガー](#triggers)を参照してください)。

手動で追加した場合も、**ワークフローに追加**のステップアクションで追加した場合も、同じワークフロー上に未完了のカードが2枚になることは決してありません。すでに未完了のカードがある人はスキップされます(一括追加の場合、カードがない人だけに新しいカードが作られます)。カードが完了すると、その人を再び追加できます。トリガーには、代わりに独自の**1人につき1回のみ**の設定が適用されます。

## ボードを操作する

ワークフローを開くと、そのボードが表示されます。各カードには、人の名前、担当者、そして期限またはステータスのチップ(**期限超過**または**スヌーズ中**)が表示されます。ステップの列には、そのステップが実行する自動アクションの小さなバッジと、振り分けの注釈も表示されるため、カードがどのように流れるかを一目で把握できます。

- **カードを移動する** -- 本人の進捗に合わせて、カードを次の列にドラッグします。
- **カードを開く** -- カードをダブルクリックする(またはクリックする)と、詳細のドロワーが開きます。ここでステップを変更したり、担当者を変えたり、メモを追加したり、これまでの経緯を確認したりできます。

カードのドロワーからは、次の操作ができます。

- カードを別の人またはグループに**割り当てる**。
- カードを1日、3日、または1週間**スヌーズ**し、期限を一時的に非表示にする。
- 前のステップに**差し戻す**、または次のステップに**スキップ**する。
- **担当者を固定** -- ステップを移動しても、同じ担当者をカードに保持します。既定では、カードを新しいステップに移動すると、そのステップの既定の担当者に再割り当てされます。担当者を固定すると、現在の担当者が最後まで責任を持ち続けます。
- カードを**完了**する。ステップに結果が設定されている場合は、**結果**のボタンを選ぶこともできます(詳しくは[振り分け](#routing-cards-with-outcomes-and-conditions)を参照してください)。
- **カードを削除** -- 完了させずにボードからカードを外します。たとえば誰かを誤って追加した場合などに使います。確認すると、カードは閉じられ、全員のリストから外れます。結果、振り分け、ステップのアクションは実行されず、履歴は**削除済み**の項目とともに残ります。[奉仕の割り当て確認](#serving-assignment-confirmations)のカードの場合、削除すると、依頼も同じ方法で閉じられます。
- **メモを追加**し、カードの**アクティビティ**を確認する -- 実行された自動アクション(送信されたメール、待機など)の記録で、それぞれ発生した日時が表示されます。

人に関するカードの場合、ドロワーには、その人の携帯電話番号とメールアドレスもリンクとして表示され、タップして電話やメールができます。また、人を表示する権限がある場合は**プロフィールを表示**のリンクも表示されます。カードの担当者は、人の画面にアクセスできなくても、電話番号とメールアドレスを確認できます。

メモはカードと一緒に保存されます。カードを開ける人は、担当者である個人やグループを含めて、メモを読み、自分のメモも追加できます。カードを開けない人は、そのメモを見ることができません。

### 一括操作

複数のカードのチェックボックスを選択すると、まとめて操作できます。あるステップのカードを一度にすべて選ぶには、そのステップの列見出しにある**すべて選択**にチェックを入れます。もう一度チェックを入れると選択が解除されます。ツールバーが表示され、選択したすべてのカードに対して、**完了**、**スヌーズ**、**割り当て**(担当者の変更)、または別のステップへの**移動...**を一度に実行できます。

## 結果と条件で振り分ける

振り分けは、カードがステップを離れるときの行き先を決めます。ステップのエディターを開くと、2種類の振り分けを設定できます。

### 結果のボタン

結果は、そのステップでカードを完了するときに、カードのドロワーに表示されるボタンです。単一の**完了**ボタンではなく、「グループに参加」や「興味なし」などの選択肢を用意できます。各結果では、次の操作を設定できます。

- このワークフロー内の**別のステップ**にカードを送る。
- カードを別のワークフローに完全に**引き継ぐ**。
- カードを**閉じる**。

これにより、1つの判断から、本人を異なる経路に分岐させられます。

### 自動的な振り分け(条件付き)

自動的な振り分けは、人が一連の条件に当てはまる場合に、誰もクリックしなくても、カードがステップに**入った瞬間**に(そして自動アクションが終わった後に)次へ移動させます。振り分けを追加し、移動先のステップを選び、1つ以上の**条件**(たとえば本人のキャンパス、年齢、メンバーシップステータスなど)を定義します。テキストのフィールドは、完全一致させるか、**を含む**、**で始まる**、**で終わる**で照合できます。条件のない振り分けは、すべての人に一致します。

日付の条件(今日の日付、生年月日、記念日)では、日付全体または一部を比較できます。たとえば曜日、**日**、**月**、経過年数です。本人の生年月日または記念日の場合、**日**には相対的な**今日**の選択肢があるため、*生年月日 · 日 = 今日*のような条件は、今日の日付と同じ日に誕生日を迎える人に一致します。**月**には、**前月**、**今月**、**来月**の選択肢があります。こうした相対的な値は、教会のタイムゾーンを基準に計算されるため、サーバーのタイムゾーンではなく、教会の暦上の日付に合わせて動きます。

**献金**の条件グループには、**献金が途絶えた定期的な献金者**があり、以前は定期的に献金していたのに、その後やめてしまった人を見つけます。3つの数値を設定します。*直近12週間のうち少なくとも3週間献金があり、直近3週間は献金がない*(これらが既定値です)。週は教会のタイムゾーンで今日から数えられ、返金された献金は数えません。これは[スケジュールトリガー](#schedule-triggers)で特に役立ちます。たとえば毎週のルールで、献金が途絶えた人を牧会的なフォローアップのボードに追加する、といった使い方です。この条件は献金の日付のみを見て、金額は見ません。また、カードやアラートに金額が表示されることもありません。誰が献金をやめたかが分かってしまうため、この選択肢は献金を閲覧できる人だけに表示され、その人だけが追加、変更、削除できます。

振り分けの条件を何らかの理由で確認できない場合、その振り分けは一致しないものとして扱われます。カードはステップに留まるか(一致する別の振り分けがあれば、それに従い)、行き詰まることはありません。

:::info
ボード上では、各ステップの列に振り分けを説明する小さな注釈が表示されます。たとえば結果のラベル、または「一致する場合」に続けて移動先のステップやワークフローへの矢印が表示されます。
:::

## 完全自動のステップ

ステップを、誰も対応せずに完全に自動で実行させることができます。そのステップに**自動アクション**を設定し、次のステップを指す**自動的な振り分け**(条件なし)を追加します。カードが入ると、アクションが実行され、その後振り分けによってすぐに次へ進みます。カードはそのまま通り抜けます。

:::tip
**待機**と組み合わせると効果的です。*歓迎メールを送信 → 3日間待機 → 「個別の電話」ステップへ自動的に進める。* メールと時間の調整は自動で行われ、ボランティアはカードが人の対応をする時期になったときだけ、そのカードを目にします。
:::

## トリガー

トリガーは、何かが起きたときに人をワークフローに自動的に追加するため、カードを手動で追加する必要がありません。ワークフローのボードで**トリガー**タブをクリックし、次に**トリガーを追加**をクリックします。トリガーには2種類あります。

### イベントトリガー

B1 のレコードが変更されるとすぐに起動します。イベントを選び、必要に応じて**条件**を追加すると、条件に合う人だけが追加されます。

- **人 · 作成 / 更新** -- たとえば、ステータスが*来訪者*または*ゲスト*(自分で登録した人に付くステータス)になった人を追加します。
- **献金 · 作成** -- たとえば、初めての献金や高額の献金を、お礼のワークフローに追加します(金額、基金、方法で照合できます)。
- **グループ · メンバーが参加** / **グループ · 作成**。
- **フォーム · 送信** -- 選んだフォームを送信した人を追加します(「新しく参加しました」や「つながりたい」のカードに最適です)。

### スケジュールトリガー

毎日、毎週、毎月、または毎年といった定期的なスケジュールで、一連の条件に基づいて実行されます。たとえば*今日が誕生日の全員*(生年月日 · 日 = **今日**、月は**今月**に一致)や、*毎月*のチェックインなど、時期に基づく働きかけに使います。**1人につき1回のみ**の設定がなくても、スケジュールトリガーは、同じ繰り返し期間内(日、週、月、年のうち、実行頻度に応じた期間)に同じ人を再び追加することはありません。

どのトリガーでも、次の項目を設定できます。

- 新しいカードが配置される**開始ステップ**(既定では最初のステップ)。
- **1人につき1回のみ** -- トリガーによって同じ人がワークフローに二度追加されないようにします。この設定がオンの場合、そのワークフローにすでにカードがある人はスキップされます。
  - **カードが閉じられた後に再度追加** -- **1人につき1回のみ**がオンの場合に表示されます。オンにすると、そのワークフロー上の以前のカードが閉じられた後に、トリガーで同じ人を再び追加できます。人がそのワークフロー上で同時に未完了のカードを2枚持つことは、依然としてありません。再来訪者や毎年のプロセスなど、複数回起こりうる出来事に使います。
- **有効** -- トリガーを削除せずにオンまたはオフにします。

:::tip
**フォーム · 送信**トリガーと**新しい来訪者のフォローアップ**テンプレートを組み合わせると、「コネクトカード」や「新しく参加しました」のフォームを、自動のフォローアップの流れに変えられます。
:::

## 奉仕の割り当て確認

特別な種類のワークフローは、ボランティアが承諾または辞退するまで、[奉仕の依頼](./plans.md#assigning-team-members)をフォローアップできます。このボードの各カードは、人ではなく**1件の割り当て**、つまり1つの計画における1つの役割に就く1人を追跡します。同じ人が2つの役割、または2つの礼拝を担当する場合は、それぞれ別のカードになります。これは任意です。計画の設定で確認ワークフローを選ぶまで、その計画には何も変わりません。

### 設定する

1. ワークフローのページで**ワークフローを追加**をクリックし、**奉仕の割り当て確認**テンプレートを選びます。(または**空のワークフロー**から始めて、**ワークフローの目的**を**奉仕の割り当て確認**に設定します。)テンプレートから作成するには、テキストのステップが含まれるため、テキストを送信する権限が必要です。
2. ステップを確認します。テンプレートは次の内容で始まります。
   - **依頼を送り返答を待つ** -- 奉仕の依頼をメールとテキストで送信し、2日間待機してから、リマインダーメールを送信し、さらに1日待機した後、カードを自動的に次に進めます。
   - **返答のない依頼についてボランティアに電話** -- 1日後が期限で、担当者が電話をかけるためのステップです。このステップに**既定の担当者**を設定してください。設定がない場合、カードは奉仕のリーダー、またはリーダーがいなければ奉仕チームに渡されます。
3. 教会に合うように、待機時間、メッセージ、ステップを編集します。
4. [計画の設定](./plans.md#plan-settings)を開き、**確認ワークフロー**でこのワークフローを選びます。

これらのワークフローでは、**メールを送信**と**テキストを送信**の代わりに**奉仕の依頼を送信**アクションを使います。**メール**または**テキストメッセージ**を選び、必要に応じて**依頼メッセージ**を入力します。依頼には常に役割、計画、奉仕日、返信用のリンクが含まれます。メッセージ内では`{{planName}}`、`{{positionName}}`、`{{serviceDate}}`を使えます。メッセージを空のままにすると、既定の依頼文が使われます。ボランティアの通知設定、テキストの受信への同意、教会のテキスト送信サービス、教会のメール承認はすべて適用され、スキップまたはブロックされた送信試行はカードに記録されます。これらのボードでは、**メールを送信**、**テキストを送信**、**ワークフローに追加**は利用できません。

確認ワークフローの**トリガー**タブには、トリガーを提供する代わりに、カードの開始方法が説明されています。また、これらのワークフローは、人向けの**ワークフローに追加**の一覧には表示されません。

### カードの開始と終了

- 公開された計画で、ボランティアに**通知**すると、カードが開始されます(詳しくは[ボランティアへの通知](./plan-validation.md#notifying-volunteers)を参照してください)。返答のない新しい割り当てごとに、カードが1枚作られます。計画を保存、公開、コピー、自動入力しても、それだけでは誰にも連絡されず、仮の計画では何も送信されません。
- ボランティアには、通常のアプリ内通知が引き続き届きます。メールとテキストによるフォローアップは、ワークフローから送信されます。
- ボランティアが**承諾または辞退**すると、そのカードは、紐づいたフォローアップのタスクとともに自動的に閉じられます。
- カードのドロワーには、役割、奉仕日、計画へのリンクが表示されます。**完了**の代わりに、ボタンには**フォローアップ完了を記録**と表示されます。クリックすると、誰かがフォローアップしたことが記録されますが、カードは開いたまま担当者に割り当てられた状態(**返答待ち**と表示)になります。ボランティアが返答するか、返答期限を過ぎるまで続きます。
- 返答期限は、その役割のチームが奉仕する最後の礼拝時間の終了時刻です。計画に一致する時間がない場合は、奉仕日の終了時刻になります。期限までに誰も返答しなかった場合、カードは**返答期限が過ぎました**と表示されて閉じられ、**返答のない奉仕依頼を確認**タスクが、カードの現在の担当者または奉仕のリーダーに送られます。そのうえで誰かが、この枠をどう埋めるかを判断できます。割り当ては**未確認**のままになります。
- 割り当てを削除する、その人、役割、計画の日付を変更する、計画を仮の状態に戻す、または計画を別の確認ワークフローに切り替えると、カードは閉じられます。閉じられたカードは、別の**通知**によって再び開かれることはありません。新しい依頼を送るには、新しい割り当てを追加してください。

:::info
確認ワークフローを通して送られた依頼については、[ボランティアへのリマインダー](./plans.md#volunteer-reminders)は**承諾した**ボランティアにのみ送信されます。そのため、返答を待っている人がワークフローのフォローアップに加えてリマインダーを受け取ることはありません。
:::

## マイカード

ボランティアやスタッフが、すべてのボードを探して自分の仕事を見つける必要はありません。**マイワーク**ページの**マイカード**の一覧には、すべてのワークフローで現在のユーザーに割り当てられたカードがすべて表示されます。ここにアクセスするには、ワークフローのページ上部にある**マイカード**をクリックするか、ジャンプメニューで**奉仕 > マイワーク**を開きます。カードをクリックすると、マイワークのページ上で詳細パネルが開き、そこでカードを操作したり削除したりできます。ページを離れる必要はありません。ワークフローを閲覧できる場合、パネルには**ワークフローのボードを開く**リンクも表示され、そのカードが属するボードに移動できます。

## レポート

ワークフローを開き、**レポート**をクリックすると、そのワークフローの分析を確認できます。

- **期限超過** -- 期限を過ぎたカードの数。
- **ステップごとのカード数** -- 各ステップに現在あるカードの数を、縦棒グラフで表示します。
- **完了(30日間)** -- 過去30日間の処理量を、折れ線グラフで表示します。

これらを使うと、ボトルネックを見つけられます。たとえば、カードが積み上がって先に進まないステップなどです。
