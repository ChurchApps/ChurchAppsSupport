# カレンダーの承認

<div class="article-intro">

承認ページでは、管理者が保留中の部屋・リソースの予約リクエストと、公開前に承認が必要なカレンダーイベントを確認して処理できます。

</div>

<div class="prereqs">
<h4>始める前に</h4>

- [Rooms & Resources](./rooms-resources.md)で、部屋またはリソースに**Approval Group**を設定しておく
- **Calendars Admin**権限または**content.edit**権限が必要です

</div>

## 承認ページを開く

B1 Adminで、[ジャンプメニュー](../introduction.md#getting-around-with-the-jump-menu)（左上の検索バー）を開き、**Calendars**を展開して**Approvals**をクリックします。確認待ちの予約リクエストとレビュー待ちのイベントがここに一覧表示されます。

## 予約リクエスト

グループがイベントを作成して部屋やリソースを申請すると、そのリクエストは**Room & Resource Requests**セクションに表示されます。各行には次の情報が表示されます。

- イベント名と日時
- 申請された部屋またはリソース（複数台のリソースの場合は数量も）
- 競合の有無を示すステータスバッジ

### 競合インジケーター

リクエストが同じ部屋またはリソースの別の予約や利用不可の時間帯と重なる場合、ステータスに**Conflicts**バッジが表示されます。バッジにカーソルを合わせると詳細を確認できます。重なりのないリクエストには**No conflicts**と表示されます。競合するリクエストは、どちらかを承認する前に慎重に確認してください。

### 承認または却下

予約リクエストの**Approve**または**Reject**をクリックします（却下する場合は先に確認が求められます）。申請したグループには決定内容が通知されます。承認された予約は、そのイベントの間、該当の部屋またはリソースに固定されます。却下された予約は、その時間枠を他の人が使えるようになります。

**Approve**をクリックすると**Approve booking**ダイアログが開きます。同じ操作でイベントを公開することもできます。

1. **Publish to public calendar**にチェックを入れると、イベントがそのグループのカレンダーで公開されます。チェックを外したままにすると、イベントの公開設定は変えずに予約だけを承認します。
2. **Publish to public calendar**にチェックを入れたら、必要に応じて**Also add to calendar**からキュレーションカレンダーを選び、イベントを[キュレーションカレンダー](./curated-calendar.md)にも追加できます。追加しない場合は**None**のままにします。（このオプションは**content.edit**権限がある場合にのみ表示されます。）
3. **Approve**をクリックします。

## 保留中のイベント

カレンダーの運用で、イベントを一般公開する前に承認が必要な場合、保留中のイベントは**Event Requests**セクションに表示されます。**Approve**をクリックするとイベントがカレンダーに公開され、**Reject**をクリックすると投稿者に変更が必要であることを通知します。

:::tip
部屋に承認グループを設定すると、その部屋の利用に承認を必要とできます。[Rooms & Resources](./rooms-resources.md)で設定してください。アクセス権のあるグループは、イベント作成時にその部屋を申請でき、そのリクエストがこのページに届きます。
:::
