# エンドポイントリファレンス

<div class="article-intro">

このセクションでは、ChurchApps API が公開しているすべての REST エンドポイントを説明します。各モジュールのページには、HTTP メソッド、パス、認証要件、必要な権限を含むすべてのルートが記載されています。

</div>

## ベース URL

| 環境 | URL |
|-------------|-----|
| ローカル開発 | `http://localhost:8084` |
| 本番 | `https://api.churchapps.org` |

## リクエストの規則

- **Content-Type:** すべてのリクエストとレスポンスの本文は `application/json` を使用します
- **マルチテナント:** 認証が必要なすべてのリクエストは、JWT トークンから取り出された `churchId` にスコープされます。URL に `churchId` を渡す必要はありません
- **一括保存:** ほとんどの `POST` エンドポイントは**オブジェクトの配列**を受け付けます。API は 1 回の呼び出しで、新しいレコード（`id` フィールドなし）を挿入し、既存のレコード（`id` フィールドあり）を更新します
- **ID:** すべてのエンティティ ID は UUID です

### 例: 一括保存

```json
POST /membership/people
Authorization: Bearer <token>

[
  { "firstName": "Jane", "lastName": "Doe" },
  { "id": "abc-123", "firstName": "John", "lastName": "Smith" }
]
```

最初のオブジェクトは作成され（新規）、2 番目のオブジェクトは更新されます（`id` があります）。

## レスポンス形式

成功したレスポンスは JSON を返します。単一のオブジェクトまたは配列です。エラーレスポンスでは標準の HTTP ステータスコードを使用します:

| コード | 意味 |
|------|---------|
| `200` | 成功 |
| `400` | 不正なリクエスト（検証エラー） |
| `401` | 認証されていません（トークンがない、または無効、または権限が不足しています） |
| `404` | 見つかりません |
| `500` | サーバーエラー |

検証エラーは次のように返されます:

```json
{
  "errors": [
    { "msg": "enter a valid email address", "param": "email", "location": "body" }
  ]
}
```

## エンドポイント表の読み方

各モジュールのページでは、エンドポイントをコントローラーごとに整理しています。表では次の列を使用します:

| 列 | 説明 |
|--------|-------------|
| **Method** | HTTP メソッド（`GET`、`POST`、`DELETE`） |
| **Path** | コントローラーのベースパスからの相対ルートパス |
| **Auth** | **JWT** = Bearer トークンが必要、**Public** = 認証不要 |
| **Permission** | 必要な権限（例: `People.Edit`）。`—` は認証済みのすべてのユーザーを意味します |
| **Description** | エンドポイントの機能 |

標準の CRUD 基底クラスを拡張しているコントローラーは、次の 4 つのエンドポイントを自動的に提供します: `GET /`（一覧の取得）、`GET /:id`（ID による取得）、`POST /`（作成/更新）、`DELETE /:id`（削除）。

## レポートモジュール

レポートモジュールは他のモジュールとは動作が異なります。データベースベースの CRUD ではなく、ディスク上の JSON ファイルからレポート定義を読み込み、パラメータ化された SQL クエリを実行します。

| メソッド | パス | 認証 | 説明 |
|--------|-----------|-----------|-------------|
| GET | `/reporting/reports/:keyName` | JWT | キー名でレポート定義を読み込む |
| GET | `/reporting/reports/:keyName/run` | JWT | レポートを実行し、結果を返す |

レポートのパラメータはクエリ文字列の値として渡します（例: `?startDate=2024-01-01&endDate=2024-12-31`）。`churchId` パラメータは JWT トークンから自動的に挿入されます。各レポート定義では、独自の権限要件を指定できます。
