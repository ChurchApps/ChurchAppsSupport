# 教会所有の Twilio オンボーディング草案

:::caution 提案中の連携に関する草案
これは提案段階のワークフローです。現在 B1 には **設定 > Texting** に基本的な **Twilio** の選択肢があります（Account SID、Auth Token、From Number、受信 STOP Webhook）。詳しくは [教会設定: Texting](../../b1-admin/settings/church-settings.md#texting) を参照してください。以下の追加の B1 設定項目、同意の対応付け、検証手順は将来のリリースで必要となる要件であり、既存の設定を探すための手順ではありません。対象範囲と依存関係については [技術提案](./twilio-byok-proposal) を読んでください。Twilio の情報は 2026 年 10 月 22 日に確認したものです。キャンペーンを申請する前に、最新の要件を必ず確認してください。
:::

## 推奨される体制

教会は、有料の Twilio アカウント、電話番号、Messaging Service、請求、キャンペーン登録を所有します。B1 は、教会の設定に非公開で入力された認証情報を使って、これらのリソースから送信します。Twilio アカウントにアクセスできる教会の管理者を少なくとも 2 名確保し、アカウントのセキュリティを有効にして、同意、受信返信、拒否通知を担当する人を決めてください。

ここで提案する最初のリリースは、米国の市内局番を 1 つと、内容を明確に説明した教会のメッセージングプログラム 1 つを対象とします。以下の例では、架空の **Grace Community Church** が、礼拝の変更、イベントのリマインダー、ボランティアのスケジュールのために **Grace Church Updates** というプログラムを運営しています。名前、ドメイン、頻度、連絡先、目的は、必ず教会の実際の運用に置き換えてください。これらは Twilio のルールを教会に当てはめた例であり、事前承認されたキャンペーンや、承認を保証するものではありません。

## 1. B1 の公開サインアップ体験を準備する

教会の B1 ウェブサイトに、`https://www.example.org/text-updates` のようなページを公開してください。埋め込みの公開 B1 フォーム、または単独の公開フォームへの分かりやすいリンクを置きます。あわせて `https://www.example.org/privacy` と `https://www.example.org/sms-terms` も公開してください。これらのアドレスはプレースホルダーです。実際に到達可能な URL を提出してください。

提案する SMS サインアップフォームの設定は次のとおりです。

| 設定 | 推奨構成 |
|---|---|
| アクセス | 公開・制限なし。審査中および継続的な登録期間中は有効。ログインなしで利用可能 |
| フォームモード | 最初は標準モード。会話形式モードには、技術提案で説明する明示的な同意サポートが必要 |
| 携帯電話 | 国番号を含めて明確にラベル付けする。一般的なつながり/イベントフォーム内で使う場合は、SMS 登録を選んだときのみ必須にする |
| SMS の選択 | 別個の任意チェックボックス。初期状態はオフ。特定のプログラムと携帯電話フィールドに対応付ける |
| 開示事項 | SMS の選択肢のそばに表示する。教会/プログラム名、メッセージの目的と頻度、通信料の可能性、STOP、HELP、サポート窓口、実際にクリックできるプライバシーポリシーと SMS 利用規約のリンク |
| その他の操作 | ゲストは SMS に登録せずに、接続カードの送信、イベントへの登録、情報の依頼ができること |
| 証跡 | プログラム、正確な電話番号、選択された同意、送信元の提出内容、サーバー時刻、開示/ポリシーのバージョンを保存する。現状では、通常のフォーム回答だけでは登録されない |
| 人/グループの自動処理 | 既存のマッチングルールを確認するまでは、初回のサインアップ試行では人の自動作成とグループ割り当てをオフにしておく。グループへの割り当ては SMS の許可にはならない |
| 既存の自動処理 | すべてのフォーム送信者やグループメンバーをテキストメッセージのワークフローに登録しない。確認済みの同意の対応付けだけが、そのプログラムへの登録を許可できる |
| サンキューメッセージ | 同意が拒否された場合や、確認/審査が保留中の場合は、SMS に登録されたとはせず、フォームが受け付けられたことだけを伝える |

既存のチェックボックス項目でフォームの例を示すことはできますが、B1 には依然として同意の記録と送信の制御が必要です。現在の共有レンダラーは説明文をプレーンテキストとして表示します。説明欄に Markdown や URL を入力しても、ポリシーのリンクがクリック可能になるという保証にはなりません。実装では、実際のリンクを含むアクセシブルな同意コントロールを提供する必要があります。[B1 フォームの作成](../../b1-admin/forms/creating-forms) と [技術提案](./twilio-byok-proposal#consent-and-suppression-are-required-release-work) を参照してください。

Twilio は、自発的で検証可能なオプトインを求めています。SMS を、必須の会員規約、メール/電話の許可、寄付への同意、イベント登録と一緒にまとめないでください。訪問者カードに携帯電話番号を書いてあっても、それ自体は SMS への同意にはなりません。Twilio の [自発的な同意に関する要件](https://www.twilio.com/docs/api/errors/30923) と [キャンペーンの推奨事項](https://help.twilio.com/hc/en-us/articles/26149060902555-A2P-10DLC-Campaign-Registration-Recommendations) を参照してください。

### サインアップ文面の例

教会が実際の目的、送信者、頻度を決めてから、これを使用してください。チェックボックスは任意で、初期状態はオフです。以下のポリシー名は、レンダリングされたフォームでリンクになっている必要があります。

> はい、Grace Community Church から、礼拝の変更、教会のイベント、ボランティアのスケジュールについて、Grace Church Updates を通じて [登録済みの教会の番号] から SMS を受け取ることに同意します。毎月最大 4 件のメッセージが届く予定です。メッセージ料金とデータ通信料がかかる場合があります。配信を停止するには STOP、サポートが必要な場合は HELP と返信してください。SMS への登録は任意であり、出席、登録、献金の条件ではありません。[プライバシーポリシー] と [SMS 利用規約] をご覧ください。お問い合わせ: [教会のサポートメールまたは電話番号]

「最大 4 件」は例としての約束であり、Twilio が定める上限ではありません。教会が実際に守れる頻度に置き換えてください。頻度がばらつく場合は、そのことを正直に開示し、想定される頻度を説明してください。プロモーションの案内や、その他の伝道プログラムは、目的と同意が別途検討されるまで、このチェックボックスの対象外にしておいてください。

一般的な訪問者/イベントフォームでは、このチェックボックスをオフにしたままでも送信が成功する必要があります。SMS 専用フォームでは、チェックすると登録を希望することになると説明してもかまいませんが、無関係な教会の礼拝が登録に依存するようなことがあってはなりません。実際の動作は、スマートフォンとデスクトップの両方で確認してください。

### 準備するポリシーの内容

教会のプライバシーページには、テキストメッセージのために収集する情報、その利用方法と保護方法、保管期間と連絡方法を説明してください。携帯電話番号とメッセージへの同意が、第三者や関連会社に対して、そのマーケティングや販促目的で販売・共有されないことを明確に記載する必要があります。必要なサービス提供者による処理は正確に説明してください。B1 と Twilio を使っているのに、教会が処理業者を一切利用していないと主張してはいけません。この区別については、Twilio の [プライバシーポリシーの案内](https://www.twilio.com/docs/api/errors/30908) と [キャンペーンの推奨事項](https://help.twilio.com/hc/en-us/articles/26149060902555-A2P-10DLC-Campaign-Registration-Recommendations) を基準にしてください。

SMS 利用規約には、教会とプログラムの名称、目的、実際の頻度、通信料の可能性、STOP/HELP の案内、サポート窓口、プライバシーのリンクを明記してください。また、Twilio の現在の審査で求められる追加の開示事項があれば、それも含めてください。オプトインページのポリシーリンクは、キャンペーンに提出した URL と完全に一致させてください。2026 年 6 月 30 日以降、Twilio は新しい API キャンペーンの登録に、専用の公開プライバシーと利用規約の URL を求めています。Console の手続きでも同じ情報が収集されます。[Twilio の要件](https://www.twilio.com/en-us/changelog/a2p-10dlc-campaign-registration-will-require-privacy-policy-and-)

これらは、教会の実際のポリシーに適用すべき内容の要件であり、既存のプライバシー慣行の代わりになるものではありません。また、確認せずに貼り付けるための汎用的なポリシーでもありません。

## 2. Twilio で教会とそのメッセージングプログラムを登録する

1. **教会が所有する有料アカウント**を作成するか、既存のものを使用します。また、SMS 対応の米国の市内局番を用意します。教会の正式名称、EIN/事業登録情報、住所、ウェブサイト、正式な代表者を一貫して使用してください。ChurchApps の情報や他の教会の情報で代用しないでください。
2. 教会の実際の法人形態に合わせて、Twilio の直接顧客向けブランド登録手続きに従ってください。対象となる非営利団体の場合は、[非営利団体向けの登録ガイダンス](https://www.twilio.com/docs/messaging/compliance/a2p-10dlc/onboarding-for-government-and-non-profit-agencies) を使用してください。慈善団体や 501(c)(3) の用途は資格によって異なります。教会という名称だけでは、Twilio の承認や免除を受けられるわけではありません。
3. 専用の Messaging Service を作成し、該当する A2P 10DLC キャンペーンを提出します。実際のメッセージと、承認されたブランドで利用可能なオプションに正確に合う用途を選んでください。ここにある例は、すべての教会に共通する用途コードを指定するものではありません。
4. 公開サインアップの URL、ポリシーの URL、オプトインとメッセージフローの完全な説明、求められたサンプルメッセージを提出します。実際のサインアップ方法をすべて含め、埋め込みリンクや電話番号の申告が実際の内容と一致するようにしてください。キーワード登録やダブルオプトインは、そのフローが存在し、テスト済みの場合にのみ記載してください。
5. 送信用の番号を、サービスと承認済みキャンペーンに関連付けます。送信前に、キャンペーンの検証**と番号登録の完了**の両方を待ってください。

これらの手順は、教会自身の Twilio Console で行ってください。提案中の B1 連携が、教会に代わって登録を送信することはありません。登録項目とステータスについては、Twilio の [登録クイックスタート](https://www.twilio.com/docs/messaging/compliance/a2p-10dlc/quickstart) と [キャンペーンのリソース](https://www.twilio.com/docs/messaging/api/usapptoperson-resource) を参照してください。キャンペーンが承認された後も、番号が保留中のままだと送信がブロックされることがあります。[番号登録](https://www.twilio.com/docs/api/errors/30035)

### キャンペーンの説明例

> Grace Community Church は、Grace Church Updates を使って、教会のウェブサイトでこのプログラムを選んだ方々に、礼拝スケジュールの変更、教会イベントのリマインダー、ボランティアのスケジュール連絡を送信します。このプログラムでは、1 か月に最大 4 件までのメッセージを送信します。受信者はいつでもメッセージの受信を停止できます。このプログラムには、購入した連絡先、第三者のプロモーション、寄付の呼びかけは含まれません。

この例は、実際にその上限と除外事項を守っている教会にのみ当てはまります。ボランティアのリマインダーだけで約束した頻度を超えてしまう場合は、提出前にプログラムの設計と開示内容を変更してください。

### メッセージフローの説明例

> 訪問者は [実際の教会のサインアップ URL] を開き、携帯電話番号を入力し、任意の Grace Church Updates のチェックボックスを個別に選択します。このチェックボックスは、フォームを開いたときはオフになっています。開示事項には、Grace Community Church の名称、礼拝の変更、イベントのリマインダー、ボランティアのスケジュールの内容、月間の上限と通信料の可能性、STOP と HELP の説明が含まれます。表示されるプライバシーポリシーと SMS 利用規約は、[実際のプライバシー URL] と [実際の SMS 利用規約 URL] にリンクしています。SMS を拒否しても、出席、イベント登録、献金、一般的なつながりフォームの利用は妨げられません。B1 は、積極的な選択、電話番号、送信時刻、開示事項のバージョンを記録します。このプログラムは、文書化された登録者にのみ送信し、配信停止の申し出を受けたら、以降の送信を止めます。

この段落は、実際に実装されたフローに合わせて調整してください。電話による確認やスタッフの審査を使う場合は、保留中の状態と正確な有効化の手順を説明してください。その他の方法を使う場合は、それぞれの方法と証拠を含めてください。登録がログインの背後にある場合や、紙で行われる場合、Twilio は実際のオプトインの体験について、公開されている個人情報を伏せた証拠を求めます。記入済みのフォームや会員データは決して公開しないでください。[検証可能なオプトインのガイダンス](https://www.twilio.com/docs/api/errors/30923)

### 送信メッセージの例

以下は、調整して使う架空のサンプルです。提出前に、実際の教会の URL を使い、角括弧内の値を置き換えてください。Twilio のキャンペーン API は、2 件から 5 件のサンプルを受け付けます。サンプルには、教会を特定できること、申告した目的に沿っていること、配信停止の手順が含まれていることが必要です。[キャンペーンのサンプル項目](https://www.twilio.com/docs/messaging/api/usapptoperson-resource)

```text
Grace Community Church: Sunday's service will start at [time] due to [reason]. Details: [church website URL]. Reply STOP to end texts.
```

```text
Grace Community Church: A reminder that [church event] is on [date] at [time]. Information: [church event URL]. Reply STOP to end texts.
```

```text
Grace Community Church: You are scheduled to serve on [team] this [day]. Please review your plan: [B1 church portal URL]. Reply STOP to end texts.
```

角括弧内の URL はサンプルの変数を示しています。提出するサンプルには、実際の教会のドメインと実際のリンクの形式を示してください。予定表へのリンクにはログインが必要な場合がありますが、審査に使うサインアップページとポリシーは、公開して誰でも確認できるようにしておく必要があります。承認用のサンプルに、非公開のメモ、子どもの情報、個人を特定できる会員の詳細を含めないでください。サンプルの内容は、B1 のテンプレートが実際に送信する内容と一致させてください。利用できない返信用の受信箱や、特定のリマインダーの動作を約束しないでください。

### STOP、START、HELP への応答

これらの確認応答には、Twilio の Messaging Service Advanced Opt-Out を使用し、教会とプログラムの情報、サポートの詳細をカスタマイズしてください。応答の例は次のとおりです。

- **STOP:** Grace Church Updates の配信が停止されたことを確認し、再開するための正式な方法を説明します。
- **START:** 同じプログラムの再開を確認し、設定されたフローで必要とされる、プログラム名、頻度/料金、ヘルプと停止の案内を含めます。
- **HELP:** Grace Community Church であることを示し、実際のサポート窓口と配信停止の手順を案内します。

Twilio がすでに応答している場合は、B1 から二重に確認を送らないでください。HELP への返信は登録ではありません。START によって、その人が別の教会のプログラムに登録されたり、会員ディレクトリに表示されたりしてはいけません。[Twilio Advanced Opt-Out](https://www.twilio.com/docs/messaging/tutorials/advanced-opt-out)

## 3. 提出前に承認パケットを確認する

- [ ] 教会の実際の法的情報/ブランド情報、ウェブサイトの身元、キャンペーンの目的が一致している。
- [ ] サインアップページと有効なフォームが、プライベートブラウザーでログインなしで開く（モバイル端末を含む）。
- [ ] SMS のチェックボックスは初期状態がオフになっており、主要な訪問者/イベントの操作を完了する際に拒否できる。
- [ ] プログラムの目的、送信元、実際の頻度、通信料の可能性、STOP、HELP、サポート窓口、クリック可能なポリシーのリンクが、SMS の選択肢のそばに表示されている。
- [ ] Twilio に提出した正確なプライバシー/利用規約の URL が公開されており、認証情報なしで動作し、同じ教会/プログラムを特定している。ポリシーの内容が実際の処理と一致している。
- [ ] 各サンプルメッセージが、プログラム、実際の送信者の身元、想定されるリンクや電話番号の動作と一致している。キャンペーンには、実際のオプトイン方法がすべて記載されている。
- [ ] 審査者に見えるとおりの、空白のフォーム、チェックボックスと開示事項、ポリシーのリンクを示す、個人情報を伏せたスクリーンショットがある。証拠には会員の記録や鍵を含まない。
- [ ] 同意の証拠を保持し、送信前に配信停止を処理する運用手段が教会にある。電話やメールで受けた依頼も含む。

これらの確認は、避けられる不一致を減らすためのものです。承認の判断は、Twilio とその審査パートナーが行います。審査中だけでなく、承認後も実際のサインアップページとポリシーの URL を利用可能にしておいてください。

## 4. 将来の B1 連携を接続して検証する

連携がリリースされたら、提案中の Texting の設定で、教会の Account SID、専用の API Key SID/シークレット、Webhook 用の別個の Auth Token、Messaging Service SID、選択した送信者を入力できるようにする必要があります。キーは教会の Console でのみ作成し、シークレットは非公開の B1 設定にのみ入力してください。[Twilio API キーのガイダンス](https://www.twilio.com/docs/iam/api-keys)

B1 が提供する、教会固有の受信用および配信状況用の Webhook URL を、対応する Twilio のサービス設定にコピーしてください。Advanced Opt-Out を有効にし、受信メッセージが設定済みの Webhook に届くことを確認します。B1 は、認証情報、サービスと送信者の所有、承認済みキャンペーン、番号登録の完了、受信の検証、テスト配信の成功を、それぞれ別々に確認できるように表示する必要があります。認証情報を保存したことや API リクエストが受け付けられたことは、最終的な配信を意味しません。

B1 が登録の状態をプログラムで確認できない場合は、Console で直接確認してください。UI には、日付付きの結果が管理者によって確認されたものであると表示する必要があります。本番のテキスト送信を有効にする前に、保留中または失敗の状態を解消してください。テストは、実際に同意した成人のテスト受信者にのみ、明示的に依頼されたものを使用し、その後次の手順を行います。

1. 対応する文書化されたサインアップによって、正しい電話番号とプログラムの同意記録が作成されることを確認します。拒否したり電話番号を変更したりしても、受信者が黙って登録されてはいけません。
2. テストを 1 件送信し、受信を確認します。B1 の状態と Twilio の Message SID および配信結果を照合します。
3. STOP と返信し、手動のメッセージ、グループメッセージ、ワークフロー、リマインダーがその電話番号をスキップすることを確認します。ディレクトリの表示は変わらないはずです。
4. 文書化された同じプログラムへの再登録フローと HELP への応答を確認します。確認の重複がなく、無関係な設定変更が発生していないことを確かめてください。

## 5. プログラムを維持する

Twilio で、キャンペーンやアカウントの状態、残高と請求のアラート、メッセージの失敗、受信した返信を監視する教会の責任者を決めてください。提案している最初の B1 リリースには会話型 SMS の受信箱はありません。実際のヘルプ窓口を公開して監視し、スタッフが B1 でそれらを確認できると思い込まず、返信を実際にチェックしてください。

同意と配信停止の履歴、現在の開示事項/ポリシーのバージョン、キャンペーンの識別子、個人情報を伏せた承認の証拠は、教会が管理する記録に保存してください。鍵や受信者リストを、公開のサポートチケットに貼り付けないでください。番号、サービス、認証情報、サインアップの流れ、頻度、目的のいずれかが変更された場合は、連携を再確認し、再開する前に、必要に応じて登録と同意を更新してください。共有の家族用の番号や変更された番号は慎重に確認してください。対象となるかどうかは、同意した電話番号とプログラムによって決まり、家族全員の記録によって決まるわけではありません。

却下された場合は、実際の Twilio のエラーを読み、ウェブサイトと提出内容の両方で、特定の不一致を修正してから、教会の Console から再提出してください。未登録または保留中の送信者の場合は、番号を切り替えて回避するのではなく、登録が完了するまで待ってください。[Twilio の登録のトラブルシューティング](https://www.twilio.com/docs/messaging/compliance/a2p-10dlc/troubleshooting-a2p-brands) と、提供されているエラーコードの一覧を使用してください。処理にかかる期間を固定して約束しないでください。
