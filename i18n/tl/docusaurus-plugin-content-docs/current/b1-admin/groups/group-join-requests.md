# Mga Join Request ng Group

<div class="article-intro">

Kapag naka-configure ang isang group sa join policy na nangangailangan ng approval, maaaring magsumite ang mga tao ng request para sumali. Sinusuri at inaaprubahan o tinatanggihan ito ng mga group leader at administrator. Nagbibigay ito sa iyong simbahan ng kontrol sa membership ng group habang madali para sa mga tao na ipahayag ang kanilang interes na sumali.

</div>

<div class="prereqs">
<h4>Bago Ka Magsimula</h4>

- Kailangan mo ng permission na mamahala ng mga group, o dapat kang leader ng partikular na group. Tingnan ang [Roles & Permissions](../people/roles-permissions.md) para sa mga detalye.
- Dapat nakatakda sa **Request** (kailangan ng approval) ang join policy ng group. Tingnan ang [Creating Groups](./creating-groups.md) para sa kung paano i-configure ang mga join policy.

</div>

## Pag-unawa sa mga Join Policy

Maaaring may tatlong magkakaibang join policy ang mga group:

- **Open** -- Sinuman ay maaaring sumali kaagad nang walang approval
- **Request** -- Nagsusumite ang mga tao ng join request na nangangailangan ng approval
- **Closed** -- Walang sinuman ang makakahiling na sumali (dapat idagdag nang manu-mano ang mga miyembro)

Kapag gumagamit ang group ng **Request** policy, dumadaan lahat ng pagtatangkang sumali sa approval workflow na inilalarawan sa pahinang ito.

## Pagtingin sa mga Nakabinbing Request

### Para sa mga Group Leader

1. Sa B1 Admin, buksan ang [Jump menu](../introduction.md#getting-around-with-the-jump-menu) at piliin ang **People > Groups**
2. I-click ang pangalan ng group
3. Ipinapakita ng seksyong **Members** kung ilan ang nakabinbing request. I-click ang **All members** -- lalabas sa itaas ng listahan ng miyembro ang mga nakabinbing request para sa group na ito

### Para sa mga Administrator

Maaaring tingnan ng mga administrator na may permission sa pamamahala ng group ang mga nakabinbing request sa lahat ng group:

1. Sa Jump menu, piliin ang **People > Groups**
2. I-click ang **pending requests** button sa header ng pahina (halimbawa, "3 pending requests"). Lalabas lang ito kapag may naghihintay na request.
3. Suriin ang lahat ng nakabinbing request sa buong simbahan

## Pagsusuri ng Join Request

Ipinapakita ng bawat join request ang:

- **Pangalan at larawan ng tao** -- Ang taong humihiling na sumali
- **Opsyonal na mensahe** -- Isang personal na mensahe na nagpapaliwanag kung bakit gusto nilang sumali (kung may ibinigay)
- **Petsa ng request** -- Kung kailan isinumite ang request

Para suriin ang isang request:

1. Basahin ang mensahe ng tao kung nagbigay sila ng isa
2. I-click ang pangalan ng tao para tingnan ang profile niya kung kailangan
3. Magpasya kung aaprubahan o tatanggihan

## Pag-aapruba ng Request

1. I-click ang **Approve** sa join request
2. Agad na idinadagdag ang tao sa group bilang miyembro
3. Makakatanggap ang nag-request ng notification na naaprubahan ang kanyang request
4. Mamarkahan ang request bilang approved sa sistema

:::tip
Kapag inaprubahan mo ang isang request, nagiging regular na miyembro ng group ang tao. Maaari mo siyang i-promote bilang group leader sa ibang pagkakataon mula sa pahinang [Group Members](./group-members.md) kung kinakailangan.
:::

## Pagtanggi sa Request

1. I-click ang **Decline** sa join request
2. Opsyonal na magbigay ng dahilan ng pagtanggi (hanggang 500 character)
3. I-click ang **Confirm**
4. Makakatanggap ang nag-request ng notification kasama ang iyong dahilan ng pagtanggi (kung may ibinigay)
5. Mamarkahan ang request bilang declined

:::info
Ang pagbibigay ng dahilan ng pagtanggi ay nakakatulong sa tao na maintindihan kung bakit hindi naaprubahan ang request niya at maaaring mag-udyok sa kanya na subukan muli sa hinaharap o tuklasin ang ibang group.
:::

## Pag-aapruba mula sa Tasks Page {#approving-from-the-tasks-page}

Bawat join request ay lumilikha rin ng task sa ilalim ng **Serving &rarr; My Work**, na may titulong "*Person* requested to join *Group*." Itinatalaga ito sa mga leader ng group. Kung wala pang leader ang group, mapupunta ito sa sinumang staff na may permission na **Group Members &gt; Edit**, o sa mga domain admin ng simbahan kung walang may ganoong permission. Ang mga staff at admin na nakatanggap ng task sa ganitong paraan ay nakakatanggap din ng notification na direktang nagli-link dito.

Kapag binuksan ang task, makikita ang pangalan ng nag-request, ang group, at ang opsyonal na mensahe niya, kasama ang mga button na **Approve** at **Decline** mismo sa task card (ang Decline ay nagbubukas ng parehong opsyonal na reason field na inilarawan sa itaas). Ito ay nagbibigay sa mga leader ng ikalawang paraan, na udyok ng notification, para kumilos sa request nang hindi binubuksan ang listahan ng miyembro ng group.

Ang pagpapasya sa isang request mula sa alinman sa dalawang lugar -- ang listahan ng miyembro ng group o ang Tasks card nito -- ay magsasara nito sa lahat ng lugar, kaya hindi kailanman makikita ng mga leader ang lumang task para sa request na naasikaso na ng iba.

## Mga Notification

Awtomatikong nagpapadala ang join request system ng mga notification:

- **Kapag may isinumiteng request** -- Makakatanggap ng notification ang lahat ng group leader. Kung walang leader ang group, sa halip ay aabisuhan ang staff o admin na nakatalaga sa task (tingnan sa itaas).
- **Kapag naaprubahan ang request** -- Makakatanggap ang nag-request ng kumpirmasyon
- **Kapag tinanggihan ang request** -- Makakatanggap ang nag-request ng notification kasama ang anumang dahilan ng pagtanggi

Lumalabas ang mga notification sa notification center ng user sa B1.church at sa mobile app. Sa notification bell ng B1 Admin, ang pag-click sa join-request notification (o sa **View Details** nito) ay magbubukas ng group sa B1.church site ng iyong simbahan sa bagong tab.

## Pamamahala ng mga Request mula sa Panig ng Miyembro

Maaaring pamahalaan ng mga tao ang sarili nilang join request mula sa B1.church:

- Tingnan ang status ng kanilang mga nakabinbing request sa group detail page
- Kanselahin ang nakabinbing request kung magbago ang isip nila
- Tingnan kung naaprubahan o tinanggihan ang kanilang request

## Mga Pinakamahusay na Gawi

- **Tumugon agad** -- Subukang suriin ang mga request sa loob ng 24-48 oras para hindi naghihintay nang matagal ang mga tao
- **Maging malinaw sa mga dahilan ng pagtanggi** -- Tulungan ang mga tao na maintindihan ang mga susunod na hakbang o ang mga alternatibong opsyon
- **Suriin ang mga profile** -- Tingnan ang profile ng tao para malaman kung angkop siya sa group
- **Ipaalam ang inaasahan** -- Siguraduhing malinaw na sinasabi ng deskripsyon ng group kung para kanino ito
