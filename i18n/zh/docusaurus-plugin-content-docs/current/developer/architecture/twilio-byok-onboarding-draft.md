# 教会自有 Twilio 入驻草稿

:::caution 拟议集成的草稿
这是一个拟议中的工作流程。B1 现在在 **Settings > Texting** 下提供了基础的 **Twilio** 选项（Account SID、Auth Token、From Number 以及入站 STOP webhook）——参见[教会设置：短信](../../b1-admin/settings/church-settings.md#texting)。下文中额外的 B1 设置控件、同意映射和验证步骤，是未来版本的需求，并非指引你去查找现有设置。请阅读[技术提案](./twilio-byok-proposal)了解范围和依赖关系。Twilio 的资料于 2026 年 10 月 22 日核对；在提交营销活动之前，请核实当前要求。
:::

## 推荐的安排

你的教会拥有其付费的 Twilio 账户、电话号码、Messaging Service、账单以及营销活动注册。B1 将使用通过教会设置中私下输入的凭据，通过这些资源进行发送。请至少确保两位合适的教会管理员能够访问 Twilio 账户，启用账户安全功能，并指定一名负责同意记录、入站回复和拒绝通知的人员。

这里提议的首个版本涵盖一个美国本地号码和一个描述清晰的教会消息项目。下面的示例使用虚构的 **Grace Community Church** 及其项目 **Grace Church Updates**，用于服务变更、活动提醒和志愿者排班。请将所有名称、域名、发送频率、联系方式和用途替换为教会的真实情况。这些是 Twilio 规则的教会特定示例，而非预先批准的营销活动，也不保证获得批准。

## 1. 准备公开的 B1 注册体验

在教会的 B1 网站上发布一个页面，例如 `https://www.example.org/text-updates`，其中嵌入公开的 B1 表单，或提供指向独立公开表单的明显链接。同时还要发布 `https://www.example.org/privacy` 和 `https://www.example.org/sms-terms`。这些地址只是占位符；请提交实际可访问的 URL。

对于拟议的短信注册表单：

| 设置 | 推荐配置 |
|---|---|
| 访问权限 | 公开/不受限制；在审核期间和持续注册期间保持有效；无需登录即可访问 |
| 表单模式 | 初始使用标准模式；对话式模式需要技术提案中所述的明确同意支持 |
| 手机号 | 清楚标注国家代码；如果用于普通连接/活动表单，仅在选择短信注册时必填 |
| 短信选项 | 独立的可选复选框，默认未勾选，并映射到特定项目和手机号字段 |
| 披露信息 | 在短信选项旁边可见：教会/项目、消息用途和频率、可能的资费、STOP、HELP、支持联系方式，以及真实可点击的隐私政策/短信条款链接 |
| 其他操作 | 访客可以在不订阅短信的情况下提交连接卡、报名参加活动或请求信息 |
| 证据 | 保存项目、确切手机号、所选同意内容、来源提交记录、服务器时间以及披露/政策版本；目前仅仅是普通表单回答并不能完成注册 |
| 人员/小组自动化 | 除非经过针对教会现有匹配规则的审核，否则在初始注册试点中关闭自动创建人员/分配小组。小组分配绝不构成短信授权。 |
| 现有自动化 | 不要将每位表单提交者或小组成员都加入短信工作流。只有经过验证的拟议同意映射才能授权该项目。 |
| 感谢短信 | 确认表单已收到，但在复选框被拒绝或确认/审核仍待处理时，不要声称已完成短信注册。 |

现有的复选框问题可以用来说明表单，但 B1 仍需要同意记录和发送门控。当前的共享渲染器会将说明显示为纯文本；仅在其中输入 Markdown 或 URL，并不足以保证政策链接可以点击。实现时必须提供一个带有实际链接的无障碍同意控件。参见[创建 B1 表单](../../b1-admin/forms/creating-forms)和[技术提案](./twilio-byok-proposal#consent-and-suppression-are-required-release-work)。

Twilio 要求自愿且可验证的同意（opt-in）。不要将短信与必需的会员条款、电子邮件/电话许可、捐赠同意或活动报名捆绑在一起。访客卡上的手机号本身并不构成短信同意。请参阅 Twilio 的[自愿同意要求](https://www.twilio.com/docs/api/errors/30923)和[营销活动建议](https://help.twilio.com/hc/en-us/articles/26149060902555-A2P-10DLC-Campaign-Registration-Recommendations)。

### 注册文案示例

仅在教会确定了实际用途、发送方和频率之后使用。该复选框是可选的，默认未勾选；下列政策名称必须在渲染后的表单中是链接。

> 是的，我希望 Grace Community Church 通过 Grace Church Updates，从[已注册的教会号码]向我发送关于服务变更、教会活动和志愿者排班的短信。每月最多发送 4 条消息。可能产生消息和数据费用。回复 STOP 取消订阅，或回复 HELP 获取帮助。短信注册是可选的，不需要用于参加、报名或奉献。请参阅我们的隐私政策和短信条款。问题咨询：[教会支持邮箱或电话]。

“每月最多 4 条”是一个示例承诺，并非 Twilio 规定的限制。请将其替换为教会真正能够履行的频率；如果频率会有变化，请如实披露，并描述预期的发送节奏。除非其用途和同意已另行评估，否则请将促销内容或其他事工项目置于此复选框之外。

对于一般的访客/活动表单，在未勾选此复选框的情况下提交，必须仍然能够成功。专门的仅短信表单可以说明勾选即表示请求注册，但绝不能让无关的教会服务依赖于注册。请在手机和电脑上确认真实的行为。

### 需要准备的政策内容

教会的隐私页面应说明其为短信收集哪些信息、如何使用和保护这些信息，以及其保留和联系方式的做法。页面应明确说明，手机号和短信同意信息不会出售或分享给第三方或关联方用于其营销或推广用途。准确说明必要的服务提供商处理情况；不要在使用 B1 和 Twilio 的同时声称教会从不使用任何处理商。Twilio 的[隐私政策指引](https://www.twilio.com/docs/api/errors/30908)和[营销活动建议](https://help.twilio.com/hc/en-us/articles/26149060902555-A2P-10DLC-Campaign-Registration-Recommendations)是理解这一区别的参考依据。

短信条款应说明教会和项目、用途、实际发送频率、可能产生的消息费用、STOP/HELP 说明、支持联系方式和隐私链接；并包括 Twilio 当前审核要求的任何其他披露内容。注册页面上的政策链接必须与提交给营销活动的 URL 完全一致。自 2026 年 6 月 30 日起，Twilio 要求新的 API 营销活动注册必须提供专用的公开隐私政策和条款 URL；其控制台流程同样会收集这些 URL。[Twilio 要求](https://www.twilio.com/en-us/changelog/a2p-10dlc-campaign-registration-will-require-privacy-policy-and-)

以上这些是需要应用于教会真实政策的内容要求，而不能替代教会现有的隐私做法，也不是可以不加检查就直接粘贴的通用政策。

## 2. 在 Twilio 中注册教会及其消息项目

1. 创建或使用一个**由教会拥有的付费账户**，以及一个支持短信的美国本地号码。请始终如一地使用教会的法定名称、EIN/商业注册信息、地址、网站和授权代表。不要替换为 ChurchApps 的身份信息或其他教会的信息。
2. 根据教会实际的实体类型，遵循 Twilio 的直接客户品牌注册流程。对于符合条件的非营利组织，请使用[非营利组织注册指引](https://www.twilio.com/docs/messaging/compliance/a2p-10dlc/onboarding-for-government-and-non-profit-agencies)。慈善/501(c)(3) 的用途取决于资格；仅凭教会名称并不能确立 Twilio 的批准或豁免。
3. 创建一个专用的 Messaging Service，并提交相关的 A2P 10DLC 营销活动。选择真实地与实际消息以及该已批准品牌可用选项相符的用途类别；此处的示例并不规定统一的教会用途代码。
4. 提供公开的注册 URL、政策 URL、完整的同意/消息流程说明，以及所要求的示例消息。包括每一种真实的注册方式；将嵌入链接/电话号码的声明设置为与实际内容一致。除非该流程确实存在并经过测试，否则不要列出关键词注册或双重确认。
5. 将发送号码与该服务及已批准的营销活动关联。在发送之前，等待营销活动审核**和号码注册完成**。

请在教会自己的 Twilio 控制台中完成这些步骤。拟议的 B1 集成不会为教会提交注册。Twilio 的[注册快速入门](https://www.twilio.com/docs/messaging/compliance/a2p-10dlc/quickstart)和[营销活动资源](https://www.twilio.com/docs/messaging/api/usapptoperson-resource)解释了注册字段和状态。即使营销活动已获批准，待处理的号码仍可能阻止发送。[号码注册](https://www.twilio.com/docs/api/errors/30035)

### 营销活动描述示例

> Grace Community Church 使用 Grace Church Updates，向在我们的公开教会网站上选择该项目的人员发送服务时间变更、教会活动提醒和志愿者排班通知。根据此项目，我们每月发送的消息不超过四条。收件人可以随时停止接收这些消息。本项目不包括购买的联系人、第三方促销或募捐呼吁。

此示例仅适用于确实遵守这些限制和排除条款的教会。如果仅志愿者提醒就超过了承诺的频率，请在提交前更改项目设计和披露内容。

### 消息流程说明示例

> 访客打开 [实际的教会注册 URL]，输入手机号，并自行选择可选的 Grace Church Updates 复选框。该复选框在表单打开时是未勾选的。披露内容注明了 Grace Community Church，说明了服务变更、活动提醒和志愿者排班，给出了每月的发送上限和可能的资费，并解释了 STOP 和 HELP。展示的隐私政策和短信条款分别链接到 [实际的隐私 URL] 和 [实际的短信条款 URL]。拒绝短信不会妨碍参加礼拜、活动报名、奉献或使用一般的连接表单。B1 会记录肯定的选择、手机号、提交时间以及披露版本。我们只会向那些有记录的订阅者发送本项目的消息，并在进一步发送之前抑制已撤回的订阅。

请将该段落调整为实际实现的流程。如果使用了电话确认或员工审核，请描述待处理状态以及确切的激活步骤。如果使用了其他方式，请包括每种方式及其证据。如果注册位于登录之后或以纸质形式进行，Twilio 会要求提供公开的、已脱敏的实际同意体验证据；切勿公开已填写的表单或成员数据。[可验证的同意指引](https://www.twilio.com/docs/api/errors/30923)

### 外发消息示例

这些是需要改编的虚构示例；请在提交前使用真实的教会 URL，并替换方括号中的值。Twilio 的营销活动 API 接受两到五个示例。示例应标明教会身份、体现所声明的用途，并包含退订说明。[营销活动示例字段](https://www.twilio.com/docs/messaging/api/usapptoperson-resource)

```text
Grace Community Church: Sunday's service will start at [time] due to [reason]. Details: [church website URL]. Reply STOP to end texts.
```

```text
Grace Community Church: A reminder that [church event] is on [date] at [time]. Information: [church event URL]. Reply STOP to end texts.
```

```text
Grace Community Church: You are scheduled to serve on [team] this [day]. Please review your plan: [B1 church portal URL]. Reply STOP to end texts.
```

方括号中的 URL 表示示例变量；提交的示例应显示教会的真实域名和实际的链接样式。计划的链接可能需要登录，但用于审核的注册页面和政策应可以公开查看。请勿在批准示例中包含私人笔记、儿童信息或可识别的成员详情。请使示例内容与 B1 模板实际发送的内容保持一致；不要承诺提供 B1 中并不存在的回复收件箱或特定的提醒行为。

### STOP、START 和 HELP 回复

请使用 Twilio Messaging Service 的 Advanced Opt-Out 来发送这些确认信息，并自定义教会/项目的身份和支持详情。示例回复意图如下：

- **STOP：** 确认 Grace Church Updates 已停止发送，并说明受支持的恢复订阅方式。
- **START：** 确认该项目已恢复，包括按已配置流程要求的项目身份、频率/资费以及帮助/退订说明。
- **HELP：** 说明 Grace Community Church 的身份，并提供真实的支持联系方式和退订说明。

当 Twilio 已经回复时，不要再发送第二条 B1 确认信息。回复 HELP 并不等于注册。START 绝不能让某人报名其他教会项目，也不能将其显示在成员通讯录中。[Twilio Advanced Opt-Out](https://www.twilio.com/docs/messaging/tutorials/advanced-opt-out)

## 3. 提交前检查审批材料

- [ ] 教会真实的法定/品牌信息、网站身份和营销活动用途保持一致。
- [ ] 注册页面和有效的表单可以在私人浏览器中无需登录打开，包括在移动设备上。
- [ ] 短信复选框默认未勾选，并且在完成主要的访客/活动操作时可以拒绝。
- [ ] 项目用途、发送方、实际频率、可能的费用、STOP、HELP、支持联系方式以及可点击的政策链接，都显示在短信选项旁边。
- [ ] 提供给 Twilio 的确切隐私/条款 URL 是公开的，无需凭据即可访问，并标识相同的教会/项目。政策内容与实际的数据处理一致。
- [ ] 每个示例消息都与项目、实际的发送方身份以及预期的链接/电话行为相符。营销活动描述了每一种真实的同意方式。
- [ ] 已脱敏的截图显示了空白表单、复选框/披露内容以及审核人员将看到的政策链接。证据中不包含任何成员记录或密钥。
- [ ] 教会具备可操作的方式来保留同意证据，并在发送前尊重撤回请求，包括通过电话/电子邮件收到的请求。

这些检查有助于减少可以避免的不一致；最终的批准决定由 Twilio 及其审核合作伙伴做出。批准之后，请保持真实的注册页面和政策 URL 可访问，而不仅仅是在审核期间。

## 4. 连接并验证未来的 B1 集成

集成发布之后，其拟议的短信设置应收集教会的 Account SID、专用的 API Key SID/secret、独立的 webhook Auth Token、Messaging Service SID，以及所选的发送方。仅在教会的控制台中创建密钥，并且仅在私密的 B1 设置中输入密钥。[Twilio API 密钥指引](https://www.twilio.com/docs/iam/api-keys)

将 B1 提供的、针对教会的入站和投递状态 webhook URL，复制到 Twilio 服务中相应的配置中。启用 Advanced Opt-Out，并检查入站消息能否到达已配置的 webhook。B1 应分别显示以下项目的检查结果：凭据、服务/发送方归属、已验证的营销活动、已完成的号码注册、入站验证，以及已投递的测试消息。已保存的凭据或已被接受的 API 请求，并不等于最终送达。

如果 B1 无法以编程方式检查注册状态，请直接在控制台中确认；界面必须将带日期的结果标注为“管理员已确认”。在启用正式短信之前，请解决待处理或失败的状态。请使用单独的、明确要求的测试，向一位真实的、同意接收的成年人测试收件人发送，然后：

1. 确认与某条有文档记录的注册相匹配时，会创建正确的电话/项目同意记录；拒绝或更换电话号码，不能悄无声息地为收件人注册。
2. 发送一条测试消息，确认收到，并将 B1 的状态与 Twilio 的 Message SID 及投递结果进行比对。
3. 回复 STOP，并检查手动短信、群发短信、工作流和提醒是否都会跳过该手机号。通讯录的可见性不应改变。
4. 演练有文档记录的同一项目重新订阅流程和 HELP 回复；验证没有重复的确认信息，也没有无关的偏好设置变更。

## 5. 维护该项目

指定一名教会负责人，负责在 Twilio 中监控营销活动/账户状态、余额和账单提醒、消息失败情况以及入站回复。拟议的 B1 首个版本没有对话式短信收件箱，因此请发布并监控一个真实的帮助联系方式，并检查回复，而不要假设员工能在 B1 中看到这些回复。

请将同意和撤回记录、当前的披露/政策版本、营销活动标识符以及已脱敏的审批证据，保存在教会可控的记录中。切勿将密钥或收件人名单粘贴到公开的支持工单中。当号码、服务、凭据、注册流程、频率或用途发生变化时，请在恢复发送之前重新检查集成，并在需要时更新注册和同意信息。仔细检查共用的家庭号码以及已更换的号码；资格取决于同意接收的电话和项目，而不是家庭中每位成员的记录。

对于被拒绝的情况，请阅读 Twilio 返回的实际错误，在网站和提交材料中修正具体的不一致之处，然后通过教会的控制台重新提交。对于未注册或待处理的发送方，请等待注册完成，而不要为了绕过而更换号码。请使用 [Twilio 注册故障排除指南](https://www.twilio.com/docs/messaging/compliance/a2p-10dlc/troubleshooting-a2p-brands)以及所提供的错误代码参考。不要承诺固定的处理时限。
