# 服务器管理

<div class="article-intro">

ChurchApps 中的服务器管理功能仅适用于具有 **Server.Admin** 权限的用户。这些工具用于跨系统中所有教会的平台操作、支持和故障排除。

</div>

:::warning 访问受限
本页面描述的功能需要 **Server.Admin** 权限，普通教会管理员无法使用。这些功能仅适用于平台运营商和支持人员。
:::

## 访问服务器管理

具有 Server.Admin 权限的用户可以从 B1 Admin 访问服务器管理面板：

1. 登录到 [admin.b1.church](https://admin.b1.church)
2. 打开**设置**，然后在设置菜单中点击**服务器管理**。（您也可以直接转到 `admin.b1.church/admin`。）
3. 服务器管理面板有教会、用户、模拟用户、后台作业、Commons、使用趋势、翻译查找、服务器健康和数据库迁移的部分

## 用户模拟

模拟功能允许服务器管理员以另一个用户身份登录，用于支持和故障排除。这在调查用户报告的问题或帮助教会配置其系统时很有用。

### 如何模拟用户

1. 打开服务器管理面板的**模拟用户**部分
2. 在搜索字段中输入用户的名称或电子邮件地址
3. 点击**搜索**或按 Enter
4. 从搜索结果中，点击您想要模拟的用户
5. 在出现的对话框中确认模拟
6. 您将以该用户身份登录并被重定向到其账户

### 重要提示

- 模拟创建一个具有目标用户权限和教会访问权限的新会话
- 模拟另一个用户时，您的原始管理员会话将结束
- 模拟时采取的所有操作都记录在审计跟踪中
- 要返回您的管理员账户，请注销然后使用您的凭据重新登录
- 仅在支持必要时使用模拟，并在访问其账户进行支持时始终告知用户

### API 端点

模拟功能由会员模块 API 中的 `/users/:userId/impersonate` 端点支持。有关技术细节，请参阅[会员端点](/docs/developer/api/endpoints/membership#users)。

### 安全考虑

- 模拟需要 Server.Admin 权限——应该谨慎地且仅向受信任的平台运营商授予此权限
- 所有模拟事件都使用管理员用户 ID 和目标用户 ID 记录
- 模拟发生时不会通知教会，因此应为何时以及如何使用此功能建立明确的策略
- 考虑在您的支持票证系统中记录模拟事件以实现问责制

## Commons 审核

Commons 是跨产品用户提交内容的共享审核队列——WorshipCommons 歌曲、Lessons.church 课程、FreeShow 模板和 B1 网站构建器模板都通过同一个队列而不是单独的按产品审查工具。

### 访问 Commons

1. 导航到服务器管理面板中的 **Commons** 选项卡。
2. 您将看到三个子选项卡：**队列**、**报告**和**资产**。

有限的**音乐编辑**角色也可以看到队列选项卡，但被阻止批准改变歌曲权利或许可的提交。

### 队列

队列列出跨所有产品的每个待处理提交，可按产品和资产类型过滤。每一行显示提交是新资产、原始作者的编辑还是第三方的编辑，以及提交者的批准记录和提交已等待多长时间（一旦超过 72 小时就标记）。

点击**审查**打开一个抽屉，其中包含字段级差异、文件预览和项的嵌入式只读预览。使用**a**/**r** 键盘快捷方式批准或拒绝，使用**j**/**k** 移动到下一个或上一个提交而不离开抽屉。拒绝需要选择原因（例如质量、重复、许可、ccli、ai 或离题）和说明。

### 报告

"报告"选项卡处理针对已发布资产提交的版权和政策/质量报告，分为单独的版权和政策及其他队列加上已解决的历史。申领报告以开始处理，然后使用解决方案（支持、驳回或重复）和操作（无、取消发布或删除）解决。

### 资产

资产选项卡是已发布内容的可搜索浏览器，提供的操作可以**突出显示**资产（在产品的主页上突出显示它）、**取消发布**/**重新发布**它或**删除**它（带有版权或政策原因）。

对于歌曲，这也是歌曲变成**周日就绪**和有资格出现在教会 B1 Admin 歌曲搜索中的地方：评论者打开资产并在听过一遍并确认乐谱、和弦和幻灯片都存在后标记每个已发布的键为**已听**。只有每个键都被勾选后，歌曲才变成周日就绪。

:::info
Commons 审核仅限员工——个别教会永远看不到这个队列。个别教会 B1 Admin 接触 Commons 数据的唯一地方是[歌曲搜索](/docs/b1-admin/serving/songs#free-songs-from-worshipcommons)的"WorshipCommons — 免费"部分，它只展示已经通过此审查过程的歌曲。
:::

有关基础数据模型和提交生命周期，请参阅[内容 Commons 架构](/docs/developer/architecture/commons)页面。

## 组电子邮件批准

教会在服务器管理员批准前无法发送教会编写的电子邮件（组电子邮件、表单跟进、工作流电子邮件和账户邀请）。这可以防止机器人注册的教会使用共享的 ChurchApps 发送地址进行垃圾邮件。

1. 打开服务器管理面板中的**教会**选项卡。
2. 每个教会显示一个**组电子邮件**芯片：**已批准**（绿色）或**未批准**（轮廓）。
3. 点击芯片并确认以批准教会，或撤销批准。

教会员工在 B1 Admin 的发送电子邮件对话框中使用**请求审查**按钮请求批准。该请求被电子邮件至支持地址，并列出教会的名称、ID、注册日期、位置和谁请求的。一个教会每周可以发送一个请求。有关每日配额和对退件和投诉的自动暂停，请参阅[教会编写的电子邮件限制](/docs/developer/architecture/notifications#church-authored-email-limits)。

## 数据库迁移

部署不改变数据库。托管的数据库仅接受来自 Api 网络内部的连接，因此在添加迁移的发布之后，服务器管理员从**数据库迁移**选项卡应用它。（自托管 Docker 安装在 Api 容器启动时仍然自动运行迁移。）

选项卡显示当前环境和每个模块（会员、出席、捐款等）的一行，其状态、应用和待处理迁移的数量以及最后应用的。

- **运行待处理迁移**应用每个待处理迁移，一次一个模块，按顺序。它在第一个失败时停止并显示为每个模块应用的内容。
- 标记为**无历史**的模块有一个早于迁移跟踪的数据库。它永远不会自动运行，因为那会在实时表上重播旧数据迁移。点击该模块上的**检查架构**。Api 将每个迁移创建的表、列和索引与实时数据库进行比较，并标记每个迁移为**已应用**、**缺失**、**部分应用**或**仅数据**。检查不改变任何内容。
- 在检查结果中，**记录为已应用**将检测到的迁移写入迁移历史而不运行它们。缺失的仍然待处理，可以正常运行。
- **部分应用**的迁移阻止记录。如果迁移可以安全运行（先阅读它），勾选**重新运行**使其保持待处理并从头开始运行。

服务器管理面板和 CLI（`yarn migrate:up`）使用相同的 Kysely 迁移器和 `kysely_migration` 表，所以他们总是同意已应用的内容。支持端点是 `GET /membership/serverHealth/migrations`、`POST /membership/serverHealth/migrations/:module/run`、`GET .../:module/detect` 和 `POST .../:module/baseline`，全部仅限 Server.Admin。
