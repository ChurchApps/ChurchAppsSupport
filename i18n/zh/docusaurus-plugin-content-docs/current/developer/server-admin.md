# 服务器管理

<div class="article-intro">

ChurchApps 中的服务器管理功能仅对具有**服务器.管理**权限的用户可用。这些工具用于跨系统中所有教会的平台操作、支持和故障排除。

</div>

:::warning 访问受限
本页面上描述的功能需要**服务器.管理**权限，对常规教会管理员不可用。它们仅用于平台操作员和支持人员。
:::

## 访问服务器管理

具有服务器.管理权限的用户可以从 B1 Admin 访问服务器管理面板：

1. 登录到 [admin.b1.church](https://admin.b1.church)
2. 打开 [Jump 菜单](../b1-admin/introduction.md#getting-around-with-the-jump-menu)，展开**设置**，然后单击**服务器管理**。（您也可以直接转到 `admin.b1.church/admin`。）
3. 服务器管理面板有教会、用户、模拟用户、背景作业、公共、使用趋势、翻译查询、服务器健康和数据库迁移的部分

## 用户模拟

模拟功能允许服务器管理员以另一个用户的身份登录以进行支持和故障排除。这在调查用户报告的问题或帮助教会配置其系统时很有用。

### 如何模拟用户

1. 打开服务器管理面板的**模拟用户**部分
2. 在搜索字段中输入用户的名称或电子邮件地址
3. 单击**搜索**或按 Enter
4. 从搜索结果中，单击您要模拟的用户
5. 在出现的对话框中确认模拟
6. 您将以该用户的身份登录并重定向到他们的帐户

### 重要注意事项

- 模拟创建一个具有目标用户权限和教会访问的新会话
- 当您模拟另一个用户时，您的原始管理员会话结束
- 所有在模拟时采取的操作都在审计跟踪中记录
- 要返回您的管理员帐户，请登出并使用您的凭证重新登入
- 仅在必要时将模拟用于支持目的，并在访问其帐户以获得支持时始终通知用户

### API 端点

模拟功能由成员 API 中的 `/users/:userId/impersonate` 端点支持。有关技术详情，请参阅[成员端点](/docs/developer/api/endpoints/membership#users)。

### 安全考虑

- 模拟需要服务器.管理权限 - 此权限应仅授予受信任的平台操作员
- 所有模拟事件都与管理员用户 ID 和目标用户 ID 一起记录
- 当发生模拟时不会通知教会，因此请为此功能的使用时机和方式建立明确的政策
- 考虑在您的支持票系统中记录模拟事件以获得问责

## 公共版本管理

Commons 是用户提交的内容的共享审核队列，跨产品 — WorshipCommons 歌曲、Lessons.church 课程、FreeShow 模板和 B1 网站建设者模板都通过相同的队列而不是单独的每产品审查工具流动。

### 访问公共

1. 在服务器管理面板中导航到**公共**选项卡。
2. 您将看到三个子选项卡：**队列**、**报告**和**资产**。

有限的**音乐编辑器**角色也可以看到队列选项卡，但被阻止批准改变歌曲权利或许可的提交。

### 队列

队列列出跨所有产品的每个待处理提交，可按产品和资产类型过滤。每行显示提交是新资产、其原始作者的编辑还是第三方的编辑，以及提交者的批准记录以及提交等待了多长时间（一旦超过 72 小时就标记）。

单击**审查**打开一个抽屉，其中包含字段级差异、文件预览和嵌入式项目的只读预览。使用**a**/**r**键盘快捷键批准或拒绝，使用**j**/**k**移动到下一个或上一个提交而不离开抽屉。拒绝需要选择原因（例如质量、重复、许可、ccli、ai 或离题）和注释。

### 报告

报告选项卡处理针对已发布资产提交的版权和政策/质量报告，分为单独的版权和政策和其他队列加上已解决的历史。声称报告以开始处理它，然后用分辨率（维持、驳回或重复）和操作（无、取消发布或删除）解决它。

### 资产

资产选项卡是已发布内容的可搜索浏览器，其中包括操作以**特性**资产（在产品主页上突出显示）、**取消发布**/**重新发布**它或**删除**它（带有版权或政策原因）。

对于歌曲特别是，这也是歌曲变为**周日准备**并有资格出现在教会的 B1 Admin 歌曲搜索中的地方：审查者打开资产并标记每个已发布密钥为**已听**一旦他们通过它并确认分数、和弦和幻灯片都存在。歌曲仅在每个密钥都被检查时变为周日准备。

:::info
Commons 版本管理仅是员工 — 个别教会从不看到这个队列。个别教会的 B1 Admin 触及 Commons 数据的一个地方是[歌曲搜索](/docs/b1-admin/serving/songs#free-songs-from-worshipcommons)的"WorshipCommons — 免费"部分，仅显示已通过此审查过程的歌曲。
:::

请参阅[内容 Commons 架构](/docs/developer/architecture/commons)页面的底层数据模型和提交生命周期。

## 组电子邮件批准

教会不能发送教会编写的电子邮件（组电子邮件、表单后续、工作流电子邮件和账户邀请），直到服务器管理员批准他们。这防止了机器人注册的教会使用共享的 ChurchApps 发送地址进行垃圾邮件。

1. 在服务器管理面板中打开**教会**选项卡。
2. 每个教会显示一个**组电子邮件**筹码：**已批准**（绿色）或**未批准**（概述）。
3. 单击筹码并确认批准教会，或撤销批准。

教会员工通过 B1 Admin 的发送电子邮件对话框中的**请求审查**按钮请求批准。请求通过电子邮件发送到支持地址，并列出教会的名称、ID、注册日期、位置以及谁要求。教会可以每周发送一个请求。请参阅[教会编写的电子邮件限制](/docs/developer/architecture/notifications#church-authored-email-limits)以了解每日津贴和反弹和投诉的自动暂停。

## 数据库迁移

部署不更改数据库。托管数据库仅接受来自 Api 网络内部的连接，所以在添加迁移的发布后，服务器管理员从**数据库迁移**选项卡应用它。（自我托管的 Docker 安装仍然在 Api 容器启动时自动运行迁移。）

选项卡显示当前环境和每个模块（成员、出席、给予等等）一行及其状态、应用和待处理迁移的数量以及最后应用的一行。

- **运行待处理迁移**应用每个待处理迁移，一次一个模块，按顺序。它在第一个失败处停止并显示应用的内容针对每个模块。
- 一个标记为**没有历史**的模块有一个数据库，预约迁移跟踪。它从不自动运行，因为这会在实时表上重播旧数据迁移。相反，单击该模块上的**检查模式**。Api 比较表、列和索引每个迁移创建的实时数据库并标记每个迁移**已应用**、**缺失**、**部分应用**或**仅数据**。检查没有改变任何东西。
- 在检查结果中，**记录为已应用**将检测到的迁移写入迁移历史，而不运行它们（在确认后）。一切直到最后**已应用**迁移被记录，包括该范围内的**仅数据**迁移；**缺失**迁移保持待处理并可以通过**运行待处理迁移**正常运行。
- 一个**部分应用**迁移阻止记录。如果迁移安全地再次运行（首先读取它），勾选**重新运行**所以它保持待处理并从顶部再次运行。

服务器管理面板和 CLI（`yarn migrate:up`）使用相同的 Kysely migrator 和 `kysely_migration` 表，所以他们始终同意应用的内容。支持端点是 `GET /membership/serverHealth/migrations`、`POST /membership/serverHealth/migrations/:module/run`、`GET .../:module/detect` 和 `POST .../:module/baseline`，所有服务器.管理仅。
