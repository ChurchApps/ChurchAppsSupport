# 服务器管理

<div class="article-intro">

ChurchApps 的服务器管理功能仅对拥有 **Server.Admin** 权限的用户开放。这些工具用于平台运营、支持和故障排查，适用于系统中的所有教会。

</div>

:::warning 访问受限
本页所述功能需要 **Server.Admin** 权限，普通教会管理员无法使用。这些功能仅供平台运营人员和支持人员使用。
:::

## 访问服务器管理

拥有 Server.Admin 权限的用户可以从 B1 Admin 访问服务器管理面板：

1. 登录 [admin.b1.church](https://admin.b1.church)
2. 打开[跳转菜单](../b1-admin/introduction.md#getting-around-with-the-jump-menu)，展开**设置**，然后点击**服务器管理**。（您也可以直接访问 `admin.b1.church/admin`。）
3. 服务器管理面板会在左侧按三组列出各个部分：**目录**（教会、用户、模拟用户）、**运维**（后台任务、公共组件、使用趋势）和**系统**（翻译查询、服务器健康状况、数据库迁移）

## 用户模拟

模拟功能允许服务器管理员以其他用户的身份登录，用于支持和故障排查。这在调查用户报告的问题，或协助教会配置其系统时非常有用。

### 如何模拟用户

1. 打开服务器管理面板中的**模拟用户**部分
2. 在搜索框中输入用户的姓名或电子邮件地址
3. 点击**搜索**或按 Enter 键
4. 从搜索结果中点击您要模拟的用户
5. 在弹出的对话框中确认模拟操作
6. 您将以该用户的身份登录，并被重定向到其账户

### 重要说明

- 模拟会创建一个新会话，其权限和教会访问范围与目标用户相同
- 您模拟其他用户时，原有的管理员会话将结束
- 模拟期间执行的所有操作都会记录在审计日志中
- 如需返回您的管理员账户，请退出登录，然后使用您的凭据重新登录
- 仅在支持需要时使用模拟功能，并且在为支持而访问用户账户时，务必告知用户

### API 端点

模拟功能由会员模块中的 `/users/:userId/impersonate` 端点提供支持。技术细节请参阅[会员端点](/docs/developer/api/endpoints/membership#users)。

### 安全注意事项

- 模拟需要 Server.Admin 权限 -- 该权限应谨慎授予，且仅授予值得信赖的平台运营人员
- 所有模拟事件都会记录管理员用户 ID 和目标用户 ID
- 模拟发生时不会通知教会，因此应事先制定明确的使用时机和方式规范
- 建议将模拟事件记录在您的支持工单系统中，以便问责

## Commons 审核

Commons 是各产品用户提交内容的共享审核队列。WorshipCommons 歌曲、Lessons.church 课程、FreeShow 模板以及 B1 网站构建器模板，都通过同一个队列处理，而不是使用各自独立的审核工具。

### 访问 Commons

1. 导航至服务器管理面板中的 **Commons** 标签页。
2. 您将看到三个子标签页：**队列**、**举报**和**资源**。

受限的**音乐编辑**角色也可以看到队列标签页，但无法批准会更改歌曲版权或授权的提交内容。

### 队列

队列列出所有产品中待处理的提交内容，可按产品和资源类型进行筛选。每一行会显示该提交是新资源、原作者的编辑，还是第三方的编辑，同时显示提交者的审批记录，以及该提交已等待的时长（超过 72 小时后会被标记）。

点击**审核**即可打开抽屉面板，其中包含字段级别的差异对比、文件预览以及该项目的只读嵌入预览。使用 **a** / **r** 快捷键可批准或拒绝，使用 **j** / **k** 可在抽屉中切换到下一个或上一个提交。拒绝时需要选择原因（例如质量、重复、授权、CCLI、AI 或离题）并填写备注。

### 举报

举报标签页处理针对已发布资源提交的版权和政策/质量举报，分为独立的**版权**和**政策及其他**队列，另有**已处理**历史记录。认领举报即可开始处理，处理时需选择结果（维持、驳回或重复）和操作（无、取消发布或删除）。

### 资源

资源标签页是一个可搜索的已发布内容浏览器，提供以下操作：**推荐**某资源（在产品首页上突出显示）、**取消发布**/**重新发布**，或**删除**（需注明版权或政策原因）。

对于歌曲而言，此处也是歌曲变为**主日就绪**并可出现在教会 B1 Admin 歌曲搜索中的地方：审核人员打开该资源后，在确认乐谱、和弦和幻灯片均已齐全并完整听过之后，将每个已发布调性标记为**已听过**。只有所有调性都被勾选后，歌曲才会成为主日就绪。

:::info
Commons 审核仅限工作人员使用，各个教会永远看不到此队列。各教会的 B1 Admin 唯一接触 Commons 数据的地方，是[歌曲搜索](/docs/b1-admin/serving/songs#free-songs-from-worshipcommons)中的"WorshipCommons -- 免费"部分，该部分仅显示已经通过此审核流程的歌曲。
:::

底层数据模型和提交生命周期，请参阅 [Content Commons 架构](/docs/developer/architecture/commons)页面。

## 群组电子邮件审批

在服务器管理员批准之前，教会无法发送由教会撰写的电子邮件（群组电子邮件、表单后续邮件、工作流邮件和账户邀请）。这样可以防止通过机器人注册的教会使用 ChurchApps 共享发信地址发送垃圾邮件。

1. 打开服务器管理面板中的**教会**标签页。
2. 每个教会都会显示一个**群组电子邮件**标签：**已批准**（绿色）或**未批准**（轮廓样式）。
3. 点击该标签并确认，即可批准该教会，或撤销其批准。

教会工作人员可在 B1 Admin 的"发送电子邮件"对话框中点击**申请审核**来申请批准。该申请会通过电子邮件发送至支持地址，内容包括教会名称、ID、注册日期、所在地以及申请人。每个教会每周只能提交一次申请。每日发送额度以及退信和投诉时的自动暂停机制，请参阅[教会撰写的电子邮件限制](/docs/developer/architecture/notifications#church-authored-email-limits)。

## 数据库迁移 {#database-migrations}

**Deploy Prod** 工作流会自行应用待处理的迁移。托管的数据库只接受来自 API 网络内部的连接，因此 GitHub 运行器无法访问它们。相反，在 `serverless deploy` 之后，该工作流会立即调用 API 的 `migrate` Lambda 函数（`api-Prod-migrate`），该函数使用与本标签页相同的运行器执行每个模块的待处理迁移；如果任何模块出错或被拒绝，部署将失败。**Rollback Prod** 仅会回滚 Lambda 代码，已应用的迁移仍保持已应用状态。**数据库迁移**标签页用于检查状态、运行部署未执行的迁移（例如在演示环境中，其部署不会执行迁移），以及为没有历史记录的模块建立基线。（自托管的 Docker 安装会在 Api 容器启动时自动运行迁移。）

该标签页会显示当前环境，并为每个模块（会员、考勤、奉献等）显示一行，包括其状态、已应用和待处理迁移的数量，以及最近一次应用的迁移。

- **运行待处理迁移**会按顺序逐个模块应用所有待处理迁移。遇到第一个失败时即停止，并显示每个模块已应用的内容。
- 标记为**无历史记录**的模块，其数据库早于迁移追踪功能。此类模块永远不会自动运行，因为这样会在实时表上重放旧的数据迁移。请对该模块改为点击**检查架构**。Api 会将每个迁移所创建的表、列和索引与实时数据库进行比较，并将每个迁移标记为**已应用**、**缺失**、**部分应用**或**仅数据**。检查不会更改任何内容。
- 在检查结果中，**记录为已应用**会将检测到的迁移写入迁移历史，而不运行这些迁移（需确认）。直到最后一个**已应用**迁移为止的所有迁移都会被记录，包括该范围内的**仅数据**迁移；**缺失**的迁移仍保持待处理状态，之后可通过**运行待处理迁移**正常运行。
- **部分应用**的迁移会阻止记录。如果该迁移可以安全地重新运行（请先阅读其内容），请勾选**重新运行**，使其保持待处理状态，并从头开始再次运行。

服务器管理面板和 CLI（`yarn migrate:up`）使用相同的 Kysely 迁移器和 `kysely_migration` 表，因此两者对已应用的迁移始终保持一致。对应的端点包括 `GET /membership/serverHealth/migrations`、`POST /membership/serverHealth/migrations/:module/run`、`GET .../:module/detect` 和 `POST .../:module/baseline`，均仅限 Server.Admin 使用。
