# 数据安全

<div class="article-intro">

虽然没有绝对安全的系统，但 ChurchApps 高度重视数据安全。本页说明为保护录入 B1.church Admin 及其他 ChurchApps 产品的所有数据而采取的措施。

</div>

<div class="prereqs">
<h4>开始之前</h4>

- 阅读本页，了解你教会的数据是如何受到保护的
- 设置[角色与权限](./roles-permissions.md)，以控制谁可以访问敏感信息
- 熟悉[隐私政策](https://churchapps.org/privacy)

</div>

## 尽量减少敏感数据的存储 {#limiting-sensitive-data-stored}

我们的首要做法是不存储超出必要范围的敏感数据。这意味着我们从不存储用于奉献的信用卡或银行账户信息。当用户通过 B1.church Admin 或 B1 进行奉献时，信用卡数据从不会传输到我们的任何服务器，只会传输到你的支付网关（Stripe）。因此，即使发生数据泄露，也不会泄露任何信用卡或银行信息。

我们的系统也从不存储密码。所有密码都经过单向哈希算法处理，该算法会丢弃部分数据，使任何人（包括我们自己）都无法从数据库中还原密码。验证密码时，输入的值必须经过相同的单向哈希运算，并产生相同的结果。

去除上述两类数据后，剩下的敏感数据只有姓名和联系方式。

:::tip
由于 ChurchApps 从不存储信用卡或银行信息，即使发生最坏情况的数据泄露，也不会暴露金融账户详情。仅有姓名和联系方式会面临风险。
:::

## 采用标准最佳实践 {#using-standard-best-practices}

我们采用行业标准的安全最佳实践，包括使用 HTTPS 对往返于我们服务器的所有数据进行加密传输。所有服务器都托管在亚马逊网络服务（AWS）的安全物理数据中心内。所有数据库服务器都位于防火墙之后，无法从互联网访问。

## 数据隔离 {#data-segregation}

数据会根据范围分隔到不同的数据库中。我们的每个模块（会员、奉献、出勤、消息、事工和内容）都是拥有各自数据库的独立数据孤岛。如果其中一个模块遭到入侵，在其他模块也被入侵之前，数据的可利用价值是有限的。例如，如果奉献 API/数据库遭到入侵，攻击者可能获取捐款清单和日期（但绝不会包含卡号或银行数据）。然而，他们无法得知是哪些用户进行了奉献，或奉献给了哪些教会，因为这些数据存储在独立的会员数据库中。

:::info
数据隔离意味着入侵一个系统并不能访问教会的全部数据。每个 API 都独立运行，并拥有自己的数据库，从而限制了任何潜在入侵的影响范围。
:::

## 有限的访问权限 {#limited-access}

对生产服务器的访问严格限制在确有需要的服务器管理员范围内。目前有两人拥有访问权限，他们同时也是董事会成员。开发人员、志愿者和其他董事会成员均不允许访问生产服务器。

## 隐私政策 {#privacy-policy}

你的数据归你所有，绝不会出售给第三方。你可以[在此处](https://churchapps.org/privacy)阅读我们的完整隐私政策。

## GDPR 合规 {#gdpr-compliance}

ChurchApps 支持为在英国或欧盟拥有会员的教会提供 GDPR 合规支持。以下是我们对关键要求的处理方式：

### 数据主体权利 {#data-subject-rights}

ChurchApps 提供工具，帮助教会响应数据主体请求：

- **访问权（第 15 条）** -- 会员可以联系其教会，请求获取一份其个人数据的副本。管理员可以在 B1.church Admin 中，通过人员记录上的 **Export Data**（导出数据）功能，或在该人员编辑表单的 **Data Management**（数据管理）部分，导出任何人员的数据。
- **删除权（第 17 条）** -- 会员可以在其个人资料页面中自行请求删除账户（参见[审核账户删除请求](../profile/account-deletion.md)），也可以直接联系其教会。管理员还可以在人员详情页面的 **Data Management**（数据管理）部分，对所有模块中该人员的数据进行匿名化处理。匿名化会以通用值替换个人信息，同时保留教会财务报告所需的汇总记录（奉献总额、出勤人数）。
- **限制处理权（第 18 条）** -- 会员可以联系其教会，请求限制对其数据的处理，包括选择退出通讯。
- **数据可携权（第 20 条）** -- 管理员可以代表提出请求的会员，以结构化、机器可读的 JSON 格式导出其个人数据。

### 使用数据管理工具 {#using-the-data-management-tools}

要为个人访问 GDPR 数据工具：

1. 在 B1 Admin 中进入 **People**（人员），并打开该人员的记录。
2. 点击 **Edit**（编辑）进入编辑模式。
3. 向下滚动到 **Data Management**（数据管理）部分（默认折叠），点击展开。
4. 使用 **Export Data**（导出数据）下载一个 JSON 文件，其中包含该人员的所有已存储数据。（同样的 **Export Data** 链接也位于人员姓名下方的操作选项中，无需打开编辑表单即可使用。）
5. 使用 **Anonymize**（匿名化）以通用值替换个人信息。系统会要求你输入 `ANONYMIZE` 以确认 -- 此操作无法撤销。

:::warning
匿名化是永久性的。出于财务报告目的，奉献总额和出勤人数会被保留，但所有个人标识信息（姓名、电子邮件、地址等）都会被删除，且无法恢复。
:::

### 数据处理 {#data-processing}

ChurchApps 作为**数据处理者**代表你的教会（即**数据控制者**）行事。我们的[数据处理协议](https://churchapps.org/terms)概述了各方的责任，包括分包处理方的使用、数据泄露通知程序以及终止服务时的数据处理方式。

### 国际数据传输 {#international-data-transfers}

ChurchApps 的数据托管在美国的亚马逊网络服务（AWS）上。从英国/欧盟进行的国际数据传输，受 AWS 的标准合同条款（SCC）保障，该条款依据 [AWS 数据处理附录](https://aws.amazon.com/compliance/data-processing-addendum/)执行。AWS 数据处理附录会自动纳入所有客户的 AWS 服务条款。在采用 SCC 等适当的传输机制时，无需在欧盟境内托管数据。

有关传输风险的评估方式，请参阅[传输风险评估](./transfer-risk-assessment.md)。

### 分包处理方 {#sub-processors}

- **亚马逊网络服务（AWS）** -- 基础设施托管、数据存储和内容分发
- **Stripe** -- 奉献的支付处理（ChurchApps 不存储任何卡片数据）

:::info
有关我们如何处理个人数据的完整详情，请参阅我们的[隐私政策](https://churchapps.org/privacy)和[服务条款](https://churchapps.org/terms)。如果你对 GDPR 合规有疑问，请通过 support@churchapps.org 与我们联系。
:::
