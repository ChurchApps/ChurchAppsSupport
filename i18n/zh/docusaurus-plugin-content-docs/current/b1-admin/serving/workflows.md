# 工作流

<div class="article-intro">

工作流通过可视化看板，引导人们逐步完成一系列步骤。每个人都会成为一张卡片，在各个步骤之间移动——从首次来访者的跟进，到会员入会流程，再到首次奉献者的感谢，以及任何需要让大量人员经历相同阶段并进行跟踪的场景。某个步骤既可以要求志愿者去做某件事（打电话、进行一次交谈），**也可以**自动执行操作——发送电子邮件或短信、等待几天、将人员添加到小组——因此工作流既能处理人工跟进，也能处理其周边的琐碎事务。工作流将[任务](./tasks.md)扩展为可拖放的看板，让任何事情和任何人都不会被遗漏。

</div>

<div class="prereqs">
<h4>开始之前</h4>

- 确保您想要跟踪的人员已存在于 B1 Admin 中
- 熟悉[任务](./tasks.md)的工作方式，因为看板上的每张卡片都是一个任务
- 要使用 **发送电子邮件** 操作，请先创建您想要发送的电子邮件模板（在 **设置 → 电子邮件模板** 下管理）
- 要使用 **发送短信** 操作，请先连接[短信服务提供方](../settings/church-settings.md#texting)
- 您需要相应的任务权限。查看、编辑卡片和管理工作流是各自独立的权限级别（参见[角色与权限](../settings/roles-permissions.md)）

</div>

## 查看工作流

打开[跳转菜单](../introduction.md#getting-around-with-the-jump-menu)（B1 Admin 左上角的搜索栏），展开 **服侍**，然后点击 **工作流**。您的工作流会以表格形式列出，显示每个工作流的 **类别** 和 **状态**（**启用** 或 **停用**）。如果您使用了类别，列表上方的标签页可让您按类别筛选。点击任意工作流即可打开其看板。

## 创建工作流

1. 在工作流页面，点击 **添加工作流**。
2. 选择开始方式：
   - **空白工作流** -- 从零开始，自行构建步骤。
   - **从模板创建** -- 以一组现成的步骤开始，您可以进行编辑。内置模板包括：
     - **新访客跟进** -- 发送欢迎邮件 → 个人电话 → 邀请参加下一步 → 已连接
     - **会员课程** -- 表达兴趣 → 报名参加课程 → 参加课程 → 完成入会
     - **首次奉献者感谢** -- 发送感谢信 → 分享奉献影响 → 已奉献管理
     - **服侍分配确认** -- 发出请求并等待回复 → 致电未回复请求的志愿者（参见[服侍分配确认](#serving-assignment-confirmations)）

   创建模板的步骤可能需要一点时间。在此期间，**添加工作流** 按钮会显示为 **正在创建...**，且无法再次点击，因此您不会得到重复的工作流。如果出现问题，页面会显示 *"无法创建工作流，请重试。"*
3. 为工作流填写**名称**。
4. 可选择指定**类别**，将相关工作流归为一组。您可以直接在下拉菜单中创建新类别。
   对于空白工作流，您还需选择其**工作流用途**：**人员跟进**（常规类型）或**服侍分配确认**。工作流创建后，用途无法更改。
5. 保持工作流为**启用**状态，以便将人员添加到其中；或将其设为**停用**，以将其从"添加到工作流"列表中隐藏。
6. 点击 **保存**。

:::tip
在工作流列表中使用 **复制** 按钮，可以复制现有工作流 -- 包括其步骤、自动操作和路由 -- 作为新工作流的起点。
:::

## 使用步骤构建看板

每个工作流看板由**步骤**组成，步骤以从左到右的列显示。打开一个工作流，使用 **添加步骤** 为流程的每个阶段创建步骤。

添加或编辑步骤时，您可以配置：

- **步骤名称** -- 列标题（例如"欢迎电话"或"等待报名"）。
- **到期天数** -- 当卡片进入此步骤时自动设置到期日期。超过到期日期的卡片会被标记为 **逾期**。
- **默认负责人** -- 新卡片进入此步骤时自动分配的个人或小组。当默认负责人是个人时，他们会收到一条通知，告知有卡片已分配给他们。
- **自动操作** -- 卡片到达时系统自行执行的操作（见下文）。
- **路由** -- 卡片离开此步骤后前往的位置（参见[路由](#routing-cards-with-outcomes-and-conditions)）。

将步骤列拖动到与您的流程相匹配的顺序。该顺序也决定了在没有其他路由适用时，卡片默认的前进路径。

:::info
请先保存新步骤。自动操作和路由都附加在步骤上，因此编辑器会在步骤存在后解锁这些部分。
:::

## 自动操作

每个步骤都可以包含一组**自动操作**，当卡片**进入**该步骤的那一刻，这些操作会自动运行 -- 在任何人接触它之前。这是步骤既能提示志愿者，又能处理后续例行工作的方式。

在步骤编辑器中，打开 **自动操作**，点击 **添加操作**，选择一种类型并填写其设置。您可以添加任意数量的操作；它们会**从上到下依次运行**。点击步骤上的 **保存**，即可同时保存该步骤及其所有操作。使用垃圾桶图标删除操作会立即生效。

| 操作 | 作用 |
|---|---|
| **发送电子邮件** | 向此人发送您选择的电子邮件模板。您可以覆盖主题行。 |
| **发送短信** | 通过您教会的[短信服务提供方](../settings/church-settings.md#texting)向此人发送您撰写的消息。 |
| **等待** | 将卡片暂停指定天数后再继续（见下文）。 |
| **添加到小组** | 将此人添加到您选择的[小组](../groups/index.md)中。 |
| **从小组移除** | 将此人从您选择的小组中移除。 |
| **记录出席** | 在进行中的小组礼拜时间内，将此人标记为出席（见下文）。 |
| **添加到工作流** | 将此人启动到另一个工作流中 -- 适用于在不同流程之间交接。 |
| **添加备注** | 在卡片的历史记录中记录一条备注。 |
| **设置字段** | 更新此人记录中的字段：会员状态、婚姻状况、性别、城市、州/省或邮编。 |
| **Webhook** | 将卡片的详细信息发送到您提供的外部网址（URL），用于与其他系统连接。 |
| **创建任务** | 使用您输入的标题和描述创建一个[任务](./tasks.md)，并分配给您选择的人。 |
| **通知人员** | 向您选择的工作人员或志愿者发送一封关于该卡片的电子邮件和 B1 通知（见下文）。 |

在一个步骤的所有操作完成后，卡片会**停留在该步骤**，以便有人处理它 -- 除非该步骤设有自动路由，将其推进到下一步（参见[完全自动化的步骤](#fully-automated-steps)）。

:::info
只有当卡片通过正常流程到达时，自动操作才会运行 -- 即首次添加时、结果或自动路由将其带入时，或等待结束后。当工作人员手动将卡片拖到该步骤或将其退回时，这些操作**不会**重新运行，因此人员不会收到同一封邮件两次。
:::

### 发送电子邮件

选择 **发送电子邮件**，挑选您的一个电子邮件模板，并可选择输入自定义主题。当卡片进入该步骤时，此人会自动收到该邮件。（如果此人没有登记电子邮件地址，该步骤会直接跳过此操作。）模板中的[合并字段](../settings/email-templates.md#merge-fields)，例如 `{{firstName}}`，会填入此人的个人信息。

邮件发出后，卡片的历史记录会记录 **已发送电子邮件**。如果无法发送 -- 例如您教会的电子邮件尚未获批，或已达到每日上限 -- 则不会添加"已发送电子邮件"的记录。

:::info
工作流电子邮件只有在您的教会获准发送小组电子邮件后才会发出，并且会计入教会的每日电子邮件上限。参见[为您的教会开启小组电子邮件](../groups/group-members.md#turning-on-group-email-for-your-church)。**发送电子邮件** 操作会在步骤编辑器中警告您这些邮件何时无法发送：如果批准仍在等待中，会显示 *"您的教会的电子邮件尚未获得批准..."*；如果近期邮件被退回或被举报为垃圾邮件，则会显示 *"您的教会的电子邮件已暂停..."*。
:::

### 记录出席

选择 **记录出席**，然后点击 **选择小组**，挑选需要记录出席的小组。操作运行时，此人会在该小组进行中的礼拜时间内被标记为出席 -- 与其签到的效果相同。这在与一个触发器配合使用时很有用，该触发器会在人员到达时将其添加到工作流中，从而无需单独签到即可统计出席。

- 出席是以卡片**创建**的那一刻计算的，因此工作流中较早的**等待**不会使其超过礼拜时间。
- 只有设置了星期和开始时间的礼拜时间才会计入。如果在那一刻，该小组的任何礼拜时间都不在进行中，则不会记录任何内容，并且卡片的历史记录会注明 **没有进行中的排定礼拜 —— 未记录出席**。
- 记录出席后，卡片的历史记录会显示 **已记录出席**，后跟该小组的名称。对同一场礼拜再次运行该操作，不会重复计算此人。

### 通知人员

选择 **通知人员**，点击 **选择人员**，并可选择输入一条**消息**。当卡片进入该步骤时，该人员会收到一封电子邮件和一条 B1 通知，内容包括卡片上人员的姓名、工作流和步骤名称、您的消息，以及一个用于打开卡片的链接。这可用于提前告知工作人员或事工负责人 -- 例如，*"当有人到达会员面谈步骤时，通知牧师。"* 卡片的历史记录会记录 **已通知**，后跟该人员的姓名。

### 发送短信

选择 **发送短信**，并输入**短信内容**（最多 1,600 个字符）。当卡片进入该步骤时，此人会在其手机上收到该短信。您可以使用 `{{firstName}}`、`{{lastName}}`、`{{displayName}}` 或 `{{churchName}}` 个性化消息，发送短信时它们会被替换为此人的相应信息。

- 如果此人没有登记手机号码，则不会发送短信，卡片的历史记录会记录 **已跳过短信：没有手机号码**。
- 如果此人已退订，则不会发送短信，卡片的历史记录会记录 **已跳过短信：已退订**。
- 短信发出后，卡片的历史记录会记录 **已发送短信**。如果发送失败 -- 例如未连接短信服务提供方，或教会的短信额度已用完 -- 失败情况会记录在卡片的历史记录中，且该步骤中其余的操作仍会继续运行。

:::warning
短信通过您教会自己的[短信服务提供方](../settings/church-settings.md#texting)发送。如果未连接任何提供方，操作编辑器会提示 *"尚未设置短信服务提供方"*，此时短信将不会发送。
:::

### 等待若干天（培育序列）

**等待** 操作会将卡片保留您设定的天数。等待期间，卡片会显示为 **已暂停**。B1 每 30 分钟检查一次已结束的等待，因此卡片会在等待结束后约半小时内恢复。等待结束后：

1. 该**同一步骤中剩余的所有操作**会运行 -- 因此您可以构建一个培育序列，例如 **发送电子邮件 → 等待 3 天 → 发送提醒电子邮件**。
2. 然后，如果该步骤设有自动路由，卡片会前进；否则，它会停留在该步骤上，等待有人接手处理。

:::tip
在步骤的最开始设置一个**等待**，是在将卡片交给志愿者之前"暂存"它的简单方法 -- 例如，*等待 7 天，然后由一位教练主动联系*。
:::

## 将人员添加为卡片

将人员放到看板上有以下几种方式：

- **从看板添加** -- 点击步骤列底部的 **添加卡片**，然后选择一个人员。您也可以选择一个小组，该小组的每位成员都会被添加为一张卡片。
- **从个人记录添加** -- 在某人的页面上使用 **添加到工作流**，将其放入工作流。
- **从人员搜索添加** -- 选择多人，然后使用批量 **添加到工作流** 操作，一次性全部添加。
- **通过触发器自动添加** -- 在某些事件发生时添加人员，例如表单提交或首次奉献（见下方[触发器](#triggers)）。

## 处理看板

打开工作流即可查看其看板。每张卡片会显示人员姓名、分配给谁，以及到期日期或状态标签（**逾期** 或 **已暂停**）。步骤列还会显示其运行的自动操作的小徽章，以及其路由的注释，让您一目了然地看到卡片的流转方式。

- **移动卡片** -- 随着人员的进展，将卡片从一列拖到下一列。
- **打开卡片** -- 双击卡片（或点击它）以打开其详情抽屉，您可以在其中更改步骤、重新分配、添加备注并查看已发生的事件。

在卡片抽屉中，您可以：

- **分配** 卡片给其他人或小组。
- **暂停** 卡片 1 天、3 天或 1 周，以暂时隐藏其到期日期。
- **退回** 到上一步，或 **跳过** 到下一步。
- **固定负责人** -- 即使卡片在步骤之间移动，仍保持同一负责人。默认情况下，将卡片移动到新步骤会将其重新分配给该步骤的默认负责人；固定负责人则会让当前负责人始终承担责任。
- **完成** 卡片，或者如果该步骤已配置**结果**，则选择一个**结果**按钮（参见[路由](#routing-cards-with-outcomes-and-conditions)）。
- **添加备注**并查看卡片的**活动** -- 这是已运行的自动操作（已发送的电子邮件、等待等）的日志，每项都附有发生的日期和时间。

对于与某人相关的卡片，抽屉还会将该人员的手机号码和电子邮件显示为链接，您可以点击以拨打电话或发送邮件；如果您有查看人员的权限，还会显示 **查看个人资料** 链接。即使没有人员模块的访问权限，卡片的被分配人也能看到该电话和电子邮件。

备注会随卡片一起保存。任何能打开该卡片的人 -- 包括被分配的人员或小组 -- 都可以阅读备注并添加自己的备注。无法打开卡片的人看不到其备注。

### 批量操作

勾选多张卡片的复选框，即可对它们一起进行操作。若要一次选中某个步骤中的所有卡片，请勾选该步骤列标题中的 **全选** 框；再次勾选即可取消选择。随后会出现一个工具栏，允许您为所有选中的卡片一次性执行 **完成**、**暂停**、**分配**（重新分配）或 **移动到…** 另一个步骤。

## 使用结果和条件进行路由

路由控制卡片离开某个步骤后前往的位置。打开步骤的编辑器，即可配置两种路由。

### 结果按钮

结果是在完成该步骤上的卡片时，显示在卡片抽屉中的按钮。您可以提供"已加入小组"或"不感兴趣"等选项，而不再只有一个 **完成** 按钮。每个结果可以：

- 将卡片发送到此工作流中的**另一个步骤**，
- 将卡片**交接**给完全不同的工作流，或
- **关闭**卡片。

这样，一个决定就可以将人员引导到不同的路径上。

### 自动路由（条件性）

自动路由会在卡片**进入某个步骤的那一刻**（并在其自动操作完成后），如果人员符合一组条件，就将卡片推进到下一步，无需任何人点击。添加一条路由，选择目标步骤，并定义一个或多个**条件**（例如人员的校区、年龄或会员状态）。文本字段可以进行完全匹配，或使用**包含**、**开头为**或**结尾为**进行匹配。没有任何条件的路由会匹配所有人。

日期条件（今天的日期、出生日期或周年纪念日）可以比较完整日期，也可以只比较其一部分 -- 星期几、**月中的日**、**月份**，或已经过的年数。对于人员的出生日期或周年纪念日，**月中的日**提供相对的**今天**选项，因此诸如 *出生日期 · 月中的日 = 今天* 的条件会匹配生日在当月当天的人员。**月份**提供 **上个月**、**本月** 和 **下个月**。这些相对值会根据教会的时区计算，因此会与教会的日历日期对齐，而不是与服务器的时间对齐。

如果路由的条件由于某种原因无法检查，则该路由会被视为不匹配。卡片会留在该步骤上（或沿着另一条匹配的路由前进），而不会卡住。

:::info
在看板上，每个步骤列都会显示关于其路由的小注释 -- 例如结果标签，或"如果匹配"后面跟着一个指向目标步骤或工作流的箭头。
:::

## 完全自动化的步骤

您可以让某个步骤完全自行运行，无需任何人处理。为该步骤设置其**自动操作**，并添加一条指向下一步的**自动路由**（不设条件）。卡片进入时，操作会运行，随后路由会立即将其推进 -- 卡片会直接穿过该步骤。

:::tip
将此与**等待**结合使用：*发送欢迎邮件 → 等待 3 天 → 自动推进到"个人电话"步骤。* 邮件和时间都会自动处理，志愿者只有在需要进行人工接触时才会看到这张卡片。
:::

## 触发器

触发器会在某些事件发生时自动将人员添加到工作流中，因此您无需手动添加卡片。在工作流看板上，点击 **触发器** 标签页，然后点击 **添加触发器**。触发器有两种类型：

### 事件触发器

在 B1 中某条记录发生变化时立即触发。选择事件，然后可选择添加**条件**，使只有符合条件的人员才会被添加：

- **人员 · 已创建 / 已更新** -- 例如，将状态变为*访客*或*来宾*（分配给自行登记的人员的状态）的任何人添加进来。
- **奉献 · 已创建** -- 例如，将首次或大额奉献添加到感谢工作流中（可按金额、基金或方式匹配）。
- **小组 · 成员已加入** / **小组 · 已创建**。
- **表单 · 已提交** -- 添加提交所选表单的任何人（非常适合"我是新人"或"联系我们"卡片）。

### 定时触发器

按日、周、月或年的周期性运行，并基于一组条件进行匹配。可用于基于时间的外联，例如*今天过生日的每个人*（出生日期 · 月中的日 = **今天**，并将月份匹配为**本月**），或*每月*一次的关怀回访。即使未开启**每人仅一次**，定时触发器也不会在同一个重复周期内（一天、一周、一个月或一年，取决于其运行频率）再次添加同一个人。

对于任何触发器，您还可以设置：

- **起始步骤** -- 新卡片所在的位置（默认为第一个步骤）。
- **每人仅一次** -- 确保同一个人不会被触发器重复添加到工作流中。开启后，已在该工作流中拥有卡片的人会被跳过。
  - **在其卡片关闭后再次添加** -- 在开启**每人仅一次**时出现。勾选后，触发器可以在某人在该工作流中的先前卡片关闭后，再次将其添加进来。一个人在工作流中仍然永远不会同时拥有两张未关闭的卡片。适用于可能发生多次的事情，例如回访的来宾或年度流程。
- **启用** -- 开启或关闭触发器，而无需将其删除。

:::tip
将**表单 · 已提交**触发器与**新访客跟进**模板搭配使用，即可将您的"联系卡"或"我是新人"表单变成自动跟进流程。
:::

## 服侍分配确认

一类特殊的工作流可以跟进[服侍请求](./plans.md#assigning-team-members)，直到每位志愿者接受或拒绝为止。此看板上的每张卡片跟踪的不是人员，而是**一项分配** -- 即某个计划中某个职位上的某个人。同一人的两个职位或两次服侍会获得各自独立的卡片。这是选择加入的功能：在您于某个计划的设置中选择确认工作流之前，该计划不会有任何变化。

### 设置确认工作流

1. 在工作流页面，点击 **添加工作流**，然后选择 **服侍分配确认** 模板。（或者开始一个 **空白工作流**，并将其**工作流用途**设为**服侍分配确认**。）从模板创建需要具备发送短信的权限，因为该模板包含一个短信步骤。
2. 检查步骤。该模板最初包含：
   - **发出请求并等待回复** -- 通过电子邮件和短信发送服侍请求，等待 2 天，发送一封提醒电子邮件，再等待 1 天，然后自动将卡片推进。
   - **致电未回复请求的志愿者** -- 由一个人打电话给志愿者的步骤，到期时间为 1 天。请在此步骤上设置**默认负责人**。如果未设置，卡片会交给事工负责人，如果没有负责人，则交给事工团队。
3. 编辑等待时间、消息和步骤，使其符合您的教会情况。
4. 打开[计划的设置](./plans.md#plan-settings)，在 **确认工作流** 下选择此工作流。

这些工作流使用**发送服侍请求**操作，而不是**发送电子邮件**和**发送短信**。选择**电子邮件**或**短信**，并可选择撰写**请求消息**。请求始终包含职位、计划、服侍日期以及回复链接；您可以在消息中使用 `{{planName}}`、`{{positionName}}` 和 `{{serviceDate}}`。将消息留空则使用默认请求。志愿者的通知偏好、短信订阅、您的短信服务提供方以及教会的电子邮件批准都会生效，任何被跳过或被阻止的尝试都会记录在卡片上。**发送电子邮件**、**发送短信**和**添加到工作流**在这些看板上不可用。

确认工作流的 **触发器** 标签页会说明卡片是如何启动的，而不是提供触发器，并且这些工作流不会出现在人员的**添加到工作流**列表中。

### 卡片如何启动和关闭

- 在已发布的计划上**通知**志愿者时，卡片就会开始创建（参见[通知志愿者](./plan-validation.md#notifying-volunteers)）。每个新的、尚未回复的分配会获得一张卡片。保存、发布、复制或自动填充计划本身不会联系任何人，而暂存的计划则不会发送任何内容。
- 志愿者仍会收到常规的应用内提醒。电子邮件和短信跟进则由工作流发出。
- 当志愿者**接受或拒绝**时，其卡片会自动关闭，同时关闭与之关联的任何后续任务。
- 卡片抽屉会显示职位、服侍日期以及指向计划的链接。按钮不再是 **完成**，而是 **记录已跟进**。点击它会记录有人已跟进，但卡片会保持打开并分配给某人（显示为 **等待回复**），直到志愿者回复或回复截止日期已过。
- 回复截止日期是该职位所在团队服侍的最后一个礼拜时间的结束时刻。如果计划没有匹配的时间，则为服侍当天的结束时刻。如果到那时仍无人回复，卡片会以 **已超过回复截止日期** 关闭，并且会向卡片的当前负责人或事工负责人分配一个 **审核未回复的服侍请求** 任务，以便有人决定如何填补该空缺。该分配仍为 **未确认** 状态。
- 删除该分配、更改其人员、职位或计划日期、将计划恢复为暂存，或将计划切换到其他确认工作流，都会关闭该卡片。已关闭的卡片永远不会被另一次**通知**重新打开；如需发送新请求，请添加一项新的分配。

:::info
对于通过确认工作流发出的请求，[志愿者提醒](./plans.md#volunteer-reminders)只会发送给已**接受**的志愿者，因此等待回复的人不会在工作流的跟进之外再收到提醒。
:::

## 我的卡片

志愿者和工作人员无需翻查每个看板即可找到自己的工作。**我的工作** 页面上的 **我的卡片** 列表会显示当前用户在所有工作流中被分配的每一张卡片。若要前往该页面，请点击工作流页面顶部的 **我的卡片**，或在跳转菜单中打开 **服侍 > 我的工作**。点击某张卡片即可打开其所属的看板。

## 报告

打开工作流并点击 **报告**，即可查看该工作流的分析数据：

- **逾期** -- 超过到期日期的卡片数量。
- **每步骤卡片数** -- 每个步骤目前有多少张卡片，以柱状图显示。
- **已完成（30 天）** -- 过去 30 天的处理量，以折线图显示。

利用这些数据发现瓶颈 -- 例如，某个步骤的卡片不断堆积，从未前进。
