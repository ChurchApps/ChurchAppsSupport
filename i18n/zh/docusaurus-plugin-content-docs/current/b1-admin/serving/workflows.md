# 工作流

<div class="article-intro">

工作流可以让人们在可视化看板上逐步推进。每个人都是一张卡片，从一个步骤移动到下一个步骤——从新访客的跟进，到入会流程，再到首次奉献的感谢，以及其他需要让大量人员经历同一组阶段的情况。某个步骤可以请志愿者去做一件事（打电话、进行交流），同时也可以自动执行操作——发送邮件或短信、等待几天、将人员加入小组——因此工作流既能处理人工跟进，也能处理其周边的繁琐事务。工作流将[任务](./tasks.md)扩展为可拖放的看板，确保没有任何事情或任何人被遗漏。

</div>

<div class="prereqs">
<h4>开始之前</h4>

- 确保您要跟踪的人员已存在于 B1 Admin 中
- 熟悉[任务](./tasks.md)的工作方式，因为看板上的每张卡片都是一个任务
- 要使用 **Send email**（发送邮件）操作，请先创建好要发送的邮件模板（在 **Settings → Email Templates**（设置 → 邮件模板）下管理）
- 要使用 **Send text**（发送短信）操作，请先连接[短信服务提供商](../settings/church-settings.md#texting)
- 您需要具备相应的任务权限。查看、编辑卡片和管理工作流是分开的权限级别（参见[角色与权限](../settings/roles-permissions.md)）

</div>

## 查看工作流

打开[快速跳转菜单](../introduction.md#getting-around-with-the-jump-menu)（B1 Admin 左上角的搜索栏），展开 **Serving**，然后点击 **Workflows**。您的工作流会以表格形式列出，显示每个工作流的 **Category**（类别）和 **Status**（状态）（**Active**（启用）或 **Inactive**（停用））。如果您使用了类别，列表上方的标签页可以让您按类别筛选。点击任意工作流即可打开其看板。

## 创建工作流

1. 在 Workflows 页面，点击 **Add Workflow**（添加工作流）。
2. 选择开始方式：
   - **Blank workflow**（空白工作流）——从零开始，自行构建步骤。
   - **From a template**（从模板创建）——从一组现成的步骤开始，并可进行编辑。内置模板包括：
     - **New Visitor Follow-up**（新访客跟进）——发送欢迎邮件 → 个人电话 → 邀请参加下一步 → 已建立联系
     - **Membership Class**（入会班）——表达兴趣 → 报名参加课程 → 参加课程 → 完成入会
     - **First-time Giver Thank-you**（首次奉献感谢）——发送感谢便条 → 分享奉献的影响 → 成为尽责的奉献者
     - **Serving Assignment Confirmation**（服事安排确认）——请求并等待回复 → 致电尚未回复请求的志愿者（参见[服事安排确认](#serving-assignment-confirmations)）

   从模板创建步骤可能需要一点时间。在此过程中，**Add Workflow** 按钮会显示 **Creating...**（创建中）且无法再次点击，因此不会产生重复的工作流。如果出现问题，页面会显示 *"The workflow could not be created. Please try again."*（无法创建工作流，请重试。）
3. 为工作流输入**名称**。
4. 可选地为工作流分配一个**类别**，将相关的工作流归为一组。您可以直接从下拉菜单中新建类别。
   对于空白工作流，您还需要选择其**工作流用途**：**People follow-up**（人员跟进，通常的类型）或 **Serving assignment confirmation**（服事安排确认）。工作流创建后，用途无法更改。
5. 保持工作流为 **Active**（启用），以便向其中添加人员；或将其设为 **Inactive**（停用），使其不出现在“添加到工作流”的列表中。
6. 点击 **Save**。

:::tip
在工作流列表中使用 **Duplicate**（复制）按钮，可以复制现有工作流——包括其步骤、自动化操作和流转规则——作为新工作流的起点。
:::

## 用步骤构建看板

每个工作流看板都由**步骤**组成，步骤以从左到右的列显示。打开工作流，然后使用 **Add Step**（添加步骤）为流程的每个阶段创建一个步骤。

添加或编辑步骤时，您可以配置：

- **Step Name**（步骤名称）——列标题（例如“欢迎电话”或“等待报名”）。
- **Due in (days)**（截止天数）——在卡片进入此步骤时自动设置截止日期。超过截止日期的卡片会被标记为 **Overdue**（已逾期）。
- **Default assignee**（默认负责人）——新卡片进入此步骤时自动分配的人员或小组。如果默认负责人是某个人，该人会收到一条通知，告知有一张卡片已分配给他。
- **Automated actions**（自动化操作）——卡片到达时系统自行执行的操作（见下文）。
- **Routing**（流转）——卡片离开此步骤后前往的位置（参见[流转](#routing-cards-with-outcomes-and-conditions)）。

将步骤列拖动到符合您流程的顺序。该顺序同时也决定了在没有其他流转规则适用时，卡片默认经过的路径。

:::info
先保存新步骤。自动化操作和流转规则都附属于步骤，因此只有步骤存在后，编辑器才会解锁这些部分。
:::

## 自动化操作

每个步骤都可以附带一组**自动化操作**，卡片一旦**进入**该步骤，这些操作就会自动运行——在任何人处理之前。这就是步骤既能提醒志愿者，又能处理其周边日常工作的方式。

在步骤编辑器中，打开 **Automated actions**，点击 **Add Action**（添加操作），选择一种类型并填写其设置。您可以添加任意数量的操作，它们会**按从上到下的顺序依次运行**。点击步骤上的 **Save**，即可一并保存该步骤及其所有操作。使用垃圾桶图标删除操作会立即生效。

| 操作 | 作用 |
|---|---|
| **Send email**（发送邮件） | 向该人员发送您选择的邮件模板。您可以覆盖邮件主题。 |
| **Send text**（发送短信） | 通过您教会的[短信服务提供商](../settings/church-settings.md#texting)，向该人员发送您撰写的消息。 |
| **Wait**（等待） | 在继续之前将卡片暂停若干天（见下文）。 |
| **Add to group**（加入小组） | 将该人员加入您选择的[小组](../groups/index.md)。 |
| **Remove from group**（移出小组） | 将该人员从您选择的小组中移除。 |
| **Record Attendance**（记录出勤） | 在小组进行中的礼拜时间内，将该人员标记为出席（见下文）。 |
| **Add to workflow**（添加到工作流） | 将该人员加入另一个工作流——适用于在不同流程之间交接。 |
| **Add note**（添加备注） | 在卡片的历史记录中添加备注。 |
| **Set field**（设置字段） | 更新该人员记录中的字段：会籍状态、婚姻状况、性别、城市、州或邮编。 |
| **Webhook** | 将卡片的详细信息发送到您提供的外部网址（URL），用于与其他系统连接。 |
| **Create task**（创建任务） | 创建一个[任务](./tasks.md)，使用您输入的标题和描述，并分配给您选择的人。 |
| **Notify Person**（通知某人） | 向您选择的工作人员或志愿者发送一封关于该卡片的电子邮件和一条 B1 通知（见下文）。 |

在某个步骤的所有操作完成后，卡片会**停留在该步骤**，以便有人处理——除非该步骤设有自动流转规则将其推进（参见[完全自动化的步骤](#fully-automated-steps)）。

:::info
只有当卡片通过正常流程到达时，自动化操作才会运行——即首次添加、结果或自动流转将其带入，或 Wait 结束之后。如果工作人员手动将卡片拖到该步骤或将其退回，操作**不会**重新运行，因此同一个人不会收到两次相同的邮件。
:::

### 发送邮件 {#sending-email}

选择 **Send email**，挑选您的一个邮件模板，并可选择输入自定义主题。当卡片进入该步骤时，该人员会自动收到这封邮件。（如果该人员档案中没有电子邮件地址，此步骤会直接跳过此操作。）模板中的[合并字段](../settings/email-templates.md#merge-fields)（例如 `{{firstName}}`）会被替换为该人员自己的信息。如果由 **Donation · Created**（奉献 · 已创建）触发器启动了工作流，那么即使在 Wait 之后运行的步骤中，奉献字段 `{{amount}}`、`{{giftDate}}`、`{{fund}}` 和 `{{receipt}}` 也会根据该笔奉献进行填充。参见[奉献合并字段](../settings/email-templates.md#gift-merge-fields)。

邮件发出后，卡片的历史记录会显示 **Email sent**（邮件已发送）。如果邮件无法发送——例如教会的邮件尚未获得批准，或已达到每日上限——则不会添加“Email sent”记录。

:::info
工作流邮件只有在教会获准发送小组邮件之后才会发出，并且会计入教会的每日邮件上限。参见[为教会开启小组邮件](../groups/group-members.md#turning-on-group-email-for-your-church)。当这些邮件无法发送时，**Send email** 操作会在步骤编辑器中给出警告：如果审批仍在等待中，会显示 *"Your church's email hasn't been approved yet..."*（您教会的邮件尚未获得批准……）；如果近期邮件被退回或被举报为垃圾邮件，则会显示 *"Your church's email is paused..."*（您教会的邮件已暂停……）。
:::

### 记录出勤

选择 **Record Attendance**（记录出勤），然后点击 **Pick group**（选择小组），选择应记录出勤的小组。操作运行时，该人员会被标记为出席该小组正在进行中的礼拜时间——效果与其签到相同。如果配合一个会在人员到达时将其加入工作流的触发器使用，这一功能会很有用，这样他们无需单独签到即可被计入。

- 出勤是以卡片**创建**的时刻来衡量的，因此工作流中较早的 **Wait** 不会把它推迟到礼拜之后。
- 只有设置了星期和开始时间的礼拜时间才会计入。如果在该时刻，该小组的礼拜时间都不在进行中，则不会记录任何内容，卡片的历史记录会显示 **No scheduled service in progress — attendance not recorded**（没有进行中的礼拜——未记录出勤）。
- 记录出勤后，卡片的历史记录会显示 **Attendance recorded**（已记录出勤），后面跟着小组名称。对同一场礼拜再次运行该操作，不会把该人员重复计算。

### 通知某人

选择 **Notify Person**（通知某人），点击 **Pick person**（选择人员），并可选择输入**消息**。卡片进入该步骤时，该人员会收到一封电子邮件和一条 B1 通知，内容包括卡片上人员的姓名、工作流和步骤名称、您的消息，以及一个用于打开卡片的链接。可用于提前告知工作人员或事工负责人——例如：*“当有人到达入会面谈步骤时，通知牧师。”* 卡片的历史记录会显示 **Notified**（已通知），后面跟着该人员的姓名。

### 发送短信 {#sending-a-text}

选择 **Send Text**（发送短信），然后输入**短信内容**（最多 1,600 个字符）。如果您的教会保存了[短信模板](../settings/email-templates.md)，输入框上方会出现 **Start from a template**（从模板开始）列表。选择其中一个模板会将其文字复制到消息中，您仍然可以编辑。该步骤保留自己的副本，因此之后对模板的修改不会影响此步骤。卡片进入该步骤时，该人员会在其手机上收到这条短信。若要个性化消息，请点击输入框下方的标签——**First Name**（名字）、**Last Name**（姓氏）、**Display Name**（显示名称）或 **Church Name**（教会名称）——将 `{{firstName}}`、`{{lastName}}`、`{{displayName}}` 或 `{{churchName}}` 插入光标位置。发送时，每一项都会被替换为该人员的相应信息。**Amount**（金额）、**Gift Date**（奉献日期）、**Fund**（基金）和 **Receipt**（收据）标签会插入奉献字段，这些字段仅在由 **Donation · Created** 触发器启动工作流时才会填充。例如：`Thanks {{firstName}} for your gift of {{amount}} to {{fund}}!`

- 如果该人员的档案中没有手机号码，则不会发送短信，卡片的历史记录会显示 **Text skipped: no mobile phone**（已跳过短信：没有手机号码）。
- 如果该人员已退订，则不会发送短信，卡片的历史记录会显示 **Text skipped: opted out**（已跳过短信：已退订）。
- 短信发出后，卡片的历史记录会显示 **Text sent**（短信已发送）。如果发送失败——例如未连接短信服务提供商，或教会的短信额度已用完——失败信息会记录在卡片的历史记录中，并且该步骤的其余操作仍会继续运行。

:::warning
短信通过教会自己的[短信服务提供商](../settings/church-settings.md#texting)发送。如果未连接任何提供商，操作编辑器会提示 *"No texting provider is set up"*（尚未设置短信服务提供商），短信将无法发送。
:::

### 等待数天（滴灌序列）

**Wait** 操作会将卡片保留您设置的天数。等待期间，卡片会显示为 **Snoozed**（已暂停）。B1 每 30 分钟检查一次已结束的等待，因此卡片会在等待结束后约半小时内重新开始处理。等待结束后：

1. 该步骤中**同一步骤内剩余的操作**会运行——因此您可以构建一个滴灌序列，例如 **发送邮件 → 等待 3 天 → 发送提醒邮件**。
2. 然后，如果该步骤设有自动流转，卡片会继续前进；否则它会停留在该步骤，等待人员处理。

:::tip
在某个步骤的最开始使用 **Wait**，是在卡片交给志愿者之前“暂存”它的简便方法——例如，*等待 7 天，然后由一位辅导员联系。*
:::

## 将人员添加为卡片

有几种方式可以把人员放到看板上：

- **从看板添加**——点击某个步骤列底部的 **Add Card**（添加卡片），然后选择一个人员。您也可以选择一个小组，该小组的每位成员都会被添加为卡片。
- **从人员记录添加**——在某人的页面上使用 **Add to Workflow**（添加到工作流），即可将其放入某个工作流。
- **从人员搜索添加**——选择多个人员，然后使用批量 **Add to Workflow** 操作一次性全部添加。
- **通过触发器自动添加**——当某件事情发生时（例如表单提交或首次奉献）自动添加人员（参见下文[触发器](#triggers)）。

手动添加某人，或通过 **Add to workflow** 步骤操作添加，永远不会在同一个工作流上为其创建第二张未结束的卡片。如果该人员已有未结束的卡片，则会被跳过（在批量添加时，只有没有卡片的人员会获得新卡片）。卡片关闭后，您可以再次添加该人员。触发器则遵循其自身的 **Only once per person**（每人仅一次）设置。

## 管理看板 {#working-the-board}

打开工作流即可查看其看板。每张卡片会显示人员姓名、分配给谁，以及截止日期或状态标签（**Overdue**（已逾期）或 **Snoozed**（已暂停））。步骤列还会显示其所执行的自动化操作的小标记，以及其流转规则的注释，让您一眼就能看清卡片的流向。

- **移动卡片**——随着人员的进展，将卡片从一列拖到下一列。
- **打开卡片**——双击卡片（或点击它）打开详情抽屉，您可以在其中更改步骤、重新分配、添加备注，并查看已发生的事件。

在卡片抽屉中，您可以：

- **Assign**（分配）——将卡片分配给其他人或小组。
- **Snooze**（暂停）——将卡片暂停 1 天、3 天或 1 周，以暂时隐藏其截止日期。
- **Send Back**（退回）到上一步骤，或 **Skip**（跳过）到下一步骤。
- **Pin assignment**（固定分配）——即使卡片在步骤之间移动，也保持同一负责人。默认情况下，将卡片移动到新步骤会将其重新分配给该步骤的默认负责人；固定分配则会让当前负责人在整个过程中保持负责。
- **Complete**（完成）卡片以结束它，或者，如果该步骤已配置结果，则选择一个 **Outcome**（结果）按钮（参见[流转](#routing-cards-with-outcomes-and-conditions)）。
- **Remove card**（移除卡片）——在不完成的情况下将卡片从看板上拿走，例如某人被误添加时。确认后，卡片会被关闭，并从所有人的列表中移除。不会运行任何结果、流转或步骤操作，其历史记录会保留并显示 **Removed**（已移除）条目。对于[服事安排确认](#serving-assignment-confirmations)卡片，移除它会以同样的方式关闭该请求。
- **Add notes**（添加备注）并查看卡片的 **Activity**（活动）——即已运行的自动化操作日志（已发送的邮件、等待等），每项都带有发生的日期和时间。

对于与人员相关的卡片，抽屉还会将该人员的手机号码和电子邮件显示为链接，点击即可拨打电话或发送邮件；如果您有查看人员的权限，还会显示 **View profile**（查看个人资料）链接。即使没有人员的访问权限，卡片被分配的人员也能看到电话和电子邮件。

备注会与卡片一同保存。任何可以打开卡片的人——包括卡片被分配到的人员或小组——都可以阅读备注并添加自己的备注。无法打开卡片的人员则看不到其备注。

### 批量操作

勾选多张卡片的复选框，即可对它们进行统一操作。若要选中某一步骤中的全部卡片，请勾选该步骤列标题中的 **Select all**（全选）复选框；再次勾选即可取消。屏幕上会出现一个工具栏，可让您同时对所有选中的卡片执行 **Complete**（完成）、**Snooze**（暂停）、**Assign**（重新分配）或 **Move to…**（移动到……）其他步骤的操作。

## 使用结果与条件进行卡片流转 {#routing-cards-with-outcomes-and-conditions}

流转决定了卡片离开某个步骤时前往何处。打开步骤编辑器即可配置两种流转方式。

### 结果按钮

结果是在完成该步骤上的卡片时，显示在卡片抽屉中的按钮。您可以提供如“加入小组”或“没有兴趣”等选项，而不再只有一个 **Complete** 按钮。每个结果可以：

- 将卡片送到此工作流中的**另一个步骤**，
- 将卡片**转交**给完全不同的工作流，或
- **关闭**卡片。

这样，一个决定就能让人员走上不同的路径。

### 自动流转（条件式）

自动流转会在卡片**进入某个步骤的那一刻**（以及其自动化操作结束之后），如果人员符合一组条件，就会在无人点击的情况下将卡片推进。添加一条流转规则，选择目标步骤，并定义一个或多个**条件**（例如人员的校区、年龄或会籍状态）。文本字段可以进行精确匹配，也可以使用 **contains**（包含）、**starts with**（以……开头）或 **ends with**（以……结尾）匹配。没有条件的流转规则会匹配所有人。

日期条件（Today's Date（今天的日期）、Birth Date（出生日期）或 Anniversary（纪念日））可以比较完整日期，也可以只比较其一部分——星期几、**Day of Month**（一个月中的第几天）、**Month**（月份），或已经过的年数。对于人员的出生日期或纪念日，**Day of Month** 提供相对的 **Today**（今天）选项，因此像 *Birth Date · Day of Month = Today* 这样的条件，会匹配生日在当天日期的人员。**Month** 则提供 **Previous Month**（上个月）、**Current Month**（本月）和 **Next Month**（下个月）。这些相对值是按照教会所在的时区计算的，因此与教会的日历日期保持一致，而不是按服务器的时间。

**Giving**（奉献）类条件中有 **Lapsed regular giver**（已停止定期奉献的人），用于找出过去曾定期奉献、之后又停止的人员。请设置三个数字：*在最近 **12** 周中至少奉献过 **3** 次，然后在最近 **3** 周内没有奉献*（这些是默认值）。这些周数是从今天起，按教会所在时区往回计算的，已退款的奉献不计算在内。该条件最适合用于[定时触发器](#schedule-triggers)——例如，每周运行一次的规则，将已停止定期奉献的人员加入牧养关怀跟进看板。该条件只查看奉献日期，从不查看金额，卡片和提醒也从不显示金额。由于它会揭示谁已停止奉献，因此只有能够查看奉献的人员才能看到此选项，并可以添加、更改或删除它。

如果某条流转规则的条件因某种原因无法检查，则该规则会被视为不匹配。卡片会留在该步骤上（或沿着另一条匹配的流转规则前进），而不会被卡住。

:::info
在看板上，每个步骤列都会显示小注释，描述其流转规则——例如结果标签，或“if matches”（如果匹配），后面跟着指向目标步骤或工作流的箭头。
:::

## 完全自动化的步骤 {#fully-automated-steps}

您可以让某个步骤完全自动运行，无需任何人处理。为该步骤设置其**自动化操作**，并添加一条指向下一步骤的**自动流转**（不带任何条件）。卡片进入时，操作会运行，然后流转会立即将其推进——卡片直接穿过该步骤。

:::tip
将其与 **Wait** 结合使用：*发送欢迎邮件 → 等待 3 天 → 自动推进到“个人电话”步骤。* 邮件和时间安排都由系统处理，只有到了需要人工接触的时候，志愿者才会看到这张卡片。
:::

## 触发器 {#triggers}

触发器会在某件事情发生时自动将人员添加到工作流中，因此您无需手动添加卡片。在工作流看板上，点击 **Triggers**（触发器）标签页，然后点击 **Add Trigger**（添加触发器）。触发器有两种：

### 事件触发器

在 B1 中某条记录发生变化时立即触发。选择事件，然后可以选择添加**条件**，使只有符合条件的人员才会被添加：

- **Person · Created / Updated**（人员 · 已创建 / 已更新）——例如，将会籍状态变为*访客*或*来宾*（即自行注册的人员所获得的状态）的任何人添加进来。
- **Donation · Created**（奉献 · 已创建）——例如，将首次或大额奉献加入感谢工作流（可按金额、基金或方式匹配）。
- **Group · Member Joined**（小组 · 成员已加入）/ **Group · Created**（小组 · 已创建）。
- **Form · Submitted**（表单 · 已提交）——将提交指定表单的任何人添加进来（非常适合“我是新人”或“联系”卡片）。

### 定时触发器 {#schedule-triggers}

按日、周、月或年等周期性地运行，并针对一组条件进行判断。可用于基于时间的外展，例如*今天生日的所有人*（Birth Date · Day of Month = **Today**，月份匹配 **Current Month**），或*每月*的探访。即使未开启 **Only once per person**，定时触发器在同一个重复周期内（一天、一周、一个月或一年，取决于其运行频率）也不会再次添加同一个人。

对于任何触发器，您还可以设置：

- **Starting step**（起始步骤）——新卡片所在的第一个步骤（默认为第一个步骤）。
- **Only once per person**（每人仅一次）——防止同一个人被触发器重复添加到工作流中。开启后，已在该工作流上拥有卡片的人员会被跳过。
  - **Add again after their card is closed**（卡片关闭后可再次添加）——在开启 **Only once per person** 时出现。勾选后，触发器可以在某人在该工作流上的先前卡片关闭后再次添加该人。同一个人在工作流上仍然永远不会同时拥有两张未结束的卡片。适用于可能发生多次的情况，例如再次到访的新人或每年一次的流程。
- **Active**（启用）——开启或关闭触发器，无需删除它。

:::tip
将 **Form · Submitted** 触发器与 **New Visitor Follow-up** 模板配合使用，即可把您的“联系卡”或“我是新人”表单转变为自动跟进流程。
:::

## 服事安排确认 {#serving-assignment-confirmations}

一种特殊类型的工作流可以跟进[服事请求](./plans.md#assigning-team-members)，直到每位志愿者接受或拒绝为止。此看板上的每张卡片不是针对人员，而是跟踪**一项安排**——即同一个人在同一份计划中的同一个岗位。同一个人担任两个角色或参加两场礼拜，会各自拥有一张卡片。这是可选功能：在您于计划的设置中选择确认工作流之前，计划不会有任何变化。

### 设置方法

1. 在 Workflows 页面，点击 **Add Workflow**，然后选择 **Serving Assignment Confirmation** 模板。（或者开始一个 **Blank workflow**，并将其**工作流用途**设为 **Serving assignment confirmation**。）从模板创建需要有发送短信的权限，因为模板包含短信步骤。
2. 检查各个步骤。该模板默认包括：
   - **Request and wait for response**（请求并等待回复）——通过电子邮件和短信发送服事请求，等待 2 天，发送一封提醒邮件，再等待 1 天，然后自动将卡片推进。
   - **Call volunteer about unanswered request**（致电尚未回复请求的志愿者）——由人员致电志愿者的步骤，截止时间为 1 天。请为此步骤设置**默认负责人**。如果未设置，卡片会分配给事工的负责人，若没有负责人，则分配给事工团队。
3. 编辑等待时间、消息和步骤，使其符合您教会的情况。
4. 打开[计划的设置](./plans.md#plan-settings)，并在 **Confirmation workflow**（确认工作流）下选择此工作流。

这些工作流使用 **Send serving request**（发送服事请求）操作，而不是 **Send email** 和 **Send text**。请选择 **Email**（电子邮件）或 **Text message**（短信），并可选择撰写**请求消息**。请求内容始终包含岗位、计划、服事日期和回复链接；您可以在消息中使用 `{{planName}}`、`{{positionName}}` 和 `{{serviceDate}}`。将消息留空即可使用默认请求。志愿者的通知偏好、短信同意、您的短信服务提供商以及教会的邮件审批都会生效，任何被跳过或被阻止的尝试都会记录在卡片上。在这些看板上，**Send email**、**Send text** 和 **Add to workflow** 不可用。

确认工作流的 **Triggers**（触发器）标签页会说明卡片是如何启动的，而不是提供触发器；这些工作流也不会出现在人员的“添加到工作流”列表中。

### 卡片如何启动和关闭

- 当您在已发布的计划上**通知**志愿者时，卡片就会启动（参见[通知志愿者](./plan-validation.md#notifying-volunteers)）。每个新的、尚未回复的安排都会获得一张卡片。保存、发布、复制或自动填充计划本身不会联系任何人，而暂定的计划则不会发送任何内容。
- 志愿者仍会收到应用内的常规提醒。电子邮件和短信的跟进由工作流负责发送。
- 当志愿者**接受或拒绝**时，其卡片会自动关闭，连同与之关联的任何跟进任务一并关闭。
- 卡片抽屉会显示岗位、服事日期以及通往计划的链接。按钮不再显示 **Complete**，而是 **Record follow-up done**（记录已完成跟进）。点击它会记录某人已完成跟进，但卡片会保持开启并继续分配（显示为 **Awaiting response**（等待回复）），直到志愿者回复或回复截止时间过去为止。
- 回复截止时间是该岗位团队服事的最后一场礼拜时间的结束时刻。如果计划没有匹配的时间，则为服事日的结束时刻。如果到那时仍无人回复，卡片会以 **Response deadline passed**（已超过回复截止时间）关闭，并且一个 **Review unanswered serving request**（审核未回复的服事请求）任务会分配给卡片当前的负责人或事工负责人，以便有人决定如何补位。该安排会保持为 **Unconfirmed**（未确认）。
- 移除该安排、更改其人员、岗位或计划日期、将计划恢复为暂定状态，或将计划切换到其他确认工作流，都会关闭卡片。已关闭的卡片永远不会因另一次 **Notify** 而重新开启；若要发送新的请求，请添加新的安排。

:::info
对于通过确认工作流发送的请求，[志愿者提醒](./plans.md#volunteer-reminders)只会发送给已**接受**的志愿者，因此正在等待回复的人不会在工作流的跟进之外再收到提醒。
:::

## 我的卡片

志愿者和工作人员无需翻遍每个看板来找到自己的工作。**工作**页面上的 **My Cards**（我的卡片）列表会显示所有工作流中分配给当前用户的每一张卡片。要前往该处，请点击 Workflows 页面顶部的 **My Cards**，或在快速跳转菜单中打开 **Serving > My Work**。点击某张卡片会在“我的工作”页面上直接打开其详情面板，您无需离开该页面即可处理或移除卡片。如果您有查看工作流的权限，该面板还会提供 **Open workflow board**（打开工作流看板）链接，指向卡片所属的看板。

## 报告

打开某个工作流，然后点击 **Reports**（报告），即可查看该工作流的分析数据：

- **Overdue**（已逾期）——超过截止日期的卡片数量。
- **Cards per Step**（每步卡片数）——当前每个步骤上的卡片数量，以柱状图显示。
- **Completed (30 days)**（已完成（30 天））——过去 30 天的处理量，以折线图显示。

利用这些数据发现瓶颈——例如，某个步骤上的卡片不断堆积、从不前进。
