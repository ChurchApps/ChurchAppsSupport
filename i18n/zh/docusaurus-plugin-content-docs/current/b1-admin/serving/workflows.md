# 工作流 {#workflows}

<div class="article-intro">

工作流让人员在可视化看板上依次经过一系列步骤。每个人都会成为一张卡片，并从一个步骤移动到下一个步骤 -- 从首次到访的访客跟进，到入会流程，再到首次奉献者的感谢，以及任何需要让大量人员依次经历相同阶段的场景。某个步骤既可以要求志愿者去做某件事（打电话、进行交谈），**同时**也可以自行运行自动化操作 -- 发送电子邮件或短信、等待几天、将人员加入小组 -- 因此工作流既能处理人工跟进，也能处理其周边的琐碎工作。工作流将[任务](./tasks.md)扩展为可拖放的看板，确保任何事项和任何人都不会被遗漏。

</div>

<div class="prereqs">
<h4>开始之前</h4>

- 确保你想要跟踪的人员已存在于 B1 Admin 中
- 熟悉[任务](./tasks.md)的运作方式，因为看板上的每张卡片都是一项任务
- 若要使用 **Send email**（发送电子邮件）操作，请先创建你要发送的电子邮件模板（在 **Settings → Email Templates**（设置 → 电子邮件模板）下管理）
- 若要使用 **Send text**（发送短信）操作，请先连接[短信服务商](../settings/church-settings.md#texting)
- 你需要相应的任务权限。查看、编辑卡片和管理工作流是各自独立的权限级别（参见[角色与权限](../settings/roles-permissions.md)）

</div>

## 查看工作流 {#viewing-workflows}

打开[跳转菜单](../introduction.md#getting-around-with-the-jump-menu)（B1 Admin 左上角的搜索栏），展开 **Serving**（服事），然后点击 **Workflows**（工作流）。你的工作流会以表格形式列出，显示每个工作流的 **Category**（类别）和 **Status**（状态）（**Active**（启用）或 **Inactive**（停用））。如果你使用了类别，列表上方的标签页可以按类别筛选。点击任意工作流即可打开其看板。

## 创建工作流 {#creating-a-workflow}

1. 在工作流页面上，点击 **Add Workflow**（添加工作流）。
2. 选择启动方式：
   - **Blank workflow**（空白工作流）-- 从零开始，自行构建步骤。
   - **From a template**（从模板创建）-- 以现成的步骤集开始，并可进行编辑。内置模板包括：
     - **New Visitor Follow-up**（新访客跟进）-- 发送欢迎邮件 → 个人电话 → 邀请参加下一步 → 已建立联系
     - **Membership Class**（入会课程）-- 表达兴趣 → 报名课程 → 参加课程 → 完成入会
     - **First-time Giver Thank-you**（首次奉献者感谢）-- 发送感谢信 → 分享奉献的影响 → 尽心管家
     - **Serving Assignment Confirmation**（服事分派确认）-- 发出请求并等待回复 → 就未回复的请求致电志愿者（参见[服事分派确认](#serving-assignment-confirmations)）

   创建模板步骤可能需要一点时间。处理期间，**Add Workflow** 按钮会显示 **Creating...**（创建中...）且无法再次点击，因此不会产生重复的工作流。如果出现问题，页面会显示 *"The workflow could not be created. Please try again."*（无法创建工作流，请重试。）
3. 为工作流输入 **Name**（名称）。
4. 可选：为其分配 **Category**（类别），将相关工作流归为一组。你可以直接在下拉菜单中新建类别。
   对于空白工作流，你还需要选择其 **Workflow purpose**（工作流用途）：**People follow-up**（人员跟进，常规类型）或 **Serving assignment confirmation**（服事分派确认）。工作流创建后，用途无法更改。
5. 保持工作流为 **Active**（启用）状态，以便向其中添加人员；或将其设为 **Inactive**（停用），使其不再出现在"添加到工作流"的列表中。
6. 点击 **Save**（保存）。

:::tip
在工作流列表中使用 **Duplicate**（复制）按钮，可复制现有工作流（包括其步骤、自动化操作和分流规则）作为新工作流的起点。
:::

## 使用步骤构建看板 {#building-the-board-with-steps}

每个工作流看板由**步骤**组成，步骤从左到右以列的形式显示。打开工作流，使用 **Add Step**（添加步骤）为流程的每个阶段创建步骤。

添加或编辑步骤时，你可以配置以下内容：

- **Step Name**（步骤名称）-- 列标题（例如 "Welcome Call"（欢迎电话）或 "Awaiting Registration"（等待报名））。
- **Due in (days)**（截止天数）-- 卡片进入此步骤时自动设置截止日期。超过截止日期的卡片会被标记为 **Overdue**（逾期）。留空表示没有截止日期；你也可以清除之前设置的数字。
- **Default assignee**（默认负责人）-- 进入此步骤的新卡片会自动指派给的人员或小组。当默认负责人是个人时，该人员会收到通知，告知有卡片已指派给他。
- **Automated actions**（自动化操作）-- 卡片到达时系统自行执行的操作（见下文）。
- **Routing**（分流）-- 卡片离开该步骤后前往的位置（参见[分流](#routing-cards-with-outcomes-and-conditions)）。

将步骤列拖动到与你的流程相符的顺序。该顺序也决定了在没有其他分流规则适用时，卡片默认走的路径。

:::info
请先保存新步骤。自动化操作和分流规则都附加在步骤上，因此步骤存在后，编辑器才会解锁这些部分。
:::

## 自动化操作 {#automated-actions}

每个步骤都可以包含一组**自动化操作**，卡片一**进入**该步骤，这些操作便会自行运行 -- 无需等待任何人接手。这就是步骤既能提示志愿者，又能处理后续跟进周边日常工作的方式。

在步骤编辑器中，打开 **Automated actions**（自动化操作），点击 **Add Action**（添加操作），选择类型并填写其设置。可根据需要添加任意数量的操作，它们会**按从上到下的顺序**运行。在步骤上点击 **Save**（保存），即可将该步骤及其所有操作一并保存。使用垃圾桶图标移除操作会立即生效。

| 操作 | 作用 |
|---|---|
| **Send email**（发送电子邮件） | 向该人员发送你选择的电子邮件模板。你可以覆盖邮件主题。 |
| **Send text**（发送短信） | 通过你教会的[短信服务商](../settings/church-settings.md#texting)，向该人员发送你撰写的消息。 |
| **Wait**（等待） | 在继续之前，将卡片暂停指定天数（见下文）。 |
| **Add to group**（加入小组） | 将该人员加入你选择的[小组](../groups/index.md)。 |
| **Remove from group**（移出小组） | 将该人员移出你选择的小组。 |
| **Record Attendance**（记录出勤） | 将该人员标记为出席某个小组正在进行中的礼拜时间（见下文）。 |
| **Add to workflow**（加入工作流） | 让该人员开始另一个工作流，便于在不同流程之间交接。 |
| **Add note**（添加备注） | 在卡片的历史记录中添加一条备注。 |
| **Set field**（设置字段） | 更新该人员记录中的字段：Membership Status（会员状态）、Marital Status（婚姻状况）、Gender（性别）、City（城市）、State（州/省）或 Zip（邮政编码）。 |
| **Webhook**（网络钩子） | 将卡片的详细信息发送到你提供的外部网址（URL），用于连接其他系统。 |
| **Create task**（创建任务） | 创建一项[任务](./tasks.md)，其标题和描述由你输入，并指派给你选择的人员。 |
| **Notify Person**（通知人员） | 向你选择的工作人员或志愿者发送一封关于该卡片的电子邮件和一条 B1 通知（见下文）。 |

步骤的所有操作完成后，卡片会**停留在该步骤**，等待有人处理，除非该步骤设有自动分流规则，将卡片推进到下一步（参见[全自动步骤](#fully-automated-steps)）。

:::info
自动化操作仅在卡片通过正常流程到达时运行 -- 即首次添加时、某个结果或自动分流将其带入时，或等待结束后。当工作人员手动将卡片拖到该步骤或将其退回时，这些操作**不会**重新运行，因此人员不会收到重复的邮件。
:::

### 发送电子邮件 {#sending-email}

选择 **Send email**（发送电子邮件），挑选一个电子邮件模板，并可选择输入自定义主题。卡片进入该步骤时，该人员会自动收到此邮件。（如果该人员档案中没有电子邮件地址，该步骤会直接跳过此操作。）模板中的[合并字段](../settings/email-templates.md#merge-fields)（例如 `{{firstName}}`）会自动填入该人员自己的信息。如果由 **Donation · Created**（奉献 · 已创建）触发器启动了工作流，则 `{{amount}}`、`{{giftDate}}`、`{{fund}}` 和 `{{receipt}}` 等奉献字段会根据该笔奉献自动填入，即使是在等待之后运行的步骤也不例外。参见[奉献合并字段](../settings/email-templates.md#gift-merge-fields)。

邮件发出后，卡片的历史记录会显示 **Email sent**（邮件已发送）。如果邮件无法发送（例如教会的电子邮件尚未获得批准，或已达到每日上限），则不会添加 "Email sent" 记录。

:::info
只有在教会获准发送小组电子邮件后，工作流邮件才会发出，并且这些邮件会计入教会的每日电子邮件上限。参见[为你的教会开启小组电子邮件](../groups/group-members.md#turning-on-group-email-for-your-church)。当这些邮件无法发送时，**Send email** 操作会在步骤编辑器中向你发出警告：如果审批仍在等待中，会显示 *"Your church's email hasn't been approved yet..."*（你教会的电子邮件尚未获得批准……）；如果近期邮件被退回或被举报为垃圾邮件，则显示 *"Your church's email is paused..."*（你教会的电子邮件已暂停……）。
:::

### 记录出勤 {#recording-attendance}

选择 **Record Attendance**（记录出勤），然后点击 **Pick group**（选择小组），选择应记录出勤的小组。操作运行时，该人员会被标记为出席该小组正在进行中的礼拜时间，效果与其签到相同。当某个触发器在人员到达时将其加入工作流，从而无需单独签到即可统计出勤时，此功能尤其有用。

- 出勤是按卡片**创建**的时刻计算的，因此工作流中较早的 **Wait**（等待）不会使其超出礼拜时间范围。
- 只有设有星期和开始时间的礼拜时间才会计入。如果此时该小组的礼拜时间均未在进行中，则不会记录任何内容，卡片的历史记录会注明 **No scheduled service in progress — attendance not recorded**（没有正在进行的预定礼拜，未记录出勤）。
- 出勤记录成功后，卡片的历史记录会显示 **Attendance recorded**（已记录出勤），后跟该小组的名称。对同一场礼拜再次运行此操作，不会重复计算该人员。

### 通知人员 {#notifying-a-person}

选择 **Notify Person**（通知人员），点击 **Pick person**（选择人员），并可选择输入 **Message**（消息）。卡片进入该步骤时，该人员会收到一封电子邮件和一条 B1 通知，内容包括卡片上人员的姓名、工作流和步骤名称、你的消息，以及打开该卡片的链接。它可用于提前告知工作人员或事工负责人，例如 *"当有人到达会员面谈步骤时，通知牧师。"* 卡片的历史记录会显示 **Notified**（已通知），后跟该人员的姓名。

### 发送短信 {#sending-a-text}

选择 **Send Text**（发送短信），并输入 **Text message**（短信内容）（最多 1,600 个字符）。如果你的教会已保存[短信模板](../settings/email-templates.md)，输入框上方会出现 **Start from a template**（从模板开始）列表。选择一个模板会将其文字复制到消息中，之后你仍可编辑。该步骤保留其自己的副本，因此之后对模板的更改不会影响该步骤。卡片进入该步骤时，该人员会在其手机上收到此短信。若要个性化消息，请点击消息框下方的标签 -- **First Name**（名字）、**Last Name**（姓氏）、**Display Name**（显示名称）或 **Church Name**（教会名称） -- 即可在光标处插入 `{{firstName}}`、`{{lastName}}`、`{{displayName}}` 或 `{{churchName}}`。发送短信时，每个占位符都会用该人员的信息替换。**Amount**（金额）、**Gift Date**（奉献日期）、**Fund**（基金）和 **Receipt**（收据）标签会插入奉献字段，且只有在由 **Donation · Created** 触发器启动工作流时才会填入。例如：`Thanks {{firstName}} for your gift of {{amount}} to {{fund}}!`

- 如果该人员档案中没有手机号码，则不会发送短信，卡片的历史记录会注明 **Text skipped: no mobile phone**（已跳过短信：没有手机号码）。
- 如果该人员已退订，则不会发送短信，卡片的历史记录会注明 **Text skipped: opted out**（已跳过短信：已退订）。
- 短信发出后，卡片的历史记录会显示 **Text sent**（短信已发送）。如果发送失败（例如未连接短信服务商，或教会的短信额度已用完），失败原因会记录在卡片的历史记录中，且该步骤的其余操作仍会继续运行。

:::warning
短信通过你教会自己的[短信服务商](../settings/church-settings.md#texting)发送。如果未连接任何服务商，操作编辑器会提示 *"No texting provider is set up"*（尚未设置短信服务商），短信将无法发送。
:::

### 等待数天（渐进式跟进序列） {#waiting-a-few-days-drip-sequences}

**Wait**（等待）操作会将卡片保留你设置的天数。等待期间，卡片会显示为 **Snoozed**（已暂停）。B1 每 30 分钟检查一次已结束的等待，因此卡片会在等待结束后约半小时内恢复运行。等待结束后：

1. 该步骤中**剩余的操作**会运行，因此你可以构建一个渐进式序列，例如 **发送电子邮件 → 等待 3 天 → 发送提醒邮件**。
2. 然后，如果该步骤设有自动分流规则，卡片会继续前进；否则它会停留在该步骤，等待有人处理。

:::tip
在步骤的最开始放置一个 **Wait**，是在卡片呈现给志愿者之前"暂存"它的简便方法，例如 *等待 7 天，然后由教练主动联系。*
:::

## 将人员添加为卡片 {#adding-people-as-cards}

有多种方式可以将人员放到看板上：

- **从看板添加** -- 点击某个步骤列底部的 **Add Card**（添加卡片），然后选择一个人员。你也可以选择一个小组，该小组的每位成员都会被添加为卡片。
- **从人员记录添加** -- 在某人的页面上使用 **Add to Workflow**（加入工作流），即可将其放入某个工作流。
- **从人员搜索添加** -- 选择多个人员，然后使用批量 **Add to Workflow** 操作，一次性全部添加。
- **通过触发器自动添加** -- 当某事发生时自动添加人员，例如表单提交或首次奉献（见下文的[触发器](#triggers)）。

无论是手动添加，还是通过 **Add to workflow** 步骤操作添加，都不会让某人在同一工作流上拥有第二张未完成的卡片。如果他们已有未完成的卡片，则会被跳过（批量添加时，只有没有卡片的人员会获得新卡片）。卡片关闭后，你可以再次添加他们。触发器则遵循其自身的 **Only once per person**（每人仅一次）设置。

## 操作看板 {#working-the-board}

打开工作流即可查看其看板。每张卡片会显示人员姓名、指派对象，以及截止日期或状态标签（**Overdue**（逾期）或 **Snoozed**（已暂停））。步骤列还会以小徽标显示其运行的任何自动化操作，并以标注说明其分流规则，让你一目了然地看清卡片的流转方式。在每一列中，最近进入该步骤的卡片会排在最上方。

- **移动卡片** -- 随着人员的进展，将卡片从一列拖到下一列。
- **打开卡片** -- 双击卡片（或点击它）即可打开其详情抽屉，在其中你可以更改步骤、重新指派、添加备注，以及查看已发生的事件。

在卡片抽屉中，你可以：

- **Assign**（指派）-- 将卡片指派给其他人员或小组。此变更会记录在卡片的 **Activity**（活动）中，例如 "Reassigned from Jane Smith to John Doe"（已从 Jane Smith 重新指派给 John Doe）。
- **Snooze**（暂停）-- 将卡片暂停 1 天、3 天或 1 周，以暂时隐藏其截止日期。
- **Send Back**（退回）至上一步骤，或 **Skip**（跳过）至下一步骤。
- **Pin assignment**（固定指派）-- 即使卡片在各步骤之间移动，也保持同一负责人。默认情况下，将卡片移到新步骤会将其重新指派给该步骤的默认负责人；固定指派则让当前负责人在整个过程中保持负责。
- **Complete**（完成）-- 完成卡片；如果该步骤已配置结果，则可以选择 **Outcome**（结果）按钮（参见[分流](#routing-cards-with-outcomes-and-conditions)）。
- **Remove card**（移除卡片）-- 在不完成的情况下将卡片从看板上移除，例如某人被误加入时。确认后，卡片会被关闭，并从所有人的列表中移除。不会运行任何结果、分流规则或步骤操作，其历史记录会保留，并显示 **Removed**（已移除）记录。对于[服事分派确认](#serving-assignment-confirmations)卡片，移除卡片会以相同方式关闭该请求。
- **Add notes**（添加备注）并查看卡片的 **Activity**（活动）-- 这是一份已运行的自动化操作日志（已发送的邮件、等待等），每项都附有发生的日期和时间。

对于关联某个人员的卡片，抽屉中还会以链接形式显示该人员的手机号码和电子邮件，点击即可拨打电话或发送邮件；如果你有查看人员的权限，还会显示 **View profile**（查看个人资料）链接。即使没有人员页面的访问权限，卡片被指派的人员也能看到手机号码和电子邮件。

备注会与卡片一同保存。任何能够打开该卡片的人（包括卡片被指派的人员或小组）都可以阅读备注并添加自己的备注。无法打开卡片的人员则看不到其备注。

### 批量操作 {#bulk-actions}

勾选多张卡片的复选框，即可对其一并操作。若要一次选中某个步骤中的所有卡片，请勾选该步骤列标题中的 **Select all**（全选）复选框；再次勾选即可全部取消。此时会出现一个工具栏，可让你对所有已选卡片一并执行 **Complete**（完成）、**Snooze**（暂停）、**Assign**（重新指派）或 **Move to…**（移至……）其他步骤。

## 通过结果和条件进行分流 {#routing-cards-with-outcomes-and-conditions}

分流规则控制卡片离开某个步骤后前往的位置。打开步骤的编辑器，即可配置两种分流方式。

### 结果按钮 {#outcome-buttons}

结果是在完成该步骤上的卡片时，卡片抽屉中显示的按钮。你可以提供诸如 "Joined a Group"（已加入小组）或 "Not Interested"（无兴趣）等选项，而不是单一的 **Complete** 按钮。每个结果都可以：

- 将卡片发送到该工作流中的**另一个步骤**，
- 将卡片**交接**给完全不同的另一个工作流，或
- **关闭**卡片。

这样，一个决定就能将人员引向不同的路径。

### 自动分流（有条件） {#automatic-routing-conditional}

自动分流规则会在卡片**进入某个步骤的那一刻**（并在其自动化操作完成之后）将其推进，无需任何人点击，前提是该人员符合一组条件。添加一条分流规则，选择目标步骤，并定义一个或多个**条件**（例如人员的校区、年龄或会员状态）。文本字段可以进行精确匹配，也可以使用 **contains**（包含）、**starts with**（以……开头）或 **ends with**（以……结尾）匹配。没有任何条件的分流规则会匹配所有人。

日期条件（Today's Date（今天的日期）、Birth Date（出生日期）或 Anniversary（纪念日））可以比较完整日期，也可以只比较其中的一部分，例如星期几、**Day of Month**（月中日）、**Month**（月份），或已过的年数。对于人员的 Birth Date 或 Anniversary，**Day of Month** 提供相对的 **Today**（今天）选项，因此像 *Birth Date · Day of Month = Today* 这样的条件，会匹配生日恰好是当月今天的人员。**Month** 则提供 **Previous Month**（上个月）、**Current Month**（本月）和 **Next Month**（下个月）。这些相对值会按照教会的时区计算，因此与教会的日历日期保持一致，而不是与服务器的时间对齐。

**Giving**（奉献）条件组中包含 **Lapsed regular giver**（已停止定期奉献的人），用于找出过去曾定期奉献、之后却停止的人员。需设置三个数字：*在最近 **12** 周中至少奉献过 **3** 次，且最近 **3** 周没有奉献*（这些是默认值）。周数从教会时区的今天向前计算，已退款的奉献不计入。此条件最适用于[定时触发器](#schedule-triggers)，例如一条每周规则，将已停止定期奉献的人员加入牧养关怀跟进看板。该条件只看奉献日期，从不看金额，卡片和提醒也从不显示金额。由于它会显示谁已停止奉献，因此只有能够查看奉献的人员才能看到此选项，并可以添加、更改或移除它。

如果某条分流规则的条件因任何原因无法检查，则该规则被视为不匹配。卡片会停留在该步骤（或沿着另一条匹配的规则前进），而不会卡住。

:::info
在看板上，每个步骤列都会显示小标注，描述其分流规则，例如结果标签，或 "if matches"（若匹配），后跟指向目标步骤或工作流的箭头。
:::

## 全自动步骤 {#fully-automated-steps}

你可以让某个步骤完全自行运行，无需任何人处理。为该步骤设置**自动化操作**，并添加一条指向下一步骤的**自动分流规则**（不带任何条件）。卡片进入时，操作会运行，然后分流规则会立即将其推进，卡片会直接穿过该步骤。

:::tip
可以将其与 **Wait** 结合使用：*发送欢迎邮件 → 等待 3 天 → 自动推进到 "Personal call"（个人电话）步骤。* 邮件和时间安排都由系统处理，志愿者只会在需要亲自接触时才看到该卡片。
:::

## 触发器 {#triggers}

触发器会在某事发生时自动将人员加入工作流，因此你无需手动添加卡片。在工作流看板上，点击 **Triggers**（触发器）标签页，然后点击 **Add Trigger**（添加触发器）。触发器分为两种：

### 事件触发器 {#event-triggers}

在 B1 中的记录发生变化时立即触发。选择事件，然后可选择添加**条件**，使只有符合条件的人员才会被添加：

- **Person · Created / Updated**（人员 · 已创建 / 已更新）-- 例如，将状态变为 *Visitor*（访客）或 *Guest*（宾客）的任何人（这是授予自行登记者的状态）加入工作流。
- **Donation · Created**（奉献 · 已创建）-- 例如，将首次或大额奉献者加入感谢工作流（可按金额、基金或方式匹配）。
- **Group · Member Joined**（小组 · 成员加入）/ **Group · Created**（小组 · 已创建）。
- **Form · Submitted**（表单 · 已提交）-- 将提交指定表单的任何人加入工作流（非常适合 "I'm New"（我是新来的）或 "Connect"（联系）卡片）。

### 定时触发器 {#schedule-triggers}

按周期运行（每天、每周、每月或每年），并针对一组条件进行判断。可用于基于时间的外展，例如 *生日为今天的每个人*（Birth Date · Day of Month = **Today**，并将月份匹配为 **Current Month**），或*每月*一次的关怀回访。即使未开启 **Only once per person**（每人仅一次），定时触发器也不会在同一重复周期内（一天、一周、一个月或一年，视其运行频率而定）再次添加同一人员。

对于任何触发器，你还可以设置：

- **Starting step**（起始步骤）-- 新卡片落入的步骤（默认为第一个步骤）。
- **Only once per person**（每人仅一次）-- 使触发器不会将同一人员重复加入工作流。开启后，已在该工作流上拥有卡片的人员会被跳过。
  - **Add again after their card is closed**（卡片关闭后可再次添加）-- 在开启 **Only once per person** 时出现。勾选后，允许触发器在某人在该工作流上较早的卡片关闭后再次将其添加。人员在该工作流上仍然绝不会同时拥有两张未完成的卡片。适用于可能多次发生的情况，例如回访的宾客或每年一次的流程。
- **Active**（启用）-- 开启或关闭触发器，而无需删除它。

:::tip
将 **Form · Submitted** 触发器与 **New Visitor Follow-up**（新访客跟进）模板搭配使用，即可将你的 "Connect Card"（联系卡）或 "I'm New"（我是新来的）表单转变为自动跟进流程。
:::

## 服事分派确认 {#serving-assignment-confirmations}

一种特殊类型的工作流可以持续跟进[服事请求](./plans.md#assigning-team-members)，直到每位志愿者接受或拒绝为止。此看板上的每张卡片跟踪的不是人员，而是**一项分派** -- 即某计划中某个人员在某个岗位上的分派。同一人员担任两个角色或两场礼拜，会各有一张独立的卡片。此功能为可选：在你于某计划的设置中选择确认工作流之前，该计划不会有任何变化。

### 设置方法 {#setting-one-up}

1. 在工作流页面上，点击 **Add Workflow**（添加工作流），然后选择 **Serving Assignment Confirmation**（服事分派确认）模板。（或者以 **Blank workflow**（空白工作流）开始，并将其 **Workflow purpose**（工作流用途）设为 **Serving assignment confirmation**（服事分派确认）。）从模板创建需要具有发送短信的权限，因为模板包含一个短信步骤。
2. 检查步骤。模板初始包含：
   - **Request and wait for response**（发出请求并等待回复）-- 通过电子邮件和短信发送服事请求，等待 2 天，发送提醒邮件，再等待 1 天，然后自动将卡片推进。
   - **Call volunteer about unanswered request**（就未回复的请求致电志愿者）-- 由一人致电志愿者的步骤，截止时间为 1 天后。请为此步骤设置 **Default assignee**（默认负责人）。如果未设置，卡片会交给事工负责人；如果没有负责人，则交给事工团队。
3. 编辑等待时间、消息和步骤，使其符合你教会的需要。
4. 打开[计划设置](./plans.md#plan-settings)，并在 **Confirmation workflow**（确认工作流）下选择此工作流。

这些工作流使用 **Send serving request**（发送服事请求）操作，而不是 **Send email** 和 **Send text**。选择 **Email**（电子邮件）或 **Text message**（短信），并可选择撰写 **Request message**（请求消息）。请求中始终包含岗位、计划、礼拜日期以及回复链接；你可以在消息中使用 `{{planName}}`、`{{positionName}}` 和 `{{serviceDate}}`。若将消息留空，则使用默认请求内容。志愿者的通知偏好、短信接收同意、你的短信服务商以及教会的电子邮件批准均会生效，任何被跳过或被阻止的发送尝试都会记录在卡片上。这些看板上不提供 **Send email**、**Send text** 和 **Add to workflow** 操作。

确认工作流的 **Triggers**（触发器）标签页会说明卡片是如何启动的，而不提供触发器，并且这些工作流不会出现在人员的 **Add to Workflow** 列表中。看板上没有 **Add Card** 按钮，因为卡片只能来自某计划中的服事请求。

### 卡片的启动与关闭方式 {#how-cards-are-started-and-closed}

- 在已发布的计划上**通知**志愿者时，卡片即会启动（参见[通知志愿者](./plan-validation.md#notifying-volunteers)）。每项新的、未回复的分派都会获得一张卡片。保存、发布、复制或自动填充计划本身不会联系任何人，而暂定计划则不会发送任何内容。
- 志愿者仍会收到常规的应用内提醒。电子邮件和短信跟进则由工作流发出。
- 志愿者**接受或拒绝**后，其卡片会自动关闭，与其关联的所有后续任务也会一并关闭。
- 卡片抽屉会显示岗位、礼拜日期以及计划链接。按钮不再显示 **Complete**，而是显示 **Record follow-up done**（记录跟进已完成）。点击后会记录已有人跟进，但卡片保持开启并仍指派给该人（显示为 **Awaiting response**（等待回复）），直到志愿者回复或回复截止时间过去。
- 回复截止时间为该岗位团队所服事的最后一场礼拜时间的结束时刻。如果计划中没有匹配的时间，则为礼拜当天的结束时刻。如果到那时仍无人回复，卡片会以 **Response deadline passed**（已过回复截止时间）关闭，并向卡片当前负责人或事工负责人发出一项 **Review unanswered serving request**（审核未回复的服事请求）任务，以便有人决定如何补位。该分派仍保持 **Unconfirmed**（未确认）状态。
- 移除该分派、更改其人员、岗位或计划日期、将计划恢复为暂定，或将计划切换为其他确认工作流，都会关闭该卡片。已关闭的卡片绝不会因另一次 **Notify** 而重新开启；如需发送新请求，请添加新的分派。

:::info
对于通过确认工作流发出的请求，[志愿者提醒](./plans.md#volunteer-reminders)只会发送给已**接受**的志愿者，因此正在等待回复的人员不会在工作流的跟进之外再收到提醒。
:::

## 我的卡片 {#my-cards}

志愿者和工作人员无需翻查每一个看板即可找到自己的工作。**My Work**（我的工作）页面上的 **My Cards**（我的卡片）列表会显示当前用户在所有工作流中被指派的每一张卡片。若要进入该列表，请点击工作流页面顶部的 **My Cards**，或在跳转菜单中打开 **Serving > My Work**（服事 > 我的工作）。点击某张卡片，会在"我的工作"页面上直接打开其详情面板，你无需离开该页面即可处理或移除卡片。如果你有查看工作流的权限，该面板还会提供 **Open workflow board**（打开工作流看板）链接，可前往该卡片所属的看板。

## 报表 {#reports}

打开某个工作流并点击 **Reports**（报表），即可查看该工作流的分析数据：

- **Overdue**（逾期）-- 超过截止日期的卡片数量。
- **Cards per Step**（每步骤卡片数）-- 当前每个步骤上的卡片数量，以柱状图显示。
- **Completed (30 days)**（已完成（30 天））-- 过去 30 天的处理量，以折线图显示。

利用这些数据可以发现瓶颈，例如某个步骤上的卡片不断堆积而无法推进。
