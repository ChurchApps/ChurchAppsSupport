# 工作流

<div class="article-intro">

工作流通过一个可视化看板，推动人员依次经过一系列步骤。每个人都会成为一张卡片，从一个步骤移动到下一个步骤——从首次到访访客的跟进，到入会流程，再到首次奉献者的感谢，以及任何需要让大量人员依次经过同一组阶段进行追踪的情况。一个步骤既可以要求志愿者去做某件事（打电话、进行交谈），**同时**也可以自动执行操作——发送电子邮件或短信、等待几天、将人员加入小组——因此工作流既能处理人工跟进，也能处理其周边的琐碎工作。工作流将[任务](./tasks.md)扩展为可拖放的看板，确保没有任何事情或任何人被遗漏。

</div>

<div class="prereqs">
<h4>开始之前</h4>

- 确保你要追踪的人员已存在于 B1 Admin 中
- 熟悉[任务](./tasks.md)的运作方式，因为看板上的每张卡片都是一个任务
- 要使用**发送电子邮件**操作，请先创建你要发送的电子邮件模板（在 **设置 → 电子邮件模板** 下管理）
- 要使用**发送短信**操作，请先连接[短信服务商](../settings/church-settings.md#texting)
- 你需要相应的任务权限。查看、编辑卡片和管理工作流属于不同的权限级别（参见[角色与权限](../settings/roles-permissions.md)）

</div>

## 查看工作流

打开[快速跳转菜单](../introduction.md#getting-around-with-the-jump-menu)（B1 Admin 左上角的搜索栏），展开 **Serving**，然后点击 **Workflows**。你的工作流会以表格形式列出，显示每个工作流的**分类**和**状态**（**Active**（启用）或 **Inactive**（停用））。如果你使用分类，列表上方的标签页可以按分类进行筛选。点击任意工作流即可打开其看板。

## 创建工作流

1. 在 Workflows 页面，点击 **Add Workflow**（添加工作流）。
2. 选择启动方式：
   - **Blank workflow**（空白工作流）—— 从零开始，自行构建步骤。
   - **From a template**（从模板）—— 从现成的步骤集开始，并可进行编辑。内置模板包括：
     - **New Visitor Follow-up**（新访客跟进）—— 发送欢迎邮件 → 个人电话 → 邀请参加下一步 → 已联系
     - **Membership Class**（入会课程）—— 表达兴趣 → 报名课程 → 参加课程 → 完成入会
     - **First-time Giver Thank-you**（首次奉献者感谢）—— 发送感谢信 → 分享奉献的影响 → 已托管
     - **Serving Assignment Confirmation**（服事安排确认）—— 发出请求并等待回应 → 致电志愿者跟进未回复的请求（参见[服事安排确认](#serving-assignment-confirmations)）

   构建模板的步骤可能需要一点时间。在处理期间，**Add Workflow** 按钮会显示 **Creating...**（创建中）且无法再次点击，因此不会产生重复的工作流。如果出现问题，页面会显示 *"The workflow could not be created. Please try again."*（工作流无法创建，请重试。）
3. 为工作流输入**名称（Name）**。
4. 可选为工作流指定**分类（Category）**，以便将相关的工作流归为一组。你可以直接在下拉菜单中新建分类。
   如果是空白工作流，你还需要选择其**工作流用途（Workflow purpose）**：**People follow-up**（人员跟进，常规用途）或 **Serving assignment confirmation**（服事安排确认）。工作流创建后，用途无法更改。
5. 保持工作流为 **Active**（启用）状态，以便将人员添加进来；或将其设为 **Inactive**（停用），以便从"添加到工作流"的列表中隐藏它。
6. 点击 **Save**。

:::tip
在工作流列表中使用 **Duplicate**（复制）按钮，可复制现有工作流——包括其步骤、自动化操作和流转规则——作为新工作流的起点。
:::

## 使用步骤构建看板

每个工作流看板由**步骤（steps）**组成，从左到右显示为各列。打开一个工作流，并使用 **Add Step**（添加步骤）创建流程中的每个阶段。

添加或编辑步骤时，你可以配置：

- **Step Name**（步骤名称）—— 列标题（例如"欢迎电话"或"等待报名"）。
- **Due in (days)**（截止天数）—— 卡片进入该步骤时自动设置截止日期。超过截止日期的卡片会被标记为 **Overdue**（已逾期）。
- **Default assignee**（默认负责人）—— 该步骤中新卡片自动分配给的人员或小组。当默认负责人是某个人时，该人会收到一条通知，告知有卡片分配给他们。
- **Automated actions**（自动化操作）—— 卡片到达时系统自行执行的操作（见下文）。
- **Routing**（流转）—— 卡片离开该步骤后前往何处（参见[流转](#routing-cards-with-outcomes-and-conditions)）。

将步骤列拖动到与你的流程相匹配的顺序。该顺序也定义了在没有其他流转规则适用时，卡片的默认路径。

:::info
请先保存新步骤。自动化操作和流转规则都附加在步骤上，因此只有在步骤存在之后，编辑器才会解锁这些部分。
:::

## 自动化操作

每个步骤都可以附带一组**自动化操作（automated actions）**，它们会在卡片**进入**该步骤的那一刻自动运行——在任何人触碰卡片之前。这样，一个步骤既能提示志愿者，又能处理后续跟进周边的例行工作。

在步骤编辑器中，打开 **Automated actions**，点击 **Add Action**（添加操作），选择一种类型，然后填写其设置。可以添加任意数量的操作；它们会**按从上到下的顺序依次运行**。在步骤上点击 **Save**，即可同时保存该步骤及其所有操作。使用垃圾桶图标删除某个操作会立即生效。

| 操作 | 作用 |
|---|---|
| **Send email**（发送电子邮件） | 向该人员发送你所选的电子邮件模板。你可以覆盖邮件主题。 |
| **Send text**（发送短信） | 通过你教会的[短信服务商](../settings/church-settings.md#texting)，向该人员发送你撰写的消息。 |
| **Wait**（等待） | 将卡片暂停指定天数后再继续（见下文）。 |
| **Add to group**（加入小组） | 将该人员加入你选择的[小组](../groups/index.md)。 |
| **Remove from group**（移出小组） | 将该人员从你选择的小组中移除。 |
| **Record Attendance**（记录出勤） | 将该人员标记为出席该小组当前正在进行的礼拜时间（见下文）。 |
| **Add to workflow**（加入工作流） | 让该人员开始另一个工作流——适用于在不同流程之间进行交接。 |
| **Add note**（添加备注） | 在卡片的历史记录中添加备注。 |
| **Set field**（设置字段） | 更新该人员资料中的字段：会籍状态、婚姻状况、性别、城市、州或邮编。 |
| **Webhook** | 将卡片的详细信息发送到你提供的外部网址（URL），用于与其他系统对接。 |
| **Create task**（创建任务） | 创建一个[任务](./tasks.md)，使用你输入的标题和描述，并分配给你选择的人员。 |
| **Notify Person**（通知人员） | 向你选择的工作人员或志愿者发送一封关于该卡片的电子邮件和一条 B1 通知（见下文）。 |

步骤中的所有操作完成后，卡片会**停留在该步骤**，以便有人处理——除非该步骤设有自动流转规则将其推进到下一步（参见[完全自动化的步骤](#fully-automated-steps)）。

:::info
自动化操作只会在卡片通过正常流程到达时运行——即首次添加时、结果或自动流转将其带入时，或在"等待"结束之后。当工作人员手动将卡片拖到该步骤，或将其退回时，这些操作**不会**再次运行，因此人员不会收到两次相同的邮件。
:::

### 发送电子邮件

选择 **Send email**，挑选一个电子邮件模板，并可选择输入自定义主题。卡片进入该步骤时，该人员会自动收到这封邮件。（如果该人员没有登记电子邮件地址，该步骤会直接跳过此操作。）模板中的[合并字段](../settings/email-templates.md#merge-fields)（例如 `{{firstName}}`）会用该人员自己的信息填充。

邮件发出后，卡片的历史记录会显示 **Email sent**（邮件已发送）。如果无法发送——例如因为你的教会邮件尚未获批，或已达到每日上限——则不会添加"Email sent"记录。

:::info
工作流邮件只有在你的教会获准发送小组邮件之后才会发出，并且计入教会的每日邮件上限。参见[为教会开启小组邮件](../groups/group-members.md#turning-on-group-email-for-your-church)。当这些邮件无法发送时，**Send email** 操作会在步骤编辑器中给出警告：如果审批仍在等待中，会显示 *"Your church's email hasn't been approved yet..."*（你教会的邮件尚未获得批准……）；如果近期邮件被退回或被举报为垃圾邮件，则会显示 *"Your church's email is paused..."*（你教会的邮件已暂停……）。
:::

### 记录出勤

选择 **Record Attendance**，然后点击 **Pick group**（选择小组），选择应记录出勤的小组。操作运行时，该人员会被标记为出席该小组当前正在进行的礼拜时间——效果与其签到相同。这在结合会在人员到达时将其加入工作流的触发器使用时非常有用，这样无需单独签到即可计入出勤。

- 出勤以卡片**创建**的时刻为准，因此工作流中较早的**等待**操作不会使其超出礼拜时间。
- 只有设置了星期和开始时间的礼拜时间才会计入。如果该小组的礼拜时间在当时都没有进行中的，则不会记录任何内容，卡片的历史记录会显示 **No scheduled service in progress — attendance not recorded**（没有进行中的已安排礼拜——未记录出勤）。
- 记录出勤后，卡片的历史记录会显示 **Attendance recorded**（已记录出勤），后面是小组名称。对同一场礼拜再次运行该操作，不会将该人员重复计算。

### 通知人员

选择 **Notify Person**，点击 **Pick person**（选择人员），并可选择输入**消息（Message）**。卡片进入该步骤时，该人员会收到一封电子邮件以及一条 B1 通知，其中包含卡片上人员的姓名、工作流和步骤名称、你的消息，以及一个用于打开卡片的链接。用它可以提前提醒工作人员或事工负责人——例如，*"当有人到达'入会面谈'步骤时，通知牧师。"*卡片的历史记录会显示 **Notified**（已通知），后面是该人员的姓名。

### 发送短信 {#sending-a-text}

选择 **Send Text**（发送短信），并输入**短信内容（Text message）**（最多 1,600 个字符）。卡片进入该步骤时，该人员会在其手机上收到这条短信。若要个性化消息，请点击消息框下方的标签——**First Name**（名字）、**Last Name**（姓氏）、**Display Name**（显示名称）或 **Church Name**（教会名称）——将 `{{firstName}}`、`{{lastName}}`、`{{displayName}}` 或 `{{churchName}}` 插入光标处。发送短信时，每个占位符都会用该人员的信息填充。

- 如果该人员没有登记手机号码，则不会发送短信，卡片的历史记录会显示 **Text skipped: no mobile phone**（已跳过短信：没有手机号码）。
- 如果该人员已选择退订，则不会发送短信，卡片的历史记录会显示 **Text skipped: opted out**（已跳过短信：已退订）。
- 短信发出后，卡片的历史记录会显示 **Text sent**（短信已发送）。如果发送失败——例如未连接短信服务商，或教会的短信额度已用完——失败信息会记录在卡片的历史记录中，且该步骤中其余的操作仍会继续运行。

:::warning
短信通过你教会自己的[短信服务商](../settings/church-settings.md#texting)发送。如果未连接任何服务商，操作编辑器会提示 *"No texting provider is set up"*（尚未设置短信服务商），此时短信将无法发送。
:::

### 等待数天（培育序列）

**Wait**（等待）操作会将卡片保留你设定的天数。等待期间，卡片会显示为 **Snoozed**（已暂停）。B1 每 30 分钟检查一次已结束的等待，因此卡片会在等待结束后约半小时内重新开始。等待结束后：

1. 该步骤中**剩余的其他操作**会依次运行——因此你可以构建一个培育序列，例如 **发送电子邮件 → 等待 3 天 → 发送提醒邮件**。
2. 然后，如果该步骤设有自动流转，卡片会继续前进；否则，它会停留在该步骤，等待有人接手处理。

:::tip
在步骤的最开始放置一个**等待**操作，是在卡片呈现给志愿者之前将其"暂存"的简便方法——例如，*等待 7 天，然后由一位辅导员主动联系*。
:::

## 将人员添加为卡片

有几种方式可以将人员放到看板上：

- **从看板添加** —— 点击某个步骤列底部的 **Add Card**（添加卡片），然后选择一个人员。你也可以选择一个小组，该小组的每位成员都会被添加为卡片。
- **从人员资料添加** —— 在某人的页面上使用 **Add to Workflow**（加入工作流），将其放入某个工作流。
- **从人员搜索添加** —— 选择多个人员，然后使用批量 **Add to Workflow** 操作，一次性全部添加。
- **通过触发器自动添加** —— 当某件事发生时添加人员，例如表单提交或首次奉献（见下文[触发器](#triggers)）。

手动添加某人，或通过 **Add to workflow** 步骤操作添加，都不会让其在同一工作流中拥有第二张未关闭的卡片。如果该人员已有一张未关闭的卡片，则会被跳过（在批量添加时，只有没有卡片的人员会获得新卡片）。卡片关闭之后，你可以再次添加该人员。触发器则遵循其自身的 **Only once per person**（每人仅一次）设置。

## 操作看板 {#working-the-board}

打开工作流即可查看其看板。每张卡片会显示人员姓名、分配给的负责人，以及截止日期或状态标签（**Overdue**（已逾期）或 **Snoozed**（已暂停））。步骤列还会显示其运行的自动化操作的小标记，以及其流转规则的注释，让你一目了然地看到卡片的流转路线。

- **移动卡片** —— 随着人员的进展，将卡片从一列拖到下一列。
- **打开卡片** —— 双击卡片（或点击它）即可打开其详情抽屉，在其中可以更改步骤、重新分配、添加备注，并查看已发生的事件。

在卡片抽屉中，你可以：

- **分配（Assign）**卡片给其他人员或小组。
- **暂停（Snooze）**卡片 1 天、3 天或 1 周，以暂时隐藏其截止日期。
- **退回（Send Back）**到上一步骤，或**跳过（Skip）**到下一步骤。
- **固定负责人（Pin assignment）**——即使卡片在步骤之间移动，也保持同一负责人。默认情况下，将卡片移到新步骤时，会重新分配给该步骤的默认负责人；固定负责人则会让当前负责人在整个过程中保持责任。
- **完成（Complete）**卡片以结束它；如果该步骤配置了**结果（Outcome）**，则可以选择某个 **Outcome** 按钮（参见[流转](#routing-cards-with-outcomes-and-conditions)）。
- **移除卡片（Remove card）**——在未完成的情况下将卡片从看板上移除，例如某人被误加入时。确认后，卡片会被关闭并从所有人的列表中移除。不会运行任何结果、流转或步骤操作，其历史记录会保留，并显示 **Removed**（已移除）条目。对于[服事安排确认](#serving-assignment-confirmations)卡片，移除它同样会以相同方式关闭该请求。
- **添加备注**并查看卡片的**活动记录（Activity）**——即已运行的自动化操作日志（已发送的邮件、等待等），每项都标注了发生的日期和时间。

对于关于某个人的卡片，抽屉还会以链接形式显示该人员的手机号码和电子邮件，点击即可拨打电话或发送邮件；如果你有权查看人员，还会显示 **View profile**（查看资料）链接。卡片所分配的人员即使没有人员板块的访问权限，也可以看到电话和电子邮件。

备注会随卡片一同保存。任何能打开该卡片的人——包括被分配到该卡片的人员或小组——都可以阅读备注并添加自己的备注。无法打开该卡片的人则看不到其备注。

### 批量操作

勾选多张卡片的复选框，即可一起对它们进行操作。若要一次选中某个步骤中的所有卡片，请勾选该步骤列标题中的 **Select all**（全选）复选框；再次勾选即可取消选择。此时会出现一个工具栏，允许你对所有选中的卡片同时执行 **Complete**（完成）、**Snooze**（暂停）、**Assign**（重新分配）或 **Move to…**（移至……）其他步骤的操作。

## 使用结果与条件进行卡片流转 {#routing-cards-with-outcomes-and-conditions}

流转决定了卡片离开某个步骤后前往何处。打开步骤的编辑器，即可配置两种类型的流转。

### 结果按钮

结果是在完成该步骤卡片时，于卡片抽屉中显示的按钮。你可以提供诸如"加入了小组"或"不感兴趣"之类的选项，而不是单一的**完成**按钮。每个结果都可以：

- 将卡片发送到本工作流中的**另一个步骤**，
- 将卡片**交接**给完全不同的工作流，或
- **关闭**卡片。

这样，一个决定就能将人员引导至不同的路径。

### 自动流转（有条件）

自动流转会在卡片**进入某个步骤的那一刻**（并在其自动化操作完成之后）将卡片向前推进，无需任何人点击——前提是该人员符合一组条件。添加一条流转，选择目标步骤，并定义一个或多个**条件**（例如某人的校区、年龄或会籍状态）。文本字段可以进行精确匹配，也可以使用 **contains**（包含）、**starts with**（以……开头）或 **ends with**（以……结尾）进行匹配。没有任何条件的流转会匹配所有人。

日期条件（今天的日期、出生日期或纪念日）可以比较完整日期，也可以只比较其中的一部分——星期几、**Day of Month**（每月几号）、**Month**（月份），或经过的年数。对于人员的出生日期或纪念日，**Day of Month** 提供了相对的 **Today**（今天）选项，因此像 *Birth Date · Day of Month = Today* 这样的条件，会匹配生日为当天日期的人员。**Month** 提供 **Previous Month**（上个月）、**Current Month**（本月）和 **Next Month**（下个月）。诸如此类的相对值会按照你教会的时区计算，因此它们与教会的日历日期保持一致，而不是与服务器的时区一致。

**Giving**（奉献）条件组中有 **Lapsed regular giver**（已停止定期奉献者），用于找出过去曾定期奉献、之后却停止的人员。需设置三个数字：*在最近 **12** 周中至少奉献过 **3** 次，但最近 **3** 周没有任何奉献*（这些是默认值）。周数从今天起、按照你教会的时区向前计算，且已退款的奉献不计入。它最适用于[定时触发器](#schedule-triggers)——例如，每周运行一次的规则，将已停止定期奉献的人员加入牧养关怀跟进看板。该条件只查看奉献的日期，从不查看金额，而卡片和提醒也从不显示金额。由于它会揭示谁已停止奉献，因此只有能查看奉献的人员才能看到此选项，并可以添加、更改或移除它。

如果某条流转的条件因某种原因无法检查，则该流转视为不匹配。卡片会留在该步骤（或沿着另一条匹配的流转前进），而不会卡住。

:::info
在看板上，每个步骤列都会显示小注释，描述其流转规则——例如结果标签，或"如果匹配"后跟一个指向目标步骤或工作流的箭头。
:::

## 完全自动化的步骤 {#fully-automated-steps}

你可以让一个步骤完全自行运行，无需任何人处理。为该步骤设置其**自动化操作**，并添加一条指向下一步骤的**自动流转**（不带任何条件）。当卡片进入时，操作会运行，然后流转会立即将其推进——卡片会直接穿过该步骤。

:::tip
可以将其与**等待**结合使用：*发送欢迎邮件 → 等待 3 天 → 自动推进到"个人电话"步骤。*邮件和时间安排都由系统处理，只有到了需要人工接触的时候，志愿者才会看到这张卡片。
:::

## 触发器 {#triggers}

触发器会在某件事发生时自动将人员添加到工作流中，因此你无需手动添加卡片。在工作流看板上，点击 **Triggers**（触发器）标签页，然后点击 **Add Trigger**（添加触发器）。触发器分为两种：

### 事件触发器

当 B1 中的记录发生变化时立即触发。选择事件，然后可选择添加**条件**，使只有符合条件的人员才会被添加：

- **Person · Created / Updated**（人员 · 已创建 / 已更新）—— 例如，将会籍状态变为 *Visitor*（访客）或 *Guest*（来宾）的任何人（这是提供给自行登记人员的状态）加入工作流。
- **Donation · Created**（奉献 · 已创建）—— 例如，将首次奉献或大额奉献加入感谢工作流（可按金额、基金或方式匹配）。
- **Group · Member Joined**（小组 · 成员加入）/ **Group · Created**（小组 · 已创建）。
- **Form · Submitted**（表单 · 已提交）—— 将提交所选表单的任何人加入（非常适合"我是新朋友"或"联系"卡片）。

### 定时触发器 {#schedule-triggers}

按照一套条件，以每日、每周、每月或每年的周期重复运行。用于基于时间的外展，例如*所有今天过生日的人*（Birth Date · Day of Month = **Today**，并将月份匹配为 **Current Month**），或*每月*的探访。即使未开启 **Only once per person**，定时触发器在一个重复周期内（一天、一周、一月或一年，取决于其运行频率）也不会再次添加同一人员。

对于任何触发器，你还可以设置：

- **Starting step**（起始步骤）—— 新卡片最初落在的步骤（默认为第一个步骤）。
- **Only once per person**（每人仅一次）—— 使同一人员不会被触发器重复添加到工作流中。开启后，已在该工作流中拥有卡片的人员会被跳过。
  - **Add again after their card is closed**（卡片关闭后可再次添加）—— 在开启 **Only once per person** 时出现。勾选后，允许触发器在某人在该工作流中的先前卡片关闭后再次将其添加。同一人员在该工作流中仍然永远不会同时拥有两张未关闭的卡片。适用于可能发生多次的事件，例如回访的来宾或每年一次的流程。
- **Active**（启用）—— 无需删除即可开启或关闭触发器。

:::tip
将**Form · Submitted**（表单 · 已提交）触发器与**New Visitor Follow-up**（新访客跟进）模板搭配使用，即可将你的"联系卡"或"我是新朋友"表单转变为自动化的跟进流程。
:::

## 服事安排确认 {#serving-assignment-confirmations}

一种特殊类型的工作流，可以跟进[服事请求](./plans.md#assigning-team-members)，直到每位志愿者接受或婉拒为止。与人员不同，此看板上的每张卡片都跟踪**一个安排**——即同一计划中某一人担任某一岗位的安排。同一人在同一计划中担任两个岗位，或服事两场礼拜，都会各有一张独立的卡片。这属于选择性功能：除非你在某个计划的设置中选择了确认工作流，否则该计划不会有任何变化。

### 设置方法

1. 在 Workflows 页面，点击 **Add Workflow**，并选择 **Serving Assignment Confirmation** 模板。（或者启动一个 **Blank workflow**，并将其**工作流用途**设为 **Serving assignment confirmation**。）由于模板包含一个短信步骤，因此从模板创建需要具备发送短信的权限。
2. 检查各个步骤。该模板包含：
   - **Request and wait for response**（发出请求并等待回应）—— 通过电子邮件和短信发送服事请求，等待 2 天，发送一封提醒邮件，再等待 1 天，然后自动将卡片推进到下一步。
   - **Call volunteer about unanswered request**（致电志愿者跟进未回复的请求）—— 由人员致电志愿者的步骤，截止时间为 1 天后。请为该步骤设置**默认负责人（Default assignee）**。如果未设置，卡片会交给事工负责人；如果没有负责人，则交给事工团队。
3. 根据你教会的情况，编辑等待时间、消息和步骤。
4. 打开[计划的设置](./plans.md#plan-settings)，并在 **Confirmation workflow**（确认工作流）下选择此工作流。

这些工作流使用 **Send serving request**（发送服事请求）操作，而不是 **Send email**（发送电子邮件）和 **Send text**（发送短信）。选择 **Email**（电子邮件）或 **Text message**（短信），并可选择撰写**请求消息（Request message）**。请求内容始终包含岗位、计划、服事日期以及一个回复链接；你可以在消息中使用 `{{planName}}`、`{{positionName}}` 和 `{{serviceDate}}`。将消息留空则使用默认的请求内容。志愿者的通知偏好、短信订阅确认、你的短信服务商以及教会的邮件审批都会生效，任何被跳过或被阻止的尝试都会记录在卡片上。这些看板上**不提供** **Send email**（发送电子邮件）、**Send text**（发送短信）和 **Add to workflow**（加入工作流）操作。

确认工作流的**触发器（Triggers）**标签页会说明卡片是如何启动的，而不是提供触发器，并且这些工作流不会出现在人员的 **Add to Workflow**（加入工作流）列表中。

### 卡片如何启动和关闭

- 当你在已发布的计划上**通知（Notify）**志愿者时，卡片即会开始（参见[通知志愿者](./plans.md#notifying-volunteers)）。每个新的、未回复的安排都会获得一张卡片。保存、发布、复制或自动填充计划本身不会主动联系任何人，而处于暂定（penciled in）状态的计划则不会发送任何内容。
- 志愿者仍会收到常规的应用内提醒。电子邮件和短信的跟进则来自工作流。
- 当志愿者**接受或婉拒**时，其卡片会自动关闭，同时关闭与之关联的所有后续任务。
- 卡片抽屉会显示岗位、服事日期以及计划链接。按钮不再显示 **Complete**，而是 **Record follow-up done**（记录已完成跟进）。点击该按钮会记录某人已进行跟进，但卡片会保持开启并继续分配给该人（显示为 **Awaiting response**（等待回应）），直到志愿者回复或回复截止时间过去为止。
- 回复截止时间为该岗位所属团队服事的最后一场礼拜时间的结束时间。如果计划中没有匹配的时间，则为服事当天的结束时间。如果到那时仍无人回复，卡片会以 **Response deadline passed**（已过回复截止时间）关闭，并且会向卡片的当前负责人或事工负责人分配一项 **Review unanswered serving request**（审核未回复的服事请求）任务，以便有人决定如何补位。该安排会保持 **Unconfirmed**（未确认）状态。
- 移除安排、更改其人员、岗位或计划日期、将计划恢复为暂定状态，或将计划切换到其他确认工作流，都会关闭该卡片。已关闭的卡片永远不会因另一次 **Notify** 而重新开启；如需发送新的请求，请添加一个新的安排。

:::info
对于通过确认工作流发出的请求，[志愿者提醒](./plans.md#volunteer-reminders)只会发送给已**接受**的志愿者，因此正在等待回复的人员不会在工作流的跟进之外再收到提醒。
:::

## 我的卡片

志愿者和工作人员无需在每个看板中翻找自己的工作。**我的工作（My Work）**页面上的 **My Cards**（我的卡片）列表会显示所有工作流中分配给当前用户的每张卡片。若要进入该列表，请点击 Workflows 页面顶部的 **My Cards**，或在快速跳转菜单中打开 **Serving > My Work**。点击某张卡片会在"我的工作"页面上直接打开其详情面板，你可以在不离开该页面的情况下处理卡片或将其移除。如果你有权查看工作流，该面板还会提供 **Open workflow board**（打开工作流看板）链接，直达该卡片所属的看板。

## 报表

打开某个工作流，点击 **Reports**（报表），即可查看该工作流的分析数据：

- **Overdue**（已逾期）—— 超过截止日期的卡片数量。
- **Cards per Step**（每步骤卡片数）—— 目前每个步骤中的卡片数量，以柱状图显示。
- **Completed (30 days)**（已完成（30 天））—— 过去 30 天的处理量，以折线图显示。

使用这些数据可以发现瓶颈——例如，某个步骤的卡片不断堆积，始终无法推进。
