# 计划验证与志愿者通知

<div class="article-intro">

B1 Admin 会在周日前自动检查你的计划是否存在问题，包括未填补的职位、时间冲突，以及已标记该日期不可服务的志愿者。当一切正常时，你只需点击一次，即可通知全体团队。

</div>

<div class="prereqs">
<h4>开始之前</h4>

- 创建一个[服务计划](./plans.md)，并为职位分配志愿者
- 为计划添加[服务时间](./plans.md)，以便冲突检测能够检查时间重叠
- 确保志愿者已[安装 B1 App](../../b1-church/getting-started/installing-pwa.md)，以便接收推送通知

</div>

## 验证面板

每个计划都有一个**验证**面板，会在你编辑计划时自动运行。它会检查以下三项内容：

### 未填补的职位
如果某个职位需要的人数多于目前已分配的人数，验证面板会列出仍然缺少的人员，例如*“音响技术员：还需 1 人。”* 你可以一眼看出计划在活动当周之前是否已完成人员配置。

### 排班冲突
如果某位志愿者在同一计划中被分配到两个时间重叠的职位，验证面板会标记该冲突，例如*“Jane Smith：在周日礼拜期间，主领敬拜与儿童签到存在时间冲突。”* 这可以在双重排班变成周日早晨的问题之前及时发现。

### 不可排班日期
志愿者可以在 B1 App 中设置自己无法服务的日期。如果某人被分配到的计划落在其不可排班日期之内，验证面板会自动提示该冲突，方便你另外寻找替补人员。

### 跨计划冲突
验证功能还会同时检查你所有的计划。如果同一位志愿者被分配到两个时间重叠的不同计划中，例如一个运行至上午 10:30 的 9 点礼拜和一个同样运行至上午 10:30 的 10 点礼拜，B1 Admin 会将该人员标记为跨计划的双重排班。

:::tip
你无需执行任何操作即可运行验证，每当你新增或更改分配时，它都会自动更新。只需在编辑计划时留意面板即可。
:::

## 通知志愿者

计划确定后，你可以直接从验证面板一次通知所有已分配的志愿者。

1. 打开计划，滚动到**验证**面板
2. 如果有尚未通知的志愿者，你会看到一个链接，显示需要通知的人数（例如*“通知 8 位志愿者”*）
3. 点击该链接，向所有尚未收到通知的人发送推送通知
4. 志愿者会在手机上收到通知，告知他们已被排班，并提示他们确认自己的分配

:::info
只有尚未收到通知的志愿者会被纳入。如果你之后再将某人加入计划，该链接会重新出现，以便你只通知新加入的人员，而无需重复通知其他团队成员。
:::

### 设有确认流程的计划

如果计划的设置中指定了[确认流程](./workflows.md#serving-assignment-confirmations)，面板会显示*“新的请求将使用确认流程。应用内提醒仍保持开启。每个请求被接受或拒绝后，后续跟进将停止。”* 在这种情况下：

- 通知链接只统计尚未收到通知且尚未回复的志愿者。
- 点击后，系统会发送常规的应用内提醒，并在该流程的看板上为每个请求创建一张卡片。随后，流程会发送电子邮件和短信跟进，如有需要，还会将请求转交给某人进行电话联系。
- 计划必须已发布（而非暂定排期），且流程必须处于启用状态。否则，面板会显示*“无法发出请求。请检查所选流程是否已启用、计划是否已发布，然后重试。”*

:::warning
志愿者必须在主屏幕上安装 B1 App，并开启通知，才能接收推送通知。设置说明请参阅[将 B1.church 安装为应用（PWA）](../../b1-church/getting-started/installing-pwa.md)。
:::
