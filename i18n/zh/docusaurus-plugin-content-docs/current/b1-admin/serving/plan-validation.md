# 计划验证与志愿者通知

<div class="article-intro">

B1 Admin 会在周日前自动检查您的计划是否存在问题，例如未填补的职位、时间冲突，以及已设置该日期为不可用的志愿者。一切就绪后，您只需点击一次，即可通知整个团队。

</div>

<div class="prereqs">
<h4>开始之前</h4>

- 创建一个[服侍计划](./plans.md)，并为职位分配志愿者
- 为计划添加[服侍时间](./plans.md)，以便冲突检测能够检查时间重叠
- 确保志愿者已安装 B1 Mobile 应用，以便接收推送通知

</div>

## 验证面板

每个计划都有一个 **验证** 面板，它会在您编排计划时自动运行。它检查三项内容：

### 未填补的职位
如果某个职位需要的人数多于当前已分配的人数，验证面板会列出仍需要的具体人数，例如 *"音响技术员：还需 1 人。"* 您可以一眼看出计划在周日到来之前是否已完全配备人手。

### 时间冲突
如果某位志愿者被分配到同一计划中两个时间重叠的职位，验证面板会标记该冲突，例如 *"Jane Smith：敬拜领导与儿童签到在周日礼拜期间时间冲突。"* 这可以在变成周日早晨的问题之前，发现重复排班。

### 不可用日期
志愿者可以在 B1 Mobile 中设置自己无法服侍的日期。如果某人被分配到的计划落在其不可用日期之内，验证面板会自动显示该冲突，以便您找到替代人选。

### 跨计划冲突
验证还会同时检查您所有的计划。如果同一位志愿者被分配到两个时间重叠的不同计划中，例如一个上午 9 点和一个上午 10 点的礼拜，且都持续到上午 10:30，B1 Admin 会将该人员标记为跨计划重复排班。

:::tip
您无需做任何操作即可运行验证，每次添加或更改分配时它都会自动更新。编排计划时只需留意面板即可。
:::

## 通知志愿者

计划设置完成后，您可以直接从验证面板一次性通知所有已分配的志愿者。

1. 打开计划，滚动到 **验证** 面板
2. 如果有尚未收到通知的志愿者，您会看到一个链接，显示需要通知的人数（例如 *"通知 8 位志愿者"*）
3. 点击该链接，向所有尚未收到通知的人发送推送通知
4. 志愿者会在手机上收到通知，告知他们已被排班，并提示他们确认自己的分配

:::info
只有尚未收到通知的志愿者会被包括在内。如果您之后将某人添加到计划中，该链接会再次出现，以便您只通知新增的人员，而无需重新通知整个团队。
:::

### 使用确认工作流的计划

如果计划的设置中指定了[确认工作流](./workflows.md#serving-assignment-confirmations)，面板会显示 *"新请求将使用确认工作流。应用内提醒保持开启。后续跟进将在每个请求被接受或拒绝后停止。"* 在这种情况下：

- 通知链接只计算尚未收到通知且尚未回复的志愿者。
- 点击后会发送常规的应用内提醒，并在工作流的看板上为每个请求创建一张卡片。随后，工作流会发送电子邮件和短信跟进，并在需要时将请求交给某人去电话联系。
- 计划必须已发布（而非暂存），且工作流必须处于启用状态。否则，面板会显示 *"无法发出请求。请检查所选工作流是否已启用、计划是否已发布，然后重试。"*

:::warning
志愿者必须安装 B1.church 移动体验（主屏幕上的 PWA，或仍在使用的用户可使用已弃用的 B1 Mobile 原生应用），并开启通知，才能接收推送通知。设置说明请参阅[安装为应用（PWA）](/docs/b1-church/getting-started/installing-pwa)。
:::
