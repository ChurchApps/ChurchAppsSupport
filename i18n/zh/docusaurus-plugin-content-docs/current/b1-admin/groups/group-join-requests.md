# 团队加入请求

<div class="article-intro">

当团队配置为基于批准的加入政策时,人员可以提交加入请求。团队领袖和管理员审查这些请求并批准或拒绝。这使您的教会可以控制团队成员身份,同时使人们可以轻松表达加入的兴趣。

</div>

<div class="prereqs">
<h4>开始之前</h4>

- 您需要管理团队的权限,或您需要是特定团队的领袖。有关详细信息,请参阅[角色和权限](../people/roles-permissions.md)。
- 该团队必须将其加入政策设置为**请求**(需要批准)。有关如何配置加入政策,请参阅[创建团队](./creating-groups.md)。

</div>

## 了解加入政策

团队可以有三种不同的加入政策:

- **开放** - 任何人都可以立即加入,无需批准
- **请求** - 人员提交需要批准的加入请求
- **关闭** - 没有人可以请求加入(成员必须手动添加)

当团队使用**请求**政策时,所有加入尝试都会通过本页描述的批准工作流程。

## 查看待处理请求

### 对于团队领袖

1. 导航到B1 Admin中的**团队**
2. 单击团队名称
3. 本团队的待处理请求出现在**成员**选项卡的顶部

### 对于管理员

具有团队管理权限的管理员可以查看所有团队的待处理请求:

1. 导航到B1 Admin中的**团队**
2. 单击页面标题中的**待处理请求**按钮(例如,"3个待处理请求")。它仅在有待处理请求时出现。
3. 审查所有教会范围内的待处理请求

## 审查加入请求

每个加入请求显示:

- **人员名称和照片** - 请求加入的人员
- **可选消息** - 解释他们想要加入原因的个人消息(如果提供)
- **请求日期** - 提交请求的时间

要审查请求:

1. 阅读该人的消息(如果他们提供了消息)
2. 单击人员名称查看他们的个人资料(如果需要)
3. 决定是批准还是拒绝

## 批准请求

1. 在加入请求中单击**批准**
2. 该人立即被添加到团队作为成员
3. 请求者收到通知,其请求已被批准
4. 请求在系统中标记为已批准

:::tip
当您批准请求时,该人成为常规团队成员。如果需要,您可以稍后从[团队成员](./group-members.md)页面将其提升为团队领袖。
:::

## 拒绝请求

1. 在加入请求中单击**拒绝**
2. 可选择提供拒绝原因(最多500个字符)
3. 单击**确认**
4. 请求者收到通知,包括您的拒绝原因(如果提供)
5. 请求在系统中标记为已拒绝

:::info
提供拒绝原因可以帮助人员了解为什么他们的请求未被批准,并可能会促使他们稍后再次尝试或探索其他团队。
:::

## 从任务页面批准

每个加入请求也在**服事→我的工作**下创建任务,标题为"*人员*请求加入*团队*"。它被分配给团队的领袖。如果团队没有领袖,它将发送给任何具有**团队成员>编辑**权限的员工,或如果没有人具有该权限,则发送给教会的域名管理员。以这种方式获取任务的员工和管理员也会收到直接链接到它的通知。

打开任务显示请求者的名称、团队和其可选消息,以及任务卡上的**批准**和**拒绝**按钮(拒绝打开上述相同的可选原因字段)。这使领袖可以获得第二种、通知驱动的方式来处理请求,而无需导航到团队的加入请求选项卡。

从任一位置决定请求 - 团队的加入请求选项卡或其任务卡 - 在所有地方都会关闭它,因此领袖永远不会看到已由某人处理的请求的陈旧任务。

## 通知

加入请求系统自动发送通知:

- **提交请求时** - 所有团队领袖都会收到通知。如果团队没有领袖,分配给任务的员工或管理员会收到通知(见上)。
- **请求被批准时** - 请求者收到确认
- **请求被拒绝时** - 请求者收到通知,包括任何拒绝原因

通知出现在用户在B1.church上的通知中心和移动应用中。

## 从成员端管理请求

人员可以从B1.church管理自己的加入请求:

- 在团队详细信息页面上查看其待处理请求的状态
- 如果他们改变主意,取消待处理请求
- 查看其请求是否被批准或拒绝

## 最佳实践

- **及时回应** - 尽量在24-48小时内审查请求,以便人们不会被搁置
- **拒绝原因明确** - 帮助人员理解后续步骤或替代选项
- **检查个人资料** - 查看人员的个人资料,了解他们是否适合该团队
- **沟通期望** - 确保您的团队描述清楚说明团队是为谁而设的
