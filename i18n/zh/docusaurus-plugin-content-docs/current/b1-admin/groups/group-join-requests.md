# 小组加入请求

<div class="article-intro">

当组配置为基于批准的加入政策时，人员可以提交加入请求。组领导者和管理员查看这些请求并批准或拒绝它们。这给您的教会对组成员关系的控制，同时使人们容易表达对加入的兴趣。

</div>

<div class="prereqs">
<h4>开始之前</h4>

- 您需要权限来管理组，或者您需要是特定组的领导者。有关详细信息，请参阅[角色和权限](../people/roles-permissions.md)。
- 组必须将其加入政策设置为**请求**（需要批准）。有关如何配置加入政策，请参阅[创建组](./creating-groups.md)。

</div>

## 了解加入政策

组可以有三个不同的加入政策：

- **开放** -- 任何人都可以立即加入而无需批准
- **请求** -- 人员提交需要批准的加入请求
- **关闭** -- 没有人可以请求加入（成员必须手动添加）

当组使用**请求**政策时，所有加入尝试都会经历本页描述的批准工作流程。

## 查看待处理请求

### 对于组领导者

1. 在 B1 Admin 中，打开 [Jump 菜单](../introduction.md#getting-around-with-the-jump-menu)并选择**人员 > 组**
2. 点击组名称
3. 此组的待处理请求出现在**成员**选项卡的顶部

### 对于管理员

具有组管理权限的管理员可以查看所有组的待处理请求：

1. 在 Jump 菜单中，选择**人员 > 组**
2. 点击页面标题中的**待处理请求**按钮（例如，"3 个待处理请求"）。仅当有请求在等待时才出现。
3. 查看所有待处理的全教会请求

## 查看加入请求

每个加入请求显示：

- **人员的名称和照片** -- 要求加入的人员
- **可选消息** -- 个人消息解释为什么他们想加入（如果提供）
- **请求日期** -- 提交请求的时间

要查看请求：

1. 阅读人员的消息（如果他们提供了）
2. 点击人员的名称来查看他们的资料（如果需要）
3. 决定是否批准或拒绝

## 批准请求

1. 点击加入请求上的**批准**
2. 该人员立即作为成员添加到组
3. 请求者收到其请求被批准的通知
4. 请求在系统中标记为已批准

:::tip
当您批准请求时，人员成为常规组成员。您可以稍后从[组成员](./group-members.md)页面将其提升为组领导者。
:::

## 拒绝请求

1. 点击加入请求上的**拒绝**
2. 或者提供拒绝的原因（最多 500 个字符）
3. 点击**确认**
4. 请求者收到包含您的拒绝原因的通知（如果提供）
5. 请求在系统中标记为已拒绝

:::info
提供拒绝原因帮助人员了解为什么他们的请求未被批准，并可能鼓励他们稍后再试或探索其他组。
:::

## 从任务页面批准

每个加入请求也在**服务 → 我的工作**下创建一个任务，标题为"*人员*请求加入*组*。"它被分配给组的领导者。如果组还没有领导者，它会转到任何具有**组成员 > 编辑**权限的员工，或如果没有人有该权限，您的教会的域管理员。以这种方式获得任务的员工和管理员也会收到一个链接直接指向它的通知。

打开任务显示请求者的名称、组和其可选消息，右侧有**批准**和**拒绝**按钮（拒绝打开上面描述的相同可选原因字段）。这给领导者第二种、以通知驱动的方式来对请求进行操作，而无需导航到组的加入请求选项卡。

从任何地方决定请求——组的加入请求选项卡或其任务卡——在各处关闭它，所以领导者永远不会看到某人已经处理的请求的陈旧任务。

## 通知

加入请求系统自动发送通知：

- **当提交请求时** -- 所有组领导者收到通知。如果组没有领导者，分配的员工或管理员会代替收到通知（见上文）。
- **当请求被批准时** -- 请求者收到确认
- **当请求被拒绝时** -- 请求者收到包含任何拒绝原因的通知

通知显示在用户的 B1.church 和移动应用中的通知中心。

## 从成员端管理请求

人员可以从 B1.church 管理他们自己的加入请求：

- 在组详情页面上查看他们待处理请求的状态
- 如果他们改变主意，取消待处理请求
- 查看其请求是否被批准或拒绝

## 最佳实践

- **及时回应** -- 尝试在 24-48 小时内查看请求，以便人员不会被迫等待
- **在拒绝原因中要清楚** -- 帮助人员了解下一步或替代选择
- **检查个人资料** -- 查看人员的个人资料以查看他们是否适合组
- **沟通期望** -- 确保您的组描述清楚说明组是为谁的
