# 小组加入申请

<div class="article-intro">

当小组设置了基于审批的加入政策时，人员可以提交加入申请。小组负责人和管理员会审阅这些申请，并予以批准或拒绝。这让教会能够掌控小组成员资格，同时也便于人们表达加入的意愿。

</div>

<h4>开始之前</h4>

- 该小组的加入政策必须设为 **Request**（申请，需要审批）。关于如何配置加入政策，请参见[创建小组](./creating-groups.md)。

## 了解加入政策 {#understanding-join-policies}

小组可以设置三种不同的加入政策：

- **Open**（开放）——任何人无需审批即可立即加入
- **Request**（申请）——人员提交需要审批的加入申请
- **Closed**（关闭）——任何人都无法申请加入（成员必须手动添加）

当小组采用 **Request** 政策时，所有加入尝试都会经过本页所述的审批流程。

## 查看待处理的申请 {#viewing-pending-requests}

### 对于小组负责人 {#for-group-leaders}

1. 在 B1 Admin 中，打开[跳转菜单](../introduction.md#getting-around-with-the-jump-menu)，选择 **People > Groups**
2. 点击小组名称
3. **Members**（成员）板块会显示待处理的申请数量（例如"1 pending"）。点击 **All members**（所有成员）——该小组待处理的申请会显示在成员列表顶部的 **Pending Requests**（待处理申请）下方

### 对于管理员 {#for-administrators}

拥有小组管理权限的管理员可以查看所有小组的待处理申请：

1. 在跳转菜单中，选择 **People > Groups**
2. 点击页眉中的 **pending requests**（待处理申请）按钮（例如"3 pending requests"）。只有存在等待处理的申请时，该按钮才会出现。
3. **Pending Join Requests**（待处理的加入申请）页面会列出全教会所有待处理的申请，每个人的姓名旁边显示其申请加入的小组。点击页面顶部的 **Groups** 即可返回。当没有待处理的申请时，页面会显示 **No pending requests.**（没有待处理的申请。）

## 审阅加入申请 {#reviewing-a-join-request}

每个加入申请会显示：

- **人员的姓名和照片**——申请加入的人员（在全教会页面上，还会显示小组）
- **可选留言**——说明其想加入原因的个人留言（如果提供了）
- **申请日期**——申请提交的时间

审阅申请的步骤：

1. 如果对方提供了留言，请阅读该留言
2. 如有需要，点击人员姓名打开其个人资料
3. 决定批准还是拒绝

## 批准申请 {#approving-a-request}

1. 点击加入申请上的 **Approve**（批准）
2. 该人员会立即作为成员被加入小组，申请也会从列表中消失
3. 申请人会收到其申请已获批准的通知
4. 系统中该申请会被标记为已批准

:::tip
批准申请后，该人员即成为普通的小组成员。如有需要，你之后可以在[小组成员](./group-members.md)页面将其提升为小组负责人。
:::

## 拒绝申请 {#declining-a-request}

1. 点击加入申请上的 **Decline**（拒绝）
2. 在 **Decline Request**（拒绝申请）对话框中，可选择填写 **Reason (optional)**（原因（可选））（最多 500 个字符）
3. 点击 **Decline**
4. 申请人会收到一条通知，其中包含你填写的拒绝原因（如果提供了）
5. 系统中该申请会被标记为已拒绝

:::info
提供拒绝原因有助于人员理解其申请未获批准的原因，并可能鼓励他们日后再次尝试或探索其他小组。
:::

## 在任务页面中批准 {#approving-from-the-tasks-page}

每个加入申请也会在 **Serving &rarr; My Work**（服事 &rarr; 我的工作）下创建一项任务，标题为"*人员* requested to join *小组*"（*人员*申请加入*小组*）。该任务会分配给小组的负责人。如果小组尚无负责人，则会分配给任何拥有 **Group Members &gt; Edit**（小组成员 &gt; 编辑）权限的工作人员；如果没有人拥有该权限，则分配给教会的域名管理员。以此方式收到任务的工作人员和管理员，还会收到一条直接链接到该任务的通知。

打开任务后，会显示申请人的姓名、小组及其可选留言，并在任务卡片上直接提供 **Approve**（批准）和 **Decline**（拒绝）按钮（点击 Decline 会打开上述相同的可选原因字段）。这为负责人提供了第二种由通知驱动的处理申请方式，无需打开小组的成员列表。

无论是在小组的成员列表还是在其任务卡片上处理申请，处理后都会在所有地方同步关闭，因此负责人不会看到某个已被他人处理的申请仍然显示为待办任务。

## 通知 {#notifications}

加入申请系统会自动发送通知：

- **申请提交时**——所有小组负责人都会收到通知。如果小组没有负责人，则会通知被分配该任务的工作人员或管理员（见上文）。
- **申请获批时**——申请人会收到确认通知
- **申请被拒绝时**——申请人会收到一条通知，其中包含任何拒绝原因

通知会显示在 B1.church 的用户通知中心以及移动应用中。在 B1 Admin 的通知铃铛中，点击加入申请的通知（或其 **View Details**（查看详情））会在新标签页中打开教会 B1.church 网站上的该小组。

## 从成员端管理申请 {#managing-requests-from-the-member-side}

人员可以通过 B1.church 管理自己的加入申请：

- 在小组详情页面上查看其待处理申请的状态
- 如果改变主意，可以取消待处理的申请
- 查看其申请是否已获批准或被拒绝

## 最佳实践 {#best-practices}

- **及时回复**——尽量在 24 至 48 小时内审阅申请，避免让人员久等
- **拒绝原因要清楚**——帮助人员理解下一步或其他可选择的方案
- **查看个人资料**——查看该人员的资料，判断其是否适合该小组
- **明确期望**——确保小组说明中清楚写明该小组面向哪些人
