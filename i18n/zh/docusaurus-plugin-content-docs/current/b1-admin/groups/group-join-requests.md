# 群组入组申请

<div class="article-intro">

当群组配置为需要审批的加入政策时，人们可以提交入组申请。群组领袖和管理员会审核这些申请，并予以批准或拒绝。这让您的教会能够掌控群组成员资格，同时也让人们更容易表达加入的意愿。

</div>

<div class="prereqs">
<h4>开始之前</h4>

- 您需要有管理群组的权限，或者您需要是该特定群组的领袖。详情请参见[角色与权限](../people/roles-permissions.md)。
- 群组的加入政策必须设置为 **申请**（需要审批）。有关如何配置加入政策，请参见[创建群组](./creating-groups.md)。

</div>

## 了解加入政策

群组可以设置三种不同的加入政策：

- **开放** -- 任何人无需审批即可立即加入
- **申请** -- 人们提交需要审批的入组申请
- **关闭** -- 任何人都无法申请加入（成员必须手动添加）

当群组使用 **申请** 政策时，所有加入尝试都会经过本页所述的审批流程。

## 查看待处理的申请

### 对于群组领袖

1. 在 B1 Admin 中，打开[跳转菜单](../introduction.md#getting-around-with-the-jump-menu)，选择 **人员 > 群组**
2. 点击群组名称
3. **成员** 部分会显示待处理的申请数量。点击 **所有成员** —— 该群组的待处理申请会显示在成员列表的顶部

### 对于管理员

拥有群组管理权限的管理员可以查看所有群组的待处理申请：

1. 在跳转菜单中，选择 **人员 > 群组**
2. 点击页面标题中的 **待处理申请** 按钮（例如“3 个待处理申请”）。只有在有待处理的申请时该按钮才会出现。
3. 审核全教会的所有待处理申请

## 审核入组申请

每条入组申请显示以下内容：

- **申请人的姓名和照片** -- 申请加入的人员
- **可选留言** -- 申请人说明其想加入原因的个人留言（如有提供）
- **申请日期** -- 申请提交的时间

审核申请的步骤：

1. 如果申请人提供了留言，请阅读留言
2. 如有需要，点击申请人的姓名查看其个人资料
3. 决定批准还是拒绝

## 批准申请

1. 在入组申请上点击 **批准**
2. 该人员将立即被添加到群组中，成为成员
3. 申请人会收到其申请已获批准的通知
4. 该申请在系统中被标记为已批准

:::tip
批准申请后，该人员将成为普通的群组成员。如有需要，您可以之后在[群组成员](./group-members.md)页面中将其提升为群组领袖。
:::

## 拒绝申请

1. 在入组申请上点击 **拒绝**
2. 可选：填写拒绝原因（最多 500 个字符）
3. 点击 **确认**
4. 申请人会收到一条通知，其中包含您填写的拒绝原因（如有）
5. 该申请被标记为已拒绝

:::info
提供拒绝原因有助于申请人理解其申请未获批准的原因，并可能鼓励他们日后再次尝试或探索其他群组。
:::

## 在任务页面中批准 {#approving-from-the-tasks-page}

每条入组申请还会在 **服事 &rarr; 我的工作** 下创建一个任务，标题为“*人员* 申请加入 *群组*”。该任务会分配给群组的领袖。如果群组尚无领袖，则会分配给拥有 **群组成员 &gt; 编辑** 权限的任何员工；如果没有人拥有该权限，则分配给教会的域管理员。以这种方式收到任务的员工和管理员也会收到一条通知，直接链接到该任务。

打开任务后，会显示申请人的姓名、群组和其可选留言，并且在任务卡片上直接提供 **批准** 和 **拒绝** 按钮（点击 **拒绝** 会打开上述同样的可选原因字段）。这为领袖提供了第二种由通知驱动的方式来处理申请，无需打开群组的成员列表。

无论是在群组的成员列表还是在其任务卡片中做出决定，申请都会在所有位置同时关闭，因此领袖不会看到已被处理的申请所对应的过期任务。

## 通知

入组申请系统会自动发送以下通知：

- **申请提交时** -- 所有群组领袖都会收到通知。如果群组没有领袖，则改为通知被分配任务的员工或管理员（见上文）。
- **申请获批时** -- 申请人会收到确认通知
- **申请被拒绝时** -- 申请人会收到通知，其中包含任何拒绝原因

通知会显示在 B1.church 上用户的通知中心以及移动应用中。在 B1 Admin 的通知铃铛中，点击入组申请通知（或其 **查看详情**），将在新标签页中打开您教会 B1.church 网站上的该群组。

## 从成员端管理申请

人们可以在 B1.church 上管理自己的入组申请：

- 在群组详情页面查看其待处理申请的状态
- 如果改变主意，可取消待处理的申请
- 查看其申请是否已获批准或被拒绝

## 最佳实践

- **及时回复** -- 尽量在 24 至 48 小时内审核申请，避免让人们长时间等待
- **拒绝原因要清晰** -- 帮助人们了解下一步或其他可选方案
- **查看个人资料** -- 查看该人员的个人资料，判断其是否适合该群组
- **明确期望** -- 确保您的群组描述清楚地说明该群组面向哪些人
