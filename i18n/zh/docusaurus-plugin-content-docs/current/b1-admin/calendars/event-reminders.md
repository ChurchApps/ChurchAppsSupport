# 事件提醒

<div class="article-intro">

事件提醒会在事件发生前自动通知正确的人 — 例如，"不要错过！医疗保健讲座明天上午 9:00 开始。" 您在事件上配置一次提醒，B1 会根据时间表通过推送通知和电子邮件发送。成员可以从他们自己的[通知首选项](../../b1-church/getting-started/notification-preferences)中控制他们接收的提醒。

</div>

<div class="prereqs">
<h4>开始之前</h4>

- 创建要提醒人们的事件（参见[创建日历](creating-calendars)）
- 要到达注册的与会者，[在事件上启用注册](creating-calendars)
- 要到达整个小组，确保事件属于具有成员的[小组](../groups/creating-groups)

</div>

## 设置提醒

您在事件的**提醒**部分配置提醒。

- 当您**创建新事件**时，在保存前在事件编辑器中展开**提醒**部分。
- 对于**现有事件**，打开事件的**注册详情**页面（从**注册**部分）以添加或更改其提醒。

1. 打开**启用提醒**。
2. 选择**何时**发送。选择最多三个时间：**7 天前**、**3 天前**、**1 天前**和**当天**。
3. 设置提醒应该发出的**时间**（默认为**上午 9:00**，在您的教会的当地时区）。
4. 选择**谁**应该被提醒（参见下面的[谁被提醒](#谁被提醒)）。
5. 可选地添加**消息**。留空以使用默认措辞，或写您自己的 — 您可以包含`{{eventTitle}}`它会被替换为事件的名称。
6. 选择**频道**：**推送**通知、**电子邮件**或两者。
7. 保存事件。

当您进行更改时，**实时预览**会显示大约有多少人会被提醒、有多少与会者无法到达以及下一个计划的发送时间 — 因此您可以在保存前确认提醒看起来正确。

## 谁被提醒

**谁**设置控制提醒的去向：

- **仅注册人** — 为事件注册的每个链接到人员记录的人。这是当事件启用了注册时的默认值，因此小型注册事件的提醒永远不会意外转到整个小组。
- **仅主要人员/注册人** — 每个注册一个提醒（注册的人），而不是注册上的每个家庭成员。
- **小组成员** — 事件小组中的每个人。这是当事件不使用注册时的默认值。
- **自动** — 启用注册时使用注册人，否则使用小组。

:::info
仅按名称添加的访客（没有链接的人员记录）无法接收提醒，因为没有帐户、设备或电子邮件可发送到。预览告诉您有多少与会者属于这个组别，因此没有惊喜。已选择退出通信的成员也会被跳过。
:::

## 何时发送提醒

- 提醒在您选择的**时间**（在您的教会的当地时区）触发，在您选择的每个偏移上。
- 如果您**更改事件的日期或时间**，待处理的提醒会自动重新安排 — 您不需要编辑提醒。
- 如果您**删除事件**（或取消定期事件的单个发生），其待处理的提醒会自动取消。
- 定期事件会自动处理：每个即将到来的发生都会获得自己的提醒。

:::tip
提醒是**首先推送，以电子邮件为后备**发送的。如果成员启用了推送通知，他们会得到推送；如果没有，他们会得到电子邮件。成员在他们的[通知首选项](../../b1-church/getting-started/notification-preferences)中按通知类型选择他们想要的频道。
:::

## 成员可以控制什么

提醒始终遵守每个成员的[通知首选项](../../b1-church/getting-started/notification-preferences)。成员可以：

- 关闭推送或电子邮件的**事件提醒**，同时保持其他通知开启。
- 设置**安静时间**，以便非紧急通知等待合理的时间。

您无法覆盖成员选择退出事件提醒的选择 — 这使 B1 符合反垃圾邮件规则并让成员控制其收件箱。

## 服务提醒

计划上安排的志愿者会收到单独的**服务提醒**，其中包含计划详情以及当他们还没有回应时的**接受/拒绝**按钮直接在电子邮件中。这些提醒是在计划类型而不是日历事件上配置的 — 有关志愿者安排和提醒的工作原理，请参见[周日志愿者](../guides/sunday-volunteers)。
