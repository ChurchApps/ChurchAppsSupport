# 付费注册

<div class="article-intro">

事件注册可以超越简单的头数计算。您可以定义定价的参与者类型（如成人和儿童），提供可选的附加功能及其自己的价格和数量，创建折扣代码，并通过教会现有的捐献提供商在注册时收集付款。当事件满满时，可选的等待列表会让感兴趣的成员排队，并在位置开放时自动提升他们。

</div>

<div class="prereqs">
<h4>开始之前</h4>

- 首先在事件上启用注册 -- 参见[创建日历](creating-calendars#enabling-event-registration)
- 要收集付款，您的教会需要[配置在线捐献](../donations/online-giving-setup.md)（Stripe、PayPal或Kingdom Funding）。免费事件不需要捐献设置。

</div>

## 打开注册设置

1. 在B1 Admin中，打开[Jump菜单](../introduction.md#getting-around-with-the-jump-menu)（左上角的搜索栏），选择**日历 > 注册**，并打开您的事件（或从其日历打开事件）。
2. **注册设置**卡片显示基础知识 -- **启用注册**、**容量**、**注册打开/关闭**、**标签**和**注册问题**。
3. 基础知识下面有三个折叠项：**参与者类型**、**选择**和**折扣代码**。

## 参与者类型

参与者类型让您对不同类型的参与者收取不同的价格 -- 并分别限制每一个。

1. 展开**参与者类型**折叠项并点击**添加类型**。
2. 输入**名称**（例如"成人"、"儿童"、"学生"）。
3. 设置**价格**。对于免费类型使用0。
4. 可选地为此类型设置**容量**（例如仅20个儿童位置）。留空表示无每类型限制。
5. 点击**保存**。

在注册期间，每个参与者选择一个类型；售罄的类型显示为**已售罄**并无法选择。花名册显示每个参与者的类型和按类型运行的计数。

## 选择

选择是可选的定价附加功能 -- T恤、膳食计划、活动升级。

1. 展开**选择**折叠项并点击**添加选择**。
2. 输入**名称**、可选的**描述**和**价格**（0显示为"免费"）。
3. 可选地设置**容量**（所有注册中可用的总数）和**最大数量**（一个注册可以订购的最多数量）。
4. 点击**保存**。

申请人在注册期间选择数量，总数计入容量，因此您永远不会超卖。

## 折扣代码

1. 展开**折扣代码**折叠项并点击**添加折扣代码**。
2. 输入申请人将输入的**代码**。
3. 选择**类型** -- **百分比**或**金额** -- 及其**值**。
4. 可选地使用**开始日期** / **结束日期**、**最小成员**（注册上的最少参与者数）和**最大使用次数**来限制代码。
5. 点击**保存**。

每个代码显示**使用**计数，以便您可以看到它被赎回的频率。申请人在应用代码时获得即时反馈 -- 包括代码已过期、尚未开始或需要更多参与者时的清晰消息。

## 等待列表

在注册设置卡片中打开**启用等待列表**。当事件达到容量时：

- 新申请人被提供等待列表位置而不是被拒绝。他们完成相同的注册（付款在等待列表时被跳过）。
- 当有人取消时，最旧的等待列表注册被**自动提升**并收到位置开放的电子邮件。如果他们还欠余额，电子邮件链接他们完成付款。
- 您可以随时使用等待列表行上的**提升**操作手动提升某人 -- 在提高事件容量后很有用。

:::info
提升的注册保持*待处理*状态，直到任何余额被支付；支付（或没有支付）确认他们。
:::

## 注册花名册

从注册页面打开事件以查看每个注册。表格显示**名称**、**成员**、**类型**（每个参与者的类型）、**已付/总计**（当仍然欠款时的余额警告）、**状态**和**日期**，以及表格上方的按类型计数芯片。

- 单击行的详情图标以打开**注册详情**对话框 -- 成员、选择、已付/余额和**付款**表格列出每笔费用（金额、方法、日期）。
- **导出CSV**下载完整花名册，其列包括成员、参与者类型、选择、已付/总计/余额、状态和每个注册问题一列。
- **添加参与者**仍然让您手动记录在线下注册。

:::info
退款不在B1内处理。如果您需要退款取消的付费注册，从您的捐献提供商的仪表板发布退款（例如Stripe）。
:::

## 付款如何工作

付款通过教会已用于捐献的相同捐献网关运行 -- 卡片详情直接转到提供商，永远不会接触B1的服务器。价格始终从您配置的类型、选择和折扣代码从服务器计算，因此申请人无法篡改总额。已登录的成员可以使用保存的卡支付；访客在结账时输入卡。
