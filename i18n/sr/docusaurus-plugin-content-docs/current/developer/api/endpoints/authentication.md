# Аутентификација и дозволе

<div class="article-intro">

ChurchApps API користи аутентификацију засновану на JWT-у. Корисници се пријављују и добијају токен који садржи њихов идентитет, чланство у цркви и дозволе. Ова страница описује ток аутентификације, модел дозвола и подршку за OAuth.

</div>

## Ток пријављивања

### Стандардна пријава

```
POST /membership/users/login
```

**Аутентификација:** Јавна

Прихвата један од три типа акредитива:

| Поље | Опис |
|-------|-------------|
| `email` + `password` | Стандардна пријава имејлом и лозинком |
| `jwt` | Поновна аутентификација постојећим JWT-ом |
| `authGuid` | Једнократни линк за аутентификацију (користи се у порукама добродошлице и поновног постављања лозинке) |

**Одговор:**

```json
{
  "user": {
    "id": "abc-123",
    "firstName": "Jane",
    "lastName": "Doe",
    "email": "jane@example.com"
  },
  "churches": [
    {
      "church": { "id": "church-1", "name": "First Church", "subDomain": "firstchurch" },
      "person": { "id": "person-1", "membershipStatus": "Member" },
      "groups": [{ "id": "group-1", "name": "Choir", "leader": false }],
      "apis": [
        {
          "keyName": "MembershipApi",
          "permissions": [
            { "contentType": "People", "action": "View" },
            { "contentType": "People", "action": "Edit" }
          ]
        }
      ]
    }
  ],
  "token": "<jwt-token>"
}
```

Поље `token` је JWT који треба слати као `Authorization: Bearer <token>` у наредним захтевима.

### Двофакторна пријава

Корисници могу да укључе двофакторну пријаву помоћу апликације за аутентификацију (TOTP). За те кориснике, пријава помоћу `email` + `password`, `authGuid` или SSO-а не враћа токен. Уместо тога, враћа изазов:

```json
{ "mfaRequired": true, "mfaToken": "<challenge-token>" }
```

Токен изазова важи 5 минута. Пошаљите га назад на исту крајњу тачку заједно са кодом:

```json
{ "mfaToken": "<challenge-token>", "mfaCode": "123456" }
```

`mfaCode` може бити тренутни шестоцифрени код из апликације за аутентификацију или један од корисникових десет резервних кодова за једнократну употребу. Погрешан код враћа `Invalid code`, а поновљени неуспешни покушаји ограничени су по налогу. Поновна пријава помоћу `jwt`-а never се не проверава двофакторно, па постојеће сесије и даље могу да се освежавају. Објекат `user` у одговору на пријаву садржи поље `mfaEnabled`.

Крајње тачке за самопослуживање (само за пријављеног корисника, под `/membership/users/mfa`):

| Крајња тачка | Опис |
|----------|-------------|
| `GET /status` | `{ enabled, backupCodesLeft }` |
| `POST /setup` | Покреће подешавање; враћа `{ secret, otpauthUrl }` за QR код |
| `POST /enable` | Тело `{ code }`; укључује двофакторну пријаву и враћа `{ backupCodes }` само једном |
| `POST /disable` | Тело `{ code }` (код из апликације или резервни код); искључује двофакторну пријаву |
| `POST /reset/:userId` | Само Server.Admin; искључује двофакторну пријаву за другог корисника |

Тајни кодови се чувају шифровано, а резервни кодови се чувају као хеш-вредности. Укључивање, искључивање и ресетовање се бележе у дневник ревизије.

### Садржај токена

JWT садржи:
- `id` — ID корисника
- `churchId` — Тренутно изабрана црква
- `personId` — Запис особе за изабрану цркву
- Низове дозвола по сваком API-ју

### Избор цркве

Корисници могу да припадају већем броју цркава. Одговор на пријаву укључује све цркве са њиховим дозволама. Да бисте променили цркву, клијент генерише нови JWT ограничен на другу цркву из података одговора на пријаву.

## Регистрација корисника

### Регистрација новог корисника

```
POST /membership/users/register
```

**Аутентификација:** Јавна

```json
{
  "email": "jane@example.com",
  "firstName": "Jane",
  "lastName": "Doe",
  "appName": "B1 Admin",
  "appUrl": "https://app.b1.church"
}
```

Креира корисника са привременом лозинком и шаље поруку добродошлице са линком за аутентификацију. Први корисник регистрован на новој инстанци аутоматски добија приступ администратора сервера.

Прихватају се два опциона поља за замку за роботе: `website` (скривено поље-мамац које стварни корисници остављају празно) и `fillMs` (колико дуго је образац био отворен, у милисекундама). Ако је поље `website` попуњено или је `fillMs` мањи од 2000, налог се не креира, али крајња тачка и даље враћа уобичајен одговор `200`, тако да роботи не могу да знају да су одбијени. Клијенти који изостављају оба поља региструју се као обично.

### Регистрација нове цркве

```
POST /membership/churches/add
```

**Аутентификација:** JWT

Након регистрације корисника, позовите ову крајњу тачку да бисте креирали цркву и повезали корисника с њом.

## Управљање лозинкама

| Метода | Путања | Аутентификација | Опис |
|--------|------|------|-------------|
| POST | `/membership/users/forgot` | Јавна | Шаље имејл за ресетовање лозинке. Тело: `{ "userEmail": "...", "appName": "...", "appUrl": "..." }` |
| POST | `/membership/users/setPasswordGuid` | Јавна | Поставља нову лозинку помоћу auth GUID-а из имејла за ресетовање. Тело: `{ "authGuid": "...", "newPassword": "..." }` |
| POST | `/membership/users/updatePassword` | JWT | Мења лозинку тренутног корисника. Тело: `{ "newPassword": "..." }` |

## Модел дозвола

Дозволе су организоване по модулима и додељују се корисницима преко улога. Свака дозвола има **тип садржаја** и **радњу**.

### Преглед дозвола

| Одељак | Тип садржаја | Радња | Опис |
|----------------|--------------|--------|-------------|
| **Присуство** | Attendance | Checkin | Пријава чланова на богослужењима |
| | Attendance | Edit | Измена записа о присуству |
| | Services | Edit | Управљање богослужењима и терминима |
| | Attendance | View | Приказ записа о присуству |
| | Attendance | View Summary | Приказ сажетака и извештаја о присуству |
| **Прилози** | Donations | Edit | Креирање и измена записа о прилозима |
| | Settings | Edit | Измена подешавања давања и плаћања |
| | Donations | View Summary | Приказ извештаја са сажетком прилога |
| | Donations | View | Приказ појединачних записа о прилозима |
| **Особе и групе** | Forms | Admin | Потпуно администрирање образаца |
| | Forms | Edit | Измена дефиниција образаца |
| | Plans | Edit | Измена планова служби |
| | Group Members | Edit | Додавање и уклањање чланова групе |
| | Groups | Edit | Креирање и измена група |
| | Households | Edit | Измена додела домаћинстава |
| | People | Edit | Измена било ког записа особе |
| | People | Edit Self | Измена само сопственог записа особе |
| | Roles | Edit | Управљање улогама и додељивањем корисника |
| | Group Members | View | Приказ списка чланова групе |
| | People | View Members | Приказ само чланова (не посетилаца) |
| | People | View | Приказ свих особа |
| | Roles | View | Приказ улога и додела |
| | Settings | Edit | Измена подешавања цркве |
| **Садржај** | Content | Edit | Измена страница, одељака и елемената |
| | Settings | Edit | Измена подешавања садржаја |
| | StreamingServices | Edit | Управљање конфигурацијом стриминг услуга |
| | Chat | Host | Вођење и модерирање сесија ћаскања |
| **Поруке** | Texting | Send | Слање SMS порука |

### Како се провераваju дозволе

У контролерима се дозволе проверавају помоћу методе `au.checkAccess()`:

```typescript
// Захтевај одређену дозволу
if (!au.checkAccess(Permissions.people.edit)) return this.json({}, 401);

// Или унутар actionWrapper-а — CRUD систем проверава аутоматски
crudSettings: {
  permissions: {
    view: Permissions.people.view,
    edit: Permissions.people.edit
  }
}
```

### Администратор сервера

Дозвола `Server.Admin` даје потпун приступ свим црквама. Додељује се првом регистрованом кориснику и може се доделити и другима преко улоге администратора сервера.

## OAuth 2.0

API подржава OAuth 2.0 за интеграције трећих страна. Доступне су две врсте додела.

### Ток кода за ауторизацију

1. **Ауторизација:** `POST /membership/oauth/authorize` (потребан JWT)
   - Тело: `{ "client_id": "...", "redirect_uri": "...", "response_type": "code", "scope": "...", "state": "...", "code_challenge": "...", "code_challenge_method": "S256" }`
   - `code_challenge` / `code_challenge_method` (PKCE, само `S256`) су обавезни за јавне клијенте без тајне
   - Враћа: `{ "code": "...", "state": "..." }`

2. **Размена кода за токен:** `POST /membership/oauth/token` (Јавна)
   - Тело: `{ "grant_type": "authorization_code", "code": "...", "client_id": "...", "client_secret": "...", "redirect_uri": "...", "code_verifier": "..." }`
   - Пошаљите `code_verifier` када је корак ауторизације користио `code_challenge`; јавни клијенти изостављају `client_secret`. Прихватају се тела у JSON или form-encoded формату
   - Враћа: `{ "access_token": "...", "token_type": "Bearer", "expires_in": 43200, "refresh_token": "...", "scope": "..." }`

3. **Освежавање токена:** `POST /membership/oauth/token` (Јавна)
   - Тело: `{ "grant_type": "refresh_token", "refresh_token": "...", "client_id": "...", "client_secret": "..." }`

Приступни токени истичу након **12 сати**.

### Ток кода уређаја (RFC 8628)

За уређаје без прегледача (ТВ апликације, киосци):

1. **Захтевање кода уређаја:** `POST /membership/oauth/device/authorize` (Јавна)
   - Тело: `{ "client_id": "...", "scope": "..." }`
   - Враћа: `{ "device_code": "...", "user_code": "ABCD-1234", "verification_uri": "https://app.b1.church/device", "expires_in": 900, "interval": 5 }`

2. **Корисник уноси код** на адреси за верификацију и одобрава или одбија захтев

3. **Провера за токен (polling):** `POST /membership/oauth/token` (Јавна)
   - Тело: `{ "grant_type": "urn:ietf:params:oauth:grant-type:device_code", "device_code": "...", "client_id": "..." }`
   - Враћа `authorization_pending` све док се не одобри, а затим враћа приступни токен

### Управљање OAuth клијентима

| Метода | Путања | Аутентификација | Дозвола | Опис |
|--------|------|------|------------|-------------|
| GET | `/membership/oauth/clients` | JWT | Server.Admin | Приказ свих OAuth клијената |
| GET | `/membership/oauth/clients/:id` | JWT | Server.Admin | Преузимање клијента по ID-у |
| GET | `/membership/oauth/clients/clientId/:clientId` | JWT | — | Преузимање клијента по client ID-у (тајна је скривена) |
| POST | `/membership/oauth/clients` | JWT | Server.Admin | Креирање или ажурирање клијента |
| DELETE | `/membership/oauth/clients/:id` | JWT | Server.Admin | Брисање клијента |
| POST | `/membership/oauth/register` | Јавна | — | Динамичка регистрација клијента (RFC 7591) за јавне клијенте као што су MCP конектори. Видети [Повезане апликације](../connected-apps.md#dynamic-client-registration) |

### Крајње тачке за одобравање уређаја

| Метода | Путања | Аутентификација | Опис |
|--------|------|------|-------------|
| GET | `/membership/oauth/device/pending/:userCode` | JWT | Преузимање информација о чекајућем коду уређаја за интерфејс за одобравање |
| POST | `/membership/oauth/device/approve` | JWT | Одобравање ауторизације уређаја. Тело: `{ "user_code": "...", "church_id": "..." }` |
| POST | `/membership/oauth/device/deny` | JWT | Одбијање ауторизације уређаја. Тело: `{ "user_code": "..." }` |

## Јавне и аутентификоване крајње тачке

API користи две омотачке функције које одређују захтеве за аутентификацију:

- **`actionWrapper`** — Захтева важећи JWT. Објекат аутентификованог корисника (`au`) је доступан са `churchId`, `userId` и провером дозвола.
- **`actionWrapperAnon`** — Не захтева аутентификацију. Користи се за пријаву, регистрацију, јавне садржаје и пријемнике webhook-ова.

У табелама крајњих тачака у овој документацији, ово су означене као **JWT** и **Јавна** у колони Аутентификација.
