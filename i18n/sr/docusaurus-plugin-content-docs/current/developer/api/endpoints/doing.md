# Крајње тачке за Doing

<div class="article-intro">

Модул Doing управља планирањем служби, распоредом волонтера, управљањем задацима и аутоматизацијама. Пружа алате за креирање планова служби са терминима и позицијама, додељивање волонтера, управљање датумима блокаде, састављање ставки редоследа службе, повезивање са спољним провајдерима садржаја и подешавање аутоматизованих токова рада с условима и радњама.

</div>

**Основна путања:** `/doing`

## Планови

Основна путања: `/doing/plans`

| Метод | Путања | Ауторизација | Дозвола | Опис |
|--------|------|------|------|------|
| GET | `/` | JWT | — | Листа свих планова за цркву |
| GET | `/:id` | JWT | — | Преузимање плана према ID-у |
| GET | `/ids?ids=` | JWT | — | Преузимање више планова према ID-евима раздвојеним зарезом |
| GET | `/types/:planTypeId` | JWT | — | Преузимање планова по типу плана |
| GET | `/textRange?startDate=&endDate=&ministryId=&planTypeId=` | JWT | `texting.send` + измена службе | Преглед статистике коју **Text Volunteers** шаље за волонтере додељене у опсегу: `{ totalMembers, eligibleCount, optedOutCount, noPhoneCount, capped }` (по једна особа; они који су се одјавили и они без броја се прескачу; заједнички бројеви се деdupлицирају; ограничено на 200) |
| GET | `/presenter` | JWT | — | Преузимање планова за наредних 7 дана (приказ за презентера) |
| GET | `/confirmationWorkflows?ministryId=` | JWT | Измена службе | Активни токови потврде додела служења (`workflowType = "assignmentConfirmation"`) које план може изабрати: `[{ id, name }]` |
| GET | `/public/current/:planTypeId` | Јавно | — | Преузимање тренутног плана за тип плана |
| GET | `/public/signup/:churchId` | Јавно | — | Планови отворени за самостalну пријаву, најранији први, сваки са позицијама за самопријаву (сортирано по `categoryName`, затим по `name`, плус `filledCount` додела у статусу Accepted/Unconfirmed) и терминима. Без имена волонтера. Када је подешавање цркве `volunteerSignupNextOnly` `"true"`, враћа се само први план сваког типа. Сваки `plan` укључује израчунати `signupDeadline` (ISO тренутак или `null`): `signupDeadlineHours` пре најранијег термина типа `service` плана (било који термин са временом ако нема термина службе; 9:00 у часовној зони цркве на `serviceDate` ако план нема термине) |
| GET | `/signup/:planId/volunteers` | JWT | — | `[{ positionId, names }]` за позиције самопријаве плана (приказна имена додељених особа у статусу Accepted/Unconfirmed). Враћа `[]` осим ако је `showVolunteerNames` плана укључен |
| POST | `/` | JWT | — | Креирање или ажурирање планова (прихвата један објекат или низ). Поставите `confirmationWorkflowId` да укључите план у ток потврде служења, или `null` да га искључите за будуће захтеве. Пошаљите `signupDeadlineHours: null` да уклоните рок; изостављање поља задржава сачувану вредност |
| POST | `/copy/:id` | JWT | Измена службе | Копирање плана укључујући позиције, термине, доделе и ставке редоследа службе. Тело садржи `ministryId`, `serviceDate`, `copyMode` ("none", "positions", "all") и `copyServiceOrder` (boolean). Без `targetPlanId` креира се нови план, а `notes`, `signupDeadlineHours`, `showVolunteerNames` и `autoReplaceOnDecline` преносе се из изворног плана осим ако их тело не наведе. Са `targetPlanId`, копија попуњава постојећи план (позивалац мора имати право измене над њим). Опција **Repeat weekly** у B1Admin-у позива ову функцију једном недељно, сваки пут копирајући из плана креираног претходне недеље |
| POST | `/textRange` | JWT | `texting.send` + измена службе | Пошаљите поруку сваком волонтеру додељеном у опсегу датума преко провајдера слања порука цркве. Тело: `{ startDate, endDate, ministryId, planTypeId?, message }` (порука до 1600 карактера; поља за спајање се разрешавају за сваког примаоца). Враћа бројаче прегледа плус `recipientCount`, `successCount`, `failCount` и `error` (`no_provider` или `insufficient_credits`) када слање стане рано |
| POST | `/:id/issueRequests` | JWT | Измена плана | Издаје нове доделе плана у статусу Unconfirmed које још нису обавештене, кроз његов ток потврде: означава сваку као обавештену и покреће по једну картицу тока за сваку доделу. Празно тело; враћа `{ issued }`. Не успева осим ако план није објављен (није `prepared`), има активан `confirmationWorkflowId` са најмање једним кораком и ако рок за одговор није истекао |
| POST | `/autofill/:id` | JWT | — | Аутоматско попуњавање доделa волонтера за план. Тело: `{ teams: [{ positionId, personIds }] }` |
| DELETE | `/:id` | JWT | — | Брисање плана и свих повезаних термина, додела, позиција и ставки плана |

### Пример: Копирање плана

```
POST /doing/plans/copy/abc-123
Authorization: Bearer <token>

{
  "serviceDate": "2026-03-01T10:00:00.000Z",
  "copyMode": "all",
  "copyServiceOrder": true
}
```

```json
{
  "id": "def-456",
  "churchId": "church-1",
  "serviceDate": "2026-03-01T10:00:00.000Z"
}
```

## Ауторизације провајдера садржаја

Основна путања: `/doing/contentProviderAuths`

Наслеђује CRUD основну класу (GET `/`, GET `/:id`, POST `/`, DELETE `/:id` — без провера дозвола).

Управља OAuth записима за аутентификацију за спољне провајдере садржаја (нпр. интеграције софтвера за презентације).

`accessToken` и `refreshToken` се шифрују у мировању помоћу `EncryptionHelper` и дешифрују при читању, тако да API и даље враћа обичне токене. Записи сачувани пре шифровања садрже обичан текст (који никад не садржи `|`); враћају се непромењени и шифрују се при следећем чувању.

| Метод | Путања | Ауторизација | Дозвола | Опис |
|--------|------|------|------|------|
| GET | `/` | JWT | — | Листа свих ауторизација провајдера садржаја |
