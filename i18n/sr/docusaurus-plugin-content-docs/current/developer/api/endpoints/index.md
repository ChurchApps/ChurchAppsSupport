# Референца крајњих тачака

<div class="article-intro">

Овај одељак документује све REST крајње тачке које ChurchApps API излаже. Свака страница модула наводи сваку руту са њеним HTTP методом, путањом, захтевима за аутентикацију и потребним дозволама.

</div>

## Основна URL адреса

| Окружење | URL |
|-------------|-----|
| Локално развојно окружење | `http://localhost:8084` |
| Продукција | `https://api.churchapps.org` |

## Конвенције захтева

- **Content-Type:** Сва тела захтева и одговора користе `application/json`
- **Више закупаца (multi-tenant):** Сваки аутентификовани захтев је ограничен на `churchId` извучен из JWT токена — `churchId` не прослеђујете у URL-у
- **Серијско чување:** Већина `POST` крајњих тачака прихвата **низ објеката**. API ће у једном позиву убацити нове записе (без поља `id`) и ажурирати постојеће (са пољем `id`)
- **ID-еви:** Сви ID-еви ентитета су UUID-ови

### Пример: серијско чување

```json
POST /membership/people
Authorization: Bearer <token>

[
  { "firstName": "Jane", "lastName": "Doe" },
  { "id": "abc-123", "firstName": "John", "lastName": "Smith" }
]
```

Први објекат се креира (нов); други се ажурира (има `id`).

## Формат одговора

Успешни одговори враћају JSON — или један објекат или низ. Одговори са грешкама користе стандардне HTTP статусне кодове:

| Код | Значење |
|------|---------|
| `200` | Успех |
| `400` | Неисправан захтев (грешке валидације) |
| `401` | Нема овлашћења (недостаје или је неважећи токен, или недовољне дозволе) |
| `404` | Није пронађено |
| `500` | Грешка на серверу |

Грешке валидације враћају:

```json
{
  "errors": [
    { "msg": "enter a valid email address", "param": "email", "location": "body" }
  ]
}
```

## Како читати табеле крајњих тачака

Свака страница модула организује крајње тачке по контролеру. Табеле користе следеће колоне:

| Колона | Опис |
|--------|-------------|
| **Метода** | HTTP метода (`GET`, `POST`, `DELETE`) |
| **Путања** | Путања руте у односу на основну путању контролера |
| **Аутентикација** | **JWT** = захтева Bearer токен, **Public** = аутентикација није потребна |
| **Дозвола** | Потребна дозвола (нпр. `People.Edit`). `—` значи било који аутентификовани корисник |
| **Опис** | Шта крајња тачка ради |

Контролери који наслеђују стандardnu CRUD основну класу аутоматски пружају четири крајње тачке: `GET /` (листа свих), `GET /:id` (преузимање по ID-у), `POST /` (креирање/ажурирање) и `DELETE /:id` (брисање).

## Модул за извештавање

Модул за извештавање ради другачије од осталих модула. Уместо CRUD операција заснованих на бази података, учитава дефиниције извештаја из JSON фајлова на диску и извршава параметризоване SQL упите.

| Метода | Путања | Аутентикација | Опис |
|--------|------|------|-------------|
| GET | `/reporting/reports/:keyName` | JWT | Учитава дефиницију извештаја по кључном имену |
| GET | `/reporting/reports/:keyName/run` | JWT | Извршава извештај и враћа резултате |

Параметри извештаја се прослеђују као вредности у query string-у (нпр. `?startDate=2024-01-01&endDate=2024-12-31`). Параметар `churchId` се аутоматски уноси из JWT токена. Свака дефиниција извештаја може да наведе своје захтеве за дозволе.

| [Прилози](./giving) | `/giving/*` | Донације, фондови, платни пролази, претплате |
