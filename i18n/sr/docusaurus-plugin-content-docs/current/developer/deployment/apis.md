# Распоређивање API-ја

<div class="article-intro">

ChurchApps API-ји се распоређују као AWS Lambda функције помоћу Serverless Framework-а. Ова страница описује ток изградње, распоређивања и подешавања за демо и продукционо окружење.

</div>

<div class="prereqs">
<h4>Пре почетка</h4>

- Подесите API локално -- видите [Локално подешавање API-ја](../api/local-setup)
- Конфигуришите AWS акредитиве на свом рачунару
- Уверите се да имате приступ циљаном AWS налогу

</div>

## Изградња

API-ји се граде за продукцију помоћу посебне TypeScript конфигурације:

```bash
npm run build:prod
```

Ова команда користи `tsconfig.prod.json` за компајлирање пројекта за Lambda окружење.

## Распоређивање

Распоредите у демо окружење:

```bash
npm run deploy-demo
```

Распоредите у продукцију:

```bash
npm run deploy-prod
```

У пракси, API се распоређује помоћу GitHub Actions-а: **Deploy Demo** се покреће при сваком push-у на `main`, а **Deploy Prod** се покреће ручно (workflow dispatch). Стејџинг окружење више не постоји.

## Миграције базе података

**Deploy Prod** примењује чекајуће миграције базе података као део распоређивања. Продукционе базе прихватају везе само изнутра VPC-а, па одмах после `serverless deploy` workflow позива `migrate` Lambda (`api-Prod-migrate`), која извршава чекајуће миграције сваког модула и враћа `{ ok, environment, modules }`. Ако било који модул не успе или буде одбијен (на пример база без историје миграција), посао ће пасти, тако да шема никада не заостане за кодом. **Rollback Prod** враћа само Lambda код; миграције остају примењене, зато их držite адитивним. Погледајте [Администрација сервера -- Миграције базе података](../server-admin#database-migrations) за проверу статуса или ручно покретање миграција.

## Шта се креира

Свако распоређивање API-ја креира или ажурира следеће AWS Lambda функције:

| Функција | Намена |
|----------|---------|
| `web` | Обрада HTTP захтева преко API Gateway-а |
| `socket` | Обрада WebSocket веза |
| `timer15Min` | Заказани задатак који се извршава сваких 30 минута (назив је историјски) |
| `timerMidnight` | Заказани задатак који се извршава сваки дан у поноћ |
| `migrate` | Примењује чекајуће миграције базе података; позива га workflow Deploy Prod |

## Конфигурација окружења

У распоређеним окружењима конфигурација се чита из **AWS SSM Parameter Store**-а, а не из `.env` фајлова. Тако се тајне држе ван пакета за распоређивање, а измене конфигурације су могуће без поновног распоређивања.

:::warning
Никада не комитујте продукционе акредитиве у репозиторијум. Сву осетљиву конфигурацију треба чувати у AWS SSM Parameter Store-у и читати је у време извршавања.
:::

:::tip
Свако спајање у `main` прво се распоређује у демо окружење. Проверите измену тамо (на пример на [demo.b1.church](https://demo.b1.church)) пре покретања Deploy Prod-а.
:::
