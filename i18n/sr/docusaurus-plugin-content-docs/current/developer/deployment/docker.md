# Самостално хостовање уз Docker

<div class="article-intro">

Покрените сопствену приватну инстанцу B1 Admin-а, B1 чланског портала и веб-сајта, API-ја и MySQL базе података на било ком рачунару са Docker-ом: кућном серверу, малом VPS-у или локалном серверу у просторијама. Једна команда га инсталира, једна команда га ажурира, а свако ажурирање прво прави резервну копију. Ако не желите уопште да управљате сервером, погледајте [Самостално хостовање на Railway-у](./railway-template.md) као управљану алтернативу.

</div>

## Брзи почетак

<div class="prereqs">
<h4>Шта вам је потребно</h4>

- Linux рачунар (или macOS / Windows са WSL-ом или Git Bash-ом; помоћна команда `b1` је bash скрипта) са [Docker Engine](https://docs.docker.com/engine/install/) и Compose v2 (укључен у Docker Desktop)
- Око 2 GB RAM-а и 5 GB слободног простора на диску
- За јавни сајт: домен усмерен на рачунар, са доступним портовима 80 и 443

</div>

```bash
curl -fsSL https://raw.githubusercontent.com/ChurchApps/B1Admin/main/deploy/install.sh | bash -s -- --domain church.example.org
```

Изоставите `--domain` да бисте покренули на `http://localhost`. Инсталер прави фасциклу `b1church`, уписује `.env` са новогенерисаним тајним кључевима, преузима готове слике из GitHub Container Registry-ја и чека док API не пријави да је здрав. Ништа се не прави на вашем рачунару, тако да први покретање траје минут или два.

Када заврши:

1. Отворите **https://church.example.org/admin** (или http://localhost/admin) и кликните **Register**. Први налог аутоматски постаје администратор сервера.
2. Пратите упутства у апликацији да бисте направили прву цркву. Њен веб-сајт и чланski портал су активни на **https://church.example.org/** чим се направи.

Све ради иза једног домена:

| Путања | Сервис |
|--------|--------|
| `/` | B1App — веб-сајт цркве и члански портал |
| `/admin` | B1Admin — табла за особље |
| `/api` | API, отпремљене датотеке и websocket за ажурирања уживо |

HTTPS се подешава аутоматски: уграђени [Caddy](https://caddyserver.com/) прокси добија и обнавља Let's Encrypt сертификат за домен из `.env`-а. Изложени су само портови 80 и 443; база података је доступна само унутар Docker мреже.

## Команда `b1`

Инсталер оставља скрипту `deploy/b1` поред `docker-compose.yml`. То је једина ствар која вам је свакодневно потребна:

| Команда | Шта ради |
|---------|----------|
| `./deploy/b1 upgrade` | Преузима тренутно издање, прави резервну копију, поново покреће и проверава да је API здрав |
| `./deploy/b1 upgrade 2026.10.1` | Исто, фиксирано на одређено издање |
| `./deploy/b1 backup` | Прави снимак базе, отпремљених датотека и `.env`-а у `backups/<timestamp>/` |
| `./deploy/b1 restore backups/<timestamp>` | Враћа снимак (API се зауставља док ово ради) |
| `./deploy/b1 rollback` | Враћа најновију резервну копију, укључујући издање на коме је направљена |
| `./deploy/b1 status` | Инсталирана верзија и здравље контејнера |
| `./deploy/b1 logs api` | Прати логове сервиса |

Издања се објављују као један верзионисани пакет, тако да три слике увек одговарају једна другој. `B1_VERSION=stable` у `.env`-у прати најновије издање; поставите одређену верзију да бисте је фиксирали. Напомене о издањима налазе се у [B1Admin издањима](https://github.com/ChurchApps/B1Admin/releases).

## Конфигурација

Сва подешавања су у `.env` датотеци поред `docker-compose.yml`. Инсталер попуњава обавезна:

```bash
B1_VERSION=stable
DOMAIN=church.example.org
SITE_ADDRESS=church.example.org          # what Caddy serves; http://localhost for a local install
PUBLIC_URL=https://church.example.org    # how browsers and emails reach the site
MYSQL_ROOT_PASSWORD=…                    # generated
JWT_SECRET=…                             # generated
ENCRYPTION_KEY=…                         # generated, exactly 32 characters — never change it after storing credentials

# Email — strongly recommended; without it members can't reset their own passwords
MAIL_SYSTEM=SMTP
SMTP_HOST=smtp.resend.com
SMTP_USER=resend
SMTP_PASS=re_xxxxxxxxx
SMTP_SECURE=false
SUPPORT_EMAIL=noreply@church.example.org
```

После измене `.env`-а примените је командом `docker compose up -d`. Веб-апликације сами утврђују са којим API-јем треба да комуницирају на основу адресе у прегледачу, тако да је промена домена довољна ажурирањем `SITE_ADDRESS` и `PUBLIC_URL` и поновним покретањем, без поновног прављења.

:::warning
Чувајте `.env` на сигурном. `ENCRYPTION_KEY` штити сачуване креденцијале за пролаз плаћања и складиштење; резервна копија без њега не може да их дешифрује. `./deploy/b1 backup` из тог разлога укључује копију.
:::

### Прелазак на домен касније

Ако сте инсталирали на `localhost` и касније желите јавни приступ: усмерите DNS на рачунар, подесите `DOMAIN`, `SITE_ADDRESS` (голи домен) и `PUBLIC_URL` (`https://` + домен) у `.env`-у, па `docker compose up -d`. Caddy преузима сертификат при првом захтеву.

## Е-пошта, донације, више сајтова и интеграције

Ово функционише потпуно исто као на Railway-у: исте променљиве окружења, постављене у `.env` уместо на Railway контролној табли:

- **[Е-пошта / SMTP](./railway-template.md#1-email-highly-recommended)** — водичи за провајдере Resend, Brevo и Gmail
- **[Више сајтова](./railway-template.md#3-multi-site-multiple-churches-on-one-instance)** — неограничен број цркви по инстанци. `/` служи цркву чији је slug `DEFAULT_CHURCH_SLUG` (прва црква је `church`); усмерите додатне домене на рачунар и мапирајте их под **Settings → Domains** у B1Admin-у
- **[Онлајн давање](./railway-template.md#4-online-giving-stripe--paypal)** — подешава се по цркви у административном интерфејсу
- **[Опционе интеграције](./railway-template.md#6-optional-feature-integrations)** — `OPENAI_API_KEY`, `YOUTUBE_API_KEY`, `PEXELS_KEY`, `VIMEO_TOKEN`, `API_BIBLE_KEY`, `GOOGLE_RECAPTCHA_SECRET_KEY`
- **[Push обавештења](#push-notifications)** — `WEB_PUSH_*`; инсталер оставља ова поља празна, тако да су push обавештења искључена док их не додате

Позивнице и друга е-пошта коју шаљу цркве аутоматски су омогућене на самостално хостованој инстанци. Хостована услуга их ограничава ручним прегледом ради заштите репутације пошиљаоца.

## Push обавештења

Веб push обавештења у прегледачу и на мобилном вебу остају искључена док сервер нема VAPID пар кључева. Инсталер га не прави. Док га не додате, страница Notifications мобилне веб-апликације приказује да push није укључен за сајт.

1. Генеришите пар кључева. Потребан је само Docker:

   ```bash
   docker run --rm node:lts-alpine npx --yes web-push generate-vapid-keys
   ```

2. Додајте две вредности у `.env`. `WEB_PUSH_SUBJECT` је опционалан и представља контакт адресу коју виде push сервиси:

   ```bash
   WEB_PUSH_PUBLIC_KEY=…
   WEB_PUSH_PRIVATE_KEY=…
   WEB_PUSH_SUBJECT=mailto:admin@example.org
   ```

3. Примените их:

   ```bash
   docker compose up -d
   ```

4. Да бисте потврдили, отворите **Server Admin → Server Health** у B1Admin-у. Оба Web Push кључа би требало да буду приказана као подешена. Чланови затим могу да укључе обавештења из мобилне веб-апликације.

:::warning
Задржите исте кључеве када се чланови већ пријаве. Промена поништава све постојеће претплате, и сваки уређај мора поново да се региструје.
:::

## Подаци, резервне копије и складиштење датотека

Три именована Docker волумена чувају сво стање:

| Волумен | Садржај |
|---------|---------|
| `b1church_mysql-data` | Све шеме базе података |
| `b1church_api-content` | Отпремљене датотеке: фотографије, документи, слике веб-сајта |
| `b1church_caddy-data` | TLS сертификати |

`./deploy/b1 backup` записује конзистентан снимак прва два плус `.env` у `backups/<timestamp>/`. Закажите га помоћу cron-а и копирајте фасциклу на неко место ван рачунара:

```
0 3 * * * cd /opt/b1church && ./deploy/b1 backup >> backups/backup.log 2>&1
```

За велике медијске библиотеке можете пребацити складиштење датотека на S3: поставите `FILE_STORE=S3` и `AWS_*` променљиве описане у [одељку о складиштењу датотека у водичу за Railway](./railway-template.md#5-file-storage). Резервне копије базе података не укључују S3 објекте, па тамо укључите верзионисање bucket-а.

## Ажурирање

```bash
./deploy/b1 upgrade
```

Редом: преузима издање, прави резервну копију, поново креира контејнере, извршава све чекајуће миграције базе података при покретању API-ја и чека здравствену проверу API-ја. Ако било шта не успе, зауставља се и саветује вам да покренете `./deploy/b1 rollback`, који враћа ту резервну копију и претходно издање. Миграције су само унапред; враћање уназад увек значи враћање снимка.

Ажурирање са бета compose фајла (оног који је правио слике из изворног кода) функционише исто када имате `.env`: подразумевано је користио `MYSQL_ROOT_PASSWORD=churchapps`, тако да га ставите у `.env` заједно са `PUBLIC_URL` и `SITE_ADDRESS`, замените `docker-compose.yml` и `deploy/` тренутним фајловима и покрените `./deploy/b1 upgrade`.

## Изградња из изворног кода

Програмери могу да граде слике локално уместо да их преузимају:

```bash
docker compose -f docker-compose.yml -f docker-compose.build.yml up -d --build
```

`API_CONTEXT` и `B1APP_CONTEXT` у `.env`-у усмеравају изградње на локалне копије репозиторијума (нпр. `../Api`) или на git референцу.

## Решавање проблема

| Симптом | Вероватни узрок | Решење |
|---------|-----------------|--------|
| Контејнер `api` се стално поново покреће | грешка у миграцији или погрешна лозинка базе | `./deploy/b1 logs api`: миграција исписује који модул није успео |
| API бележи "ENCRYPTION_KEY must be exactly 32 characters" | ручно измењен или скраћен кључ у `.env`-у | вратите оригинални кључ од 32 знака (генеришите нови само ако још нису сачувани креденцијали) |
| Прегледач приказује упозорење о сертификату | DNS још не показује на овај рачунар или су портови 80/443 блокирани | поправите DNS или заштитни зид; Caddy сам покушава поново |
| `/` приказује табелу уместо веб-сајта | још нема цркве или се `DEFAULT_CHURCH_SLUG` не поклапа | направите цркву или поставите slug у **Settings → Church** |
| "Check your email", али е-пошта не стиже | `MAIL_SYSTEM=SMTP` са погрешним креденцијалима | исправите креденцијале или уклоните `MAIL_SYSTEM` да бисте искључили е-пошту |
| Мобилна веб-апликација каже да push обавештења нису укључена | на серверу нема VAPID кључева | додајте их како је описано у [Push обавештења](#push-notifications) |
| Ћаскање и функције уживо не раде | websocket блокира други прокси испред | сокет је на `/api/` преко истог порта; дозволите `Upgrade` заглавља |
| `install` одбија: "database volume already exists" | остаци из ранијег инсталирања | `docker compose down -v` да обришете, или напишите `.env` и користите `upgrade` |

Још увек не можете да решите проблем? Отворите issue на [github.com/ChurchApps/ChurchAppsSupport/issues](https://github.com/ChurchApps/ChurchAppsSupport/issues) и приложите излаз команде `./deploy/b1 logs`.
