# Дељене библиотеке

<div class="article-intro">

ChurchApps дељени код се објављује на npm-у под опсегом `@churchapps/*`. Сви дељени пакети налазе се у једном репозиторијуму — [Packages](https://github.com/ChurchApps/Packages) — којим се управља као Yarn (Berry) радним простором и верзионише помоћу [changesets](https://github.com/changesets/changesets).

</div>

## Пакети

| Пакет | Опис | Користе |
|-------|------|---------|
| [`@churchapps/helpers`](./helpers) | Основни слој: помоћне функције без зависности од оквира и заједničке TypeScript интерфејсе које чине уговор о подацима између апликација | Сви пројекти |
| [`@churchapps/apihelper`](./api-helper) | Серверске Express помоћне функције: аутентификација, базни контролери, приступ бази, AWS и интеграције за е-пошту | Сви API-ји |
| [`@churchapps/apphelper`](./app-helper) | Дељене React компоненте и функционални модули (пријава, донације, обрасци, markdown, веб-сајт) | Све веб апликације |
| `@churchapps/content-providers` | Апстракција над спољним добављачима садржаја (Lessons.church, Planning Center, Dropbox и други) | Api, B1Admin, B1App, FreePlay |
| `@churchapps/integration-sdk` | Алатка за израду B1.church интеграција: верификација webhook-ова, типизирани REST клијент, OAuth помоћне функције | Спољни програмери интеграција |
| `@churchapps/texting` | Апстракција над SMS добављачима (Text In Church, Clearstream, Mutual Ministry, MinistryStuff, Nalo Solutions, Twilio) | Api |

Смер зависности је строго једносмеран: апликације зависе од `apihelper` и `apphelper`, а оба декларишу `@churchapps/helpers` као **peer dependency**, тако да свака апликација користи тачно једну копију тог пакета.

## Подешавање радног простора

```bash
git clone https://github.com/ChurchApps/Packages.git
cd Packages
yarn install
yarn build
```

Репозиторијум користи Yarn Berry (меродавно је поље `packageManager` у корену) са једном lockfile датотеком. `yarn build` гради сваки пакет редоследом по зависностима; `yarn test` покреће тестове свих пакета.

## Објављивање помоћу Changesets

Свака измена у пакету иде са changeset-ом:

1. Покрените `yarn changeset` у корену радног простора. Изаберите пакет(е) које сте мењали, врсту повећања верзије (patch = исправка, minor = нови export или функционалност, major = некомпатибилна измена) и напишите сажети опис у једној реченици — он постаје унос у CHANGELOG.
2. Комитујте генерисану датотеку `.changeset/*.md` заједно са изменом кода. Pre-commit hook блокира комитовање измена изворног кода пакета без спремљеног changeset-а.
3. Када будете спремни за објаву, покрените `yarn publish-all` у корену. Ово обрађује чекајуће changeset-ове (повећава верзије, пише CHANGELOG-ове, синхронизује опсеге интерних зависности), гради све редоследом по зависностима и објављује промењене пакете на npm. Затим комитујте и пуширајте повећања верзија.

:::warning
Никада не покрећите сирови `npm publish` унутар једног пакета — он заобилази редослед изградње и књиговодство верзија које обрађује скрипта за објаву. Објављивање захтева npm налог са правом објаве у `@churchapps` опсегу.
:::

## Локални развој уз апликацију која користи пакет

Унутар радног простора пакети се граде директно уз своје суседе, без потребе за linking-ом. Да бисте тестирали необјављену верзију пакета унутар апликације која га користи (B1Admin, B1App и др.), додајте привремени Yarn portal у тој апликацији:

```bash
# у апликацији која користи пакет
yarn link ../Packages/helpers
# ... тестирање ...
yarn unlink ../Packages/helpers && yarn install
```

Прво изградите пакет (`yarn build` у корену радног простора). Апликација чита компајлирани `dist/` излаз, а не изворни код.

:::warning
`yarn link` уписује portal резолуцију у `package.json` апликације. Никада је не комитујте. Увек покрените `yarn unlink` и поново инсталирајте када завршите.
:::
