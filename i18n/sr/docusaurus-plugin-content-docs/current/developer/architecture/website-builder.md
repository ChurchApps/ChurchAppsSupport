# Архитектура градитеља веб-сајта

<div class="article-intro">

Сваки веб-сајт цркве који опслужује B1App приказује се из стабла садржаја — страница, секција и елемената — које се чува у ContentApi и уређује визуелно у B1Admin-у. Једна заједничка библиотека компоненти приказује и преглед уређивача и живи сајт, један каталог типова елемената дефинише шта може да се појави на страници, а посебна AI услуга може да генерише или препише то стабло. Ова страница приказује читав стек: уговор о елементима у `@churchapps/helpers`, цевовод приказивања, елементе са подацима цркве, виџете за цео сајт, слој блога, странице са ограниченим приступом, SEO, AI генерисање и разговорне обрасце.

</div>

## Преглед

```
┌──────────────────────────────┐             ┌─────────────────────────────────────────┐
│  B1Admin — editor            │             │  Api — /content module (ContentApi)     │
│  ContentEditor · SectionEdit │  POST /…    │                                         │
│  ElementEdit · PageLinkEdit  │ ──────────▶ │  pages ─ sections ─ elements   blocks   │
│  SiteWidgetsEdit · Blog      │             │  posts   redirects   settings   styles  │
└──────────┬───────────────────┘             └───────────────┬─────────────────────────┘
           │                                                 │ GET /content/pages/:churchId/tree?url=…
           │        shared render pipeline                   ▼            (anon, JWT honored)
           │   ┌───────────────────────────────┐   ┌─────────────────────────────────┐
           └──▶│  @churchapps/helpers          │◀──│  B1App — public site (Next.js)  │
               │    ElementTypes.ts (catalog)  │   │  Zone → Section → Element       │
               │  @churchapps/apphelper        │   │  + widgets, JSON-LD, sitemap,   │
               │    ElementRegistry, renderers │   │    redirects, branded 404       │
               │    SectionDivider, widgets    │   └───────────────┬─────────────────┘
               └───────────────────────────────┘                   │ church-data elements
┌──────────────────────────────┐                                   ▼
│  AskApi — /website/* (AI)    │             ┌─────────────────────────────────────────┐
│  generateSite · rewriteSection│            │  /giving/funds/public/…/total           │
│  generateAltText · metaDesc  │             │  /membership/groupmembers/public/…      │
│  returns JSON; B1Admin saves │             │  /attendance/servicetimes/public/…      │
└──────────────────────────────┘             └─────────────────────────────────────────┘
```

Три правила важе за читав стек:

1. **Једно стабло, два приказивача.** Страница је стабло `pages → sections → elements` у којем сваки чвор носи своја подешавања као JSON блок `answers`. Исте apphelper компоненте приказују уређивач са превлачењем у B1Admin-у и јавни сајт са серверским приказивањем у B1App-у. Не постоји посебан „формат објављивања“.
2. **Уговор живи у `@churchapps/helpers`.** `ElementTypes.ts` је јединствени каталог типова елемената; приказивачи се разрешавају кроз регистар у apphelper-у; обрасци уређивача налазе се у B1Admin-у. Додавање типа елемента значи измену сва три, тим редом.
3. **Јавни сајт чита анонимне крајње тачке.** Све што B1App треба — стабло страница, подешавања, блог објаве, преусмеравања и крајње тачке са подацима цркве у другим модулима — је јавно. Аутентификација је опциона: JWT на анонимној крајњој тачки стабла отључава странице само за чланове, ништа друго се не мења.

## Стабло садржаја

Модул за садржај (`Api/src/modules/content`) управља подацима градитеља:

| Табела | Улога |
|-------|------|
| `pages` | Једна страница по URL-у: `url`, `title`, `layout`, уз `visibility`/`groupIds` (ограничавање приступа) и `metaDescription` (SEO) |
| `sections` | Хоризонталне траке на страници (или у блоку): позадина, боја текста и `answersJSON` који садржи стилизовање и конфигурације облика разделника `dividerTop`/`dividerBottom` |
| `elements` | Садржајни делови унутар секције: `elementType` + `answersJSON`, могу бити угнеждени за типове распореда (ред/колона, карусел) |
| `blocks` | Вишекратно употребљиве групе секција/елемената (блокови подножја, блокови елемената) дељене између страница |
| `posts` | Самосталне блог објаве (видети [Блог](#blog)) |
| `redirects` | Парови `fromPath → toPath` по цркви, ограничени на 200 (видети [SEO](#seo-and-discoverability)) |
| `settings` | Подешавања цркве у облику кључ–вредност; редови означени као `public` се сервирају анонимно и садрже конфигурацију виџета/аналитике |

Читаво стабло за један URL враћа се из једног анонимног позива — `GET /content/pages/:churchId/tree?url=/about` — из којег B1App врши серверско приказивање. Захтеви уређивача уместо тога преузимају по идентификатору и задржавају интерне идентификаторе.

## Уговор о елементима

### Каталог (`@churchapps/helpers`)

`Packages/helpers/src/ElementTypes.ts` дефинише сваки тип елемента као `ElementTypeDefinition`: `elementType`, `label`, `category`, `schemaVersion`, `defaults` и `answersSchema` у стилу JSON шеме за његове одговоре. `validateElementAnswers()` намерно је попустљива — непознати типови и вишак кључева пролазе, па старији садржај никад не пуца при надоградњи каталога. **Тренутно се испоручује 35 типова:**

| Категорија | Типови елемената |
|----------|---------------|
| распоред (6) | row, column, box, carousel, whiteSpace, block |
| садржај (11) | text, textWithPhoto, card, faq, iconFeature, testimonial, socialIcons, countdown, stats, table, buttonLink |
| медији (4) | image, gallery, video, map |
| црква (12) | logo, sermons, stream, donation, donateLink, form, calendar, groupList, groups, campaignProgress, staffGrid, serviceTimes |
| напредно (2) | rawHTML, iframe |

Елемент `sermons` је најприлагодљивији од типова за цркву: одговор `layout` бира `browse` (застарели пун прегледач), `grid`, `list` или `featuredLatest`, а `playlistId`, `itemCount`, `showTitles` и `showDates` прецизирају распореде који нису `browse`.

Елемент `rawHTML` има два одговора: `rawHTML` (ознаке) и `javascript`. Скрипте убачене преко `innerHTML`-а никад се не извршавају, па `RawHTMLElement` поново креира сваки чвор `<script>` у ознакама као нови елемент. Ти чворови, који нису убачени парсером, сматрају се поузданим према CSP-јевом `strict-dynamic`-у. Одговор `javascript` који почиње знаком `<` (снипет добављача залепљен са својим `<script>` ознакама) парсира се као ознаке и добија исти третман. У супротном се извршава као обичан уграђени скрипт. B1Admin означава голи URL у пољу JavaScript, јер се сам URL извршава као скрипт без дејства. Елемент `map` ништа не приказује и не учитава скрипту Google Maps када није подешен кључ Maps API-ја.

### Приказивачи (`@churchapps/apphelper`)

Приказивачи се налазе у `Packages/apphelper/src/website/components/elementTypes/`, по једна компонента за сваки тип, а разрешавају се преко `ElementRegistry.ts` — мапе са два слоја у којој `Element.tsx` региструје подразумевани приказивач за свих 35 типова (`registerDefaultElementRenderer`), а host апликација може да замени било који од њих у време извршавања (`registerElementRenderer`) без рачвања пакета.

### Обрасци уређивача (B1Admin)

Обрасци подешавања по типу у уређивачу налазе се у `B1Admin/src/site/admin/elements/`. `ElementEdit.tsx` прослеђује посебној компоненти (`GalleryEdit`, `TestimonialEdit`, `StatsEdit`, …) или уграђеном граду поља за сваки тип. AI огледало овог каталога је алатка API-ја `describe_page_builder` у MCP-у (видети [MCP сервер](../api/mcp.md)).

Преглед уређивача монтира исту `Theme` као и живи сајт, која поставља CSS променљиве `--headingFont` / `--bodyFont` из глобалних стилова цркве. B1App примењује те променљиве преко `pages.css`, коју B1Admin не може да увезе, па `ContentEditor.tsx` убацује `EDITOR_PAGE_FONT_CSS` (`src/site/admin/editorCss.ts`) да би их применио на текст `.page` тела и на `h1`–`h6`. Без тога преглед је приказивао наслове администраторским фонтом.

### Разделници облика секција

Секције могу имати декоративне разделнике облика на било којој ивици. Конфигурација се чува у `answersJSON` секције као објекти `dividerTop` / `dividerBottom` — `{ shape, color, height, flip }`, при чему је `shape` један од: `wave, waves, slant, curve, triangle, peaks`. Apphelper испоручује компоненту `SectionDivider` и помоћну функцију `parseDividerConfig()`. Приказивачи секција обе апликације (`B1App/src/components/Section.tsx`, `B1Admin/src/site/admin/Section.tsx`) рашчлањују одговоре и монтирају разделник, а `SectionEdit.tsx` у B1Admin-у пружа бирач. Пакети испоручују само градивни блок; повезивање на нивоу секције посао је апликација које их користе.

## Елементи са подацима цркве

Три типа елемената приказују живе податке цркве, а не ауторски садржај. Изолација модула и даље важи — сваки од њих позива јавну крајњу тачку свог модула из прегледача:

| Елемент | Крајња тачка | Напомене |
|---------|----------|-------|
| `campaignProgress` | `GET /giving/funds/public/:churchId/:fundId/total` | Враћа `{ fundId, totalAmount, donationCount }`, по избору са прозором `?startDate=&endDate=`; елемент га пореди са одговором `goalAmount` |
| `staffGrid` | `GET /membership/groupmembers/public/:churchId/:groupId` | **Само по пристанку**: група мора имати постављено `publicRoster` (подразумевано искључено). Пројекција је намерно минимална — `personId`, `displayName`, `leader`, фотографија — без контакт или демографских поља |
| `serviceTimes` | `GET /attendance/servicetimes/public/:churchId` | Враћа стабло кампус → служба → време; приказивач apphelper-а на основу тога емитује најбољи напор schema.org `Event` JSON-LD (API враћа обичне податке) |

:::warning
`publicRoster` је капија приватности за `staffGrid`. Никад не проширујте јавну пројекцију чланова групе и не заобилазите ову заставицу. Крајња тачка списка је по дизајну анонимна, а минимална листа поља је безбедносно својство.
:::

### Елемент календара и странице догађаја

Одговори елемента `calendar` су `calendarType` (`group` | `curated`), `calendarId`, `display` (`month`, подразумевано, или `upcoming`) и `tag`. B1App замењује приказивач apphelper-а у `src/components/Element.tsx` помоћу `registerElementRenderer("calendar", …)`:

- **`display: "upcoming"`** приказује `UpcomingEventsElement` из B1App-а: учитава `GET /content/events/public/group/:churchId/:groupId` или `GET /content/curatedEvents/public/calendar/:churchId/:curatedCalendarId`, проширује понављања помоћу `buildOccurrences()` (`src/helpers/EventOccurrences.ts`, једно појављивање по догађају у оквиру године) и приказује првих 12 као плочице са сликама (`events.photoUrl`, а у недостатку слике наслов на тамној боји теме) које воде на `/events/{id}`, уз мени Претплати се за ICS фид календара.
- **`display: "month"`** приказује `CalendarElement` из apphelper-а са повратним позивом `eventUrl`. `GroupCalendar` / `CuratedCalendar` → `EventCalendar` / `CuratedEventCalendar` затим на клик иду на тај URL, уместо да отворе дијалог са детаљима (B1Admin не прослеђује `eventUrl`, па администраторски календар задржава свој дијалог).
- **`tag`** филтрира оба приказа помоћу `EventHelper.hasTag()` (`@churchapps/helpers`): поређење без обзира на велика и мала слова са `events.tags` вредностима одвојеним зарезом; празно приказује све. Спајање курираног календара бира `e.tags`, како би курирани догађаји имали те ознаке.

Курирани догађаји се повезују преко `realEventId` (`eventPageId()`), па URL увек именује основни догађај. `/{sdSlug}/events/[eventId]` је посебна рута (не цевовод градитеља): учитава `GET /content/events/public/:churchId/:id`, која враћа `null` за догађаје на чекању или одбијене и за приватне догађаје без пријаве, и додаје `roomNames` из резервација просторија које нису одбијене. Приказује `EventPageContent` (насловна слика, опис у markdown-у, бочна колона When/Where, **Register for this Event** када је `registrationEnabled`, и веза **Add to my calendar** ка `GET /content/events/public/:churchId/:id/ical`), користи фотографију као слику Open Graph и емитује `Event` JSON-LD за следеће појављивање преко `EventPageJsonLd`. Непознат или скривен догађај враћа прави 404.

## Виџети за цео сајт

Два виџета се приказују на свакој јавној страници, а не унутар стабла: **AnnouncementBanner** (трака на врху странице коју је могуће затворити) и **Launcher** (плутајуће чвориште радњи за везе типа давање/посета/гледање). Обе компоненте и њихове помоћне функције `parse*Config()` испоручује apphelper. Конфигурација су два јавна реда подешавања — кључеви `announcementBanner` и `launcher` — које уписује `SiteWidgetsEdit` у B1Admin-у (на страници Appearance), а чита јавни распоред B1App-а преко `GET /content/settings/public/:churchId`. API их третира као непрозирне парове кључ–вредност; називи кључева су договор између две апликације.

## Блог

Блог је самостални тип садржаја, а не слој над страницама градитеља. Ред `posts` чува целу објаву: `title`, `slug`, `excerpt`, `content` (тело у markdown-у), `authorId`, `photoUrl`, `publishDate`, `category`, `tags`. Јавни делови (сви анонимни, `PostController`):

| Рута | Сврха |
|-------|---------|
| `GET /content/posts/public/:churchId` | Објављене објаве, филтрирају се по `?category=&tag=`, пагиниране |
| `GET /content/posts/public/:churchId/categories` | Различите категорије међу објављеним објавама |
| `GET /content/posts/public/:churchId/slug/:slug` | Једна објављена објава |
| `GET /content/posts/rss/:churchId?siteUrl=` | RSS 2.0 фид, са насловом по имену цркве и категоријом и описом (извод или садржај) по ставци |

Објава је „објављена“ чим је `publishDate` постављен и прошао. Будући `publishDate` значи заказану објаву (јавно сакривену, а у администрацији приказану са ознаком Scheduled). Крајње тачке за читање обогаћују сваку објаву са `authorName`, који се разрешава из `authorId` преко мрежног пролаза модула чланства. Ако извод недостаје, у прегледима на листи, описима за мета-податке и RSS-у користи се садржај без markdown ознака (~160 знакова). B1App служи `/{sdSlug}/blog`, уреднички преглед (централизовано заглавље које постаје назив активне категорије или ознаке при филтрирању, ред филтера у облику чипова категорија, редови објава са сликом лево, потписом аутора и изводима), са RSS фидом наведеним као алтернативна веза. Такође служи `/{sdSlug}/blog/[postSlug]`, посебну руту (не цевовод Zone/Section) са централизованим заглављем (категорија као увод, наслов, потпис аутора, акцентна линија у основној боји), насловном сликом 16:9 у ширини контејнера, телом у markdown-у у читљивој колони од ~720 пиксела, ознакама у облику чипова у подножју чланка, траком повезаних објава `"More in {category}"` и JSON-LD-ом `BlogPosting` која укључује аутора. Обе странице се стилизују искључиво помоћу токена теме, па наслеђују палету сваке цркве. URL-ови блога укључени су у мапу сајта за сваку цркву.

Интерфејс за писање у B1Admin-у (**Site → Blog**) уређује објаве у дијалогу: markdown уређивач са прегледом, бирач галерије слика исечен на 16:9, бирач аутора (подразумевано корисник који уређује), ауто-довршавање категорија са постојећих категорија, провера дуплог slug-а и прекидач за објављивање. Објављени редови воде на живу објаву, а страница подсећа администраторе да додају навигациону везу `/blog`. Коментари се остављају услугама трећих страна: јавно подешавање садржаја за целу цркву `blogFooterHtml` (уређује се у **Below Every Post** на страници Blog, а приказује се само са Settings→Edit) приказује B1App-ов `BlogFooterEmbed` испод сваке објаве. Он поново креира ознаке `<script>` како би се извршиле под `'strict-dynamic'` и покреће их редом (спољашњи `src` мора да заврши учитавање пре него што се изврши следећи уграђени скрипт), јер снипети добављача најпре учитају библиотеку, а затим је позову.

## Странице само за чланове

`pages.visibility` користи исти скуп вредности као и навигационе везе — `everyone` (подразумевано), `visitors`, `members`, `staff`, `team`, `groups` (са `groupIds`) — али као **строгу капију приступа**, а не навигацијски филтер (`PageVisibilityHelper.canViewPage`). Ток је следећи:

1. Анонимна крајња тачка стабла проверава видљивост при преузимањима на основу URL-а. Анонимни позиваоци ограничене странице добијају `{ restricted: true, visibility }` уместо садржаја, па стабло никад не цури.
2. Крајња тачка и даље поштује JWT: `CustomAuthProvider` проверава заглавље `Authorization` при *сваком* захтеву, укључујући анонимне руте, па се преузимање истог URL-а од стране аутентификованог члана разрешава нормално.
3. B1App приказује `RestrictedPage` на одговор `restricted`: обнавља сесију из сачуваних акредитива, поново преузима стабло са JWT-ом и приказује га. Ако сесија не постоји, приказује капију за пријаву са `returnUrl`.

:::info
Прецизност капије варира по нивоу: `groups` проверава `groupIds` из токена у односу на листу странице, а `staff` проверава `membershipStatus`. Али `members` и `team` тренутно пропуштају било ког аутентификованог корисника цркве. Сматрајте `groups` строжом опцијом.
:::

## AI генерисање (AskApi)

Генерисање страница и сајтова ради у **AskApi**, посебном сервису, под контролером `/website`. Аутентификује се истим JWT-ом `CustomAuthProvider` као и све остало и **без стања у односу на садржај**: свака крајња тачка враћа JSON, а позиваоц (B1Admin) чува резултат преко ContentApi-ја (`POST /content/pages/importTree` креира страницу са целим угнежденим стаблом секција и елемената у једном позиву; увек уписује под црквом позиваоца и игнорише идентификаторе у телу захтева).

### Генерисање страница (`planPage` → `writePage`)

Шаблон странице „AI“ у `AddPageModal`-у B1Admin-а користи јефтин цевовод (`AskApi/src/helpers/SiteGenHelper.ts`) заснован на једном правилу: **ниједан модел никад не емитује JSON градитеља**. Два модела деле посао кроз Vercel AI Gateway (обичан HTTP, SSM кључ `/{env}/aiGatewayApiKey` или `AI_GATEWAY_API_KEY`):

- **JEV** (`typesafe-ai/jev`) — модел типизованих одлука који враћа изборе, оцене и логичке вредности са вероватноћама, али не може да пише текст. Редом бира сваку секцију из фиксне библиотеке шаблона, оцењује распореде, проверава чињенице у тексту и бира сличице и иконе. Улаз кошта око 0,04 долара по милион токена, а излаз је бесплатан, па ~90 позива по страници коштају делић цента.
- **Мали модел за ћаскање (подразумевано GPT-4.1 mini)** — попуњава именована текстуална поља ограничене дужине у изабраним шаблонима. Писац је једна константа, коју може заменити променљива окружења `SITEGEN_COPY_MODEL` (било који ID модела за ћаскање на пролазу, нпр. `anthropic/claude-haiku-4.5`). У слепом поређењу на три цркве Claude Haiku 4.5 звучао је нешто топлије, али GPT-4.1 mini је био близу, отприлике 4 пута јефтинији и бржи, па је подразумевани. Цела страница са сва три распореда кошта око 1,3 цента, од чега око 80% отпада на писца.

| Фаза | Крајња тачка | Шта се дешава |
|-------|-----------|-------------|
| 1 | `POST /website/planPage` | Класификује тип странице (почетна, посета, о нама…), затим узоркује 10 кандидата за распоред из вероватноћа JEV-а по кругу (насловна секција + број секција → свака секција → завршетак), уклања дупликате, има JEV оцену за уклопљеност, ток и празнине и враћа три најбоља плус глас писања и `suggestedStyle` (палету и фонтове). Кандидати који до сада деле исте секције постављају JEV-у идентично питање, па се кругови меморишу по префиксу. Најбоља оцена испод 6 бележи се као `lowLayoutScore`. Тај запис је списак шаблона вредних додавања. ~2 с |
| 2 | `POST /website/writePage` (један позив по кандидату) | Попуњава текст поља по два одељка у позиву, паралелно, и враћа пет наслова за насловну секцију између којих бира JEV. JEV проверава чињенице сваке секције. Секције које не прођу, користе устаљену фразу или поново препричавају раније одељке (заједнички низови од 4 речи, проверава се кодом) преписују се паралелно уз наведен конкретан разлог. Чишћење кодом уклања реченице са устаљеним фразама church-сајтова (осим ако опис саме цркве их користи). JEV бира теме слика, иконе и разделник облика насловне секције и оцењује резултат. Враћа стабло секција спремно за чување и оцену. ~6–9 с |
| 3 | `POST /content/pages/importTree` | B1Admin уписује само најбоље рангирани распоред (други по реду је резерва ако тај упис не успе), чува га и отвара преглед (~10 с након чувања) |

Свака фаза је засебан захтев, тако да сваки позив остаје у оквиру ограничења API Gateway-а од 29 секунди. Шаблони у `SiteGenHelper.buildTree` су фиксна стабла секција и елемената из каталога (`text`, `row`/`column`, `card`, `iconFeature`, `faq`, `table`, `testimonial`, `textWithPhoto`, `box`, `map`, `sermons`) и referенцирају токене теме (`var(--accent)`, `var(--lightAccent)`…), па генерисане странице наслеђују постојећа подешавања изгледа цркве. Додавање шаблона секције значи додавање његове листе поља у `SECTIONS` и његовог стабла у `buildTree`. Јединични тест пролази кроз сваки шаблон и проверава стабло.

**Улази.** Текст сме да наводи чињенице само из два извора: онога што је корисник укуцао и `churchContext.facts`, записа које B1Admin прикупља пре планирања (јавна времена служби и јавни називи група, плус назив и адреса цркве). Исте заставице контролишу шаблоне са подацима: `times` приказује живи елемент `serviceTimes` када црква чува времена служби у B1, а иначе ручно унету табелу. `groups` и `countdown` се нуде само када иза њих постоје подаци. JEV позиви су заштићени: дупликат се покреће после 1,5 с и први одговор побеђује, јер капија повремено застане, а позиви су готово бесплатни.

**Остати на теми.** Корисников упит је *тема странице*, а не позадина о цркви. `planPage` класификује захтев (`home`, `visit`, `about`, `ministries`, `give`, `contact`, `event`, `topic`). За странице `event` и `topic` општи шаблони за цркву (порука пастора, проповеди, служења, групе, утицај на заједницу, недељна времена и одбројавање, видео насловна секција) се чак и не нуде, док се нуде `details` (када / где / шта понети) и датумски `eventCountdown`. Оба судије оцењују тематску подударност. B1Admin прослеђује `pageType` из плана у сваки позив `writePage`.

**Потпуне странице из кратких захтева.** Странице имају три до шест средњих секција, широке дужине поља, уводни ред у секцијама картица и петопитањни FAQ. Корективни пролаз проширује сваку секцију која се врати оскудна. Генерисање је један клик: нема додатних питања. Када захтев изостави обичан детаљ који је потребан потпуној страници (почетно време, просторија, шта понети, како се пријавити), писац га попуњава уверљивим, скромним избором који црква може да уреди. Пошто се секције пишу паралелно, те празнине се одлучују **једном**, у `planPage` (`assumedDetails`, један мали позив писцу који се извршава уз узоркивање распореда). Прослеђују се назад у сваки позив `writePage` кроз `churchContext.assumedDetails`, тако да једна секција не може да каже 5:00 а друга 5:30. JEV поправља сваку секцију која се противречи захтеву, записима цркве или тим одлукама. Донете одлуке се не приказују у интерфејсу. Црква прегледа и уређује страницу као и сваку другу. Неке ствари се никад не измишљају: имена људи, телефонски бројеви, адресе е-поште и веб-адресе, цене, статистика, историја цркве, цитати приписани особама и дан у недељи за датум за који захтев није навео дан.

**Визуелни елементи.** Шаблони никад не именују своје фотографије или иконе. Остављају отворена поља, а један општи пролаз (`visualSlots` → `pickVisuals` → `applyVisuals` у `SiteGenHelper`) прелази готово стабло и попуњава свако: позадину секције или унос галерије означен са `auto:photo`, `auto:icon`, `auto:divider` насловне секције и, без икакве ознаке, сваки елемент `textWithPhoto`, `card` или `image` чије је `photo` празно. JEV бира сваки према тексту поред њега (фотографију картице према наслову и тексту те картице, позадину према тексту секције), без понављања теме на страници. Нови шаблон зато добија фотографије без додатног рада. Фотографије су Pexels претраге које се емитују као placeholder-и `pexels:<term>`, а B1Admin их разрешава преко `POST /content/stock/search`. Клијент који не шаље `resolvesPhotos` добија уграђену насловну слику, равне обојене траке и картице без фотографија. Намерно нема портретних тема, а шаблон пастора не садржи фотографију: сликовни странац никад не сме да заузме место стварне особе. За цркву без страница још увек B1Admin примењује `suggestedStyle` на глобалне стилове. Постојећи сајтови задржавају свој изглед.

### Остале крајње тачке

:::info
Дугме за препис у `SectionToolbar`-у и дугме „Generate Site“ у списку страница у B1Admin-у остају искоментарисани на страни клијента. Крајње тачке AskApi-ја испод и даље одговарају. Сакривен је само тај интерфејс.
:::

| Крајња тачка | Сврха |
|----------|---------|
| `POST /website/generatePageOutline` → `generateSection` | Првобитни дво-корачни ток странице (преглед, па један позив LLM-у по секцији који емитује JSON елемената). У B1Admin-у га је због трошкова заменио `planPage`/`writePage`; задржан је за потрошаче API-ја |
| `POST /website/generateSite` | Генерисање целог сајта. **Дво-фазно по замишљају**: позив са `planOnly: true` враћа само план са више страница (један брз позив моделу), а затим клијент тражи пун садржај. Тако сваки захтев остаје у оквиру временског ограничења Lambda/API Gateway-а |
| `POST /website/rewriteSection` | Препис који чува структуру: модел сме да мења само одговоре који садрже текст. Рекурзивни потпис структуре (идентификатори, типови и редослед) пореди се пре и после. Свако неподударање враћа оригиналну секцију са `fallback: true`, уместо оштећене структуре |
| `POST /website/generateAltText` | Позив визуелном моделу над до 20 URL-ова слика. Враћа сажет алт текст (≤125 знакова, префикси „photo of“ уклоњени) |
| `POST /website/generateMetaDescription` | Један SEO мета опис (≤155 знакова) из текстуалног садржаја странице. Повезан је са дугметом Generate у подешавањима странице у B1Admin-у |

Упутства за ове крајње тачке су markdown датотеке под `AskApi/config/instructions/`, укључујући каталог елемената из којег model генерише. Два дизајнерска принципа држе каталог поузданим: клијент прослеђује `availableElementTypes` у сваком захтеву (упутство сме да користи само типове са те листе, а сервер никад не укључује комплетан скуп), а алатка MCP-а `describe_page_builder` у API-ју носи исти водич за AI агенте који раде преко [MCP-а](../api/mcp.md). Модели су Anthropic Claude преко OpenRouter-а: 3.5 Haiku за садржај секција (латенција), 3.5 Sonnet за прегледе, планове сајтова и визуелни рад. Са OpenAI резервом користи се када OpenRouter кључ није подешен.

## Разговорни обрасци

Обрасци (модул чланства) добили су разговорни режим намењен страницама у стилу картица за везу. Четири колоне у `forms` га покрећу: `displayMode` (`standard` | `conversational`), `autoCreatePerson`, `followUpSubject` и `followUpBody`.

- **Приказивање**: `FormSubmissionEdit` из apphelper-а прелази на компоненту `ConversationalForm` (једно питање у једном тренутку) када је `displayMode` `conversational`. Страница обрасца B1App-а прослеђује режим. У оба случаја исти је садржај пријаве.
- **Аутоматско креирање особе**: при слању са постављеним `autoCreatePerson`, `ConversationalFormHelper.findOrCreatePerson` уклања дупликате по е-пошти (без обзира на велика и мала слова). Иначе креира домаћинство и особу са `membershipStatus: "Guest"`, па повезује пријаву са том особом.
- **Порука праћења**: када су постављени предмет и садржај, подносилац добија шаблонску поруку (са токенима `{firstName}` / `{churchName}`) преко постојећег трансакционог пута (`TransactionalEmailHelper`), никад преко дневног дајджеста обавештења. Обе споредне радње нису фаталне: грешка никад не изгуби пријаву.

Четири поља се тренутно постављају преко API-ја. Уређивач образаца у B1Admin-у их још не приказује.

## Кеш јавног сајта

Путања јавног приказивања B1App-а кешира преузимања означена црквом (`next: { revalidate: 300, tags: [sdSlug] }` у продукцији; `0` у развоју), па жива страница може да остане застарела до пет минута након уписа у ContentApi. `POST /api/revalidate/{sdSlug}` на B1App-у позива `revalidateTag(sdSlug)` и јединствен је начин да се тај кеш раније одбаци.

Два писца га погађају:

1. **B1Admin**: `clearSiteCache()` у `B1Admin/src/site/siteCache.ts` шаље POST после чувања у уређивачу. Преферира поддомен активног сајта (секундарни сајт мора да поништи *ту* ознаку, а не подразумевану ознаку цркве).
2. **Api**: измене садржаја које никад не пролазе кроз B1Admin (API кључеви, MCP, AI) покрећу `SiteCacheHelper.bump(churchId)` из контролера садржаја. Помоћна функција разрешава поддомен цркве преко `SubDomainHelper` и шаље POST на `{b1AppRoot}/api/revalidate/{sd}`. Грешке се прећутно прескачу, како недоступан B1App не би могао да прекине чување.

Контролери који покрећу поништавање: странице (чување, брисање, дуплирање, објављивање, одбацивање, повлачење, AI привремена), секције, елементи, блокови, везе, глобални стилови, објаве и преусмеравања. `b1AppRoot` у развоју је `http://{subdomain}.localtest.me:3301`; демо и продукција користе `https://{subdomain}.b1.church`.
