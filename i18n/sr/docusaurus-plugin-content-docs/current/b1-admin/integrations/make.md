# Make

<div class="article-intro">

[Make](https://www.make.com) (раније Integromat) је платформа за визуелну аутоматизацију радних токова, слична Zapier-у по духу, с флексибилнијом логиком и јефтинијом ценом при већем обиму. Званична B1.church апликација за Make омогућава вам да правите „сценарије” који одмах реагују на догађаје у B1 и уписују записе назад у B1.

</div>

<div class="prereqs">
<h4>Пре почетка</h4>

- Налог на [Make](https://www.make.com) (бесплатан ниво покрива мале радне токове)
- Администратор цркве са дозволом **Edit Settings** у B1Admin-у
- Грубу представу о сценарију који желите да направите

</div>

## Модули

| Врста | Штаради | B1 догађај / крајња тачка |
|---|---|---|
| **Instant Trigger** | Watch Events | било који претплаћени B1 догађај (`person.created`, `donation.created`, …) |
| **Action** | Create Person | додаје нову особу |
| **Action** | Add Donation | бележи донацију |
| **Action** | Add Group Member | додаје особу у групу |
| **Search** | Search People | проналази особе по имену или имејлу |

Тренутни окидач (instant trigger) омогућава вам да изаберете који догађај слуша. Један модул окидача по сценарију, конфигурисан за сваки догађај посебно.

## Подешавање

### 1. Направите B1 API кључ

1. У B1Admin-у идите на **Settings → Developer → API Keys**.
2. Кликните на **New API Key**, назовите га „Make” и додělite потребне опсеге (scopes).
3. **Укључите `settings:write`** ако било који од ваших сценарија користи тренутни окидач. Make региструје webhook у ваше име када се сценарио укључи.
4. Такође додајте опсеге које захтевају модули акција (нпр. `donations:write` за модул Add Donation).
5. Сачувајте и копирајте кључ `cak_…`.

### 2. Инсталирајте везу

1. У Make-у направите нови сценарио и превуците модул окидача **B1.church** на платно.
2. Када се појави упит, изаберите **Create a connection**. Налепите API кључ у поље *API Key* и оставите *API Base URL* као `https://api.churchapps.org` (осим ако тестирате на staging окружењу).
3. Кликните на **Save**. Make проверава кључ читањем вашег профила цркве.

Веза се чува на вашем Make налогу и користи се поново у свим сценаријима.

### 3. Подесите окидач

1. Отворите подешавања модула **Watch Events**.
2. Изаберите догађај који желите, нпр. `donation.created`.
3. Сачувајте. Make генерише јединствени webhook URL и интерно га чува.

### 4. Додајте модуле у наставку тока

Превуците било који од стотина модула апликација из Make-а на платно: Mailchimp, Google Sheets, Slack, HubSpot, сопствену HTTP крајњу тачку итд. Мапирајте излаз окидача (`event`, `churchId`, `data.id`, `data.amount`, …) у поља њихових улаза. Модули flatten / iterator / router / aggregator омогућавају вам да правите разгранате и паралелне токове које би у Zapier-у било тешко направити.

### 5. Укључите сценарио

Укључите **Active** у заглављу сценарија. Make позива B1-ов `POST /membership/webhooks` да региструје URL. Од тог тренутка сваки одговарајући B1 догађај тече кроз сценарио у реалном времену.

Искључивање сценарија позива `DELETE /membership/webhooks/{id}`, тако да не остају заостале претплате.

## Уобичајени рецепти

### Синхронизујте донације у Google табелу за финансијски преглед

- **Окидач**: B1: Watch Events (`donation.created`)
- **Акција**: Google Sheets: Add a Row. Мапирајте `data.donationDate`, `data.amount`, `data.personId`, `data.method`, `data.batchId` у колоне табеле.

### Условно Slack обавештење према износу донације

- **Окидач**: B1: Watch Events (`donation.created`)
- **Router**:
  - Грана A: Filter: `data.amount >= 1000` → Slack: објави у `#major-gifts`
  - Грана B: подразумевано → Slack: објави у `#donations`

### Нова особа → CRM + добродошлица имејлом + Slack

- **Окидач**: B1: Watch Events (`person.created`)
- **Акција**: HubSpot: Create Contact
- **Акција**: Mailgun: Send Welcome Email
- **Акција**: Slack: Обавести `#new-people` (паралелно, користите Make-ов router)

## Како функционише тренутни окидач

Тренутни окидач је заснован на webhook-у, а не на анкетирању. Када се активира, Make позива `POST /membership/webhooks` са генерисаним URL-ом и догађајем који сте изабрали. Када се догађај деси у B1, B1 шаље POST омотач на Make-ов URL и ваш сценарио се покреће за неколико секунди. Деактивирање сценарија уклања webhook.

Окидач се активира само за догађаје који се дешавају **док је сценарио активан**. Нема накнадног преузимања догађаја.

## Ограничења и напомене

- **Један догађај по модулу Watch Events.** Да бисте слушали више догађаја у једном сценарију, поставите више модула окидача у засебне сценарије (или користите један модул са обједињеном листом догађаја, видите испод).
- **Провера потписа није доступна.** Make не прослеђује `X-B1-Signature` сценарију. Граница поверења је Make-ов тешко погодљив URL webhook-а за сваки сценарио. Ово је уобичајена Make пракса. Ако су вам потребне експлицитне провере потписа, направите прилагођену интеграцију помоћу [SDK](/docs/developer/api/webhooks#sdk-support).
- **Број операција.** Сваки API позив из модула акције се рачуна у вашу квоту Make операција, а не у било шта на B1 страни.

## Решавање проблема

- **Тест везе не успева.** Најчешће је реч о грешци у API кључу. Поново га копирајте из B1Admin-а (цео кључ се приказује само једном; ако сте га изгубили, направите нови кључ).
- **Модул окидача се не активира.** Проверите **Settings → Developer → Webhooks** у B1Admin-у. Ако не видите ред „Make — &lt;event&gt;” након активирања сценарија, кључу недостаје `settings:write`. Ажурирајте кључ и поново активирајте сценарио.
- **Акција враћа `403 Forbidden`.** API кључ нема потребан опсег за ту крајњу тачку. На пример, Add Donation захтева `donations:write`. Ажурирајте кључ у B1Admin-у и поново тестирајте.

## Прилагођавање апликације

Апликација B1.church за Make је отвореног кода. JSON дефиниције се налазе у репозиторијуму `B1Integrations/Make/`. Ако вам треба модул који не постоји (нпр. нова акција за крајњу тачку коју још нисмо покрили), отворите issue или PR у том репозиторијуму.
